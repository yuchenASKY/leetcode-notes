# 1. 两数之和

> **难度**：简单
> **标签**：数组 · 哈希表
> **原题链接**：https://leetcode.cn/problems/two-sum/

---

## 一、题目描述

给定一个整数数组 `nums` 和一个整数目标值 `target`，在数组中找出**和为目标值**的那两个整数，返回它们的下标。保证每种输入只对应一个答案，且同一个元素不能重复使用。

### 示例

```text
输入：nums = [2,7,11,15], target = 9
输出：[0,1]
解释：nums[0] + nums[1] == 2 + 7 == 9
```

### 约束条件

- `2 <= nums.length <= 10^4`
- `-10^9 <= nums[i] <= 10^9`
- `-10^9 <= target <= 10^9`
- 只会存在一个有效答案

---

## 二、解题思路

### 核心思想

**用哈希表把「找配对」从 O(n) 降到 O(1)。** 遍历时对每个 `x` 判断 `target - x` 是否已出现过，出现过就直接返回。

### 思路演进

1. **暴力解法**：双重循环枚举所有 `(i, j)` 数对，和为 `target` 就返回。时间 O(n²)，n = 10^4 时约 10^8 次比较，勉强能过但很危险。
2. **观察到**：内层循环做的事本质是「在数组里查 `target - nums[i]` 是否存在」。这一步是纯粹的存在性查询，却用了线性扫描。
3. **优化为**：把已经扫过的元素放进哈希表（`值 -> 下标`），查询变成 O(1)。一次遍历同时做「查询」和「插入」即可。

### 关键点

- **先查再插**，而不是先插再查 —— 否则当 `nums[i] * 2 == target` 时会错误地匹配到自己。
- 存的是 `值 -> 下标`，因为答案要的是下标，而查找依据是值。
- 这题是「**空间换时间**」的原型：用 O(n) 额外空间换掉一整个数量级的时间。

---

## 三、代码实现

### 最终代码

```python
class Solution:
    def twoSum(self, nums: list[int], target: int) -> list[int]:
        seen = {}                      # 值 -> 下标
        for i, x in enumerate(nums):
            need = target - x
            if need in seen:           # 先查
                return [seen[need], i]
            seen[x] = i                # 再插
        return []
```

| :--- | :--- | :--- |
| **最终代码** | O(n) | O(n) |
| 朴素解法 | O(n²) | O(1) |
| 理论下界 | O(n) | O(1) |

## 五、优化评估

**结论**：时间复杂度已是理论下界，**但空间复杂度仍有优化余地**。

### 瓶颈分析

时间上，任何算法都必须至少看一遍数组（否则可能漏解），所以 O(n) 不可突破。当前的 O(n) 额外空间来自哈希表。

### 可优化空间

题目只要求「和为目标值」，如果数组**已经有序**，就可以用**左右双指针**把空间压到 O(1)。但本题数组无序，排序会破坏下标 —— 除非同时记录原始下标，那又回到 O(n) 空间。

因此：**在无序输入下，O(n) 空间是必要代价**。

### 优化代码

以下版本在输入**有序**时可把空间降到 O(1)：

```python
class Solution:
    def twoSumSorted(self, nums: list[int], target: int) -> list[int]:
        """nums 非递减有序时的 O(1) 空间解法"""
        lo, hi = 0, len(nums) - 1
        while lo < hi:
            s = nums[lo] + nums[hi]
            if s == target:
                return [lo, hi]
            if s < target:
                lo += 1        # 和偏小，右移左指针
            else:
                hi -= 1        # 和偏大，左移右指针
        return []
```

**优化理由**：有序性给了我们**单调性** —— `nums[lo] + nums[hi]` 随 `lo` 增而增、随 `hi` 减而减。据此可以每次排除一个元素，无需额外存储。

### 常数级优化（可选）

- 用 `try/except KeyError` 替代 `if need in seen`：命中时少一次哈希查找。但 Python 中异常开销不小，**多数情况下 `in` 更快**，不建议盲改。
- 大数据量下 `dict` 比 `set` 必要，因为需要返回值对应的下标；若只需判断存在性则用 `set` 更省内存。

## 六、易错点与总结

### 易错点

- **先插后查**导致自己匹配自己（如 `nums = [3,3], target = 6` 时可能返回 `[0,0]`）。
- 误把索引当值存进哈希表 —— 要存 `值 -> 下标`，不是反过来。
- 返回空列表的分支理论上不可达（题目保证有解），但保留可避免静态检查报 `None`。

### 题型套路沉淀

- **哈希表查找配对**：凡是「找两个数/两个元素满足某关系」的题，都先想能不能用哈希把内层 O(n) 查找降成 O(1)。同型题：`167. 两数之和 II`、`15. 三数之和`、`454. 四数相加 II`。
- **先查再插** 是这类题目的固定动作，务必形成肌肉记忆。
