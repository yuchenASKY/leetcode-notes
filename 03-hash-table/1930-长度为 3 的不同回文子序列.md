# 1930. 长度为 3 的不同回文子序列

> **难度**：中等
> **标签**：位运算 · 哈希表 · 字符串 · 前缀和
> **原题链接**：https://leetcode.cn/problems/unique-length-3-palindromic-subsequences/

---

## 一、题目描述

给定只含小写字母的字符串 `s`，统计其中**长度为 3 的不同回文子序列**的个数。子序列保持原相对顺序、可删除任意字符；**相同的子序列只计一次**（哪怕有多种取法）。

### 示例

```text
输入：s = "aabca"
输出：3
解释：三个回文子序列是 "aba"、"aaa"、"aca"

输入：s = "adc"
输出：0
解释：不存在长度为 3 的回文子序列

输入：s = "bbcbaba"
输出：4
解释："bbb"、"bcb"、"bab"、"aba"
```

### 约束条件

- `3 <= s.length <= 10^5`
- `s` 仅由小写英文字母组成

---

## 二、解题思路

### 核心思想

**长度为 3 的回文，形态被完全锁死：`c ? c`。** 首尾必须是同一个字符，中间随便什么。所以不必枚举三个下标，只需要对 26 个字母逐个问一句：**以它为首尾，中间能塞进多少种不同字符？**

而对于固定的首尾字符 `c`，把左端点取得越靠左、右端点取得越靠右，中间能覆盖的字符集合就越大。因此**只有 `c` 的第一次出现和最后一次出现有意义**，中间那道「窗口」里的去重字符数就是 `c` 的贡献。

### 思路演进

1. **暴力解法**：三重循环枚举所有 `i < j < k`，判断 `s[i] == s[k]`，是就把 `s[i] + s[j] + s[k]` 塞进一个集合里最后数大小。时间 O(n³)，n = 10^5 时是 10^15 量级，完全不可能过；即使把第三层换成「只跟前面出现过的字符配对」也还是 O(n²)。

2. **观察到**：`i < j < k` 且 `s[i] == s[k]` 这件事，本质上只受两个因素约束 —— **首尾字符是什么**、**中间那个位置在哪**。而字符集只有 26 个，答案的上界是 `26 × 26 = 676`，与 n 无关。既然答案这么小，就该按「字符对」而不是按「下标对」来组织计算。

3. **关键转化**：固定首尾字符 `c`，合法的 `(i, k)` 有很多组，但它们是**包含关系**——取 `i = s.find(c)`、`k = s.rfind(c)` 得到的区间 `(l, r)` 覆盖了所有其他合法组。于是：
   - 中间字符 `m` 只要在 `s[l+1..r-1]` 中出现过，就存在一组合法的 `(l, k=r)`，`"cmc"` 可构造；
   - 若 `m` 在 `(l, r)` 里从未出现，则任何合法的 `(i, k)` 之间都没有 `m`，`"cmc"` 都构造不出来。
   
   两者合起来 ⇒ **贡献恰为 `len(set(s[l+1:r]))`**，不多不少，不需要再枚举具体位置。

4. **优化为**：外层跑 26 个字母，每个字母做一次 `find` + `rfind` 定位首末，再对中间那段做集合去重计数。总复杂度 O(26 × n)，即 O(n)。

### 关键点

- **答案是「字符对」的函数，不是「下标对」的函数**：`(首字符, 中间字符)` 唯一确定一个回文串，所以只需对这 26 × 26 种组合判可行，不必关心具体用的是哪一组下标。
- **首末位置就够，取最宽窗口**：注意到合法区间的包含单调性，这是把 O(n²) 压成 O(n) 的支点。
- **去重是天然的**：不同 `c` 得到的串首字符不同，必不相同；同一个 `c` 下中间字符用 `set` 去重。因此不会重复计数，不需要额外去重结构。
- **单次出现的字符自动归零**：`l == r` 时切片 `s[l+1:r]` 为空串，贡献 0，无需特判。

## 三、代码实现

### 最终代码

```python
from string import ascii_lowercase


class Solution:
    def countPalindromicSubsequence(self, s: str) -> int:
        ans = 0
        for alpha in ascii_lowercase:
            i = s.find(alpha)          # 首次出现
            if i < 0:                  # 该字母没出现，跳过
                continue
            j = s.rfind(alpha)         # 末次出现
            ans += len(set(s[i + 1:j]))  # 首末之间能当中间字符的种类数
        return ans
```

> `from string import ascii_lowercase` 截图里没有，已补（否则 `ascii_lowercase` 未定义会直接 NameError）。

## 四、复杂度分析

| 版本 | 时间复杂度 | 空间复杂度 |
| :--- | :--- | :--- |
| **最终代码** | O(26n) = O(n) | O(1) 额外 / O(n) 峰值临时 |
| 朴素解法（枚举三元组） | O(n³) | O(答案) |
| 理论下界 | O(n) | O(1) |

> 复杂度中的 n 指字符串 `s` 的长度。常数 26 来自字母表大小，与 n 无关。

- **时间**：26 轮，每轮 `find` / `rfind` / 切片 / `set` 各扫一遍区间，单轮 O(n)（`find`/`rfind` 由 C 层实现，仍是线性扫描）⇒ 总计 O(26n)。
- **空间**：额外结构只有切片出的子串和 `set`，其元素种类最多 26 个 ⇒ 按渐进意义是 O(1)；但**切片 `s[i+1:j]` 会真实复制一份最多 n 个字符的临时字符串**，峰值内存是 O(n)。这一步不是必须的，见第五节。

## 五、优化评估

**结论**：时间复杂度已达理论下界 O(n)（必须读完整个串才能确定末尾字符），**但峰值临时内存与常数都可以再压**。

### 瓶颈分析

时间上无可优化 —— 每个字符至少要被「看见」一次。真正浪费在两处：

1. 每轮都对区间做一次 `s[i+1:j]` 切片，复制 O(n) 个字符，26 轮下来是 26 份字符拷贝；
2. 用 `set` 存字符，付出哈希开销，而字符种类只有 26 种。

### 可优化空间

「中间有哪些字符」这个问题只需要 26 个 bit 就够表达，用 `int` 当位集合：扫区间时 `mask |= 1 << (ch - 'a')`，最后 `mask.bit_count()` 就是种类数。这样**不需要切片、不需要哈希，额外空间恒为 O(1)**，峰值内存从 O(n) 降到 O(1)。首末位置也可以用一次正序遍历时顺手记录下来，省掉 26 次 `find`/`rfind` 的重复扫描（每轮都要从头扫，最坏 26 遍全串）。

### 优化代码

```python
class Solution:
    def countPalindromicSubsequence(self, s: str) -> int:
        first = [-1] * 26
        last = [-1] * 26
        for i, ch in enumerate(s):          # 一次遍历同时记首末位置
            c = ord(ch) - 97
            if first[c] < 0:
                first[c] = i
            last[c] = i

        ans = 0
        for c in range(26):
            if first[c] < 0 or last[c] - first[c] < 2:   # 未出现 / 中间为空
                continue
            mask = 0
            for k in range(first[c] + 1, last[c]):
                mask |= 1 << (ord(s[k]) - 97)
            ans += mask.bit_count()          # Python 3.10+
        return ans
```

**优化理由**：位掩码把「去重计数」从「分配容器 + 哈希插入 + 数大小」变成「一次或运算 + 一次 popcount」，且天然有界（26 bit）。同时首末位置只扫一遍串就够，避免 26 次重复的 `find`/`rfind`。大 O 不变（仍是 O(26n)），但削掉了切片拷贝和哈希这两笔实打实的常数开销。

### 常数级优化（可选）

- `mask.bit_count()` 需要 Python 3.10+；更老的版本用 `bin(mask).count("1")` 或手写 popcount。
- 中间字符种类数其实可以用「前后缀掩码」直接算：`mid = prefix[j] & ~prefix[i+1]`（前缀掩码按位与取反），免掉内层 for 循环 —— 这就是标签「前缀和」的用法，用一个 `prefix[i] = 前 i 个字符的掩码` 数组即可，代价是 O(n) 的整数数组（Python 里约 28 bit 的 int 对象，内存不便宜，反而不划算）。当前版本在可读性与开销之间更平衡。

## 六、易错点与总结

### 易错点

- **`find` 返回 -1 时忘记跳过**：`s[i+1:j]` 在 `i = -1`、`j = -1` 时会退化成 `s[0:-1]`（几乎整串），把一个根本没出现的字母算出一大堆贡献，答案直接爆掉。这是本题最容易踩的坑。
- **误以为要特判「只出现一次」**：其实不用。`l == r` 时切片为空、`set` 为空、贡献 0，逻辑自洽。但用位掩码版时区间 `range(l+1, l)` 同样是空，也不必特判（加 `last - first < 2` 只是省一次循环）。
- **混淆「子序列」与「子串」**：子序列不要求连续，所以首末字符之间的一切都是可用的；如果按子串想，就会漏掉大量解。
- **担心重复计数而额外开集合**：不需要。首字符不同则整串不同，首字符相同则中间字符已用 `set`/位掩码去重，天然唯一。
- **漏 `import`**：`ascii_lowercase` 来自 `string` 模块，不在内置命名空间里。

### 题型套路沉淀

- **定长回文 = 结构锁死**：长度只有 3 时回文形态必然是 `c ? c`，把「枚举位置」转成「枚举字符组合」。凡是回文长度极短（3、5）且字符集小的题，先问一句「答案能不能用字符对/字符元组表达」。
- **首末出现位置是最宽合法窗口**：凡涉及「两端相同」的区间类问题，`find` + `rfind` 给出的窗口对所有其他合法窗口是**包含关系**，取它一定不漏。这一招可以直接把 O(n²) 的枚举压到 O(n)。
- **小字符集 + 存在性判断 ⇒ 位掩码**：26 个字母的「出现过哪些」用一个 int 完全够用，配合 `bit_count()` 就是现成的去重计数器，比 `set` 更省、比 `bool[26]` 更快。
- **先看答案上界再选算法**：本题答案 ≤ 676，和 n 无关 —— 这种「答案空间远小于输入空间」的信号，往往意味着可以按答案维度而不是输入维度来组织计算。
