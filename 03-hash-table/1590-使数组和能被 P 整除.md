# 1590. 使数组和能被 P 整除

> **难度**：中等
> **标签**：数组 · 哈希表 · 前缀和
> **原题链接**：https://leetcode.cn/problems/make-sum-divisible-by-p/

---

## 一、题目描述

给定正整数数组 `nums` 和正整数 `p`，删除其中一段**连续子数组**（允许为空，但不允许把整个数组删空），使剩下元素的和能被 `p` 整除。求需要删除的最短子数组长度；无解返回 `-1`。

设总和为 `S`，删掉的子数组和为 `t`，则要求 `(S - t) % p == 0`，等价于 `t ≡ S (mod p)`。**题目被化成：找一段和模 `p` 等于 `S % p` 的最短连续子数组。**

### 示例

```text
输入：nums = [3,1,4,2], p = 6
输出：1
解释：总和 10，10 % 6 = 4，需要删掉和 ≡ 4 的子数组；[4] 本身就满足，长度 1。

输入：nums = [6,3,5,2], p = 9
输出：2
解释：总和 16，16 % 9 = 7；删掉 [5,2]（和 7）后剩 9 能被 9 整除，长度 2。

输入：nums = [1,2,3], p = 3
输出：0
解释：总和 6 已能被 3 整除，删除空子数组即可。
```

### 约束条件

- `1 <= nums.length <= 10^5`
- `1 <= nums[i] <= 10^9`
- `1 <= p <= 10^9`

## 二、解题思路

### 核心思想

**把「子数组和模 p」转成「前缀和余数相等」的查询，用哈希表记录每个余数最近一次出现的位置。** 要找以 `i` 结尾的最短合法子数组，就要找满足条件的 `j` 里最靠右的那个 —— 这是「存最新下标」而不是「存最旧下标」的哈希表用法。

### 思路演进

1. **暴力解法**：预处理前缀和，枚举所有 `(j, i]` 区间，判断 `(pre[i] - pre[j]) % p == x`。区间数是 `n(n+1)/2`，n = 10^5 时约 5×10^9 次判断，必然超时；而且暴力法对每个区间都重新算差值，没有复用任何信息。

2. **观察到**：条件 `(pre[i] - pre[j]) % p == x` 可以移项成 `pre[j] % p == (pre[i] - x) % p`。也就是说，**对固定的右端 `i`，候选的左端 `j` 全部是「前缀余数等于某个确定值」的下标集合**。把「扫一遍所有 `j` 去比对」换成「按余数建索引，直接取」，这就是从 O(n) 内层扫描降到 O(1) 查表。

3. **再观察到（方向很关键）**：同一个余数会在很多位置出现，该留哪一个？目标是**最小化** `i - j`，所以对固定的 `i` 要让 `j` 尽量大 ⇒ 每个余数只保留**最后一次出现**的下标，后来的覆盖先前的。这与「和为 K 的子数组」那类题要**最早**出现的写法正好相反 —— 那类题求的是子数组个数/存在性，本题求的是最短长度。

4. **边界处理**：`x = S % p == 0` 时直接返回 0（空删除合法）；另外「不能删整个数组」，所以答案必须严格小于 `n`，扫完仍为初值就说明无解返回 `-1`。查表用 `last.get(key, -n)` 这种「极左哨兵」写法，可以让未命中的情况算出 `i + n >= n`，自然被后面的 `< n` 判定排除，不需要在循环里 `if` 判断。

### 关键点

- **移项**是整道题的转折：把「两前缀之差同余」变成「单前缀余数的等值查询」，右侧才是哈希表能吃的形状。
- **余数表存最新下标**（覆盖写），不是存最早下标。存反了会把最短长度算成最长长度。
- **余数要先取模再比较**：`(pre[i] - x) % p` 中 Python 的 `%` 对负数返回非负结果，正好符合余数语义；换成 C++/Java 需要写成 `((pre[i] - x) % p + p) % p`。
- **`x == 0` 必须提前返回**：此时若走主循环，`(s - x) % p == s % p`，刚写进去的当前下标会被自己查到，得到长度 0 而掩盖「其实是空删除」这一事实；提前返回既正确又省一遍扫描。
- 答案初值取 `n`（而非无穷大）配合 `-n` 哨兵，把「长度必须 < n」这条约束直接编码进比较里。

## 三、代码实现

### 最终代码

```python
from typing import List   # 截图里没有、已补


class Solution:
    def minSubarray(self, nums: List[int], p: int) -> int:
        x = sum(nums) % p          # 目标：删掉的子数组和 ≡ x (mod p)
        if x == 0:
            return 0               # 已是 p 的倍数，删空子数组

        ans = n = len(nums)
        s = 0                      # 当前前缀和
        last = {s: -1}             # 余数 -> 最近一次出现的边界下标
        for i, v in enumerate(nums):
            s += v
            last[s % p] = i        # 先登记当前边界（覆盖旧值，保留最新）
            j = last.get((s - x) % p, -n)   # 找最靠右的合法左边界
            ans = min(ans, i - j)
        return ans if ans < n else -1
```

| 版本 | 时间复杂度 | 空间复杂度 |
| :--- | :--- | :--- |
| **最终代码** | O(n) | O(min(n, p)) |

## 五、优化评估

**结论**：时间复杂度已是理论下界，**空间上还有一条常数级的压缩路线，但收益有限**。

### 瓶颈分析

时间上，`S % p` 必须看完整数组才能确定，任何算法都不可能少于读一遍数组，O(n) 无法突破。当前是单次遍历、每步一次哈希查表 + 一次哈希写入，两侧都是摊还 O(1)。

空间上，哈希表最多存 `n + 1` 个条目；但余数只有 `p` 种取值，实际规模是 `min(n+1, p)`。原始代码没有利用这一点。

### 可优化空间

时间维度没有余地。空间维度上，由于余数键落在 `[0, p)`，可以用**值域桶**（长度 `p` 的数组，初值 `-n`）替代哈希表，把「哈希 → 取模寻址」这一步去掉。但这是有条件的划算：

- `p` 很大时（如 10^9）开不出这个数组，只能退回哈希表；
- `p` 较小时数组版更快；两者是**分档取舍**，不是无脑替换。

所以本题保留哈希表实现作为通用解，值域桶版本仅作为「`p` 有界时」的备选写法记录思路。

### 常数级优化（可选）

- 用 `enumerate(nums)` 而非 `for i in range(n): s += nums[i]`，省掉一次下标访问。
- 把 `p`、`x`、`last` 提到循环外的局部变量（Python 中局部变量查找比属性/全局快），属编译器无关的微优化。
- `ans` 初值用 `n` 而非 `inf`，省掉最后一步类型转换与比较。

## 六、易错点与总结

### 易错点

- **余数表存最新下标**。写成「若不存在才写入」会退化成求最长合法子数组，答案偏大。
- **忘记「不能删整个数组」**：若某个前缀余数组合恰好让 `i - j == n`，那是整段删除，必须排除；只用 `ans == n` 判无解不够，因为合法答案也可能等于 `n`（此时本就无解），这里靠 `-n` 哨兵 + `< n` 判定统一处理是对的，但换成别种写法时要显式检查 `j >= 0` 或 `i - j < n`。
- **`x == 0` 不提前返回**：会因为「查到自己」得到 0 而碰巧答对，但逻辑上是错的；更危险的是若改成先查后写的顺序，`x == 0` 时会一律返回 `-1`。
- **负数取模**：`(s - x) % p` 在 Python 天然落在 `[0, p)`，移到其他语言必须手写 `+p` 修正。
- 题目问的是**删除**的长度，不是**保留**的长度，别把 `i - j` 写成 `n - (i - j)`。

### 题型套路沉淀

- **模意义下的子数组问题**：`子数组和 ≡ x (mod p)` 一律化成 `pre[j] ≡ pre[i] - x (mod p)`，然后「前缀余数 → 下标」建哈希表，这是「前缀和 + 哈希表」在模运算下的标准变形。
- **同一个前缀表，两种取法**：求**最短**子数组要存**最新**下标；求**个数 / 是否存在**用「先查后写」（避免自己配自己）；求**最长**才需要存**最早**下标。先问清楚目标是最小化还是最大化，再决定覆盖策略。
- **用哨兵替代分支**：给 `dict.get` 一个「绝对不可能成为答案」的默认值（这里是 `-n`），能把 `if key in map` 从内层循环里消掉，代价是必须保证哨兵参与运算后不会误判为可行解。
