# 3185. 构成整天的下标对数目 II

> **难度**：中等
> **标签**：数组 · 哈希表 · 计数
> **原题链接**：https://leetcode.cn/problems/count-pairs-that-form-a-complete-day-ii/

---

## 一、题目描述

给定整数数组 `hours`，统计满足 `i < j` 且 `hours[i] + hours[j]` 是 **24 的整数倍** 的下标对 `(i, j)` 数量。

### 示例

```text
输入：hours = [12,12,30,24,24]
输出：2
解释：构成整天的下标对是 (0, 1)（12+12=24）和 (3, 4)（24+24=48）

输入：hours = [72,48,24,3]
输出：3
解释：(0,1)=120、(0,2)=96、(1,2)=72 都是 24 的倍数；3 与任何数都配不成整天
```

### 约束条件

- `1 <= hours.length <= 5 * 10^5`
- `1 <= hours[i] <= 10^9`

---

## 二、解题思路

### 核心思想

**「两数之和是 24 的倍数」只取决于两数各自对 24 的余数**，与数值本身大小无关。于是把元素归约到 `0..23` 这 24 个等价类，一边遍历一边用哈希表累计「此前各余数出现过几次」，把内层的整段查找压成一次 O(1) 查询。

### 思路演进

1. **暴力解法**：双重循环枚举所有 `i < j`，检查 `(hours[i] + hours[j]) % 24 == 0`。时间 O(n²)。本题 n 上到 `5 * 10^5`，量级约 `1.25 * 10^11` 次加法取模，必然超时 —— 题名带 `II` 且单独出一版，正是为了把 I 版本（n ≤ 100）能过的暴力直接卡死。
2. **观察到**：判断条件可以拆开看。设 `a = hours[i] % 24`、`b = hours[j] % 24`，那么
   `(hours[i] + hours[j]) % 24 == 0` 等价于 `(a + b) % 24 == 0`，也就是 `b == (-a) % 24`。
   换言之，**一个数要配哪些数，完全由它的余数决定**：余数 12 只会和余数 12 配（12+12=24），余数 5 只会和余数 19 配（5+19=24），余数 0 只会和余数 0 配。
3. **优化为**：内层循环做的事本质是「在所有已扫过的元素里，数一数余数等于 `(-a) % 24` 的有几个」。这是一次**计数查询**，正好是哈希表的主场。遍历时维护 `cnt[余数]`，对每个元素先 `ans += cnt[需要的余数]`，再 `cnt[自己的余数] += 1`。一趟扫描即可，均摊 O(1) / 元素。

### 关键点

- **先归约再配对**：`num = hours[i] % 24`，之后一切判断只用 `num`，数值大小（`72` 与 `24`）不再参与。
- **配对余数必须再取一次模**：`temp = (24 - num) % 24`。当 `num == 0` 时 `24 - num` 得到 `24`，而余数取值域是 `0..23`，`cnt[24]` 永远查不到 —— 取模把它拨回 `0`，才是「余数 0 和余数 0 配」的正确语义。
- **先查再插**：保证只统计 `j < 当前下标` 的历史元素，从而 `i < j` 成立、不会自己和自己配对、也不会把 `(i, j)` 与 `(j, i)` 重复计数。
- **`(12, 12)` 这种同余数自配对是合法的**：只要它们是**两个不同下标**。先查再插天然满足 —— 第二个 12 到来时，第一个已经在表里了。

## 三、代码实现

### 最终代码

```python
from typing import List
from collections import defaultdict  # 截图里没有、已补


class Solution:
    def countCompleteDayPairs(self, hours: List[int]) -> int:
        cnt = defaultdict(int)   # 余数 -> 已出现次数
        ans = 0
        for i in hours:          # 注意：i 是元素值，不是下标
            num = i % 24         # 归约到 0..23
            temp = (24 - num) % 24   # 能与之凑成 24 倍数的余数（num=0 时仍是 0）
            ans += cnt[temp]     # 先查：只数与此前元素配成的对
            cnt[num] += 1        # 再插：把自己计入
        return ans
```

## 五、优化评估

**结论**：时间、空间都已是理论下界，**没有算法级优化空间**。

### 瓶颈分析

时间上，任何解法都必须至少读一遍每个元素 —— 漏看一个元素就可能漏掉若干有效对，所以 Ω(n) 是硬下界，当前 O(n) 已顶到。空间上，不同余数只有 24 种，计数表规模恒定，不可能再往下压（连输入的 O(n) 都不占，是额外空间）。

### 可优化空间

无。这一题的关键转化（把「两数之和是 24 的倍数」降解为「余数互补」）已经用尽，剩下的只是实现层面的常数项差异。

### 常数级优化（可选）

- 余数取值域固定在 `0..23`，因此可以用长度 24 的定长列表代替 `dict` 做计数：省掉哈希与 `defaultdict` 的键插入逻辑，大 O 完全不变，只是常数项更小的写法。代价是失去「只出现过的余数才占位」的性质（本题无所谓，24 个格子可以忽略）。
- 当前写法里 `defaultdict` 的 `cnt[temp]` 在 `temp` 尚未出现时会**静默插入一个 0 值键**；本题无害（迟早也要计数），但换成定长列表或 `cnt.get(temp, 0)` 就不会有这个隐式写入。

## 六、易错点与总结

### 易错点

- **`24 - num` 不加 `% 24`**：`num == 0` 时得到 `24`，超出余数取值域，`cnt[24]` 恒为 0，会**漏掉所有「24 的倍数 + 24 的倍数」的配对**（如示例的 `[24, 24]`）。必须写 `(24 - num) % 24` 或等价的 `(-num) % 24`。
- **先插后查**：把元素自己算进配对 —— `hours = [24]` 会返回 1 而不是 0；同时 `(i, j)` 与 `(j, i)` 被各数一次。顺序不能颠倒。
- **循环变量命名**：截图里 `for i in hours` 的 `i` 实际是元素值而非下标，读代码时极易误以为在做下标运算。保持提交版本原样，但心里要清楚它是值。
- **答案规模**：n 可达 `5 * 10^5`，全数组同余时答案约 `n² / 2 ≈ 1.25 * 10^11`，**超过 32 位整型**。Python 自动大整数不受影响，但 C++ / Java 写这题必须用 `long long` / `long`。
- **误以为要排序或双指针**：配对条件不是「和等于定值」，而是「和是 24 的倍数」，目标值随两个操作数变化，双指针的单调性用不上；归约到余数后直接计数才是正路。

### 题型套路沉淀

- **「两数之和」的计数版骨架**：当配对条件只依赖元素的某个**特征值**（余数、补数、异或值……），且要求**统计所有对**而不是找一个对时，一定是「特征值哈希计数 + 一次扫描」，模板如下：

  ```python
  ans = 0
  cnt = defaultdict(int)
  for x in arr:
      k = feature(x)              # 归约到等价类
      ans += cnt[need(k)]         # 先查：与历史元素配对
      cnt[k] += 1                 # 再插
  ```

- **判据**：看到「两数之和满足某整除 / 同余 / 互为补数」且 n 在 `1e5` 量级、答案可能到 `1e11` —— 立刻想到等价类归约 + 哈希计数，同时把答案类型抬到 64 位。
- **「先查再插」是这类题目的固定动作**：它同时解决三件事 —— 保证下标有序、避免自配对、避免重复计数。
- **余数类问题必查边界 `r = 0`**：补数公式在 0 处需要额外取模，是这类题最常见的一处 off-by-one。
