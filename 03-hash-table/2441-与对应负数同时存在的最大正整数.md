# 2441. 与对应负数同时存在的最大正整数

> **难度**：简单
> **标签**：数组 · 哈希表
> **原题链接**：https://leetcode.cn/problems/largest-positive-integer-that-exists-with-its-negative/

---

## 一、题目描述

给定一个**不含 0** 的整数数组 `nums`，找出「它本身和它的相反数都在数组中」的最大正整数 `k`。若不存在这样的数，返回 `-1`。

### 示例

```text
输入：nums = [-1,2,-3,3]
输出：3
解释：3 和 -3 都在数组中，且没有更大的正数满足条件。

输入：nums = [-1,10,6,7,-7,1]
输出：7
解释：1/-1 和 7/-7 都成对存在，7 更大。

输入：nums = [-10,8,6,7,-2,-3]
输出：-1
解释：没有任何一对相反数同时出现。
```

### 约束条件

- `1 <= nums.length <= 1000`
- `-1000 <= nums[i] <= 1000`
- `nums[i] != 0`

---

## 二、解题思路

### 核心思想

对每个数 `x`，只需要回答一个问题：**`-x` 之前出现过吗？** 把已扫过的元素放进哈希集合，这个查询就是 O(1)；一边扫一边问，一遍就能筛出所有成对的数，取最大值即可。

### 思路演进

1. **暴力解法**：两重循环枚举所有数对 `(i, j)`，判断 `nums[i] == -nums[j]`，记录其中最大的正数。时间是 O(n²)，n = 1000 时约 5×10⁵ 次比较，能过但完全是浪费。
2. **观察到**：内层循环做的事情，本质是一次「存在性查询」——在数组里找 `-nums[i]`。这是最典型的可以用哈希降到 O(1) 的操作，没有任何附加条件（不需要下标、不需要顺序、不需要计数）。
3. **优化为**：扫一遍，把元素丢进 `set`；每读到一个 `x`，就检查 `-x` 是否已在集合里，命中则把 `|x|` 记录下来。最后取所有命中值里的最大值。
4. **为什么不用排序/双指针**：排序后确实能用双指针夹逼找对称对，但排序本身是 O(n log n)，比哈希的一趟 O(n) 更慢，且要额外修改输入或付出 O(n) 拷贝。本题只查询「存在性」，哈希是更贴合的武器。

### 关键点

- **判据是 `-x` 在不在集合里，不是 `x` 在不在** —— 哈希表里存的是原值，查的是相反数。
- **`nums[i] != 0` 让「自己匹配自己」不可能发生**：只有 `x == 0` 时才会有 `x == -x`，题意已排除，所以「先插入再查询」的写法不会产生假阳性（详见易错点）。
- 命中时记的是 `abs(x)`：可能是因为读到正数 `x` 而 `-x` 已在集合里，也可能是因为读到负数 `x` 而 `-x`（正数）已在集合里，两种情况取绝对值才统一。
- 结果用一个**单独的集合**收集命中的绝对值，是为了去重 —— 一对 `3 / -3` 会被命中两次（读到 3 时一次、读到 -3 时一次），若用列表收集再取 max 也不影响正确性，但集合更干净。

## 三、代码实现

### 最终代码

```python
from typing import List


class Solution:
    def findMaxK(self, nums: List[int]) -> int:
        temp = set()          # 已扫过的数
        ans = set()           # 命中的 |x|（去重）
        for i in nums:
            temp.add(i)
            if -1 * i in temp:
                ans.add(abs(i))
        return max(ans) if ans else -1
```

> `from typing import List` 在截图中没有（LeetCode 运行环境已自带），为让代码可独立运行已补上。

## 四、复杂度分析

| 版本 | 时间复杂度 | 空间复杂度 |
| :--- | :--- | :--- |
| **最终代码** | O(n) | O(n) |
| 朴素解法（双重循环） | O(n²) | O(1) |
| 理论下界 | O(n) | O(n) |

> 复杂度中的 n 指数组 `nums` 的长度（本题 n ≤ 1000）。理论下界一栏：时间上任何算法都必须至少读完整个数组才能确认某对数不存在，故 O(n) 不可突破；空间上要判断「`-x` 是否出现过」，若不允许改动输入，O(n) 的额外存储是必要的。

## 五、优化评估

**结论**：时间复杂度已到理论下界，但**实现上还多付了一个集合和一趟 `max`**，可以收掉。

### 瓶颈分析

时间上，一趟哈希扫描 O(n) 已无可压缩；真正的开销落在空间与常数上：`temp` 与 `ans` 两个集合同时存在，其中 `ans` 只是为了「收集后统一取最大值」，而最大值完全可以边扫边维护（滚动最大值），不需要存下来。

### 可优化空间

- **去掉 `ans` 集合，改用滚动最大值 `best`**：额外空间从「两个集合」降到「一个集合」，末端的 `max(ans)` 也一并省掉（O(n) 的收尾扫描变 O(1)）。
- **判断顺序可以调成「先查后插」**：本题因 `nums[i] != 0` 两种顺序都正确，但先查后插是这类题的通用安全写法 —— 换到允许 0 存在的题面上仍然正确，不需要再想一遍。
- 注意这只是**常数级**改进，大 O 不变；不要为了这点收益把可读性搞坏。

### 优化代码

```python
from typing import List


class Solution:
    def findMaxK(self, nums: List[int]) -> int:
        seen = set()
        best = -1                      # -1 天然充当「没找到」的哨兵
        for x in nums:
            if -x in seen:             # 先查
                best = max(best, abs(x))
            seen.add(x)                # 后插
        return best
```

**优化理由**：把「收集所有答案再取 max」改成「边扫边更新 best」，省掉一个集合与最后一趟遍历；`best` 初值取 `-1` 正好与题目「无解返回 -1」的约定重合，省去了额外的空判断。

### 常数级优化（可选）

- 用 `abs(x)` 而不用 `x if x > 0 else -x` 在可读性上更好；两者在本题规模下无实质差别。
- `-1 * i` 可直接写 `-i`，语义相同、少一次乘法运算。
- 若把窗口放到值域上：`-1000 <= nums[i] <= 1000`，可以用一个长度 2001 的布尔数组（或一个大整数的位图）替代 `set`，把哈希开销换成直接下标访问；元素量大时这是常见的降常数手段，但 n ≤ 1000 时完全没必要。

## 六、易错点与总结

### 易错点

- **先插后查的假阳性风险**：本写法把 `temp.add(i)` 放在查询之前，若数组允许 `0` 存在，`0 == -0` 会让它与自己「配对」，把一个不合法的数误判为命中。本题约束 `nums[i] != 0` 恰好规避了这一点，换成通用题面时必须改成先查后插。
- **漏掉「读到负数」的分支**：一对 `(3, -3)` 中如果先出现 `-3`，那么读到 `3` 时命中；如果先出现 `3`，读到 `-3` 时命中。若只处理 `x > 0` 的分支，会漏掉后一种顺序 —— 用 `abs(x)` 统一两者才安全。
- **无解时的返回值**：漏写 `else -1`（或用 `max()` 默认的空序列异常）会直接报错。
- **误把 `ans` 当计数器**：这题要的是最大的 `k`，不是对数，别在 `ans` 里累加次数。

### 题型套路沉淀

- **哈希集合做存在性查询**：凡是「判断某个值 / 某个配对是否出现过」的题，先想一遍能不能用 `set` 把 O(n) 的存在性查询压成 O(1)，整体从 O(n²) 降到 O(n)。本题是「查相反数」，同骨架的变体还有「查 `target - x`」「查 `x²`」「查 `2x`」。
- **命中即维护最值**：不需要把答案收集起来最后再取 max，边扫边用 `best = max(best, ...)` 更新即可，省一次空间和一趟遍历。
- **哨兵值要与题意对齐**：题目要求无解返回 `-1`，就把 `best` 初始化成 `-1`，让「无解」和「已找到」走同一条返回语句，减少分支。
- **先想「查询什么」再想「存什么」**：这类题的第一步永远是明确「我要查的是 `-x` 而不是 `x`」，写代码前把这一点说清楚，能避免绝大多数下标/符号出错。
