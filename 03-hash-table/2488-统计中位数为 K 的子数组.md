# 2488. 统计中位数为 K 的子数组

> **难度**：困难
> **标签**：数组 · 哈希表 · 前缀和
> **原题链接**：https://leetcode.cn/problems/count-subarrays-with-median-k/

---

## 一、题目描述

给定一个长度为 `n` 的数组 `nums`，它由 `1` 到 `n` 的**不同**整数组成（即一个排列）。再给一个正整数 `k`。统计 `nums` 中**中位数恰好等于 `k`** 的非空连续子数组个数。

中位数的定义：数组排序后位于正中间的元素；若长度为偶数，取**中间靠左**的那个。例如 `[2,3,1,4]` 排序后是 `[1,2,3,4]`，中位数取 `2`（不是 3）。

### 示例

```text
输入：nums = [3,2,1,4,5], k = 4
输出：3
解释：中位数为 4 的子数组有 [4]、[4,5] 和 [1,4,5]。

补充：nums = [2,3,1,4,5], k = 4 → 输出 2，即 [4]、[4,5]
```

### 约束条件

- `n == nums.length`
- `1 <= n <= 10^5`
- `1 <= nums[i], k <= n`
- `nums` 由 `1` 到 `n` 的不同整数组成（`k` 在数组中**恰好出现一次**）

---

## 二、解题思路

### 核心思想

**中位数是不是 `k`，只取决于「比 `k` 大的个数」和「比 `k` 小的个数」之差，与具体数值无关。** 把每个元素按与 `k` 的大小关系映射成 `+1 / 0 / -1`，问题就变成「统计区间和属于 `{0, 1}` 的子数组个数」，再用**前缀和 + 哈希表计数**一遍扫完。

### 思路演进

1. **暴力解法**：枚举所有 `(l, r)` 共 O(n²) 个子数组，各自排序后取中位数，时间 O(n³ log n)。即使把排序换成计数，也只是 O(n²)。

2. **观察到**：排序是多余的动作。子数组里 `k` 排名第几，只看有多少元素比它小。设子数组包含 `k`，其中比 `k` 大的有 `g` 个、比 `k` 小的有 `l` 个，长度 `m = g + l + 1`。`k` 在有序结果中的下标就是 `l`，而中位数要求下标为 `⌊(m-1)/2⌋ = ⌊(g+l)/2⌋`，于是
   - `g - l = 0`：`⌊2l/2⌋ = l` ✔
   - `g - l = 1`：`⌊(2l+1)/2⌋ = l` ✔（偶数长度、靠左规则）
   - `g - l = 2`：得到 `l+1` ✘；`g - l = -1`：得到 `l-1` ✘

   ⇒ **充要条件是 `g - l ∈ {0, 1}`**。至此每个元素只需贡献一个 `+1 / 0 / -1`，中位数判定退化成一次求和。

3. **优化为**：令 `b[i] = -1 (nums[i] < k) / 0 (== k) / +1 (> k)`，前缀和 `P[0] = 0, P[i] = b[1] + … + b[i]`。子数组 `[l, r]`（1-indexed）的 `g - l = P[r] - P[l-1]`，条件变成
   ```text
   P[l-1] == P[r]     或     P[l-1] == P[r] - 1
   ```
   即对每个右端点 `r`，去哈希表里查**两个键**：`P[r]` 和 `P[r]-1`。

4. **处理「必须包含 k」这个额外约束**：如果直接在整条前缀和上建表，会把不含 `k` 的子数组也算进来（它们同样可能满足 `g - l ∈ {0,1}`，但里面根本没有 `k`，中位数无从谈起）。
   巧妙做法是用 `k` 的位置 `m` 当**分界线**：表里只放**下标 `< m` 的前缀和**（`P[0] … P[m-1]`），扫描时才处理 `r ≥ m`。这样任何被计数的组合都自动满足 `l - 1 ≤ m - 1` 且 `r ≥ m`，即 `l ≤ m ≤ r`，子数组**天然包含 `k`**，不需要额外判断。
   代码里用一个 `flag` 实现：遇到 `k` 之前的每个位置都往表里记一次，遇到之后只查不记。

### 关键点

- **`x == k` 时前缀和不变**（贡献 0），所以 `P[m] == P[m-1]`，位置 `m` 本身也落在「查表」阶段里，`[k]` 这个单元素子数组会被 `cnt[P[m]]` 自然算到。
- **`cnt[0] = 1`** 代表空前缀 `P[0]`，它是「子数组从左边界 `1` 开始」的全部来源，漏了就少算。
- **两个键都要查**：只查 `P[r]` 会漏掉所有「长度偶数、多出那一个比 `k` 大的元素」的情况。
- 依赖「`nums` 是 `1..n` 的排列」⇒ `k` **唯一**，才能用单个分割点 `m` 把左端点的合法范围一次性框死。

## 三、代码实现

### 最终代码

```python
from typing import List
from collections import defaultdict


class Solution:
    def countSubarrays(self, nums: List[int], k: int) -> int:
        ans = s = 0
        cnt = defaultdict(int)
        cnt[0] = 1          # 空前缀
        flag = False        # 是否已经越过 k 的位置
        for x in nums:
            if x < k:
                s -= 1
            elif x > k:
                s += 1
            else:                       # x == k：前缀和不变，从此刻起开始统计
                flag = True
            if not flag:
                cnt[s] += 1              # k 之前：只建表，不统计
            else:
                ans += cnt[s] + cnt[s - 1]   # k 及之后：查两个键
        return ans
```

> 截图里只有 `class Solution`，`from typing import List` 与 `from collections import defaultdict` 是补的。

## 四、复杂度分析

| 版本 | 时间复杂度 | 空间复杂度 |
| :--- | :--- | :--- |
| **最终代码** | O(n) | O(n) |
| 朴素解法（枚举 + 排序） | O(n³ log n) | O(n) |
| 朴素解法（枚举 + 计数） | O(n²) | O(1) |
| 理论下界 | O(n) | O(n) |

> 复杂度中的 n 指数组 `nums` 的长度。哈希表的键是前缀和，取值落在 `[-n, n]`，最坏有 Θ(n) 个不同键。

## 五、优化评估

**结论**：时间复杂度 O(n) 已达理论下界，**时间无优化空间**；空间是 O(n) 的计数表，量级不可避免，只剩实现层面的常数差。

### 瓶颈分析

一遍扫描里每个位置做 O(1) 次的加减与两次哈希查表，总时间 O(n)；空间全部来自「左端点前缀和 → 出现次数」这张表，最多 n+1 次插入。

### 可优化空间

- **时间**：任何解法都必须至少扫一遍数组（否则无法定位 `k`、也无法统计跨 `k` 的子数组组合），所以 Ω(n) 无法突破。
- **空间**：前缀和的值域是已知的 `[-n, n]`，理论上可以用定长数组代替哈希表来做计数 —— 大 O 不变，但省掉了哈希函数与探测的开销。不过这属于常数级改动，且需要额外偏移量（`+n`）处理负下标。

### 常数级优化（可选）

把 `defaultdict` 换成 `list`（长度 `2n+1`，用 `s + n` 当索引）可避免哈希查表；但可读性下降，且本题 `n ≤ 10^5` 时哈希表本来就够快。日常提交保持哈希表版本更不容易写错。

## 六、易错点与总结

### 易错点

- **忘了用 `flag` 限制建表范围**：如果把所有前缀和都记进表里，扫到 `k` 之后就会把**不含 `k`** 的子数组也计入（它们的 `g-l` 同样可能是 0 或 1），答案系统性偏大。这是本题最容易翻车的地方。
- **只查 `cnt[s]` 漏掉 `cnt[s-1]`**：`g-l = 1`（长度为偶数、比 `k` 大的多一个）这一支全部丢失。
- **漏写 `cnt[0] = 1`**：所有从下标 0 开始的合法子数组都会少算。
- **把偶数长度的规则记反**：题目规定取「中间靠左」，所以是 `g = l + 1` 合法；若取靠右，合法的差分就变成 `{0, -1}`，整道题的符号要一起翻。
- **`k` 的贡献必须为 0**：`else`（`x == k`）分支里不能对 `s` 做任何加减，一旦把 `k` 也并进 `+1` 那一支，前缀和全部偏移，答案必错。
- **重复元素假设失效**：本题靠「`k` 唯一出现」才敢用单一分割点 `m`；若 `k` 出现多次，需要改成「记录每个 `k` 位置」的更复杂版本。

### 题型套路沉淀

- **值域映射成 ±1，把「中位数 / 众数 / 多数」类判定变成区间和**：这类题（中位数、是否过半数、括号平衡）都先把元素压成 `{+1, 0, -1}`，条件通常落成「区间和属于某个小集合」。
- **前缀和 + 哈希计数（键 = 前缀值，值 = 出现次数）**：右端点一次扫描，左端点用表 O(1) 反查。目标值有多个时就把多个 `cnt[…]` 相加，本题是 `cnt[s] + cnt[s-1]`。
- **把「必须包含某个特殊元素」编码进表的构造里**，而不是在判定里额外加条件：先用特殊位置把数组切成前后两段，只把**前半段**的前缀和放进表，约束就自动成立。这个技巧比每次去检查 `l ≤ m ≤ r` 干净得多。
- **`defaultdict` 查不到自动建键**：在「只查不写」的阶段用 `defaultdict` 会悄悄污染结构，本题因为写入的默认值是 0 所以结果不受影响；若默认值非 0 或后续要区分「出现过 / 没出现过」，应改用 `dict.get(key, 0)`。
