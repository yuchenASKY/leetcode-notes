# 3583. 统计特殊三元组

> **难度**：中等
> **标签**：数组 · 哈希表 · 计数
> **原题链接**：https://leetcode.cn/problems/count-special-triplets/

---

## 一、题目描述

给定整数数组 `nums`，统计满足 `i < j < k` 且 `nums[i] == nums[j] * 2`、`nums[k] == nums[j] * 2` 的下标三元组 `(i, j, k)` 个数，结果对 `10^9 + 7` 取模。

注意两个条件都挂在中轴 `j` 上：`i` 和 `k` 处的值必须**都**等于 `nums[j] * 2`，也就是 `nums[i] == nums[k]`。

### 示例

```text
输入：nums = [6,3,6]
输出：1
解释：唯一的三元组是 (0,1,2)：nums[0] = 6 = 3*2，nums[2] = 6 = 3*2

输入：nums = [0,1,0,0]
输出：1
解释：唯一的三元组是 (0,2,3)，三者都是 0 —— 2*0 仍然是 0

输入：nums = [8,4,2,8,4]
输出：2
解释：(0,1,3) 与 (1,2,4)
```

### 约束条件

- `3 <= n == nums.length <= 10^5`
- `0 <= nums[i] <= 10^5`

---

## 二、解题思路

### 核心思想

**枚举中轴 `j`，把左右两侧独立计数后相乘。** 对固定的 `j`，合法三元组数 = （`j` 左侧值为 `2 * nums[j]` 的元素个数）× （`j` 右侧值为 `2 * nums[j]` 的元素个数）—— 因为 `i` 和 `k` 的取值彼此无关，只由「在谁左边 / 右边」决定，是标准的乘法原理。

### 思路演进

1. **暴力解法**：三重循环枚举 `i < j < k`，逐组校验两个等式。时间 O(n³)，n = 10^5 时是 10^15 量级，完全不可行。
2. **降一维**：固定 `j` 后，另外两个下标要满足的条件只剩「值等于 `2 * nums[j]`」。于是问题退化成两次**计数**，而不是两次枚举 —— 只要知道左右两侧各有多少个 `2 * nums[j]` 即可。但每换一个 `j` 都重新遍历左右两侧，仍然是 O(n²)。
3. **优化为**：注意到 `j` 是从左往右逐个移动的，左右两侧的计数可以**增量维护**：一开始把整个数组的频率表当作「右侧」，`j` 前移时把 `nums[j]` 从右侧扣掉、算完答案后加进左侧。这样每个 `j` 的查询都是 O(1) 的哈希查表，总时间 O(n)。

### 关键点

- **顺序不能乱**：进入 `j` 这一轮，必须先把 `nums[j]` 从后缀表里减去（此时它既不属于左侧，也不属于右侧），否则 `j` 自己会被当成合法的 `k`，答案虚增。
- **两侧要分开维护两张表**，不能只用一张全量频率表。三元组的合法性依赖下标先后，全量计数丢掉了「在左还是在右」这个信息。
- **乘法原理是这题的核心**：一旦确认 `i` 与 `k` 的约束彼此独立，就不用真的配对，直接乘起来即可 —— 这一步把 O(n²) 的组合枚举变成了 O(1) 的算术。
- **`0` 是真正的边界**：`2 * 0 == 0`，所以值为 0 的元素可以自己和自己构成三元组（示例 2）。任何「假定值都是正数」的写法都会在这里翻车。
- 查 `2 * x` 时不必判断是否越界：哈希表 miss 返回 0，天然安全。

## 三、代码实现

### 最终代码

```python
from typing import List
from collections import Counter, defaultdict


class Solution:
    def specialTriplets(self, nums: List[int]) -> int:
        MOD = 1_000_000_007
        suf = Counter(nums)        # 右侧待选区：初始为整个数组
        pre = defaultdict(int)     # 左侧已选区
        ans = 0

        for x in nums:             # x 充当三元组的中轴 nums[j]
            suf[x] -= 1            # 先把 j 自身摘出去，它不属于任何一侧
            ans += pre[x * 2] * suf[x * 2]
            pre[x] += 1            # 处理完再归入左侧，供后面的 j 使用

        return ans % MOD
```

> 截图里的代码没有写 `import`，此处已补上 `List` / `Counter` / `defaultdict`。

## 四、复杂度分析

| 版本 | 时间复杂度 | 空间复杂度 |
| :--- | :--- | :--- |
| **最终代码** | O(n) | O(n) |
| 朴素解法（三重循环枚举） | O(n³) | O(1) |
| 朴素解法（固定 j 后左右各扫一遍） | O(n²) | O(1) |
| 理论下界 | O(n) | O(n) |

> 复杂度中的 n 指数组 `nums` 的长度。空间项取 O(n) 是宽松上界，实际只与「不同取值的数量」成正比。

## 五、优化评估

**结论**：时间复杂度已是理论下界，**没有进一步优化的必要**。

### 瓶颈分析

每个元素都必须至少被检查一次，否则可能漏掉以它为 `i`、`j` 或 `k` 的三元组，因此 O(n) 是时间下界。当前实现只对每个元素做常数次哈希查表与自增，已经贴着这个下界跑。

空间上，两张表存的都是「值 → 出现次数」，条目数不超过不同取值的个数；在本题 `nums[i] <= 10^5` 的值域下，这个数量是有界的。

### 可优化空间

时间上不存在更优解：本题没有任何可以跳过元素的单调性或有序性可以利用，输入无序、条件也不是区间型的，只能逐个元素过一遍。

空间上若不追求通用性，可以利用值域上界把哈希表换成定长数组（下标即值），查询变成纯下标访问；但这把空间绑死在值域大小上，属于「用已知值域换常数」的取舍，大 O 并不改变。

## 六、易错点与总结

### 易错点

- **忘了先扣掉中轴自己**：`suf[x] -= 1` 如果写在计数之后，当前 `j` 会被同时算进右侧，`pre[x*2] * suf[x*2]` 里凭空多出一批非法组合。
- **`0` 的倍数关系**：`2 * 0 == 0`，全 0 数组（如 `[0,0,0]`）答案是 1，不是 0。任何「`nums[j] * 2 > nums[j]` 所以可以只往大处找」的推理都会在这里出错。
- **左右不分**：只维护一张全量 `Counter` 会丢掉下标先后信息，把 `k < j` 的非法组合也数进去。
- **取模位置**：只在最后 `% MOD` 不影响正确性（Python 整数不会溢出），但混着写「中途取模 + 最后不取」容易漏；保持一次统一取模最稳妥。
- `defaultdict` 在查询未命中的键时会插入一个 0，多出若干无意义键 —— 不影响正确性，但知道这点可以避免误以为「表变大了就是逻辑写错」。

### 题型套路沉淀

- **三元组计数 → 枚举中轴**：当两个约束都挂在同一个中间元素上（`nums[i] == nums[k] == f(nums[j])`）时，枚举 `j`，左右两侧的计数彼此独立，直接相乘。这把「枚举三个下标」降到「枚举一个下标 + O(1) 查表」。
- **前缀/后缀计数对**：凡是「左边有多少个 X、右边有多少个 Y」这类问题，都用「初始全量后缀 + 边扫边搬」的模式增量维护，避免每个位置重扫。
- **乘法原理优先于枚举**：只要两组选择互不影响，答案就是两个计数的**乘积**而不是配对过程；看到「统计组合数」先问一句「能不能拆成独立的两半」。
- 配套提醒：涉及「计数 + 下标先后」的题，`defaultdict` / `Counter` 的**扣减时机**（处理前 / 处理后）是固定易错位，写完先拿 `[0,1,0,0]` 这类含重复值和 0 的小数据过一遍。
