# 2711. 对角线上不同值的数量差

> **难度**：中等
> **标签**：数组 · 哈希表 · 矩阵
> **原题链接**：https://leetcode.cn/problems/difference-of-number-of-distinct-values-on-diagonals/

---

## 一、题目描述

给定一个 `m x n` 的矩阵 `grid`，要求返回同样大小的答案矩阵 `answer`。对每个格子 `(r, c)`：

- `topLeft[r][c]`：该格子**左上对角线**上（不含自身）**不同值**的个数；
- `bottomRight[r][c]`：该格子**右下对角线**上（不含自身）**不同值**的个数；
- `answer[r][c] = |topLeft[r][c] - bottomRight[r][c]|`。

这里的「对角线」是**左上 → 右下（↘）**方向的斜线，即 `r - c` 相同的那些格子。

### 示例

```text
输入：grid = [[1,2,3],[3,1,5],[3,2,1]]
输出：[[1,1,0],[1,0,1],[0,1,1]]
解释：
- (0,0)：右下对角线为 [1]（即 grid[1][1]），左上对角线为空 → |1 - 0| = 1
- (1,2)：右下对角线为空，左上对角线为 [2]（即 grid[0][1]） → |0 - 1| = 1
- (1,1)：右下为 [1]（grid[2][2]），左上为 [1]（grid[0][0]） → |1 - 1| = 0

输入：grid = [[1]]
输出：[[0]]
解释：(0,0) 两侧都为空 → |0 - 0| = 0
```

### 约束条件

- `m == grid.length`，`n == grid[i].length`
- `1 <= m, n, grid[i][j] <= 50`

---

## 二、解题思路

### 核心思想

**同一条对角线上的所有格子共享同一批元素**，所以别按格子逐个重扫 —— 把矩阵按对角线分组（`r - c` 恒定），沿每条对角线一次性把「左上不同值数」和「右下不同值数」算出来。

### 思路演进

1. **暴力解法**：对每个格子 `(r, c)`，分别向左上 `(r-1, c-1), (r-2, c-2), ...` 和向右下 `(r+1, c+1), ...` 走一遍，边走边塞进 `set`，最后取两个集合大小之差的绝对值。单格 O(min(m, n))，总计 O(m·n·min(m,n))。

2. **观察到**：格子 `(r, c)` 的左上对角线，正好就是「同一条斜线上排在它前面的那些格子」；右下对角线是「排在它后面的那些格子」。同一条斜线被反复扫描了 L 次（L 为该斜线长度），大量工作完全重复。

3. **优化为**：按对角线分组，一条斜线只处理一次。先用 `k` 编号斜线（`k = (r - c) + n`，取值 `1 .. m+n-1`），对斜线上的每个格子，前缀集合给 `topLeft`、后缀集合给 `bottomRight`。当前代码就是这一层：**分组已经做了，但每个格子的前后缀集合仍然从头重新收集**，所以每条斜线还是 O(L²)。

4. **再进一步**（见「五、优化评估」）：前缀/后缀的「不同值个数」本身可以增量维护，正反各扫一遍就能把每条斜线压到 O(L)，总复杂度降到 O(m·n)。

### 关键点

- **对角线判据是 `r - c` 恒定**，不是 `r + c` 恒定。写成 `r + c` 统计的是另一组斜线（↙↗ 方向），示例 1 立刻就对不上。
- `topLeft` / `bottomRight` **不含当前格子**。包含自身会让示例 2 输出 `1` 而不是 `0`。
- 斜线的起止边界：编号为 `d = r - c` 的斜线，起点在 `(max(d, 0), max(-d, 0))`，走到越界为止。当前代码把「列」当循环变量 `j`，行由 `k - n + j` 反推，等价但要多做一次换算。
- 长度 1 的斜线（只有 `(0,0)` 或角上的孤立格）两侧集合都为空，答案自然是 0。

## 三、代码实现

### 最终代码

> `from typing import List` 截图里没有、已补（LeetCode 环境预置，本地跑需要显式导入）。

```python
from typing import List

class Solution:
    def differenceOfDistinctValues(self, grid: List[List[int]]) -> List[List[int]]:
        m = len(grid)
        n = len(grid[0])
        ans = [[0 for _ in range(n)] for _ in range(m)]

        # k 编码斜线：斜线上第 j 列的格子行号为 k - n + j，即 r - c = k - n
        # 因而 k 的取值范围是 1 .. m + n - 1
        for k in range(1, m + n):
            min_j = max(0, n - k)                  # 该斜线最左的列下标（行号为 0 或列号为 0 的那端）
            max_j = min(n - 1, m + n - k - 1)      # 该斜线最右的列下标
            for j in range(min_j, max_j + 1):
                temp1 = 0
                seen1 = set()
                temp2 = 0
                seen2 = set()

                # 严格左上：同一斜线上列号 < j 的部分
                for i in range(min_j, j):
                    if grid[k - n + i][i] not in seen1:
                        temp1 += 1
                        seen1.add(grid[k - n + i][i])

                # 严格右下：同一斜线上列号 > j 的部分
                for i in range(j + 1, max_j + 1):
                    if grid[k - n + i][i] not in seen2:
                        temp2 += 1
                        seen2.add(grid[k - n + i][i])

                ans[k - n + j][j] = abs(temp1 - temp2)

        return ans
```

## 四、复杂度分析

| 版本 | 时间复杂度 | 空间复杂度 |
| :--- | :--- | :--- |
| **最终代码**（按斜线分组，但每格重扫前后缀） | O(m·n·min(m,n)) | O(m·n) 答案矩阵 + O(min(m,n)) 辅助集合 |
| 逐格独立暴力（每格各走两遍斜线） | O(m·n·min(m,n)) | O(m·n) + O(min(m,n)) |
| 两次扫描（前后缀增量维护） | O(m·n) | O(m·n) + O(min(m,n)) |

> 复杂度中的 `m`、`n` 分别指矩阵 `grid` 的行数与列数；`min(m, n)` 是单条斜线长度的上界（格子数最多的那条）。答案矩阵本身占 `m·n` 个格子，所以时间下界是 O(m·n)。

本题 `m, n <= 50`，最坏情形约 `50 × 50 × 50 = 1.25 × 10^5` 量级的元素访问，实测远低于时限，最终代码在这个数据范围内完全够用。

## 五、优化评估

**结论**：在 `m, n <= 50` 的约束下**已足够**；但从量级上看，`min(m, n)` 这个因子是可以消掉的，存在 O(m·n) 的写法。

### 瓶颈分析

时间花在「同一批元素被反复重新装进集合」：一条长度 L 的斜线，被它的 L 个格子各扫一遍前后缀，单条斜线累计 O(L²)，所有斜线加起来约 O(m·n·min(m,n))。而 `topLeft` 沿斜线前进时只会**单调增**（加入新元素，不同值数只会涨或不变），完全不需要每次重算。

### 可优化空间

把斜线取出来存成数组后，**正向扫一遍**得到每个位置的「严格左上不同值数」（就是进入该位置前 `len(seen)`），**反向扫一遍**得到「严格右下不同值数」（进入该位置前 `len(seen)`）。每个格子 O(1)，每条斜线两趟，总时间 O(m·n)。

### 优化代码

```python
from typing import List

class Solution:
    def differenceOfDistinctValues(self, grid: List[List[int]]) -> List[List[int]]:
        m, n = len(grid), len(grid[0])
        ans = [[0] * n for _ in range(m)]

        # 按斜线编号 d = r - c 分组，d ∈ [-(n-1), m-1]
        for d in range(1 - n, m):
            cells = []
            r = max(d, 0)          # 起点：行号为 0 或列号为 0 的那端
            c = r - d
            while r < m and c < n:
                cells.append((r, c))
                r += 1
                c += 1

            L = len(cells)
            pre = [0] * L          # pre[i] = 严格左上方的不同值个数
            seen = set()
            for i in range(L):
                pre[i] = len(seen)         # 先取计数，再加自己 → 天然不含自身
                seen.add(grid[cells[i][0]][cells[i][1]])

            seen.clear()
            for i in range(L - 1, -1, -1):
                r, c = cells[i]
                ans[r][c] = abs(pre[i] - len(seen))   # 此时 seen 是严格右下方
                seen.add(grid[r][c])

        return ans
```

**优化理由**：`topLeft`/`bottomRight` 的定义是「严格一侧的不同值个数」，而 `len(set)` 在逐个 `add` 的过程中天然就是「目前已见过的不同值个数」。只要控制「取计数」与「加自己」的先后顺序，就同时解决了「去重计数」和「不含自身」两件事，省掉了每格重扫。

### 常数级优化（可选）

- `if x not in seen: temp += 1; seen.add(x)` 三个动作可以压成 `seen.add(x); temp = len(seen)` —— 集合自己就是去重计数器，省掉一次查找和一次自增。
- 值域很小（`grid[i][j] <= 50`），把 `set` 换成定长计数数组 `cnt = [0] * 51`，配合「首次出现才把计数 +1」的逻辑，常数更小且无哈希开销。
- 斜线编号直接用 `d = r - c`，起点 `(max(d, 0), max(-d, 0))`；最终代码那套 `k = (r - c) + n` 的编码虽然正确，但每取一个格子都要做 `k - n + i` 的换算，可读性与开销都不如直接用 `d`。

## 六、易错点与总结

### 易错点

- **对角线方向写反**：本题是 `r - c` 恒定（↘ 方向）。写成 `r + c` 恒定会统计另一组斜线，示例 1 直接不匹配。
- **统计区间包含自身**：`topLeft`/`bottomRight` 都是**严格**的。若把当前格子算进去，示例 2 会输出 `1`（正确是 `0`）。
- **斜线边界算错**：编号 `d` 的斜线不是从 `(0, d)` 开始 —— `d < 0` 时行号为 0 的格子在负列上，真正起点是 `(0, -d)`。用 `max(d, 0)` 取行、`max(-d, 0)` 取列才不会越界或漏格。
- **少枚举斜线**：`d` 的范围是 `[-(n-1), m-1]` 共 `m + n - 1` 条，写成 `[0, m+n-1)` 会漏掉左下角和右上角那几条短斜线。
- **`min` / `max` 混用**：列下界是 `max(0, ...)`、列上界是 `min(n-1, ...)`，两者写反会导致 `range` 为空、整张答案矩阵全是 0。

### 题型套路沉淀

- **斜线分组模板**：`d = r - c` 编号 ↘ 方向斜线（`r + c` 编号 ↙ 方向），起点 `(max(d,0), max(-d,0))`，沿 `r += 1, c += 1` 走到越界。凡「按对角线/反对角线做的事」，先用这套骨架把格子捞成数组。
- **前缀 + 后缀双扫**：一个格子要同时用「左边一段」和「右边一段」的统计量时，标准动作是——正向扫一遍存前缀结果，反向扫一遍存后缀结果，再合并。反向扫时 index 从 `L-1` 往 `0` 走，且**先取计数、再加自己**，才能保证「不含自身」。
- **网格题先想「按线分组」再想「逐格」**：一旦发现同一个统计量在同一条线上被重复计算，就该把线抽出来当一维数组处理，往往能消掉一个维度带来的因子。
