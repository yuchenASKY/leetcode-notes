# 1512. 好数对的数目

> **难度**：简单
> **标签**：数组 · 哈希表 · 计数
> **原题链接**：https://leetcode.cn/problems/number-of-good-pairs/

---

## 一、题目描述

给定一个整数数组 `nums`。若一组数字 `(i, j)` 满足 `nums[i] == nums[j]` 且 `i < j`，则称它为一组**好数对**。返回数组中好数对的数目。

### 示例

```text
输入：nums = [1,2,3,1,1,3]
输出：4
解释：有 4 组好数对，分别是 (0,3), (0,4), (3,4), (2,5)，下标从 0 开始

输入：nums = [1,1,1,1]
输出：6
解释：数组中的每组下标对都是好数对（4 个 1 任取 2 个 = C(4,2) = 6）
```

### 约束条件

- `1 <= nums.length <= 100`
- `1 <= nums[i] <= 100`

---

## 二、解题思路

### 核心思想

**把「两两配对」改成「每个新元素只和它左边同值元素配对」。** 用哈希表记录每个值在**前缀**里出现过几次，扫到一个 `x` 就把它前面已有的 `cnt[x]` 组配对一次性结算掉。

### 思路演进

1. **暴力解法**：双重循环枚举 `i < j` 全部下标对，`nums[i] == nums[j]` 就 `ans += 1`。时间是 C(n,2) = n(n-1)/2，n = 100 时约 4950 次比较 —— 本题能过，但这是因为它小，不是因为这样对。
2. **观察到**：同一组的配对其实不需要重复枚举。扫到下标 `j` 时，能与它配成好数对的 `i` 恰好是**它左边所有等于 `nums[j]` 的下标**，数量就是该值在前缀中已出现的次数。
3. **优化为**：一次遍历，`cnt` 维护「值 → 此前出现次数」。每读到一个 `x`，`ans += cnt[x]`（结算它与左侧同值元素构成的所有配对），再把 `cnt[x] += 1`（把自己计入前缀）。总数不变，但从"枚举配对"变成"结算贡献"，两层循环塌缩成一层。

> 两种口径完全等价：最终答案 = Σ<sub>x</sub> C(freq(x), 2) = Σ<sub>x</sub> freq(x)·(freq(x)−1)/2，只是「按出现次数成对计算」被拆成了「每步累加一次」。

### 关键点

- **先累加、后自增**（`ans += cnt[x]` 再 `cnt[x] += 1`）。顺序反了就把自己算进了自己的配对里，多出一倍。
- **首次出现时计数要一次性置为 1**，不能从 0 开始"两边都从 0 涨"。若写成本次读完才统一 `+1` 且初值为 0，第 k 次出现只会贡献 k−1 的前提就被破坏，答案会整体偏小。
- 本题值域只有 `1..100`，用哈希表其实是"杀鸡用牛刀"；但代码不依赖值域，改值域上限也无需改逻辑 —— 这是选择 `dict` 的理由（见第五节）。

---

## 三、代码实现

### 最终代码

```python
class Solution:
    def numIdenticalPairs(self, nums: list[int]) -> int:
        cnt = {}        # 值 -> 该值在前缀中已出现的次数
        ans = 0
        for i in nums:
            if i not in cnt:
                cnt[i] = 1          # 首次出现：此后它左侧同值元素有 1 个
            else:
                ans += cnt[i]       # 先结算：与左侧每个同值元素各成一好数对
                cnt[i] += 1         # 后自增：把自己计入前缀
        return ans
```

> 截图里的代码没有 `import`，本题也用不到（`list[int]` 是内置泛型，Python 3.9+ 直接可用），无需补。

## 四、复杂度分析

| 版本 | 时间复杂度 | 空间复杂度 |
| :--- | :--- | :--- |
| **最终代码** | O(n) | O(k)，k 为不同取值个数（本题 ≤ 100） |
| 朴素解法 | O(n²) | O(1) |
| 理论下界 | O(n) | O(1) |

> 复杂度中的 n 指数组 `nums` 的长度；k 指数组中不同数值的个数。
> 本题 k 有上界 100，因此空间可视为 O(1)；若值域不设限（如 `nums[i]` 可取任意 int），空间就是 O(k) 且最坏 O(n)。

## 五、优化评估

**结论**：时间复杂度已是理论下界 O(n)，**空间在本题值域下有常数级替代方案**，但意义有限。

### 瓶颈分析

时间全花在遍历 n 个元素上 —— 任何算法都至少要读一遍数组才能知道有哪些数，所以 O(n) 不可再降。每个元素只做一次哈希查找和一次自增，两步都是 O(1) 平摊，没有嵌套的重活。

空间侧的压力来自 `dict`：它要为每个不同的值存一个键值对，还要承担哈希表本身的装载开销。

### 可优化空间

只有当**值域很小且已知**时才有替代空间：

- 本题 `1 <= nums[i] <= 100`，可以开一个长度 101 的 `list` 当计数表，下标即数值，把 `dict` 换成数组。这样空间是**固定的 101 个槽位**，与 n 无关，也不再走哈希。
- 但要注意：这个替换的合法性完全来自"值域有上界"这一条题目条件。换一道 `nums[i]` 可达 `10^9` 的题，开数组就直接爆空间，必须老老实实用哈希表。

因此结论是：**当前写法是通用形态，数组写法是本题条件下的特化形态**，两者时间复杂度相同，选哪个取决于值域是否可预知。

### 优化代码

```python
class Solution:
    def numIdenticalPairs(self, nums: list[int]) -> int:
        cnt = [0] * 101         # 依赖 1 <= nums[i] <= 100
        ans = 0
        for x in nums:
            ans += cnt[x]
            cnt[x] += 1
        return ans
```

**优化理由**：值域有界 ⇒ 计数表可以定长预分配，下标直接对应数值，省掉哈希映射这一层。同时这个版本把「首次出现」的分支也消掉了 —— 数组初值 0 天然表示"还没出现过"，统一写成 `ans += cnt[x]; cnt[x] += 1` 即可，少一个 `if`。（原版 `if/else` 的结构性冗余，正是这里顺带解决的。）

### 常数级优化（可选）

- 若只需要最终数量而不关心中途前缀，也可以先完整统计频次，再用公式 `Σ f*(f-1)//2` 一次算出。两趟遍历、写法更贴近数学定义，适合推导时校验答案。
- `ans += cnt[x]` 与 `cnt[x] += 1` 的顺序不能交换，任何"简化"都不得破坏这一点。

## 六、易错点与总结

### 易错点

- **先增后加**：写成 `cnt[i] += 1; ans += cnt[i]`（或在增量版里把两行调序），会把自己算进配对，答案偏大。
- **分支里初值写错**：`if i not in cnt: cnt[i] = 1` 这一支不累加时，必须把计数置为 **1** 而不是 0/略过，否则后续每个元素的贡献都少 1。原代码这里是对的，但这是本写法唯一一处"看着像初始化、其实参与计数"的隐蔽点。
- **双计**：把 `(i, j)` 和 `(j, i)` 各算一次会得到 2 倍答案。题目要求 `i < j`，本文的"只与左侧配对"天然满足。
- **答案类型**：本题 n ≤ 100，答案最大 C(100,2) = 4950，`int` 足够。若同类题 n 放大到 `10^5`，答案量级到 `5×10^9`，C++/Java 需用 64 位整型（Python 无此问题）—— 这是把本题思路迁移到大数据题时最容易漏的一条。

### 题型套路沉淀

- **计数贡献法模板**：`for x in nums: ans += cnt[x]; cnt[x] += 1`。适用于一切「求满足等值条件的下标对数」。它与公式 `Σ C(f,2)` 等价，区别只是"边扫边结算"还是"先统计后套公式"。
- **看到「下标对 / 组数 / 对数」先想前缀**：把 O(n²) 的两两枚举，改写成"当前元素与前缀的交互"，通常就能降到 O(n)。判据是**配对条件只依赖元素值、不依赖两个下标的相对位置之外的东西**。
- **值域是否可预知，决定用数组还是哈希表**：做题时先看约束里的数据范围；有上界且不大就定长数组，否则哈希表。别把"数组代替哈希"当成无条件成立的技巧。
