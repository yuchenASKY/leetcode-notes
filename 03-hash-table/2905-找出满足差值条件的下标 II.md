# 2905. 找出满足差值条件的下标 II

> **难度**：中等
> **标签**：数组 · 哈希表
> **原题链接**：https://leetcode.cn/problems/find-indices-with-index-and-value-difference-ii/

---

## 一、题目描述

给定长度为 `n` 的整数数组 `nums`，以及两个整数 `indexDifference`、`valueDifference`。要求在下标区间 `[0, n-1]` 内找出一对下标 `i`、`j`，同时满足：

- `abs(i - j) >= indexDifference`
- `abs(nums[i] - nums[j]) >= valueDifference`

找到任意一组即可（`i` 和 `j` 允许相等），无解返回 `[-1, -1]`。

### 示例

```text
输入：nums = [5,1,4,1], indexDifference = 2, valueDifference = 4
输出：[0,3]
解释：abs(0-3) = 3 >= 2，abs(nums[0]-nums[3]) = abs(5-1) = 4 >= 4，成立。

输入：nums = [2,1], indexDifference = 0, valueDifference = 0
输出：[0,0]
解释：abs(0-0) >= 0 且 abs(2-2) = 0 >= 0；此时 i 与 j 相等也合法。

输入：nums = [1,2,3], indexDifference = 2, valueDifference = 4
输出：[-1,-1]
解释：下标差至少为 2 的只有 (0,2)，差值为 |1-3| = 2 < 4，无解。
```

### 约束条件

- `1 <= n == nums.length <= 10^5`
- `0 <= nums[i] <= 10^9`
- `0 <= indexDifference <= 10^5`
- `0 <= valueDifference <= 10^9`

## 二、解题思路

### 核心思想

**固定右端点 `i` 后，合法的 `j` 恰好构成一个只会变长的前缀；而值差这个阈值条件只需要看该前缀的最大值和最小值。** 于是把二维枚举压成一维扫描 + 两个极值变量。

### 思路演进

1. **暴力解法**：双重循环枚举所有 `(i, j)`，两条件都满足就返回。时间 O(n²)，n 到 10^5 时是 10^10 量级，必超时。

2. **观察到**：条件 `abs(i - j) >= indexDifference` 里，只要限定 `j <= i`（对称性保证另一端不必单独枚举），它就退化成 `j <= i - indexDifference`。也就是说，**对固定的 `i`，所有可选 `j` 就是前缀 `[0, i - indexDifference]`**。而随着 `i` 从 `indexDifference` 递增到 `n-1`，这个前缀每次只**向右扩一个元素** —— 只增不减，天然适合增量维护。

3. **关键转化**：剩下的条件 `abs(nums[i] - nums[j]) >= valueDifference` 看似要对前缀里的每个值逐个判断，其实只需两个数：
   - 若存在某个 `j` 使 `nums[j] - nums[i] >= valueDifference`，那么**前缀最大值** `mx` 必然也满足；
   - 若存在某个 `j` 使 `nums[i] - nums[j] >= valueDifference`，那么**前缀最小值** `mi` 必然也满足。

   绝对值的两个方向，正好分别对应前缀的最大端和最小端。因此每步只要 `abs(nums[i] - mi)` 和 `abs(nums[i] - mx)` 各试一次就能判定有无解。

4. **优化为**：`i` 从 `indexDifference` 开始遍历，每轮先把下标 `i - indexDifference` 这个新元素并入候选前缀（同时更新 `mi`、`mx` 及其下标），再用两个极值判定。全程一趟线性扫描。

### 关键点

- **不变式**：进入第 `i` 轮循环时，候选集恰好是下标 `[0, i - indexDifference]`。因为每轮只并入一个新下标、从不删除，所以 `mi`/`mx` 可以 O(1) 增量更新，不必重新扫描前缀。
- **`mi`/`mx` 足够的原因**：判定条件只和「差得够不够大」有关，与具体是哪个 `j` 无关；极值一端就代表了该方向上能取到的最大差值。
- **要同时记住极值对应的下标**：题目返回的是下标而不是值，所以维护 `(mi, mi_idx)`、`(mx, mx_idx)` 成对出现。
- **多解任取**：题目明确说「存在多组时返回任意一组」，因此一旦命中就立刻返回，不需要枚举完再挑。
- **`indexDifference == 0` 时 `j` 可以等于 `i`**：此时候选前缀包含 `i` 本身，与题目「`i` 和 `j` 可能相等」的说明一致。

## 三、代码实现

### 最终代码

> 截图里没有 `from math import inf` 与 `from typing import List`，**已补**。

```python
from math import inf
from typing import List


class Solution:
    def findIndices(self, nums: List[int], indexDifference: int,
                    valueDifference: int) -> List[int]:
        n = len(nums)
        cnt1 = {}          # 值 -> 该值首次出现的下标
        cnt2 = {}
        mi = inf           # 候选前缀中的最小值
        mx = 0             # 候选前缀中的最大值
        for i in range(indexDifference, n):
            # 把下标 i - indexDifference 并入候选前缀
            if nums[i - indexDifference] not in cnt1:
                cnt1[nums[i - indexDifference]] = i - indexDifference
                mi = min(mi, nums[i - indexDifference])
                mx = max(mx, nums[i - indexDifference])
            # 用前缀最小值 / 最大值各试一次
            if abs(nums[i] - mi) >= valueDifference:
                return [cnt1[mi], i]
            if abs(nums[i] - mx) >= valueDifference:
                return [cnt1[mx], i]
        return [-1, -1]
```

## 四、复杂度分析

| 版本 | 时间复杂度 | 空间复杂度 |
| :--- | :--- | :--- |
| **最终代码** | O(n) | O(n) |
| 朴素解法 | O(n²) | O(1) |
| 理论下界 | O(n) | O(1) |

> 复杂度中的 n 指数组 `nums` 的长度。最终代码的时间是 O(n)：每个下标只被并入候选集一次、只被判定一次；空间上 `cnt1` 最坏存下所有互不相同的值，故为 O(n)。

## 五、优化评估

**结论**：时间复杂度已是理论下界，**空间还有压缩到 O(1) 的余地**。

### 瓶颈分析

时间上，任何解法都必须至少看一遍 `nums`（少看一个元素就可能漏解），O(n) 不可突破，当前实现已经到位。

空间上，`cnt1` 承担的唯一职责是回答「`mi` / `mx` 对应的下标是多少」。但这个映射并不需要整张表：`mi`、`mx` 本身只在被更新的那一刻才需要配一个新下标，用两个下标变量同步维护即可。`cnt1` 实际上是把「维护两个极值的下标」放大成了「记录所有出现过的值的下标」。另外 `cnt2` 从头到尾没有被读写，是残留。

### 可优化空间

把 `(值, 下标)` 成对维护成 `(mi, mi_idx)` 和 `(mx, mx_idx)`，候选集里的元素一旦不改变极值就完全不用记住 —— 空间降到 O(1)。

### 优化代码

```python
class Solution:
    def findIndices(self, nums: List[int], indexDifference: int,
                    valueDifference: int) -> List[int]:
        n = len(nums)
        mi = inf
        mx = -inf
        mi_idx = mx_idx = -1
        for i in range(indexDifference, n):
            j = i - indexDifference
            v = nums[j]
            if v < mi:
                mi, mi_idx = v, j
            if v > mx:
                mx, mx_idx = v, j
            if abs(nums[i] - mi) >= valueDifference:
                return [mi_idx, i]
            if abs(nums[i] - mx) >= valueDifference:
                return [mx_idx, i]
        return [-1, -1]
```

**优化理由**：极值是谁、在哪，只需要两个变量就能表达；哈希表在这个场景里没有提供任何额外能力，是可以整体去掉的中间层。同时 `mx` 的初值从 `0` 改成 `-inf`，去掉了对「数组非负」这一前提的隐性依赖。

### 常数级优化（可选）

- `abs(nums[i] - mi) >= valueDifference` 可以拆成 `nums[i] - mi >= valueDifference or mi - nums[i] >= valueDifference` 两个比较，省掉一次函数调用；不过可读性会下降，本题 O(n) 已经很宽裕，不必为此牺牲清晰度。
- 把 `nums` 绑定为局部变量（`a = nums`）后，循环内的下标访问少一层属性查找。
- 由于每轮只并入一个元素，`min()` / `max()` 的调用也可以直接换成 `if` 比较（优化版已这样做）。

## 六、易错点与总结

### 易错点

- **`mx` 的初始哨兵必须是 `-inf`**：写成 `mx = 0` 之所以在这题能过，只因为约束给了 `nums[i] >= 0`；一旦值域含负数，`mx` 会长期停在 0，从而返回一个根本不存在的「最大值 0」及其下标。
- **循环起点少写一格**：`range(indexDifference, n)` 的第一轮对应候选前缀恰好是 `{0}`；若写成 `range(indexDifference + 1, n)`，会漏掉 `j = i - indexDifference` 这个边界，而它恰恰是下标差「刚好等于」`indexDifference` 的唯一合法位置。
- **返回的是下标不是值**：`return [cnt1[mi], i]` 里必须取下标；直接把 `mi` 返回去会错得很隐蔽（`mi` 恰好也是数组里的值）。
- **只维护极值时必须同步维护它的下标**：如果只在极值变化时才更新，忘记更新下标，就会返回一个「值对、位置不对」的答案，且仍然满足值差条件 —— 这种错误不会被值差判断本身发现。
- **`indexDifference == 0` 的边界**：此时 `j = i` 合法，候选集包含当前元素自身，第一轮就会命中，不要想当然地以为 `i != j`。

### 题型套路沉淀

- **「固定一端 → 另一端是前缀 / 后缀」的单调扩张结构**：凡是形如 `|i - j| >= k` 的下标约束，都可以通过固定较大者把可选集合化简成一段前缀（或后缀）。此后只需考虑这段前缀上需要维护什么统计量，而不必枚举元素。
- **阈值型的差值条件只看极值**：`|a - b| >= d` 这类「够不够远」的判断，两个方向分别对应一侧极值，因此维护 `min` / `max` 就等价于维护了全部候选。反之，若条件是「存在某个值恰好等于 `b + d`」这类精确匹配，就必须回到哈希表 —— 区分点是「范围条件」还是「点条件」。
- **哈希表不是越多越好**：先用哈希表把值映射到位置、再反查极值的下标，是常见的绕远路；当需要的只是「某个统计量的伴随信息」时，一个变量比一张表更直接。
- **多解任取的题一律「命中即返回」**，不要为了「找更优的一组」去做无谓的完整搜索。
