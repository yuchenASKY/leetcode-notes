# 3837. 相等元素的延迟计数

> **难度**：中等
> **标签**：数组 · 哈希表
> **原题链接**：https://leetcode.cn/problems/delayed-count-of-equal-elements/

---

## 一、题目描述

给定长度为 `n` 的整数数组 `nums` 和整数 `k`。对每个下标 `i`，延迟计数是满足 `i + k < j <= n - 1` 且 `nums[j] == nums[i]` 的下标 `j` 的个数。要求对所有 `i` 返回延迟计数组成的数组。

换句话说：**只看 i 右侧、且至少隔开 k 个位置（即 j 至少要跳到 i+k+1）的那些元素里，有几个和 `nums[i]` 相等。**

### 示例

```text
输入：nums = [1,2,1,1], k = 1
输出：[2,0,0,0]
解释：
  i=0：合法 j ∈ {2,3}，nums[2]=nums[3]=1，与 nums[0]=1 相等 → 2
  i=1：合法 j ∈ {3}，nums[3]=1 ≠ nums[1]=2 → 0
  i=2、3：i+k 已越过末尾，无合法 j → 0

输入：nums = [3,1,3,1], k = 0
输出：[1,1,0,0]
解释：k=0 时合法区间是 (i, n-1]，即「右侧全部元素」（不含自己）
  i=0：右侧 {1,3,1} 中与 3 相等的有 1 个
  i=1：右侧 {3,1} 中与 1 相等的有 1 个
  i=2、3：右侧无等值元素 → 0
```

### 约束条件

- `1 <= n == nums.length <= 10^5`
- `1 <= nums[i] <= 10^5`
- `0 <= k <= n - 1`

---

## 二、解题思路

### 核心思想

**逆序枚举 + 增量维护一个「后缀频次表」。** 从右往左走，`i` 每左移一格，合法区间只向左侧扩张一个元素 —— 把「重扫一遍后缀」换成「加一个元素进哈希表」。

### 思路演进

1. **暴力解法**：对每个 `i`，内层 `j` 从 `i+k+1` 扫到 `n-1`，逐个比较 `nums[j] == nums[i]` 累加。
   正确但时间 O(n²)：`n = 10^5` 时最坏约 5×10^9 次比较，必然超时。

2. **观察到**：`i` 从 `i` 减到 `i-1` 时，合法区间从 `(i+k, n-1]` 变成 `((i-1)+k, n-1] = (i+k-1, n-1]`。
   两者只差一个元素 —— 新进来的就是 `nums[i+k]`。也就是说，相邻两个 `i` 的查询区间几乎是同一个后缀，唯一变化是左端多包住了一个下标。

3. **优化为**：让 `i` 从右往左枚举，同时维护哈希表 `cnt`，其中 `cnt[v]` = **当前合法区间内值 `v` 出现的次数**。
   走到 `i` 时，`cnt[nums[i]]` 就是答案（O(1) 查询）；随后把 `nums[i+k]` 计入 `cnt`，供下一轮 `i-1` 使用（O(1) 更新）。
   每个下标只被读一次、被计数一次，整体 O(n)。

### 关键点

- **起始下标是 `n-1-k`，不是 `n-1`**：`i > n-1-k` 时 `i+k >= n-1`，合法区间为空，答案必然是 0，而 `ans` 初始化为全 0，直接跳过即可。这也保证了循环里 `i+k <= n-1` 不越界。
- **「先读答案、后加元素」与「先加元素、后读答案」是两套差一位的写法**，必须和起始下标配套，不能混：
  - 先读后加 ⇒ 起点 `n-1-k`，加的是 `nums[i+k]`；
  - 先加后读 ⇒ 起点 `n-1-k-1`，加的是 `nums[i+k+1]`。
  混用会整体错一位（把本该排除的 `nums[i+k]` 算进答案）。
- **区间是严格大于 `i+k`**：`k = 0` 时合法区间是 `(i, n-1]`，**不含自己**；任何写成 `>= i` 的等价变形都会把自己算进去。
- `0 <= k <= n-1` 保证起点非负；`k = n-1` 时区间恒空，答案全 0。

## 三、代码实现

### 最终代码

```python
from typing import List
from collections import defaultdict  # 截图里没有、已补


class Solution:
    def delayedCount(self, nums: List[int], k: int) -> List[int]:
        n = len(nums)
        ans = [0] * n
        cnt = defaultdict(int)          # 当前合法区间 (i+k, n-1] 内各值的出现次数
        for i in range(n - 1 - k, -1, -1):
            ans[i] = cnt[nums[i]]       # 此刻 cnt 统计的恰好是 (i+k, n-1]
            cnt[nums[i + k]] += 1       # nums[i+k] 到下一轮 i-1 才进入合法区间
        return ans
```

## 四、复杂度分析

| 版本 | 时间复杂度 | 空间复杂度 |
| :--- | :--- | :--- |
| **最终代码** | O(n) | O(n) |
| 朴素解法 | O(n²) | O(1) |
| 理论下界 | O(n) | O(n) |

> 复杂度中的 n 指数组 `nums` 的长度；哈希表最多存放 `min(n, 值域)` 个键，本题值域同为 10^5 量级，故记 O(n)。

## 五、优化评估

**结论**：时间复杂度已达理论下界，空间是「计数类」问题绕不开的代价。

### 瓶颈分析

时间上每个下标都必须被看一次（漏看一个就可能漏掉一个等值对），所以 Ω(n) 不可突破；当前每个元素只触发一次哈希查询 + 一次哈希更新，已无重复扫描。

空间上，`cnt` 的大小取决于「后缀里出现过多少种不同的值」，最坏 O(n)。这是必要的：答案依赖「后缀中各值的出现次数」，不记下来就只能回头重扫，时间又会退回 O(n)。

### 可优化空间

时间已无渐近改进空间。空间侧唯一可换的是**容器形态**：`nums[i] <= 10^5` 是有限值域，可以改用定长计数数组做下标寻址，省掉哈希函数与冲突探测的开销；代价是无论实际出现多少种值都要占满值域。属于常数级取舍，不是复杂度改进。

### 常数级优化（可选）

- 用定长 `list` 替代 `defaultdict`（值域已知且较小）：

```python
class Solution:
    def delayedCount(self, nums: List[int], k: int) -> List[int]:
        n = len(nums)
        ans = [0] * n
        cnt = [0] * (max(nums) + 1)     # 值域上界由 max(nums) 决定
        for i in range(n - 1 - k, -1, -1):
            ans[i] = cnt[nums[i]]
            cnt[nums[i + k]] += 1
        return ans
```

- `defaultdict` 在下标读取 miss 时会**静默插入该键**。本题最多插入 `n` 个键、值域也有限，不会造成问题；但若值域极大而实际取值稀疏，这个行为会让内存按「被读过的不同值个数」无谓增长 —— 那种场景应改用 `dict.get`。

## 六、易错点与总结

### 易错点

- **起始下标与「先读/先加」不配套**：`n-1-k` 配「先读后加 `nums[i+k]`」，`n-2-k` 配「先加 `nums[i+k+1]` 后读」。两者等价，混写必然错一位。
- **把 `i+k` 自己也计入答案**：条件是 `i + k < j`，严格大于。`k=0` 时最容易写成包含自身。
- **`i` 只枚到 `n-1-k`**，之后的位置直接依赖 `ans` 的零初始化，不要漏掉 `ans` 的分配（长度必须是 `n`）。
- **越界**：循环内要用到 `nums[i+k]`，只有当 `i <= n-1-k` 时该下标才合法 —— 这正由起始下标保证；若反过来从 `n-1` 开始枚举，第一轮就会越界。
- 截图代码缺 `List` 与 `defaultdict` 的 import（已补），提交前用本地环境跑一下可避免 `NameError`。

### 题型套路沉淀

- **逆序枚举 + 后缀频次表**：当查询区间 `(i+k, n-1]` 随 `i` 单调平移、相邻两轮只差一个元素时，用「一个元素进出表」代替「整段重扫」，是 O(n²) → O(n) 的标准通道。前缀方向的同构写法是「正序枚举 + 前缀频次表」。
- **固定间隔的延迟统计**：题面给出的 `i + k < j` 相当于给每个下标错开一个 `k+1` 的窗口；逆序走时，`nums[i+k]` 天然就是「下一轮刚够格进窗口」的那个元素，用它做增量更新最省心。
- 判断该不该上哈希表的一个快捷问法：**内层循环在数「某种值的出现次数」吗？** 是的话，几乎都能用频次表把它压成 O(1)。
