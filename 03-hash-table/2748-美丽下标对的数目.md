# 2748. 美丽下标对的数目

> **难度**：简单
> **标签**：数组 · 哈希表 · 数学 · 计数
> **原题链接**：https://leetcode.cn/problems/number-of-beautiful-pairs/

---

## 一、题目描述

给定下标从 0 开始的整数数组 `nums`。若下标对 `i < j` 满足 `nums[i]` 的**第一个数字**与 `nums[j]` 的**最后一个数字**互质（`gcd == 1`），则称其为一个**美丽下标对**。返回美丽下标对的总数。

### 示例

```text
输入：nums = [2,5,1,4]
输出：5
解释：五个合法对分别是 (0,1) 2-5、(0,2) 2-1、(1,2) 5-1、(1,3) 5-4、(2,3) 1-4。
      注意 (0,3)：2 与 4 不互质，被排除。
```

```text
输入：nums = [11,21,12]
输出：2
解释：11 的首位 1 与 21 的末位 1、12 的末位 2 都互质，共 2 对。
```

### 约束条件

- `2 <= nums.length <= 100`
- `1 <= nums[i] <= 9999`
- `nums[i] % 10 != 0`（末位数字不会是 0）

---

## 二、解题思路

### 核心思想

**判定只看两个 0~9 的「数字」，与元素本身的大小无关** —— 于是把每个元素压成 `(首位数字, 末位数字)` 两个 digit，再用一张「首位数字 → 出现次数」的计数哈希表，一趟扫描边数边插。

### 思路演进

1. **暴力解法**：双重循环枚举所有 `i < j`，各自取首位与末位、算一次 `gcd`。共 `n(n-1)/2` 对，每对做一次取位 + gcd，时间 O(n²·log C)。`n = 100` 时约 4950 对，能过，但每对都在重复算同一件事。

2. **观察到（关键压缩）**：`gcd` 的入参只有 `nums[i]` 的首位数字和 `nums[j]` 的末位数字，两者都是 **0~9 的单个 digit**。也就是说 `9999` 和 `9` 作为「i 位置的元素」贡献完全相同 —— 元素的身份对判定毫无影响，**只有这两个 digit 有意义**。

3. **转化（固定右端点）**：把当前扫描到的元素当作 `j`，那么要数的就是「它**之前**出现过的元素里，首位数字与 `nums[j]` 的末位互质」的个数。这正好是哈希表最擅长的形式：`cnt[首位数字] = 已出现次数`，把「逐个比较」变成「按首位数字分桶后一次性取和」。

4. **消除重复判定（查表）**：`gcd(a, b)` 的 10×10 种组合是固定的，没必要每对重算一次。预处理一张 `dot[末位] = [所有与它互质的首位数字]`，遍历时只做 `for d in dot[last]: ans += cnt[d]`。

5. **顺序天然满足 `i < j`**：边扫边加，`cnt` 里永远只有当前元素**左侧**的元素，不需要容斥、不需要除以 2，也不会重复计数。

### 关键点

- **两个 digit 的用途不同**：当前元素作为 `j` 时，用它的**末位**去查互质表；而插入哈希表时要用它的**首位**。方向写反是最常见的错。
- **必须先查后插**：先 `ans += cnt[...]`，再 `cnt[首位] += 1`。若先插，当前元素会和自己配成一对（首位与末位恰好互质时），`i < j` 被破坏。
- **首位数字的取法**：`while temp >= 10: temp //= 10`。注意是 `>= 10` 而不是 `> 10`，否则 `10` 会停在 `10` 而不是 `1`。
- **`1` 是万能首位**：`gcd(1, x) == 1` 恒成立，所以首位为 `1` 的元素能和任何末位配对；互质表里首位 `1` 与 `1~9` 全部互质，漏掉它是最隐蔽的失分点。
- 末位为 `0` 的情况本题不会出现（`nums[i] % 10 != 0`），但表里 `dot[0] = [1]` 仍然成立（`gcd(0,1)=1`，`gcd(0,j)=j>1`），所以写法不必为此特判。

## 三、代码实现

### 最终代码

```python
import math
from collections import defaultdict
from typing import List


class Solution:
    def countBeautifulPairs(self, nums: List[int]) -> int:
        # 预处理互质表：dot[末位] = 所有与它互质的首位数字
        dot = defaultdict(list)
        for i in range(10):
            for j in range(10):
                if math.gcd(i, j) == 1:
                    dot[i].append(j)

        ans = 0
        cnt = defaultdict(int)          # 首位数字 -> 已出现次数
        for i in nums:
            temp = i                    # 取首位数字
            while temp >= 10:
                temp //= 10
            last = i % 10               # 取末位数字
            # 当前元素作 j：用末位去查「与它互质的历史首位」
            for j in dot[last]:
                ans += cnt[j]
            cnt[temp] += 1              # 查完再插，保证 i < j
        return ans
```

> 截图里的代码缺少 `math` / `defaultdict` / `List` 三个导入，此处已补全；其余与提交版本一致。

## 四、复杂度分析

| 版本 | 时间复杂度 | 空间复杂度 |
| :--- | :--- | :--- |
| **最终代码** | O(10² + 9n) = O(n) | O(10) = O(1) |
| 朴素解法 | O(n² log C) | O(1) |
| 理论下界 | O(n) | O(1) |

> 复杂度中的 n 指 `nums` 的长度；C 指元素值域（≤ 9999），log C 是单次 `gcd` 的代价。

与朴素解相比，时间从「对数级枚举」降到「元素个数级」，空间只多出两个长度为 10 的小表 —— 因为值域被压成了单个 digit，额外空间与 n 无关，恒为常数。

## 五、优化评估

**结论**：已是最优，时间已达理论下界。

### 瓶颈分析

每扫到一个元素，代价是「取首位 + 取末位 + 至多 9 次哈希查表」，全部是与 n 无关的常数操作乘以元素个数，没有冗余循环，也没有重复的 `gcd` 计算（已被预计算表消掉）。

### 可优化空间

- **时间不可能更好**：每个元素都必须被读一次才能确定它的首位和末位 digit，否则可能漏掉合法对，所以 Ω(n)；当前就是 O(n)。
- **空间不可能更好**：判定所需的全部信息只有 0~9 这 10 个首位数字的计数，信息量固定，O(1) 已到顶。

### 常数级优化（可选）

大 O 相同、只影响常数因子的几处（本题 n ≤ 100，收益很小，仅作写法参考）：

- 把 `cnt` / `dot` 换成定长 `list`（长度 10 的 `[0]*10` / 互质表）。值域已知且不超过 10，`list` 的按下标取值比 `dict` 少一层哈希开销；同时避免 `defaultdict` 在「读」时就插入键的隐式分配。
- 互质表可以在类级别只算一次（提到 `Solution` 外或 `@lru_cache`），而不是每次调用 `countBeautifulPairs` 都重算 10×10 的 `gcd`。
- 取首位数字也可以直接用 `len(str(i))` 配合整除，但字符串构造本身有成本，`while` 除以 10 通常更轻。

## 六、易错点与总结

### 易错点

- **首位 / 末位用反**：当前元素作 `j` 时要用它的**末位**查表，插入哈希表要用它的**首位**。写成 `cnt[last]` 或 `dot[temp]` 会得到看似合理但全错的答案。
- **先插后查**：破坏 `i < j`，会把元素自己和自己的配对也算进去。固定动作是「先 `ans += ...`，后 `cnt[...] += 1`」。
- **取首位的边界写错**：`while temp >= 10` 正确；写成 `while temp > 10` 会让 `10` 的首位变成 `10`。
- **漏掉首位为 1 的贡献**：`1` 与任何数互质，预生成互质表时若按「只保留 2~9」裁剪，会把大量合法对漏掉。
- **误以为要排序或去重**：本题的 `i < j` 是**位置顺序**，不是数值大小；排序会打乱位置关系，反而全错。

### 题型套路沉淀

- **计数型哈希（固定右端点、统计左端点）**：把「统计满足条件的有序对数量」拆成「枚举右端点 + 用哈希表 O(1) 汇总左端点」。一趟扫描、边查边插，天然保证下标顺序，无需容斥、不用除以 2。这是 O(n²) 枚举 → O(n) 计数最通用的降维手法。
- **判定只依赖少数小整数时，先做「值 → 特征」压缩**：本题把 `1~9999` 压成两个 digit，等价关系被压缩成 10×10 的固定表，之后所有判定都退化成查表。看到「只需首位 / 末位 / 奇偶 / 模 10 余数」这类需求，就该想到把值域压到 10 以内再上哈希。
- **不变的子问题先预计算**：`gcd` 表、互质表、位串前缀表都属于「输入无关、只跟值域有关」的缓存，写进循环外。
