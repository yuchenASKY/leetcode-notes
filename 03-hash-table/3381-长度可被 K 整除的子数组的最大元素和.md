# 3381. 长度可被 K 整除的子数组的最大元素和

> **难度**：中等
> **标签**：数组 · 哈希表 · 前缀和
> **原题链接**：https://leetcode.cn/problems/maximum-subarray-sum-with-length-divisible-by-k/

---

## 一、题目描述

给定整数数组 `nums` 和整数 `k`，在所有**长度能被 `k` 整除**的**非空连续子数组**中，求元素和的最大值。

### 示例

```text
输入：nums = [1,2], k = 1
输出：3
解释：子数组 [1,2] 的和为 3，长度为 2，可以被 1 整除。

输入：nums = [-1,-2,-3,-4,-5], k = 4
输出：-10
解释：只能取长度为 4 的子数组，其中 [-1,-2,-3,-4] 的和 -10 最大。
```

### 约束条件

- `1 <= nums.length <= 2 * 10^5`
- `-10^9 <= nums[i] <= 10^9`
- `1 <= k <= nums.length`

---

## 二、解题思路

### 核心思想

**「长度是 k 的倍数」等价于「左右端点的前缀和下标对 k 同余」。** 于是把前缀和按下标模 `k` 分成 `k` 组，每组只维护**出现过的最小前缀和**，扫一遍右端点即可。

### 思路演进

1. **暴力解法**：枚举左端点 `l` 与右端点 `r`，用前缀和在 O(1) 内求和，判断 `r - l` 是否被 `k` 整除。子数组共 O(n²) 个，n = 2×10⁵ 时约 2×10¹⁰ 次操作，必然超时。
2. **观察到**：设前缀和 `P[i] = nums[0] + … + nums[i-1]`，则区间 `[l, r)` 的和为 `P[r] - P[l]`，长度为 `r - l`。
   - `(r - l) % k == 0` ⟺ `r ≡ l (mod k)` —— **长度条件被转化成下标同余**；
   - 固定 `r` 时，`P[r]` 是常数，要让 `P[r] - P[l]` 最大，只需**让 `P[l]` 在这个同余类里最小**。
3. **优化为**：扫描 `r = k, k+1, …, n`，每步先把 `l = r - k` 的 `P[l]` 投入它所属余数的「最小值表」，再从表里取 `r % k` 那一格的最小值做差。因为每步只投入 `r - k`，表里永远只含**下标 ≤ r-k** 的合法左端点，长度必然 ≥ k 且是 k 的倍数。

### 关键点

- **转化是全部**：把「长度整除 k」变成「下标同余」，问题就从二维枚举塌缩成一维扫描 + 按余数分桶。
- **先投放 `l = r-k`、再查询 `r % k`**，这个顺序决定了正确性。若把当前的 `P[r]` 也投进表再查询，会取到 `P[r] - P[r] = 0`，即「空子数组」，全负数组上直接给出错误答案。
- **同一余数只留最小值**，所以每个桶只需要一个数，不需要保存整段历史，也不需要滑窗。
- 已通过代码里 `cnt[i] = total`（i 从 1 到 k）用的是**下标本身**当键而不是 `i % k`，这样 `P[1]…P[k]` 各自的首次出现都能落进表里，且 `P[0] = 0` 单独由 `cnt[0] = 0` 占位。`cnt[k]` 这一格是**死键**（查询用的余数永远落在 `0…k-1`），留着无害，只是说明它还带着「预填充」的痕迹。

## 三、代码实现

### 最终代码

```python
from itertools import accumulate
from math import inf
from typing import List


class Solution:
    def maxSubarraySum(self, nums: List[int], k: int) -> int:
        ans = -inf                             # 全负数时答案可能为负，不能用 0 初始化
        s = list(accumulate(nums, initial=0))   # s[i] = nums[0] + ... + nums[i-1]

        # cnt[r] = 余数 r 下出现过的最小前缀和
        cnt = {}
        total = 0
        for i in range(1, k + 1):              # 先放入 P[1..k]，它们分别是各余数的首个前缀
            total += nums[i - 1]
            cnt[i] = total
        cnt[0] = 0                             # P[0] = 0 属于余数 0

        for i, x in enumerate(s):              # i 为右端点
            if i < k:                          # 长度至少为 k，右端点太小没有合法左端点
                continue
            temp = i % k
            ans = max(ans, x - cnt[temp])      # 用同余类里的最小前缀做差
            cnt[temp] = min(cnt[temp], x)      # 再把 P[i] 纳入候选，供后续使用

        return ans
```

> 截图里没有 `import`，已补上 `accumulate`、`inf`、`List`。

| 版本 | 时间复杂度 | 空间复杂度 |
| :--- | :--- | :--- |
| **最终代码** | O(n) | O(n)，前缀和数组 + O(k) 的余数表 |

## 五、优化评估

**结论**：时间复杂度已是理论下界（**O(n)**），**空间还有一档可压缩**：O(n) → O(k)。

### 瓶颈分析

时间上，任何解都必须至少读一遍数组才能确定最大和（漏看一个元素就可能漏掉最优子数组），所以 O(n) 不可再降；当前实现每个元素只被访问常数次，时间侧没有浪费。

空间上，O(n) 完全来自 `s = list(accumulate(...))` 这一整条前缀和数组，而算法真正要用到的只有「`P[i]` 与 `P[i-k]`」这两个相差 k 的位置 —— 也就是说，前缀和数组只需要**延迟 k 步的滑动窗口**，不需要全量。

### 可优化空间

用一个长度 `k+1` 的环形缓冲保存最近 k+1 个前缀和，就能在 O(k) 空间内取到 `P[i-k]`；余数表本身也只有 k 格。注意缓冲长度必须是 `k+1` 而不是 `k`：写入 `P[i]` 时读的是 `P[i-k]`，两者槽位相差 `k`，长度取 k 会让「刚写的」覆盖「正要读的」。

### 优化代码

```python
from math import inf
from typing import List


class Solution:
    def maxSubarraySum(self, nums: List[int], k: int) -> int:
        n = len(nums)
        ans = -inf
        best = {}                      # 余数 -> 该余数下最小的前缀和
        total = 0                      # 滚动前缀和 P[i]
        buf = [0] * (k + 1)            # 环形缓冲：buf[i % (k+1)] = P[i]

        for i in range(n + 1):
            if i:
                total += nums[i - 1]
            buf[i % (k + 1)] = total

            if i >= k:                 # 右端点 i 对应最早可用的左端点 j = i - k
                j = i - k
                pj = buf[j % (k + 1)]
                r = j % k              # 与 i 同余，故直接可用 i 的余数
                if r not in best or pj < best[r]:
                    best[r] = pj
                ans = max(ans, total - best[r])

        return ans
```

**优化理由**：把「先建全量前缀和、再延迟 k 步查表」改成「边算边存、靠环形缓冲找回 `P[i-k]`」，额外空间从 O(n) 降为 O(k)；时间仍是 O(n)（每个元素一次加法、每步一次查表）。

### 常数级优化（可选）

- 两个循环（预填充 + 主循环）可以合并成一个从 `i = k` 起的循环，逻辑只走一遍，同时消掉 `cnt[k]` 那个永远不会被查询的死键 —— 可读性收益大于性能收益。
- `ans` 用局部变量累加、避免在循环里反复写 `max(ans, ...)` 之外的多余中间量，属于语言层面的细节，不影响复杂度结论。

## 六、易错点与总结

### 易错点

- **`ans` 初始化成 0**：全负数组（如 `nums = [-1]`、`k = 1`）会返回 0，而正确答案是 -1。必须用 `-inf`。
- **先查后投 vs 先投后查搞反**：如果先把 `P[i]` 投进表再查询，就会取到 `P[i] - P[i] = 0`，等于允许空子数组，全负数据上直接错。
- **忽略「长度至少为 k」**：`k = 4` 时长度为 8、12 的都合法，但 0 不合法；代码里 `if i < k: continue` 就是在挡这一条。注意删掉它**不会报错**，而是静默返回 0 —— 预填充的 `cnt[i]` 恰好就是 `P[i]` 本身，`P[i] - P[i] = 0`，看起来"算出来了"其实是非法的空/短子数组。
- **`k = n` 的边界**：整个数组是唯一合法的子数组，答案就是总和；预填充循环正好读到 `nums[k-1] = nums[n-1]`，不会越界，但换成「下标 i-k」的写法时要注意不要让 `j` 取到负数（Python 里 `-1 % k` 是 `k-1` 而非 -1，静默取到错桶）。
- **余数桶里存的是「最小值」而不是「最早的值」**：负数前缀很常见，存错成首次出现会让后续答案偏小。

### 题型套路沉淀

- **前缀和 + 下标同余分组**：凡是「子数组和」叠加「长度受限」的题，先写出 `P[r] - P[l]`，再看长度约束能不能翻译成 `l`、`r` 的关系 —— 本题翻译成「同余」，另一种常见翻译是「`l <= r - 下限`」（对应延迟 k 步的滑窗）。
- **「固定一端，另一端只留极值」**：固定右端点后左端点只剩「取前缀和最小」这一个诉求，于是 O(n) 的候选集被压成 O(1) 的桶。这类「一维扫描 + 分桶维护极值」是前缀和题的标准骨架。
- **同族骨架**：「和可被 k 整除」的子数组（同余计数，求个数）、「和至少为 k 的最短子数组」（同余/单调队列维护下标）都是同一个 `P[r] - P[l]` 出发的不同极值诉求，区别只在桶里存「最小前缀和」还是「最小/最大下标」。
