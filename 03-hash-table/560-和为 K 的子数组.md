# 560. 和为 K 的子数组

> **难度**：中等
> **标签**：数组 · 哈希表 · 前缀和
> **原题链接**：https://leetcode.cn/problems/subarray-sum-equals-k/

---

## 一、题目描述

给定整数数组 `nums` 与整数 `k`，统计并返回数组中**和恰好为 `k` 的连续非空子数组**的个数。子数组是数组中元素的连续非空序列。

注意元素可以是负数，因此「和」不随长度单调变化，这是本题最容易踩空的地方。

### 示例

```text
示例 1：
输入：nums = [1,1,1], k = 2
输出：2
解释：和为 2 的子数组有两个：[1,1]（下标 0..1）与 [1,1]（下标 1..2）。

示例 2：
输入：nums = [1,2,3], k = 3
输出：2
解释：和为 3 的子数组是 [3] 与 [1,2]。

示例 3：
输入：nums = [1,-1,0], k = 0
输出：3
解释：[1,-1]、[0]、[1,-1,0]。
```

### 约束条件

- `1 <= nums.length <= 2 * 10^4`
- `-1000 <= nums[i] <= 1000`
- `-10^7 <= k <= 10^7`

---

## 二、解题思路

### 核心思想

**把「区间和等于 k」翻译成「两个前缀和的差等于 k」，于是数子数组就变成数前缀和。** 固定右端点 `j` 后，要求的是「有多少个更早的前缀和恰好等于 `P[j] - k`」—— 一次哈希计数就能 O(1) 回答。

### 思路演进

1. **暴力解法**：枚举左右端点 `(i, j)` 累加求和，等于 `k` 就计数。直接三重循环 O(n³)；把内层改成累加则 O(n²)。n = 2×10^4 时 n² ≈ 4×10^8，Python 里必然超时，即便 C++ 也很勉强。
2. **观察到**：内层循环做的其实是「增量维护区间和」，而任意区间和都能用前缀和 O(1) 得到：
   `sum(i..j) = P[j+1] - P[i]`。于是条件 `sum(i..j) == k` 等价于 `P[i] == P[j+1] - k`。
   此时对每个右端点 `j`，问题变成：**在 `P[0..j]` 中有多少个值恰好等于 `P[j+1] - k`**。
3. **优化为**：把「在前缀里数某个值出现几次」交给哈希表（`前缀和 -> 出现次数`）。一次从左到右的遍历，边累加当前前缀和、边在表里查 `当前前缀和 - k` 的计数、边把当前前缀和计入表，O(n) 一遍扫完。

### 关键点

- **前缀和必须包含 `P[0] = 0`**（空前缀），它代表「子数组从下标 0 开始」这种情况。所以初始化 `cnt[0] = 1`，而**不是** `cnt` 空表。
- **先查后插**：查询用的是「当前前缀和**之前**出现过的次数」，若先插入再查询，`k == 0` 时会把当前这个空前缀算进去，把 `[i, i)` 这种长度为 0 的区间误计成答案。
- **要的是计数不是判定**：表里存的是「出现次数」而不是「是否出现过」；同时因为要数个数，也不能用 `set`。
- **有负数 ⇒ 前缀和不单调 ⇒ 滑动窗口做不到**。「窗口和偏大就收缩」的前提是元素非负，本题 `nums[i]` 可为负，收缩后窗口和可能反向变大，双指针会漏解 —— 这是它和「正整数数组求和为 k 的子数组」的关键区别。
- **答案可能很大**：最坏 `n(n+1)/2 ≈ 2×10^8` 量级，Python 的 int 天然无溢出问题，但换成 C++/Java 时累计变量要用 `long long` / `long`。

## 三、代码实现

### 最终代码

```python
from collections import defaultdict
from typing import List


class Solution:
    def subarraySum(self, nums: List[int], k: int) -> int:
        n = len(nums)
        s = [0] * (n + 1)          # s[i] = nums[0..i-1] 的前缀和，s[0] = 0
        cnt = defaultdict(int)     # 前缀和 -> 出现次数
        cnt[0] = 1                 # 空前缀，代表「从下标 0 开始的子数组」
        ans = 0
        for i in range(1, n + 1):
            s[i] = s[i - 1] + nums[i - 1]
            ans += cnt[s[i] - k]   # 先查：更早的前缀和里有多少个等于 s[i] - k
            cnt[s[i]] += 1         # 后插：当前前缀和计入表
        return ans
```

> 截图里的代码没有 `from collections import defaultdict` 与 `from typing import List`，这里已补上（LeetCode 判题环境自带 `List`，本地跑则需要显式 import）。

## 五、优化评估

**结论**：时间复杂度已是理论下界，**空间复杂度在「元素可为负」的前提下也是必要代价**。

### 瓶颈分析

时间上，任何正确算法都必须至少扫一遍数组才能确认每段区间的和，O(n) 已经到顶；剩下的只是常数差异。空间上，O(n) 来自哈希表 —— 最坏情况下 n+1 个前缀和两两不同，表里就要放 n+1 项。

### 可优化空间

能不能把空间降到 O(1)？只有在**元素全为非负**时才可以：那时前缀和单调递增，可以用双指针滑动窗口，一边移动一边加减，无需存储。但本题允许负数，前缀和序列失去单调性，「窗口和偏大该左移」这个判据不再成立，双指针会漏解。因此在一般情形下，**必须用某种能按值随机访问的数据结构记录每个前缀和的重数**，O(n) 空间是绕不过去的。

至于「用排序 + 二分替代哈希」这类替代路线：排序会打乱前缀和的**时间先后顺序**，而本题要求「只统计出现在当前元素之前的前缀和」，顺序是语义的一部分，所以也不成立。

### 优化代码

下面的写法去掉辅助的 `s` 数组，用滚动变量维护前缀和 —— 渐进复杂度不变（仍是 O(n) 时间、O(n) 空间），但少一次 O(n) 的数组分配与一次数组下标访问：

```python
from collections import defaultdict
from typing import List


class Solution:
    def subarraySum(self, nums: List[int], k: int) -> int:
        cnt = defaultdict(int)
        cnt[0] = 1                 # 空前缀
        ans = 0
        pre = 0                    # 滚动前缀和，替代 s 数组
        for x in nums:
            pre += x
            ans += cnt[pre - k]    # 先查
            cnt[pre] += 1          # 后插
        return ans
```

**优化理由**：`s[i]` 只在下一步用到一次（`s[i] = s[i-1] + nums[i-1]`），属于典型的「只用前一项」的递推，因此不需要保留整个数组，一个标量足够。逻辑与最终代码完全等价。

### 常数级优化（可选）

- `cnt[pre - k]` 在 `defaultdict` 上会**在读取时静默插入一个值为 0 的键**，使字典慢慢被未命中的前缀和撑大，并且每次都要多做一次「插入后取值」。改成显式 `v = cnt.get(pre - k)` / `if v: ans += v`，语义不变但避免了无谓的键增长，同时与手写 `dict` 的行为一致。
- 把 `cnt` 的方法绑成局部变量（如 `get = cnt.get`）在纯 Python 实现里能省掉每次调用的属性查找，但在 CPython 中收益有限，可读性下降，**不建议为了它牺牲清晰度**。

## 六、易错点与总结

### 易错点

- **忘写 `cnt[0] = 1`**：这是本题第一大坑。漏掉它，所有「从下标 0 开始」且和恰为 `k` 的子数组全部丢失，`nums = [1,1,1], k = 2` 会得到 1 而不是 2（第一个 `[1,1]` 就是靠空前缀配出来的）。
- **先插后查**：`k == 0` 时会把当前空前缀错算进去，多出不存在的空区间。
- **误用滑动窗口**：看到「连续子数组求和」就想双指针。前缀和单调的前提是元素非负，本题有负数，双指针会漏解。
- **用 `set` 代替计数表**：`set` 只能回答「有没有」，回答不了「有几个」，而答案要的是个数。
- **区间和与下标错位**：`s[i] = nums[0..i-1]` 这种「多开一位」的定义最容易把 `s[i] - k` 写成 `s[i-1] - k`，建议写代码时先在纸上标清楚 `s[0]` 是空数组的和。
- **整数溢出（非 Python）**：答案上界约 2×10^8，C++ 用 `int` 尚可、Java 也够，但若题目放宽容错量级（n 更大）就要 `long long`，别养成用 `int` 累计的习惯。

### 题型套路沉淀

- **「区间和 → 前缀和之差」是这类题的统一入口**：只要题目问「有多少个子数组满足某个关于和的线性条件」，第一步就该把区间和换成 `P[j] - P[i]`，然后看条件能不能改写成 `P[i] == f(P[j])` 的形式。能改写 → 扫描时用哈希表记录历史前缀的计数，O(n)。
- **扫描型前缀和模板（固定三段式）**：
  1. 初始化 `cnt = {0: 1}`（空前缀）；
  2. 遍历，维护 `pre`；
  3. **先按 `pre - k` 查表累加答案，再把 `pre` 计入表**。
  第 3 步的顺序不可交换，这是模板里唯一容易写反的地方。
- **判断能不能上双指针，先看元素符号**：有负数就放弃滑动窗口，改用哈希 + 前缀和；只有非负（或单调）时才考虑双指针。
- **同族变体**：`325. 和等于 k 的最长子数组长度`（表里存首次出现的下标而非次数）、`974. 和可被 K 整除的子数组`（存前缀和模 K 的余数）、`523. 连续的子数组和`（同余 + 长度 ≥ 2）、`930. 和相同的二元子数组`、`1248. 统计「优美子数组」`（把条件转成奇数个数前缀差）。它们的骨架与本题完全一致，只是把「等于 `pre - k`」换成各自的等价条件。
