# 3067. 在带权树网络中统计可连接服务器对数目

> **难度**：中等
> **标签**：树 · 深度优先搜索 · 数组
> **原题链接**：https://leetcode.cn/problems/count-pairs-of-connectable-servers-in-a-weighted-tree-network/

---

## 一、题目描述

给定一棵 n 个节点的无根带权树，节点 0 ~ n−1 各有编号代表 n 台服务器，`edges[i] = [a_i, b_i, w_i]` 表示 a_i 与 b_i 之间有一条权值为 w_i 的双向边，另给整数 `signalSpeed`。

称服务器对 (a, b) 是通过服务器 c **可连接**的，当且仅当同时满足：

- `a < b`，且 `a != c`、`b != c`；
- `dist(c, a)` 能被 `signalSpeed` 整除；
- `dist(c, b)` 能被 `signalSpeed` 整除；
- 路径 c→a 与路径 c→b 没有任何公共边。

返回长度为 n 的数组 `count`，`count[i]` 为通过服务器 i 可连接的服务器对数目。

一句话概括：**对每个中心点，数出「到它的距离模 signalSpeed 为 0」的节点中、落在不同分支里的两两组合数。**

### 示例

示例 1：

```text
输入：edges = [[0,1,1],[1,2,5],[2,3,13],[3,4,9],[4,5,2]], signalSpeed = 1
输出：[0,4,6,6,4,0]
解释：signalSpeed = 1 时任何距离都可整除，"无公共边" 成为唯一约束，
      于是 count[c] = c 左侧点数 × 右侧点数；两端点各只有一条出边，凑不出跨分支对，答案为 0。
```

示例 2：

```text
输入：edges = [[0,6,3],[6,5,3],[0,3,1],[3,2,7],[3,1,6],[3,4,2]], signalSpeed = 3
输出：[2,0,0,0,0,0,2]
解释：以 0 为中心：6 分支里 dist(0,6)=3、dist(0,5)=6 都可整除；3 分支里只有 dist(0,4)=1+2=3 可整除，
      两个分支各给出 2 个和 1 个合法端点 ⇒ 2×1 = 2，即 (4,5) 与 (4,6)。
      以 6 为中心同理得到 (4,5) 与 (0,5)。其余节点的合法端点都挤在同一个分支里，答案为 0。
```

### 约束条件

- `2 <= n <= 1000`
- `edges.length == n - 1`，`edges[i].length == 3`，`0 <= a_i, b_i < n`
- `1 <= w_i <= 10^6`，`1 <= signalSpeed <= 10^6`
- 输入保证 `edges` 构成一棵合法的树

## 二、解题思路

### 核心思想

树上「两条路径没有公共边」等价于「两个端点落在中心点的**不同邻居分支**里」；于是对每个中心，先统计各分支内距离余数为 0 的节点数，再用「跨分支两两相乘求和」合并。

### 思路演进

1. **暴力解法**：对每个中心 c 做一次遍历求所有点到 c 的距离、并标记每个点属于 c 的哪个分支；然后枚举所有点对 (a, b)，逐个检查「两距离都可整除」且「分支不同」。每个中心枚举点对要 O(n²)，n 个中心 ⇒ 总 **O(n³)**。
2. **观察到**：枚举点对这一步是纯重复劳动。一旦各分支的合法点数 cnt₁, cnt₂, …, cnt_k 确定，答案就是 Σ_{i<j} cnt_i·cnt_j，与具体是哪几个点毫不相关。k 个分支只需 O(k) 就能合并——每来一个新的 cnt，把它与「此前所有分支之和 s」相乘累加即可（滚动前缀和），不用真去两两枚举。
3. **优化为**：每个中心的代价降为一次全树遍历 O(n)，总 **O(n²)**。把「距离能否被 signalSpeed 整除」改写成携带**余数**的 DFS：状态是「从中心走到当前节点这段距离 mod signalSpeed」的值，进入子节点时更新为 `(s + wt) % signalSpeed`，余数为 0 的节点就是本分支的合法端点。中心自己不能当端点（a ≠ c、b ≠ c），所以每个分支都从邻居出发、把初始余数设为 `wt % signalSpeed`。

### 关键点

- **分支天然隔离**：从中心向每个邻居各开一次 DFS，且 DFS 不回走父节点，搜索范围恰好是一个分支，不需要额外着色或去重标记。
- **余数可加**：判整除时不必求完整距离，mod 的转移只依赖路径本身；`(s + wt) % signalSpeed` 中 s 是余数，与「全距离再取模」结果一致。
- **汇总必须跨分支**：写成 `ans += cnt * 已累计 s`，随后 `s += cnt`；这与 `(S² − Σcnt²) / 2` 完全等价，但只扫一遍。

## 三、代码实现

### 最终代码

```python
from typing import List
from functools import cache


class Solution:
    def countPairsOfConnectableServers(self, edges: List[List[int]], signalSpeed: int) -> List[int]:
        n = len(edges) + 1
        g = [[] for _ in range(n)]
        for i, j, k in edges:
            g[i].append((j, k))
            g[j].append((i, k))

        # 返回：以 x 为根的这块分支里，到中心点距离 mod signalSpeed == 0 的节点数
        # s 为「中心 → x」这段距离对 signalSpeed 的余数
        @cache
        def dfs(x: int, fa: int, s: int) -> int:
            cnt = 0 if s else 1                # 余数为 0，x 自己就是合法端点
            for y, wt in g[x]:
                if y != fa:
                    cnt += dfs(y, x, (s + wt) % signalSpeed)
            return cnt

        ans = [0] * n
        for i, gi in enumerate(g):
            if len(gi) == 1:                   # 叶子只有一条出边，凑不出跨分支对
                continue
            s = 0
            for y, wt in gi:
                cnt = dfs(y, i, wt % signalSpeed)
                ans[i] += cnt * s              # 与前面各分支的合法端点两两配对
                s += cnt
        return ans
```

> 截图版本缺少 `from typing import List` 与 `from functools import cache`，此处已补齐；算法逻辑与已通过提交一致。

## 四、复杂度分析

| 版本 | 时间复杂度 | 空间复杂度 |
| :--- | :--- | :--- |
| **最终代码** | O(n²) | O(n)（邻接表 + 递归栈；`@cache` 键上界 O(n²)） |
| 朴素解法 | O(n³) | O(n) |
| 理论下界 | O(n)（仅输出规模） | O(n) |

> 复杂度中的 n 指：树的节点（服务器）数，即 `n = len(edges) + 1`。

- 时间：外层枚举 n 个中心，每个中心对整棵树做一遍 DFS，单次 O(n)，合计 O(n²)。分支合并只占 O(度)。
- 空间：邻接表 O(n)；单次 DFS 递归深度最坏为树高，链状树上是 O(n)。`@cache` 的键是 (x, fa, s)，三者里 s 由 (x, fa) 唯一决定，因此键集规模与「访问过的 (节点, 父节点) 对」同量级，最坏 O(n²)。

## 五、优化评估

**结论**：O(n²) 已经是本题的标准量级，n ≤ 1000 时无需再往下沉。

### 瓶颈分析

- 时间几乎全花在「换一个中心就要重新遍历整棵树」：n 个中心 × O(n) 次访问。这是解法结构的代价，不是实现细节的浪费。
- 单个中心内部没有冗余：每个节点只被访问一次，配对合并在分支层面一次扫完，不存在重复枚举。
- 空间主体是邻接表 O(n) 与递归栈 O(n)；缓存最坏会到 O(n²) 个键。

### 可优化空间

- 想突破 O(n²) 就必须合并「不同中心之间的重复遍历」（例如按余数类别做全局计数再换根统计），实现复杂度大幅上升，而本题 n ≤ 1000，收益撑不起这个代价，不采纳。
- 逻辑层没有可删的枚举：每个 (中心, 节点) 组合的余数都可能独立影响答案，O(n²) 的信息量是本题朴素信息结构下绕不过去的。

### 常数级优化（可选）

- 本题没有值得做的常数级改写。唯一需要留意的是递归深度（见易错点最后一条），那属于正确性问题，不是速度问题。

## 六、易错点与总结

### 易错点

- **把中心本身算成端点**：题目要求 `a != c`、`b != c`。本解法让每个分支从邻居出发、初始余数为 `wt % signalSpeed`，天然把 c 排除；若图省事从 c 自己开始 DFS，会多统计一个点。
- **忽略「无公共边」这一条**：余数为 0 的点可能全部落在同一个分支里，它们之间**不能**用该中心配对。必须先按分支分组，再跨分支组合。
- **配对时自我配对或重复计数**：`ans[i] += cnt * s`（随后再 `s += cnt`）与 `(S² − Σcnt²) / 2` 等价，混用会重复计数；最常见的是先更新 s 再相乘，导致自己与自己配对。
- **余数传递时漏取模**：`(s + wt) % signalSpeed` 的前提是 s 已经是余数；若某处把全距离和余数混着传，判 0 的条件就会失效（本题权重与路径长度不溢出，但语义会错）。
- **叶子中心的处理**：`len(gi) == 1` 时提前 `continue` 只是剪枝，不提前跳过也不影响正确性（分支只有一个，`cnt * s` 恒为 0）。
- **递归深度**：链状树上 DFS 深度接近 n−1，n ≤ 1000 时余量不大。截图版本未设置递归上限，本地用长链数据复现时应显式放宽（`sys.setrecursionlimit(10**6)`）。
- **误解 `@cache` 的作用**：键 (x, fa, s) 中 s 由 (x, fa) 唯一确定，同一中心内不会出现重复键；不同中心的 fa 也不同，因此它并不在「不同中心之间」复用结果——保留无害，但别把它当成优化依据。

### 题型套路沉淀

- **树上「路径不相交」→ 按分支分组**：凡是「从 c 出发的两条路径不能共边」的统计题，第一步固定是把 c 的邻居拆成若干分支，问题立刻降维成「每个分支贡献一个计数，求跨分支组合」。k 个分支用滚动前缀和一行合并，永远不要真的枚举点对。
- **带权距离的整除判定 → 余数随 DFS 传递**：只关心 mod k 是否为 0 时，状态里存余数而不是完整距离，转移是 `(r + w) % k`。这类「余数作状态」的写法也适用于最短路计数、按余数分层建图等场景。
- **「以每个点为中心统计」→ 先看规模再决定换根**：n ≤ 10³ 时，「对每个根各做一次全树遍历」就是预期解法，不必一上来就写换根 DP；先确认数据规模，再决定要不要付出换根的实现成本。
