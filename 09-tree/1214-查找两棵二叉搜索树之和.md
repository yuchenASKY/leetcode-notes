# 1214. 查找两棵二叉搜索树之和

> **难度**：中等
> **标签**：树 · 二叉搜索树 · 中序遍历 · 双指针
> **原题链接**：https://leetcode.cn/problems/two-sum-bsts/

---

## 一、题目描述

给出两棵二叉搜索树的根节点 `root1` 和 `root2`，从两棵树中各挑一个节点，判断是否存在这样一对节点，使它们的**值之和等于 `target`**。存在返回 `True`，否则返回 `False`。

### 示例

```text
输入：root1 = [2,1,4], root2 = [1,0,3], target = 5
输出：true
解释：2 + 3 和为 5
```

### 约束条件

- 每棵树的节点数在 `[1, 5000]` 范围内
- `-10^9 <= Node.val <= 10^9`
- `-10^9 <= target <= 10^9`
- 每棵树内部的节点值互不相同
- **进阶**：能否做到 O(n + m) 的时间复杂度，其中 n、m 分别为两棵树的节点数

---

## 二、解题思路

### 核心思想

**BST 的中序遍历是严格递增序列 —— 把两棵树各自拍平成一个有序数组，题目就退化成「两个有序数组求配对和」。** 有序性直接白送单调性，于是双指针一趟扫完，时间 O(n + m)。

### 思路演进

1. **暴力解法**：枚举 `tree1` 的每个节点 × `tree2` 的每个节点，判 `a + b == target`。时间是 O(n·m)，n = m = 5000 时是 2.5×10⁷ 次配对比较。
2. **观察到**：这个做法完全没用到「BST」这个条件 —— 换成两棵普通二叉树也一样跑得动，说明必然有信息被浪费了。BST 唯一的结构红利就是：**按中序访问节点，取到的值天然升序**。
3. **转化**：于是先做两次中序，得到两个升序数组 `l1`、`l2`。原问题变成「在 `l1` 与 `l2` 之间找一对和等于 `target`」。
4. **优化为双指针**：`i` 指向 `l1` 的最小值（开头），`j` 指向 `l2` 的最大值（末尾）。
   - 和偏**小** → 需要更大的值 → `i` 右移（换 `l1` 里更大的）
   - 和偏**大** → 需要更小的值 → `j` 左移（换 `l2` 里更小的）
   
   每一步都能确定性地排除一个元素，总共最多走 n + m 步，O(n + m)。
5. **中间路线**（对比用）：不做第二次中序，而是遍历 `tree1` 的每个值 `v`，在 `tree2` 里二分查 `target - v`。时间 O(n log m)，比暴力好，但比双指针多一个 log。它说明「用上 BST 的查找性质」也是一种解法，只是不如「用上 BST 的有序性」彻底。

### 关键点

- 双指针必须**一个从头、一个从尾**。两个都从头出发时，移动一端无法判断该增大还是减小，单调性用不上。
- 指针移动方向和比较结果是**反直觉的配对**：`s > target` 动的是 `r`（右数组那一端），`s < target` 动的是 `l`。写反了不会报错，只会静默地扫空整个数组并返回 `False`。
- 循环条件要**同时**守住 `l < len(l1)` 和 `r >= 0`，任何一侧走完就说明无解。
- 这题与普通的「两数之和」差别就在输入已经有序 ⇒ **不需要哈希表**，除了两个数组外没有额外结构。

## 三、代码实现

### 最终代码

```python
from typing import Optional


class Solution:
    def twoSumBSTs(self, root1: Optional[TreeNode], root2: Optional[TreeNode], target: int) -> bool:
        # 中序遍历二叉搜索树，生成递增数组
        def dfs(root: Optional[TreeNode]) -> list[int]:
            res = []
            if not root:
                return res
            res.extend(dfs(root.left))
            res.append(root.val)
            res.extend(dfs(root.right))
            return res

        l1 = dfs(root1)
        l2 = dfs(root2)
        l, r = 0, len(l2) - 1

        # 双指针：l 从 l1 的最小值开始，r 从 l2 的最大值开始
        while l < len(l1) and 0 <= r:
            s = l1[l] + l2[r]
            if s == target:
                return True
            elif s > target:
                r -= 1
            else:
                l += 1
        return False
```

> `from typing import Optional` 是截图里没有、补上的（`TreeNode` 由判题环境提供）。

## 四、复杂度分析

| 版本 | 时间复杂度 | 空间复杂度 |
| :--- | :--- | :--- |
| **最终代码**（中序 + 双指针） | O(n + m) | O(n + m) |
| 遍历 tree1 + 在 tree2 二分 | O(n log m) | O(1)（不计递归栈） |
| 朴素解法（双重枚举） | O(n·m) | O(1) |
| 理论下界（时间） | O(n + m) | O(h₁ + h₂)（见第五节） |

> 复杂度中的 n 指 `root1` 的节点数，m 指 `root2` 的节点数；h₁、h₂ 分别是两棵树的高度（最坏退化成长链时 h = n）。

补充说明：递归版的空间不只是两个结果数组，还要加上递归深度 O(h)。总空间写作 O(n + m) 是因为数组本身已经是 O(n)、O(m) 量级，把较小的递归栈淹没掉了。

## 五、优化评估

**结论**：时间已达下界，**空间仍可优化**。

### 瓶颈分析

时间上 n + m 是硬下界 —— 最坏情况必须把两棵树的每个值都看一遍（否则可能漏掉唯一的解），所以 O(n + m) 不可能再压，进阶要求问的也正是这个。真正的浪费在空间：为了做双指针，我们把两棵树的全部值都物化成了数组，而双指针**从头到尾只需要「当前这个值」和「下一个值」**。

### 可优化空间

把中序改成**栈模拟的惰性迭代器**：不预先展开整棵树，而是维护一条从根到当前节点的路径，每次要「下一个值」时才沿路径推进。这样：

- `root1` 用**正向**中序（升序），`root2` 用**反向**中序（降序），两者正好构成双指针的两端；
- 任意时刻栈里只存一条根到叶的路径，空间从 O(n + m) 降到 **O(h₁ + h₂)**；
- 时间仍是 O(n + m)，每个节点进出栈各一次。

### 优化代码

```python
from typing import Optional


class Solution:
    def twoSumBSTs(self, root1: Optional[TreeNode], root2: Optional[TreeNode], target: int) -> bool:
        # 惰性中序迭代器：每次调用 nxt() 取「下一个值」，耗尽返回 None
        # reverse=False -> 升序；reverse=True -> 降序
        def make(root: Optional[TreeNode], reverse: bool):
            st, node = [], root

            def nxt():
                nonlocal node
                # 一路压栈到这一侧的最深处
                while node:
                    st.append(node)
                    node = node.right if reverse else node.left
                if not st:
                    return None
                cur = st.pop()
                node = cur.left if reverse else cur.right
                return cur.val

            return nxt

        nxt1, nxt2 = make(root1, False), make(root2, True)
        a, b = nxt1(), nxt2()
        while a is not None and b is not None:
            s = a + b
            if s == target:
                return True
            if s < target:
                a = nxt1()      # 和偏小：左数组后移（取更大的）
            else:
                b = nxt2()      # 和偏大：右数组后移（降序序列里下一个更小）
        return False
```

**优化理由**：双指针的本质是「两个有序序列各有一个游标」，从来不要求序列整体可随机访问。用栈把中序变成流式输出后，游标只需要 `push/pop` 就能前进一步，于是省掉了两个 O(n)、O(m) 的数组。同时它是**迭代**的，退化链（深度 5000）也不会撞 Python 的递归深度上限。

### 常数级优化（可选）

- 当前 `dfs` 每层都会 new 一个 `res` 再 `extend` 给上一层，节点数多时会造出 O(节点数) 个临时 list 对象。改成把同一个 list 一路传下去、只做 `append`，能省掉这批中间对象。
- 双指针循环里 `len(l1)` 每轮都会被求值，提到循环外存成局部变量，省掉一次属性查找。

## 六、易错点与总结

### 易错点

- **指针移动方向写反**：`s > target` 要缩小和，动的是 `r`（右端最大值那一侧）；`s < target` 要增大和，动的是 `l`。写反不报错，只是把整个数组扫空后返回 `False`。
- **只判一侧边界**：`while l < len(l1) and 0 <= r` 少了后半截，`r` 会变成 -1 并在 Python 里索引到 `l2[-1]`（静默取到最后一个元素，结果错得毫无提示）。
- **误以为要用哈希表**：这题输入天然有序，照搬「两数之和」的哈希写法不但更慢的方向，也多付了 O(n) 空间。
- **递归深度**：本地默认 `sys.setrecursionlimit(1000)`，一棵 5000 节点的退化 BST（整棵树是一条左链）会直接 `maximum recursion depth exceeded`（已实测）。判题侧通常放宽了限制，但要做本地复现或加强鲁棒性时，第五节的迭代写法更稳。

### 题型套路沉淀

- **「两棵 BST / 两个有序结构里找配对」的固定套路**：中序拍平成升序数组 → 双指针。见到「BST + 求和 / 求差 / 求最接近」先想这条。
- **有序数组两数之和的唯一动作**是「和与 target 比大小 → 只动能改变和的那一端」，且两端必须一低一高。
- **要求把辅助空间压掉时，把「物化整个序列」换成「惰性迭代器」**：中序栈只保留一条路径，O(n) → O(h)，时间不变。这是树题里最常用的空间降维手法。
