# 3540. 访问所有房屋的最短时间

> **难度**：中等
> **标签**：数组 · 前缀和
> **原题链接**：https://leetcode.cn/problems/minimum-time-to-visit-all-houses/

---

## 一、题目描述

`n` 座房屋排成一个环，两条有向边链把环串起来：

- `forward[i]`（`0 <= i <= n-2`）是 `i → i+1` 的路长；`forward[n-1]` 是 `n-1 → 0` 的路长 —— 即**顺时针**一圈。
- `backward[i]`（`1 <= i <= n-1`）是 `i → i-1` 的路长；`backward[0]` 是 `0 → n-1` 的路长 —— 即**逆时针**一圈。

注意两条链的边权**可以不一样**：从 `i` 走到 `i+1` 和从 `i+1` 走回 `i` 是两条长度不同的路。

以 1 米/秒行走，从房屋 `0` 出发，按 `queries` 给出的顺序依次访问这些房屋，返回总时间的最小值。

**关键性质**：环上任意两点 `x → y` 只有两条简单路径（顺时针一整段弧、逆时针另一段弧），而每次移动的代价只与端点有关、与「之前怎么来的」无关 —— 所以每段独立取较小值，加总就是全局最优。

### 示例

```text
示例 1：
输入：forward = [1,4,4], backward = [4,1,2], queries = [1,2,0,2]
输出：12
解释：0(0) → 1(1) → 2(5) → 1(7) → 0(8) → 2(12)
      0→1 走 forward[0]=1；1→2 走 forward[1]=4；
      2→1 走 backward[2]=2（逆时针更近）；1→0 走 backward[1]=1；
      0→2 顺时针 1+4=5，逆时针 backward[0]=4，取 4。

示例 2：
输入：forward = [1,1,1,1], backward = [2,2,2,2], queries = [1,2,3,0]
输出：4
解释：0 → 1 → 2 → 3 → 0 全程顺时针，每段 1 秒。
```

### 约束条件

- `2 <= n <= 10^5`
- `n == forward.length == backward.length`
- `1 <= forward[i], backward[i] <= 10^5`
- `1 <= queries.length <= 10^5`
- `0 <= queries[i] < n`
- `queries[i] != queries[i+1]`
- `queries[0] != 0`

> 最后一行的读法：本题保证相邻两个查询点不同、且第一个查询点不是起点 0，所以「原地不动」的分支实际不会出现 —— 但代码里仍应让它自然得 0，不要依赖这个约束。

## 二、解题思路

### 核心思想

**每段移动是「环上一段连续弧的边权和」，而边权是静态的 —— 用前缀和把这段弧求和从 O(n) 降到 O(1)。** 环上跨过下标 `0` 的弧，靠**把数组翻倍**（`a + a`）变成线性区间来求和。

### 思路演进

1. **暴力解法**：对每对相邻查询 `(x, y)`，沿 `forward` 从 `x` 一步一步走到 `y` 累加边权，再沿 `backward` 走一遍，取较小值。单次移动 O(n)，总共 O(nq)。`n, q` 都是 10^5 时是 10^10 量级，必然超时。

2. **观察到**：暴力里被反复重算的东西是「`forward[x] + forward[x+1] + ... + forward[k]`」这类**静态区间和**。边权在整轮查询中从不改变，正是前缀和的理想场景 —— 建一次表 O(n)，之后每次区间求和 O(1)。总代价降到 O(n + q)。

3. **优化为**：环形的麻烦在于「区间可能绕过边界」。设 `x = 3, y = 1`，顺时针路径是 `3 → 4 → … → n-1 → 0 → 1`，在原始数组里它是**两段**。解决办法是把数组**首尾相接复制一份**（`forward + forward`），原数组的任意环形区间都能在长度 `2n` 的数组里表示成**一个连续区间** `[x, y+n)`。

4. **两个方向要各建一张表**：`forward[i]` 是 `i → i+1`，`backward[i]` 是 `i → i-1`。两者方向相反，所以「哪一段边属于哪一段弧」的**边界偏移差一位**。让两张前缀和的起始偏移差一位，就能让顺时针/逆时针共用同一套下标公式：

   - **顺时针 `x → y`**（沿 `forward`）：需要 `forward[x] + … + forward[y-1]`，即**左闭右开**区间。所以 `nxt_cost` 带 `initial=0`，`nxt_cost[k] = forward[0] + … + forward[k-1]`。
     - `y > x`：`nxt_cost[y] - nxt_cost[x]`
     - `y < x`：绕边界，`nxt_cost[y + n] - nxt_cost[x]`
   - **逆时针 `x → y`**（沿 `backward`）：需要 `backward[x] + backward[x-1] + … + backward[y+1]`，即**左开右闭**区间（注意 `backward` 的下标挂在「边的终点」上）。所以 `pre_cost` **不带** `initial=0`，`pre_cost[k] = backward[0] + … + backward[k]`，于是 `pre_cost[b] - pre_cost[a] = backward[a+1] + … + backward[b]`。
     - `y < x`：`pre_cost[x] - pre_cost[y]`
     - `y > x`：绕边界，`pre_cost[x + n] - pre_cost[y]`

   两个分支可以合成一句「需要绕边界时把起点加 `n`」，也就是代码里的 `y + n if y < x else y` 与 `x + n if y > x else x`。

### 关键点

- **环形区间 = 数组翻倍后的线性区间**，这是所有环形求和题的第一步，写一次记住一辈子。
- 两张表的 **`initial` 一个加、一个不加**，不是笔误：`forward` 的边权挂在**边的起点**（`i → i+1`），`backward` 的边权挂在**边的终点**（`i → i-1` 的终点是 `i-1`）。刚好差一位，用初始偏移吸收掉，公式才对称。
- 每个 `(x, y)` 只依赖当前段的两个端点，**段与段之间无后效性**（怎么走到 `x` 的不影响从 `x` 出发的代价），所以「每段取 min 再累加」是严格最优，不需要 DP。
- 起点是房屋 `0`，`x` 的初值取 `0`，**不是** `queries[0]`。
- 答案最大约 `10^5 × 10^5 × 10^5 = 10^15` 量级，非 Python 语言要用 64 位整型。

## 三、代码实现

### 最终代码

```python
from itertools import accumulate
from typing import List


class Solution:
    def minTotalTime(self, forward: List[int], backward: List[int], queries: List[int]) -> int:
        n = len(forward)

        # 顺时针：nxt_cost[k] = forward[0] + ... + forward[k-1]，左闭右开，长度 2n+1
        nxt_cost = list(accumulate(forward + forward, initial=0))
        # 逆时针：pre_cost[k] = backward[0] + ... + backward[k]，左开右闭，长度 2n
        pre_cost = list(accumulate(backward + backward))

        ans = 0
        x = 0                                  # 起点是房屋 0
        for y in queries:
            # 顺时针从 x 到 y：y < x 时要绕过 n-1 -> 0 的边界
            forward_time = nxt_cost[y + n if y < x else y] - nxt_cost[x]
            # 逆时针从 x 到 y：y > x 时要绕过 0 -> n-1 的边界
            backward_time = pre_cost[x + n if y > x else x] - pre_cost[y]
            ans += min(forward_time, backward_time)
            x = y
        return ans
```

> 原始提交版本里没有 `import` 那两行，这里补上了（否则 `List` 与 `accumulate` 都未定义）。

## 四、复杂度分析

| 版本 | 时间复杂度 | 空间复杂度 |
| :--- | :--- | :--- |
| **最终代码** | O(n + q) | O(n) |
| 朴素解法（逐条边累加） | O(n × q) | O(1) |
| 理论下界 | O(n + q) | O(n) |

> 复杂度中的 `n` 指房屋数量（即 `forward` / `backward` 的长度），`q` 指 `queries` 的长度。

建两张长度 `2n` 的前缀和表是 O(n)，扫描 `queries` 是 O(q)，共 O(n + q)。空间上两张表各 2n 个整数，仍是 O(n) 量级。

下界说明：必须读完 `forward` / `backward`（否则不知道边长）、也必须读完 `queries`（否则不知道访问顺序），所以 O(n + q) 时间不可突破；O(n) 空间则来自「必须存下边长才能做 O(1) 求和」。

## 五、优化评估

**结论**：**时间复杂度已是最优**，无需再优化。

### 瓶颈分析

总耗时由两部分组成：建表 O(n) 与扫描 O(q)，两者都是「每个输入元素碰常数次」，没有可省的重复计算。查询循环里每次只有两次减法、两次比较与一次加法，常数已经很低。

### 可优化空间

时间上没有改进余地。空间上当前用两张长度 `2n` 的表，如果改成「只存长度 `n` 的表 + 一个环总长」，绕边界时用 `总长 - 直段` 来算，表可以缩到 `n` —— 代价是每个分支都要多写一次减法、代码可读性下降，而空间复杂度仍是 O(n)、不改变量级，**本机没必要这么做**。翻倍写法换来的「一句下标表达式打天下」更值得。

### 常数级优化（可选）

- 把 `forward + forward` 的拼接结果缓存成局部变量、`nxt_cost` / `pre_cost` 用局部名访问，能省下若干次属性查找；本题数据量下收益不明显，属于可写可不写。
- 循环内先把 `x_n = x + n` 算出来，两个分支共用，能少一次加法。同样属于微调。

## 六、易错点与总结

### 易错点

- **`y < x` 时忘了绕边界**：直接写 `nxt_cost[y] - nxt_cost[x]` 会得到**负数**，答案莫名其妙变小。这是本题最典型的一个 bug，且不报错、只是结果错。
- **把 `backward[i]` 当成 `i → i+1` 用**：`backward[i]` 是 `i → i-1`。方向搞反后示例 1 会算出偏大的值。
- **两张表的 `initial` 写成一样**：如果 `pre_cost` 也带 `initial=0`，`pre_cost[b] - pre_cost[a]` 就变成了 `backward[a] + … + backward[b-1]`，边界整体偏移一位，绕边界的分支会差出一条边的长度。此处「不对称」是对的，别顺手改成对称。
- **下标越界**：`x + n` 最大为 `n-1 + n = 2n-1`，`nxt_cost` 需要长度 `2n+1`（带 `initial` 正好是），`pre_cost` 需要长度 `2n`。如果只按长度 `n` 建表，绕边界的分支会直接 `IndexError`。
- **起点写错**：从房屋 `0` 出发，`x` 应初始化成 `0`。写成 `queries[0]` 会漏掉第一段移动。
- **以为要 DP**：这题没有「选择影响后续」的结构 —— 每段怎么走不影响下一段的代价，逐段取 min 就是全局最优，不要过度设计。

### 题型套路沉淀

- **环形数组求和 → 数组翻倍破环**：把 `a + a` 拼成长度 `2n` 的数组，任意环形区间都变成连续区间，`pref[r] - pref[l]` 一句搞定。凡是「环上区间和 / 环上距离」的题，先想这一招。
- **不同方向的边权 → 各建一张前缀表**：如果在环上正向、反向的边权不同，那它们是两个独立的权值序列，必须分别建表；同时注意边权「挂在下标哪一侧」，用 `initial` 的有无去对齐偏移，比在公式里到处 ±1 干净得多。
- **「按序经过给定点集，求总代价最小」= 逐段独立**：只要段与段之间无耦合（代价只由端点决定），就把「全局最优」拆成「每段最优」。判定依据是**无后效性**，而不是「看起来像贪心」。
- **前缀和的两种口径要分清**：`accumulate(a, initial=0)` 给左闭右开区间，不带 `initial` 给左开右闭区间。哪一侧的边权挂在区间端点上，就用哪种口径 —— 这是前缀和题最容易错一位的地方。
