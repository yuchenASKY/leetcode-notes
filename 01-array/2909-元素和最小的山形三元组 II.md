# 2909. 元素和最小的山形三元组 II

> **难度**：中等
> **标签**：数组 · 前缀和
> **原题链接**：https://leetcode.cn/problems/minimum-sum-of-mountain-triplets-ii/

---

## 一、题目描述

给定整数数组 `nums`，找出下标满足 `i < j < k` 且 `nums[i] < nums[j]`、`nums[k] < nums[j]` 的「山形三元组」，返回**元素和的最小值**；不存在则返回 `-1`。

换句话说：`nums[j]` 是山顶，左右各挑一个比自己**严格更小**的元素，求三者之和的最小值。

### 示例

```text
输入：nums = [8,6,1,5,3]
输出：9
解释：三元组 (2,3,4)：1 < 5、3 < 5，和为 1+5+3 = 9，且没有更小的合法组合。

输入：nums = [5,4,8,7,10,2]
输出：13
解释：三元组 (1,3,5)：4 < 7、2 < 7，和为 4+7+2 = 13。

输入：nums = [6,5,4,3,4,5]
输出：-1
解释：任意一个元素都找不到「右侧存在更小元素」的组合，无法构成山形。
```

### 约束条件

- `3 <= nums.length <= 10^5`
- `1 <= nums[i] <= 10^8`

---

## 二、解题思路

### 核心思想

**固定山顶 `j`，左右互不相干。** 对每个 `j`，左侧要挑一个比它小的（取左侧最小值），右侧要挑一个比它小的（取右侧最小值），三者相加就是一个候选答案；对所有 `j` 取最小即得结果。

### 思路演进

1. **暴力解法**：三重循环枚举 `(i, j, k)`，逐个校验 `i < j < k` 与两个不等式，取最小和。n = 10^5 时约 10^15 次组合，完全不可行。

2. **观察到**：一旦 `j` 确定，`i` 与 `k` 的选择就**完全解耦** —— `i` 只看 `[0, j-1]`，`k` 只看 `[j+1, n-1]`，两者互不约束，只各自要求 `< nums[j]`。既然互不影响，最优策略就是「左右各取最小」。于是三重循环塌成一次对 `j` 的一重循环，问题变成：**怎么在 O(1) 时间内拿到 `j` 左侧的最小值和右侧的最小值？**

3. **关键转化**：这正是「前缀最值 + 后缀最值」的用武之地。定义

   - `left_min[i] = min(nums[0..i])`
   - `right_min[i] = min(nums[i..n-1])`

   两者都能 O(n) 一遍递推出来。之后对每个 `j`，左候选 = `left_min[j-1]`，右候选 = `right_min[j+1]`。

4. **再进一步**：判据可以更省事 —— 不需要真的去找「哪个下标更小」，只要**最小值都小于 `nums[j]`**，那么取到该最小值的那个下标天然满足 `i < j` / `k > j`，合法三元组必定存在；反之若最小值都 ≥ `nums[j]`，说明整个左（右）区间没有任何元素满足严格小于，此时无解。**「存在性判断」与「最优值查询」被同一次 min 查询合并了**，这是本题能写得这么短的原因。

5. **实现层面的一个细节**：正序建 `left_min`、逆序建 `right_min` 本是两趟循环，但两者的递推方向正好相反，可以用负下标把它们塞进**同一趟** `for i in range(1, n)` 里 —— `left_min` 从 `i-1 → i` 往右长，`right_min` 用 `-i-1 → -i` 往左长，一趟同时建好两个数组。

### 关键点

- **区间必须排除 `j` 自己**：用 `left_min[j-1]` 和 `right_min[j+1]`。写成 `left_min[j]` 就等于把 `nums[j]` 自己也算进了最小值，条件 `left_min[j] < nums[j]` 永远不成立，答案恒为 `-1`。
- **两处都是严格小于**：`nums[i] < nums[j]` 与 `nums[k] < nums[j]`，等号不成立，所以判据写 `<` 而不是 `<=`。
- **前缀最小值单调不增**：`left_min[i] = min(left_min[i-1], nums[i])`，所以它只会越走越小；`right_min` 同理在反向递推时单调不增。
- **负下标映射**：`right_min[-i-1]` 等价于 `right_min[n-1-i]`，`right_min[-i]` 等价于 `right_min[n-i]`。`i = 1` 时填的是倒数第二个位置（`n-2`），到 `i = n-1` 时填到下标 `0`；`right_min[n-1]` 保持初值 `nums[-1]`，正好是它该有的值。
- **无解哨兵**：`ans` 初值取 `inf`，最后靠 `ans <= 10 ** 9` 判断是否被更新过。

## 三、代码实现

### 最终代码

```python
from typing import List   # 截图里没有，已补（LeetCode 环境预置了 typing）
from math import inf      # 截图里没有，已补（同上，预置了 math）

class Solution:
    def minimumSum(self, nums: List[int]) -> int:
        n = len(nums)
        left_min = [nums[0]] * n
        right_min = [nums[-1]] * n
        for i in range(1, n):
            left_min[i] = min(left_min[i - 1], nums[i])
            right_min[-1 * i - 1] = min(right_min[-1 * i], nums[-1 * i - 1])

        ans = inf
        for i in range(1, n - 1):
            if left_min[i - 1] < nums[i] and nums[i] > right_min[i + 1]:
                ans = min(ans, left_min[i - 1] + nums[i] + right_min[i + 1])
        return ans if ans <= 10 ** 9 else -1
```

## 五、优化评估

**结论**：时间复杂度已达下界，**空间 O(n) 是本题的结构性代价**，没有实用的 O(1) 改法。

### 瓶颈分析

代码一共扫两趟：第一趟同时递推前缀 / 后缀最小值（合趟是原代码已经做到的优化，避免了写两个 `for`），第二趟扫 `j` 求答案。两趟都是线性的，没有嵌套。

时间上不可能做到比 O(n) 更好：任何一个元素都可能成为山顶或成为某一侧的候选最小值，不看完整数组就无法排除它。

### 可优化空间

**时间**：O(n) 已是下界，没有进一步压缩余地。

**空间**：想降到 O(1)，就必须在扫到 `j` 时**同时**知道左右两侧的信息，但单向流式扫描天然拿不到「还没读到的那一半」的最小值。左到右扫可以 O(1) 维护前缀最小，代价是右侧信息得预先存下来 —— 无论选哪个方向，总要有一个 O(n) 的数组承载反向信息。所以这里的 O(n) 空间不是「写得不够省」，而是问题本身的对称结构决定的。

> 判断「有没有更优解」的标准不是「能不能少用一个数组」，而是「这个数组承载的信息能否在 O(1) 内被重建」—— 本题不能。

### 常数级优化（可选）

- **哨兵值可以更语义化**：`10 ** 9` 能成立，靠的是 `nums[i] <= 10^8` ⇒ 三数之和最大 `3 × 10^8 < 10^9`。这是个**隐式依赖值域**的写法，值域一变就错。改成 `return ans if ans is not inf else -1` 与值域解耦，意图也更清楚。
- **`left_min` 的最后一格是浪费的**：它只覆盖到下标 `n-2`（`left_min[i-1]` 中 `i` 最大取 `n-2`），数组末位永远不会被读。省掉这一格会把下标映射搞乱，得不偿失。
- 循环里 `left_min[i-1]`、`right_min[i+1]` 各被读了两次，可以先取到局部变量复用；但这点开销在 Python 里可以忽略，反而降低可读性，不建议改。

## 六、易错点与总结

### 易错点

- **把 `j` 自己算进最值**：写 `left_min[j] < nums[j]` 必然为假（`min` 含自己），结果是所有测试都返回 `-1`，但代码看起来完全正常 —— 这是本题最容易静默出错的点。
- **`<` 写成 `<=`**：题目要求严格小于，相等不构成山形。`nums = [1,1,1]` 这类用例会直接暴露。
- **负下标递推方向写反**：`right_min[-i - 1]` 从尾部向左填，`right_min[-i]` 是它的右邻居。若误写成 `right_min[i]`，填的就是前缀位置，后缀语义彻底错位。
- **哨兵与值域耦合**：`ans <= 10 ** 9` 依赖 `nums[i] <= 10^8`。题目值域若放大到 `10^9`，合法答案 `(2~3) × 10^9` 会被判成无解返回 `-1`，且没有任何报错。
- **`n = 3` 的边界**：`range(1, n - 1)` 此时只有 `i = 1` 一个值，恰好是唯一可能的山顶，写法本身已经覆盖，不需要额外特判（`n >= 3` 由约束保证）。
- **初值必须是真实值，不能填 `inf`**：`left_min = [nums[0]] * n` 里的 `nums[0]` 会在 `i = 1` 时被当作「左侧只有一个元素」的最小值读取，所以它必须是真值；若习惯性写成 `[inf] * n`，`left_min[0]` 就永远停在 `inf`，`i = 1` 处的判据必错。`right_min = [nums[-1]] * n` 同理（它负责 `i = n-2` 时那个位置）。

### 题型套路沉淀

- **「固定中间、左右解耦」**：凡是形如「找 `i < j < k` 且 `nums[j]` 相对两侧满足某单调关系」的题（山形 / 谷形 / 递增三元组），第一反应就是把 `j` 钉死，然后分别求左侧最值、右侧最值。双向预处理（前缀最值 + 后缀最值）是这类题的固定模板。
- **存在性判据与最优值查询合并**：当「要求存在某个元素严格小于 `x`」时，只需判断**区间最小值**是否 `< x` —— 最小值都不满足，则区间内无人满足；最小值满足，取到它的那个下标就是最优解。一次 min 查询同时回答了「有没有」和「取哪个」。
- **两趟反向递推可以合趟**：前缀类数组从左往右长、后缀类数组从右往左长，用负下标在一趟循环里同时推进，是减少循环次数的常用手法（可读性有代价，注释要写清楚）。
- **哨兵要与值域解耦**：能用 `inf` / `is inf` 判断「未更新」，就别用「比理论最大值更大的常数」去比大小 —— 后者一旦值域变动就会静默出错。
