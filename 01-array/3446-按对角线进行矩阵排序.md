# 3446. 按对角线进行矩阵排序

> **难度**：中等
> **标签**：数组 · 矩阵 · 排序
> **原题链接**：https://leetcode.cn/problems/sort-matrix-by-diagonals/

---

## 一、题目描述

给一个 `n × n` 的整数方阵 `grid`，按对角线方向（左上到右下）重新排列元素：

- **左下三角（含主对角线）**：每条对角线按**非递增**（降序）排列；
- **右上三角**：每条对角线按**非递减**（升序）排列。

返回调整后的矩阵。

### 示例

```text
输入：grid = [[1,7,3],[9,8,2],[4,5,6]]
输出：[[8,2,3],[9,6,7],[4,5,1]]
解释：
  左下三角（降序）：[1,8,6] → [8,6,1]；[9,5]、[4] 不变
  右上三角（升序）：[7,2] → [2,7]；[3] 不变
```

```text
输入：grid = [[0,1],[1,2]]
输出：[[2,1],[1,0]]
```

### 约束条件

- `grid.length == grid[i].length == n`
- `1 <= n <= 10`
- `-10^5 <= grid[i][j] <= 10^5`

## 二、解题思路

### 核心思想

**同一条对角线上的所有格子满足 `row - col` 恒定。** 把 `d = row - col` 当作对角线的编号，二维的「沿对角线遍历」就退化成一维参数遍历；再按 `d` 的符号决定这条对角线是升序还是降序。

### 思路演进

1. **朴素解法**：对每条对角线，先把整条的元素搬到临时数组里，`sort` 之后按下标写回。正确、直观，时间 `O(n² log n)`，代价是每条对角线要开 `O(n)` 的临时数组。
2. **观察到**：本题的矩阵规模极小（`n <= 10`），开临时数组其实毫无压力；真正值得练的是「**不借助额外空间，直接在矩阵上完成排序**」这件事 —— 于是把每一条对角线看成一个一维序列，对它做**插入排序**。
3. **优化为（本解法）**：固定差值 `i`，则
   - 左下三角（`d = i >= 0`）的格子写成 `grid[p + i][p]`，`p` 是沿对角线的步进下标；
   - 右上三角（`d = i > 0`）的格子写成 `grid[p][p + i]`。

   `p` 从 `0` 递增，把当前格 `p` 与前驱 `p - 1` 比较：降序时当前值更大就交换并继续往回走（把大数顶到前面），升序时当前值更小就交换 —— 这正是插入排序「逐元素前移到位」的动作。`p` 扫完一条对角线，这条对角线就有序了；`i` 扫过全部差值，整个矩阵就调整完毕。

   两轮循环分别处理「降序的左下」和「升序的右上」；主对角线（`i == 0`）在第一轮里已经按降序排好，第二轮必须**跳过**它。

### 关键点

- **`row - col` 是这套解法的地基**：它同时承担「对角线编号」和「区域划分」两个职责 —— `d <= 0` 是左下（含主对角线），`d > 0` 是右上。
- **两轮循环各管一半**：第一轮（`grid[p+i][p]`，降序）覆盖 `d = 0 .. n-1`；第二轮（`grid[p][p+i]`，升序）覆盖 `d = 1 .. n-1`，靠 `if i == 0: continue` 把主对角线排除在外。
- **边界条件分两段写**：`p > 0` 挡的是左上边界，`p + i < n` 挡的是右下边界，缺一个就会读越界。
- **比较方向与目标顺序必须一致**：降序用 `>` 触发交换，升序用 `<` 触发交换。

## 三、代码实现

> 截图里没有 `import`（LeetCode 环境已预置 `List`），此处补上 `from typing import List`。

### 最终代码

```python
from typing import List


class Solution:
    def sortMatrix(self, grid: List[List[int]]) -> List[List[int]]:
        n = len(grid)
        for i in range(n):
            for j in range(n):
                temp = j
                right = j
                while temp > 0 and temp + i < n and grid[temp + i][temp] > grid[temp + i - 1][temp - 1]:
                    grid[temp + i][temp], grid[temp + i - 1][temp - 1] = grid[temp + i - 1][temp - 1], grid[temp + i][temp]
                    temp -= 1
                if i == 0:
                    continue
                while right > 0 and right + i < n and grid[right][right + i] < grid[right - 1][right + i - 1]:
                    grid[right][right + i], grid[right - 1][right + i - 1] = grid[right - 1][right + i - 1], grid[right][right + i]
                    right -= 1
        return grid
```

| 理论下界 | O(n² log n) | O(1) |

## 五、优化评估

**结论**：空间已是理论下界 **O(1)**；时间复杂度 **O(n³) 未到最优**，但在本题 `n <= 10` 的规模下完全无压力，没有必要改。

### 瓶颈分析

- **时间**：对角线长度从 1 递增到 n、再递减回 1，插入排序在长度 L 的对角线上是 `O(L²)`，把所有对角线加起来是 `sum(L²) ≈ 2n³/3`，所以整体 `O(n³)`。具体到 `n = 10`，全部对角线的 `sum(L²) = 670`、最坏交换次数约 285 —— 一次提交几十微秒的量级，谈不上瓶颈。
- **空间**：全程只用了两个下标游标 `temp` / `right` 和一个交换临时值，`O(1)` 额外空间，这条已经压到底了。

### 可优化空间

时间上能降到 `Θ(n² log n)`：每条长度 L 的对角线的信息论下界是 `L log L` 次比较，所有对角线求和后主导项来自两条长度 n 的对角线，即 `Ω(n² log n)`。要摸到这个界，就得用比较排序而不是插入排序 —— 而比较排序要么开 `O(n)` 辅助空间（取出到数组后 `sort`），要么实现原地的堆排序。

所以这里本质是**「时间换空间」与「空间换时间」的取舍**：本解法选了 `O(1)` 空间，代价是 `O(n³)` 时间；取数组版本反过来。题目 `n <= 10`，两者都在时限内，选哪个只看需不需要就地完成（例如矩阵以引用形式共享时）。

### 优化代码

不要求原地时，直接取出排序更简洁，也更快：

```python
from typing import List


class Solution:
    def sortMatrix(self, grid: List[List[int]]) -> List[List[int]]:
        n = len(grid)
        for i in range(n):                     # i = row - col
            # 左下三角（含主对角线）：降序
            vals = [grid[p + i][p] for p in range(n - i)]
            vals.sort(reverse=True)
            for p, v in enumerate(vals):
                grid[p + i][p] = v
            if i == 0:
                continue
            # 右上三角：升序
            vals = [grid[p][p + i] for p in range(n - i)]
            vals.sort()
            for p, v in enumerate(vals):
                grid[p][p + i] = v
        return grid
```

**优化理由**：把「沿对角线收集元素」显式化成一维列表，用内建排序替换手写插入排序，时间从 `O(n³)` 降到 `O(n² log n)`，代价是每条对角线 `O(n)` 的临时列表（最大长度 n）。

### 常数级优化（可选）

大 O 不变，只是省一点常数：

- **把 `i == 0` 的判断提到内层循环外**：两轮 `j` 循环拆开写，只在真正需要的地方判一次，而不是每个 `j` 都判一次。
- **缓存重复的下标运算**：`grid[temp + i]` 这类子表达式在 while 条件里要算多次，提成局部变量能省一点下标加法。
- **`>=` / `<=` 与 `>` / `<`**：对正确性没有影响（相等时交换是空转），但用严格不等号能少做无效交换。

## 六、易错点与总结

### 易错点

- **主对角线被两轮都处理**：第一轮把它排成降序，若第二轮没有 `if i == 0: continue` 跳过，又会被排回升序，与题意完全相反。这是本题最容易翻车的一处。
- **索引顺序写反**：左下用 `grid[p + i][p]`（行偏移在前），右上用 `grid[p][p + i]`（列偏移在前），两者混用会读到不同对角线的元素，且往往不报错、只是结果悄悄错。
- **边界只判了一半**：`p > 0` 只挡住左上越界，`p + i < n` 才挡右下越界；漏掉后者会 `IndexError`。
- **两个游标共用**：降序轮用 `temp`、升序轮用 `right`，如果合并成一个变量继续用，上一轮残留的步进位置会污染下一轮。
- **比较方向与目标顺序对不上**：降序要「当前更大就往前顶」（`>`），升序要「当前更小就往前顶」（`<`），写反了排序结果就整条反过来。

### 题型套路沉淀

- **矩阵「沿对角线」操作的通用套路**：先用 `row - col`（主对角线走向）或 `row + col`（反对角线走向）确定对角线编号，再把格子写成该编号的**一元函数**（本题是 `grid[p+i][p]` / `grid[p][p+i]`）。做完这一步，「二维矩阵 + 对角线约束」就变成「若干个一维数组各自操作」，几乎所有同类型题都是这个起手式。
- **差值的符号天然切分左右三角**：`d <= 0` 与 `d > 0`（或 `d >= 0` / `d < 0`）正好对应两个三角，含不含主对角线按题意核对一遍再动笔。
- **排序粒度的判断**：如果题目只说「每条对角线上排序」，那是 n 条互相独立的一维序列；如果还说「整体有序」（例如逐层填充），才需要构造复合键。本题是前者，别想复杂。
- **原地 vs 非原地的取舍要主动说清**：这类题给「取出排序写回」一定能 AC，但能否在 `O(1)` 空间下完成，取决于会不会手写原地排序（插入排序在这种短序列上就是最顺手的工具）。
