# 121. 买卖股票的最佳时机

> **难度**：简单
> **标签**：数组 · 动态规划
> **原题链接**：https://leetcode.cn/problems/best-time-to-buy-and-sell-stock/

---

## 一、题目描述

给定数组 `prices`，`prices[i]` 是某支股票第 `i` 天的价格。**只能完成一笔交易**（选一天买入、在之后的某一天卖出），求能获取的最大利润。若无法获利（价格全程不涨），返回 `0`。

### 示例

```text
示例 1
输入：prices = [7,1,5,3,6,4]
输出：5
解释：第 2 天（价格 1）买入，第 5 天（价格 6）卖出，利润 6-1=5。
      注意 7-1=6 不合法：买入日必须早于卖出日。

示例 2
输入：prices = [7,6,4,3,1]
输出：0
解释：价格单调下跌，任何一笔交易都亏，选择不交易。
```

### 约束条件

- `1 <= prices.length <= 10^5`
- `0 <= prices[i] <= 10^4`

---

## 二、解题思路

### 核心思想

固定「卖出日」，能拿到的最好买入价必然是**它之前所有价格的最小值**。于是把「枚举买入日 + 卖出日」压成一次遍历：边走边维护前缀最小值。

### 思路演进

1. **暴力解法**：枚举买入日 `i` 和卖出日 `j`（`j > i`），取 `max(prices[j] - prices[i])`。时间复杂度 `O(n²)`，`n = 10^5` 时约 5×10^9 次比较，必然超时。空间 `O(1)`。

2. **观察到**：内层循环在「固定卖出日 `j`」时做的事，其实只是在找 `prices[0..j-1]` 里的最小值。而这个最小值**可以随 `j` 递增 O(1) 地增量维护** —— 第 `j` 天之前的最低价 = 第 `j-1` 天之前的最低价与 `prices[j-1]` 取 min。既然买入价这个「内层循环的结果」能被增量更新，内层循环就整层消失了。

3. **优化为**：一次从左到右的扫描，同时维护两个量：
   - `min_price`：截至目前（含当天）见过的最低价，即"如果今天卖，最佳买点在哪"；
   - `ans`：截至目前的最大利润。

   每天做两件事：先用当天价格更新 `min_price`，再用「当天价格 − `min_price`」去更新 `ans`。

   这一步把两重枚举合成了单重遍历，`O(n²) → O(n)`。

4. **为什么它等价于 DP**：`min_price[j]` 就是状态「第 `j` 天卖出时能取得的最大利润」的前驱量，`ans = max(ans, prices[j] - min_price[j])` 即转移。所以本解法也可视为最简状态机 DP 退化成一维滚动后的结果 —— 本题的 `tags` 里 `动态规划` 正来自这层对应关系。

### 关键点

- **顺序不能反**：必须**先**用当前价刷新最低价、**再**用当前价算利润，保证买入日不晚于卖出日（跨到之后的价格里）。本题因为「同日买卖」差值为 `0` 不会抬升答案，写反了也能 AC；但一旦题目变体要求"必须交易"或"至多两笔"，顺序写反就会把非法交易算进去 —— 按正确顺序写，是为了让骨架可以直接迁移。
- **最低价必须来自卖出日之前**：不能用全局 `min(prices)` 当买入价，再去它后面找最高价卖（见「易错点」第一条）。
- **`ans` 初值为 `0`**：等价于"允许不交易"，自动覆盖单调下跌的情况。
- 只做**一笔**交易，利润不能分段累加。

## 三、代码实现

### 最终代码

```python
from math import inf


class Solution:
    def maxProfit(self, prices: list[int]) -> int:
        ans = 0
        num = inf          # num 记录「截至目前的最低价」
        for i in prices:
            num = min(num, i)       # 先刷新最低买入价
            ans = max(ans, i - num)  # 再以今天为卖出日结算利润
        return ans
```

> `from math import inf` 截图里没有、已补 —— 缺少它时 `inf` 会触发 `NameError`。

## 四、复杂度分析

| 版本 | 时间复杂度 | 空间复杂度 |
| :--- | :--- | :--- |
| **最终代码** | `O(n)` | `O(1)` |
| 朴素解法（双重枚举） | `O(n²)` | `O(1)` |
| 理论下界 | `O(n)` | `O(1)` |

> 复杂度中的 n 指：`prices` 数组的长度，即交易天数。

## 五、优化评估

**结论**：已是最优 —— 时间、空间均触及下界。

### 瓶颈分析

时间全部花在「把 `prices` 读一遍」上，循环体内只有两次比较和一次减法，没有任何嵌套。空间只有 `ans`、`num` 两个标量。

### 可优化空间

- **时间不可能降到亚线性**：任一天的价格若不被读到，就无法判断它是否是更低的买点、或是否是更高的卖点，因此每个元素都必须至少被访问一次，`Ω(n)` 是硬下界，当前已是 `O(n)`。
- **空间不可能再省**：辅助变量已是常数个，`O(1)` 本身即下界（输入不计入）。
- 因此本题没有「换更优算法」的余地，剩下的只有常数级取舍。

### 常数级优化

以下是可读性/依赖上的取舍，不是算法改进：

- `num = inf` 需要额外 `import`；改用 `num = prices[0]` 并让循环从第二个元素开始，可去掉该依赖，语义完全等价（第 1 天不可能是卖出日）。
- `min`/`max` 每次调用有一次函数调用开销，手写 `if` 判断可省掉，但代码可读性下降，本笔记不采用。

## 六、易错点与总结

### 易错点

- **❌ 用全局最低价当买点**：`min_price = min(prices)`，再取它之后的最大值。这是本题最典型的错解 —— 数组的全局最低点可能出现在最高点**之后**，此时这一段"买入→卖出"在时间上是倒序的，不合法。例如 `[7,1,5,3,6,4]` 用全局最低价 `1` 恰好没问题，但 `[2,4,1]` 会算出 `4-1=3`，而正确答案是 `4-2=2`（最低点 `1` 在最后，买不了）。→ 最低价必须是**前缀**上的最低价，这正是"边扫边更新"不可省略的原因。
- **❌ 先算利润、后更新最低价**：在"必须交易"的变体里会引入同日买卖；本题因差值为 0 侥幸不出错，但骨架不可直接复用。
- **❌ 允许累加多笔**：把每段上涨的差值加起来（如 `[1,5,3,6]` 累加 `4+3=7`）是「III/多笔交易」的答案，本题只允许一笔，答案应为 `5`。
- **❌ `ans` 初始化成负无穷**：会丢掉"不交易返回 0"的分支，单调下跌时输出负数。
- **⚠️ 变量命名**：`num` 实际语义是"最低买入价"，不是"当前价格"，`i` 才是当前价格。二刷时建议改成 `min_price` / `min_buy`，避免读代码时把两者混用。

### 题型套路沉淀

- **「单次买卖求最大差」模板 = 一次遍历 + 前缀极值**：`前缀最小买入价` 与 `当前价` 作差。识别的关键是题面里出现"i 买、j 卖且 i < j"这种**有序约束** —— 有序约束 → 增量维护前缀最值，是无序最值（全局 min/max）不可替代的。
- **前缀极值 vs 全局极值**：凡是"先做 A 再做 B、且顺序有要求"的题，B 的候选集只能是 A 之后的部分，所以只能用前缀/后缀极值，不能整体求最值。这条比本题本身更有迁移价值。
- **同族变体的分叉点**：本题是 `1 笔 + 允许不交易`；放宽成「至多 k 笔」后一维遍历不够用，需要 `buy[i]` / `sell[i]` 的状态机 DP，但状态转移的每个分量仍然是本题这一行的推广 —— 先吃透本题的"先刷新最低价、再结算利润"两行，推广时不容易写反方向。
