# 2874. 有序三元组中的最大值 II

> **难度**：中等
> **标签**：数组
> **原题链接**：https://leetcode.cn/problems/maximum-value-of-an-ordered-triplet-ii/

---

## 一、题目描述

给定下标从 0 开始的整数数组 `nums`。在所有满足 `i < j < k` 的下标三元组 `(i, j, k)` 中，求 `(nums[i] - nums[j]) * nums[k]` 的最大值；若所有三元组的值都为负，返回 `0`。

### 示例

```text
输入：nums = [12,6,1,2,7]
输出：77
解释：下标三元组 (0, 2, 4) 的值是 (nums[0] - nums[2]) * nums[4] = (12 - 1) * 7 = 77，
     可以证明不存在值大于 77 的有序下标三元组。

输入：nums = [1,10,3,4,19]
输出：133
解释：下标三元组 (1, 2, 4) 的值是 (nums[1] - nums[2]) * nums[4] = (10 - 3) * 19 = 133。
     注意 j 取的是 2 而不是 3：nums[3] = 4 虽然更靠右，但 (10 - 4) * 19 = 114 < 133，
     中间项要的是"尽量小"，与右边要"尽量大"是两个不同方向。

输入：nums = [1,2,3]
输出：0
解释：唯一的三元组 (0, 1, 2) 值为 (1 - 2) * 3 = -3，为负，返回 0。
```

### 约束条件

- `3 <= nums.length <= 10^5`
- `1 <= nums[i] <= 10^6`

---

## 二、解题思路

### 核心思想

**固定中间下标 `j`，把表达式拆成「左边最大值」「中间值」「右边最大值」三段，用前缀最大值 + 后缀最大值两次扫描搞定。** 单个 `j` 的最优值是 `(max(nums[0..j-1]) - nums[j]) * max(nums[j+1..n-1])`。

### 思路演进

1. **暴力解法**：三重循环枚举 `i < j < k`，逐个算 `(nums[i] - nums[j]) * nums[k]` 取最大。时间 O(n³)，n = 10^5 时是 10^15 量级，完全不可行 —— 这题的数据范围就是为了逼出 O(n) 才设成 10^5 的（它的上一版数据范围只有 100，三重循环能过）。

2. **观察到**：把表达式按角色拆开看：

   ```text
   (nums[i] - nums[j]) * nums[k]
     ↑被减数      ↑减数      ↑乘数
   ```

   对**固定**的 `j` 和 `k` 来说，`nums[i]` 只以「被减数」身份出现，**它取多少完全不影响 `j`、`k` 的合法性**（合法性只由下标顺序决定，与取值无关）。而 `A - nums[j]` 随 `A` 单调递增 ⇒ 左边直接取 `max(nums[0..j-1])` 即可，不需要枚举 `i`。
   同理，对固定的 `j`，`nums[k]` 是纯乘数 ⇒ 直接取 `max(nums[j+1..n-1])`。

3. **优化为**：只剩一层枚举 `j`。预处理 `sufMax[j] = max(nums[j..n-1])`（从右往左一遍），再从左往右扫 `j`，同时维护 `preMax = max(nums[0..j-1])`。整体 O(n)。

### 关键点

- **「各自取最值」需要符号条件，不能无条件套用。** 这里能取 `nums[k]` 的最大值，是因为题目约束 `nums[i] >= 1`，即 `nums[k]` 恒为正 —— 正乘数下，差值无论正负都是「越大越好」：差值为正时乘大得大，差值为负时乘大"更接近 0"（仍是最大的那个负值）。**若 `nums[k]` 允许为负，这个化简立刻失效**，就得同时保留右边的最小值一起算。这是本题最容易写对却讲不清的地方。
- **`preMax` 的更新必须在算完当前 `j` 之后**：先 `ans = max(ans, (preMax - nums[j]) * suf[j+1])`，再 `preMax = max(preMax, nums[j])`。写反了 `nums[j]` 会拿自己当 `i`，`i < j` 被破坏。
- **取 `suf[j+1]` 而不是 `suf[j]`**：`k` 必须严格大于 `j`。
- **`ans` 初值取 `0`**：正好满足"全为负返回 0"的要求，不需要额外判断。负数永远打不过初值 0，所以不必用 `-inf` 初始化再特判。
- 循环范围 `j ∈ [1, n-2]`：`j` 两边都必须至少有一个元素，`suf[j+1]` 才不越界。

## 三、代码实现

### 最终代码

```python
from typing import List


class Solution:
    def maximumTripletValue(self, nums: List[int]) -> int:
        n = len(nums)

        # suf[i] = max(nums[i..n-1])，从右往左一遍即可
        suf = [0] * n
        suf[-1] = nums[-1]
        for i in range(n - 2, -1, -1):
            suf[i] = max(suf[i + 1], nums[i])

        ans = 0
        pre = nums[0]                      # pre = max(nums[0..j-1])
        for j in range(1, n - 1):
            # 先用 pre（此时它还没吃到 nums[j]），保证 i < j
            ans = max(ans, (pre - nums[j]) * suf[j + 1])
            pre = max(pre, nums[j])        # 用完再更新
        return ans
```

> `from typing import List` 是截图里没有的，已补上，否则本地跑会 `NameError`。

## 五、优化评估

**结论**：时间复杂度已到理论下界，**空间还能从 O(n) 压到 O(1)**。

### 瓶颈分析

时间上必须至少扫一遍数组才能知道所有元素，O(n) 不可突破。空间上的 O(n) 来自 `suf` 数组 —— 但它其实只是给每个 `j` 提供"右侧最大值"这一条信息。

### 可优化空间

**省掉 `suf` 数组。** 把「枚举 `j`、用前后两段最值」的做法等价改写成**增量式状态**：从左往右扫时，同时维护两个量 ——

- `preMax` = 目前见过的最大 `nums[i]`；
- `bestDiff` = 目前所有合法 `(i < j)` 数对中 `nums[i] - nums[j]` 的最大值。

当扫到位置 `k` 时，`bestDiff` 里已经装好了「结束于 `k` 之前的最优差值」，直接乘 `nums[k]` 就是候选答案；**先算答案，再把当前位置当作 `j` 去更新 `bestDiff`，最后当作 `i` 去更新 `preMax`**。这样只需两个变量，空间 O(1)。

### 优化代码

```python
from typing import List


class Solution:
    def maximumTripletValue(self, nums: List[int]) -> int:
        NEG = -10 ** 18                    # 比任何合法差值都小（nums[i] >= 1，差值最小约 -1e6）
        pre_max = nums[0]
        best_diff = NEG                    # 还没有任何合法 (i, j) 数对
        ans = 0
        for k in range(1, len(nums)):
            ans = max(ans, best_diff * nums[k])          # ① 先把当前位置当 k 用掉
            best_diff = max(best_diff, pre_max - nums[k])  # ② 再当 j
            pre_max = max(pre_max, nums[k])                # ③ 最后当 i
        return ans
```

**优化理由**：`best_diff` 是前缀最大值 `pre_max` 与当前值的差的最大值，它把「左边最大」这一步压缩成了一个滚动变量，于是右侧不需要任何后缀数组。三步顺序 ①②③ 分别对应「`k` 用旧状态、`j` 紧接其后、`i` 最后」—— 这个顺序是正确性的全部保证，调换任意两步都会引入非法的下标关系（例如先更新 `pre_max` 再算 `ans`，就会出现 `i == k`）。

### 常数级优化（可选）

- 用户版本里每轮循环调一次 `max()`，可以改成 `if` 比较，省掉函数调用开销；但在 O(n) 已是最优的前提下，这属于纯常数层面，收益有限，可读性换性能，一般不必。
- `suf` 可以用列表推导 + 从右往左的 `itertools.accumulate(..., max)` 生成，写法更短但本质不变。

## 六、易错点与总结

### 易错点

- **`pre` 更新时机写反**（先更新再计算），使 `nums[j]` 自己参与了「左边最大值」，`i < j` 被破坏。
- **写成 `suf[j]` 而不是 `suf[j + 1]`**：`k` 取到了 `j` 本身，等于 `k == j`。
- **`ans` 初始化成 `-inf`**：本题要求全负时返回 0，用 `-inf` 还得补一句 `max(0, ans)`；直接初值 0 更省事。
- **误以为可以无条件"左边取最大、右边取最大"**：本题成立的前提是 `nums[k] > 0`（约束保证 `nums[i] >= 1`）。把它迁移到"乘数可为负"的变体上会直接算错。
- **忘记补 `from typing import List`**：LeetCode 环境内置，本地跑必炸。
- **C++/Java 用 `int` 存结果**：`nums[i] - nums[j]` 最大约 10^6、`nums[k]` 最大 10^6，乘积可达 10^12，必须 `long long` / `long`。Python 无此问题。

### 题型套路沉淀

- **「有序下标三元组求最值」的通用拆法**：先固定一个下标，看表达式能否拆成「该下标左右两侧各自的最值」。能拆 ⇒ 前缀/后缀最值预处理 + 单层枚举，O(n²) 或 O(n³) 直接降一两个数量级。
- **先问「能不能各自取最值」**：判据是「变量之间的约束是否只有下标顺序、不含取值耦合」。有耦合（比如要求 `nums[i] < nums[j]`）就不能独立取下标，得换单调栈 / 树状数组那一类。
- **再看「取最值的方向是否唯一」**：加法和正数乘法下"越大越好"；一旦出现负数、减法方向反转、绝对值等情况，就得同时维护最大和最小两条链。
- **状态压缩的味道**：凡是"固定分割点 + 两侧预处理"能解的题，几乎都能改写成从左往右滚动两三个变量的增量形式（本题的 `pre_max` + `best_diff` 就是典型），这是把 O(n) 空间压到 O(1) 的固定套路。
- **同型题**：`2873. 有序三元组中的最大值 I`（数据范围只有 100，三重循环即可，用来对照"为什么需要 O(n)"）、`1014. 最佳观光组合`（固定右端点，维护左侧最优 `nums[i] + i`，本质是同一招）。
