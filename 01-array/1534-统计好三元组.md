# 1534. 统计好三元组

> **难度**：简单
> **标签**：数组 · 枚举
> **原题链接**：https://leetcode.cn/problems/count-good-triplets/

---

## 一、题目描述

给定整数数组 `arr` 和三个阈值 `a`、`b`、`c`，统计满足 `i < j < k` 且三对差值分别受 `a`、`b`、`c` 限制的三元组 `(arr[i], arr[j], arr[k])` 个数。注意三个条件对应的是三对元素：`(i, j)` 用 `a`、`(j, k)` 用 `b`、`(i, k)` 用 `c`。

### 示例

```text
输入：arr = [3,0,1,1,9,7], a = 7, b = 2, c = 3
输出：4
解释：4 个好三元组为 [(3,0,1), (3,0,1), (3,1,1), (0,1,1)]
（arr[1] 与 arr[3] 都是 1，两个下标产生的三元组分别计数）

输入：arr = [1,1,2,2,3], a = 0, b = 0, c = 1
输出：0
解释：a = b = 0 要求相邻两值完全相等，而 2 与 3 不相等，凑不出三段全等的三元组
```

### 约束条件

- `3 <= arr.length <= 100`
- `0 <= arr[i] <= 1000`
- `0 <= a, b, c <= 1000`

---

## 二、解题思路

### 核心思想

**固定中间元素 `j`，把三条约束拆成两个互不干扰的单侧候选集。** 固定 `j` 之后，`i` 只受 `i < j` 与 `|arr[i]-arr[j]| <= a` 限制，`k` 只受 `k > j` 与 `|arr[k]-arr[j]| <= b` 限制 —— 两者独立，剩下的 `|arr[i]-arr[k]| <= c` 变成一个「两个有序集合之间的配对计数」，用双指针一遍扫完。

### 思路演进

1. **暴力解法**：三层循环枚举 `i < j < k`，逐条校验三个不等式。正确但每次都要从头判断，复杂度 `O(n³)`；`n = 100` 时约 16 万次组合，能过，但重复劳动明显 —— 固定 `j` 后，`i` 与 `k` 的合法性其实与对方无关。

2. **观察到**：三个条件里有两个（`a`、`b`）只涉及"一对元素"，只有 `c` 是跨 `i`、`k` 的。于是固定 `j`，可以先筛出左候选集 `L = {arr[i] | i < j, |arr[i]-arr[j]| <= a}` 和右候选集 `R = {arr[k] | k > j, |arr[k]-arr[j]| <= b}`，问题降为：在 `L × R` 中数出 `|x - z| <= c` 的对数。这一步把 `O(n³)` 的枚举压成了「`n` 次 `O(n)` 的筛选 + 一次配对计数」。

3. **优化为**：配对计数若对每个 `x` 都在 `R` 里二分，是 `O(|L| log|R|)`；但 `x` 递增时窗口 `[x-c, x+c]` 只向大值侧平移，于是用两个指针 `k1`（左边界，开区间 `< x-c`）与 `k2`（右边界，闭区间 `<= x+c`）单调前进，整体 `O(|L| + |R|)`，总复杂度 `O(n²)`。

4. **顺序从哪来**：两条约束都要求「值有序」才能用指针，而「保留下标顺序」又要求不能直接对数组排序。做法是先算出 `idx = sorted(range(n), key=lambda i: arr[i])` —— 这是**按下标取值升序**的遍历序列，再用它过滤出 `L`、`R`，得到的两个列表天然升序，同时 `i < j`、`k > j` 这些下标约束依旧用原始下标判断，一个都不丢。

### 关键点

- **排序只决定遍历顺序，不改变下标语义**：`idx` 里存的仍是原始下标，`i < j < k` 必须始终按下标判，否则会把 `(i, k)` 前后颠倒的组合重复计数。
- **`L`、`R` 必须由同一个 `idx` 过滤得到**：若偷懒写成 `arr[:j]` 取左集，`L` 就不再升序，双指针会漏数。
- **两个指针的边界开闭必须区分**：`k2` 用 `<= x + c` 累计右边界，`k1` 用 `< x - c` 跳过太小值，答案累加 `k2 - k1`；若把 `k1` 也写成 `<=`，等于 `x - c` 的元素会被漏掉。
- **`k1`、`k2` 不能在内层重置**：它们是跨 `x` 单调前进的，一旦每次重置就退化成 `O(|L|·|R|)`。

## 三、代码实现

### 最终代码

```python
from typing import List   # 截图里没有、已补（LeetCode 环境自带，本地运行需显式导入）


class Solution:
    def countGoodTriplets(self, arr: List[int], a: int, b: int, c: int) -> int:
        # 按下标取值排序：遍历顺序按值升序，但保存的仍是原始下标
        idx = sorted(range(len(arr)), key=lambda i: arr[i])
        ans = 0
        for j in idx:
            y = arr[j]
            # 固定中间元素 j：左集只受 a 约束、右集只受 b 约束；
            # 两者都由 idx 过滤而来，因此保持值升序
            left = [arr[i] for i in idx if i < j and abs(arr[i] - y) <= a]
            right = [arr[k] for k in idx if k > j and abs(arr[k] - y) <= b]

            k1 = k2 = 0
            for x in left:          # x 递增 ⇒ 窗口 [x-c, x+c] 单调右移，两指针只前进
                while k2 < len(right) and right[k2] <= x + c:
                    k2 += 1
                while k1 < len(right) and right[k1] < x - c:
                    k1 += 1
                ans += k2 - k1
        return ans
```

## 四、复杂度分析

| 版本 | 时间复杂度 | 空间复杂度 |
| :--- | :--- | :--- |
| **最终代码** | O(n²) | O(n) |
| 朴素解法（三重循环枚举） | O(n³) | O(1) |
| 理论下界 | Ω(n) | O(1) |

> 复杂度中的 n 指：`arr` 的长度。
> 最终代码外层枚举 n 个中间元素，每层扫三遍（构造 `left`、构造 `right`、双指针），即 `3n`，合计 `O(n²)`；额外空间是 `idx`、`left`、`right` 三个长度不超过 n 的列表。
> 理论下界只给到「至少要读完输入」的 `Ω(n)`：本题没有已知的更强下界，而且 `n <= 100` 的规模下 `O(n³)` 的实际开销也很小，所以这里写 `O(n²)` 是为了结构上更稳，而不是为了过时限。

## 五、优化评估

**结论**：在本题规模下已经够用，没有必做的进一步优化。

### 瓶颈分析

时间全部花在「对每个 `j` 重新筛一遍全体元素」上：`a`、`b` 的上界随 `y = arr[j]` 变化，`L`、`R` 的内容换一个 `j` 就全变，无法在 `j` 之间复用。唯一被复用下来的是「按值有序」这个性质，也正是双指针能成立的原因。

### 可优化空间

- 想再降阶就要在 `j` 之间复用筛选结果，但 `a`、`b` 形成的值区间随 `j` 平移，同时还要维持下标顺序，不存在既省时间又不加结构的写法 —— 换言之，`O(n²)` 是这条思路的收口。
- 另一个方向是按值域计数整桶（`arr[i] <= 1000`），但要额外维护「每个值的下标序列」，判 `i < j < k` 反而更啰嗦；`n <= 100` 时完全没必要。
- 所以本题更实际的结论是：**`O(n³)` 的直白三重循环本来就够过，这里的 `O(n²)` 是写法上的收紧，不是必需。**

### 常数级优化（可选）

- `len(right)` 在两层 `while` 里会被反复求值，可提到循环外存成局部变量；本题规模下这对结果与可读性都没有实质影响，不改也不亏。

## 六、易错点与总结

### 易错点

- **把排序结果当成下标**：`idx` 是"按值升序的下标序列"，不是"值序列"。任何需要 `i < j < k` 的判断都必须回到原始下标，用 `arr[i]` 和 `i` 混着比就全错了。
- **用切片代替过滤**：`left` 若从 `arr[:j]` 取，虽满足下标约束但失去有序性，双指针会静默漏数（不报错、只是答案偏小）。
- **`a`、`b` 用错位置**：`a` 管 `(i, j)`，`b` 管 `(j, k)`，`c` 管 `(i, k)`。把 `b` 套到 `left` 上是这题最常见的抄写错误，而示例 2 里 `a = b = 0` 恰好对称，测不出来。
- **开闭区间写反**：`k1` 必须用 `< x - c`（严格小于）跳过过小值，`k2` 用 `<= x + c`；写成同一种比较符就会差一。
- **指针被重置**：`k1`、`k2` 定义在 `for x in left` 之外，靠单调性保证正确；放进循环体内重置虽然答案可能仍对，但复杂度退化为 `O(|L|·|R|)`。
- **`List` 未导入**：LeetCode 环境预置了 `typing.List`，本地直接跑会 `NameError`，抄代码时容易漏。

### 题型套路沉淀

- **三元组计数类问题的通用拆法**：固定中间元素 → 把三条约束拆成「左单侧」「右单侧」两个独立筛选 + 一条跨侧约束。跨侧约束若能写成区间形式，配对计数就从枚举变成双指针/二分。
- **"既要值有序、又要原下标有序"时的标准动作**：`sorted(range(n), key=...)` 拿一个按值排序的下标序列，之后的过滤、判下标、双指针全部复用这一个序列，避免二次排序。
- **双指针成立的两个前提**要逐一核对：被扫的序列有序、扫描量（这里是 `x`）单调。缺任一条都不能用双指针。
- **本题规模判断**：`n <= 100`、值域 `<= 1000`，属于「怎么写都能过」的题；练手价值在于把 `O(n³)` 收紧到 `O(n²)` 的推导过程，而不是复杂度本身。
