# 3917. 统计下标的相反奇偶性得分

> **难度**：简单
> **标签**：数组
> **原题链接**：https://leetcode.cn/problems/count-indices-with-opposite-parity/

---

## 一、题目描述

给定长度为 `n` 的整数数组 `nums`。下标 `i` 的**分数**定义为满足 `i < j < n` 且 `nums[i]` 与 `nums[j]` **奇偶性不同**（一奇一偶）的下标 `j` 的**个数**。要求返回长度为 `n` 的数组 `answer`，其中 `answer[i]` 是下标 `i` 的分数。

### 示例

```text
输入：nums = [1,2,3,4]
输出：[2,1,1,0]
解释：
  i=0，nums[0]=1（奇）：j=1(偶)、j=3(偶) 满足 → 2
  i=1，nums[1]=2（偶）：j=2(奇) 满足 → 1
  i=2，nums[2]=3（奇）：j=3(偶) 满足 → 1
  i=3，nums[3]=4（偶）：右侧无元素 → 0

输入：nums = [1]
输出：[0]
解释：只有一个元素，下标 0 的分数为 0。
```

### 约束条件

- `1 <= nums.length <= 100`
- `1 <= nums[i] <= 100`

---

## 二、解题思路

### 核心思想

**分数只和「右侧那些元素的奇偶性」有关，而右邻居与 `nums[i]` 的奇偶关系只有两种**，于是 `answer[i]` 可以由 `answer[i+1]` 直接推出：奇偶相同就继承，奇偶不同就取「互补计数」。

### 思路演进

1. **暴力解法**：对每个 `i`，再枚举所有 `j > i` 统计奇偶不同的个数。时间 O(n²)、空间 O(1)。n ≤ 100 时完全能过，但这是本题的起点而不是终点。
2. **观察到**：`i` 向右移动一位时，集合 `{j : j > i}` 只比 `{j : j > i+1}` 多了一个元素 `j = i+1`。也就是说相邻两个位置的「候选集合」几乎相同，只有**一个元素的差**，不该从头重数一遍。
3. **进一步观察**：设 `f(i)` 为下标 `i` 的分数。讨论 `nums[i]` 与 `nums[i+1]` 的奇偶关系：
   - **奇偶相同**（都是奇或都是偶）：`i` 与 `i+1` 要找的是同一批「相反奇偶」的元素，右侧集合也几乎一致，唯一差的那个 `j = i+1` 与 `nums[i]` 同奇偶、本来就不算分 ⇒ `f(i) = f(i+1)`。
   - **奇偶不同**：此时「与 `nums[i]` 奇偶相反」等价于「与 `nums[i+1]` 奇偶相同」。而 `f(i+1)` 数的是 `j > i+1` 中与 `nums[i+1]` 相反的个数（即与 `nums[i]` 相同的个数）。右侧 `j > i` 一共 `n-1-i` 个元素，去掉这 `f(i+1)` 个「与 `nums[i]` 相同」的，剩下的正好是「与 `nums[i]` 相反」的 ⇒ `f(i) = (n-1-i) - f(i+1)`。
4. **优化为**：从右往左一次遍历，`answer[i]` 只依赖 `answer[i+1]` 和一个可随时算出的总数 `n-1-i`，不需要额外维护奇/偶两个计数器，也不需要第二遍扫描。

> 式子的另一种理解：奇偶不同时，`f(i)` 与 `f(i+1)` 是**互补**关系 —— 两者之和恰好等于右侧元素总数 `n-1-i`。

### 关键点

- **`f(i)` 与 `f(i+1)` 的奇偶关系只有两种，各对应一个式子**；不要漏掉「奇偶不同」时 `j = i+1` 本身也算一个贡献。
- 递推方向必须**从右往左**（`answer[i]` 依赖 `answer[i+1]`），所以循环写作 `range(n-2, -1, -1)`，`answer[n-1]` 天然为 0。
- `n-1-i` 是 `j > i` 的元素个数，随 `i` 递减；写成 `temp` 缓存或直接算都可以，注意别写成 `n-1-i-1`。

---

## 三、代码实现

### 最终代码

```python
class Solution:
    def countOppositeParity(self, nums: list[int]) -> list[int]:
        n = len(nums)
        ans = [0] * n
        for i in range(n - 2, -1, -1):
            temp = n - 1 - i                      # j > i 的元素个数
            if nums[i] % 2 == 0:
                if nums[i + 1] % 2 == 0:
                    ans[i] = ans[i + 1]           # 同偶：直接继承
                else:
                    ans[i] = temp - ans[i + 1]    # 偶/奇：取互补计数
            else:
                if nums[i + 1] % 2 == 0:
                    ans[i] = temp - ans[i + 1]    # 奇/偶：取互补计数
                else:
                    ans[i] = ans[i + 1]           # 同奇：直接继承
        return ans
```

## 五、优化评估

**结论**：时间已达理论下界，**空间也已是 O(1)**（除必须返回的 `answer` 之外），没有渐近意义上的优化空间。

### 瓶颈分析

时间上，任何正确解法都必须至少读完整个数组（漏看一个元素就可能少算或错算分数），所以 O(n) 是下界；当前实现正好是**单趟常数次比较 + 一次赋值**，把「数数」的工作完全转移到了 `answer` 自身的递推里。空间上，除了要返回的 `answer`，只用了 `temp` 一个标量。

### 可优化空间

无。相比「维护奇/偶后缀计数」的常规写法（需要两个计数器），本解法把计数器省掉、直接复用 `answer[i+1]`，是这题最紧凑的形态。

### 常数级优化（可选）

- `nums[i] % 2 == 0` 可换成 `nums[i] & 1 == 0`，位运算少一次取模；本题数据范围为正数，二者结果完全一致。
- 四个分支可以合并成一句：`ans[i] = ans[i+1] if nums[i] & 1 == nums[i+1] & 1 else temp - ans[i+1]`。分支更少，但可读性下降，**二刷时按个人习惯取舍即可**。
- `temp = n - 1 - i` 实际就是从 `n-1` 递减到 `1` 的计数器，可用 `for temp in range(n - 1, 0, -1): i = temp - 1` 省掉一次减法，收益可以忽略，不建议为此牺牲可读性。

## 六、易错点与总结

### 易错点

- **把「奇偶不同」的两种情况写反**：`nums[i]` 与 `nums[i+1]` 奇偶不同时用 `temp - ans[i+1]`，相同时用 `ans[i+1]`。写反时示例 1 仍可能凑巧过，但会在大数组上悄悄出错。
- **漏掉 `j = i+1` 这一个**：奇偶不同时，`j = i+1` 自己就是一个合法下标，所以式子是 `(n-1-i) - ans[i+1]` 而不是 `(n-2-i) - ans[i+1]`。
- **循环上界写成 `n-1`**：`answer[n-1]` 必须保持 0（它右侧没有元素），循环应从 `n-2` 开始。
- **把 `i < j < n` 误读成 `j != i`**：只统计右侧，左侧元素一律不算。
- **忘记 `n == 1` 的边界**：`range(-1, -1, -1)` 为空，`return ans` 直接给出 `[0]`，不需要额外特判 —— 但若手写 `nums[n-1]` 之类的前置赋值，就要单独考虑 n=1。
- 本题 `nums[i] >= 1`，不必操心负数取模；若扩展到含负数，`% 2` 判断奇偶在 Python 里依然安全（结果非负），但换成 `& 1` 时对负数的行为与取模不同，需要留意。

### 题型套路沉淀

- **「每个位置统计右侧某种元素的个数」→ 从右往左递推**：这类题的共同结构是「候选集合随 i 平移只差一个元素」，因此可以从右端建立递推，而不是每次重扫。
- 递推时优先找**相邻两项之间的互补/继承关系**：若两个位置「要找的目标」恰好在奇偶、颜色、大小关系上对立，则 `f(i) + f(i+1)` 往往等于右侧元素总数，答案为「总数减对方」，可省掉额外计数器。
- 常见同族思路（不同题目细节各异，二刷时各自推一遍式子，不要套用本题系数）：后缀计数（维护「右侧奇数/偶数各多少个」）、后缀和、右侧更大元素计数。
