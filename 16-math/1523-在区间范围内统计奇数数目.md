# 1523. 在区间范围内统计奇数数目

> **难度**：简单
> **标签**：数学
> **原题链接**：https://leetcode.cn/problems/count-odd-numbers-in-an-interval-range/

---

## 一、题目描述

给定两个非负整数 `low` 和 `high`，返回闭区间 `[low, high]`（含两端）内**奇数的个数**。

### 示例

```text
输入：low = 3, high = 7
输出：3
解释：3 到 7 之间的奇数数字为 [3, 5, 7]

输入：low = 8, high = 10
输出：1
解释：8 到 10 之间的奇数数字为 [9]
```

### 约束条件

- `0 <= low <= high <= 10^9`

---

## 二、解题思路

### 核心思想

**区间长度和端点奇偶就能完全决定答案**：奇数在数轴上严格交替出现（每隔 2 个数一个），所以 `[low, high]` 内的奇数个数要么是 `⌊L/2⌋`、要么是 `⌈L/2⌉`（`L = high - low + 1`），只看起点是奇数还是偶数。

### 思路演进

1. **暴力解法**：从 `low` 循环到 `high`，逐个 `x % 2` 累加。时间 O(L)，而 `high` 最大 `10^9`，最坏要跑十亿次 —— 必然超时。
2. **观察到**：奇偶性是**周期性**的，周期 2。既然答案只取决于"有多少个数"和"从哪里开始"，那就没必要真的去数。
3. **分类讨论**：设 `L = high - low + 1`。
   - `low` 为奇数时，奇数落在 `low, low+2, ...`，个数 = `⌈L/2⌉`；
   - `low` 为偶数时，奇数从 `low+1` 开始，个数 = `⌊L/2⌋`。

   换成用两端的奇偶判断：`L` 为奇数当且仅当 `low`、`high` 同奇偶。
   - **两端都是偶数** → `L` 是奇数，且起点是偶数 → 个数 = `⌊L/2⌋ = (high - low) / 2`；
   - 其余三种组合（奇奇、奇偶、偶奇）→ 个数都恰好等于 `(high - low) // 2 + 1`。

   这就是最终代码的由来：用一个 `if` 把"双偶"这一种情形单独挑出来。
4. **再进一步（统一成无分支式子）**：与其对四种组合分类，不如写**前缀计数**。记 `f(x)` = `[0, x]` 内奇数的个数 —— 由于 0 是偶数、之后奇偶交替，`f(x) = (x + 1) // 2`（`x + 1` 个数里奇数占一半，向下取整即得）。
   于是答案 = `f(high) - f(low - 1) = (high + 1) // 2 - low // 2`，四种奇偶组合被整除截断自然吸收，一行说完。

### 关键点

- **绝对不能循环**：`10^9` 量级的数据范围就是在提示"这题要推公式"。
- 整除的**截断方向**决定了 `⌊L/2⌋` 与 `⌈L/2⌉` 之别，公式里的 `+1` 就是在补这个差。
- 前缀写法里 `f(low - 1)` 用 `low // 2` 表达，`low = 0` 时自动退化为 `f(0) = 0`，不会出现 `f(-1)` 这种越界概念。
- **0 是偶数**，`low = 0` 不会被计入奇数。

---

## 三、代码实现

### 最终代码

```python
class Solution:
    def countOdds(self, low: int, high: int) -> int:
        m = low % 2
        n = high % 2
        if m == 0 and n == 0:
            return (high - low) // 2
        else:
            return (high - low) // 2 + 1
```

## 四、复杂度分析

| 版本 | 时间复杂度 | 空间复杂度 |
| :--- | :--- | :--- |
| **最终代码** | O(1) | O(1) |
| 朴素解法 | O(n)，n = high - low + 1 | O(1) |
| 理论下界 | O(1) | O(1) |

> 复杂度中的 n 指闭区间 `[low, high]` 内整数的个数，即 `high - low + 1`（最坏约 `10^9`）。
> 最终代码只做几次取模、整除与加法，与 n 无关，因此是常数时间。

## 五、优化评估

**结论**：时间已是**理论下界 O(1)**，算法层面无优化余地；可改进的只剩写法层面的可读性。

### 瓶颈分析

没有任何遍历、没有任何额外存储，时间只花在两次取模、两次整除和一次加法上。答案本身就只是一次算术运算的结果，不可能比 O(1) 更少。

### 可优化空间

- **算法层面**：无。输出依赖全部输入且只需常数次运算，O(1) 就是下界。
- **写法层面**：现在的 `if` 把四种端点奇偶组合拆成两支，而其中三种组合的结果表达式完全相同 —— 属于"分类讨论的残留"，可以合并。

### 优化代码

```python
class Solution:
    def countOdds(self, low: int, high: int) -> int:
        return (high + 1) // 2 - low // 2
```

**优化理由**：用前缀计数视角代替分类讨论。`f(x) = (x + 1) // 2` 表示 `[0, x]` 内奇数个数，答案 = `f(high) - f(low - 1)`，而 `f(low - 1)` 恰好写成 `low // 2`。一行覆盖四种奇偶组合，不可能漏分支，也不容易出现 `+1` 加错位置的 off-by-one。

### 常数级优化（可选）

- 非负整数下 `x // 2` 与 `x >> 1` 等价，可用移位替代整除（`(high + 1) >> 1`）。但两者在 Python 里都是 C 层整数运算，差异可忽略，**优先保留 `//` 的可读性**。
- `low % 2`、`high % 2` 若只为判奇偶，写成 `low & 1`、`high & 1` 更贴位运算语义，同样是风格问题。

## 六、易错点与总结

### 易错点

- **老老实实写循环**：`high` 到 `10^9`，暴力枚举必超时 —— 看到这种量级要先想公式。
- **区间长度写错**：闭区间长度是 `high - low + 1`，不是 `high - low`；把 `high - low` 直接当长度会让所有计数偏小。
- **无脑 `(high - low) // 2 + 1`**：忘了"双偶"区间要减 1，`low = 2, high = 4` 会返回 2（正确答案是 1）。
- **把 0 当作奇数**：`low = 0` 时 0 是偶数，不应计入。
- **`f(low - 1)` 越界**：若显式写 `(low - 1 + 1) // 2`，`low = 0` 时概念上要算 `f(-1)`；用 `low // 2` 表达天然规避。

### 题型套路沉淀

- **周期性计数一律用前缀相减**：凡"统计 `[L, R]` 内满足交替/周期条件的元素个数"，先写出单侧前缀函数 `f(x)`，答案就是 `f(R) - f(L-1)`；重点处理 `L = 0` 时 `f(-1)` 的写法。
- **分类讨论是通向统一公式的桥梁**：按端点奇偶列出 4 种情形后，注意观察哪几种结果表达式相同 —— 合并掉冗余分支往往能得到更短的式子。
- **数据范围就是复杂度提示**：`10^9` 几乎总意味着 O(1) 或 O(log) 的公式/二分，而不是线性扫描。
