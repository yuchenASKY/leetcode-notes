# 3511. 构造正数组

> **难度**：中等
> **标签**：贪心 · 数组 · 前缀和
> **原题链接**：https://leetcode.cn/problems/make-a-positive-array/

---

## 一、题目描述

给定一个整数数组 `nums`。如果**每个长度超过 2 的元素**（即长度 ≥ 3）的连续子数组的元素之和都为正，则称 `nums` 是**正的**。

每次操作可以用 `[-10^18, 10^18]` 之间的**任意整数**替换数组中的**一个**元素，操作可执行任意多次。求把 `nums` 变成正数组所需的**最少操作次数**。

注意：长度 1 和长度 2 的子数组**不受任何约束**——单个元素是否为正、相邻两数之和是否为负都无所谓。

### 示例

```text
输入：nums = [-10,15,-12]
输出：1
解释：长度 ≥ 3 的子数组只有整个数组，( -10) + 15 + (-12) = -7 < 0，不合法。
      把 nums[0] 换成 0 后，和为 0 + 15 + (-12) = 3 > 0，数组变为正数组，1 次操作即可。
      而长度 2 的子数组 [-10,15]=5、[15,-12]=3 本身都没问题，
      所以「至少两个元素」那套判据在这里不适用。
```

### 约束条件

> 本题为 Plus 会员题，题面未公开 `Constraints` 段落；下面按题目已给出的操作值域与本类题的常见规模整理，二刷时以题面为准。

- `1 <= nums.length <= 10^5`
- `-10^9 <= nums[i] <= 10^9`
- 替换值域：`-10^18 <= new_val <= 10^18`
- 结果（最少操作数）不超过 `n / 3` 量级

---

## 二、解题思路

### 核心思想

**把「子数组和为正」翻译成前缀和的单调约束，然后从左往右贪心：一旦在 `i` 处发现违规，就改掉 `nums[i]`，并把前缀基线清零、重新开始计数。**

### 思路演进

1. **暴力判定 + 枚举改法**：先枚举要修改哪些位置（`2^n` 种），对每种改法检查所有 `O(n²)` 个子数组的和是否为正。时间为 `O(2^n · n²)`，`n` 稍大就彻底不可行。而且「改成什么值」本身也是个搜索空间。

2. **观察到：改成什么值毫无悬念**。既然可以填任意整数，那就直接填 `10^18`：
   `n <= 10^5`、`|nums[i]| <= 10^9` 时，**其余所有元素绝对值之和最多 `10^14`**，
   一个 `10^18` 足以压过任何负数组合 ⇒ **任何包含这个位置的子数组和必定为正**。
   于是问题退化为纯粹的**选位置**问题：选出最少的若干个位置，使所有长度 ≥ 3 的「非正和」子数组都被至少一个选中位置**穿过**。
   题目把值域上界设成 `10^18` 正是在暗示这一点。

3. **观察到：违规判定可以用前缀和 `O(1)` 完成**。设 `s[0]=0`、`s[i]=nums[0]+...+nums[i-1]`，则子数组 `(k, i]`（长度 `i-k`）的和为 `s[i]-s[k]`。于是

   ```text
   所有长度 >= 3 的子数组和 > 0
     ⟺ 对每个 i，s[i] > max{ s[k] : k <= i-3 }
   ```

   也就是说，走到 `i` 时只需维护「`i-3` 及更早的最大前缀和」，比它小就说明存在一个以 `i` 结尾、长度 ≥ 3 的非正和子数组。**这是把 `O(n²)` 判定压成 `O(n)` 的关键。**

4. **贪心：违规就改当前元素**。设 `i` 处违规，那个非正和子数组是 `(k, i]`。把 `nums[i]` 改成极大正数，
   - 所有**以 `i` 结尾**的子数组都含 `i`（只要长度 ≥ 1 就含），立刻变为正；
   - 所有**跨过 `i`** 的后续子数组也含 `i`，一并无忧；
   - 唯一还要继续检验的，只剩**完全落在 `i` 之后**的子数组。
   
   **交换论证说明这样选最优**：任何最优解为了修掉 `(k, i]`，必须改 `(k, i]` 中的某个位置 `p`；把 `p` 换成 `i` 不破坏任何已检验过的子数组（不含 `i` 却含 `p` 的子数组必定整个落在 `[1, i-1]` 内，早已验证为正），而且覆盖了含 `i` 的全部后续子数组，只会更强。所以「改最右边那个」永远不亏。

5. **实现技巧：改完就把前缀基线清零**。改掉 `nums[i]` 之后，包含 `i` 的子数组已经确定为正，后续只需要关心 `[i+1, n]` 内部的子数组——它们的和等于**相对 `i` 重新起算**的前缀差。所以直接把 `s[i]`（及新的窗口最大值）置 0，并令 `j = i` 作为新的「段起点」，代码就自然分成互不干扰的若干段。

### 关键点

- **判据是「长度 ≥ 3」，不是「长度 ≥ 2」**。题面措辞是「超过两个元素」（more than two），长度 2 的配对不在约束内。写成 `i - j >= 2` 会多算：比如 `[... 0, -1]` 这种末尾配对一旦被误判，就会白改一次元素。
- **窗口最大值只统计到 `i-3`**。因为长度 ≥ 3 要求起点 `k <= i-3`；`s[i-1]`、`s[i-2]` 对应长度 1、2，**不能进窗口**。这也是循环里 `pre_mx` 要比判定「晚一步」更新的原因。
- **重置时 `s[i]` 写 0 而不是写 `10^18`**：写 `10^18` 会把后续的前缀和全部推到一个天文数字上，虽然结论不变，但失去了「段内相对量」的语义；写 0 等价于「从这里重新开始，前面的账一笔勾销」。
- **每段至少 3 个元素才可能触发一次修改**，所以答案天然不超过 `n / 3` 量级。

## 三、代码实现

### 最终代码

```python
from typing import List     # 截图里没有、已补


class Solution:
    def makeArrayPositive(self, nums: List[int]) -> int:
        s = [0]                 # 前缀和，s[i] = nums[0..i-1] 之和
        ans = pre_mx = j = 0    # j: 当前段的起点；pre_mx: s[j..i-3] 的最大值
        for i, x in enumerate(nums, 1):
            s.append(s[-1] + x)
            # 长度 >= 3 才需要判定：s[i] 小于等于前面第 3 个位置之前的最值 => 存在非正和子数组
            if i - j > 2 and s[-1] - pre_mx <= 0:
                ans += 1        # 改掉 nums[i-1]，这里直接记一次操作
                j = i
                pre_mx = s[-1] = 0   # 段内重新起算
            elif i - j >= 2:
                pre_mx = max(pre_mx, s[i - 2])   # 扩窗到 i-2，供下一轮当 i-3 用
        return ans
```

## 四、复杂度分析

| 版本 | 时间复杂度 | 空间复杂度 |
| :--- | :--- | :--- |
| **最终代码** | O(n) | O(n) |
| 暴力（枚举改法 + 逐子数组判定） | O(2^n · n²) | O(n) |
| 理论下界 | O(n) | O(1) |

> 复杂度中的 n 指数组 `nums` 的长度。前缀和数组、以及 `j` 的重新起算，都不会让元素被重复扫描——每个下标只进出循环一次，所以是严格线性。

## 五、优化评估

**结论**：时间复杂度已是最优，**空间可以从 O(n) 压到 O(1)**。

### 瓶颈分析

时间上，任何解都必须至少看一遍 `nums`；而且「是否违规」只依赖前缀和的局部窗口最大值，不存在一次遍历拿不到的信息，所以 `O(n)` 不可突破。

空间上，`s` 整个数组其实只被用到三处：`s[-1]`（当前值）、`s[i-2]`（扩窗用）、以及窗口最大值 `pre_mx` 本身。**换句话说，只要保留「最近两个前缀值 + 一个窗口最大值」，全部历史都可以丢掉。**

### 可优化空间

用三个滚动变量替代整个前缀和数组：`cur` 是当前 `s[i]`，`prev1`/`prev2` 分别是 `s[i-1]`/`s[i-2]`。`pre_mx` 的更新时机不变（用 `prev2` 扩窗），段重置时把 `cur` 与 `pre_mx` 归零，`prev1`/`prev2` 交给正常的滚动覆盖即可——因为重置后的第一轮（`since == 1`）不扩窗、第二轮用到的 `prev2` 恰好就是重置时归零的那个 `s[i]`。

### 优化代码

```python
class Solution:
    def makeArrayPositive(self, nums: List[int]) -> int:
        ans = 0
        cur = 0         # s[i]
        prev1 = 0       # s[i-1]
        prev2 = 0       # s[i-2]
        win_max = 0     # max(s[j..i-3])
        since = 0       # i - j，即当前段长度
        for x in nums:
            cur += x
            since += 1
            if since > 2 and cur <= win_max:
                ans += 1
                cur = 0
                win_max = 0
                since = 0
            elif since >= 2:
                win_max = max(win_max, prev2)
            prev2 = prev1
            prev1 = cur
        return ans
```

**优化理由**：窗口最大值只需「退后三位」的那一个前缀值，而它可以用两个滚动变量延迟复现；段重置时也只是把基线归零，不需要真正擦除历史。于是 `O(n)` 的存储降为 `O(1)`，时间仍是单次扫描。

### 常数级优化（可选）

- 判定写成 `cur <= win_max`（即 `cur - win_max <= 0`）少一次减法，语义也更直白。
- `max(win_max, prev2)` 在 `prev2` 通常很小的情况下可以直接 `if prev2 > win_max: win_max = prev2`，省掉函数调用开销；量级很小，按习惯取舍即可。

## 六、易错点与总结

### 易错点

- **把「超过两个元素」读成「至少两个元素」**：这是本题的头号错因。长度 2 的配对和长度 1 的单元素完全不受约束，一旦把窗口写成 `k <= i-2`，会把 `[..., 0, -1]` 这类末尾配对误判成违规，多改元素导致答案偏大。
- **窗口最大值更新早了一步**：若在判定**之前**就把 `s[i-2]` 塞进 `pre_mx`，窗口就变成 `[j, i-2]`，等价于按「长度 ≥ 2」判——又是同一个错误。正确顺序是「先用 `[j, i-3]` 判定，再用 `s[i-2]` 扩窗」。
- **重置时忘记清 `pre_mx`**：只把 `s[i]` 置 0 而不清窗口最大值，会让新段继承上一段的天文前缀值，后续每步都判违规。
- **改值取小了**：想当然用 `10^9` 之类，遇到「一半负数」的极端数据时，包含该位置的子数组仍可能为负。填 `10^18`（题面上界）才安全。
- **改的位置选左边**：改靠左的元素看起来「管得更早」，其实覆盖不到以 `i` 结尾的整段子数组，需要更多次操作。

### 题型套路沉淀

- **「子数组和」→ 前缀和 + 窗口最值**：凡是「所有长度 ≥ k 的子数组和满足某单调性质」的题，都可转成 `s[i]` 与 `max/min{ s[j] : j <= i-k }` 的比较，判定从 `O(n²)` 降到 `O(n)`，是这类题的固定起手式。
- **区间覆盖型贪心：右端点最优**。"要覆盖一批区间，选点"的问题里，**选区间右端点**通常最优（交换论证：右端点能覆盖所有含它的区间，且不破坏左侧已解决部分）。本题「修掉违规子数组 → 改它最右边的元素」正是这一模板。
- **「区间都满足约束」的题，重置往往比修补更简洁**：一次操作把某位置改成极端值后，包含它的子数组集体安全，残余问题天然被切成互不相干的若干段——遇到这种结构就放心用「段起点指针 + 归零」的写法。
- **先看操作值域的暗示**：能填 `±10^18` 却只有 `±10^9` 的元素范围，说明出题人允许「一个值压过全数组」，别在「改什么值」上做搜索。
