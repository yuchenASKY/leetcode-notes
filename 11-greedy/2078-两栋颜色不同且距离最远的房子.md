# 2078. 两栋颜色不同且距离最远的房子

> **难度**：简单
> **标签**：贪心 · 数组
> **原题链接**：https://leetcode.cn/problems/two-furthest-houses-with-different-colors/

---

## 一、题目描述

街上一排 `n` 栋房子，`colors[i]` 是第 `i` 栋的颜色。要求选出**颜色不同**的两栋，让它们的下标距离 `abs(i - j)` 最大，返回这个最大距离。

### 示例

```text
输入：colors = [1,1,1,6,1,1,1]
输出：3
解释：房子 0（颜色 1）与房子 3（颜色 6）距离 3；(3, 6) 同样是 3。

输入：colors = [1,8,3,8,3]
输出：4
解释：房子 0（颜色 1）与房子 4（颜色 3）距离 4。

输入：colors = [0,1]
输出：1
```

### 约束条件

- `n == colors.length`
- `2 <= n <= 100`
- `0 <= colors[i] <= 100`
- 测试数据保证**至少**存在 2 栋颜色不同的房子

---

## 二、解题思路

### 核心思想

距离的上限就是 `n - 1`（两个端点）。**先看两端颜色是否不同**：不同就立刻返回 `n - 1`，这是能达到的最大值。**若两端同色**（记该颜色为 `c = colors[0]`），则最优解必定「一端顶到数组边界」，只需找最右侧的异色位置 `r` 与最左侧的异色位置 `l`，答案是 `max(r, n - 1 - l)`。

### 思路演进

1. **暴力解法**：枚举所有下标对 `(i, j)`，颜色不同就更新 `j - i` 的最大值。时间 O(n²)，n ≤ 100 时完全能过，但这是"没想清结构"的写法。
2. **观察到上界**：任何两点距离都不超过 `n - 1`，而 `n - 1` 只能由 `(0, n - 1)` 这一对取得。所以先检查这一对 —— 一旦 `colors[0] != colors[-1]`，答案已经达到上界，**剩下整个数组都不用看**。
3. **两端同色时怎么办**：记 `c = colors[0] = colors[-1]`。任取一个合法对 `(i, j)`（`i < j`），由于两栋颜色不同，**至少有一端不是 `c`**（否则两端都是 `c`，就同色了）。于是分两种情况：
   - 右端 `j` 不是 `c`：令 `r` 为最右侧的异色下标，则 `j <= r`，距离 `j - i <= j <= r`；
   - 左端 `i` 不是 `c`：令 `l` 为最左侧的异色下标，则 `i >= l`，距离 `j - i <= (n-1) - i <= n-1-l`。

   合起来：**答案 ≤ `max(r, n-1-l)`**。而 `(0, r)` 与 `(l, n-1)` 这两对本身都合法（`colors[0] = c != colors[r]`，`colors[l] != c = colors[n-1]`），所以这个上界**取得到**。
4. **落到实现**：只需两个线性扫描 —— 从 `n-2` 往左找第一个异色点得 `r`，从 `1` 往右找第一个异色点得 `l`，然后取 `max`。

### 关键点

- **早返回是承重的，不是加速可有可无的**。只有确认了 `colors[-1] == c`，才能保证异色房子一定落在 `[1, n-2]` 区间内：如果唯一的异色房子恰好在 `n-1`，`r` 会从 `n-2` 一路减到 `-1`，而 `colors[-1]` 又等于 `c`，判定条件恒真 → **死循环**（Python 里 `colors[-1]` 合法，不会报错，更难发现）。同理，左侧 `l` 的扫描也要靠"至少两栋异色"这条保证才会在 `n-1` 之前停下。
- **中间隔了什么颜色无所谓**。距离只看下标差，与颜色值本身无关，只需要"异色"这一个布尔信息 —— 所以不必统计颜色种类，也不用哈希表。
- `l` 从 `1` 开始即可：`colors[0]` 恒等于 `c`，从 0 开始只是白跑一次判断。

## 三、代码实现

### 最终代码

```python
from typing import List          # 截图里没有、已补（LeetCode 环境自带，本地跑需显式导入）


class Solution:
    def maxDistance(self, colors: List[int]) -> int:
        n = len(colors)
        c = colors[0]
        if c != colors[-1]:
            return n - 1

        # 找最右边的颜色不等于 c 的房子
        # 题目保证至少有两栋颜色不同的房子
        r = n - 2
        while colors[r] == c:
            r -= 1

        # 找最左边的颜色不等于 c 的房子
        l = 1
        while colors[l] == c:
            l += 1

        return max(r, n - 1 - l)
```

## 五、优化评估

**结论**：**已是最优**。时间达到 O(n) 下界，空间是最小的 O(1)。

### 瓶颈分析

时间全部花在两个 `while` 上：它们各自只做「往某个方向推进一步直到颜色变化」，两段加起来推进的步数不超过 `n`。空间只用了 `n / c / r / l` 四个标量。

### 可优化空间

**不可能比 O(n) 更快**。反例很直接：构造 `colors` 为「除一个位置外全是 `c`」，那个异色位置可以落在任意下标上。任何只读取 O(1) 个位置的算法都无法确定 `r` 和 `l` 分别在哪，因此必须 Ω(n) 次读取。唯一能省下的是「两端颜色不同」这类输入 —— 此时一次比较就返回，属于最好情况 O(1)。

### 常数级优化（可选）

**没有值得做的常数级改动**：循环体内只有一次取值和一次比较，`max` 也只算一次，没有重复计算或可缓存的量可以省。

需要提醒的是，**"从两端相向收缩"看起来更简洁，但并不等价**——一旦把 `lo` 或 `hi` 往里推，那些"用到原边界的配对"就被永久丢掉了。例如 `colors = [0,0,1,0,0]`，相向收缩的写法会返回 1，而正确答案是 2（`(0, 2)` 或 `(1, 3)`）。所以本题的正确性依赖"答案必含原数组端点"这个性质，不要再把端点往里挪。

## 六、易错点与总结

### 易错点

- **漏掉 `if c != colors[-1]: return n - 1`**，直接去扫右侧：当唯一的异色房子在倒数第一位时会死循环（`r` 降到 `-1`，而 `colors[-1]` 就是 `c`，条件恒真）。
- **把 `l` 侧的公式写反**：左端异色点是 `l`，距离是 `(n-1) - l`，不是 `l`。
- **误以为要考虑「任意两类颜色之间的配对」**：两端同色这个前提下，任何合法对必有一端不是 `c`，所以只需最左 / 最右各一个异色点，答案是 `max(r, n-1-l)`，与颜色种类多少无关。
- **`l` 的起点写成 0**：`colors[0] == c` 恒成立，`while` 会白转一次；不影响正确性但会掩盖"从 1 开始"这个前提。
- 截图代码用了 `List[int]` 却没有 `import`，贴到本地 IDE 直接跑会 `NameError`。

### 题型套路沉淀

- **「最大化 `|i - j|` + 一个简单关系约束」的题，先砍两端**：① 端点本身满足约束 → 答案直接是 `n-1`，达到全局上界，收工；② 端点不满足 → 最优对必有一端顶在边界上，于是问题降维成「找最左 / 最右的合格点」。
- 这条路由的关键动作是**先证上界、再验证上界可达**：上界 `n-1` 由 `(0, n-1)` 独占；两端同色时把它拆成两段上界 `r` 与 `n-1-l`，再用两条具体的合法对证明紧。这是把 O(n²) 枚举压到 O(n) 扫描的典型来源。
- 二刷自查顺序：**上界那一对查了吗 → 端点同色分支进对了吗 → 两侧边界扫描会不会跑出数组 / 死循环 → `max` 里两边的公式是否各就各位**。
