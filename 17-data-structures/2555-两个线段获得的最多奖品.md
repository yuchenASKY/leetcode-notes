# 2555. 两个线段获得的最多奖品

> **难度**：中等
> **标签**：数组 · 滑动窗口 · 二分查找
> **原题链接**：https://leetcode.cn/problems/maximize-win-from-two-segments/

---

## 一、题目描述

数轴上有若干奖品，`prizePositions` 以**非递减**顺序给出每件奖品的位置（同一位置可以有多件）。给出线段长度 `k`，可以选**两条**端点都是整数、长度恰为 `k` 的线段，拿走落在任一线段上（含端点）的全部奖品。两条线段允许相交，但**同一件奖品只能拿一次**。求最多能拿多少件。

### 示例

```text
输入：prizePositions = [1,1,2,2,3,3,5], k = 2
输出：7
解释：选线段 [1,3] 和 [3,5]，前者覆盖 1,1,2,2,3,3，后者补上 5，共 7 件。

输入：prizePositions = [1,2,3,4], k = 0
输出：2
解释：线段退化为长度为 0 的点，选 [3,3] 和 [4,4]。
```

### 约束条件

- `1 <= prizePositions.length <= 10^5`
- `1 <= prizePositions[i] <= 10^9`
- `0 <= k <= 10^9`
- `prizePositions` 非递减有序（不相邻的位置可能相距很远）

## 二、解题思路

### 核心思想

**一条线段长度固定为 `k`，所以它的位置只由「右端点贴住哪个奖品」决定 —— 候选线段只有 n 条。把「选两条」拆成「枚举右边那条（O(n) 个候选）+ 左边那条查一张前缀最优表（O(1)）」，总时间 O(n)。**

### 思路演进

1. **暴力解法**：线段的取值是值域 `[1, 10^9]` 上的连续整数，枚举两个端点等于枚举 10^18 种组合，不可能。退一步枚举「以哪件奖品为右端点」的候选线段，有 n 条，两两配对 O(n²)；n = 10^5 时 10^10 次，超时。更麻烦的是：两条线段可以相交，配对时怎么保证不重复计数？直接枚举配对还要处理交集，这个方向本身就绕。

2. **观察到（确定候选线段）**：给定右端点 `p`（某件奖品的位置），最优线段一定是 `[p-k, p]` —— 左端点再往右只会少拿，往左则与右端点固定矛盾。于是候选线段就是「以每件奖品位置为右端点、长度 k」的 n 条，第 `right` 条覆盖的是下标区间 `[left(right), right]`，其中 `left(right)` 是满足 `p - prizePositions[left] <= k` 的最小下标。

3. **关键转化（把「相交」消掉）**：固定右边那条线段覆盖 `[left, right]` 之后，另一条线段**不可能跨在它两侧**：一条长 k 的线段若同时含有位置 `< p-k` 和位置 `> p` 的奖品，两者的距离就超过 k 了，矛盾。所以另一条线段要么整段落在下标 `< left` 的奖品里，要么整段落在下标 `> right` 的奖品里。后一种情况把两条线段角色对调后会被外层枚举覆盖；前一种情况，另一条线段的最优值只取决于「只看前 `left` 件奖品时，一条线段最多拿几件」，可以预处理成前缀最大值数组 `mx[i]`。

4. **优化为**：`left` 随着 `right` 增大而单调右移（数组有序），用双指针边扫边维护窗口长度；同时维护 `mx[right+1] = max(mx[right], 当前窗口长度)`。对每个 `right` 更新 `ans = max(ans, mx[left] + right - left + 1)`。一遍扫描出答案。

### 关键点

- **候选线段只需枚举右端点**：长度固定 ⇒ 一条线段的位置自由度只剩「贴住哪个奖品」，n 条候选代替 10^9 个端点。
- **不相交的口径靠「下标切分」实现**：不是让两条线段在几何上不重叠（题目允许相交），而是让**参与计数的下标集合**不重叠 —— 右段拿 `[left, right]`，左段只从 `0..left-1` 里取。这样相交在形式上被完全绕开，不需要算交集。
- **`mx` 的下标是「前缀件数」不是下标**：`mx[i]` 表示只考虑前 `i` 件奖品（下标 `0..i-1`），所以更新写在 `mx[right+1]`，查表用 `mx[left]`。
- **左段拿不到 `p` 到 `p_right` 之间的空档**：`right` 那条的右端点贴死了 `p`，右段之外的奖品只可能在 `p-k` 左边或 `p` 右边，中间不会有漏（长度 k 的限制），这也是第 3 步论证能成立的原因。
- **开头的早退依赖「位置是整数」**：`2k+1 >= 最大值-最小值` 时两条线段必然能覆盖全部奖品（因为两条线段各长 k，缝隙只有 1 个单位宽，而整数位置上放不下奖品）。这只是加速分支，去掉它结果不变。

## 三、代码实现

### 最终代码

```python
from typing import List


class Solution:
    def maximizeWin(self, prizePositions: List[int], k: int) -> int:
        n = len(prizePositions)
        # 两条长度 k 的线段足以覆盖全部奖品（位置为整数，缝隙放不下奖品）
        if k * 2 + 1 >= prizePositions[-1] - prizePositions[0]:
            return n

        ans = left = 0
        mx = [0] * (n + 1)   # mx[i]：只在前 i 件奖品里选一条线段，最多能拿几件
        for right, p in enumerate(prizePositions):
            # 维护以 p 为右端点、长度 k 的线段覆盖的最左下标
            while p - prizePositions[left] > k:
                left += 1
            # 右段拿 [left, right]，左段在 [0, left-1] 里取最优
            ans = max(ans, mx[left] + right - left + 1)
            mx[right + 1] = max(mx[right], right - left + 1)
        return ans
```

## 四、复杂度分析

| 版本 | 时间复杂度 | 空间复杂度 |
| :--- | :--- | :--- |
| **最终代码** | O(n) | O(n) |
| 朴素解法（枚举候选线段两两配对） | O(n²) | O(1) |
| 理论下界 | O(n) | O(1) |

> 复杂度中的 n 指奖品数量，即 `prizePositions` 的长度（最大 10^5）。值域最大 10^9，与 n 无关，所以复杂度只能记在 n 上。

## 五、优化评估

**结论**：时间已到理论下界 O(n)，**空间还能从 O(n) 压到 O(1)**。

### 瓶颈分析

时间上必须把每件奖品至少看一次（否则可能漏掉最优线段），O(n) 不可再降。单次扫描里 `left` 只增不减，总共移动 n 次，均摊 O(1)，没有多余的内层开销。当前的空间开销只来自前缀最大值数组 `mx`，它同时也是索引加速的关键 —— 每件奖品的「单线段最优窗口」只算一次，之后 O(1) 查询。

### 可优化空间

`mx` 之所以看起来必需，是因为要查 `mx[left]`，而 `left` 是任意过去位置。但注意两点：① `mx` 本身是**非递减**的；② `left` 在扫描中**单调右移**。既然查询位置只往右走，那就不需要整张表 —— 只需要维护一个「当前 `mx` 值」，并让它在 `left` 前移时同步更新：`mx(left+1) = max(mx(left), 以 left 为右端点的最长合法窗口)`。后面这一项再用第二个双指针（`j` 追 `left`）维护，就得到 O(1) 空间版本。

代价是多一个指针和一个分支，常数略大；n 只有 10^5，两者的运行表现没有实质差别，所以上面保留可读性更好的前缀数组版本。

### 优化代码

```python
from typing import List


class Solution:
    def maximizeWin(self, prizePositions: List[int], k: int) -> int:
        n = len(prizePositions)
        pos = prizePositions
        if k * 2 + 1 >= pos[-1] - pos[0]:
            return n

        ans = left = 0
        s = i = 0          # s：以 i 为右端点的窗口左边界；i：下一个要并入 best 的下标
        best = 0           # 等价于 mx[left]：只看下标 < left 时单线段最优
        for right, p in enumerate(pos):
            while p - pos[left] > k:
                left += 1
            # 把 best 从 mx[left] 逐步推进到位（left 单调，所以 i 也只增不减）
            while i < left:
                while pos[i] - pos[s] > k:
                    s += 1
                best = max(best, i - s + 1)
                i += 1
            ans = max(ans, best + right - left + 1)
        return ans
```

**优化理由**：`mx` 数组提供的其实只是「按下标递增的前缀最大值」，而查询下标 `left` 单调不减 ⇒ 整张表可以折叠成一个滚动变量 `best`：`left` 每前移一格，就把下标 `left-1` 那一格的单线段最优值并进 `best`。那一格的最优窗口长度用第二个双指针（`s` 追 `i`）顺带算出，`s` 同样单调右移，所以总量仍是 O(n)。空间从 O(n) 降到 O(1)，代价是多一层循环与一个分支，可读性略差 —— n 只有 10^5，两种写法都够快，默认还是用上面的前缀数组版本。

### 常数级优化（可选）

- 把 `prizePositions` 提到局部变量（本来就是参数，已符合）、`mx.append` 与定长数组二选一：本题用定长 `[0] * (n+1)` 预分配即可，避免扩容。
- `ans` 用局部变量累积，循环结束后返回；不要在循环里反复读 `self` 属性。
- 早退分支计算 `prizePositions[-1] - prizePositions[0]` 用两个局部变量取值，避免负数下标的额外开销 —— 收益极小，可读性优先。

## 六、易错点与总结

### 易错点

- **把「两条线段几何不相交」当成前提**：题目明说可以相交，如果按「不重叠」去切分，会在两个线段共享密集奖品时低估答案（如示例 1 的 `[1,3]` 与 `[3,5]` 在位置 3 上重叠，答案才到 7）。
- **重复计数**：面试写法里最容易犯的错就是「左段也用前缀最大值，但左段窗口右端允许越过 `left`」。必须把左段限制在下标 `< left`，否则同一件奖品会被 `mx[left]` 和 `right-left+1` 各算一次。
- **`mx` 的下标错位**：`mx[i]` 是「前 i 件」不是「以 i 结尾」。写成 `mx[right] = max(mx[right-1], ...)` 不会崩，但会漏掉 `right=0` 那一格，且查表时 `mx[left]` 的语义就错了。
- **忘记 `n == 1`**：早退分支在这种情况会直接返回 1，正好省掉后续循环的边界讨论；如果删掉早退，就要保证 `mx` 长度 `n+1` 且循环不越界。
- **`left` 用二分而不是双指针**：两者都对（`left` 可以二分定位），但数组有序 + `left` 单调，双指针能省掉 `log n` 的常数；写成二分不算错，只是多一层开销。

### 题型套路沉淀

- **固定长度区间的「双线段 / 双窗口」模型**：长度固定 ⇒ 一条线段的位置只由端点所贴的元素决定，候选数量从值域降到 n。这类题的通用骨架是「枚举右侧候选 + 左侧查前缀最优」，把 O(n²) 配对压成 O(n)。
- **相交/重叠限制的消解方式**：当题目允许几何重叠但禁止重复计数时，不要去做区间并（并集不好维护），而是**把元素按下标切成两段互不相交的部分** —— 谁属于哪一段由「另一段的边界」决定，重复计数自然消失。这个「下标切分代替几何切分」的思路在双区间、双窗口类题目里反复出现。
- **前缀最大值表（`mx[i]` = 前 i 个元素里的单次最优）** 是「两段互不重叠的最优」这类问题的标准配件：一次预处理，之后任意切分点都能 O(1) 取到左半部分的最优值。
- 双指针能成立的前提只有一条：**数组有序 ⇒ 边界单调**。看到「非递减 / 有序」就要想双指针，别一上来写二分。
