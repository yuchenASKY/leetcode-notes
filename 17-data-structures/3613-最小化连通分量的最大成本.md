# 3613. 最小化连通分量的最大成本

> **难度**：中等
> **标签**：并查集 · 图 · 排序 · 贪心

## 一、题目描述

给定一张含 `n` 个节点（编号 `0 ~ n-1`）的无向连通图，边以 `edges[i] = [ui, vi, wi]` 给出（`wi` 为边权），另给一个整数 `k`。允许删除任意多条边，使剩下的图中**连通分量个数不超过 `k`**。每个连通分量的**成本**定义为该分量内部边权的**最大值**（若分量没有任何边，成本为 `0`）。求所有连通分量成本最大值的最小可能值。

### 示例

```text
示例 1：
输入：n = 5, edges = [[0,1,4],[1,2,3],[1,3,2],[3,4,6]], k = 2
输出：4
解释：删掉节点 3 与节点 4 之间的边（权值 6）。剩下两个分量，成本分别为 0 和 4，
      最大成本 = 4。

示例 2：
输入：n = 4, edges = [[0,1,5],[1,2,5],[2,3,5]], k = 1
输出：5
解释：k = 1 要求整张图必须保持连通，一条边都不能删，分量成本即最大边权 5。
```

### 约束条件

- `1 <= n <= 5 * 10^4`
- `0 <= edges.length <= 10^5`
- `edges[i].length == 3`，`0 <= ui, vi < n`
- `1 <= wi <= 10^6`
- `1 <= k <= n`
- 输入图是**连通图**

## 二、解题思路

### 核心思想

**把「枚举删边方案」换成「枚举边权阈值 W」：保留所有权值 ≤ W 的边，连通分量数最少；而分量数随 W 增大单调不增 ⇒ 第一次降到 `k` 时用到的那条边权就是答案。** 用并查集按边权升序增量合并，边合并边读 `cc`。

### 思路演进

1. **暴力解法**：删哪些边是组合问题，枚举所有边子集共 `2^m` 种，每种再跑一次连通性统计，`m` 可达 `10^5`，完全不可行。

2. **观察到（第一次转化）**：答案的值域并不大 —— 无论怎么删边，代价只会在「某条边的权值」和 `0` 之间取。原因是每个分量的成本**一定等于该分量里某条边的权值**，所以全局最大成本必然是某个 `wi`（除非最优方案是完全无边）。于是问题变成：**在候选集 `{0} ∪ {所有 wi}` 里找最小可行值**。

3. **观察到（第二次转化，也是本题的关键）**：对固定的阈值 W，判定「是否存在删边方案使所有分量成本 ≤ W」时，**保留所有 `wi <= W` 的边是最优的**：这样每个分量内部的边权都不超过 W（成本约束满足），而且连通分量数在这一前提下**最少**。于是定义函数 `cc(W)` = 只保留所有权值 ≤ W 的边时的连通分量数，它是 **W 的单调不增函数**，判定条件就是 `cc(W) <= k`。

4. **优化为**：既然 `cc(W)` 随 W 单调不增、且只在边权取值处变化，就**不必对每个 W 重新建图**。把边按权值**升序**排序，依次尝试加入每条边：加入一条边若把两个不同集合接在一起，`cc` 就减一；`cc` 第一次降到 `k` 时，当前这条边的权值 `w` 就是「使 `cc(W) <= k` 成立的最小 W」，也就是答案。整个过程只需一次排序 + 一次线性扫描。

### 关键点

- **答案是「某个边权」或 `0`**：这是把无限/组合的枚举空间压缩到 `m+1` 个候选的支点。
- **单调性**：`W` 越大保留的边越多 ⇒ 分量数越少。因此第一次满足 `cc <= k` 就是最小值。
- **并查集维护 `cc` 计数**：把「连通分量个数」当成一个可 O(1) 读取的状态，只有**合并成功**时才对它减一（合并同一集合的边不能减）。
- **`k == n` 是独立分支**：此时可以把所有边删光，`n` 个孤立点各自成本为 `0`，答案就是 `0`；不特判的话循环里 `cc` 从 `n` 起步、第一次合并就变 `n-1`，`cc == k` 永不为真（`n == k` 的分支不会进循环体），会算错。

## 三、代码实现

### 最终代码

```python
from typing import List   # 截图里没有，已补


class UnionFind:
    def __init__(self, n: int):
        # 一开始有 n 个集合 {0}, {1}, ..., {n-1}
        # 集合 i 的代表元是自己，大小为 1
        self.fa = list(range(n))  # 代表元
        self.cc = n  # 连通块个数

    def find(self, x: int) -> int:
        # 如果 fa[x] == x，则表示 x 是代表元素
        if self.fa[x] != x:
            self.fa[x] = self.find(self.fa[x])  # fa 改成代表元
        return self.fa[x]

    def merge(self, from_: int, to: int) -> None:
        x, y = self.find(from_), self.find(to)
        if x == y:  # from 和 to 在同一个集合，不做合并
            return
        self.fa[x] = y  # 合并集合。修改后就可以认为 from 和 to 在同一个集合了
        self.cc -= 1    # 成功合并，连通块个数减一


class Solution:
    def minCost(self, n: int, edges: List[List[int]], k: int) -> int:
        if k == n:
            return 0
        edges.sort(key=lambda e: e[2])
        u = UnionFind(n)
        for x, y, w in edges:
            u.merge(x, y)
            if u.cc == k:
                return w
```

## 四、复杂度分析

| 版本 | 时间复杂度 | 空间复杂度 |
| :--- | :--- | :--- |
| **最终代码** | O(m log m + m log n) | O(n + m) |
| 朴素解法（枚举删边子集 / 对每个候选 W 重建图跑 BFS） | O(2^m · m) / O(m · (n + m)) | O(n + m) |
| 理论下界 | O(m log m) | O(n) |

> 复杂度中的 n 指节点数，m 指边数（`edges.length`）。
>
> - 最终代码的主项是排序 O(m log m)；并查集部分共 m 次 `find`/`merge`，仅做路径压缩时单次均摊 O(log n)，合计 O(m log n)，被排序项吸收。
> - 空间上 `fa` 数组 O(n)，排序最坏需要 O(m) 的额外空间，故合计 O(n + m)。
> - 理论下界：至少要读入全部边（Ω(m)），而本题解依赖「按权排序后取首个满足条件的边权」，在比较模型下需 Ω(m log m)；空间至少要放下并查集，Ω(n)。

## 五、优化评估

**结论**：**已是该思路下的最优**，不存在数量级上的优化空间。

### 瓶颈分析

时间几乎全部花在 `edges.sort(key=lambda e: e[2])` 上，`m = 10^5` 时约 1.7×10^6 次比较；后续的并查集扫描只是一次 O(m) 的线性过程，量级上被排序完全盖住。空间上唯一的非输入开销是 `fa` 数组（O(n)），已经到最小。

### 可优化空间

- **不能突破排序项**：答案必然是某条边的权值，而「谁是第一个使 `cc <= k` 的边权」这个信息天然要求边按权有序；不排序就得付出等价的代价。
- **理论下界**：任何解法都必须读完所有边（Ω(m)），本解为 O(m log m)，与「排序 + 一次扫描」这一最自然的结构一致，没有浪费。

## 六、易错点与总结

### 易错点

- **漏掉 `k == n` 的特判**：此时答案恒为 `0`（删光所有边）。漏判后 `cc` 从 `n` 出发、每次成功合并才减一，永远等不到 `cc == n`，函数会走到循环外返回 `None`。
- **判断位置**：`if u.cc == k: return w` 必须写在 `merge` **之后**。因为 `cc` 只会因「本次成功合并」而降到 `k`，此时返回的才正好是这条边的权值；放在 `merge` 之前就会用到上一条边的 `w`。
- **返回的是 `w`（刚加入的边权）**，不是 `cc - 1`、也不是最后一条边的权值。
- **合并同一集合的边时不能减 `cc`**：`merge` 里 `x == y` 必须提前 `return`，否则分量计数会被多减，阈值判断整体偏移。
- **复杂度口径**：这段实现只做了路径压缩、没做按大小/按秩合并，`find` 的最坏均摊是 **O(log n)** 而不是反阿克曼 O(α(n))，写复杂度时别顺手写成 α。

### 题型套路沉淀

- **「最小化最大成本 / 最小化临界阈值」类题目的通用骨架**：先证单调性（阈值越大越宽松）→ 把答案枚举空间压缩到「输入中出现的候选值」→ 用**排序 + 增量合并**一次扫描定位临界点。识别信号：题目问「最小可能的最大值」，且约束满足性随某个参数单调变化。
- **并查集当「连通分量计数器」用**：维护一个 `cc` 初值 `n`，只在合并成功时 `-1`，就能把分量个数变成 O(1) 可读的状态 —— 这比每次重新统计连通块省掉一整轮遍历。
- **Kruskal 式增量思维**：把边按权升序逐条加入，等价于「让阈值 W 从小到大扫过所有边权」，这类「逐条加入 + 记录首次满足条件的瞬间」的写法值得背下来。
