# 363. 矩形区域不超过 K 的最大数值和

> **难度**：困难
> **标签**：数组 · 二分查找 · 矩阵 · 有序集合 · 前缀和
> **原题链接**：https://leetcode.cn/problems/max-sum-of-rectangle-no-larger-than-k/

---

## 一、题目描述

给定一个 `m x n` 的矩阵 `matrix` 和一个整数 `k`，找出矩阵内部某个**非空矩形区域**（边与矩阵边平行）的元素和，要求该和**不超过** `k`，返回能取到的最大值。数据保证至少存在一个这样的矩形区域。

### 示例

```text
输入：matrix = [[1,0,1],[0,-2,3]], k = 2
输出：2
解释：第 0~1 行、第 1~2 列构成的矩形 [[0,1],[-2,3]] 和为 0 + 1 + (-2) + 3 = 2；
     整个矩阵的和是 3，已超过 k = 2，所以 2 就是最大值。

输入：matrix = [[2,2,-1]], k = 3
输出：2
解释：单行矩阵，前两个元素构成的区间和为 4 > 3；取 [[2]] 或 [[2,2,-1]] 都不超过 3 的最优值是 2。
```

### 约束条件

- `m == matrix.length`
- `n == matrix[i].length`
- `1 <= m, n <= 100`
- `-100 <= matrix[i][j] <= 100`
- `-10^5 <= k <= 10^5`
- 题目数据保证总会存在一个数值和不超过 `k` 的矩形区域
- 进阶追问：如果行数远大于列数，如何优化？

---

## 二、解题思路

### 核心思想

**先把二维降成一维，再用有序集合处理「不超过 k」这个上界。** 固定矩形的上下边界后，每一列被压成一个「列区间和」，矩形和就退化成一维数组的连续子段和；而「子段和 ≤ k」等价于「前缀和之差 ≤ k」，用 `SortedList` 上的 `lower_bound` 即可每次 O(log n) 找到最优左端点。

### 思路演进

1. **暴力解法**：矩形由「上、下、左、右」四条边确定，枚举全部四元组共 O(m²n²) 个矩形，配合二维前缀和 O(1) 求值。m = n = 100 时是 10^8 量级，Python 不可能过。
2. **观察到**：矩形 = 「连续的若干整行」×「连续的若干整列」。一旦把上下边界定死，矩形对行的选择就结束了，剩下的自由度只在这一维列上 —— 而列是可加的一维数组。
3. **降一维**：固定上边界 `i`、下边界 `j`，把第 `c` 列在 `i..j` 行上的和记为 `total[c]`，问题变成「在长度 n 的一维数组 `a` 里求和 ≤ k 的最大子段和」。上下边界只有 O(m²) 种，且换下边界时 `total` 只需加上新的一行（增量维护，不必重新求和）。
4. **为什么不能直接 Kadane**：没有 `k` 时 Kadane 用「以当前元素结尾的最大子段和」做状态转移，O(n) 解决。但「≤ k」这个上界破坏了它的最优子结构 —— Kadane 依赖「前缀越大越好」，而上界约束下前缀和**太大会越界**、太负反而更容易装得下，贪心选择不再成立。
5. **换成前缀和之差**：子段和 `= s[r] - s[l] ≤ k` ⟺ `s[l] ≥ s[r] - k`。固定右端点 `r`，在所有**历史**前缀和里找「**≥ s[r] - k 的最小值**」，这个最小值让差值尽可能大又不越界。这正是有序集合上的 `lower_bound`：用 `SortedList` 维护历史前缀和，查询和插入各 O(log n)。
6. **合计**：O(m²) 种上下边界 ×（O(n) 增量压缩 + O(n log n) 前缀和查询）= **O(m² · n log n)**。

### 关键点

- **有序集合初始要塞一个 `0`**（代表空前缀），否则「左边界就是第 0 列」的那些矩形永远查不到合法左端点。
- **先查再插**：查询 `s - k` 的 lower_bound 时集合里不能包含当前的 `s`，否则 `s - s = 0` 会被当成合法答案（反例见易错点）。
- 用 **`bisect_left`** 而不是 `bisect_right`：要的是「≥ s-k 的最小值」，当集合里恰好存在 `s-k` 时，差值正好等于 k，这是合法且最优的候选，必须算进来。
- `lb == len(totalSet)` 表示不存在满足条件的左端点，这一轮直接跳过（题目保证整体有解，但单个右端点不一定有）。
- 压缩数组 `total` 在 `j` 递增时**增量累加**（`total[c] += matrix[j][c]`），每次只加一行，而不是重新对 `i..j` 求和。

## 三、代码实现

### 最终代码

```python
from sortedcontainers import SortedList


class Solution:
    def maxSumSubmatrix(self, matrix: list[list[int]], k: int) -> int:
        ans = float("-inf")
        m, n = len(matrix), len(matrix[0])

        for i in range(m):                     # 枚举上边界
            total = [0] * n                    # total[c] = 第 c 列在 i..j 行的和
            for j in range(i, m):              # 枚举下边界
                for c in range(n):
                    total[c] += matrix[j][c]   # 增量压缩：只加新的一行

                totalSet = SortedList([0])     # 历史前缀和，0 代表空前缀
                s = 0
                for v in total:                # 求「和 ≤ k 的最大子段和」
                    s += v
                    lb = totalSet.bisect_left(s - k)   # 第一个 ≥ s-k 的历史前缀
                    if lb != len(totalSet):
                        ans = max(ans, s - totalSet[lb])
                    totalSet.add(s)            # 先查后插
        return ans
```

> 截图里的代码缺少 `from sortedcontainers import SortedList`，直接提交会 `NameError`；LeetCode 的 Python3 环境自带该库，补上这一行即可。

## 四、复杂度分析

| 版本 | 时间复杂度 | 空间复杂度 |
| :--- | :--- | :--- |
| **最终代码** | O(m² · n log n) | O(n) |
| 朴素解法（枚举四元组 + 二维前缀和） | O(m² · n²) | O(mn) |
| 理论下界（无上界约束时的 Kadane） | O(m² · n) | O(n) |

> 复杂度中的 `m` 是矩阵行数，`n` 是矩阵列数；`log n` 来自 `SortedList` 的插入与二分查找，`n` 元素集合上二者都是对数级。

## 五、优化评估

**结论**：在「必须处理 ≤ k 上界」的前提下，复杂度已经合理，**但平方项可以挪到较短的一维上**。

### 瓶颈分析

总开销 = O(m²) 种上下边界 × 每条边界的 O(n log n)：
- 平方项 O(m²) 来自「枚举所有行区间」，这是把二维压成一维的固定代价，任何子矩阵类算法都绕不开；
- 对数项 O(log n) 来自「找 ≥ s-k 的最小前缀」，是把上界约束变成可查询结构必须付出的代价。

空间上 `total` 与 `totalSet` 都只与列数有关，已是 O(n)，没有压缩余地。

### 可优化空间

原题的进阶追问给出了唯一的改进方向：**当行数远大于列数时，平方项挂在行上就吃亏**。把矩阵沿主对角线转置，让**较短**的一维去当「被枚举的上下边界」、较长的一维去当「线性扫描的列」，复杂度从 `O(m² · n)` 变成 `O(min(m,n)² · max(m,n))`。这只改变平方项的落点，不影响对数项。

对数项本身消不掉：只要「≤ k」这个上界还在，就需要一次有序性查询。唯一能跳过的情形是 k 足够大 —— 若先跑一遍无约束的 Kadane，发现最大值已经 ≤ k，就可以直接返回，省掉整个有序集合分支。

### 优化代码

```python
from sortedcontainers import SortedList


class Solution:
    def maxSumSubmatrix(self, matrix: list[list[int]], k: int) -> int:
        m, n = len(matrix), len(matrix[0])

        # 让「行」成为较短的一维，平方项挂在较短边上
        if m > n:
            matrix = [list(col) for col in zip(*matrix)]
            m, n = n, m

        ans = float("-inf")
        for i in range(m):
            total = [0] * n
            for j in range(i, m):
                for c in range(n):
                    total[c] += matrix[j][c]

                totalSet = SortedList([0])
                s = 0
                for v in total:
                    s += v
                    lb = totalSet.bisect_left(s - k)
                    if lb != len(totalSet):
                        ans = max(ans, s - totalSet[lb])
                    totalSet.add(s)
        return ans
```

**优化理由**：`min(m,n)² · max(m,n)` 在方阵下与原来完全相同，但在长条矩阵上把平方项换到了短边，是进阶追问所指的方向。转置用 `zip(*matrix)` 一次成型，`list(col)` 转成行便于反复下标访问。

### 常数级优化（可选）

- 把 `len(totalSet)` 存成局部变量，避免在热点循环里重复做属性查找。
- 内层 `for v in total: s += v` 可以写成 `for v in accumulate(total)`，把累加交给 C 层循环。
- `ans = max(ans, x)` 是函数调用，热点里改成 `if x > ans: ans = x` 能省一点开销。

## 六、易错点与总结

### 易错点

- **漏掉 `import`**：`SortedList` 不是内置类型，必须 `from sortedcontainers import SortedList`。
- **有序集合忘了塞哨兵 `0`**：只写 `SortedList()` 的话，从左边界 0 开始的子段找不到合法左端点，答案会偏小、甚至整轮都更新不了。
- **先插后查**：会把自己当成左端点，`s - s = 0` 被误判成合法答案。反例：`matrix = [[-1]], k = 0`，正确答案是 `-1`；先插后查时 `s = -1` 已在集合里，`-1 - (-1) = 0` 会被当成答案返回 `0`。
- **用 `bisect_right`**：当 `s - k` 恰好存在于集合中时，`bisect_right` 会跳到它后面，把「差值正好等于 k」的最优解漏掉。
- **忘判越界**：`lb == len(totalSet)` 时必须跳过，否则下标越界。
- **每次重新求列和**：换下边界时应对 `total` 增量累加一行，而不是重新扫 `i..j` 行，否则压缩本身就退化。
- **`ans` 初值写成 `0`**：答案可能是负数（全负矩阵配非负数 k），必须用 `-inf`；题目保证有解，所以最终不会原样返回 `-inf`。

### 题型套路沉淀

- **二维区间问题先想「固定一维、压缩另一维」**：凡是「子矩阵 / 矩形」求最值，第一反应都是枚举一条边的上下界、把另一维压成一维数组，把 O(m²n²) 降到 O(m²n) 起步。这是子矩阵类问题的总纲。
- **「和 ≤ k 的最大子段和」是成套模板**：前缀和 + 有序集合 lower_bound。核心等式 `s[r] - s[l] ≤ k ⟺ s[l] ≥ s[r] - k`，要找的是「满足条件的**最小** `s[l]`」，因为只有最小值才能让差值最大。换成「和 ≥ k 的最小值」就是找最大 `s[l]`，同样一次二分。
- **上界约束会杀死 Kadane**：Kadane 只在「前缀越大越好」的单调偏好下成立；一旦加「不能超过 k」，偏好方向被截断，就必须换成「有序结构上的邻界查询」，即把问题从「递推」改写为「查找」。
- **哨兵 + 先查后插**是前缀和 + 集合类问题的固定动作（哨兵覆盖空前缀，先查后插避免自配），务必形成肌肉记忆。
- **复杂度里平方项跟着较短的维度走**：任何「枚举两个边界 + 扫描其余」的二维题，都要问一句「扫的维度是不是最短的那一维」，否则长条数据上会白吃一个数量级。
