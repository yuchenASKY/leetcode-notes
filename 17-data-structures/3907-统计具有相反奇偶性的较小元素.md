# 3907. 统计具有相反奇偶性的较小元素

> **难度**：中等
> **标签**：数据结构 · 有序集合 · 二分查找 · 数组
> **原题链接**：https://leetcode.cn/problems/count-smaller-elements-with-opposite-parity/

---

## 一、题目描述

给定长度为 `n` 的整数数组 `nums`。下标 `i` 的**得分**是满足下面三个条件的下标 `j` 的个数：

- `i < j < n`（必须在 i 的右侧）
- `nums[j] < nums[i]`（值必须严格更小）
- `nums[i]` 与 `nums[j]` **奇偶性相反**（一个奇数、一个偶数）

返回长度同为 `n` 的数组 `answer`，`answer[i]` 即下标 `i` 的得分。

一句话概括：**对每个位置，统计它右边「更小且奇偶性相反」的元素个数。**

### 示例

```text
输入：nums = [5,2,4,1,3]
输出：[2,1,2,0,0]
解释：
  i=0：v=5（奇），右侧更小的偶数有 2、4          → 2
  i=1：v=2（偶），右侧更小的奇数有 1             → 1
  i=2：v=4（偶），右侧更小的奇数有 1、3          → 2
  i=3：v=1（奇），右侧更小的偶数没有             → 0
  i=4：右侧无元素                                → 0
```

```text
输入：nums = [4,4,1]
输出：[1,1,0]
解释：两个 4 都是偶数，右侧更小的奇数只有 1，故各得 1 分；下标 2 右侧无元素，得 0。
      —— 重复值必须各自计数，不能去重。
```

```text
输入：nums = [7]
输出：[0]
```

### 约束条件

- `1 <= nums.length <= 10^5`
- `1 <= nums[i] <= 10^9`

---

## 二、解题思路

### 核心思想

**从右往左扫，把「已扫描过的右侧元素」按奇偶拆成两个有序多重集；对当前值 `v`，去相反奇偶的那个集合里做一次 `bisect_left`，返回值就是得分。**

### 思路演进

1. **暴力解法**：对每个 `i`，把右侧所有 `j` 都过一遍，三个条件逐一判断。时间 O(n²)，`n = 10^5` 时是 10^10 量级的比较，必然超时。

2. **观察到**：三个条件里，`i < j` 由**遍历方向**决定，奇偶性只是**一次二选一的筛选**，真正难啃的只有 `nums[j] < nums[i]` —— 它要求对右侧元素集合做「有序 + 计数」。暴力把这一步做成了线性扫描，而它本质是一次**秩查询**：
   - 「右侧元素中严格小于 v 的有几个」= 在有序集合里 `lower_bound(v)` 的下标。
   - 而「奇偶性相反」只是把集合分成两类，查询时选对那一个即可。

3. **优化为**：维护两个有序多重集 `ji`（奇数）和 `ou`（偶数）。**从右往左**遍历，保证进入下标 `i` 时两个集合里恰好是 `i` 右侧的全部元素：

   - `v = nums[i]`，若 `v` 是奇数 → 到 `ou`（相反奇偶）里 `bisect_left(v)`，结果即为得分；然后把 `v` 插进 `ji`。
   - 若 `v` 是偶数 → 到 `ji` 里 `bisect_left(v)`；然后把 `v` 插进 `ou`。

   一次扫描、每个元素各做一次查询和一次插入，整体 O(n log n)。

4. **为什么这个顺序是对的**：反向遍历 + 「边扫边插」= 把后缀集合**增量地**维护起来。这比"先把后缀建好再逐个删"简单得多 —— 删除要处理重复计数，插入不用。

### 关键点

- **两个容器分工明确**：**查询查「相反奇偶」，插入插「自身奇偶」**。这两步指向不同容器，是本题唯一的坑点。
- `bisect_left(v)` 的返回值**本身就是答案**（严格小于 `v` 的元素个数），不要再写成 `len(...) - idx`。
- 容器必须是**多重集**：重复值的个数会影响更左侧元素的计数，用 `set` 会算错。
- 值域 10^9 但只关心相对大小 —— `SortedList` 按值比较即可，**不需要离散化**；只有换成树状数组/桶时才需要先把值压成 rank。

## 三、代码实现

### 最终代码

```python
from sortedcontainers import SortedList   # 截图里没有、已补


class Solution:
    def countSmallerOppositeParity(self, nums: list[int]) -> list[int]:
        ji = SortedList()   # 右侧已扫描的奇数
        ou = SortedList()   # 右侧已扫描的偶数
        n = len(nums)
        a = [0] * n
        for i in range(n - 1, -1, -1):
            v = nums[i]
            if v & 1:                     # 奇 → 去偶数集里数比它小的
                a[i] = ou.bisect_left(v)
                ji.add(v)                 # 再把自己放进奇数集
            else:                         # 偶 → 去奇数集里数比它小的
                a[i] = ji.bisect_left(v)
                ou.add(v)
        return a
```

## 四、复杂度分析

| 版本 | 时间复杂度 | 空间复杂度 |
| :--- | :--- | :--- |
| **最终代码**（双 SortedList） | O(n log n) | O(n) |
| 朴素解法（双重循环） | O(n²) | O(1) |
| 理论下界 | O(n log n) | O(n) |

> 复杂度中的 n 指数组 `nums` 的长度；记 m 为不同取值的个数时，离散化版本的空间是 O(m)。

- 每个元素做一次 `bisect_left`（O(log n)）和一次 `add`（文档标注 O(log n)，近似值：底层是分块有序数组，先二分定位、再块内后移，块大小有上限）。
- 空间是两个容器合计至多 n 个元素，加上输出数组本身。

## 五、优化评估

**结论**：时间复杂度已到比较模型下界（"统计逆序关系"至少要对数级别），**不需要再优化**；空间 O(n) 中的绝大部分是题目要求返回的数组本身。

### 瓶颈分析

每个元素两次容器操作是固定开销，n 次重复构成 n log n。真正可议的只是**这两次操作各自花了多少常数**：`SortedList.add` 除了二分定位，还要在块内把后面的元素后移。

### 可优化空间

1. **换成树状数组 + 离散化**：把"有序容器"换成"rank 前缀计数"，每次操作退化成一串纯下标跳转，完全不做元素搬移。时间复杂度同阶（O(n log n)），代价是多一趟排序去重求 rank。
2. **值域小的时候用桶计数**：若 `nums[i]` 的上界很小，直接开桶做前缀和，查询能降到 O(1)。本题值域 10^9，不适用。
3. **n 很小的时候**（几百以内）双重循环常数最小，容器操作反而是负担。

### 优化代码

离散化 + 双树状数组版本：

```python
class Solution:
    def countSmallerOppositeParity(self, nums: list[int]) -> list[int]:
        n = len(nums)
        # 只关心相对大小 → 离散化成 1..m 的 rank
        rank_of = {v: i + 1 for i, v in enumerate(sorted(set(nums)))}
        m = len(rank_of)

        bit = [[0] * (m + 1) for _ in range(2)]   # bit[0] 存偶数, bit[1] 存奇数
        ans = [0] * n

        def update(tree, x):
            while x <= m:
                tree[x] += 1
                x += x & -x

        def query(tree, x):                       # 前缀 [1, x] 的计数和
            s = 0
            while x > 0:
                s += tree[x]
                x -= x & -x
            return s

        for i in range(n - 1, -1, -1):
            v = nums[i]
            p = v & 1                             # 自身奇偶
            r = rank_of[v]
            ans[i] = query(bit[p ^ 1], r - 1)     # 相反奇偶里 rank < r，即值严格更小
            update(bit[p], r)
        return ans
```

**优化理由**：把「有序容器的定位 + 插入」换成「离散化 rank + 前缀和查询」，每个元素固定 O(log n) 次下标跳转，没有任何元素搬移；同时奇偶用 `p ^ 1` 直接当数组下标，省掉 if/else 分支。

### 常数级优化（可选）

- 奇偶判定用 `v & 1`，取相反奇偶用 `p ^ 1`，避免 `%` 与条件分支。
- `a[i] = ou.bisect_left(v)` 这一步不用再减，返回值即"严格小于 v 的个数"。
- 数据量小时直接双重循环，别为了"看起来高级"而引入容器。

## 六、易错点与总结

### 易错点

- **查错容器**：查「相反奇偶」、插「自身奇偶」。写成查同奇偶时代码照样跑、不报错，只是答案全错 —— 这是本题最隐蔽的错误。
- **遍历方向反了**：从左往右会把 `i` 左侧的元素算进去，违反 `i < j`。
- **先插后查**：把 `v` 自己先塞进容器再查询，虽然奇偶不同时不会数到自己，但逻辑已经错了，条件稍一放宽就崩。
- **用 `set` / 去重**：重复值必须各自计数（示例 2 的 `[4,4,1]` 就是为此设计的）。
- **忘了 `from sortedcontainers import SortedList`**：LeetCode 页面不显示这个 import，本地跑会 `NameError`。
- **`bisect_right` 与 `bisect_left`**：本题因奇偶不同、相反奇偶集合里不可能与 `v` 相等，两者结果恰好相同；但按题意 `nums[j] < nums[i]` 是严格小于，语义上必须用 `bisect_left`，别靠巧合。

### 题型套路沉淀

- **「右侧比当前小的个数」是逆序对计数的单边版本**，三件套任选：有序容器（`SortedList`）、树状数组（配离散化）、归并排序统计。要求在线/动态答案时优先前两者。
- **条件带「值 × 额外属性」两个维度时，按额外属性分桶**，桶内各自维护有序结构，查询只查符合条件的桶。比把属性拼进 key 简单得多，也不破坏比较语义。
- **反向遍历 + 边扫边插**是"后缀集合增量维护"的标准骨架，凡 `i < j` 型统计题都能套：进入 `i` 时容器恰好等于"i 右侧"。
- 数据结构的选型口诀：**要「秩查询 + 动态插入」就找有序集合；要「前缀计数」就找树状数组/线段树；值域小就直接开桶。**
