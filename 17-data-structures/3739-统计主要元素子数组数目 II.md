# 3739. 统计主要元素子数组数目 II

> **难度**：困难
> **标签**：线段树 · 数组 · 哈希表 · 分治 · 前缀和 · 归并排序
> **原题链接**：https://leetcode.cn/problems/count-subarrays-with-majority-element-ii/

---

## 一、题目描述

给定整数数组 `nums` 和目标值 `target`，统计有多少个**连续非空子数组**以 `target` 为「主要元素」。

「主要元素」的定义：该元素在子数组中出现的次数**严格大于**子数组长度的一半。也就是说，若某段 `[l, r]` 中 `target` 出现 `cnt` 次、长度为 `len = r - l + 1`，则需要 `2 * cnt > len`。

注意「严格大于」—— 恰好等于一半不算。

### 示例

```text
输入：nums = [1,2,2,3], target = 2
输出：5
解释：满足条件的子数组为
      [2]          (nums[1..1])
      [2]          (nums[2..2])
      [2,2]        (nums[1..2])
      [1,2,2]      (nums[0..2])
      [2,2,3]      (nums[1..3])
```

```text
输入：nums = [1,1,1,1], target = 1
输出：10
解释：10 个非空子数组全部满足（2 个出现 1 次、2 次、3 次、4 次的各若干，cnt 恒 > len/2）。

输入：nums = [1,2,3], target = 4
输出：0
解释：target 不在数组中，不可能成为任何子数组的主要元素。
```

### 约束条件

- `1 <= nums.length <= 10^5`
- `1 <= nums[i] <= 10^9`
- `1 <= target <= 10^9`

## 二、解题思路

### 核心思想

把「出现次数 > 长度一半」改写成**子数组和 > 0**：令 `target` 记 `+1`、其它元素记 `-1`，则一段子数组的和恰为 `cnt - (len - cnt) = 2 * cnt - len`，「主要元素」条件 `2 * cnt > len` 就等价于**该段和大于 0**。再用**前缀和**把它变成「统计顺序对」—— 一段 `(l, r]` 的和大于 0 等价于 `P[r] > P[l]`，于是问题变成**数有多少对下标 `l < r` 满足 `P[l] < P[r]`**，用有序容器边扫边二分即可。

### 思路演进

1. **暴力解法**：枚举所有左右端点 `O(n²)`，内层维护 `cnt` 与 `len` 判断 `2 * cnt > len`。n = 10^5 时子数组总数约 5×10^9 个，即使每次判断 O(1) 也远超时间限制。瓶颈在「枚举所有子数组」这件事本身。

2. **观察到**：真正决定成败的不是 `cnt` 和 `len` 各自的值，而是 `2 * cnt - len` 的**正负**。把 `target` 记 `+1`、非 `target` 记 `-1` 后，一段的和恰好就是 `2 * cnt - len`。于是判据从「数两个量」变成「看一个量是否为正」，可以复用**前缀和**的差：`sum(l, r] = P[r] - P[l] > 0`。

3. **再转化**：`P[r] - P[l] > 0` ⟺ `P[l] < P[r]`。所以答案 = 满足 `l < r` 且 `P[l] < P[r]` 的**下标对数** —— 也就是前缀和序列里的「顺序对」个数（`l < r` 保证了子数组非空）。

4. **优化为**：从左到右扫前缀和，扫到 `P[r]` 时，只需要知道「**已经出现过**的 `P[0..r-1]` 中有多少个**严格小于** `P[r]`」。这正是一个「有序集合 + 统计更小元素个数」的查询：用 `SortedList` 维护已出现的前缀和，`bisect_left(P[r])` 返回严格小于它的个数（`bisect_left` 定位第一个 `>= P[r]` 的位置，其左侧全部严格更小），累加后把 `P[r]` 插入。

### 关键点

- **`+1/-1` 映射是整题的关键一步**：它把「频率与长度的双重约束」压成「和的正负」这一个标量，后面的前缀和与计数才有意义。
- **严格小于 ⇒ `bisect_left`**，不是 `bisect_right`。用后者会把「相等」也算成合法，而 `P[l] == P[r]` 对应子数组和为 0，即 `cnt` 恰好等于一半，**不**满足「严格大于一半」。
- **`P[0] = 0` 必须提前放进集合**。前缀和下标从 0 起算，子数组 `(0, r]` 依赖 `P[0]`；漏掉它会把「从数组开头起的子数组」全部漏统计。
- **答案量级**：n = 10^5 时最多约 `n(n+1)/2 ≈ 5×10^9` 对，超过 32 位有符号整数范围。C++/Java 需要 `long long`；Python 的 `int` 天然安全。
- `SortedList` 来自 `sortedcontainers` 库，LeetCode 的 Python 环境已内置；本地运行时需要 `pip install sortedcontainers`。

## 三、代码实现

### 最终代码

```python
from sortedcontainers import SortedList


class Solution:
    def countMajoritySubarrays(self, nums: List[int], target: int) -> int:
        s1 = SortedList([0])        # 已出现的前缀和，预先放入 P[0] = 0
        s = 0                       # 当前前缀和
        ans = 0
        for i in nums:
            s += 1 if i == target else -1      # target 记 +1，其余记 -1
            ans += s1.bisect_left(s)           # 严格小于当前前缀和的个数
            s1.add(s)
        return ans
```

> 说明：截图里的代码没有 `s = 0` 的初始化、也没有 `from sortedcontainers import SortedList`，这两处已补上（缺前者会直接 `NameError`，缺后者会 `NameError: SortedList`）。

## 四、复杂度分析

| 版本 | 时间复杂度 | 空间复杂度 |
| :--- | :--- | :--- |
| **最终代码** | O(n log n) | O(n) |
| 朴素解法 | O(n²) | O(1) |
| 理论下界 | O(n) | O(n) |

> 复杂度中的 n 指数组 `nums` 的长度。

- **最终代码**：每个元素做一次 `bisect_left` 与一次 `add`，各 `O(log n)`；`SortedList` 内部是分块列表，插删的均摊代价为 `O(log n)` 级别的块定位加块内移动。总共 n 次，故 `O(n log n)` 时间；集合最多存 n+1 个前缀和，`O(n)` 空间。
- **朴素解法**：枚举 `O(n²)` 个子数组、每次 O(1) 判断，共 `O(n²)`；只用到几个计数器，空间 `O(1)`。
- **理论下界**：至少要读一遍数组，`O(n)` 是时间下界；前缀和本身不必存成数组（相邻值只差 ±1，可在扫描中增量维护），故空间也可做到 `O(n)`（哈希表存频次）。

## 五、优化评估

**结论**：解法正确、能过，但时间复杂度**还有一档可优化**：本题可做到 `O(n)`。原因是前缀和序列有一个别处没有的特殊性质 —— **相邻两项只差 ±1**，这使得「严格小于当前值的已有前缀和个数」可以**增量维护**，不需要每步二分。

### 瓶颈分析

`O(n log n)` 的 log 全部来自 `SortedList` 的查询与插入：我们要的其实只是一个标量 `less = #{已出现的前缀和 : 值 < s}`，但为了在 `s` 变化后重新算出它，才不得不维护一棵有序结构。

### 可优化空间

注意 `s` 每次只变 1：

- `s → s + 1`：原来「等于旧 `s`」的那 `freq[s]` 个前缀和，现在全部变成「严格小于新 `s`」，故 `less += freq[s]`。
- `s → s - 1`：新值 `s` 自身的那 `freq[s]` 个不再算「严格小于自己」，故 `less -= freq[s]`。

于是把有序结构换成**哈希表记频次**，`less` 变成 O(1) 增量更新，整体 `O(n)`。由于值域跨度可达 ±10^5，哈希表比数组更稳（无需偏移映射）。

### 优化代码

```python
class Solution:
    def countMajoritySubarrays(self, nums: List[int], target: int) -> int:
        freq = {0: 1}       # 已出现的前缀和频次，先放入 P[0] = 0
        s = 0               # 当前前缀和
        less = 0            # 已出现的、严格小于 s 的前缀和个数
        ans = 0
        for x in nums:
            if x == target:
                less += freq.get(s, 0)   # 旧值 s 现在全部严格更小
                s += 1
            else:
                s -= 1
                less -= freq.get(s, 0)   # 新值 s 自己不再算"严格小于"
            ans += less
            freq[s] = freq.get(s, 0) + 1
        return ans
```

**优化理由**：`less` 的定义只依赖「当前值」和「频次分布」，而当前值每步只移动 1，所以相邻两步的 `less` 之差恰好是「跨过的那一档」的频次。把「重新查询」换成「增量修正」，`log n` 就被消掉了。注意两步的更新方向相反、且 `-1` 分支必须**先 `s -= 1` 再查 `freq[s]`**，因为要扣的是新值那一档。

### 常数级优化（可选）

- `freq.get(s, 0)` 里的 `get` 比 `if s in freq` 少一次哈希查找；但**不要**用 `defaultdict` —— 它在「读」时也会插入键，会让 `freq` 无限膨胀，且语义上把访问当成了写入。
- 把 `1 if x == target else -1` 换成 `+1 if x == target else -1` 只是可读性问题，无性能差别；真正影响常数的是把分支挪出循环（例如先预处理成 ±1 序列），但预处理本身又要一次遍历，通常不划算。

## 六、易错点与总结

### 易错点

- **`bisect_left` 写成 `bisect_right`**：会把 `P[l] == P[r]`（和为 0，`cnt` 恰好为一半）误算进答案，答案偏大。这是本题最容易错的一处。
- **忘了 `P[0] = 0`**：`SortedList([0])` 或 `freq = {0: 1}` 是必需的初始状态，漏掉就漏掉所有「从下标 0 开始」的子数组。
- **把「严格大于一半」写成 `>=`**：`2 * cnt >= len` 会把偶数长度的恰好一半情况算进来，示例 1 就会得到 6 而不是 5。
- **答案溢出**：`O(n²)` 量级的计数在 C++/Java 中要用 `long long`，`int` 会静默溢出。
- **`defaultdict` 陷阱**：在增量维护版里用 `defaultdict(int)` 当频次表，`freq[s]` 的读取会插入大量 0 值键；且判断"是否存在"时 `d[k]` 与 `d.get(k, 0)` 语义不同，容易写出隐蔽 bug。

### 题型套路沉淀

- **「子数组满足计数条件」→ 转成「子数组和的正负」→ 再转成「前缀和的大小关系」**：这是连续子数组计数题最通用的一条流水线。凡是条件里出现「某元素占多数 / 超过一半 / 出现次数与长度比较」，第一反应就该是 ±1 映射。
- **`P[l] < P[r]` 的计数 = 顺序对计数**，三种实现路线：有序容器二分（`SortedList`，`O(n log n)`，最易写）、树状数组/线段树（先离散化，`O(n log n)`）、归并排序统计（`O(n log n)`，`O(1)` 额外空间但需要能改数组）。官方标签里的「线段树」「归并排序」「分治」正对应后两条。
- **当相邻前缀和只差 ±1 时，务必想到「增量化」**：这类「查询一个随扫描位置连续移动的量」的问题，往往能把 log 去掉。判断能否增量的信号是「新查询值与旧查询值之间的差集很小」。
- **写完后自检三件事**：严格/非严格的边界（`<` vs `<=`）、初始状态（空前缀是否入表）、答案量级（是否超 32 位）。
