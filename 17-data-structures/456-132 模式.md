# 456. 132 模式

> **难度**：中等
> **标签**：栈 · 数组 · 二分查找 · 有序集合 · 单调栈
> **原题链接**：https://leetcode.cn/problems/132-pattern/

---

## 一、题目描述

给定整数数组 `nums`，判断是否存在下标 `i < j < k`，满足 `nums[i] < nums[k] < nums[j]`。也就是在数组里找一个形如 `1-3-2` 的**子序列**（不要求连续）：先一个小值，再一个大值，最后夹在中间的中值。

### 示例

```text
输入：nums = [1,2,3,4]
输出：false
解释：整体递增，第三个位置之后的数不会比中间的「峰值」更小。

输入：nums = [3,1,4,2]
输出：true
解释：子序列 [1, 4, 2] 满足 1 < 2 < 4。

输入：nums = [-1,3,2,0]
输出：true
解释：[-1, 3, 2]、[-1, 3, 0]、[-1, 2, 0] 都满足条件。
```

### 约束条件

- `n == nums.length`
- `1 <= n <= 2 * 10^5`
- `-10^9 <= nums[i] <= 10^9`

---

## 二、解题思路

### 核心思想

**把三个下标的问题拆成「固定中间那个峰值 `j`」的子问题：只要 `j` 左边的最小值 `min_left < ` 右边某个值 `< nums[j]`，答案就是 true。** 维护这个「右边某个值」的最优候选，可以做到只扫一遍。

### 思路演进

1. **暴力解法**：三重循环枚举所有 `(i, j, k)`，判断 `nums[i] < nums[k] < nums[j]`。时间 O(n³)，n = 2×10^5 时是 8×10^15 次比较 —— 完全不可能。

2. **压缩一层：定 `j`，左右分开看**。固定 `j` 后，条件变成「`j` 左侧存在比 `nums[j]` 小的值」且「`j` 右侧存在介于两者之间的值」。左侧最小值 `min_left` 可以 O(1) 递推（前缀最小值），于是只剩右侧查询：找一个 `nums[k] ∈ (min_left, nums[j])`。

3. **朴素地查右侧**：对每个 `j` 扫它右边所有元素，时间退化成 O(n²)。n = 2×10^5 时仍是 4×10^10，不行。

4. **观察到「大部分扫描是重复的」**：`j` 从左往右移动时，`min_left` 只会变小（更容易满足下界 `> min_left`）；而右侧候选里，**一旦某个值被右侧更大的元素「压过」，它的存在意义就消失了** —— 因为它既当不了「3」（右边有更大的），作为「2」也不如更大的那个好用。这正是单调栈的淘汰规则。

5. **反向扫描 + 单调栈**：从右往左扫，栈里存「还没被淘汰的候选 `nums[j]`（即未来的 `3`）」，并维护 `k` = **所有被淘汰元素（未来的 `2`）中的最大值**。

   - 遇到 `nums[i]`：先看 `nums[i] < k` 是否成立 —— 成立就找到了「1」。为什么？`k` 这个值当初是被某个下标更靠右、且更大的元素 `nums[j]` 弹出栈的，而 `i` 在这个 `j` 的左边，于是 `nums[i] < k < nums[j]` 且 `i < j < k_index`，正好是 132。
   - 然后按单调栈常规操作：把栈顶所有**严格小于** `nums[i]` 的元素弹出（它们被 `nums[i]` 压过，可以退休了），**每弹出一个就用它更新 `k` 的最大值**。
   - 最后把 `nums[i]` 压栈。

   每个元素最多进出栈一次，总时间 O(n)。

### 关键点

- **`k` 要取 `max` 而不是「弹出的最后一个」**：栈是单调不增的，从栈顶弹出去的元素顺序并不保证递增，只有取最大值才是对「2」最优的候选（`k` 越大，`nums[i] < k` 越容易成立，且 `k` 仍然满足 `k < 某个右侧峰值`）。
- **比较必须是严格小于**：题目要求 `nums[i] < nums[k] < nums[j]` 三个严格不等式，所以 `while stack[-1] < nums[i]` 不能写成 `<=`，否则相等的元素会被误当成合法的大小关系。
- **先判 `nums[i] < k`，再做弹栈**：判断时用的 `k` 只包含「被右侧更大元素淘汰过」的值，这正是合法「2」的定义。顺序颠倒虽不会造成误报，但会让 `k` 的语义变模糊。
- **哨兵要严格小于所有可能取值**：`-(10**9 + 7)` 严格小于下界 `-10^9`，保证初始的 `k` 不会与任何 `nums[i]` 构成「合法」比较；若写成 `0`，全负数数组会直接漏判。
- 栈的取值范围：右侧元素按**单调不增**（自底向上递减）维护，栈顶始终是候选中的最小值。

## 三、代码实现

### 最终代码

```python
class Solution:
    def find132pattern(self, nums: list[int]) -> bool:
        stack = []
        k = -(10 ** 9 + 7)                  # 哨兵：严格小于 -10^9，记录已淘汰「2」的最大值
        for i in range(len(nums) - 1, -1, -1):
            if nums[i] < k:                 # 当前值能当「1」
                return True
            while stack and stack[-1] < nums[i]:
                k = max(k, stack.pop())     # 被 nums[i] 压过的元素，均可当「2」
            stack.append(nums[i])           # nums[i] 作为未来的「3」入栈
        return False
```

## 四、复杂度分析

| 版本 | 时间复杂度 | 空间复杂度 |
| :--- | :--- | :--- |
| **最终代码** | O(n) | O(n) |
| 朴素解法（枚举三元组） | O(n³) | O(1) |
| 定 `j` 后线性扫右侧 | O(n²) | O(1) |
| 理论下界 | O(n) | O(n) |

> 复杂度中的 n 指数组 `nums` 的长度。最终代码里每个元素最多入栈一次、出栈一次，故总时间 O(n)；栈最坏情况下（数组严格递减）装满全部元素，空间 O(n)。

## 五、优化评估

**结论**：时间复杂度已达理论下界 O(n)，**空间 O(n) 也是这类解法的必要代价**，没有可去掉的冗余。

### 瓶颈分析

时间上，任何算法都必须完整读一遍数组才能确认「不存在」，所以 O(n) 不可再降。当前实现里每个元素只有一次入栈和至多一次出栈，循环内均摊 O(1)，没有多余遍历。

空间上，栈里存的是「尚未被右侧更大元素淘汰的峰值候选」。数组严格递减时，每一个元素都还可能充当「3」，必须全部保留到左侧出现更小的「1」为止 —— 这种情况下栈确实要装 n 个元素。若只用 O(1) 辅助空间，就得重复扫描来换取信息，时间会退回 O(n²)，得不偿失。

### 可优化空间

没有算法层面的改进空间。同类问题的另一条正解是「从左往右维护前缀最小值 + 用有序集合/二分查找在后缀里找落在区间内的值」，时间 O(n log n)、空间 O(n)，在本题的数据规模下不如当前 O(n) 的单向扫描。

### 常数级优化（可选）

- 把 `max(k, stack.pop())` 换成显式比较，少一次函数调用与一次元组打包：

```python
class Solution:
    def find132pattern(self, nums: list[int]) -> bool:
        stack: list[int] = []
        two = float("-inf")                 # 已淘汰的「2」中的最大值
        for x in reversed(nums):
            if x < two:
                return True
            while stack and stack[-1] < x:
                v = stack.pop()
                if v > two:
                    two = v
            stack.append(x)
        return False
```

- 用 `for x in reversed(nums)` 代替 `range(len(nums) - 1, -1, -1)` 加下标访问，省掉每次迭代的索引运算和一次 `nums[i]` 取值。
- 用 `float("-inf")` 当哨兵和用 `-(10**9 + 7)` 等价，前者不依赖数据范围，改动数据约束时更安全。

## 六、易错点与总结

### 易错点

- **弹栈时忘了取最大值**：直接写成 `k = stack.pop()` 会把 `k` 覆盖成一个可能更小的值，漏掉解。例如 `[3,1,4,2]` 从右往左弹栈时会先后弹出不同量级的候选，只有最大值有效。
- **`<` 写成 `<=`**：题目要求三处严格不等式，相等元素不构成 132 模式；`while stack[-1] < nums[i]` 用 `<=` 会把相等的元素也判成「有更大的峰值压过它」，逻辑基础就不再成立。
- **哨兵取值不当**：初始 `k` 若写成 `0`，负数数组（如 `[-1,3,2,0]` 这类）会直接返回 false；写成 `float("-inf")` 或小于 `-10^9` 的常数才安全。
- **扫描方向与栈的单调性搞反**：本题必须**从右往左**扫、栈维护单调不增序列。若从左往右扫，栈里存的是左侧元素，逻辑要整体重写（改前缀最小值 + 后缀结构），照抄方向会得到错误答案。
- **误以为需要连续子数组**：题目要的是子序列，`i`、`j`、`k` 之间允许隔着任意多个元素，不需要相邻。

### 题型套路沉淀

- **「132 / 峰值两侧夹心」模型**：固定中间峰值 `j`，把问题拆成「左边最小值」和「右边某个区间内的值」两个独立查询。遇到「找三个下标满足某个大小关系」的题，先试着固定中间那个。
- **反向单调栈 + 淘汰值聚合**：从右往左扫，栈维护还没被更大元素压过的候选，同时用一个变量聚合「已被淘汰的候选」里的极值。这是「右侧下一更大元素」家族的自然延伸 —— 栈解决「谁是第一个更大的」，被弹出去的那些值则携带了额外的信息（本题里就是合法的「2」）。
- **单调栈的三个固定决策**：扫的方向、栈内单调性（增/减）、弹出条件是否严格。这三处任一处写错，答案都会悄悄错在边界数据上。
- 复杂度上这类题的典型形态是「O(n) 时间 + O(n) 空间」，看到 n ≤ 2×10^5 就应该立刻排除 O(n²)。
