## 一、题目描述

给定整数数组 `nums` 与两个整数 `k`、`m`，统计满足下列**两个条件同时成立**的连续非空子数组个数：

- 子数组**恰好**包含 `k` 个不同的整数；
- 其中每个不同的整数都**至少**出现 `m` 次。

### 示例

```text
示例 1
输入：nums = [1,2,1,2,2], k = 2, m = 2
输出：2
解释：满足条件的子数组为
      [1,2,1,2]    -> 不同整数 {1,2}，频次 {1:2, 2:2}
      [1,2,1,2,2]  -> 不同整数 {1,2}，频次 {1:2, 2:3}

示例 2
输入：nums = [3,1,2,4], k = 2, m = 1
输出：3
解释：[3,1]、[1,2]、[2,4] 各含 2 个不同整数且每个至少出现 1 次
```

### 约束条件

- `1 <= nums.length <= 10^5`
- `1 <= nums[i] <= 10^5`
- `1 <= k, m <= nums.length`

## 二、解题思路

### 核心思想

引入两个关于窗口的**单调**度量：`d` = 窗口内不同整数个数，`g` = 窗口内「出现次数 ≥ m」的不同整数个数（`g <= d` 恒成立）。

因为 `g <= d`，所以

```text
「恰好 k 个不同 且 每个至少 m 次」
  ⟺ d == k 且 g == k
  ⟺ d == k 且 g >= k
  ⟺ #{d >= k, g >= k} − #{d >= k+1, g >= k}
```

**把「恰好（等号）」换成两个同向单调的「至少」条件之差** —— 两个 `>=` 条件都随窗口变长而单调变真，于是各自的合法左端点构成前缀，一个 `left` 指针就能数完，每项 O(n)。

### 思路演进

1. **暴力解法**：枚举 O(n²) 个子数组，每个用哈希表统计频次，判断 `len(cnt) == k and min(cnt.values()) >= m`。由于每个子数组都要重新扫一遍，实际是 O(n³)，`n = 10^5` 时不可能。
2. **瓶颈定位（为什么第一反应「滑窗」直接用不了）**：子数组数量是 O(n²)，要降到 O(n) 必须靠「固定右端时合法左端是一个前缀」这种单调结构。但本题的约束是**等号**：
   - 固定右端 `j`，左端 `l` 左移（窗口变长）时 `d` 单调不减，于是 `d == k` 成立的那些 `l` 落在**中间一段区间**，既不是前缀也不是后缀；
   - 单指针 `left` 只能刻画前缀边界，数不出「区间」，所以「恰好 k 个不同」**不能**直接做成一个滑窗。
3. **关键转化**：
   - **观察到 1**：加一个辅助量 `g`（窗口内频次 ≥ m 的不同整数个数），则「恰好 k 个不同且每个都够 m 次」⟺ `d == k` **且** `g >= k`。因为 `g <= d`，`g >= k` 配上 `d == k` 时恰好逼出 `g == d == k`，即「k 个种类全都达标」。
   - **观察到 2**：把等号 `d == k` 拆成两个 `≥` 的差：`#{d >= k, g >= k} − #{d >= k+1, g >= k}`，剩下的正是 `#{d == k, g >= k}`。
   - **为什么现在行了**：`d >= L` 与 `g >= k` 都随窗口变长而**单调变真**，所以「两个条件同时成立」也是单调的 —— 固定右端 `j`，满足条件的左端恰好是前缀 `[0, left-1]`，个数就是 `left`。同一个 `while` 判据、一个指针就能数。
4. **最优解**：写函数 `calc(L) = #{子数组 : d >= L 且 g >= k}`，用「收缩到刚好不满足判据」的滑窗实现；答案 = `calc(k) − calc(k+1)`。两趟各摊还 O(n)。

### 关键点

- **判据（一句话）**：对固定右端 `j`，「窗口 `[l, j]` 满足 `d >= L 且 g >= k`」关于 `l` 单调不增（窗口变长只会更容易满足）⇒ 合法左端点集合是**前缀**，`while` 退出时的 `left` 就是它的长度，`ans += left` 逐轮累加即可。
- **窗口停在「非法一侧」**：`while` 的收缩条件**就是**判据本身（`len(cnt) >= L and good_numbers >= k`），循环退出时 `left` 是第一个**不满足**判据的左端，因此计数区间是 `[0, left-1]`。这与「求最长/最短窗口」那类滑窗（收缩到合法为止）方向正好相反。
- **两根单调性**：`d`、`g` 关于左端单调 ⇒ 判据单调；`left` 全程只增不减（总移动 ≤ n）⇒ 内层 `while` 摊还 O(1)，不是 O(n²)。
- **`g` 的 O(1) 维护**：进窗元素计数 `== m` 时 `g += 1`；出窗元素计数**恰好** `== m` 时 `g -= 1`（表示从 m 掉到 m-1，跨过阈值）。两处都必须「先比较、再改计数」。
- **`len(cnt) >= L` 写在 `and` 的左边**：短路掉不必要的比较（`g >= k` 的求值次数会明显减少）。
- **差分方向**：`calc(k) − calc(k+1)` 与 `while` 里的 `>=` 是**配套**的，拆开改会得到完全错误的量（见易错点）。

## 三、代码实现

### 最终代码

> 截图里只有 `class Solution`，`defaultdict` / `List` 的 import 已补上；代码为用户已提交通过的版本，**未改动逻辑**。

```python
from collections import defaultdict
from typing import List


class Solution:
    def countSubarrays(self, nums: List[int], k: int, m: int) -> int:
        def calc(distinct_limit: int) -> int:
            ans = left = good_numbers = 0
            cnt = defaultdict(int)
            for j in nums:
                cnt[j] += 1
                if cnt[j] == m:                       # 该值刚跨过 m，成为「达标值」
                    good_numbers += 1
                while len(cnt) >= distinct_limit and good_numbers >= k:
                    if cnt[nums[left]] == m:          # 先判断：即将从 m 掉到 m-1
                        good_numbers -= 1
                    cnt[nums[left]] -= 1
                    if cnt[nums[left]] == 0:
                        del cnt[nums[left]]           # 种类数 d = len(cnt)，归零必须删键
                    left += 1
                ans += left                           # 合法左端点 = [0, left-1]
            return ans

        return calc(k) - calc(k + 1)                  # 差掉「d >= k+1 且 g >= k」的部分
```

## 四、复杂度分析

> 复杂度中的 n 指数组 `nums` 的长度。

| 版本 | 时间复杂度 | 空间复杂度 |
| :--- | :--- | :--- |
| **最终代码** | O(n)（摊还；常数约 2 趟） | O(n) |
| 朴素解法 | O(n³) | O(n) |
| 理论下界 | O(n) | O(n) |

- **时间**：每趟里每个元素进窗 1 次、出窗至多 1 次，`left` 单调不减，故单趟摊还 O(n)；跑 `L = k`、`k+1` 两趟 ⇒ 2n 次进窗 + 2n 次出窗，O(n)（只是常数翻倍）。
- **空间**：最坏 O(n)。例：`nums` 全不相同且 `m >= 2` 时 `g` 恒为 0，永远不满足 `g >= k`，窗口一路长到 n 个数（对应实测场景 S1/S4 里 dict 涨到 10^5 个键）。
- **下界**：任何算法都要读入全部元素（否则没读到的位置取何值都会改变它作为单元素子数组是否合法），故时间 Ω(n)；而上文最坏情形下窗口内可能出现 n 个不同值、必须逐值保留计数，故 O(n) 空间也是必要代价。

## 五、优化评估

**结论**：**渐进复杂度已到理论下界**（时间 O(n)、空间 O(n)），剩余空间全在常数上。常数层面实测**「值域数组计数」版最优**：n = 10^5 的四档场景下比截图原版快 **1.50× ~ 1.79×**。

### 瓶颈分析

时间几乎全花在哈希表操作上：每轮 `cnt[j] += 1`（含 `__missing__` 回退）、收缩时的读 / 减 / 删，再乘上两趟。`len(cnt)` 也在每轮判据里被调用一次。

### 可优化空间

1. **`defaultdict` → `dict.get`**：去掉 `__missing__` 的每次调用开销（实测 1.44× ~ 1.60×）。
2. **值域数组替代哈希表**：题面保证 `1 <= nums[i] <= 10^5`，可以用 `[0]*(max+1)` 数组做计数，用独立变量 `distinct` 顶替 `len(cnt)` —— 数组下标比哈希查找快，且没有 `del` 的开销（实测 1.50× ~ 1.79×，四档全胜）。
3. **单趟双窗**（两个 `left` 指针、两张计数表共用一个 `for`）：实测**基本无收益**（1.46× ~ 1.63×，与只做 `dict.get` 的版本持平甚至略慢）—— 因为省下的只是一个循环外壳，进窗/出窗的总次数没变，反而多维护一张表的状态。

**为什么不可能是 O(n) 以下 / 能不能一个窗口搞定**：不能。答案 = `#{d >= k, g >= k} − #{d >= k+1, g >= k}`，这两项的分母（`d` 的下界）不同，各自需要独立的窗口状态；而 `d == k` 本身非单调（合法左端是区间不是前缀），单窗口数不出来 —— 所以「两趟差分」不是写法选择，而是这一族题的必需结构。

### 优化代码

```python
from typing import List


class Solution:
    def countSubarrays(self, nums: List[int], k: int, m: int) -> int:
        # 题面保证 1 <= nums[i] <= 10^5，值域有界 ⇒ 可以用数组代替哈希表
        top = max(nums) + 1

        def calc(distinct_limit: int) -> int:
            ans = left = good = distinct = 0
            cnt = [0] * top                       # 值 -> 频次
            for j in nums:
                if cnt[j] == 0:
                    distinct += 1                 # 顶替 len(cnt)
                cnt[j] += 1
                if cnt[j] == m:
                    good += 1
                while distinct >= distinct_limit and good >= k:
                    x = nums[left]
                    if cnt[x] == m:
                        good -= 1
                    cnt[x] -= 1
                    if cnt[x] == 0:
                        distinct -= 1
                    left += 1
                ans += left
            return ans

        return calc(k) - calc(k + 1)
```

**优化理由**：判据 `d >= L` 只用到「不同整数个数」，用一个 `distinct` 计数器即可，不必依赖 `len(哈希表)`；值域有界时数组下标访问比哈希查找快，且不必 `del`。**代价**：空间从 O(窗口内不同值个数) 变为 O(max(nums))，且**仅当值域有界（题面给出 `nums[i] <= 10^5`）时可用**；值域无界时只能用哈希表版本。

### 常数级优化（实测表）

## 六、易错点与总结

### 易错点

- **`while` 的 `>=` 与减法方向必须配套**（本题最坑的一处）：把 `len(cnt) >= L` 写成 `len(cnt) > L`，却仍用 `calc(k) − calc(k+1)`，算出来的是 `#{d == k+1, g >= k}` 而不是答案。最小反例就是**官方示例 1**：`nums=[1,2,1,2,2], k=2, m=2`，真值 2、得 0。正确配法是 `>` 配 `calc(k-1) − calc(k)`（实测 52 组 0 偏差）——**阈值平移一位，减法方向就得跟着平移一位**。
- **收缩不能用 `if` 顶替 `while`**：单步可能连续多格都不满足「收缩完成」。最小反例 `nums=[1,1,2], k=1, m=1`：真值 4、`if` 版得 5（`j=2` 那轮只缩一格，窗口 `[1,2]` 仍满足判据，`left` 停在 1 而不是 2，漏数了一个左端点）。
- **答案口径是「合法左端点数 `left`」，不是窗口长度**：写成 `ans += right - left + 1` 得到的是另一个量。最小反例 `nums=[1], k=1, m=1`：真值 1、窗口长度版得 **−1** —— **答案出现负数就是口径写错的信号**。
- **`del cnt[x]` 不能省**：判据里的 `d` 就是 `len(cnt)`，计数归零不删键会让 `d` 只增不减，指针被一路推到越界。
- **出窗顺序**：必须「先 `if cnt[x] == m: good -= 1`，再 `cnt[x] -= 1`」，反过来会把「恰好从 m 掉下去」这一步漏掉。
- **`nums[left]` 的越界风险**：`while` 内访问 `nums[left]` 只在窗口非空时发生（判据含 `d >= L >= 1`），故 `left <= j` 恒成立；但若哪天需要 `L = 0`（如 `k = 0` 的变体），收缩条件会恒真并把 `left` 推到 `j+1`，那时必须补 `left <= right` 守卫。本题 `k >= 1`，不需要。

### 题型套路沉淀

- **计数型滑窗（约束形如「度量 ≥ 下限」）**：窗口收缩到**刚好跌破**约束，循环退出后「合法左端点」是前缀 `[0, left-1]`，答案口径是 `ans += left`。方向与「求最长/最短子数组」的滑窗**相反**，两者最容易串用。
- **「恰好 k 个」的通用拆法**：任何「恰好的等号约束」先想能不能写成两个同向 `≥`（或 `≤`）条件的差；能拆的前提是拆出来的每一项关于窗口大小**单调**。
- **双条件滑窗的成立条件**：所有并列条件必须同向单调（窗口变长时一起变真），合法性集合才可能是前缀；一旦出现「越多越不好」的项（如 `d <= k`），就必须改用差分，而不是硬塞进一个窗口。
- 本题的骨架与 `992`、`930`、`1248` 同属「计数 + 差分」一族，但**判据与差值构造方式各不相同**，二刷时按本题自身推导，不要套用别的题的条件式。
