# 1852. 每个子数组的数字种类数

> **难度**：中等

## 一、题目描述

给定长度为 `n` 的整数数组 `nums` 和整数 `k`，返回长度为 `n - k + 1` 的数组 `ans`，其中 `ans[i]` 是子数组 `nums[i .. i+k-1]` 中**不同元素的个数**。

### 示例

```text
示例 1
输入：nums = [1,2,3,2,2,1,3], k = 3
输出：[3,2,2,2,3]
解释：
  nums[0..2] = [1,2,3] -> 3 个数
  nums[1..3] = [2,3,2] -> 2 个数
  nums[2..4] = [3,2,2] -> 2 个数
  nums[3..5] = [2,2,1] -> 2 个数
  nums[4..6] = [2,1,3] -> 3 个数

示例 2
输入：nums = [1,1,1,1,2,3,4], k = 4
输出：[1,2,3,4]
解释：四个窗口里的不同元素个数依次为 1、2、3、4。
```

### 约束条件

- `1 <= k <= nums.length <= 10^5`
- `1 <= nums[i] <= 10^5`
- 注意：**保证 `k <= nums.length`**，所以答案数组长度恒 `>= 1`
- 值域有界（`nums[i] <= 10^5`）—— 这一点后面会用到

## 二、解题思路

### 核心思想

**定长滑动窗口 + 频率计数表**。窗口每往后滑一位，只有「一个元素进、一个元素出」两处变化，维护一张「元素 → 窗口内出现次数」的表，那么 **不同元素个数 == 表的键数 == `len(cnt)`**。

### 思路演进

1. **暴力解法**：对每个起点 `i ∈ [0, n-k]` 执行 `len(set(nums[i:i+k]))`。
   时间 O(n·k)。`n` 和 `k` 都能到 10^5，最坏量级约 10^10 次操作 —— 不是"慢"，是根本跑不完。

2. **观察到**：窗口 `nums[i..i+k-1]` 与下一个窗口 `nums[i+1..i+k]` 有 `k-1` 个元素完全重叠，重新建一遍 set 是纯粹浪费。真正变化的只有两处：
   - 新进来的 `nums[i+k]`（右端）
   - 被挤出去的 `nums[i]`（左端）

3. **优化为**：把窗口做成"增量可维护"的。维护 `cnt`（元素 → 出现次数）：
   - 右端进：`cnt[x] += 1`
   - 若该元素计数从 0 变 1，说明窗口里多了一个**新种类**；从 0 变 1 这个判断是"种类数"增减的唯一依据
   - 左端出：`cnt[y] -= 1`，若归零则删键，说明窗口里少了一个种类

4. **代码上的简化**：既然"种类数"就是 `cnt` 的键数，而 Python 的 `dict` 天然提供 `len()`（CPython 下是 O(1) 读内部计数器），于是**连 `distinct` 变量都不用维护**，直接 `ans.append(len(cnt))`。

5. **循环结构的处理**：传统模板要写两段（先铺满 `k` 个，再滑动），本题用 `enumerate` 单循环 + `if i < k - 1: continue` 把两段合并成一段，代码更短。

### 关键点

- **`len(cnt)` 直接就是答案**。这是本题最省事的一点，也是为什么它比 1100 更"顺手"：1100 是拿 `len(cnt)` 做比较（判是否等于 k），1852 是把 `len(cnt)` 直接当结果。
- **出窗归零必须 `del` 键**。`len()` 数的是**键的个数**，不是"当前窗口内不同值个数"。不删键，历史值会一直占着位置，窗口明明已经滑走了，`len(cnt)` 还把它们算进去 → 结果系统性偏大。
- **三件事的顺序固定为「右进 → 记录 → 左出」**。若把 `append` 放到左出之后，记录的就是长度 `k-1` 的窗口，答案偏小。
- **`nums[i-k+1]` 是出窗元素的下标**（窗口右端为 `i` 时）。写成 `nums[i-k]` 会整体错位一位。
- **本题不需要 `k > len(nums)` 的保护**：一是约束保证 `k <= n`，二是即便真传了越界的 `k`，`if i < k-1: continue` 会让循环一次都不记录，直接返回 `[]`，不会越界。

## 三、代码实现

### 最终代码

```python
from collections import defaultdict
from typing import List


class Solution:
    def distinctNumbers(self, nums: List[int], k: int) -> List[int]:
        ExistNum = defaultdict(int)   # 元素 -> 当前窗口内的出现次数
        ans = []
        for i, j in enumerate(nums):
            ExistNum[j] += 1          # 1) 右端进窗
            if i < k - 1:             #    窗口还没铺满 k 个
                continue
            ans.append(len(ExistNum))             # 2) 键数 == 窗口内不同元素个数
            ExistNum[nums[i - k + 1]] -= 1        # 3) 左端出窗
            if ExistNum[nums[i - k + 1]] == 0:    #    归零则删键，保证 len() 语义正确
                del ExistNum[nums[i - k + 1]]
        return ans
```

> **自检**：`len(ans) == n - k + 1`；且恒有 `1 <= ans[i] <= k`。
> 实测：`[1,2,3,2,2,1,3], k=3` → `[3,2,2,2,3]` ✓；`[1,1,1,1,2,3,4], k=4` → `[1,2,3,4]` ✓；另与暴力解做了 6000 组随机对拍，零 mismatch。

## 四、复杂度分析

| 版本 | 时间复杂度 | 空间复杂度 |
| :--- | :--- | :--- |
| **最终代码**（dict + `len()`） | O(n) | O(min(k, V)) |
| 计数数组版 | O(n) | O(V) |
| 朴素解法（逐窗口建 set） | O(n·k) | O(k) |
| 理论下界 | O(n) | O(min(k, V))（另需 O(n-k+1) 输出） |

> 复杂度中的 `n` 指数组 `nums` 的长度，`k` 为窗口长度，`V` 为值域大小（本题 `V = max(nums) <= 10^5`）。
> 空间上界 `O(min(k, V))`：计数表的键数不可能超过窗口长度 `k`，也不可能超过值域 `V`。

## 五、优化评估

**结论**：时间复杂度 **O(n) 已是理论下界**，空间也是**必要代价**；但**常数因子有 1.4 ~ 2.0 倍的压缩空间**。

### 瓶颈分析

1. **时间下界为什么是 O(n)**：`nums` 的每个元素都可能是某个窗口的组成部分，跳过任何一个都可能漏解；此外答案本身就要输出 `n-k+1` 个数。故 `Ω(n)` 不可突破。
2. **空间为什么不能压到 O(1)**：增量维护"窗口内不同元素个数"必须知道每个值在窗口里的**剩余次数**，才能判断"移出这个值后种类数该不该减一"。这份信息无可回避，至少 `O(min(k, V))`。
3. **实际开销的三处来源**：
   - `len(cnt)` 虽在 CPython 下是 O(1)，但每轮仍是一次方法调用；
   - `dict` 的哈希与 `del` 涉及内存管理，值域越大（表越接近 `k` 个键）开销越明显；
   - `ans.append` 需要执行 `n-k+1` 次。

### 可优化空间

**用计数数组替代哈希表**。本题 `nums[i] <= 10^5`，值域有界，`list` 下标访问没有哈希成本、也没有 `del` 的内存操作；再配上显式维护的 `distinct` 变量，就**彻底不需要 `del` 与 `len()`** —— 进窗时"计数由 0 变 1"则 `distinct += 1`，出窗时"计数归零"则 `distinct -= 1`。

**实测对比**（本机 Python 3.13，`n = 10^5` 随机数据，单位 ms，越小越好）：

| 实现 | k=1000<br>值域 10^5 | k=1000<br>值域 300 | k=50000<br>值域 10^5 | k=50000<br>值域 300 |
| :--- | ---: | ---: | ---: | ---: |
| 用户的 `defaultdict` + `len()` | 39.6 | 27.9 | 33.6 | 19.7 |
| `dict.get` + `len()`（两段式） | 25.8 | 22.5 | 31.3 | 15.7 |
| `dict` + 显式 `distinct` | 29.2 | 22.0 | 25.0 | 16.0 |
| **计数数组 + 显式 `distinct`** | **23.8** | **19.0** | **16.9** | **14.3** |

→ 计数数组版在全部场景中最快，比目前的写法快 **1.2 ~ 2.0 倍**；且当前写法是四种里最慢的。
（不过 40 ms 距离题目 2 s 的时限非常安全，本题**不优化也能稳过**，优化价值主要在大规模/高频调用场景。）

### 优化代码

```python
from typing import List


class Solution:
    def distinctNumbers(self, nums: List[int], k: int) -> List[int]:
        # 值域有界（nums[i] <= 10^5），用计数数组替代哈希表
        cnt = [0] * (max(nums) + 1)
        ans = []
        distinct = 0
        for i, x in enumerate(nums):
            if cnt[x] == 0:
                distinct += 1          # 新种类入窗
            cnt[x] += 1

            if i >= k:                 # 窗口已超长，左端出窗
                y = nums[i - k]
                cnt[y] -= 1
                if cnt[y] == 0:
                    distinct -= 1      # 该值彻底离开窗口

            if i >= k - 1:             # 窗口长度达到 k，记录答案
                ans.append(distinct)
        return ans
```

**优化理由**：

- `list` 下标是纯内存寻址，省掉字符/整数哈希与 `del` 的内存管理，这正是上表 1.2~2.0× 的来源。
- 显式 `distinct` 变量把"种类数"变成纯整数加减，不再依赖 `dict` 的键数，也就**从根上消除了"忘记 del 导致答案虚高"这个坑**。
- 空间 O(V)：本题 V ≤ 10^5，一个 10 万长的 int 列表约 800 KB，完全可接受。

**适用边界**：值域一旦放开（例如 `nums[i]` 可达 10^9），数组版就不可用了，只能退回哈希表 —— 此时用 `dict.get` + 显式 `distinct`（两段式）比 `defaultdict` + `len()` 约快 20%。

### 进阶：贡献法 + 差分数组（另一种思路，非优化）

滑窗是"在线"思路。本题还有一种"离线"思路，值得作为思维拓展：

- 记 `prev[j]` 为 `nums[j]` 上一次出现的下标；
- `nums[j]` 会成为"以 `i` 为起点的窗口"中该值的**首次出现**（即对 `ans[i]` 贡献 1）⟺ `i <= j`（它在窗口内）、`i >= j-k+1`（它没被挤出）、`i > prev[j]`（它是窗口内第一个）；
- 合起来：`i ∈ [max(j-k+1, prev[j]+1), min(j, n-k)]`，这是一个**区间**；
- 于是"每个 `j` 对一段连续的 `i` 各贡献 1" → 区间 +1 用**差分数组**，最后前缀和还原出 `ans`。

```python
from typing import List


class Solution:
    def distinctNumbers(self, nums: List[int], k: int) -> List[int]:
        n = len(nums)
        m = n - k + 1                      # 答案长度
        diff = [0] * (m + 1)               # 差分数组
        prev = {}
        for j, x in enumerate(nums):
            p = prev.get(x, -1)
            prev[x] = j
            lo = max(j - k + 1, p + 1)     # 能覆盖到 j 的窗口起点下界
            hi = min(j, m - 1)             # 上界
            if lo <= hi:                   # 区间 [lo, hi] 全部 +1
                diff[lo] += 1
                diff[hi + 1] -= 1
        ans, s = [], 0
        for i in range(m):                 # 前缀和还原
            s += diff[i]
            ans.append(s)
        return ans
```

**为什么它在本题不是优化**：时间复杂度同为 O(n)，但每轮 `max`/`min`/两次取模式的字典操作常数更大，额外空间是 O(n) 而非 O(k)。**它真正的价值在推广**：如果同一份数组上要回答**任意多个、窗口大小不固定**的"不同元素个数"查询，滑窗就失效了，而"上次出现位置 + 区间加"这套离线思想可以配合树状数组做到 `O((n+q) log n)`。

### 常数级优化（可选）

- 把 `ans.append` 换成预分配 `ans = [0] * m` 再按下标赋值：能省掉列表扩容，但可读性下降，实测收益有限，**不建议**。
- 循环内把 `nums` 绑定成局部名（如 `n_ = nums`）：Python 局部变量查找略快，10^5 规模收益微小。
- 用 `enumerate` 而非 `range(n)` + 下标访问：`enumerate` 更快且更 Pythonic，保持现状即可。

## 六、易错点与总结

### 易错点

- **漏写 `del`**（头号杀手）：`len(cnt)` 会变成"历史上出现过的不同值个数"，只增不减，答案整体虚高且不可逆。这也是为什么优化版改用**显式 `distinct` 变量**更稳妥 —— 它让"种类数"不再依赖 `dict` 的键数语义。
- **`append` 与"左出"的顺序写反**：`ans.append(len(cnt))` 必须在移出左端**之前**，否则记录的是长度 `k-1` 的窗口，答案偏小。
- **出窗下标写成 `i - k`**：正确是 `i - k + 1`（窗口右端为 `i`、长度 `k` 时，左端是 `i-k+1`）。错一位就崩。
- **`if i < k - 1: continue` 的位置**：必须放在 `ExistNum[j] += 1` **之后**。放在前面的话，前 `k-1` 个元素压根没进窗口，首个窗口就是错的。
- **套用"先铺满 `k` 个"的两段式模板时忘记 `k > n` 保护**：`for i in range(k)` 会 IndexError。本题约束保证了 `k <= n`，但换成 `enumerate` 单循环写法天然免疫这个风险。
- **误以为"个数"就是"窗口长度"**：只有全不重复时二者才相等，这类错误在 `[1,1,1,1,2,3,4], k=4` 这种样例上会立刻暴露。

### 题型套路沉淀

- **定长滑窗求"窗口内统计量"的通用骨架**（背下来）：

  ```text
  for i, x in enumerate(nums):
      1. 右端进窗，更新统计量
      2. if i >= k: 左端出窗（下标 i-k），回退统计量
      3. if i >= k - 1: 窗口长度达标，记录答案
  ```

  想合并成单段就用这套；想写得更传统、更好读就用"先铺满 `k` 个，再从 `i=k` 开始滑"的两段式。

- **"窗口内不同元素个数" 的万能钥匙是 `len(dict)`（或显式 `distinct` 变量）**，同型题一大把：
  - `1100. 长度为 K 的无重复字符子串`（本仓库同目录）—— 用 `len(cnt) == k` **判是否无重复**；
  - **本题 1852** —— 把 `len(cnt)` **直接作为答案**；
  - `3. 无重复字符的最长子串`、`340. 至多 K 个不同字符的最长子串`、`992. K 个不同整数的子数组`、`2461. 长度为 K 子数组中的最大和`。

- **1852 与 1100 是同一骨架的两种包装**，建议连着刷：先做 1100 建立"用 `len(cnt)` 判无重复"的感觉，再做 1852 把它变成"直接数出来"。两题的易错点（漏 `del`）完全同源。

- **值域有界 → 数组；值域无界 → 哈希表**。这是"计数表"类题目的第一决策分支，看到 `nums[i] <= 10^5` 就该条件反射想到能不能开数组。
