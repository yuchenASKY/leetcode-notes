# 2743. 计算没有重复字符的子字符串数量

> **难度**：中等
> **标签**：哈希表 · 字符串 · 滑动窗口
> **原题链接**：https://leetcode.cn/problems/count-substrings-without-repeating-character/

## 一、题目描述

给定一个只含小写英文字母的字符串 `s`。若 `s` 的某个子串中**每个字符最多出现一次**（即子串内部无重复字符），就称它为「特殊子串」。求 `s` 中特殊子串的总数。

注意两点：长度 1 的子串永远合法；"无重复"是对整个子串而言的，与字符是否相邻无关（如 `"p"` 与 `"pop"` 里的 `p` 不相邻，但 `"pop"` 依然不合法）。

### 示例

```text
输入：s = "abcd"
输出：10
解释：所有子串都合法 —— 长度 1 有 4 个、长度 2 有 3 个、长度 3 有 2 个、长度 4 有 1 个，共 4+3+2+1 = 10

输入：s = "abab"
输出：7
解释：长度 1 的 4 个 + 长度 2 的 "ab" / "ba" / "ab" 共 3 个 = 7；长度 ≥ 3 的子串都含重复字符
```

### 约束条件

- `1 <= s.length <= 10^5`
- `s` 仅由小写英文字母组成

> 注：本题是 Plus 题，公开题页与本次截图都不展示约束区。以上范围按题目标准约束记录，实际以官方题面为准。

## 二、解题思路

### 核心思想

**固定右端点做计数。** 维护一个始终不含重复字符的窗口 `[left, right]`，每轮把 `right` 往右推一格，然后数清"以 `right` 结尾的合法子串有多少个"——恰好就是 `right - left + 1`。

### 思路演进

1. **暴力解法**：枚举所有子串 `s[i..j]`（O(n²)），每个用 set 从头判重（O(n)）。总时间 **O(n³)**，n = 10^5 完全不可行。

2. **瓶颈定位**：慢在"对每个子串把判重重做一遍"。相邻子串之间共享大量信息 —— `s[i..j]` 与 `s[i..j+1]` 只差一个字符，却被当成全新的子串重新扫描。修复方向是**增量维护判重状态**：固定左端点 `i`，让 `j` 逐步右移、把字符塞进同一个 set，一遇重复就 `break`。时间降到 **O(n²)**，但每个 `i` 仍要独立"起跑"一遍。

3. **关键转化**：把枚举方向翻过来 —— **固定右端点**，让左端点自己滑。核心观察是下面这条单调性：

   > 若 `s[x..right]` 无重复、且 `x ≤ y ≤ right`，则 `s[y..right]` 也无重复（它是前者的子串）。
   > 反过来，若 `s[x..right]` 含重复，那么任何 `x' < x` 得到的都是它的**超串**，必然同样含重复。

   ⇒ 固定 `right` 时，合法左端点恰好构成一段**连续后缀区间** `{left, left+1, ..., right}`；并且随着 `right` 右移，`left` 只会增大、**永远不回退**。这正是双指针/滑动窗口能成立的根本原因（前提一旦不满足，就得换结构）。

4. **最优解**：把 `left` 一起维护成滑动窗口边界。每轮就三步 —— 把 `s[right]` 纳入窗口、必要时右移 `left` 直到窗口重新合法、累加 `right - left + 1`。`left` 全程单调右移，总移动量 ≤ n，因此整体 **O(n)**。

### 关键点

- **判据**：窗口 `[left, right]` 合法 ⟺ 窗口内每个字符的出现次数都 ≤ 1。
- **"违规量"恒为 1，"要挪的格数"不一定**：每轮只加入 1 个字符，而加入前窗口是合法的 ⇒ 唯一可能超限的就是新加入的那个字符，且它的计数恰好变成 2。但要消除这 1 个违规，需要把 `left` 一直推到"这个字符上一次出现的位置 + 1"——**可能一次要挪好几格**。这是本题最容易做错的一点（见第六节的最小反例）。
- **累加口径**：以 `right` 结尾的合法子串，左端点可以取 `left..right` 中任意一个，共 `right - left + 1` 个；每个子串按自己的右端点**唯一归属**某一轮 ⇒ 不重不漏。
- 窗口长度天然 **≤ 26**（字符集只有 26 个小写字母），这给"单步最多挪几格"提供了常数上界（≤ 25），也是空间复杂度能算 O(1) 的原因。

## 三、代码实现

### 最终代码

> 截图中代码起于 `class Solution:`，没有 import（LeetCode 已预置 `collections`）。这里补上 `from collections import defaultdict`，其余与截图逐行一致。

```python
from collections import defaultdict


class Solution:
    def numberOfSpecialSubstrings(self, s: str) -> int:
        ans = left = 0                  # left：窗口左边界；ans：累计答案
        cnt = defaultdict(int)          # 窗口内各字符的出现次数
        for right, j in enumerate(s):
            cnt[j] += 1                 # 把 s[right] 纳入窗口
            while cnt[j] >= 2:          # 加入前窗口合法 ⇒ 只有新字符可能超限
                cnt[s[left]] -= 1       # 从左侧逐个移出，直到那个重复被清掉
                left += 1
            ans += right - left + 1     # 以 right 结尾的合法子串数
        return ans
```

**正确性（不变量 + 归纳）**

- 不变量：**每轮 `while` 结束后，`s[left..right]` 内无重复字符。**
- 归纳步：设上轮结束时 `s[left..right-1]` 无重复，本轮加入 `c = s[right]`：
  - 若 `c` 此前不在窗口内，`cnt[c]` 由 0 变 1，`while` 条件不成立，窗口仍合法；
  - 若 `c` 出现过，`cnt[c]` 变成 2，而窗口中**其余**字符的计数仍都是 1。`while` 每次从左侧删掉一个字符并回退其计数：删到旧的那个 `c` 时 `cnt[c]` 回落到 1、循环退出。删除过程中不会引入新的违规（其余字符本来就没超限）⇒ 结束时窗口重新合法。
- 终态即答案：每轮累加的 `right - left + 1`，正好是 `s[left..right]` 的全部非空后缀子串（它们都无重复）；而左端点 `< left` 的任何子串必含重复（否则 `left` 不会停在这里）。所有合法子串按右端点被完整计入且只计一次。
- `left` 单调性：只在 `while` 里自增、永不回退 ⇒ 总移动量 ≤ n。

## 四、复杂度分析

| 版本 | 时间复杂度 | 空间复杂度 |
| :--- | :--- | :--- |
| **最终代码（截图原版）** | O(n) 均摊 | O(26) = O(1) |
| 暴力（枚举子串 + set 从头判重） | O(n³) | O(n) |
| 暴力（固定左端 + 增量判重） | O(n²) | O(26) = O(1) |
| 理论下界 | Ω(n) | O(1) |

> 复杂度中的 n 指字符串 `s` 的长度。
>
> 时间：外层循环 n 次；`while` 虽内嵌，但 `left` 全程只自增、累计不超过 n 次 ⇒ 总操作数 ≤ 2n，均摊每轮 O(1)。
> 空间：字典的键只可能是 26 个小写字母之一，且窗口长度 ≤ 26 ⇒ 规模有常数上界。这是它算 O(1)（而非 O(n)）的原因。

## 五、优化评估

**结论**：时间复杂度已是理论下界（**不可能低于 O(n)** —— 任何算法都必须至少读一遍输入），但**常数项还有 2 倍以上的空间**，实测可压。

### 瓶颈分析

把 n = 10^5 时的每字符成本拆开看，原版的开销主要在三处：

1. `cnt[j] += 1` —— `defaultdict` 的哈希查找 + 自增 + 回写，比列表索引重；
2. `while cnt[j] >= 2` —— 每轮无条件一次条件判断；
3. 收缩时每格一次字典读写 + 一次 `s[left]` 下标访问（虽然总量摊还 O(1)，但常数不小）。

### 可优化空间

分两刀做，实测（n = 10^5，4 种输入场景轮转测量，各取 9 次最优）：

| 场景 | V1 截图原版 | V2 数组 + while | V3 last + 跳转 | 纯遍历参照 |
| :--- | ---: | ---: | ---: | ---: |
| 全 `'a'`（极端重复） | 21.5 ms | 18.7 ms | **10.5 ms** | 2.3 ms |
| 随机 2 字母 | 22.1 ms | 19.3 ms | **10.7 ms** | 2.3 ms |
| 随机 26 字母 | 23.1 ms | 19.7 ms | **9.8 ms** | 2.3 ms |
| 26 字母循环 | 22.3 ms | 18.7 ms | **10.3 ms** | 2.3 ms |
| **相对 V1 提速** | 1.00× | 1.14~1.19× | **2.04~2.36×** | — |

- **第一刀（字典 → 定长数组）只有约 1.15×**：说明 `cnt[j] += 1` 的哈希开销并不是主要成本（单字符字符串的哈希在 CPython 里有缓存）。
- **第二刀（逐格 `while` → "最后出现位置"精确跳转）才是大头，2.0~2.4×**：它把"收缩"从"逐格删除 + 每格一次条件判断"降成"一次数组比较 + 一次赋值"。
- **天花板在哪**：纯遍历（`for ch in s: pass`，什么都不算）耗时 2.3 ms，即 n = 10^5 下"不可去开销"约占 **10%（V1）/ 22%（V3）**。V3 余下的 78% 是它自己必须做的 `ord` / 数组读写 / 计数器更新 —— 在纯 Python 里已接近实际下界，再快只能靠 C 层实现。

### 优化代码

```python
class Solution:
    def numberOfSpecialSubstrings(self, s: str) -> int:
        last = [-1] * 26          # 各字符上一次出现的下标（-1 = 未出现）
        left = ans = 0
        base = ord('a')
        for right, ch in enumerate(s):
            i = ord(ch) - base
            if last[i] >= left:   # 该字符还在窗口内 ⇒ 左边界精确跳到它后面
                left = last[i] + 1
            last[i] = right
            ans += right - left + 1
        return ans
```

**优化理由**：由"加入前窗口合法"可知违规量恒为 1，于是根本不需要"逐格收缩到合法"这个循环 —— 直接把 `left` 一次跳到 `last[c] + 1` 即可。这一跳与逐格 `while` **逐轮状态完全等价**（跳完后窗口同样无重复、`left` 同样落在正确位置），只是把量级不定的挪动换成了 O(1) 查表。

> ⚠️ 别把"跳到 `last[i] + 1`"和"每轮最多挪 1 格"混为一谈：后者会让窗口短暂非法、答案偏大，见第六节。

### 常数级优化（可选）

- 用 `[0] * 128` 代替 `[-1] * 26` 可以省掉 `ord('a')` 的减法，但实测差异落在解释器开销的量级内，不值得牺牲可读性。
- `enumerate(s)` 比 `for i in range(len(s)): s[i]` 明显快，保持即可。

## 六、易错点与总结

### 易错点

- **❌ 把"收缩"写成"左边界每轮最多挪一格"。** 违规量恒为 1 **不等于** 只需要挪一格。实测搜索到的最小反例只有 3 个字符：

  ```text
  s = "abb"
  正确：a、b、b、ab → 4
  错解：处理到第二个 'b' 时只把 left 挪到 1，窗口变成 "bb"（依然非法），
        却仍按 right - left + 1 = 2 累加 → 得 5
  ```

  ⇒ 必须 `left = last[c] + 1`（精确跳到重复字符之后），而不是 `left += 1`。
- **`cnt[j] >= 2` 是"局部判据"**，它成立依赖一个前置条件：**加入 `s[right]` 之前窗口是合法的**。一旦别的写法破坏了"每轮窗口合法"，这个判据就发现不了上一轮残留的重复 —— 这正是上面那条错误写法的根源。
- **答案口径别混**：本题累加的是"以当前右端点结尾的合法子串数" `right - left + 1`。写成"只在窗口变长时累加"或"最后返回 `n - left`"都会错（后者是"最长窗口长度"那类题的口径，与本题的计数口径不是一回事）。
- 若把字典换成 `cnt = [0] * 26`，务必用 `ord(c) - ord('a')` 换算下标；直接用 `cnt[c]` 会 TypeError，用 `cnt[ord(c)]` 则需要长度 ≥ 123 的数组。

### 题型套路沉淀

- **固定右端点做计数**：凡是"统计满足某性质的子串/子数组**个数**"，先问"能不能按右端点一次性数清"。若该性质对左端点**后缀封闭**，那么"合法左端点构成连续区间 + `left` 单调不减"就成立，可以直接 `ans += right - left + 1`。
- **"窗口内部状态型" vs "两端点值型"**：本题的合法性由**窗口内所有字符的计数**共同决定（不是只看两端点的值），所以收缩靠维护计数并右移左边界，而不是"先排序、再证明最优解是连续区间"那一路 —— 两族的判据不能串用。
- **"最后出现位置"是收缩的通用加速器**：当"每轮只追加一个元素、违规量恒为 1"时，把逐格 `while` 换成 `left = max(left, last[x] + 1)` 是标准手法。状态从"窗口内计数表"退化成"每个元素的最后位置表"，逻辑等价、常数更小（本例实测 2 倍）。
- 同类窗口题之间的差异（"求最长"还是"求个数"、允许出现 k 次还是 1 次、按值判据还是按键数判据），请对照 `04-two-pointers` 目录下的其它笔记逐题自行推导，**不要跨题套用判据**。
