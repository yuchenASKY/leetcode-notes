# 3364. 最小正和子数组

> **难度**：简单
> **标签**：数组 · 前缀和 · 滑动窗口
> **原题链接**：https://leetcode.cn/problems/minimum-positive-sum-subarray/

---

## 一、题目描述

给定整数数组 `nums` 与整数 `l`、`r`，在所有**长度落在 `[l, r]` 闭区间内**的连续子数组中，找出**和为正**的那些，返回其中**最小的和**；若一个都不存在则返回 `-1`。

注意「子数组」要求连续且非空，而长度有上下界 —— 这两条约束同时存在，使它不能像普通的「最短正和子数组」那样用一个双指针单调推进解决。

### 示例

```text
示例 1：
输入：nums = [3, -2, 1, 4], l = 2, r = 3
输出：1
解释：合法子数组有 [3,-2]=1、[3,-2,1]=2、[-2,1,4]=3、[1,4]=5，其中最小正和为 1。

示例 2：
输入：nums = [-2, 2, -3, 1], l = 2, r = 3
输出：-1
解释：长度 2 的和为 0、-1、-2，长度 3 的和为 -3、0，均非正，故返回 -1。

示例 3：
输入：nums = [1, 2, 3, 4], l = 2, r = 4
输出：3
解释：[1,2] 长度为 2、和为 3，是所有正和中最小者。
```

### 约束条件

- `1 <= nums.length <= 100`
- `1 <= l <= r <= nums.length`
- `-1000 <= nums[i] <= 1000`

## 二、解题思路

### 核心思想

**前缀和把「区间和」变成「两点之差」，于是「固定右端点、在合法下标窗口里找最优左端点」这件事，可以交给一个支持二分的有序集合。** 求最小正差 = 求「严格小于 `s[j]` 的最大前缀值」。

### 思路演进

1. **暴力解法**：先求前缀和 `s`，然后枚举长度 `len ∈ [l, r]` 与右端点，`O(1)` 算出每段和，保留最小正值。
   子数组总数为 `n·(r-l+1) ≤ n²`，n = 100 时也就 1 万次运算，**直接就能过**。复杂度 O(n²)。

2. **观察到**：枚举「长度」这一维其实是多余的。把子数组写成右开区间 `[i, j)`，则
   `sum(i, j) = s[j] - s[i]`，长度约束 `l ≤ j - i ≤ r` 等价于 `j - r ≤ i ≤ j - l`。
   也就是说：**长度约束只是把左端点 `i` 限制在一个长度为 `r-l+1` 的滑动窗口里**，不需要单独循环长度。

3. **再观察到**：固定 `j` 后，「让 `s[j] - s[i]` 为正且最小」等价于「在合法 `i` 中让 `s[i]` **尽可能大**，但仍**严格小于** `s[j]`」。这是一个纯粹的「前驱查询」（predecessor），不需要把窗口内所有 `i` 都扫一遍。

4. **优化为**：维护一个装着 `{s[i] | j-r ≤ i ≤ j-l}` 的**有序集合**。`j` 每右移一格，窗口只动一格 —— 加入 `s[j-l]`、移出 `s[j-r]`。每次用 `bisect_left(s[j])` 定位，取它前一个元素即为「小于 `s[j]` 的最大前缀」，两者之差就是一个候选答案。

### 关键点

- **长度约束靠 `i` 的取值范围表达**：`i ∈ [j-r, j-l]`，两端都包含。写成 `j-r-1` / `j-l-1` 会整体错一位。
- **必须是 `bisect_left` 且取 `k-1`**：`bisect_left` 落在第一个 `≥ s[j]` 的位置，所以 `k-1` 是严格小于 `s[j]` 的最大值，差值必为正；若用 `bisect_right`，取到的可能是相等的前缀，差值为 0，会被误当成合法答案。
- **三段顺序不能换：先 `add`、再查询、最后 `remove`**。当 `l == r` 时 `s[j-l]` 与 `s[j-r]` 是同一个元素 —— 先加后删刚好「用完就扔」，一旦把 `remove` 提前，就会去删一个还没加进去的元素而直接抛异常。
- `k == 0` 表示窗口里没有比 `s[j]` 更小的前缀，此时无候选，必须跳过。
- 无解返回 `-1`，不能把 `inf` 原样返回。

## 三、代码实现

### 最终代码

> 截图里的代码没有写 import，已按 LeetCode 运行环境补齐：`accumulate`（`itertools`）、`SortedList`（`sortedcontainers`）、`inf`（`math`）、`List`（`typing`）。

```python
from itertools import accumulate
from math import inf
from typing import List
from sortedcontainers import SortedList


class Solution:
    def minimumSumSubarray(self, nums: List[int], l: int, r: int) -> int:
        ans = inf
        s = list(accumulate(nums, initial=0))   # s[j] = nums[0..j-1] 的和
        sl = SortedList()                       # 窗口内 {s[i] | j-r <= i <= j-l}

        for j in range(l, len(nums) + 1):
            sl.add(s[j - l])                    # 1. 加入新的左端点 i = j-l
            k = sl.bisect_left(s[j])            # 2. 第一个 >= s[j] 的位置
            if k:                               #    存在严格小于 s[j] 的前缀
                ans = min(ans, s[j] - sl[k - 1])#    取最大的那个，差即候选正和
            if j >= r:                          # 3. 右端点继续走，i = j-r 出窗
                sl.remove(s[j - r])

        return -1 if ans == inf else ans
```

## 四、复杂度分析

| 版本 | 时间复杂度 | 空间复杂度 |
| :--- | :--- | :--- |
| **最终代码** | O(n√n) | O(n) |
| 朴素解法（枚举长度 + 前缀和） | O(n²) | O(n) |
| 理论下界 | O(n) | O(n) |

> 复杂度中的 n 指数组 `nums` 的长度；`r - l + 1` 为合法长度区间的宽度。
> 最终代码里 `SortedList` 的 `add` / `remove` 是分块结构，单次 O(√n)，`bisect_left` 单次 O(log n)，循环 n 次，故整体 O(n√n)。

## 五、优化评估

**结论**：**本题约束下属于「做过头了」** —— n ≤ 100 时朴素 O(n²) 完全够用，当前解法的价值在于它能扛住 `n` 到 10⁵ 量级的数据。

### 瓶颈分析

时间主要花在 `SortedList` 的两次分块增删上（每次 O(√n)），二分本身只占 O(log n)。空间上是前缀和数组与有序集合两份 O(n) 开销。

### 可优化空间

- **对本题而言没有优化必要，反而应该「降级」**：n ≤ 100 时，`O(n²)` 的朴素解常数更小、代码更短、不依赖第三方库（`sortedcontainers` 不在标准库里，面试或某些判题环境未必可用）。
- **若数据规模放大到 10⁵**，朴素解会退化到 10¹⁰ 量级、彻底不可行；此时「前缀和 + 滑动窗口 + 有序集合」是必要路线，因为每个右端点都要在 O(r-l) 个前缀值里找前驱，线性扫描不可接受。
- 换句话说，**这题的难度感来自数据规模，而不是思路本身**：约束是 n ≤ 100，所以官方给的标签里「简单」是站得住的。

### 优化代码

以下是**贴合本题约束**的写法（去掉有序集合，直接双重枚举），在 n ≤ 100 下更快、更稳：

```python
from itertools import accumulate
from typing import List


class Solution:
    def minimumSumSubarray(self, nums: List[int], l: int, r: int) -> int:
        s = list(accumulate(nums, initial=0))
        n = len(nums)
        ans = float("inf")
        for length in range(l, r + 1):
            for i in range(0, n - length + 1):
                total = s[i + length] - s[i]
                if 0 < total < ans:
                    ans = total
                    if ans == 1:            # 整数正和不可能比 1 更小
                        return 1
        return -1 if ans == float("inf") else ans
```

**优化理由**：本题合法子数组至多约 5000 个（n = 100 时），枚举的常数开销远小于有序集合的分块维护；`ans == 1` 提前退出进一步砍掉大量无意义枚举。代价是复杂度从 O(n√n) 退回 O(n²) —— 在本题约束内没有损失。

### 常数级优化（可选）

- `if k:` 拦掉空候选，避免 `sl[-1]` 取到窗口最大值这种「看似合法、实则反了」的错误。
- 把 `s[j]` 提成局部变量 `sj = s[j]`，可省掉循环体内的两次列表索引。
- `accumulate(nums, initial=0)` 走的是 C 层实现，比自己写 `for` 循环累加前缀和简洁且更快。

## 六、易错点与总结

### 易错点

- **加 / 查 / 删的顺序写反**：`l == r` 时 `s[j-l]` 与 `s[j-r]` 是同一个值，先把 `remove` 提到查询前会去删一个尚未加入的元素（或删掉刚加入的那个），直接抛 `ValueError`。
- **用 `bisect_right` 或取 `sl[k]`**：会拿到等于 `s[j]` 的前缀，差值 0 被当成答案，输出 0 而非正数。
- **窗口边界写错**：`i` 的下界是 `j - r`（不是 `j - r - 1`），上界是 `j - l`（不是 `j - l + 1`）。偏一位会漏掉长度恰为 `l` 或 `r` 的子数组。
- **无解时返回 `inf` / 大数**：题目要求返回 `-1`，需显式转换。
- **忘记 import**：`SortedList` 来自 `sortedcontainers`，`accumulate` 来自 `itertools`，`inf` 来自 `math` —— 三者都不是内置。
- **误以为可以纯双指针滑动窗口**：数组有负数，窗口和随右端点移动不单调，「右移右端点就一定能变大/变小」的前提不成立，普通的双指针在这里是错的。

### 题型套路沉淀

- **子数组和 + 长度受限 + 求极值** → 固定「前缀和两点差」视角：`sum(i,j) = s[j] - s[i]`，长度约束转化为 `i` 的取值范围，问题随即变成「在滑动的下标窗口里对前缀值做有序查询」。
- **「最小正差」= 前驱查询**：`> 0` 的最小差值，等价于「严格小于当前值的最大值」。凡出现这类表述，优先想二分 / 有序集合，而不是遍历。
- **窗口维护的三段式模板**（加入 → 查询 → 弹出）适用于所有「下标窗口 + 有序容器」的组合，弹窗方向与 `l`、`r` 两个边界一一对应，务必先在本子上标出 `i` 的闭区间再写代码。
- 先看数据范围再选解法：`n ≤ 100` 就老实写 O(n²)，不要为了复杂度好看引入第三方有序结构 —— 这是本题最实际的经验。
