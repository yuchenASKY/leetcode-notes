## 一、题目描述

社媒上有 `n` 个用户，`ages[i]` 是第 `i` 个人的年龄。若下列任意一条成立，则 `x` **不会**给 `y`（`x != y`）发好友请求：

1. `ages[y] <= 0.5 * ages[x] + 7`
2. `ages[y] > ages[x]`
3. `ages[y] > 100 && ages[x] < 100`

否则 `x` 会给 `y` 发一条请求。请求不必互相发送，且没人会给自己发。求请求总数。

### 示例

```text
示例 1：输入 ages = [16,16]                   输出 2      （两人互发）
示例 2：输入 ages = [16,17,18]                输出 2      （17->16, 18->17）
示例 3：输入 ages = [20,30,100,110,120]       输出 3      （110->100, 120->110, 120->100）
```

### 约束条件

- `n == ages.length`
- `1 <= n <= 2 * 10^4`
- `1 <= ages[i] <= 120`

## 二、解题思路

### 核心思想

**把「对人的判断」换成「对年龄的判断」，再用一个左指针维护合法年龄区间的下界。**

三条禁令取反后，「`x` 可以发给 `y`」等价于：

```text
0.5 * ages[x] + 7  <  ages[y]  <=  ages[x]          （条件 1 与条件 2 取反）
```

即**对固定的 `x`，合法接收者的年龄是一个连续区间** `(0.5x + 7, x]`。而年龄值域只有 120 ⇒ 用计数数组代替排序，然后让 `age_x` 从小到大扫过所有桶；区间的**右端天然就是 `age_x` 本身**（扫到哪，条件 2 就自动对哪一段满足），只需用一个左指针 `age_y` 维护下界。

### 思路演进

1. **朴素解**：双重循环枚举所有有序人对 `(i, j)`（`i != j`），把三条禁令逐条判一遍，全不成立就 `ans += 1`。时间 O(n²)，n = 2×10⁴ 时是 4×10⁸ 次判定 —— 在 Python 里必然超时；空间 O(1)。

2. **瓶颈定位**：慢的根因不是「判定太复杂」，而是**判定的结果重复算了**。三条禁令只依赖 `(ages[x], ages[y])` 这一对**数值**，与「是谁」无关。于是同一个年龄对 `(a, b)` 被反复判定了 `cnt[a] * cnt[b]` 次 —— 而不同的年龄对最多只有 120×120 种。**输入是 2×10⁴ 个人，状态空间却只有 120 个年龄**，这就是可压缩的地方。

3. **关键转化**：把「枚举人」换成「枚举年龄」。
   - 用 `cnt[age]` 做值域桶，O(n) 建表；
   - 对每个 `age_x`，合法 `age_y` 落在 **`(0.5 * age_x + 7, age_x]`** 这个连续区间里；
   - 右端 `age_x` 固定为当前扫到的桶 ⇒ **条件 2（`ages[y] <= ages[x]`）被窗口的右端自动满足**，不用额外判断；
   - 下界 `0.5 * age_x + 7` 随 `age_x` **单调不减** ⇒ 左指针只需单向前进，扫一遍 O(120) 即可。

4. **最优解**：`cnt_window` 维护「当前窗口内的总人数」，扫到年龄 `age_x` 时该年龄有 `c` 人，每人可发给窗口内除自己以外的 `cnt_window - 1` 人，贡献 `c * (cnt_window - 1) = c * cnt_window - c`。总时间 O(n + 120)，空间 O(120)。

### 关键点

#### ① 条件 3 是**冗余**的（它被条件 2 蕴含）

设条件 2 已成立，即 `ages[y] <= ages[x]`：

- 若 `ages[x] < 100`，则 `ages[y] <= ages[x] < 100` ⇒ 「`ages[y] > 100`」为假 ⇒ 条件 3 不成立；
- 若 `ages[x] >= 100`，则「`ages[x] < 100`」为假 ⇒ 条件 3 不成立。

两种情形下条件 3 都恒为假 ⇒ **只要条件 2 成立，条件 3 就永远不起作用**。所以窗口内不需要为它做任何特判。

> 注意这只是「在已经用条件 2 筛过」的前提下成立。若换一套口径（比如按年龄升序但不以 `age_x` 作右端），条件 3 就未必冗余 —— **不能无条件地把它划掉**。本次用两个只在条件 3 上不同的二分实现互相对拍，结果恒等，等于把这个推导落实成了事实（见 §七）。

#### ② 只有 `age_x >= 15` 的人才可能发出请求

合法区间 `(0.5x + 7, x]` 非空 ⟺ `x > 0.5x + 7` ⟺ `x > 14`。所以 `age_x <= 14` 的桶贡献恒为 0，且此时连 `x` 自己都被挡在区间外（`x <= 0.5x + 7`）。

#### ③ 内层只需要一次 `if`，不需要 `while`

`age_x` 每轮只 +1，下界 `0.5 * age_x + 7` 每轮最多上升 0.5 ⇒ **`age_y` 每轮最多需要前进 1 格**：

```text
上一轮合法:  2 * age_y > age_x_old + 14   ⇒  2 * age_y >= age_x_new + 14
若本轮失效:  2 * age_y = age_x_new + 14  ⇒  2 * (age_y + 1) = age_x_new + 16 > age_x_new + 14
```

即「跳一格之后必定合法」。这里的 `if` 是**精确收缩**（与 `while` 逐格收缩逐轮状态完全等价），不是那种「每轮只挪一格」的近似写法；判断能否只跳一格，看的是下界的**增长率**，而不是元素个数。

#### ④ `if cnt_window:` 不是冗余守卫

见「六、易错点」第 1 条 —— 它挡的是 `age_x <= 14` 时 `cnt_window == 0` 却仍要 `- c` 的情况。实测删掉它会让 `ages = [1]` 返回 **−1**。

#### ⑤ 本题所属的判据族

窗口的合法性由**两端点的值**决定（`0.5 * age_x + 7 < age_y <= age_x`），而不是由窗口内部元素的统计量决定 —— 这是「排序 / 值域 + 双指针求合法区间」这一族，和「窗口内计数 / 种类数满足某约束」那一族的判据**不能串用**：本族的左指针移动量由图上的下界函数决定（本题可证最多 1 格，一般情形要用 `while`），后一族的左指针移动量由内部计数的变化量决定。本族里「窗口右端 = 当前枚举值」这一条尤其重要 —— 它一次性消掉了「`ages[y] <= ages[x]`」这个条件。

## 三、代码实现

### 最终代码

```python
from typing import List


class Solution:
    def numFriendRequests(self, ages: List[int]) -> int:
        cnt = [0] * 121
        for age in ages:
            cnt[age] += 1

        ans = cnt_window = age_y = 0
        for age_x, c in enumerate(cnt):
            cnt_window += c                       # 先把 age_x 这一桶纳入窗口
            if age_y * 2 <= age_x + 14:           # 条件 1 取反：2 * age_y > age_x + 14
                cnt_window -= cnt[age_y]          # 下界不合法，左端前移一格
                age_y += 1
            if cnt_window:                        # age_x <= 14 时窗口为空（cnt_window == 0）
                ans += c * cnt_window - c         # c * (cnt_window - 1)
        return ans
```

### 逐段对应关系

| 代码片段 | 对应的题面/推导 |
| :--- | :--- |
| `cnt = [0] * 121` + 计数循环 | 值域桶，`ages[i] <= 120` |
| `cnt_window += c` | 窗口右端固定在 `age_x` ⇒ 条件 2 自动满足 |
| `if age_y * 2 <= age_x + 14` | 条件 1 的取反式，用整数避免浮点边界 |
| `cnt_window -= cnt[age_y]; age_y += 1` | 下界单调不减 ⇒ 左端单向前进 |
| `if cnt_window` | `age_x <= 14` 时区间为空 |
| `ans += c * cnt_window - c` | 每个 `x` 少算一个「自己」 |

## 四、复杂度分析

| 版本 | 时间复杂度 | 空间复杂度 |
| :--- | :--- | :--- |
| **最终代码** | O(n + A) | O(A) |
| 排序 + 双指针 / 二分（等价路线） | O(n log n) | O(1)（原地排序）/ O(log n)（栈） |
| 朴素双重循环 | O(n²) | O(1) |
| 理论下界 | Ω(n) | O(1) |

> 复杂度中的 `n` 是 `ages` 的长度；`A` 是年龄值域上界（本题 `A = 121`，为**与 `n` 无关的常数**，故 O(A) 等价于 O(1)，O(n + A) 等价于 O(n)）。
>
> 最终代码的 O(n) 就是下界：任何解法都必须至少读一遍输入（否则可能漏掉全部由某个年龄贡献的请求）。答案本身可以大到 Θ(n²)（如 `n = 2×10⁴`、全为同一合法年龄时约 4×10⁸ 条请求），但**求和并不需要按对枚举** —— 这是这题能压到 O(n) 的关键。

## 五、优化评估

**结论**：**已是最优**，且常数层面也几乎贴地 —— 滑窗那部分开销只占整体耗时的 **1% ~ 3%**。唯一看起来「能省」的改动（缩短桶扫描范围）实测是**负优化**。

### 瓶颈分析

时间只有两段：

1. O(n) 的计数循环 —— **绝对主体**；
2. O(121) 的滑窗扫描 —— 固定 106 轮有效轮次，与 `n` 无关。

微基准直接量化了占比（`n = 2×10⁴`，7 轮轮转取最优，单位 ms）：

| 变体 | 随机 1..120 | 低龄 1..14 | 高龄 100..120 | 值域集中 15..40 |
| :--- | ---: | ---: | ---: | ---: |
| 纯计数循环（基线） | 0.686 | 0.771 | 0.754 | 0.742 |
| **A 截图原版** | **0.702** | **0.782** | **0.773** | **0.755** |
| A 相对基线 | 1.02× | 1.01× | 1.02× | 1.02× |

⇒ 即使把滑窗整段砍成 0 耗时，最多也只能提速约 2%。**优化空间的天花板就在这里。**

空间上是 `O(121)` 的定长数组，与 `n` 无关：因为年龄值域是题面给的常数，而每个年龄的人数必须知道（否则无法 O(1) 算出贡献），所以这个数组不可省。

### 为什么不可能更好

- **时间**：Ω(n) 的下界由「必须读入全部输入」给出，当前代码正好达到。
- **空间**：必须为每个年龄保存人数（或等价的排序后下标），值域 120 是常数 ⇒ O(121) 已达下界。
- **换路线也不占优**：见下表的 C 变体（前缀和 + 按人遍历）虽然也是 O(n)，却慢 1.5× ~ 3.4× —— 它把 O(n) 的 Python 层循环保留了下来，而滑窗版本把这部分换成了 121 轮定长迭代。

### 微基准：等价改法与负优化（同一批数据、同一轮次）

| 变体 | 相对纯计数基线的倍数（四档场景） | 结论 |
| :--- | :--- | :--- |
| A2 删掉 `if cnt_window:` 守卫 | 1.01× ~ 1.02× | ❌ **错误**，`ages = [1]` 返回 −1；见 §六 |
| A3 把守卫换成 `if age_x > 14:` | 1.01× ~ 1.02× | ✅ 等价，但**不更快**（在噪声内） |
| B1 `enumerate(cnt)` → `range(121)` | 1.01× | ✅ 等价，无差别 |
| B2 计数循环里顺手取 `max(ages)` | **1.30× ~ 1.34×** | ⚠️ **负优化** —— 唯一的退化来源 |
| ~~B = B1 + B2（把扫描上界收到 `max(ages)`）~~ | ~~1.29× ~ 1.34×~~ | ⚠️ **负优化**：省下的是空转的 121 轮（纳秒级），付出的是 n 次额外比较 |
| C 前缀和 + 按人遍历 | 1.55× ~ 3.38× | ⚠️ 等价但更慢 |
| D 前缀和 + 按桶遍历 | 1.01× ~ 1.03× | ✅ 等价，与 A 持平 |

三条要记的：

- **「缩短扫描范围」看着诱人，实则倒亏**：`max(ages)` 要在 O(n) 的计数循环里多带一次比较与赋值（B2 单独就是 1.30× 的退化），而省掉的是空桶上极廉价的一次循环体。**先量清「省掉的东西有多贵」，再决定要不要为它付出 O(n) 的代价。**
- **B1/B2 必须拆开归因**：合起来看（B）只是「慢了 1.3×」，拆开才知道锅全在 B2，`range` 与 `enumerate` 在 121 轮的量级上测不出差别。做常数对比时，把合并改动一起上会得出错误归因。
- **C / D 的对比说明「O(n) 的 Python 层循环」才是贵的**：两者都是前缀和、复杂度都是 O(n)，但 C 把循环放在 `n` 上、D 放在 121 上，差 3 倍左右。

### 优化代码

无可优化项。A3 与 D 是两种等价改写，实测均**不产生收益**，因此保留原始形态：

```python
# 等价改法示例（不推荐替换，仅供理解）
# A3：把 "事后判断窗口为空" 换成 "事前判断年龄档"
#     —— 依据：age_x <= 14 时必有 cnt_window == 0，age_x >= 15 时必有 cnt_window >= c
# D ：前缀和 + 按桶遍历，121 轮 O(1) 查表，不维护 cnt_window
```

**优化理由**：三种写法时间同为 O(n + 121)、空间同为 O(121)，实测差异在 1% ~ 3% 以内，属于噪声量级 —— 没有理由用可读性更差、且需要额外论证正确性的版本来替换当前代码。

## 六、易错点与总结

### 易错点

1. **把 `if cnt_window:` 当成冗余守卫删掉 —— 这是本题最大的坑。**
   它挡的是 `age_x <= 14` 的桶：那时合法区间 `(0.5x + 7, x]` 为空，连 `x` 自己都被左指针移出了窗口，`cnt_window == 0`；此时若仍然执行 `ans += c * cnt_window - c`，就会**减去** `c`（该年龄的人数），凭空产生负贡献。
   - 实测删掉它：30 组随机对拍错 **14 组**；
   - **最小反例 `ages = [1]`**：真值 0、实得 **−1**（差值恰为该年龄人数）。
   - ⇒ 答案出现**负数**，就是这类「守卫被当成冗余删掉」的信号。
   - 顺带注意 `if age_x > 14:` 是与它等价的另一种写法（`age_x >= 15` 时必有 `cnt_window >= c`），但要理解成「事前判定年龄档」而不是「随手加的特判」。

2. **`ans += c * cnt_window - c` 里的 `- c` 不能写成 `- 1`**：同一年龄可能有 `c` 个人，每个 `x` 都要少算自己那一条，所以是减去 `c`（等价于每人的 `cnt_window - 1` 乘以人数）。

3. **`cnt_window` 加在判断之前**：必须先把 `age_x` 这一桶纳入窗口，再检查下界。反过来写的话，`age_x` 自己那一桶会被漏掉或错移。

4. **条件 1 用整数式 `2 * age_y <= age_x + 14`**：与题面 `age_y <= 0.5 * age_x + 7` 等价（两边乘 2）。写成浮点虽然本题（`.5` 可被二进制精确表示）不会出错，但整数式没有任何边界风险。

5. **别用 `while` 收缩左端然后担心复杂度**：本题左端每轮最多前进 1 格（见 §二 关键点 ③），写成 `while` 也不会错，只是多做几次条件判断；反过来说，**任何一轮让 `age_y` 前进超过 1 格的写法都是错的**（意味着窗口左端越过了它该在的位置）。

6. **答案规模**：`n = 2×10⁴` 时可达到约 4×10⁸，接近 32 位有符号上限（2.1×10⁹），Python 无溢出问题但心里要有数。

### 题型套路沉淀

- **值域小 ⇒ 桶计数**：当「判定结果只依赖元素的值」且值域很小（本题 120）时，把 O(n²) 的「枚举对」换成 O(A) 的「枚举值域 + 一个区间」是通用降维手法。识别信号：题面同时出现「两个人/两个元素」和「值域 ≤ 10^5 甚至 ≤ 120」。
- **「窗口右端 = 当前枚举值」的妙用**：当合法性里正好含一条「`y <= x`」型条件时，把枚举顺序定成从小到大、让窗口右端就是当前值，这条条件就**自动消失**，不用进判据。
- **左指针步长看下界函数的增长率**：`if`（精确跳一格）还是 `while`（逐步收缩），判据是「枚举值每前进 1 时，合法下界最多上升多少」，不是「元素个数的增减」。
- **判断某个守卫/特判是否冗余，用「删掉再对拍 + 搜最小反例」**：本题的守卫只在 `age_x <= 14` 这一小段输入上起作用，随机用例里有相当概率撞不到（实测 30 组里能撞到 14 组是靠刻意混入了低龄档），必须专门构造小值域用例才有说服力。
