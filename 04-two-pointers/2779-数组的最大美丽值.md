# 2779. 数组的最大美丽值

> **难度**：中等
> **标签**：数组 · 排序 · 滑动窗口 · 双指针 · 二分查找
> **原题链接**：https://leetcode.cn/problems/maximum-beauty-of-an-array-after-applying-operation/

---

## 一、题目描述

给定整数数组 `nums` 和非负整数 `k`。每个下标 `i` **最多被操作一次**，操作后 `nums[i]` 可以取 `[nums[i] - k, nums[i] + k]` 内的**任意整数**（本来的值也在范围里，故"不操作"也算一种选择）。

"美丽值"= 数组中**由相等元素组成的最长子序列**的长度（子序列只保序、不要求相邻）。问任意次操作后能取得的最大美丽值。

### 示例

```text
示例 1
输入：nums = [4,6,1,2], k = 2
输出：3
解释：把下标 1 的 6 变成 4（[4,8] 内），再把下标 3 的 2 变成 4（[0,4] 内），
      得到 [4,4,1,4]，可取下标 0、1、3 这三个相等的 4 作为子序列。
      下标 2 的 1 无法参与（[−1,3] 与 {4} 无交集），所以答案是 3 而不是 4。

示例 2
输入：nums = [1,1,1,1], k = 10
输出：4
解释：不需要任何操作，整个数组本来就相等。
```

### 约束条件

- `1 <= nums.length <= 10^5`
- `0 <= nums[i], k <= 10^5`

## 二、解题思路

### 核心思想

**子序列要求的是"值相等"，与元素在原数组的先后位置无关；而每个元素能取的值是一条长度为 `2k` 的区间。** 于是问题等价于：在数轴上找一个点（或一段窗口），使尽量多的元素区间覆盖它 ⇔ 排序后找一段**最长连续区间，且首尾之差 ≤ 2k**。

### 思路演进

1. **暴力解法（直接照题意枚举）**：枚举所有子序列，检查这一组下标能否同时变成同一个值 —— 一组区间公共交非空 ⟺ `max - min <= 2k`。复杂度 O(2^n · n)，n = 10^5 时完全不可行；退一步的版本是枚举目标值 `t`（只需取 `nums[i] - k` 这类端点），对每个 `t` 扫一遍数组数覆盖数 —— O(n²)，10^5 规模下 10^10 次操作，同样不可行。

2. **瓶颈定位**：两个暴力都卡在"组合爆炸 / 重复扫描"，但根因是同一个 —— **没有利用 '值' 这一个维度上的结构**。元素能不能凑成一组，只取决于它们的**值**，与它们在下标轴上排在哪毫无关系；而"哪些值能凑到一起"在数轴上是严格局部的（凑成一组 ⟺ 值域跨度 ≤ 2k）。暴力却在**下标**空间里枚举组合，白白丢掉了这个结构。

3. **关键转化**：
   - 一维区间的公共交非空 ⟺ `max - min <= 2k`（一维 Helly 性质）。所以"从数组里挑一个子序列" → **"在数轴上取一段长度为 2k 的区间，数落在里面的元素个数"**。
   - 但"落在值域区间里的元素"在原数组里是散落的。**排序**一次，就抹平了这个差异：排序后值连续 = 下标连续，"值在 `[lo, lo+2k]` 内的元素"恰好是**一段连续子数组**。子序列只要求保序，任意排序都找得到对应的合法子序列，所以重排数组**不损失任何解**。
   - 于是问题退化成一句：**排序后，找满足 `nums[r] - nums[l] <= 2k` 的最长连续区间长度。**

4. **最优解**：排序后固定右端 `r`，满足条件的左端是一段前缀 `[0, l_r]`，且 `l_r` 随 `r` **单调不减**（`nums` 递增 ⇒ 右端变大时最小可行左端只会右移，不会左移）。⇒ 左指针全程只向一个方向走、总移动量 ≤ n，右指针走 n 步，合计**摊还 O(n)**。总复杂度由排序主导：O(n log n)。

### 关键点

- **判据**：窗口 `[l, r]` 合法 ⟺ `nums[r] - nums[l] <= 2k`。
- 这题属于「**合法性只由两端点的值决定**」这一判据族（排序后中间元素必然夹在两端之间），**不是**「窗口内部计数/求和」族（如"窗口内不同种类 ≤ K"）。两族的左指针行为、易错点都不一样，不能串用。
- 由两端点判据的直接推论：新加入 `nums[r]` 可能让窗口**一次违规很多** ⇒ 左端需要连续追赶多格 ⇒ 用 `while`。（后文常数级优化里会看到：这里其实允许连追多于 1 格，实测单轮最多 15 格。）
- `ans` 必须**每轮取 max**，不能等循环结束用 `n - left` 收尾 —— 原因见「易错点」，这是本题最值钱的一处。
- 左指针 `left` 恒满足 `left <= right`（`k >= 0` 时 `nums[right] > nums[right] + 2k` 永不成立），因此 `nums[left]` 不会越界、也不会负索引。

## 三、代码实现

### 最终代码

```python
from typing import List


class Solution:
    def maximumBeauty(self, nums: List[int], k: int) -> int:
        nums.sort()
        left = ans = 0
        for right, j in enumerate(nums):
            # 窗口合法性只看两端：保证 nums[right] - nums[left] <= 2 * k
            while j > nums[left] + 2 * k:
                left += 1
            ans = max(ans, right - left + 1)
        return ans
```

## 四、复杂度分析

| 版本 | 时间复杂度 | 空间复杂度 |
| :--- | :--- | :--- |
| **最终代码**（排序 + 双指针） | O(n log n) | O(1) 额外（排序本身 O(n)，Timsort 最坏） |
| 朴素解（枚举子序列） | O(2^n · n) | O(1) |
| 朴素解（枚举目标值 t + 扫描） | O(n²) | O(1) |
| 理论下界（比较模型） | Ω(n log n) | — |
| 值域计数版（见第五节） | O(n + V) | O(V) |

> 复杂度中的 n 指数组 `nums` 的长度；V 指值域上界（本题 `max(nums) + 1 <= 100001`）。

**下界为什么是 Ω(n log n)**：取 `k = 0`，答案退化为"数组中同一数值的最多出现次数"，于是"答案是否 ≥ 2"就等价于**判断数组是否存在重复元素**（element distinctness）。该问题在代数判定树模型下有 Ω(n log n) 下界 ⇒ 本题在这个模型下也不可能优于排序。**所以"排序 + 双指针"在比较模型下时间已是最优**，剩下的空间只能是常数层面或换模型（见第五节的值域计数）。

## 五、优化评估

**结论**：时间复杂度已是**比较模型下的下界**，无可压缩；但本题 `nums[i], k <= 10^5` 的值域上界给了**换模型**的机会 —— 用"值域计数 + 前缀和"替掉排序，实测 **1.46× ~ 4.15×**。同时实测证伪了一个"看起来更标准"的写法（每端二分）。

### 瓶颈分析

n = 10^5 实测拆分（9 轮取最优）：

| 场景 | 总耗时 | 其中 `sorted()` | 其中滑窗循环 |
| :--- | :--- | :--- | :--- |
| 随机 / 值域 ≈ 1e9 | 31.01 ms | 12.43 ms（40.1%） | 18.58 ms |
| 重复度高（值域 50） | 21.05 ms | 6.77 ms（32.2%） | 14.28 ms |
| 升序输入 | 18.12 ms | 0.74 ms（4.1%） | 17.38 ms |

⇒ 主要开销落在**纯 Python 的滑窗循环**（逐元素比较 + 指针推进），排序只占 4%~40%。想再快，要么压低循环常数，要么**换掉"逐元素比较"这件事本身**。

### 可优化空间

**(a) 被证伪的改法：排序 + 每题二分。** 两个变体对照，n = 10^5，9 轮轮转取最优（ms）：

| 场景 | 用户代码（双指针） | ~~排序 + `bisect` 找左端~~ | 实测倍率 |
| :--- | :--- | :--- | :--- |
| 随机 / 值域 ≈ 1e9 | 32.00 | 35.24 | 0.91× |
| 重复度高（值域 50） | 23.09 | 27.70 | 0.83× |
| k = 0 / 全不同 | 32.97 | 37.45 | 0.88× |
| 升序输入 | 27.18 | 28.27 | 0.96× |
| 降序输入 | 21.60 | 25.19 | 0.86× |
| 全相同 | 12.48 | 19.79 | 0.63× |

**"对每个右端点二分找左边界"看着是教科书式的 O(n log n)，实测却慢 4%~37%。** 原因：左指针的推进本来就是**摊还 O(1)**（全程只走 n 格），用 O(log n) 的 C 层二分去替代它，是用更大的常数换一个并不存在的量级收益。已被删除线保留，避免重犯。

**(b) 真正有效：值域计数 + 前缀和**（本题值域 ≤ 1e5 才成立）。n = 10^5，9 轮轮转取最优：

| 场景 | 用户代码 | 常数优化版 | 计数 + 前缀和 |
| :--- | :--- | :--- | :--- |
| 随机 / 值域 ≈ 1e5 | 31.03 ms | 28.72 ms（1.08×） | **17.80 ms（1.74×）** |
| 重复度高（值域 50） | 20.54 ms | 18.72 ms（1.10×） | **4.95 ms（4.15×）** |
| 值域 1e5 / k = 1e5 | 23.89 ms | 22.03 ms（1.08×） | **16.40 ms（1.46×）** |
| 全相同 | 10.63 ms | 8.92 ms（1.19×） | **5.05 ms（2.10×）** |

### 优化代码

**版本一：同算法的常数优化**（不依赖值域，通用；本机实测 1.04×~1.19×，升序场景另测到 1.51×）

```python
from typing import List


class Solution:
    def maximumBeauty(self, nums: List[int], k: int) -> int:
        a = sorted(nums)
        n = len(a)
        lim = 2 * k          # 常量提到循环外
        left = 0
        ans = 0
        for right in range(n):
            al = a[left] + lim          # 复用 al，避免每次重启 while 时重复算
            while a[right] > al:
                left += 1
                al = a[left] + lim
            w = right - left + 1
            if w > ans:                 # 用 if 替掉 max() 的函数调用
                ans = w
        return ans
```

**版本二：值域计数 + 前缀和**（本题最优实测写法，1.46×~4.15×）

```python
from itertools import accumulate
from typing import List


class Solution:
    def maximumBeauty(self, nums: List[int], k: int) -> int:
        # 值域 0..max(nums)，按值建桶
        M = max(nums) + 1
        cnt = [0] * M
        for x in nums:
            cnt[x] += 1
        # pre[i] = 值 < i 的元素个数，C 层 accumulate 完成
        pre = [0] + list(accumulate(cnt))
        lim = 2 * k
        ans = 0
        for lo in range(M):
            hi = lo + lim                      # 值窗口 [lo, lo + 2k]
            c = (pre[hi + 1] if hi < M else pre[M]) - pre[lo]
            if c > ans:
                ans = c
        return ans
```

**优化理由**：与第三节同一句等价式 —— 合法性只由"值的跨度 ≤ 2k"决定，**排序的作用仅仅是把近值聚拢**。既然值域只有 1e5，直接按值建桶即可跳过排序：`pre[hi+1] - pre[lo]` 一次 O(1) 得到"值落在 `[lo, lo+2k]` 的元素个数"，枚举左端取最大即为答案。复杂度 **O(n + V)**，且把逐元素比较换成了两个 C 层的线性扫描。

**前提与代价（务必写清）**：
1. 强依赖 `nums[i] >= 0` 且值域上界可控。若值域是 1e9，`cnt` 直接内存爆炸 ⇒ **不具泛化性**；面试/通用场合仍应给排序 + 滑窗。
2. 依赖 `itertools.accumulate` 的 C 实现。若手写纯 Python 前缀和循环，优势会明显缩水。
3. 实测 3000 组随机对拍 + 8 组边界（含 `k = 1e5` 越界分支、单元素、全 0）**偏差均为 0**，`hi` 越界的 `min` 处理正是这批边界测出来的。

### 常数级优化（可选）

- `max(ans, w)` → `if w > ans: ans = w`：每轮省一次函数调用，是上表"常数优化版"里贡献最大的一项。
- `enumerate(nums)` → `range(n)` + 下标访问：避免每轮解包元组。
- `2 * k` 提到循环外；`a[left] + lim` 缓存。
- **不要**为"省掉指针"改用 `collections.Counter` 或切片：切片会引入 O(窗口长) 的拷贝，而本题窗口可以很长（`k` 很大时窗口 ≈ n），是实打实的负优化。

## 六、易错点与总结

### 易错点

- **把答案写成"终值 `n - left`"（错得最隐蔽的一处）**。`while` 版是"收缩到合法为止"，一次可能连追多格 ⇒ 窗口长度序列**会下降** ⇒ 必须在每轮取 `max`，不能等循环结束收尾。
  - 全搜索空间穷举 78,120 组（n ≤ 6，值域 0..4，k ≤ 3）**错 17,403 组（22.3%）**；补充穷举 65,532 组（n ≤ 7，值域 0..3，k ≤ 2）错 18,132 组。
  - **最小反例 `nums = [0,0,1], k = 0`**：正确答案 2（两个 0），终值口径得 1。三元素即可复核。
  - 对照：如果把左指针换成 `if`（每轮最多挪一格），长度就单调不减，`max` 口径与终值口径**才**等价 —— 同一份四象限穷举里 `if` 两种口径都是 0 错。**会错的是"只换一半"**。
- **判据漏乘 2**：写成 `nums[right] - nums[left] > k`。两个元素要能变成同一个值，各自可动 `k`，条件是 `|a - b| <= 2k`。
- **误以为左指针每轮只挪一格**：实测（3000 组，n ≤ 60）单轮最多连追 **15 格**，平均每个输入左指针累计移动 22.66 格，约 20% 的轮次窗口长度会下降。
- **`k = 0` 不必特判**：退化成"最长等值连续段"，上面的代码自然成立（已用边界用例断言）。
- **截图来源的代码缺 `import`**：`from typing import List` 必须补，且要真的调用一次才算验证过（`exec` 只定义类不会报错）。
- **负索引**：`nums[left]` 中 `left <= right` 恒成立，无 `arr[-1]` 静默取尾部的风险。

### 题型套路沉淀

- **排序 + 两端判据滑窗**：只要窗口合法性**只依赖两端点的值**（排序后 `max - min` 就等于两端之差），标准动作是"右端单调右移、左端只增不减"，左端可能一次连追多格 ⇒ `while` + **每轮取 max**。
- **识别信号**："每个元素可以变成某个范围内的任意值"、"最多修改 k 次"、"最长子序列（不要求连续但有相等/跨度约束）" ⇒ 先想"**值域上取一段区间，数覆盖数**"，再想排序消掉下标维度。
- **一维区间公共交非空 ⟺ max − min ≤ 2k**（一维 Helly 性质）：把"选子序列"这类组合问题降成"数轴上取一段"的关键等价式。
- **与相邻判据族的分界**：本族（两端判据）与"窗口内部计数/求和"族（如"窗口内不同种类 ≤ K"、"窗口和 ≤ 预算"）**判据不同源**，左指针行为与易错点也不同，写代码时先把归属认准，别串用。
- **别把"摊还 O(1) 的指针推进"换成 O(log n) 的二分**：量级没变、常数更大，实测负优化（见第五节 a）。
