# 1695. 删除子数组的最大得分

> **难度**：中等
> **标签**：数组 · 哈希表 · 滑动窗口
> **原题链接**：https://leetcode.cn/problems/maximum-erasure-value/

---

## 一、题目描述

给定**正整数数组** `nums`，从中删掉一个元素**互不相同**的连续子数组（必须删一个、不能删空），得分 = 这个子数组各元素之和。求能拿到的最大得分。

### 示例

```text
示例 1
输入：nums = [4,2,4,5,6]
输出：17
解释：最优子数组是 [2,4,5,6]，和 17。（[4,5,6] 也合法，但和只有 15）

示例 2
输入：nums = [5,2,1,2,5,2,1,2,5]
输出：8
解释：最优子数组是 [5,2,1] 或 [1,2,5]，和都是 8。
```

### 约束条件

- `1 <= nums.length <= 10^5`
- `1 <= nums[i] <= 10^4`（**全部为正**，这条是解题的命门）

> **两条必须立刻记下的推论**：
> 1. **元素全为正 ⇒ 得分对"多包含元素"单调递增**。所以对每个右端 `r`，合法窗口里**最长的那一个就是和最大的那一个** —— 答案只需在所有"以某个 `r` 结尾的最长合法窗口"里取最大和，不必枚举非极长的合法窗口。这一条把后面的正确性论证砍掉一半。
> 2. **值域只有 `1..10⁴`** ⇒ "每个值上次出现的位置"可以用**定长数组**存，不必上哈希表（第五节的优化要用到）。

---

## 二、解题思路

### 核心思想

**变长滑动窗口 + 按值计数**：维持不变量「窗口 `[left, right]` 内所有元素互不相同」，右指针只进不退；一旦新加入的 `nums[right]` 与窗口内某元素重复，就把 `left` 右移直到重复消失。每轮用窗口和更新答案。

它和同目录的 `3. 无重复字符的最长子串` 是**同一条骨架**，只换了两处：

| | `3` / `3090` | **本题 1695** |
| :--- | :--- | :--- |
| 输入 | 字符串 | 正整数数组 |
| 窗口合法性 | 每个字符出现 ≤ k 次 | 每个值出现 ≤ 1 次 |
| **答案口径** | **窗口长度** | **窗口元素之和** ← 本笔记的重点在这一格 |

### 思路演进

1. **暴力解法**：枚举所有子数组 `(l, r)`，用 `set` 判重再求和 → O(n³)；用前缀和把求和压掉 → O(n²)。`n = 10^5` 时 O(n²) 是 10¹⁰ 量级，必然超时。

2. **瓶颈定位**：固定左端 `i`、右端一路向右扩，每个 `i` 都要重扫一遍 —— 重复枚举。而实际上：合法性对左端是**后缀封闭**的（`[l, r]` 合法 ⇒ `[l+1, r]` 也合法），所以对每个 `r` 只需要知道"最小的合法左端 `L(r)`"。更关键的是 **`L(r)` 关于 `r` 单调不减**：左端右移只会让"无重复"更容易满足。于是两个指针都只向右走，总移动量 O(n)。

3. **关键转化（把解法压成一句判据）**：

   > **窗口 `[l, r]` 合法 ⟺ 窗口内每个值的计数 ≤ 1** —— 一条**按值**的判据。

   它直接给出两个后果：
   - 违规只可能是"新加入的 `nums[r]` 把自己的计数从 1 变成 2"，**超出量恒为 1**，与窗口里其它元素无关；
   - 把 `left` 移到「`nums[r]` 上一次出现位置 + 1」处，违规就被一次性消除 —— 不需要通用的"一格一格挪"。

   ⚠️ 但要注意"超出量恒为 1"说的是**违规的量**，不是**左指针要挪的格数**：实测单步最多挪 **373 格**（`n = 10^5`、窗口顶到值域上界时平均 81 格）。这个区分是后文「`while` 能不能换 `if`」的分水岭。

4. **最优解**：两种等价写法 ——
   - **收缩版（用户版）**：`cnt` 计数表 + 运行和 `temp`，`while cnt[j] > 1` 逐格挪；
   - **跳转版**：记每个值上次出现的位置，`left = last[x] + 1` 一次跳到位，窗口和用**前缀和**差分算。

   两者**逐轮状态完全相同**：`left` 序列、窗口和序列、答案三者全等（穷举 38 万组 + `n = 2000` 随机 200 组，差异 0）。区别只在常数。

### 关键点

- **判据"按值"还是"按键数"，决定要不要 `del`**：本题用 `cnt[x] > 1`（按值），计数减到 0 留着键**完全无害**，所以用户版不写 `del` 是对的；对照 `904. 水果成篮` 的判据是 `len(cnt) > 2`（按键数），那里**必须** `del` 清掉归零的键，否则键数只增不减。
- **`while` 版每轮都把窗口收缩到合法为止**。本题答案是**求和**，这个性质不可让渡（第五节）。
- **`ans` 必须每轮更新**：窗口和序列不单调（`[4]`、`[4,2]` 之后遇到 `4` 会掉回来），只在循环外取最后一次必错。
- **正整数是前提，不是装饰**：推论 1 依赖它。放开到含负数，算法直接失效 —— 实测 `nums = [-1, 5]` 真答案 5、本解法给 4。
- 左指针总位移 ≤ n ⇒ 摊还 O(1)；**别用二分去替它**（`1208` 那轮实测过：O(log n) 替代摊还 O(1) 是负优化）。

## 三、代码实现

### 最终代码（用户提交版）

截图里的代码**缺两行 import**：`defaultdict` 来自 `collections`，本地复制必须补上（LeetCode 环境已内置 `List`，本地跑还要 `from typing import List`）。以下为补齐后的逐字版本：

```python
from collections import defaultdict
from typing import List


class Solution:
    def maximumUniqueSubarray(self, nums: List[int]) -> int:
        cnt = defaultdict(int)          # 窗口内各值的计数
        left = ans = temp = 0           # temp: 窗口内元素和
        for right, j in enumerate(nums):
            temp += j
            cnt[j] += 1
            while cnt[j] > 1:           # 只有 j 自己可能违规
                temp -= nums[left]
                cnt[nums[left]] -= 1    # 按值判据，不需要 del
                left += 1
            ans = max(ans, temp)        # 每轮都要更新
        return ans
```

**它好在哪**：`while cnt[j] > 1` 这个条件写得很省 —— 因为窗口在上一轮结束时已经合法，新元素是**唯一**可能的违规源，所以不必扫描整张计数表。循环体只有 4 次算术/查表，没有切片、没有 `find`、没有 `del`，比 `3 / 3090` 里那两版用户代码干净。

**它的代价**：`defaultdict` 的哈希开销；窗口长时 `while` 单步要挪几十上百格（实测平均 81、最多 373）；每轮一次 `max()` 调用；`enumerate` 拆出来的 `right` **一次都没用到**（窗口和靠累加，不是 `pre[right] - pre[left]`）。

## 四、复杂度分析

| 版本 | 时间复杂度 | 空间复杂度 |
| :--- | :--- | :--- |
| **最终代码（用户版）** | O(n) 摊还 | O(D) |
| 优化版 D（`last` 定长数组 + 前缀和） | O(n) | O(n) + O(M) |
| 优化版 C（`last` 字典 + 前缀和） | O(n) | O(n) + O(D) |
| 优化版 F（`set` + 运行和） | O(n) 摊还 | O(D) |
| 朴素解法（固定左端向右扩） | O(n²) | O(D) |
| 朴素解法（枚举子数组 + 判重求和） | O(n³) | O(n) |
| 理论下界 | **Ω(n)** | Ω(1)（"值域有界"口径） |

> 复杂度中的 `n` 指数组 `nums` 的长度；`D` 指扫描到的**不同取值个数**（≤ min(n, 10⁴)）；`M = 10⁴` 是值域上界。
>
> **时间下界 Ω(n)**：最坏情况下（整个数组互不相同）答案依赖**每一个**元素，任何算法都必须至少读一遍输入。
>
> **空间口径要说清**：用户版的 O(D) 是**随 `n` 增长**的（哈希表最多装 min(n, 10⁴) 个键）；"O(1) 额外空间"只在**把值域 10⁴ 视为常数**的意义下成立 —— 用定长数组替代哈希表即得（优化版 D 的 `last`）。值域一旦无界，O(D) 就压不掉。
>
> 用户版的摊还依据：`left` 整趟只向右推进，总位移 ≤ n（实测 `n = 10⁵` 各场景为 99,789 ~ 99,999），所以内层 `while` 的**总**迭代次数是 O(n) 而非 O(n²)。

## 五、优化评估

**结论**：时间已是理论下界 O(n)，**算法层面没有可优化空间** —— 用户版与最优写法（跳转版）**逐轮状态完全一致**。可做的是**常数级**优化：实测「`last` 数组 + 前缀和」快 **1.21~1.57×**，`set` 版快 **1.25~1.99×**（但不稳）。

### 瓶颈分析

**(1) 用户版每轮的固定成本**：`defaultdict` 一次取值 + 一次写入（两次哈希）、一次 `max()` 调用；`while` 内部每挪一格还要一次哈希读写 + 一次 `nums[left]` 索引。

**(2) `while` 单步要挪多少格 —— 这是"能不能换 `if`"的证据**（插桩实测，`n = 10⁵`）：

| 场景 | 收缩轮次占比 | 单步 ≥2 格占比 | 单步最多格数 | 平均格数 | 左指针总位移 |
| :--- | ---: | ---: | ---: | ---: | ---: |
| 1 种值（窗口恒 1） | 100.0% | 0.0% | 1 | 1.00 | 99,999 |
| 2 种值交替（窗口恒 2） | 75.0% | 25.0% | 2 | 1.33 | 99,999 |
| 10 种值随机 | 36.6% | 26.5% | 10 | 2.73 | 99,995 |
| 1000 种值随机 | 4.0% | 3.9% | 118 | 25.18 | 99,975 |
| 10⁴ 种值随机 | 1.3% | 1.2% | **373** | 79.64 | 99,789 |
| 10⁴ 值整块循环 | 1.2% | 1.2% | 339 | 81.41 | 99,975 |

⇒ ① 左指针总位移恒 ≤ n，摊还 O(1) 成立；② **单步可以要挪几百格**，所以"每轮只挪一格"的写法在这里连窗口合法性都保不住。

**(3) `right` 是死变量**：`enumerate` 拆出来的 `right` 全程未使用，换成 `for j in nums` 可省掉拆包。

### 可优化空间

**算法级：没有。** 跳转版与用户版的 `left`、窗口和、答案三个序列**逐轮全等**（穷举 38 万组 + 大随机 0 差异），所以"换成 `last` 数组 + 前缀和"只是**换实现**，不是换算法，上界仍是 O(n)。

**「把 `while` 换成 `if`」这个念头必须掐掉** —— 本仓库 `1208 / 904` 里的"平移版"（窗口只平移、不收缩到合法，答案取 `n - left`）在本题**不成立**，而且有**两条互相独立的原因**：

**原因 ①：判据不完整（局部判据 vs 整体判据）。**
`cnt[j] > 1` 只检查"新加入的那个元素自己"，**发现不了上一轮残留的重复**。穷举实测（值域 1..2 / 1..3，`n ≤ 9`）：

| 写法 | 收缩判据 | 答案口径 | 错误率 |
| :--- | :--- | :--- | ---: |
| 只挪一格 | `cnt[j] > 1`（只看新元素） | 长度 | **74.8% / 83.1%** |
| 只挪一格 | `len(cnt) < 窗口长度`（整体判据） | 长度 | **0%**（0 / 29,523） |
| `while` 逐格（用户版） | `cnt[j] > 1` | 长度 | 0% |

最小反例（长度口径）：`nums = [1,2,2,1]`，真值 2，只挪一格版给 **3**。
⇒ 值得记牢的是：**"无重复"这个家族本身是支持平移版的**（换成整体判据后 29,523 组全对）；错的是拿"只看新元素"的判据去驱动"只挪一格"。

**原因 ②：答案口径是求和，"长度单调"这根救命稻草不存在。**
平移版的正确性靠的是「左指针每轮最多进 1 格 ⇒ 窗口长度单调不减 ⇒ 终值就是历史上出现过的最大合法窗口长度」。这句话每一步都依赖**答案是长度**。本题答案是**和**，而平移版允许窗口短暂非法 —— **非法窗口的元素和可以超过任何合法子数组的和**。实测即使把判据换成正确的整体判据：

| 写法 | 答案口径 | 错误率（值域 1..2 / 1..3） | 最小反例 |
| :--- | :--- | ---: | :--- |
| 只挪一格（整体判据） | **求和** | **64.5% / 59.4%** | `nums = [1,2,2]`：真值 3，实得 **4** |
| `while` 逐格（用户版） | 求和 | **0%**（0 / 29,523） | — |

而且这不是本题家族的偶然：在 `1004` 那种"度量按元素可加"的家族里，平移版 **+ 长度口径**是 0 错（29,520 组），但把**同一个写法**的答案改成**求和**，立刻出现反例 —— 最小的是 `nums = [1,1,1,0,3], k = 0`（真值 3，实得 4）。

⇒ **一句话判据：只要答案口径不是"窗口长度"，平移版就没有"长度单调"这根救命稻草。** 本题的 `while` 是必需的。

### 优化代码

**版本 D —— 推荐（`last` 定长数组 + 前缀和，一次跳转）**

值域 `1..10⁴` 是题面硬约束，所以这里可以合法地用定长数组代替哈希表，并用前缀和一次性拿到跳转后的窗口和：

```python
from typing import List


class Solution:
    def maximumUniqueSubarray(self, nums: List[int]) -> int:
        n = len(nums)
        pre = [0] * (n + 1)
        for i, x in enumerate(nums):
            pre[i + 1] = pre[i] + x          # 前缀和
        last = [-1] * 10001                  # 每个值上次出现的下标（值域 <= 10^4）
        left = ans = 0
        for right, x in enumerate(nums):
            p = last[x]
            if p >= left:                    # 只有"上次出现"还在窗口内才算重复
                left = p + 1                 # 一次跳到位，不是一格格挪
            last[x] = right
            v = pre[right + 1] - pre[left]   # 跳转后的窗口和，O(1) 算出来
            if v > ans:
                ans = v
        return ans
```

**版本 F —— 大多数场景最快（`set` + 运行和）**

```python
from typing import List


class Solution:
    def maximumUniqueSubarray(self, nums: List[int]) -> int:
        seen = set()
        left = temp = ans = 0
        for j in nums:
            while j in seen:
                temp -= nums[left]
                seen.discard(nums[left])
                left += 1
            seen.add(j)
            temp += j
            if temp > ans:
                ans = temp
        return ans
```

**版本 C —— 值域无界时的等价版**：把 D 的 `last` 换成 `{}`、`p = last.get(x, -1)`、初值语义不变即可，其余一字不改。

**优化理由**：

- **D**：把"每格一次哈希"换成"每轮两次数组读"，把"单步挪几十上百格"换成"一次跳转 + 一次前缀和差分"。实测 **1.21~1.57×**，六个场景相对顺序稳定。
- **F**：不维护计数表，用 `set` 的 `in`/`add`/`discard` 判重，六场景 **1.25~1.99×**，其中五个场景比 D 更快；但在"10 种值随机"这一档只有 1.25×（明显慢于 D 的 1.44×）—— 它每轮至少要一次 `set` 哈希 + 一次 `in`，窗口短、收缩频繁时反而不划算。**想要稳选 D，想要平均最快选 F。**
- 两版都**没有改算法**，与用户版逐轮状态一致（对拍 0 偏差）。

**实测（`n = 10⁵`，本机 CPython 3.13，轮转测量、各取 9 次最优值，单位 ms）：**

| 场景 | A 用户版 | B if-ans | C last字典 | D last数组 | F set | D/A | F/A |
| :--- | ---: | ---: | ---: | ---: | ---: | ---: | ---: |
| 1 种值（窗口恒 1） | 26.51 | 21.89 | 21.47 | 18.82 | **13.30** | 1.41× | 1.99× |
| 2 种值交替（窗口恒 2） | 27.05 | 22.34 | 21.40 | 19.29 | **14.07** | 1.40× | 1.92× |
| 10 种值随机 | 26.86 | 22.54 | 20.65 | **18.60** | 21.51 | 1.44× | 1.25× |
| 1000 种值随机 | 30.36 | 25.55 | 22.99 | 19.81 | **18.27** | 1.53× | 1.66× |
| 10⁴ 种值随机 | 33.22 | 29.55 | 26.00 | 21.21 | **17.62** | 1.57× | 1.89× |
| 10⁴ 值整块循环（窗口顶到 10⁴） | 43.39 | 38.17 | 41.33 | **36.00** | **25.98** | 1.21× | 1.67× |

**怎么读这张表**：

- **用户版所有场景都能过**（最坏 43 ms），它不是"会 TLE 的写法"，优化买到的是 1.2~2 倍的常数。
- **B（只把 `max` 换成 `if`）白拿 1.05~1.15×**，零风险，值得改。
- **C 与 D 的差距说明了哈希 vs 数组的账**：同一套跳转逻辑，`last` 用字典要多花 15~40%（`26.00` vs `21.21`）。值域有界时优先数组。
- **窗口越大，用户版越吃亏**（最慢的 43.39 ms 出现在窗口恒 10⁴ 的场景）：单步平均要挪 81 格，每格都是一次哈希读写。

### 常数级优化（可选）

- `ans = max(ans, temp)` → `if temp > ans: ans = temp`：省一次函数调用，实测稳赚（版本 B）。
- `for right, j in enumerate(nums)` → `for j in nums`：`right` 是死变量。
- 值域有界 ⇒ `last` 用定长数组；**值域无界 ⇒ 必须回到字典**，数组开不出来。
- `cnt` 若坚持用字典，别为了省 `defaultdict` 去写 `if j in cnt` —— `cnt[j] += 1` 依赖默认值，改成显式判断反而更慢。

## 六、易错点与总结

### 易错点

- **把 `1208 / 904` 的「`while` 换 `if` 平移」搬过来**：本题答案是**求和**，平移版一律失效（即使判据写对也错 59~64%）。这是本笔记最值钱的一条。
- **把"超出量恒为 1"读成"左指针挪一格就够"**：超出的是**违规的量**，要挪的**格数**实测最多 373。`3 / 3090` 说的"一次跳转"是"一次跳到位"，不是"一步一格"。
- **漏写 `ans` 的每轮更新**：窗口和序列不单调，`ans` 必须在 `while` 之后、每轮都取。
- **忘了 `from collections import defaultdict`**：截图第 1 行就是 `class Solution:`，本地复制会直接 `NameError`。
- **看到"计数表"就条件反射加 `del`**：本题按值判据，**不需要**；只有 `904 / 159 / 340` 那种按键数（`len(cnt) > K`）判据才必须 `del`。
- **负下标**：本解法只用 `nums[left]`（`left` 单调不减且 ≤ `right`），无负下标风险；改跳转版后要记得 `last` 初值是 `-1`、判据写 `p >= left`（不是 `p != -1`，更不是无条件 `left = p + 1`）。
- **把正整数前提当装饰**：负数会让"最长合法窗口 = 最大和窗口"失效（`[-1, 5]` 真值 5、解法给 4）。
- **用二分/前缀和+二分去"优化"左指针**：左指针是摊还 O(1)，换 O(log n) 是负优化（`1208` 实测 0.44~0.81×）。

### 题型套路沉淀

- **本族（变长滑窗 + 每值计数 ≤ k）的判据表**：

  | k | 状态 | 判据 | 代表题 |
  | :---: | :--- | :--- | :--- |
  | 1 | `cnt[x]` 计数表，或 `last[x]` | `cnt[x] > 1` / `last[x] >= left` | `3`、**本题 1695** |
  | 2 | `last1[x]` / `last2[x]` | `last2[x] >= left` | `3090` |
  | 任意 k | 每值一个长度 k 的 `deque` | `dq[0] >= left` | 通用化写法 |

- **本族与相邻族的对照（同骨架，只差"判据 / 答案口径"一格）**：

  | 题 | 窗口合法性度量 | 判据种类 | 答案口径 | `while` → 平移 `if` |
  | :--- | :--- | :--- | :--- | :--- |
  | `3` / `3090` | 每值计数 ≤ k | 按值 | 长度 | 可以换（判据须写成整体判据） |
  | `904` / `159` / `340` | 不同种类数 ≤ K | 按键数（**必须 `del`**） | 长度 | 可以换 |
  | `1004` / `1208` / `1493` | 某度量（0 的个数 / 代价和）≤ 上限 | 按度量值（可加） | 长度 | 可以换（实测 0 错） |
  | **本题 `1695`** | 每值计数 ≤ 1 | 按值 | **求和** | **不可以换** |
  | `209` 最短型 | 窗口和 ≥ target | 按和（可加） | 长度 | 不可以（"平移"只救最长型） |

- **一条可背的判别顺序**：先看**答案口径是不是"长度"**（不是长度的，平移版直接出局）；再看**收缩判据是不是对"整个窗口"成立的**（只看新元素的判据会漏掉残留违规）；两条都过，才能把 `while` 换成"只挪一格 + 终值口径"。
- **"一次跳转" ≠ "平移"**：跳转到 `last[x] + 1` 是**精确收缩**（与 `while` 逐格收缩结果完全等价），只是用 O(1) 换掉了量级不定的挪动；"平移"是**故意不收缩到合法**。名字像，性质完全不同 —— 本题推荐前者（版本 D），严禁后者。
- **同型题**：`3. 无重复字符的最长子串`（**同目录已有**，答案口径 = 长度的对照组）、`3090`（同目录已有，k = 2 推广）、`904`（同目录已有，按键数判据的对照组）、`1208`（同目录已有，"度量是代价和、答案是长度"的镜像题）、`1004`、`1493`（同目录已有）、`159` / `340`、`992. K 个不同整数的子数组`（"恰好"型，用两次"至多"作差）。

**8. 归因实验（把两个因素拆开）**：

- 同族**长度口径**：整体判据的平移版 **0 错**（0 / 29,523）⇒ 无重复家族支持平移，锅在判据；
- 同族**求和口径**：整体判据的平移版错 **64.5% / 59.4%**（最小反例 `[1,2,2]`：真 3、实得 4）⇒ 求和口径下平移版彻底失效；
- **对照家族**（`1004` 口径：#0 ≤ k，穷举 29,520 组）：平移版 + 长度口径 **0 错**；**同一写法**答案改成求和 → 出现反例，最小 `nums = [1,1,1,0,3], k = 0`（真 3、实得 4）；
- **对照家族**（`904` 口径：不同种类数 ≤ K，穷举 262,140 组）：平移版 + 长度口径 **0 错**。

**9. 最小反例**（按 `n`、值域递增搜索得到）：
长度口径 `[1,2,2,1]`（真 2 / 实得 3）、`[1,2,2,3]`（真 2 / 实得 3）；
求和口径 `[1,2,2]`（真 3 / 实得 4）；逐轮展开 `[1,1,1,2,2,2,3]`：平移版从 `right = 4` 起窗口就不再合法（窗口为 `[2,2]`），一路累计到 `right = 6` 给出 7，而真值是 5。
