# 3298. 统计重新排列后包含另一个字符串的子字符串数目 II

> **难度**：困难
> **标签**：滑动窗口 · 哈希表 · 字符串
> **原题链接**：https://leetcode.cn/problems/count-substrings-that-can-be-rearranged-to-contain-a-string-ii/

---

## 一、题目描述

给定两个字符串 `word1` 和 `word2`。子串 `x` 称为**合法**，如果 `x` 重新排列后能让 `word2` 成为它的**前缀**。

这等价于一句计数话：**`x` 中每个字符 `c` 的出现次数 ≥ `word2` 中 `c` 的出现次数** —— 把 `word2` 需要的那份排到最前面，多余的字符随便堆在后面即可。求 `word1` 中合法**子串**的数目。

注意题目特意说明：本题内存限制比通常小，**必须**是线性复杂度的解法。

### 示例

```text
示例 1：
输入：word1 = "bcca", word2 = "abc"
输出：1
解释：唯一合法的子字符串是 "bcca"，可以重新排列得到 "abcc"，"abc" 是它的前缀。

示例 2：
输入：word1 = "abcabc", word2 = "abc"
输出：10
解释：除了长度为 1 和 2 的所有子字符串都是合法的（长度 3 的 4 个 + 长度 4 的 3 个 + 长度 5 的 2 个 + 长度 6 的 1 个）。

示例 3：
输入：word1 = "abcabc", word2 = "aaabc"
输出：0
解释：word1 中总共只有 2 个 'a'，凑不出 word2 需要的 3 个。
```

### 约束条件

- `1 <= word1.length <= 10^6`
- `1 <= word2.length <= 10^4`
- `word1` 和 `word2` 都只包含小写英文字母
- 官方额外要求：线性时间复杂度（本题内存限制比常规题目更小）
- 答案规模：最坏情况 n = 10^6 时约 `n(n+1)/2 ≈ 5×10^11`，超出 32 位整数范围（C++/Java 需 `long long`，Python 无此问题）

## 二、解题思路

### 核心思想

把"子串是否覆盖 `word2`"压成一条**差值判据**：维护

```text
diff[c] = 窗口内字符 c 的个数 − word2 中字符 c 的个数
```

则 **窗口合法 ⟺ `min(diff) ≥ 0`**。固定右端点后，合法的左端点恰好是一段前缀，答案每轮累加"合法左端点的个数"。

### 思路演进

1. **暴力解法**：枚举全部 O(n²) 个子串，每个子串重新数一遍字符、与 `word2` 逐字符比对是否覆盖，时间 O(n²·|Σ|)（若用排序或逐字符 `count` 核对还能退化到更慢）。n = 10^6 时有 10^12 量级的子串，必然超时；而且任何 O(n²) 级别的中间存储都会踩到"内存限制更小"这条。

2. **观察到**：重复计算。`[l, r]` 与 `[l, r+1]` 的字符计数只差**一个字符**，暴力却每次都从头数；"判断合法性"这件事也被重复做了 O(n) 次。

3. **关键转化**（两根单调性，一句话说清为什么原来不行、现在为什么行）：
   - **合法性关于左端前缀封闭**：固定右端 `r`，左端 `l` 越小窗口越大，只会更容易满足覆盖 ⇒ 合法的 `l` 恰好是 `[0, left−1]` 一段连续前缀，**个数就是 `left`**，不用逐个枚举。
   - **最优点关于右端单调**：`r` 增大时，原先合法的 `l` 依然合法（多一个字符不会破坏覆盖）⇒ 最小合法左端 `left` 单调不减。
   - 两根单调性合起来 ⇒ **双指针**：每个下标最多进窗口一次、出窗口一次，总收缩量 ≤ n，摊还 O(1)；前一步的计数状态可以直接继承，不必重算 ⇒ 总时间 O(n)。

4. **最优解**：维护 `diff` 与 `left`。每轮把 `word1[j]` 计入窗口，然后**只要窗口仍然合法就继续右移 `left`**（`while`），直到窗口刚好非法为止，最后 `ans += left`。

### 关键点

- **判据**：窗口合法 ⟺ `min(diff) ≥ 0`；等价的更好维护形式是 **「差值 < 0 的字符种类数」`bad == 0`**（见第五节）。
- **本族方向与常规滑窗模板相反**：最长/最短窗口的模板是"窗口非法就收缩到合法为止"，本族是**"窗口合法就收缩到非法为止"**，两者的 `while` 条件互为反面；答案是**合法左端点数 `left`**，**不是窗口长度**。这是本题最容易串用的地方。
- 用 `diff` 而不是裸计数：`word2` 里没有的字符初始 `diff = 0`、往后只会 ≥ 0，天然不参与判据，不必为它们写特判。
- 截图代码里的变量名 `neg_cnt` 语义其实就是 `diff`：先存 `−need`，再把窗口内的字符加回来，名字带 `neg` 只是初始化方式的痕迹。
- **内层 `while` 一次可能连续缩很多格**：移除一个字符后，窗口**可能依然合法**（被移除的字符在窗口内是富余的），必须继续缩。所以 `while` 不能写成 `if`（实测见第六节）。
- `left` 全程只增不减，且每轮 `while` 结束时 `[left, j]` 必为非法窗口 —— 因为 `word2` 长度 ≥ 1，空窗口必然非法（差值为负）⇒ `left ≤ j` 恒成立，`word1[left]` 不会越界。

## 三、代码实现

### 最终代码

```python
from collections import Counter


class Solution:
    def validSubstringCount(self, word1: str, word2: str) -> int:
        ans = left = 0
        cnt = Counter(word2)
        neg_cnt = Counter({k: -v for k, v in cnt.items()})
        for j in word1:
            neg_cnt[j] += 1
            while min(neg_cnt.values()) >= 0:
                neg_cnt[word1[left]] -= 1
                left += 1
            ans += left
        return ans
```

> 截图从 `class Solution:` 开始，缺 `from collections import Counter`，为让代码可直接运行已补上；其余逐行与截图一致（截图未截断，`return ans` 完整可见）。

## 四、复杂度分析

设 n = `len(word1)`，m = `len(word2)`，|Σ| = 26（小写字母表大小），K = 判据涉及的字符种类数（`neg_cnt` 的键数，K ≤ 26）。

| 版本 | 时间复杂度 | 空间复杂度 |
| :--- | :--- | :--- |
| **最终代码** | O(n·K + m)，K ≤ 26 ⇒ O(n) | O(K) = O(1) |
| 朴素解法 | O(n²·\|Σ\|) | O(\|Σ\|) |
| 理论下界 | O(n) | O(1) |

> 复杂度中的 n 指 `word1` 的长度。

- 外层循环 n 次；内层 `while` 里 `left` 全程只增，总移动次数 ≤ n，摊还 O(1)；每轮判据 `min(neg_cnt.values())` 需要扫过 K 个键，故总时间 O(n·K)。
- 字母表固定为 26 ⇒ K 是常数 ⇒ 形式上就是线性；**但 K = 26 与真正的 O(1) 判据之间差着一个数量级的常数** —— 这是第五节优化的靶子，不代表会 TLE。
- 下界论证：任何解法至少要读一遍 `word1`（否则可能漏解），所以 O(n) 不可突破；空间上判据只需要每个字符的差值，O(|Σ|) 就够，**不需要 O(n)**。题面强调"内存限制更小"，指向的正是"别开前缀和数组 / 每个字符的位置表"。

## 五、优化评估

**结论**：算法结构已是理论下界（双指针的摊还 O(n) 不可再降），**但判据的维护方式可以再降一个数量级的常数**。

### 瓶颈分析

- **时间**：每轮 `min(neg_cnt.values())` 都是 O(K) 扫描（K 最多 26）。n = 10^6 时约 2×10^6 次 `min` 调用、每次遍历最多 26 个 int ⇒ 千万级比较，是本题唯一的常数热点。此外 `Counter` 的 `+=` / `-=` 走哈希 + 对象创建，也是常数开销。
- **空间**：已经是 O(26)，没有可压的余量。

### 可优化空间

判据 `min(diff) ≥ 0` 有两种等价写法：

- 逐个比较 ⇒ 每步 O(K)；
- **只数「差值 < 0 的字符种类数」`bad`，判据变成 `bad == 0`** —— `bad` 只在某个 `diff` 跨过 `0 / −1` 边界时变化，加入字符、移除字符都能 O(1) 维护 ⇒ **时间与字母表大小无关**。

官方提示 2「用常数空间存频率」以及题解里提到的 `cnt` 变量，走的都是这条路线。

### 优化代码

```python
class Solution:
    def validSubstringCount(self, word1: str, word2: str) -> int:
        need = [0] * 26
        for c in word2:
            need[ord(c) - 97] += 1
        diff = [-x for x in need]            # diff[c] = 窗口内 c 的个数 − word2 需要量
        bad = sum(1 for x in need if x > 0)  # 差值 < 0 的字符种类数
        ans = left = 0
        for ch in word1:
            i = ord(ch) - 97
            diff[i] += 1
            if diff[i] == 0:                 # 由「欠」变「齐」，欠账种类数减一
                bad -= 1
            while bad == 0:                  # 窗口合法 → 继续收缩
                k = ord(word1[left]) - 97
                if diff[k] == 0:             # 由「齐」变「欠」
                    bad += 1
                diff[k] -= 1
                left += 1
            ans += left
        return ans
```

**优化理由**：把每轮 O(K) 的 `min` 换成 O(1) 的 `bad == 0`；用 `list[26]` 取代 `Counter`，免去哈希与对象创建。收缩语义与答案口径（`ans += left`）与截图版逐轮等价。

### 实测（本机，n = 10^6，7 轮轮转取最优）

| 场景（n = 10^6） | 截图版 Counter+min | 优化版 bad+list26 | 优化版 + bytes 迭代 |
| :--- | :--- | :--- | :--- |
| S1：`word2` 含全部 26 字母 | 0.990 s | 0.197 s（**5.03×**） | 0.179 s（**5.53×**） |
| S2：`word2 = "a"`（收缩最频繁） | 0.992 s | 0.196 s（**5.06×**） | 0.179 s（**5.55×**） |

> 截图版在 n = 10^6 下约 1 s，**本身就能过**；这里的优化是把常数压下去，不是"不优化会 TLE"。

### 常数级优化（可选）

先把 `word1` 编成 bytes，循环里直接拿整数、省掉 `ord()`，实测再快约 10%（0.197 → 0.179 s）：

```python
        w = word1.encode()
        for b in w:
            i = b - 97
            # ...
            k = w[left] - 97
```

代价是**多一份 n 字节的副本**（n = 10^6 时约 1 MB），严格说把空间从 O(|Σ|) 抬到了 O(|Σ| + n)。题面特意强调内存限制，**若内存是硬约束就保留纯 list 版**；只在时间吃紧时才换这一档。

## 六、易错点与总结

### 易错点

- **把 `while` 写成 `if`**（本族最典型）。移除左端字符后窗口**可能仍然合法**，一次收缩不足以消除"已合法"状态，于是 `ans += left` 少算。实测：40 组随机小用例里 **12 组错**，最小反例 `word1 = "ba", word2 = "a"`（真值 2，实得 1）。
- **答案口径写成"窗口长度"**。本族的答案是**合法左端点数 `left`**；`while` 结束后窗口本身已经非法，"窗口长度"根本不对应任何合法子串。实测：40 组里 **39 组错**，最小反例 `word1 = "a", word2 = "a"`（真值 1，实得 0）。
- 两个错误叠加（`if` + 长度口径）：40 组**全错**。
- 判据写成"某些字符计数 ≥ 0"却不覆盖全部需求字符：必须**每一个** `word2` 字符都被满足，只看总计数、只看最大值、或漏看某个键都会错。
- 答案可达 ~5×10^11（n = 10^6），C++/Java 必须 `long long`，Python 天然无此问题。
- 空间别写成 O(n)：前缀和数组或"每个字符出现位置表"都会撞上题面的内存限制。

### 题型套路沉淀

- **计数型滑动窗口（约束是「度量 ≥ 下限」）**：窗口停在**非法**一侧 —— `while 仍然满足: 收缩`，然后 `ans += left`（**合法左端点数**），而不是 `ans += 窗口长度`。它与"最长 / 最短"模板的 `while` 条件互为反面，是本族最容易串用的地方。
- 成立需要两根单调性：① 合法性关于左端**前缀封闭**（左端左移只会更容易合法）；② 左端最优点随右端**单调不减**。缺一根就只能退回 O(n²) 或换结构。
- 判据优先写成**差值 + 违规种类数**：`diff[c] = 窗口计数 − 需求计数`，`bad = #{c : diff[c] < 0}`，条件 `bad == 0` —— 每步 O(1) 维护，比 `min(diff)` 快一个数量级。
- 可加度量的维护通式：加入 `x` ⇒ **先加计数、再看是否跨过 0**（欠 → 齐则 `bad−1`）；移除 `y` ⇒ **先看是否跨过 0**（齐 → 欠则 `bad+1`）、**再减计数**。两处顺序相反，写反会每轮多算/少算一份，而小规模样例未必暴露。
- 同族识别信号：题目问"有多少个子串满足某覆盖/计数条件"，且条件对子串是**单调（越长越容易满足）**的 —— 直接套本模板。
