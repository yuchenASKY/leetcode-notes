# 3306. 元音辅音字符串计数 II

> **难度**：中等
> **标签**：滑窗 · 字符串 · 哈希表
> **原题链接**：https://leetcode.cn/problems/count-of-substrings-containing-every-vowel-and-k-consonants-ii/

---

## 一、题目描述

给定字符串 `word` 和非负整数 `k`，统计**子字符串**总数，要求同时满足：

1. `a`、`e`、`i`、`o`、`u` 五个元音字母**每个至少出现一次**；
2. **恰好**包含 `k` 个辅音字母（`word` 只含小写英文字母，除元音外全是辅音）。

### 示例

```text
输入：word = "aeioqq", k = 1
输出：0
解释：不存在包含全部五个元音字母的子字符串。

输入：word = "aeiou", k = 0
输出：1
解释：唯一满足条件的子字符串是 word[0..4]，即 "aeiou"。

输入：word = "ieaouqqieaouqq", k = 1
输出：3
解释：满足条件的是 word[0..5]="ieaouq"、word[6..11]="qieaou"、word[7..12]="ieaouq"。
```

### 约束条件

- `5 <= word.length <= 2 * 10^5`
- `word` 仅由小写英文字母组成
- `0 <= k <= word.length - 5`

> `n` 最大 2×10^5 ⇒ 枚举全部 O(n²) 个子串的写法（约 4×10^10 量级）出局，必须做成**线性**。

## 二、解题思路

### 核心思想

**「恰好 k」不是单调条件，但它可以写成两个单调条件之差**：`恰好 k = (至少 k) − (至少 k+1)`。对每个右端点，用两根左指针分别把「五个元音齐全 + 辅音数 ≥ 阈值」的**合法左端点个数**求出来，两者相减即为本轮贡献 —— 注意这里累计的是**左端点的个数**，不是窗口长度。

### 思路演进

1. **暴力解法**：枚举全部 `O(n²)` 个子串，用增量计数统计「元音种类是否到 5、辅音是否等于 k」。分组数 2×10^5 时规模约 2×10^10 个子串（即使 O(1) 判定也无法承受），必须换思路。
2. **观察到**：固定右端点 `r`，把左端点 `l` 从 `r` 向左推移时，窗口元素**只增不减**，于是「元音齐全」和「辅音数 ≥ 阈值」这两个条件都**单调地由不成立变为成立**。⇒ 固定 `r` 时，合法的 `l` 恰好是一段**前缀** `[0, left-1]`，只要知道边界 `left`，本轮贡献就是 `left` 个子串，无需逐个枚举。
3. **关键转化**：把非单调的「恰好 k」拆成两个单调量的差 —— `#{恰好 k} = #{≥ k} − #{≥ k+1}`，再用两根滑窗左指针分别在阈值 `k` 与 `k+1` 下维护「合法左端点个数」。原来不行是因为「恰好」不能靠窗口自己收缩表达；现在行了，是因为**每个「≥ 阈值」都是单调条件，而单调条件的前缀计数可以摊还 O(1) 求出**。
4. **最优解**：见「三、代码实现」—— 一趟扫描里同时跑两个窗口，每轮 `ans += left1 - left2`。窗口收缩的方向要特别留意：**退出 while 时窗口自身是「不合法」的**（刚跌破下界），合法左端点恰恰在它左边，所以口径是 `left` 而不是窗口长度。

### 关键点

- **判据**：处理完 `r` 后，`left1 = #{ l : word[l..r] 含全部 5 个元音且辅音数 ≥ k }`，`left2` 同理（阈值 `k+1`）；答案 `Σ_r (left1 − left2)`。命题「合法左端点集 = 前缀 `[0, left-1]`」是整个解法唯一的判据，边界都在它上面浮现。
- **两根单调性**（双指针成立的根基，缺一不可）：
  - 固定 `r`，条件对 `l` 减小单调成立（窗口变大只会补元音、增辅音）⇒ 合法 `l` 构成前缀；
  - `r` 增大时合法集合只增不减（多读一个字符不会破坏已成立的条件）⇒ `left1`、`left2` 关于 `r` **单调不减** ⇒ 两根左指针全程总移动量 ≤ n，内层 `while` 是**摊还 O(1)**，整题仍 O(n)（不要因为 `while` 嵌在 `for` 里就误判成 O(n²)，更不能反过来用 O(log n) 的二分去"优化"这个摊还 O(1) 的移动）。
- **左指针停在「非法」一侧**：`while` 的条件是「窗口仍合法就继续缩」，退出时 `word[left..r]` 已经不满足下界 ⇒ 合法左端点恰好 `left` 个，**不是** `r - left + 1`。这与「求最长/最短合法窗口」那一族的 while 条件互为反面，是本族最容易串用的地方。
- **两个窗口互不干扰**：窗口 2 的判据严格更强（阈值 `k+1`）⇒ `left2 <= left1` 恒成立 ⇒ 每轮增量 `left1 - left2 >= 0`，不会出现负贡献。
- **计数容器按「键数」判定时必须删键**：这里判据是「5 种元音齐不齐」，靠 `len(cnt) == 5`。元素移出窗口且计数归零时**必须 `del`**，否则键数只增不减 —— `len(cnt) == 5` 一旦为真就永远为真，`while` 会把左指针一路推到越过 `r`，下一轮读 `word[left]` 直接 `IndexError`（静态推导，属于「按值判据不用删键、按键数判据必须删键」的分界）。
- `k = 0` 时窗口 1 的辅音条件恒真，合法窗口完全由「5 个元音齐全」钳制，逻辑不变。

## 三、代码实现

### 最终代码

```python
from collections import defaultdict   # 截图里没有，已补（仅补全，逻辑未改）


class Solution:
    def countOfSubstrings(self, word: str, k: int) -> int:
        cnt1 = defaultdict(int)        # 窗口 1（阈值 k）内的元音计数
        cnt2 = 0                       # 窗口 1 内的辅音个数
        cnt3 = defaultdict(int)        # 窗口 2（阈值 k+1）内的元音计数
        cnt4 = 0                       # 窗口 2 内的辅音个数
        ans = left1 = left2 = 0
        for right, j in enumerate(word):
            if j in 'aeiou':
                cnt1[j] += 1
                cnt3[j] += 1
            else:
                cnt2 += 1
                cnt4 += 1
            # 窗口 1：收缩到「刚好跌破」下界（5 元音齐 + 辅音 ≥ k）
            while len(cnt1) == 5 and cnt2 >= k:
                if word[left1] in 'aeiou':
                    cnt1[word[left1]] -= 1
                    if cnt1[word[left1]] == 0:
                        del cnt1[word[left1]]
                else:
                    cnt2 -= 1
                left1 += 1
            ans += left1               # 合法左端点个数 = left1
            # 窗口 2：同一趟里再跑一遍，阈值换成 k + 1
            while len(cnt3) == 5 and cnt4 >= k + 1:
                if word[left2] in 'aeiou':
                    cnt3[word[left2]] -= 1
                    if cnt3[word[left2]] == 0:
                        del cnt3[word[left2]]
                else:
                    cnt4 -= 1
                left2 += 1
            ans -= left2               # 容斥：(≥ k) − (≥ k+1) = 恰好 k
        return ans
```

### 正确性要点

- **不变量**：每轮 `for` 结束后，`word[left1..right]` 不满足「5 元音齐 + 辅音 ≥ k」，而 `word[left1-1..right]`（若 `left1 > 0`）满足；由「条件对窗口变大单调成立」，合法左端点集恰为 `[0, left1-1]`，故本轮贡献 `left1`。
- **初始条件**：`left1 = left2 = 0`，空窗口前缀计数为 0，归纳起点成立。
- **单调不减**：`right` 增加后合法集合只增 → `left1`、`left2` 不回退，收缩是纯粹的推进。

## 四、复杂度分析

| 版本 | 时间复杂度 | 空间复杂度 |
| :--- | :--- | :--- |
| **最终代码（双窗同趟）** | O(n)（每轮两处 `while` 合计摊还 O(1)，左指针各最多推进 n 次） | O(1)（`cnt1`/`cnt3` 至多 5 个键） |

## 五、优化评估

**结论**：时间与空间复杂度**均已达到理论下界**，剩下的只有**常数级优化**，且实测有效（同场景 1.20× ~ 1.46×）。

### 瓶颈分析

- 本题耗时**均匀摊在每个字符上**，没有可整段消除的阶段：基准场景 D（`k` 大到无任何合法窗口、两处 `while` 一次都不进入）仍有 0.022 s（n = 10^5），说明循环体的「每字符固定开销」占主导；A/C 场景（窗口频繁收缩）也只涨到 0.044 ~ 0.050 s。
- 每字符的固定开销 = 一次 `j in 'aeiou'` 成员判断 + 两次容器写入；每步收缩再各来一次读 / 写 / `del`。Python 层这些操作的次数，就是优化的天花板 —— 能把「每字符 Python 操作数」降多少，就是能快多少（天花板约 1 − 不可去部分占比；本题真正不可去的只有「至少读一遍字符」）。
- 空间上没有任何可压缩的冗余：两个窗口各 5 个元音槽 + 1 个辅音计数器，已是最小集。

### 可优化空间

- **大 O 无法再降**：时间 Ω(n)、空间 Ω(1) 都已触及（见「四」）。
- **常数层面**有两个方向：① 把元音判定从「每字符做一次字符串成员判断」换成**预编码查表**；② 把 `defaultdict` + `len(cnt)` 换成**定长数组 + 元音种类计数器**，省掉哈希与 `del`。方向 ② 单独用并不稳（见下"被证伪"），① + ② 合用则全场景为正。

### 优化代码

```python
_TBL = bytearray(256)
for _i, _c in enumerate(b'aeiou'):
    _TBL[_c] = _i + 1
_TBL = bytes(_TBL)


class Solution:
    def countOfSubstrings(self, word: str, k: int) -> int:
        # 预处理：'a'~'u' → 1~5，辅音 → 0（C 层 translate，一次 O(n)）
        codes = word.encode().translate(_TBL)
        c1 = [0] * 6                   # 下标 0 不用，1~5 对应 a e i o u
        c3 = [0] * 6
        kinds1 = kinds3 = 0            # 窗口内「出现次数 > 0 的元音种类数」
        c2 = c4 = 0                     # 辅音个数
        ans = left1 = left2 = 0
        k1 = k + 1
        for right, code in enumerate(codes):
            if code:
                if c1[code] == 0:
                    kinds1 += 1
                c1[code] += 1
                if c3[code] == 0:
                    kinds3 += 1
                c3[code] += 1
            else:
                c2 += 1
                c4 += 1
            while kinds1 == 5 and c2 >= k:
                lc = codes[left1]
                if lc:
                    c1[lc] -= 1
                    if c1[lc] == 0:
                        kinds1 -= 1
                else:
                    c2 -= 1
                left1 += 1
            ans += left1
            while kinds3 == 5 and c4 >= k1:
                lc = codes[left2]
                if lc:
                    c3[lc] -= 1
                    if c3[lc] == 0:
                        kinds3 -= 1
                else:
                    c4 -= 1
                left2 += 1
            ans -= left2
        return ans
```

**优化理由**：

- `word.encode().translate(_TBL)` 在 C 层一次性把每个字符替换成 1~5 / 0 的编码，此后循环里只做 **int 真假判断**与**定长 list 下标访问**，避开每字符一次的 `str in str` 判断和哈希查找。
- 用 `kinds1/kinds3` 显式记录「种类数」，取代 `len(dict)`；`del` 也随之消失（计数归零时 `kinds -= 1` 即可）—— 按键数判据的语义不变，但把「删键」这一维护动作降成了整数自减。
- 循环用 `enumerate(codes)` 迭代 `bytes`，得到的是 int 而非单字符 str，省掉一次字符串对象访问。
- 代价：多一份 n 字节的编码副本 ⇒ **空间从 O(1) 变成 O(n)**（n = 2×10^5 时约 200 KB，本题内存无压力）。若题目额外限制 O(1) 空间，则**不要**用这一版。

### 常数级优化实测（n = 10^5，9 轮轮转取每版最优值）

| 场景 | 最终代码（defaultdict） | 5 槽数组版 | **编码版（上方代码）** |
| :--- | :--- | :--- | :--- |
| A 混合字符（元音占 5/8），k = 2 | 0.0501 s（1.00×） | 0.0438 s（1.14×） | **0.0347 s（1.44×）** |
| B 元音稀疏（约 2%），k = 1 | 0.0299 s（1.00×） | 0.0340 s（0.88×） | **0.0249 s（1.20×）** |
| C 全元音，k = 0 | 0.0440 s（1.00×） | 0.0365 s（1.20×） | **0.0302 s（1.46×）** |
| D 无合法窗口（k = n） | 0.0217 s（1.00×） | 0.0219 s（0.99×） | **0.0169 s（1.28×）** |

- 编码版在**四个场景全部为正收益**（1.20× ~ 1.46×），是稳妥选择。
- **被证伪的改法（保留以供避坑）**：~~"只把 `defaultdict` 换成 5 槽数组 + `kinds` 计数，其余不动"~~ —— 它在 A/C 略快（1.14×/1.20×），但在**元音稀疏场景掉到 0.88×、无窗口场景 0.99×（持平）**：稀疏时两处 `while` 几乎不跑，而每字符却要付出两次「计数是否为 0」的 Python 层判断，收益被抵消甚至反转。⇒ 单换容器不稳，必须连元音判定一起预编码才划算。
- 三版实现在 A~D 四个大输入上的答案完全一致（38828 / 0 / 4999013665 / 0），与暴力基准同批小用例对拍亦为 0 偏差。

## 六、易错点与总结

### 易错点

**① 答案口径必须是「合法左端点数」，写成「窗口长度」必错。**

两窗同趟结构下，"两窗口长度之差"这一口径与原版增量**恒为相反数**（逐轮累计值核对 20 组全部成立）：`(r-left1+1) - (r-left2+1) = left2 - left1`。因此**只要真值 > 0 就必然出错，且答案会是负数** —— 这类题里看到负数输出，第一反应就该去查口径。

| 收缩方式 | 答案口径 | 同批 40 组随机用例 | 最小反例 |
| :--- | :--- | :--- | :--- |
| `while`（收缩到跌破下界） | ① 合法左端点数 `ans += left1 - left2` | ✅ 0/40 错 | — |
| `if`（每轮左指针至多进 1 格） | ① 合法左端点数 | ❌ 3/40 错（偏低） | `word = "aaeiou", k = 0`：真值 2、实得 1 |
| `while` | ② 两窗口长度之差 | ❌ 4/40 错（全为负） | `word = "aeiou", k = 0`：真值 1、实得 −1 |
| `if` | ② 两窗口长度之差 | ❌ 4/40 错 | 同上 |

**② `while` 不能换成 `if`。** 反例 `word = "aaeiou", k = 0`：处理到 `right = 5` 时窗口内 `a` 出现两次，删掉 `word[left1] = 'a'` 之后**五个元音仍然齐全**（辅音约束此时不拦），于是同一轮要连缩 2 格；`if` 只缩一格 ⇒ `left1` 偏小 ⇒ 计数偏低。⇒ 本族「每轮只追加一个元素 ⇒ 违规量恒为 1」并不成立，**必须用 `while`**。

**③ 不删键会越界。** 判据用了 `len(cnt) == 5`（按键数），移出元素后若计数归零而不 `del`，键数只增不减，`while` 条件一旦为真便永远为真，左指针会被推过 `right` 后读 `word[left1]` 抛 `IndexError`。

**④ 第二窗口的阈值必须是 `k + 1`。** 容斥式 `恰好 k = (≥ k) − (≥ k+1)` 少一不可；两个窗口的移出逻辑必须各用**自己**的计数器（`cnt1/cnt2` 与 `cnt3/cnt4`），共用一个会在容斥相减时相互污染。

**⑤ `k = 0` / `k = n - 5` 两个边界**：前者窗口 1 的辅音条件恒真（合法集完全由元音钳制），后者两个窗口都几乎不成立（答案常为 0）；这两个退化档已纳入对拍与基准。

### 题型套路沉淀

- **「恰好 K」型计数滑窗的通用拆法**：`恰好 = (≥ K) − (≥ K+1)`，然后对每个右端点维护**合法左端点个数**（不是窗口长度）。同型思路适用于一切「恰好等于某度量的子数组计数」。
- **本族与「最长/最短合法窗口」族的判别方法**：看 `while` 退出时窗口是**合法**还是**非法**。
  - 收缩到合法为止（条件 `while 不合法: 缩`）→ 求最长/最短，答案与窗口长度有关；
  - 收缩到跌破下界（条件 `while 仍合法: 缩`）→ 计数型，答案是「左边的合法左端点个数」`ans += left`。
  两者 `while` 条件互为反面，**串用即错**。
- **摊还分析别漏**：两根左指针各自单调不减、总量 ≤ n，所以 `for + while` 是 O(n) 而不是 O(n²)；同理，用二分/有序表替代这个摊还 O(1) 的推进是负优化。
- **按键数判定 ⇒ 必须删键**（或显式维护种类数）；**按值判定 ⇒ 计数归零也不用删**。这条决定了容器的维护动作。
- 常数优化方向：把「字符 → 类别」的判定**预编码**（`translate` / 打表），循环里只做 int 比较与数组下标；容器优先定长数组而非哈希（但稀疏输入下要实测，别想当然）。

**本次为笔记新写的代码**（编码版优化解、以及四象限/反例实验用的变体）均按下述小批量尺度验证：

| 项目 | 规模 | 结果 |
| :--- | :--- | :--- |
| 官方示例（3 条） | `"aeioqq",k=1 / "aeiou",k=0 / "ieaouqqieaouqq",k=1` | 三版实现全部符合（0 / 1 / 3） |
| 暴力基准自检 | `brute`（O(n²) 增量） vs `brute3`（O(n³) 逐子串重算），15 组小规模 | 偏差 0 |
| 手工构造用例（13 条，期望值由 `brute3` 独立给出） | 含 `k=0`、`k=n`、全元音、全辅音、空串、多解等 | 偏差 0 |
| 随机对拍（40 组，`n ≤ 20`） | 字母表分别取 `aeioub` / `aeiou` / `b` / `aeioubxyz`，`k ∈ {0,1,2,3,n,随机}` | 偏差 0（三版实现） |
| 四象限（`while`/`if` × 口径①/②） | 同一批 40 组随机用例 | ①`while` 0/40 错；①`if` 3/40；②两格各 4/40（全为负） |
| 口径② ≡ −口径① 核对 | 20 组随机用例的最终值 | 20/20 成立 |
| 最小反例搜索 | 按 n 递增枚举 `{a,e,i,o,u,b}` 全串、`k ∈ {0,1,2}`，找到首个即停 | ①`if`：`"aaeiou",k=0`（真 2 / 实得 1）；②`while`：`"aeiou",k=0`（真 1 / 实得 −1） |
| 微基准 | `n = 10^5`，4 个场景 × 3 个版本 × 9 轮**轮转**取最优 | 见「五」中表格（编码版 1.20× ~ 1.46×）；四个场景三版答案一致 |
| 用例总数 | 15 + 3 + 13 + 40 + 40 + 20 + 少量枚举 + 12 档基准输入 | 约 150 余个，远低于 500 上限 |

> 说明：口径②的失败形态在本次实验中稳定表现为**返回负值**（例如 `"ieooaauuiiiuou", k = 0`：真值 14、实得 −14），可作为二刷时的自检信号。
