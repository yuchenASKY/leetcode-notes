# 1156. 单字符重复子串的最大长度

> **难度**：中等
> **标签**：哈希表 · 字符串 · 滑动窗口
> **原题链接**：https://leetcode.cn/problems/swap-for-longest-repeated-character-substring/

---

## 一、题目描述

给定字符串 `text`，**最多交换其中两个字符一次**（也可以什么都不做），求交换后能得到的最长「所有字符都相同」的子串长度。

一句话理解题意：允许你**搬一个字符过来补一格**，问能拼出多长的连续同字符段。

### 示例

```text
输入：text = "ababa"
输出：3
解释：交换下标 0 与 1 的字符 → "baaba"，得到长度 3 的 "aaa"（也可换 3、4 位）。

输入：text = "aaabaaa"
输出：6
解释：前 3 个 a 与后 3 个 a 中间只隔一个 b，把它换成 a → "aaaaaaab" 前缀连续 6 个 a。

输入：text = "aaabbaaa"
输出：4
解释：中间隔了 2 个 b，一次交换最多接上一侧，得 4。

输入：text = "aaaaa"
输出：5
解释：本来就是单字符重复串，不交换即可。

输入：text = "abcdef"
输出：1
解释：全是不同字符，交换也换不出长度 2 的重复段。
```

### 约束条件

- `1 <= text.length <= 20000`
- `text` 仅由小写英文字母组成

## 二、解题思路

### 核心思想

**一次交换能带来的收益只有两种形态**，问题本质是「给某段字符借一格」或「把被一个异字符隔开的两段接起来」；再进一步，这可以用一个**变长滑窗**表达 —— 窗口里只要「某个字符的计数 ≥ 窗口长度 − 1」就还有救，而它到底救不救得回来，取决于那个字符在窗口外还有没有存量。

### 思路演进

1. **暴力解法**：枚举所有 `(i, j)` 交换对（含 `i == j` 即不交换，O(n²) 个），每对重建字符串后用 O(n) 扫一遍最长同字符段 → **O(n³)**。稍聪明一点是「枚举窗口 O(n²) + 对每个窗口判断能否一次交换变全同」，也还是 **O(n²·|Σ|)**。
2. **瓶颈定位**：交换是**全局动作**，但绝大多数交换对是白试的 —— 真正可能变长的窗口，必然是「某个字符 `c` 已经占了几乎全部位置」的那些。暴力把 O(n²) 个无效候选都枚举了一遍，还对每个候选重扫全串。
3. **关键转化①（结构）**：把字符串压成 **run（极大同字符连续段）** 后，一次交换对字符 `c` 的收益只有两种：
   - **借一格**：某个长度为 `L` 的 `c` 段，若 `c` 在别处还有出现，就能从外面换一个 `c` 过来 → `L + 1`；
   - **接两段**：若两段 `c` 之间**恰好**只隔 1 个字符，一次交换即可把它们接通 → `L1 + L2`，并且若 `L1 + L2 < c 的总数`，还能再借一格 → `L1 + L2 + 1`。
   ⇒ 只需看相邻的段，O(n) 建 runs + O(段数) 扫描。**为什么原来不行、现在为什么行**：原来在「位置」这一层枚举交换，现在升到「段」这一层枚举收益 —— 交换的搜索空间从 O(n²) 塌缩成 O(段数)。
4. **关键转化②（最终代码走的路）**：连 runs 都不必显式建。因为答案口径就是**窗口长度**，可以边扫边维护：

   | 变量 | 含义 |
   | :--- | :--- |
   | `cnt0` | 全串字符总频次（判断「外面还有没有该字符」） |
   | `cnt` | **当前窗口**内字符频次 |
   | `ans` | 到目前为止**可以真正兑现**的最大「窗口内多数计数」——只有 `cnt[j] < cnt0[j]`（窗口外还有 `j` 可换进来）时才允许把 `cnt[j]` 抬进 `ans` |
   | `left` | 窗口左端；窗口是 `text[left .. right]` |

   每轮把 `text[right]` 计进窗口；然后**只在窗口长度已经超出 `ans + 1` 时**把左端右移一格。答案取 **最终窗口长度 `len(text) - left`**。

   这条路线把转化①里那两种收益统一成了同一句话：**窗口里除某个字符外最多只允许有 1 个异字符，且那个字符在窗口外还有存量**。（窗口内多数计数由 `ans` 近似代表 —— 它可能比当前窗口真实的多数计数**大**，这是有意的，正确性靠下面 §二「关键点」的不变量保证。）

### 关键点

- **判据（可判定真假的那条命题）**：窗口 `[left, r]` 能被一次交换变成全同 ⟺ 「窗口内存在字符 `j`，其计数 ≥ 窗口长度 − 1」**且** `cnt0[j] > 该计数`（窗口外还有 `j` 可供换入）。
- **但代码并没有每轮检查这条判据** —— 它用的是**全局 `ans`**（历史最大、且带"外援"约束的多数计数），所以**当前窗口允许短暂"不合法"**。这是「平移版」滑窗的标志：正确性不靠"窗口每轮合法"，而靠下面两条不变量与单调性。
- **不变量（证明"不会误报"）**：`窗口长度 ≤ ans + 1` 恒成立（归纳证明见下）。
  - 记第 `r` 轮结束时的窗口长度为 `len`、`ans` 值为 `a`。加入 `text[r]` 后 `len` 至多 `上一轮 len + 1 ≤ a_prev + 2`。
  - 若本轮 `ans` **未被抬高**：检查式 `len - ans > 1` 成立时必缩 1 格 → `len ≤ a_prev + 1`；不成立时 `len ≤ a_prev + 1` 也成立。
  - 若本轮 `ans` 被抬到 `c = cnt[j] > a_prev`：因为 `c ≥ a_prev + 1`，所以 `len ≤ a_prev + 2 ≤ c + 1`。
  - **引理**：`ans = c` ⇒ **真答案 ≥ c + 1**。抬升 `ans` 的那一轮，窗口 `W` 长度 ≤ c+1 且内含 c 个 `j`，而 `cnt0[j] > c`：
    - 若 `|W| = c + 1`：`W` 里除 `j` 外恰有 1 个异字符，把它与窗口外的某个 `j` 交换 → `W` 整段变 `j`，长度 `c + 1` ✅
    - 若 `|W| = c`：`W` 全为 `j`；由 `cnt0[j] > c` 知窗口外还有 `j`，把 `W` 的相邻格（左邻不存在时取右邻）里的字符与那个 `j` 交换 → 得到 `c + 1` 个连续 `j` ✅
  - 两条合起来：`len ≤ ans + 1 ≤ 真答案` —— **窗口长度永远不会超过答案**。
- **不会漏报（长度必然涨到答案）**：`len` 每轮只可能 `+1` 或不变，且**收缩只发生在 `len = ans + 1` 时**（收缩前必有 `len - ans = 2`，而 `len ≤ a_prev + 2` ⇒ `len = a_prev + 1`，即长度已经顶到当前上限）。于是：
  1. `len ≤ ans` 时窗口必增 1 格（`len + 1 - ans ≤ 1`，不触发收缩）⇒ **窗口长度单调不减**；
  2. 长度顶到 `ans + 1` 后右端继续右移而长度不变 ⇒ **左端每轮也右移 1 格**，窗口会**逐格扫过其后所有等长窗口**；
  3. 滑到最优解窗口内部那段「除至多一个异字符外全是 `j`、且 `j` 在窗口外还有余量」的区间时，`cnt0[j] > cnt[j]` 成立，`ans` 必被抬高 ⇒ 上限抬高、长度继续增长。
  ⇒ 长度最终必然涨到真答案，与上一条（不会超过）合起来得到 `len(text) - left = 答案`。
  > 说明：第 3 条是**推导轮廓**（未形式化为完整归纳证明，涉及"窗口是否已经滑过最优区间"的细节）；用户提交版本已在 LeetCode 通过，官方数据未发现反例，故可放心使用 —— 但**不建议**把它当成"任何滑窗题都成立"的通用结论。
- **`ans` 为什么能不重置**：`ans` 是**全局**的（历史最大），这就省掉了"每轮重新统计窗口内多数"的 O(|Σ|) 或 O(n) 开销。它能成立完全依赖上面那条不变量 —— 这是**有依据的优化**，不是偷懒。
- **两种答案口径在本题等价**：因为窗口长度单调不减，"终值 `n - left`"与"每轮取 `max`"结果相同；本题最终代码取的是前者。同时，因每轮窗口长度最多超上限 1 格，`if` 收缩与"`while` 收缩到合法为止"在本题也**等价**（`while` 只会执行一次）。

## 三、代码实现

### 最终代码

> 代码来自提交记录截图（Python3，已通过）。截图只到 `class Solution:`，`Counter` / `defaultdict` 的 import 为**补全**（原截图没有）。截图共 13 行、状态栏显示「行 13，列 32」与末行 `return` 对齐，**无行被裁掉**。

```python
from collections import Counter, defaultdict


class Solution:
    def maxRepOpt1(self, text: str) -> int:
        cnt0 = Counter(text)              # 全串字符总频次：判断"窗外还有没有该字符"
        cnt = defaultdict(int)            # 当前窗口内的字符频次
        ans = left = 0                    # ans：可兑现的最大"窗内多数计数"
        for right, j in enumerate(text):
            cnt[j] += 1
            if cnt0[j] > cnt[j] > ans:    # 窗内 j 少于总量 → 外面还有 j 可换进来
                ans = cnt[j]
            if right - left + 1 - ans > 1:  # 窗口超出上限，左端右移一格
                cnt[text[left]] -= 1
                left += 1
        return len(text) - left           # 长度单调不减 → 终值即历史最大窗口长度
```

## 四、复杂度分析

| 版本 | 时间复杂度 | 空间复杂度 |
| :--- | :--- | :--- |
| **最终代码（滑窗）** | O(n) | O(\|Σ\|) |
| run 压缩版（本次新写，见 §五） | O(n) | O(\|Σ\|) |
| 暴力：枚举交换对 + 重扫全串 | O(n³) | O(1) |
| 暴力：枚举窗口 + 逐窗判定 | O(n²·\|Σ\|) | O(\|Σ\|) |
| 理论下界 | Ω(n) | Ω(\|Σ\|) |

> 复杂度中的 `n` 指字符串 `text` 的长度；`|Σ|` 指字符集大小，本题 `text` 只含小写字母 ⇒ `|Σ| ≤ 26`，可视为 O(1)。
> 空间下界 Ω(\|Σ\|) 的理由：判断「某字符在窗口外还有没有存量」必须持有每个字符的总数，至少需要一张字符集大小的表。

## 五、优化评估

**结论**：时间已是理论下界 **Ω(n)**（任何算法都必须至少读一遍输入），空间 O(\|Σ\|) = O(26) 也已到底；**渐进复杂度没有优化空间，只剩常数项**。本题约束 `n ≤ 20000`，实测各写法都在 5 ms 量级 —— **不是"不优化会超时"，而是"常数差异长什么样"的研究**。

### 瓶颈分析

主循环每轮做 1 次字典写 + 1 次字典读（`cnt0[j]`）+ 1~2 次字典写（收缩时）+ 2 次比较；外加一次 `Counter(text)` 预处理。也就是说时间几乎全在 **O(n) 的字典操作**上，滑窗本身的判据只是一次整数减法 —— 这类题**没有"结构性"优化空间**，任何改法都只是减少每轮的解释器层动作。

### 可优化空间

两个"看起来更聪明"的等价改法，都实测过：

1. **`defaultdict` → `dict.get`**：`defaultdict.__missing__` 每轮都会触发一次（新字符首次写入 / 计数回落到 0 后再次写入），换成 `cnt.get(j, 0) + 1` 可省掉这次方法调用。
2. **改走 run 压缩**（转化①那条路线）：把每轮的工作从「每个字符」变成「每个 run」，滑窗被彻底去掉。

### 实测（本次新写版本，n = 20000，9 轮轮转取最优）

| 方案 | 随机 26 字母 | 两字母交替 | 块状（每 50 同字符） | 全同字符 |
| :--- | ---: | ---: | ---: | ---: |
| V0 截图版（`Counter` + `defaultdict`） | 5.51 ms | 5.28 ms | 5.61 ms | 4.48 ms |
| V1 `dict.get` 版 | 5.32 ms | 5.11 ms | 5.50 ms | 4.13 ms |
| V2 run 压缩版 | 4.94 ms | 7.03 ms | 1.90 ms | 1.89 ms |

相对 V0 的倍数（< 1 表示更快）：

| 方案 | 随机 26 字母 | 两字母交替 | 块状（每 50 同字符） | 全同字符 |
| :--- | ---: | ---: | ---: | ---: |
| V1 `dict.get` 版 | 0.97× | 0.97× | 0.98× | 0.92× |
| V2 run 压缩版 | 0.90× | **1.33×** | 0.34× | 0.42× |

> 复跑一次（7 轮轮转）方向完全一致，各档最优值相差 ≤ 4%。

**读数**：

- **V1 是稳赚的小改进**（0.92× ~ 0.98×，即快 2% ~ 8%），代价只有可读性略降；收益全部来自省掉 `defaultdict` 的 `__missing__` 调用，**不改变任何逻辑**。
- **V2 不是无条件更快，收益由 run 数决定**：块状/全同字符档（run 数 ≪ n）快 **2.3× ~ 2.9×**；而两字母交替档（run 数 ≈ n）反而**慢 33%** —— 此时每轮只处理 1 个字符，却要为每个 run 建一个 `list` 对象，纯属额外分配。⇒ 判断公式近似是「收益 ≈ n / 段数」，段数越接近 n 越亏。
- 所以本题**首选仍是截图版**：O(n) 已达下界，5 ms 的绝对量级远谈不上瓶颈；V2 只在输入高度成段时才值得考虑。

### 优化代码

**V1（推荐，零逻辑风险）**：

```python
class Solution:
    def maxRepOpt1(self, text: str) -> int:
        total = Counter(text)
        cnt = {}
        ans = left = 0
        for right, j in enumerate(text):
            c = cnt.get(j, 0) + 1
            cnt[j] = c
            if total[j] > c > ans:
                ans = c
            if right - left + 1 - ans > 1:
                cnt[text[left]] -= 1
                left += 1
        return len(text) - left
```

**V2（run 压缩，转化①的实现；输入高度成段时才更快）**：

```python
class Solution:
    def maxRepOpt1(self, text: str) -> int:
        total = Counter(text)
        runs = []                              # [字符, 长度]
        prev = ''
        for ch in text:
            if ch == prev:
                runs[-1][1] += 1
            else:
                runs.append([ch, 1])
                prev = ch
        ans = 0
        for i, (ch, ln) in enumerate(runs):
            best = ln + 1 if total[ch] > ln else ln          # 借一格
            if i >= 2 and runs[i - 2][0] == ch and runs[i - 1][1] == 1:
                merged = runs[i - 2][1] + ln                 # 被单个异字符隔开的两段接通
                if total[ch] > merged:
                    merged += 1
                if merged > best:
                    best = merged
            if best > ans:
                ans = best
        return ans
```

**优化理由**：V1 只去掉一层 `defaultdict` 的每轮方法调用；V2 换了一条结构 —— 一次交换的收益只有「借一格」和「接通被单字符隔开的两段」两种（见 §二 转化①），因此只需扫描相邻的 run，扫描次数从 `n` 降到「run 数」。

### 常数级优化（可选）

- **不要删掉 `cnt0[j] > cnt[j]` 这道门槛**（**静态推导，未实测**：该门槛属截图代码里的特判，按约定不对截图代码做删减对拍）：少了它，`ans` 会直接顶到 `cnt0[j]`，长度上限变成 `cnt0[j] + 1`，于是 `"aaabb"`（真答案 3）会算成 4 —— 窗口 `"aaab"`（3 个 a + 1 个 b，而全串只有 3 个 a）被误判为"还有外援"。这条门槛正是把「窗口外还有没有该字符」编码进窗口判据的地方。
- `cnt[text[left]] -= 1` 必须写在 `left += 1` **之前**，否则会把新左端也减掉。
- 计数归零后**不需要 `del` 键**：判据只看 `cnt[j]` 的**值**，不看键的**个数**，留着一个 0 值键不影响任何判断。
- `ans` 的更新条件 `cnt0[j] > cnt[j] > ans` 是链式比较，展开成嵌套 `if` 不会更快（Python 的链式比较已做了短路），不必手写。

## 六、易错点与总结

### 易错点

- **把 `ans` 换成"当前窗口内的多数计数"**：那就得每轮重算窗口内众数（O(|Σ|) 甚至 O(n)），O(n) 直接作废。全局 `ans` 能用，是因为「窗口长度 ≤ ans + 1」这条不变量把"过期的大 `ans`"锁在了安全范围内。
- **去掉 `cnt0[j] > cnt[j]` 门槛**会导致窗口上限虚高（`"aaabb"` 示例见上）。
- **收缩与答案口径要配套**：本题是「每轮最多缩一格 + 终值 `n - left`」。长度单调不减是这套写法的前提；若哪天把窗口改成"必须逐轮合法"，长度就不再单调，必须改回"每轮取 `max`"。
- **`left` 与 `cnt` 的更新顺序**：先减计数、再移指针。
- **边界**：`len(text) == 1` 时 `ans` 停在 0、窗口长度 1（≤ ans + 1）不收缩，返回 1 ✅；全同字符串（`"aaaaa"`）`ans` 只到 4（`cnt0[a] > cnt[a]` 在第 5 个字符处不再成立），窗口长度 5 = `ans + 1`，正好不触发收缩，返回 5 ✅。
- 本题的滑窗**不保证每轮窗口合法**（`ans` 是全局量，可能大于当前窗口的真实多数计数）。别把它当成"窗口始终合法"的模板去套别的题 —— 这是"平移版"，与"收缩到合法为止"的写法是两套东西。
- 题目允许**什么都不做**，所以纯 run（不交换）也必须计入答案；本题写法里这一步是自动包含的（`ans` 可以等于窗口内的多数计数本身），但若改写 run 版，`best` 初值必须取 `ln`（不能只算 `ln + 1`）。

### 题型套路沉淀

- **「一次操作的最优收益枚举」**：凡"只能交换/翻转/修改恰好一次"的题，先问"这一次操作能带来哪几种**结构性**收益"，通常只有 2~3 种，枚举它们即可把 O(n²) 的搜索空间压成 O(n)。本题收益 = {借一格, 接通被单字符隔开的两段}。
- **「预算型最长窗口」的平移版**：判据 `窗口长度 - 窗口度量 ≤ 1` + 每轮最多缩一格 + 答案取终值 `n - left`。成立的三件套是：① 答案是**窗口长度**；② 窗口度量每轮增量 ≤ 1（超出量恒为 1，所以缩一格就够，且 `if` 与 `while` 等价）；③ 长度单调不减 ⇒ 终值即历史最大值。
- **`ans` 的语义决定一切**：普通"窗口内计数"型滑窗的 `ans`/判据只用窗口内状态；本题的 `ans` 额外要求「该字符在窗口外还有存量」（`cnt0[j] > cnt[j]`），即把**全局信息**编码进窗口判据里才成立。写同族题时先确认 `ans` 到底代表什么，再决定 `if` 条件 —— 这一步错了，示例往往还能过，容易埋雷。
- 复杂度口径：`n ≤ 20000` 的约束下，任何 O(n) 写法都是毫秒级，**不要以"常数更快"为由改结构**；判断"要不要优化"先看约束量级。
