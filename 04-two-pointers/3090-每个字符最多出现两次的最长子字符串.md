# 3090. 每个字符最多出现两次的最长子字符串

> **难度**：简单
> **标签**：哈希表 · 字符串 · 滑动窗口
> **原题链接**：https://leetcode.cn/problems/maximum-length-substring-with-two-occurrences/

---

## 一、题目描述

给定字符串 `s`，求**每个字符出现次数都不超过 2** 的最长连续子串的长度。

### 示例

```text
示例 1
输入：s = "bcbbbcba"
输出：4
解释：以下子字符串长度为 4，并且每个字符最多出现两次：
     "bcbb"（b×2, c×1）      —— 还有 "bcba"（b×2, c×1, a×1）也合法

示例 2
输入：s = "aaaa"
输出：2
解释：以下子字符串长度为 2，并且每个字符最多出现两次："aa"
```

### 约束条件

- `2 <= s.length <= 100`
- `s` 仅由小写英文字母组成

> **两个必须记住的推论**：
> 1. **`n ≤ 100` 极小** —— 这题在 LeetCode 上任何写法都是 0 ms。本笔记后半部分的性能对比**只在"泛化到任意 n"的意义下成立**，不是"这样写才不超时"。
> 2. 字符集只有 **26** 个小写字母 ⇒ 合法窗口长度 ≤ `2 × 26 = 52`。和 `3`（≤ 95）、`1100`（≤ 26）一样，**窗口长度被字符集卡死**，这类"看似 O(n·W)"的写法实际上界都是 O(n)。

---

## 二、解题思路

### 核心思想

**变长滑动窗口**：窗口 `[left, right]` 内每个字符出现次数 ≤ 2。遇到违规时，**左边界一次跳到违规字符在当前窗口内第一次出现的下一位**。

它和 `3. 无重复字符的最长子串` 是**同一条骨架**（左指针单调不回退），区别只是约束从"每字符 ≤ 1 次"放宽到"≤ 2 次"。

### 思路演进

1. **暴力解法 O(n³)**：枚举所有子串，逐个统计字符频次判 ≤ 2。

2. **暴力解法 O(n²)**：固定左端点 `i`，右端点向右扩到某字符第 3 次出现为止。两个端点各自单调，但每个 `i` 都要重扫一遍。

3. **观察到**：左端点 `L(r)`（"以 `r` 结尾的最长合法子串的左端点"）关于 `r` **单调不减** —— 这是所有滑动窗口的共同前提。于是不必对每个 `i` 重来，维护一个只向右走的 `left` 即可。

4. **关键观察（本题最省事的一步）**：追加一个字符时，**只有它自己的计数会变**，且最多从 2 涨到 3 —— **超出量恒为 1**。所以收缩不需要 `while` 一格一格挪，直接把 `left` 推到"该字符在当前窗口里**第一次**出现"的下一位，一步到位，犯规就被消掉。

5. **再进一步（省掉计数表）**：既然只需要"当前窗口内该字符第一次出现的位置"，那**计数表本身就多余**了 —— 只要记住每个字符**最近两次出现的位置**：

   ```
   第三个 c 到来时，窗口里（若还）留着 last2[c]、last1[c] 两个 c；
   想把 c 的个数压回 2，只须让 left 越过最早那个：left = last2[c] + 1
   ```

   一个字符最多 3 个下标，取最近的两个就够了。状态从"26 个整数计数"变成"26 对整数下标"，每轮只做常数次数组读写。

### 关键点

- **判据是"按值"还是"按键数"，决定了要不要 `del`。**
  - `1100`（定长版）用 `len(cnt) == k` —— **按键数**，所以出窗归零后必须 `del`，否则键永远留着；
  - 本题用 `cnt[ch] > 2` —— **按值**，计数减到 0 留着键完全无害，**不需要 `del`**。（`1100` 那个头号杀手在这里不会出现，但要知道为什么。）
- **数组版的守卫条件是 `last2[c] >= left`，不是 `last2[c] != -1`。** 只有当"上上次出现"**还在窗口内**才算构成 3 个；如果它已经滑出去了，窗口里只有 ≤ 2 个 `c`，不能把 `left` 往回拖。（和 `3` 里 `last[c] >= left` 是同一个道理。）
- **更新顺序不能颠倒**：必须 `last2[c] = last1[c]` 之后才 `last1[c] = right`，否则两个变量会同时指到最新位置。
- **跳转目标必须限定在窗口内**。用户版用 `s[left:right].find(i)` 天然做到了这一点；若图省事写成全局 `s.find(i)`，返回的可能是**早已滑出窗口**的下标，`left` 会往回跳，答案直接错。
- `mid`（用户版维护的窗口长度）**恒等于 `right - left`**，是纯冗余派生量（实测见文末）。

## 三、代码实现

### 最终代码

用户提交的版本。**注意：截图里第 1 行就是 `class Solution:`，看不到 `from collections import defaultdict`** —— 缺这一行调用时会抛 `NameError: name 'defaultdict' is not defined`（我实测确认过），所以这里补上，否则代码无法直接运行。

```python
from collections import defaultdict


class Solution:
    def maximumLengthSubstring(self, s: str) -> int:
        LetterNum = defaultdict(int)
        ans = mid = 0
        left = 0
        right = 0
        for i in s:
            right += 1
            LetterNum[i] += 1
            if LetterNum[i] > 2:
                n = s[left : right].find(i)
                for j in s[left : left + n + 1]:
                    LetterNum[j] -= 1
                mid -= n
                left += n + 1
                continue
            mid += 1
            ans = max(ans, mid)
        return ans
```

**它好在哪**：完全走的是第 4 步那条路线 —— **一次跳转、不用 `while` 收缩**，而且用 `s[left:right].find(i)` 把"窗口内第一次出现"这件事交给 C 层的 `find` 完成，逻辑短且正确（实测 0 偏差）。`mid -= n` 也推对了：收缩前 `mid = (right - left) - 1`，收缩后窗口长度 = `right - left - n - 1`，正好等于 `mid - n`。

**它的代价**：两处切片（每轮一次的 `s[left:right]`、收缩时的 `s[left:left+n+1]`），外加一个完全冗余的 `mid`。

## 四、复杂度分析

| 版本 | 时间复杂度 | 空间复杂度 |
| :--- | :--- | :--- |
| **最终代码（用户版）** | O(n·W)，W ≤ 2×26 = 52 ⇒ 实际 O(n) | O(\|Σ\|) = O(26) |
| 优化版 A（免切片） | O(n·W) 但常数更小 | O(\|Σ\|) |
| 优化版 B（计数 + while） | O(n) 摊还 | O(\|Σ\|) |
| 优化版 C（`last1/last2` 数组） | **O(n)** | O(\|Σ\|) = 26 对下标 |
| 朴素解法（固定左端点向右扩） | O(n²) | O(\|Σ\|) |
| 朴素解法（枚举子串 + 计数） | O(n³) | O(n) |
| 理论下界 | **Ω(n)** | Ω(\|Σ\|) |

> 复杂度中的 `n` 指字符串 `s` 的长度，`|Σ|` 指字符集大小（本题 = 26）。
>
> **用户版为什么是 O(n·W) 而不是 O(n²)**：合法窗口内每个字符最多 2 次、字符集只有 26 个字母 ⇒ `W ≤ 52`。每轮切片与 `find` 都是 O(W)，所以总代价 O(52n) = O(n)。只有字符集无界时它才是真 O(n²)。
>
> **移除用的那个切片为什么不用管**：每次收缩移除的字符是**永久离开窗口**的，全程累计移除量 ≤ n（实测无论哪种输入都是 99,948~99,998 字符），属于摊还 O(n)。

## 五、优化评估

**结论**：时间复杂度**已在 O(n) 下界**，算法不用动。可改的是**可运行性 + 冗余状态 + 两处重复分配**。

### 瓶颈分析

**(1) 缺 `from collections import defaultdict`。** 截图里没有，补上才能跑。

**(2) `mid` 是冗余派生量：恒等于 `right - left`。** 给用户代码插桩、2000 组随机输入逐轮断言，**0 次违反**（顺便也断言了"窗口内每字符 ≤ 2"始终成立）。和 `3` 里的 `mid` 是同一个问题。

**(3) 两处切片，开销量级完全不同。** 实测（`n = 10^5`，对用户版代码插桩统计）：

| 输入场景 | `find` 前的 `s[left:right]` 累计复制 | 移除用的 `s[left:left+n+1]` 累计 |
| :--- | ---: | ---: |
| 单字符重复 | 299,997 | 99,998 |
| 2 种字符 | 412,301 | 99,998 |
| 26 种随机 | 1,696,882 | 99,979 |
| 26 种循环（窗口恒 52） | **5,298,622** | 99,948 |

- 第一处是**每轮一次、长度 O(W)**，窗口越满越贵；
- 第二处**每次收缩一次，但摊还总计 ≈ n**，量级固定且小 —— 它不是问题。

**(4) 有意思的实测结果：只去掉切片，几乎没用。** 版本 A（把两处切片都换成免分配写法）在 `n = 10^5` 上只快 **1.09~1.15×**。说明**切片复制根本不是主瓶颈**，真正的大头是**每轮一次 `find` 的 O(W) 扫描 + 两次 `defaultdict` 操作**。想快 2~3× 必须**换掉状态本身**（版本 C）。

### 可优化空间

- **A（最小改动，只治分配）**：`s[left:right].find(i)` → `s.find(i, left, right)`；移除循环改成按下标 `for k in range(left, p+1)`。骨架一字不动。
- **C（换状态，治根）**：用 `last1[c] / last2[c]` 两个数组代替计数表 —— 每轮"两次数组读 + 两次数组写 + 一次比较"，没有哈希、没有切片、没有扫描，代码也短一半。

### 优化代码

**版本 A —— 最小改动（保留用户思路，只去掉切片与 `mid`）**

```python
from collections import defaultdict


class Solution:
    def maximumLengthSubstring(self, s: str) -> int:
        LetterNum = defaultdict(int)
        ans = left = right = 0
        for ch in s:
            right += 1
            LetterNum[ch] += 1
            if LetterNum[ch] > 2:
                p = s.find(ch, left, right)        # 直接在原串上搜 [left, right)，不切片
                for k in range(left, p + 1):       # 按下标移除，不切片
                    LetterNum[s[k]] -= 1
                left = p + 1
                continue
            if right - left > ans:                 # 窗口长度现算，不需要 mid
                ans = right - left
        return ans
```

**版本 C —— 换状态（`last1/last2` 数组，推荐）**

```python
class Solution:
    def maximumLengthSubstring(self, s: str) -> int:
        last1 = [-1] * 128        # 每个字符最近一次出现的下标
        last2 = [-1] * 128        # 每个字符上上次出现的下标
        left = ans = 0
        for right, ch in enumerate(s):
            c = ord(ch)
            if last2[c] >= left:  # 窗口里已经凑够两个 c，第三个到来 -> 左边界越过最早那个
                left = last2[c] + 1
            last2[c] = last1[c]   # 顺序不能颠倒：先平移，再记录新的
            last1[c] = right
            if right - left + 1 > ans:
                ans = right - left + 1
        return ans
```

**版本 B —— 经典模板对照（计数表 + `while` 收缩）**

```python
from collections import defaultdict


class Solution:
    def maximumLengthSubstring(self, s: str) -> int:
        cnt = defaultdict(int)
        left = ans = 0
        for right, ch in enumerate(s):
            cnt[ch] += 1
            while cnt[ch] > 2:
                cnt[s[left]] -= 1
                left += 1
            if right - left + 1 > ans:
                ans = right - left + 1
        return ans
```

> 版本 C 把 `if last2[c] >= left` 单独写成分支，而不是 `left = max(left, last2[c] + 1)` —— 两者等价，但前者把"什么时候才需要动左边界"说清楚了，也顺手避开了"忘记取 max 导致左边界倒退"的经典错误。
>
> 下面表里的 **D** 就是 C 的 `max` 写法版本（`left = max(left, last2[c] + 1)`，其余完全相同），用来对照"分支 vs `max`"这两种等价写法在常数上的差别。

**实测（本机 CPython 3.13，各取 7 次最优值，单位 ms）：**

`n = 100`（**官方约束就是这个量级**）：

| 场景 | 用户版 | A 免切片 | B 计数+while | C `last2` | D 对照 |
| :--- | ---: | ---: | ---: | ---: | ---: |
| 单字符重复 | 0.033 | 0.028 | 0.021 | **0.012** | 0.013 |
| 2 种字符 | 0.031 | 0.026 | 0.022 | **0.012** | 0.013 |
| 26 种随机 | 0.024 | 0.024 | 0.022 | **0.011** | 0.013 |
| 26 种循环（窗口恒 52） | 0.026 | 0.023 | 0.020 | **0.012** | 0.014 |

> 全部在 **0.01~0.03 ms** 量级 —— 这题在官方约束下，"哪个版本快"纯粹是学术问题。

`n = 10^5`（**只为看渐进趋势**）：

| 场景 | 用户版 | A 免切片 | B 计数+while | C `last2` | D 对照 | C 相对用户版 |
| :--- | ---: | ---: | ---: | ---: | ---: | ---: |
| 单字符重复 | 35.81 | 31.65 | 22.18 | **11.95** | 13.31 | **3.00×** |
| 2 种字符 | 31.75 | 28.16 | 22.93 | **12.98** | 13.50 | 2.45× |
| 26 种随机 | 23.54 | 21.66 | 23.81 | **11.44** | 13.28 | 2.06× |
| 26 种循环（窗口恒 52） | 35.65 | 31.04 | 21.75 | **12.25** | 12.55 | 2.91× |

**怎么读这两张表**：

- **只治分配（A）收益很小**（1.1×），**换状态（C）才是 2~3×** 的那个。结论很反直觉但很干净：**"少建对象"远不如"少做哈希和扫描"值钱。**
- `B`（经典模板）居中（约 22 ms）：它没有 `find` 扫描，但仍要维护 `dict`；而且它在**窗口长度大时**更好（22.18 → 21.75 之间几乎不随场景变化），因为 `while` 只是把滑出窗口的字符逐个处理，摊还是 O(1)。
- C 与 D 都是 O(n) 常数级差距（≈12 ms vs ≈13 ms），C 用数组免哈希，稳定快 5~10%。

### 常数级优化（可选）

- `last1/last2` 用定长 128 数组而非 `dict`：省掉字符哈希。
- `ans` 用 `if ... > ans` 而非 `ans = max(ans, ...)`：省一次函数调用。
- 若题目放宽成"每字符最多 k 次"，C 的思路可以推广（见下节），但**不要**在 k 很大时硬写 k 个变量 —— 那时用 `deque` 或直接用 B。

## 六、易错点与总结

### 易错点

- **缺 `from collections import defaultdict`**：截图里没有这一行，本笔记的「最终代码」已补上。本地复制代码时最容易漏。
- **用全局 `s.find(i)` 找跳转目标**：可能返回**已滑出窗口**的下标，`left` 会往回跳。必须限定在 `[left, right)` 内 —— 用户版的 `s[left:right].find(i)` 和版本 C 的 `last2[c] >= left` 都是在做这件事，殊途同归。
- **忘了"上上次出现"可能已经滑出窗口**：数组版一定要写 `>= left`，不能只写 `!= -1`。
- **把 `1100` 的 `len(cnt) == k` 判据搬过来**：那是定长窗口的等价式，本题是变长窗口，不成立。反过来，本题**不需要 `del`**（判据按值不按键数）—— 两个坑要分清是哪一个。
- **维护 `mid` 这种派生变量**：2000 组插桩 0 违反说明同步得没错，但收益为零、风险非零。
- **移动 `left` 后忘记同步 `LetterNum`**：用户版用 `for j in s[left:left+n+1]` 逐个减回去了，**不能只减重复的那个字符** —— 被跳过的每个字符都得从计数里去掉。

### 题型套路沉淀

- **「每字符最多出现 k 次」家族**（变长滑窗的一个完整分支）：

  | k | 状态 | 判据 | 代表题 |
  | :---: | :--- | :--- | :--- |
  | 1 | `last[c]`（上次出现） | `last[c] >= left` | `3` 无重复字符的最长子串 |
  | 2 | `last1[c]` / `last2[c]` | `last2[c] >= left` | **本题** `3090` |
  | 任意 k | 每字符一个长度 k 的 `deque`，存最近 k 次下标 | `dq[0] >= left` | 通用化写法 |
  | 任意 k | 窗口计数表 + `while` 收缩 | `cnt[ch] > k` | 通用模板（版本 B） |

- **"一次跳转"为什么成立**：每次只**追加一个**字符，它自己的计数最多从 k 涨到 k+1，**超出量恒为 1**，所以左边界跳一次就够，`while` 可以退化成 `if`。**这个前提不能乱套** —— 若是"一次加多个字符"，超出量就可能是多个，必须回到 `while`。这是本题与通用模板的**唯一分水岭**。
- **一句话判断走哪条路**：
  - 状态能写成"最近 k 次出现的下标" ⇒ 用 `last` 数组（无哈希、无删除、代码短）；
  - k 较大或状态复杂 ⇒ 老实用计数表 + `while`。
- **同型题**：`3. 无重复字符的最长子串`（**本仓库同目录已有**，本题是它的 k=2 推广）、`1493. 删掉一个元素以后全为 1 的最长子数组`（**本仓库同目录已有** —— 把"每个字符 ≤ 2 次"收窄成"只有 `0` ≤ 1 次"，并把答案口径改成"长度 − 1"；它的 `prev/prev2` 与本题的 `last1/last2` 同构）、`159. 至多包含两个不同字符的最长子串`、`340. 至多包含 K 个不同字符的最长子串`、`424. 替换后的最长重复字符`、`1004. 最大连续 1 的个数 III`、`2024. 考试的最大困扰度`、`1100. 长度为 K 的无重复字符子串`（**同目录已有**，定长对照）。

### 验证记录

- 2 个官方示例：五个版本**全部通过**（`"bcbbbcba"` → 4、`"aaaa"` → 2）。
- **基准自检**：先用 O(n³) 暴力解（枚举所有子串 + 逐字符计数）验 O(n²) 暴力解本身，800 组、`n ≤ 9`，**偏差 0 组**。
- **随机对拍**：以 O(n²) 暴力解为基准，5000 组随机输入（`n ≤ 40`，字符集取 1 / 2 / 3 / 4 / 6 / 26），**五个版本（用户版 / A / B / C / D）偏差均为 0 组**。
- **边界用例**：`"aa"` / `"aaa"` / `"aaaa"` / 60 个 `"a"`（答案恒为 2）、`"abc"`（3）、26 个字母各 1 次（26）、各 2 次（52）、各 3 次（52）、`"ab"×50`（4 —— 只有 2 种字符，窗口最多 2a+2b）、100 个 `"z"`（2）—— 五版结果一致。
- **不变量插桩**：2000 组随机输入下逐轮断言 `mid == right - left` **且**窗口内每字符计数 ≤ 2，**0 次违反**。
- **切片开销探测**：`n = 10^5` 各场景下 `find` 前切片累计复制 30 万~**530 万**字符，移除用切片累计恒为 ≈10 万（≈ n）—— 证实前者是每轮 O(W)、后者是摊还 O(1)。
