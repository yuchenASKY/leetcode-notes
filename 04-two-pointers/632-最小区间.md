# 632. 最小区间

> **难度**：困难
> **标签**：数组 · 哈希表 · 滑动窗口 · 排序 · 堆（优先队列）
> **原题链接**：https://leetcode.cn/problems/smallest-range-covering-elements-from-k-lists/

## 一、题目描述

有 `k` 个**非递减排列**的整数列表。要求找一个**最小区间** `[a, b]`，使得这 `k` 个列表中，每个列表都至少有一个数落在 `[a, b]` 里。

「最小」的比较规则：先比宽度 `b - a`，宽度相等时比左端点 `a`（`a` 更小者更小）。

### 示例

```text
示例 1:
输入：nums = [[4,10,15,24,26], [0,9,12,20], [5,18,22,30]]
输出：[20,24]
解释：
列表 1：[4,10,15,24,26]，24 在区间 [20,24] 中
列表 2：[0,9,12,20]，20 在区间 [20,24] 中
列表 3：[5,18,22,30]，22 在区间 [20,24] 中

示例 2:
输入：nums = [[1,2,3],[1,2,3],[1,2,3]]
输出：[1,1]
```

### 约束条件

- `nums.length == k`
- `1 <= k <= 3500`
- `1 <= nums[i].length <= 50`
- `-10⁵ <= nums[i][j] <= 10⁵`
- `nums[i]` 按非递减顺序排列（**每个列表内部有序**，这是关键前提）

> 元素总数上限 `N = k × 50 = 175000`。本文后续记 `N` 为所有列表的元素总数、`k` 为列表个数、`m` 为单个列表的长度。

## 二、解题思路

### 核心思想

**答案区间的两个端点一定是某个元素值，且「被选中的元素」在把所有元素按值排好序后必然构成一段连续区间。** 于是把「任意子集」的搜索空间压成「连续段」，再在排序数组上用双指针滑动，用一张`列表编号 → 计数`的表判断窗口是否覆盖满 `k` 个列表。

### 思路演进

1. **暴力解法**：枚举所有候选区间 `[a, b]`（`a`、`b` 从元素值里取），对每个区间检查是否每个列表都有元素落进去，取最优。枚举 `O(N²)` 个区间、每个检查 `O(N)` ⇒ `O(N³)`；若在整数值域 `[-10⁵, 10⁵]` 上枚举则更差（`O(V²·N)`）。

2. **瓶颈定位**：慢在「枚举了海量根本不可能是最优解的区间」。对任意一个区间，只要它覆盖了所有列表，我们就可以把左右端点分别往里收，直到两端正好压在某个被选中的元素上 —— **宽度只会变小，覆盖性不会破坏**。也就是说，最优解一定出现在「端点都是元素值」的区间里；再进一步，若某个被选中的元素集合在值序上是「不连续」的（中间隔着没被选中的元素），把中间那些元素也纳入区间，宽度不变、覆盖性不变。⇒ **最优解必然对应排序后数组上的一段连续区间**，搜索空间从 `2^N` 个子集塌缩成 `O(N²)` 个连续段。

3. **关键转化**：把 `N` 个元素全部展平成 `(值, 所属列表编号)` 并按值排序，问题变成「在排序数组上找一个最短的连续段，使其包含全部 `k` 种编号」。此时**「左端右移，覆盖所需的右端不会左移」**（因为段变短只会丢编号、不会多出编号）⇒ 左指针单调右移即可，双指针把 `O(N²)` 压成 `O(N)`。覆盖判定用一张 `编号 → 出现次数` 表，**表里的键数等于 `k` 就代表覆盖满**。

4. **最优解**：`arr.sort()` + 双指针 + 计数表，`O(N log N)`，瓶颈全部落在那一趟排序上。这也是本题用户代码的路线。

### 关键点

- **判据（本题的判据族）**：窗口 `arr[left..right]` 覆盖全部 `k` 个列表 **⟺** `len(cnt) == k`（`cnt` 的键是**列表编号**，键域是 `{0, …, k-1}`，所以 `len(cnt)` 最大就是 `k`，写成 `len(cnt) >= n` 等价）。
- **计数表按键数判定，所以归零必须 `del`**。本题关心的是「**种类够不够多**」（下界型：键数 ≥ k）。若删到 0 还留着键，键数只增不减，`while len(cnt) >= n` 一旦成立就**永久成立**，左指针会被一路推到数组末尾并越界崩溃。这是「按键数」族与「按值」族最本质的区别（按值族关心某元素出现次数是否超限，归零留不留键都不影响判定）。
- **收缩必须用 `while`，不能换成 `if`**。右端每轮只追加一个元素，但它只让「该元素所属编号」的计数 `+1`——**收缩要挪几格与追加了一个元素无关**：左端可能连续好几个元素都属于「计数 ≥ 2 的编号」，删掉一个之后窗口**仍然覆盖满全部 `k` 个列表**，必须继续删到不再覆盖为止。⇒ 这里「违规量恒为 1」的前提不成立。
- **收缩是「收缩到不合法为止」**：内层循环每轮先记录候选、再删元素，所以同一个 `right` 下会记录若干个候选，**最后留下的必然是左端最靠右、即最窄的那个**。
- **单调性前提**：固定 `right` 时，让窗口合法的左端集合是前缀 `[0 … L(right)]`，而 `L(right)` 随 `right` 单调不减 ⇒ 左指针只前进、不回退，总推进 `≤ N` 次。
- **答案是「值跨度」而不是「窗口长度」**：所以除了 `ans`，还要记住最优窗口的**位置**（用户代码用 `ansIndex` + `Length` 两个变量一起记）。

## 三、代码实现

### 最终代码

> 代码取自提交记录截图。截图里没有 `import` 行，已补 `defaultdict` 与 `inf`（LeetCode 环境里这两个名字可直接使用，本地跑需补上）。
> 第 2 行用的是内置泛型 `list[list[int]]`（Python 3.9+），因此不需要 `from typing import List`。

```python
from collections import defaultdict
from math import inf


class Solution:
    def smallestRange(self, nums: list[list[int]]) -> list[int]:
        n = len(nums)
        arr = []
        for i in range(n):
            for j in nums[i]:
                arr.append((j, i))
        arr.sort(key = lambda x: x[0])
        ans = inf
        ansIndex = 0
        left = 0
        Length = 0
        cnt = defaultdict(int)
        for right, j in enumerate(arr):
            cnt[j[1]] += 1
            while len(cnt) >= n:
                if ans > j[0] - arr[left][0]:
                    ans = j[0] - arr[left][0]
                    Length = right - left + 1
                    ansIndex = left
                cnt[arr[left][1]] -= 1
                if cnt[arr[left][1]] == 0:
                    del cnt[arr[left][1]]
                left += 1
        return [arr[ansIndex][0], arr[ansIndex + Length - 1][0]]
```

**正确性（不变量 → 归纳步 → 终态）**

- **不变量 A**：进入内层 `while` 体时，窗口 `arr[left..right]` 覆盖全部 `k` 个列表。依据：`len(cnt) >= n` ⇒ `cnt` 的键数已达 `k` ⇒ `{0..k-1}` 全部出现过。
- **不变量 B**：每轮 `for right` 结束后，`ans` 等于「右端 ≤ 当前 `right` 的所有合法窗口」中的最小宽度。归纳步：内层循环从上一层留下的 `left` 起把窗口一路收到「再删一格就不再覆盖」为止，中途每次仍覆盖时就记录一次，因此覆盖了左端可取的全部合法位置（含最靠右的那个）；比较用严格 `>`，宽度相等时不覆盖，于是**同宽度保留先出现的（左端更小者）**，正好满足题目的并列规则 `a` 更小者更优。
- **终态**：`right` 遍历完所有元素，`ans` 已是全局最小宽度；`ansIndex + Length - 1` 就是最优窗口的右端下标（`= left + (right - left + 1) - 1 = right`），两点取值即答案。

## 四、复杂度分析

| 版本 | 时间复杂度 | 空间复杂度 |
| :--- | :--- | :--- |
| **最终代码** | `O(N log N)` | `O(N)` |
| 朴素解法（枚举值域区间 + 覆盖检查） | `O(V² · N)`，`V` 为值域宽度 | `O(1)` |
| 朴素解法（排序后枚举连续段） | `O(N²)` | `O(N)` |

> 复杂度中的 `n` / `N` 指：**所有列表的元素总数** `N = Σ len(nums[i])`（上界 `175000`）；`k` 指列表个数（上界 `3500`）；`V` 指值域宽度（`≈ 2×10⁵`）。
>

> 本题的时间几乎全部落在排序上，双指针部分没有可压缩空间。

## 五、优化评估

**结论**：双指针部分**已是最优**（`O(N)`，每个元素进出各一次，不可能更好）；但**排序可以绕开一半**——只需在 `k` 个有序列表上做 k 路归并，用一个小顶堆维护「每个列表当前指针」的 `min/max`，即可把 `O(N log N)` 降到 `O(N log k)`。

### 瓶颈分析

- 排序 `N = 175000` 个 `(值, 编号)` 元组是主开销；`k ≤ 3500 ≪ N`，被排序的元素里存在大量「按列表划分」的冗余顺序信息 —— 每个列表**本来就有序**，这层信息被白扔了。
- 双指针自身 `O(N)`：每个元素进窗口一次、出窗口一次，是本题的天然下界（必须至少读一遍数据），无优化空间。
- 空间：`arr` 占 `O(N)`；堆版完全不建这个数组，额外空间只有 `O(k)`。

### 可优化空间：k 路归并 + 小顶堆

换个角度：不要展平重排，而是**同时站在 `k` 个列表上各拿一个指针**。堆里恒有 `k` 个元素 `(值, 列表号, 下标)`，于是：

- 这 `k` 个值一定**覆盖了全部 `k` 个列表** ⇒ `[堆顶值, 这 k 个值里的最大值]` 永远是一个合法候选区间；
- 每次弹出堆顶（当前最小值），把它所属列表的指针往后挪一格、新值入堆，同时更新维护的 `max` ⇒ 得到下一个候选；
- 某个列表的指针走到末尾时，再往后就不可能覆盖全部列表了 ⇒ 终止。

`max` 用一个变量增量维护（新入堆的值只可能变大），不必每次扫堆，因此每轮代价 `O(log k)`，总计 `O(N log k)`。

### 优化代码

```python
import heapq
from math import inf


class Solution:
    def smallestRange(self, nums: list[list[int]]) -> list[int]:
        k = len(nums)
        # 每个列表各取第一个元素入堆：(值, 列表号, 该列表内的下标)
        heap = [(nums[i][0], i, 0) for i in range(k)]
        heapq.heapify(heap)
        cur_max = max(nums[i][0] for i in range(k))   # 堆内 k 个值的最大值

        best_w, best_lo, best_hi = inf, 0, 0
        while True:
            val, i, j = heapq.heappop(heap)
            if cur_max - val < best_w:                # 严格小于 → 同宽度保留左端更小者
                best_w, best_lo, best_hi = cur_max - val, val, cur_max
            if j + 1 == len(nums[i]):                 # 该列表耗尽 → 不可能再覆盖全部列表
                break
            nxt = nums[i][j + 1]
            heapq.heappush(heap, (nxt, i, j + 1))
            if nxt > cur_max:
                cur_max = nxt

        return [best_lo, best_hi]
```

**优化理由**：堆内恒有 `k` 个值、每列表各一个 ⇒ 每轮得到的一定是合法候选区间，且**最优解的左端点必然在某一轮作为堆顶出现过**（左端点所在列表的指针推进到它时），因此候选集合覆盖了最优解。复杂度 `O(N log k)`；`k ≤ 3500 ≪ N` 时 `log k < log N`。

**实测提速（同一轮、同一台机器，各取 9 轮最优值，单位 ms）**

| 场景 | 截图版（排序 + 双指针） | 堆版 | 提速 |
| :--- | ---: | ---: | ---: |
| A：`k=200, m=50`，值域 ≈ 2×10⁵（`N=10⁴`） | 4.7 | 3.6 | 1.31× |
| B：`k=3500, m=50`，值域 ≈ 2×10⁵（`N=1.75×10⁵`） | 146.3 | 98.5 | 1.48× |
| C：`k=3500, m=50`，值域 `0..9`（重复度高） | 102.5 | 80.8 | 1.27× |

> 三档输入下两个版本给出的答案完全一致。
> **注意 `O(N log k)` 只换来 1.3~1.5×**：`list.sort()` 是 C 层实现（Timsort，元组比较高度特化），而 `heapq` 的每次 `heappush/heappop` 都要在 Python 层做元组比较。**大 O 更优 ≠ 更快**，本题里 C 实现的排序把 `log N / log k` 那点理论差距几乎吃掉了。若追求极致，还可考虑值域只有 `2×10⁵` 宽这一事实用计数/基数排序把排序压到 `O(N + V)`（未实测，不宣称收益）。

### 常数级优化（可选）

- `arr.sort(key=lambda x: x[0])` 的 `key` 是有意义的：不加 `key` 时元组比较会先比值、再比「列表编号」这第二个字段；加 `key` 后比较只发生在第一个字段上，避免无谓的二次比较。
- `Length` 是**派生量**：`ansIndex + Length - 1` 恒等于更新那一刻的 `right`（纯代数：`left + (right - left + 1) - 1 = right`）。理论上可以只记 `bestRight`、省掉一个变量；这只影响变量个数、不改变复杂度，**未做实测，不宣称性能收益**，保留原写法可读性更好。
- `while len(cnt) >= n` 里的 `>=` 与 `==` 等价（键域是 `0..k-1`，`len(cnt)` 不可能超过 `k`），属防御性写法。

## 六、易错点与总结

### 易错点

- **`cnt` 归零不 `del` ⇒ 直接崩**：键数只增不减，`len(cnt) >= n` 一旦成立就永久成立，内层循环永不退出，`left` 被推到数组末尾后 `arr[left][1]` 越界。这是「按键数」族必须删键的原因（静态推导，未实测）。
- **把 `while` 换成 `if` ⇒ 答案偏大**：`if` 版每轮最多挪一格左端（平移版），窗口收敛得更慢。它记录的候选其实**都是合法区间**（`len(cnt) >= n` 只会在覆盖满时成立），错在「不够窄」上 —— **会漏掉更优解，而不是产生非法区间**。实测最小反例：

  ```text
  nums = [[-2,-1], [-1,0]]
  真值   = [-1,-1]   （宽 0：两个列表都含 -1）
  if 版  = [-2,-1]   （宽 1：更宽的答案被当成了最优）
  ```

  ⇒ 这类「最短 / 最小化」型滑窗**不能**用平移版省掉长度变量；平移版那套「左指针每轮最多前进一格 ⇒ 长度单调不减」的救命稻草只对**最长**型成立。
- **本题答案口径是「值跨度」，不是「窗口长度」**：所以「长度单调不减」这类论证在本题里根本不成立（最优解是让跨度最小，跨度序列可以上下波动），必须老老实实每轮取 `min`，并且额外记录最优窗口的位置。
- **并列规则**：宽度相等时要返回**左端点更小**的区间。用户代码用严格 `>` 比较天然满足（同宽度不覆盖，保留先出现者）；若手滑写成 `>=`，同宽度会被后出现（左端更大）的窗口覆盖掉。
- **不要忘记「每个列表本来就非递减」**：既可以用它把 `O(N²)` 的连续段枚举解释清楚，也可以用它省掉整趟排序（第五节堆版）。

### 题型套路沉淀

- **覆盖型滑窗的判据**：「每个分组各取至少一个」翻译成「`cnt` 的**键数** == 分组数」；键是**分组编号**、不是元素值。
- **按键数族的两个必备动作**：① 归零必须 `del`；② 收缩判据必须是「整个窗口」的判据（`len(cnt) vs k`），不能写成「只看新加入的那个元素」的局部判据。
- **收缩方式的判别法**：问一句「删掉一个元素之后，窗口有没有可能**仍然满足**约束？」——会，就得用 `while` 收到底；只有在「一次追加最多造成 1 个单位违规」时才可能退化成 `if`。
- **下界型 vs 上界型**：本题是「种类数 ≥ k（要够多）」的下界型，收缩发生在**达标之后**；「种类数 ≤ K（不能多）」是上界型，收缩发生在**超标之后**。两者方向相反，判据不要互串。
- **多序列各取一个 ⇒ 堆**：凡是「来自 `k` 个有序序列、每序列各取一个」的问题，都可以摆 `k` 个指针 + 小顶堆维护 `min`（堆顶）与 `max`（增量变量），把「排序全部元素」降成「排序 `k` 个候选」。
