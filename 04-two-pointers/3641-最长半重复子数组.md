# 3641. 最长半重复子数组

> **难度**：中等
> **标签**：数组 · 哈希表 · 滑动窗口
> **原题链接**：https://leetcode.cn/problems/longest-semi-repeating-subarray/

---

## 一、题目描述

给定一个长度为 `n` 的整数数组 `nums` 和一个整数 `k`。

**半重复子数组**是指最多有 `k` 个元素重复（即出现超过一次）的连续子数组。

返回 `nums` 中最长半重复子数组的长度。

> 关键在于「`k` 个元素」中的元素是**去重后按种类计**的：一个子数组里不管某个值出现了 3 次还是 30 次，它都只贡献 **1** 个「重复元素」名额。

### 示例

```text
示例 1：
输入：nums = [1,2,3,1,2,3,4], k = 2
输出：6
解释：最长的半重复子数组是 [2,3,1,2,3,4]，其中有 2 个重复元素（2 和 3）。

示例 2：
输入：nums = [1,1,1,1,1], k = 4
输出：5
解释：最长的半重复子数组是 [1,1,1,1,1]，其中只有 1 个重复元素（1）。

示例 3：
输入：nums = [1,1,1,1,1], k = 0
输出：1
解释：最长的半重复子数组是 [1]，它没有重复元素。
```

### 约束条件

- `1 <= nums.length <= 10^5`
- `1 <= nums[i] <= 10^5`
- `0 <= k <= nums.length`

## 二、解题思路

### 核心思想

**滑动窗口 + 增量维护「窗口内重复元素的种类数」。**

给窗口定一条判据：设

```text
rep = |{ x : cnt[x] >= 2 }|        # cnt[x] = 窗口内 x 的出现次数
```

则**窗口合法 ⟺ rep ≤ k**。由于每轮只从右侧加入一个元素，`rep` 的更新是 O(1) 的增量：

- 加入 `x` 后 `cnt[x]` 恰好变成 2 → 有一种新元素「升级」成重复元素，`rep += 1`；
- 移出 `y` 后 `cnt[y]` 恰好降回 1 → 有一种元素「降级」回单次，`rep -= 1`。

于是整个算法只需右指针走一遍、左指针最多走一遍。

### 思路演进

1. **暴力解法**：枚举所有 O(n²) 个子数组，对每个子数组重新统计每个值的出现次数、数出「出现 ≥ 2 次」的值的个数，判断是否 ≤ k。每个子数组统计是 O(n)，总时间 **O(n³)**；即便「枚举左端后向右增量扩展」也只能降到 **O(n²)**。题面 `n ≤ 10^5`，O(n²) = 10^10 次操作，必然超时。

2. **瓶颈定位**：相邻子数组之间共享绝大多数元素，重新统计是纯粹的重复劳动。而固定右端 `r` 时，左端 `l` 越往右，窗口越小，**任何元素的计数只会下降，「重复元素种类数」只可能减少** —— 判据 `rep ≤ k` 对「从左侧删元素」是**前缀封闭**的。这个单调性正是双指针的立足点。

3. **关键转化**：把「子数组整体统计」换成「窗口内 O(1) 增量维护」。原文里 `rep` 是「数一遍窗口」算出来的派生量，但注意到 `cnt[x]` 每次只变 ±1，`rep` 的**变化量**只发生在 `cnt[x]` 跨越 1↔2 这一刻，因此可以从上一轮的 `rep` 直接推出本轮的 `rep`，不必重扫窗口。

   > 一句话说清「为什么原来不行、现在为什么行」：原来每换一个子数组就要 O(n) 重数一遍；现在窗口每移动一格只让**一个**值的计数 ±1，而 `rep` 只在这一个值跨过「2」这条线时才变，所以能 O(1) 跟进。

4. **最优解**：上面第 3 步的转化让窗口的扩张/收缩都变成 O(1)，左指针全程只前进不回退，总时间 **O(n)**，达到理论下界（任何算法都必须至少读一遍数组才能知道元素，`Ω(n)`）。

### 关键点

- **判据按「键数」而不是按「值」**：超限的量是「重复元素的**种类数**」，不是某个元素的出现次数。这决定了两件事：
  1. 收缩时必须把「不再重复」的值**从集合中删掉**，否则集合只增不减，`while` 会一路把左指针推到越界；
  2. 「一种元素重复多少次」无关紧要，`k` 判的是种类。
- **登记时机必须精确**：只在 `cnt[x] == 2`（刚刚成为重复元素）时登记一次，写成 `cnt[x] >= 2` 会把同一个值重复登记许多次，`rep` 直接算错。`== 2` 成立的前提是「每轮只加入一个元素」—— 本题成立；若改成一次加一批，就必须换成显式的集合（`set` 天然去重）。
- **`rep` 的超出量恒为 1，但左指针可能要走多步**：每轮只加一个元素 ⇒ `rep` 每轮最多 +1 ⇒ 违规的量是 1。但「移出 `nums[left]` 一格」**不一定**能让 `rep` 减 1 —— 若 `nums[left]` 在窗口内出现次数 > 2，移出一个副本后它仍然是重复元素。所以 `while` 循环仍可能连走多步（实测 `nums=[1,1,1,2,2], k=1` 需要连收两步）。
- **答案口径必须配 `while` 版**：`while` 版是「收缩到合法为止」，窗口长度序列**不单调**，必须每轮 `ans = max(ans, ...)`；用终值 `n - left` 会错（实测见第五部分）。

## 三、代码实现

### 最终代码

> 截图里只有 `class Solution:`，缺 `from typing import List` 与 `from collections import defaultdict`，这里已补齐（不补会在**调用时**抛 `NameError`，只做 `exec` 校验发现不了）。

```python
from collections import defaultdict
from typing import List


class Solution:
    def longestSubarray(self, nums: List[int], k: int) -> int:
        cnt = defaultdict(int)      # 窗口内每个值的出现次数
        cnt0 = []                   # 窗口内出现次数 >= 2 的值（重复元素集合，用 list 当 set 用）
        left = ans = 0
        for right, j in enumerate(nums):
            cnt[j] += 1
            if cnt[j] == 2:                 # 该值首次「升级」为重复元素，登记一次
                cnt0.append(j)
            while len(cnt0) > k:            # 重复元素种类数超出预算，收缩左边界
                cnt[nums[left]] -= 1
                if cnt[nums[left]] == 1:    # 该值从「重复」降级回「单次」
                    if nums[left] in cnt0:
                        cnt0.remove(nums[left])
                left += 1
            ans = max(ans, right - left + 1)
        return ans
```

## 四、复杂度分析

| 版本 | 时间复杂度 | 空间复杂度 |
| :--- | :--- | :--- |
| **最终代码**（`cnt0` 用 list） | 均摊 O(n)，**最坏 O(n·k)** | O(n) |
| 优化版（`cnt0` 换 set 或只留计数器） | **O(n)** | O(n) |
| 朴素解法（枚举左端后向右增量扩展） | O(n²) | O(n) |
| 朴素解法（每个子数组重新统计） | O(n³) | O(n) |
| 理论下界 | Ω(n) | Ω(min(n, 值域)) |

> 复杂度中的 **n 指数组 `nums` 的长度**；`k` 是题面允许的重复元素种类数上限（`0 ≤ k ≤ n`）；「值域」指 `nums[i]` 的取值上限 `10^5`。

**为什么最终代码是「均摊 O(n)，最坏 O(n·k)」**：右指针走 n 步、左指针全程最多走 n 步，这部分是 O(n)。但 `cnt0` 是 list，`nums[left] in cnt0` 与 `cnt0.remove(...)` 都是 O(len(cnt0))，而 `len(cnt0)` 可以长到 `k + 1` 个。触发收缩的轮数最坏是 Θ(n)，于是出现一个额外的 `O(n·k)` 项。当 `k` 与 `n` 同阶、且输入被构造得让 `cnt0` 长期维持在满预算附近时，这一项会盖过主项（实测见第五部分）。

## 五、优化评估

**结论**：**正确性没问题，但复杂度有实打实的优化空间。** `cnt0` 用 list 当 set 用，把「均摊 O(n)」拖出了 `O(n·k)` 的最坏项；换成 `set`（或干脆只留一个计数器 `rep`）即可拿到确定的 O(n)。在题面约束上限（n = 10⁵）构造出的真·最坏输入上，实测提速 **5.3～6.2 倍**（165.7 ms → 26.9 ms）。

> **口径说明**：本题约束 `n ≤ 10^5` 属于「约束够大、谈得上性能」的一档。实测最坏档 165.7 ms，**在 10⁵ 量级下不会超时** —— 所以这是「值得改」而不是「必须改」。但 `O(n·k)` 这个最坏项是真实存在的，同样的写法一旦搬到更宽松的规模上就会失控。

### 瓶颈分析

时间几乎全部耗在收缩分支里的两次 list 操作上：

- `nums[left] in cnt0` —— 线性扫描，最坏扫满 `len(cnt0)`；
- `cnt0.remove(nums[left])` —— 先线性定位、再把后续元素整体前移，最坏搬移 `len(cnt0)` 个元素。

两者都是**按元素个数计费**的 C 层操作，单次常数很小（这也正是它在 10⁵ 规模下仍然不超时的原因），但触发次数 × 每次长度乘积起来就是 `O(n·k)`。

### 可优化空间

`rep` 需要的只是「有多少**种**重复元素」这个**数量**，而不是「具体是哪几种」。因此：

1. **最小改动**：把 `cnt0` 换成 `set` —— `add` / `discard` 均摊 O(1)，语义与原来完全一致；
2. **最省**：连集合都不要，只维护一个整数 `rep`。收缩时判断「`cnt[y]` 是否从 2 降到 1」即可决定 `rep` 是否 −1，不需要知道 `y` 是谁。

两种改法都把最坏项消掉，成为确定的 O(n)。

### 优化代码

```python
from collections import defaultdict
from typing import List


class Solution:
    def longestSubarray(self, nums: List[int], k: int) -> int:
        cnt = defaultdict(int)
        rep = 0                     # 窗口内出现次数 >= 2 的「值」的个数
        left = ans = 0
        for right, x in enumerate(nums):
            cnt[x] += 1
            if cnt[x] == 2:
                rep += 1
            while rep > k:
                y = nums[left]
                cnt[y] -= 1
                if cnt[y] == 1:     # y 从重复降级回单次
                    rep -= 1
                left += 1
            ans = max(ans, right - left + 1)
        return ans
```

**优化理由**：`rep` 是个**派生量**，但它只需要「个数」这一个信息，就用一个整数存它，把原来「维护集合 → 取 `len()`」的间接写法直接消掉，每次更新都是 O(1) 的整数加减。左指针全程只前进 ≤ n 步，因此总时间严格 O(n)。

**实测提速**（n = 3×10⁴ 与 n = 10⁵ 四档场景，9 次轮转取最优值，同批次同机）：

| 场景 | 原始 list 版 | `set` 版 | 计数器版 |
| :--- | :--- | :--- | :--- |
| A 值域小、重复密集（n=3万, k=200） | 18.69 ms | 10.39 ms（**1.80×**） | 9.01 ms（**2.07×**） |
| B 值域 ≈ n、几乎全不同（n=3万, k=1） | 8.14 ms | 8.16 ms（1.00×） | 7.87 ms（1.03×） |
| C 循环排列（n=3万, 值域 n/3, k=值域−1） | 18.84 ms | 8.34 ms（**2.26×**） | 7.13 ms（**2.64×**） |
| **D 最坏档（n=10万, 值域 n/4, k=值域−1）** | **165.72 ms** | **31.11 ms（5.33×）** | **26.86 ms（6.17×）** |

- 场景 B 三版几乎并排：窗口内所有值都不同，`cnt0` 恒空、`while` 从不执行，说明**差异全部来自收缩分支**，与主循环无关。
- 场景 D 是按「开销 ≈ Σ len(cnt0) ≈ (n − 2V)·V」在 `V = n/4` 处取极大值构造的循环输入（`nums = [1..V]` 重复 4 遍，`k = V−1`），开销约 2.5×10⁹ 次元素操作 —— 这是本题能构造出的、对 list 版最不利的输入，也正是在这里差距从前三档的 2 倍级放大到 **5～6 倍**。
- 计数器版比 `set` 版还快：省掉了集合的哈希计算与元素对象管理。

### 常数级优化（可选）

- 值域固定为 `1..10^5`，可用定长数组 `cnt = [0] * (max(nums) + 1)` 替代 `defaultdict`，省掉哈希与缺省值开销；代价是要先扫一遍求 `max(nums)`。**此项未做实测，收益不作为结论。**
- `enumerate(nums)` 已同时给出下标与值，不必再写 `nums[right]` 二次索引，原作者在这里写法是正确的。

## 六、易错点与总结

### 易错点

- **把「种类数」当成「总次数」**：判据是 `|{x : cnt[x] ≥ 2}| ≤ k`，即**去重后的种类**。一个值出现 100 次也只占 1 个名额。
- **登记条件写成 `cnt[x] >= 2`**：会让同一个值被反复登记，`rep` 只增不减。必须用 `== 2`（首次跨过这条线）。注意 `== 2` 成立的前提是「每轮只加入一个元素」。
- **收缩时忘记删键**：本族是**按「键数」**判定的，必须把「不再重复」的值从集合里移除。不删的话集合单调增，`while` 会一直收缩直到 `left` 越界。
- **`while` 版配错答案口径**：`while` 版长度序列**不单调**，必须每轮取 `max`。实测把口径换成终值 `n - left`，在 20000 组穷举里错 **7.23%**（1446 组）。
- **误以为「超出量恒为 1」⇒「左指针挪一格就够」**：违规的量确实是 1（每轮只加一个元素），但要挪几格是另一回事。`nums[left]` 的计数可能 > 2，移出它不会让 `rep` 减少，`while` 就要继续走。
- **截图代码缺 import**：`List` / `defaultdict` 都没引入，直接提交会报 `NameError`。

### 题型套路沉淀

**队列定位**：凡题面约束形如「窗口内**最多 k 种 / k 个满足某条件的元素**」，而判定对象是**种类**而非总量，就走这一族。

- **先分清两类判据**（本族最容易串用的地方）：

  | 类型 | 超限的是什么 | 收缩时要不要删键 |
  | :--- | :--- | :--- |
  | **按键数**（本题） | 不同种类数 > K | **必须删键**，否则键数只增不减 |
  | **按值** | 单个元素的计数 > K | 不需要删键，计数归零就行 |

  本题是「按键数」：判据 `len(rep) > k` 是**关于整个窗口**成立的**整体判据**，不是「只看刚加进来的那个元素」（后者发现不了窗口里残留的其他违规）。

- **判据的增量维护**：凡是形如「窗口内满足某谓词 P 的元素个数 ≤ K」的约束，都先问一句「P 会不会因为单个值的计数跨过某个阈值而改变」。会，就能 O(1) 增量更新；`rep` 在 `cnt` 跨越 1↔2 时 ±1，就是这一族的标准型。

- **「收缩方式 × 答案口径」四象限**（本题实测，20000 组穷举）：

  | 收缩方式 | 答案口径 | 本题结果 |
  | :--- | :--- | :--- |
  | `while` | 每轮取 `max` | ✅ 0 / 20000（原始代码） |
  | `while` | 终值 `n - left` | ❌ **1446 / 20000（7.23%）** |
  | `if`（每轮最多挪一格） | 终值 `n - left` | ✅ 0 / 20000 |
  | `if`（每轮最多挪一格） | 每轮取 `max` | ✅ 0 / 20000 |

  只有「换一半」会错：`while` 版是收缩到合法为止、长度序列会下降，必须每轮记 `max`；`if` 版左指针每轮最多前进一格、长度单调不减，两种口径才等价。

  > 最小反例 **`nums = [2,1,1], k = 0`**：正确答案 2（子数组 `[2,1]`），`while` + 终值口径得 1。
  > 原因是这个窗口长度曾经到过 2（在 `right=1`、`left=0` 时），随后为了排除 `[1,1]` 把左指针连推到 2，中途的最大值被丢掉 —— 而终值口径只认最后一轮。

- **两个问题要分开问**：`if` 版（只挪一格）**不保证每轮窗口合法**（实测 `nums=[1,1,1,2,2], k=1` 时窗口会短暂停在非法的 `[1,1,2,2]` 上），但**答案仍然正确**（0/20000）。合法性不成立 ≠ 答案不正确，因为「从左侧删除元素不会让非法变合法」这条前缀封闭性成立，长度单调不减的 `if` 版最终仍会停到正确答案上。

- **模板骨架**：

  ```python
  cnt = defaultdict(int)   # 值 -> 窗口内出现次数
  rep = 0                  # 窗口内「出现次数 >= 2 的值的个数」= 判据量
  left = ans = 0
  for right, x in enumerate(nums):
      cnt[x] += 1
      if cnt[x] == 2: rep += 1          # 只在这里 +1
      while rep > k:                    # 整体判据
          y = nums[left]
          cnt[y] -= 1
          if cnt[y] == 1: rep -= 1      # 只在这里 -1
          left += 1
      ans = max(ans, right - left + 1)
  ```
