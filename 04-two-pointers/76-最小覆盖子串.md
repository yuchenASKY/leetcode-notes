# 76. 最小覆盖子串

> **难度**：困难
> **标签**：哈希表 · 字符串 · 滑动窗口
> **原题链接**：https://leetcode.cn/problems/minimum-window-substring/

---

## 一、题目描述

给定字符串 `s`（长度 `m`）和 `t`（长度 `n`），在 `s` 中找一个**最短的子串**，要求它包含 `t` 中的**每一个字符，重复次数也要够**。不存在这样的子串则返回 `""`。题目保证答案唯一。

### 示例

```text
输入：s = "ADOBECODEBANC", t = "ABC"
输出："BANC"
解释："BANC" 包含 'A'、'B'、'C'，且是长度最小的满足条件的子串。

输入：s = "a", t = "a"
输出："a"

输入：s = "a", t = "aa"
输出：""
解释：s 里只有一个 'a'，凑不出两个，返回空串。
```

### 约束条件

- `1 <= m, n <= 10^5`
- `s` 和 `t` 由大小写英文字母组成（字母表大小 |Σ| = 52）
- 测试用例保证答案唯一（如果存在）
- **进阶要求**：设计 O(m + n) 的算法

---

## 二、解题思路

### 核心思想

**用两个单向指针把 O(n²) 个子串的枚举压成一次扫描。** 右指针负责"扩张"直到窗口覆盖 `t`，左指针负责"收缩"到刚好不覆盖，中途记录最短的一次。合法性判据只有一条：**窗口内已达标的字符种类数 == `t` 的不同字符种类数**。

### 思路演进

1. **暴力解法**：枚举所有 `O(n²)` 个子串，每个子串重新统计一遍字符计数再判断是否覆盖 `t`。时间 O(n²·|Σ|)。n = 10^5 时是 10^10 量级，完全不可行。

2. **瓶颈定位**：慢在两处 ——
   - 相邻子串之间**重复统计**：`[l, r]` 与 `[l, r+1]` 的计数只差一个字符，却每次都从头数一遍；
   - 更根本的是，对每个左端 `l` 都**从头重新找一个右端 `r`**，而左右端点之间其实有单调性可用。

3. **关键转化**：两个单调性观察把双指针立起来 ——
   - **扩张单调**：固定左端 `l`，右端 `r` 增大时窗口只增不减 ⇒ 覆盖性**一旦成立就永远成立**。所以对每个 `l`，合法的 `r` 构成一个后缀，只需找**最小的那一个**。
   - **收缩单调**：固定右端 `r`，左端 `l` 增大时窗口只减不增 ⇒ 覆盖性**一旦破坏就不会恢复**（约束对"从左侧删元素"是前缀封闭的）。所以 `l` 不需要回退，可以做成**只前进**的指针。
   - 两条合起来：`r` 单调右移、`l` 单调右移，两者总移动次数都 ≤ n ⇒ 摊还 O(n)。**为什么原来不行、现在行**：原来每个 `l` 都要重新扫右边，是因为没有用上"窗口变短不会让覆盖恢复"这条单调性；用上之后 `l` 直接跟着 `r` 走即可。

4. **最优解**：三张哈希表 + 一条判据。

   | 表 | 含义 |
   | :--- | :--- |
   | `cnt0` | `t` 的需求计数（每个字符要几个），建表一次 O(m) |
   | `cnt1` | 当前窗口 `[left, right]` 的字符计数 |
   | `cnt2` | **已达标的字符集合**：`cnt2[c] = 1` 表示 `c ∈ t` 且窗口里 `c` 的数量已 ≥ 需求 |

   判据：**窗口覆盖 `t` ⟺ `len(cnt2) == len(cnt0)`**（`len(cnt0)` 就是 `distinct(t)` 的种类数）。

   右端每进来一个字符就更新一次计数；只要判据成立，就用 `while` 反复收缩左端并把当前窗口记一次账，直到判据被破坏。

### 关键点

- **判据是"比较键数"，不是"比较值"**：`cnt2` 只有集合语义（值恒为 1），所以当窗口里某字符的数量掉回需求之下时**必须 `del cnt2[c]`**。忘了删键 → `cnt2` 的键数只增不减 → 窗口被判成"永远合法" → 左指针被一路推到越界、答案全错。这是本族最经典的坑。
- **`del cnt2[s[left]]` 不会 `KeyError`**，理由是一条不变量：进入 `while` 体时判据成立 ⇒ 对 ∀`c ∈ t` 都有 `cnt1[c] >= cnt0[c]`（因为此时所有种类都在 `cnt2` 里）且 `cnt2 = {c ∈ t : cnt1[c] >= cnt0[c]}`。于是本次 `cnt1[s[left]] -= 1` 之后若出现 `< cnt0[s[left]]`，只能是"减之前恰好等于"，那个键一定在 `cnt2` 里，删得掉。
- **不在 `t` 里的字符只更新 `cnt1`、直接 `continue`**：`cnt1` 记的是窗口内全部字符（键数最多 |Σ|），但不参与判据。
- **`while` 必须收缩到判据被破坏为止，不能用 `if` 只缩一格**：一次收缩能挪多少格完全取决于窗口的冗余度，和"右端只加了一个字符"没有关系（实测退化输入下单次要挪上万格）。所以这里**用不了**"每轮增量 ≤ 1 ⇒ `while` 退化成 `if`"那条简化。
- **记录必须发生在收缩之前**（或"收缩后若仍合法再记录"）。因为一次收缩过程里每一步都可能刷新最短记录，先收缩再记录会把非法窗口写进答案。
- 答案唯一 ⇒ 比较用严格小于 `ansLength > right - left + 1` 即可，不必处理并列解。

## 三、代码实现

### 最终代码

> 来源：本人已提交通过的 AC 版本（截图）。
> 截图里没有 import，已按仓库约定补上 `defaultdict` / `inf`。
> ⚠️ 截图底部把最后两行裁掉了，已按结构补全为 `left += 1` / `return ans`，并用 3 个官方示例确认补全无误（见第七节）。

```python
from collections import defaultdict
from math import inf


class Solution:
    def minWindow(self, s: str, t: str) -> str:
        ans = ''
        ansLength = inf
        left = 0
        cnt0 = defaultdict(int)   # t 的需求计数
        cnt1 = defaultdict(int)   # 当前窗口 [left, right] 的字符计数
        cnt2 = defaultdict(int)   # 已达标的字符集合，值恒为 1
        for j in t:
            cnt0[j] += 1
        for right, j in enumerate(s):
            cnt1[j] += 1
            if j not in t:
                continue
            if cnt1[j] >= cnt0[j]:
                cnt2[j] = 1
            while len(cnt2) == len(cnt0):
                if ansLength > right - left + 1:
                    ansLength = right - left + 1
                    ans = s[left: right + 1]
                cnt1[s[left]] -= 1
                if s[left] in t:
                    if cnt1[s[left]] < cnt0[s[left]]:
                        del cnt2[s[left]]
                left += 1
        return ans
```

## 四、复杂度分析

| 版本 | 时间复杂度 | 空间复杂度 |
| :--- | :--- | :--- |
| **最终代码（原版）** | 字典部分是摊还 O(m + n)，但夹着两个会退化的项：`in t` 字符串查找最坏 O(m)/次 ⇒ O(n·m)，答案切片最坏 O(n²) ⇒ **严格最坏 O(n·m + n²)** | O(\|Σ\|) |

## 五、优化评估

**结论**：**算法骨架已是本题最优**（摊还 O(m + n)，与理论下界同级，无需换算法），但**实现里有两处会把它拖出 O(m + n)**，两处都实测确认过，改掉即可。

### 瓶颈分析

两处都来自"顺手写法"，和算法无关：

1. **`ans = s[left: right + 1]` 每刷新一次就拷一份子串。**
   问题不在"切片本身贵"，而在**一次收缩过程里每一步都在刷新记录**：窗口长度从 L 一路递减到 L_min，每减一格都满足 `ansLength > len`，于是每格都拷一次，总拷贝量 ≈ L²/2 ⇒ 最坏 O(n²)。
   触发条件是"首个合法窗口很长、且左端要连续收缩很多格"的输入，例如 `s = "a"×(n−1) + "b"`, `t = "ab"`。

2. **`j not in t` / `s[left] in t` 是对字符串做成员判断，最坏 O(m)。**
   CPython 对单字符针会走 memchr，常数极小，但**复杂度仍是 O(m)**，而且主循环每轮都做一次 ⇒ O(n·m)。当 `t` 很长、`s` 里的字符不在 `t` 中时会退化成对 `t` 的全表扫描。
   把判断对象换成 `cnt0`（字典）就是 O(1)。

3. 附带项：三张 `defaultdict` 的哈希开销。做了对照（见下表 V4），**换定长数组并没有稳定收益**，不值得为它牺牲可读性。

### 可优化空间

- 时间：改掉上面两处后就是严格 O(m + n)，没有进一步的空间 —— 下界是 Ω(m + n)，已经贴上。
- 空间：可选做法是把三张表并成一张（V3 的 `missing` 标量法），空间意义不大（都是 O(|Σ|)），但**常数收益明显**。

### 优化代码

最小改动版：只把"记录答案"和"成员判断"两处换掉，判据、不变量、指针语义一个字不改。

```python
from collections import defaultdict
from math import inf


class Solution:
    def minWindow(self, s: str, t: str) -> str:
        cnt0 = defaultdict(int)
        for ch in t:
            cnt0[ch] += 1
        kinds = len(cnt0)              # distinct(t)，先算好，省掉每轮 len()
        cnt1 = defaultdict(int)
        cnt2 = defaultdict(int)
        left = 0
        best_left, best_len = 0, inf   # 只记下标 + 长度，不再拷贝子串
        for right, ch in enumerate(s):
            cnt1[ch] += 1
            if ch not in cnt0:         # O(1)，原来是 ch not in t（O(m)）
                continue
            if cnt1[ch] >= cnt0[ch]:
                cnt2[ch] = 1
            while len(cnt2) == kinds:
                if best_len > right - left + 1:
                    best_len = right - left + 1
                    best_left = left
                cnt1[s[left]] -= 1
                if s[left] in cnt0 and cnt1[s[left]] < cnt0[s[left]]:
                    del cnt2[s[left]]
                left += 1
        return s[best_left: best_left + best_len] if best_len < inf else ''
```

**优化理由**：答案只记 `(best_left, best_len)`，**整个循环结束时切一次**子串，把最坏 O(n²) 的拷贝压回 O(n)；成员判断从字符串换成字典，把 O(n·m) 压回 O(n)。两处都是纯粹的常数/结构替换，**不改变任何判据**，正确性由对拍确认（第七节：官方示例 3/3、手工边界 12 条全过、随机对拍 40 组长度偏差 0）。

### 常数级优化（可选）

把 `cnt2` 的"达标集合"换成**一个标量 `missing`**，三张表并成一张：`need[c]` 在窗口内**多余**时为负，`missing == 0` 就表示覆盖成立，收缩时把"有多余的量"一路退回去。

```python
from collections import defaultdict


class Solution:
    def minWindow(self, s: str, t: str) -> str:
        need = defaultdict(int)
        for ch in t:
            need[ch] += 1
        missing = len(t)               # 还差多少个字符（按个数，不按种类）
        left = 0
        best_left, best_right = 0, -1
        for right, ch in enumerate(s):
            if need[ch] > 0:           # 这个字符还欠着，补上一个
                missing -= 1
            need[ch] -= 1              # 多余的量会记成负数
            if missing == 0:
                while need[s[left]] < 0:      # 左端字符多余，退掉
                    need[s[left]] += 1
                    left += 1
                if best_right < 0 or right - left < best_right - best_left:
                    best_left, best_right = left, right
                need[s[left]] += 1     # 把左端这个"关键字符"移出窗口
                missing += 1
                left += 1
        return s[best_left: best_right + 1] if best_right >= 0 else ''
```

判据从"`len(cnt2) == len(cnt0)`（比种类数）"换成了"`missing == 0`（比缺的个数）"，好处是**每轮只碰一张表、且全是一次加一减一**。这是四个版本里实测最快的（见下表）。

也可以把哈希换成定长数组（按 `ord` 索引 128 长 list）—— 实测**没有稳定优势**（C 档略快、A/B/D 均更慢），为可读性考虑不采用。

**实测表**（同一台机器、同一输入、4 个版本**轮转测量 7 轮取最优**，单位 ms；倍率 = V1 耗时 ÷ 该版本耗时，越大越快）：

| 场景 | V1 原版 | V2 记下标 | V3 单表 missing | V4 定长数组 |
| :--- | :--- | :--- | :--- | :--- |
| A 切片退化 `s="a"×19999+"b"`, `t="ab"` | 16.13 (1.00×) | 8.19 (1.97×) | **4.47 (3.61×)** | 5.87 (2.75×) |
| B 切片退化 `n=4e4`（A 的 2 倍规模） | 41.63 (1.00×) | 16.64 (2.50×) | **8.82 (4.72×)** | 12.11 (3.44×) |
| C `in t` 退化 `s="c"×3e4`, `t="ab"×1.5e4`（答案为空） | 55.40 (1.00×) | 4.64 (11.94×) | 5.20 (10.65×) | **4.54 (12.21×)** |
| D 随机大输入 `n=5e4`, `m=5e2` | 20.26 (1.00×) | 19.23 (1.05×) | **11.56 (1.75×)** | 13.24 (1.53×) |

从这张表能读出三件事（都是实测，不是估的）：

- **切片是"最坏情况风险"，不是常态开销。** A→B 规模翻倍时，V1 的耗时从 16.13 涨到 41.63（2.58×，超线性），而 V2/V3 恰好翻倍（2.03× / 1.97×，干净线性）；把切片成本单拎出来看，V1 相对 V2 的**额外**耗时由 7.94 ms 涨到 24.99 ms（≈3.15×，接近二次方）。但在随机输入 D 上 V2 只比 V1 快 1.05× —— 因为答案窗口短，切片本来就便宜。**结论：只改切片几乎不改善常态，只削掉最坏情况。**
- **`in t` 是最不值得留的一处。** C 档 `t` 长 3e4 且 `s` 的字符全不在 `t` 里，V1 要对 `t` 全表扫 3e4 次 ⇒ 比换成字典的版本慢 **11.94×**。这处的修复是"一改就赢"，而且不挑输入。
- **真正的常态收益来自单表化。** V3 在 D（随机大输入）上仍有 1.75×，是不依赖退化输入的稳定收益；定长数组（V4）则只在 C 这种"哈希键少但调用密"的场景中有微弱优势。

> 补充：V1 的耗时都远在本题时限内（最慢的 C 档 55 ms），它在 LeetCode 上 AC 没有任何问题 —— 上面这些是**按 10^5 约束泛化到最坏输入**的研究结论，不是说原版会超时。

## 六、易错点与总结

### 易错点

- **`while` 写成 `if`（只收缩一格）**：一次收缩最多挪一格，但窗口该收缩的格数由冗余量决定，可能是上万格。**最小反例 `s="ba", t="a"`** —— `right` 走到第二个字符时窗口 `"ba"` 合法，记录下来的却是 `"ba"`，而真正的答案 `"a"` 是收缩**之后**才出现的，`if` 版把这一步丢掉了，返回 `"ba"`。
- **先收缩再记录**：会把已经不合法的窗口写进答案。**最小反例 `s="a", t="a"`** —— 收缩后 `left` 已越过 `right`，记录下来的是空串，返回 `""`。正确顺序是"收缩前记录"，或"收缩后若仍合法再记录"。
- **忘记 `del cnt2[c]`**：键数只增不减，窗口会被永久判成合法，`left` 一路推到越界。
- **比较方向写反**：`ansLength > right - left + 1` 是"找到更短的才更新"，写成 `>=` 在有并列解时会取到靠后的一个（本题保证答案唯一，所以不影响结果，但语义上应保持严格小于）。
- **`cnt1` 与 `cnt0` 混用**：`cnt1` 统计窗口内**所有**字符（含不在 `t` 里的），`cnt0` 只有 `t` 的字符。成员判断要用 `cnt0` 或 `t`，不能用 `cnt1`。
- **空结果的出口**：只要 `t` 里有 `s` 中不存在的字符，`cnt2` 永远凑不齐，`ans` 保持 `''` 自然返回 —— 不需要额外写特判，但要知道这条路径是靠"判据永远不成立"兜住的。
- **`left` 不会越过 `right + 1`**：`t` 非空 ⇒ 空窗口一定不合判据 ⇒ `while` 必然退出。这个不变量的前提是 `n >= 1`（本题约束保证）。
- 本机运行需要补 `from collections import defaultdict` 与 `from math import inf`（`inf` 不是内置名，`float('inf')` 或 `math.inf` 才是）。

### 题型套路沉淀

- **滑窗的统一骨架**（本族通用）：写清判据 → 右端扩张一个元素 → `while` 收缩左端直到判据被破坏 → 收缩过程中记账 → 左端再推一格。**左指针只前进 ⇒ 总移动 ≤ n ⇒ 摊还 O(n)**，这是"为什么滑窗是 O(n)"的全部依据。
- **上手先问两件事**：
  1. **合法性的单调性从哪来？** 本题是"固定右端时，从左边删元素不会把不合法变合法"（约束前缀封闭）；只要有这条，双指针就成立；一旦约束允许负权/双向影响，滑窗失效，要换前缀和 + 单调队列之类。
  2. **判据是按"值"还是按"键数"？** 按值（某元素计数 > k）⇒ 归零也不必删键；**按键数 ⇒ 收缩时必须删键**，否则键数只增不减，指针会被推爆。本题是按种类数，属于后者。
- **最短型 vs 最长型的硬性差别**（本题属最短型）：
  - 最短型：必须 `while` 收缩到判据被破坏为止，并**每轮记录**（长度序列不单调，不能只取终值）；
  - 最长型：在"答案口径为窗口长度 + 判据是对整个窗口成立的"这两个前提下，才可以退化成 `if` 平移版 + 终值口径。
  - 本题恰好踩在"不能简化"的一侧 —— 这就是上面两个最小反例的来源。
- **滑窗提速三件套**（都能实测，不要凭感觉）：① 答案只记下标、最后切一次；② 成员判断用 dict/数组，别对字符串做 `in`；③ 字母表固定时考虑定长数组（本题实测收益不稳定，别硬换）。
- 同族题（滑动窗口里"窗口内部计数决定合法性"这一支）：`3. 无重复字符的最长子串`、`209. 长度最小的子数组`、`438. 找到字符串中所有字母异位词`、`567. 字符串的排列`。
