# 1100. 长度为 K 的无重复字符子串

> **难度**：中等
> **标签**：哈希表 · 字符串 · 滑动窗口
> **原题链接**：https://leetcode.cn/problems/find-k-length-substrings-with-no-repeated-characters/
> **备注**：LeetCode **Plus 会员题**，非会员看不到题目页。

## 一、题目描述

给定字符串 `s` 和整数 `k`，统计 `s` 中**长度为 `k` 且不含重复字符**的连续子串的个数。注意 `k` 可能大于 `s` 的长度，此时答案为 `0`。

### 示例

```text
示例 1
输入：s = "havefunonleetcode", k = 5
输出：6
解释：6 个满足条件的子串分别是 'havef'、'avefu'、'vefun'、'efuno'、'etcod'、'tcode'。
      （注意 'funon' 含两个 'n'，不计入）

示例 2
输入：s = "home", k = 5
输出：0
解释：k 大于 s 的长度，不存在这样的子串。
```

### 约束条件

- `1 <= s.length <= 10^4`
- `s` 仅由小写英文字母组成
- `1 <= k <= 10^4`
- 隐含约束：**字符集大小只有 26**，因此 `k > 26` 时答案恒为 `0`

---

## 二、解题思路

### 核心思想

**定长滑动窗口 + 字符计数**。相邻两个长度为 `k` 的窗口只差「首尾各一个字符」，没必要对每个窗口重新判重。维护窗口内各字符的出现次数，每滑动一次只做「进一个字符、出一个字符」两次 O(1) 更新。

判断条件上有个关键等价替换：**窗口大小恰好是 `k` 时，「无重复字符」⟺「不同字符数 == k」**（此时每个计数都 ≥ 1，总数是 `k`，若不同字符数也是 `k`，只能每人各 1 次）。

### 思路演进

1. **暴力解法**：枚举每个起点 `i ∈ [0, n-k]`，把 `s[i:i+k]` 塞进 `set` 判断 `len(set) == k`。
   时间 O(n·k)。`n` 和 `k` 都可达 10^4，最坏约 10^8 次字符操作，Python 下必然超时。

2. **观察到**：窗口 `s[i..i+k-1]` 和 `s[i+1..i+k]` 的重叠部分高达 `k-1` 个字符，每轮都重算一遍集合是纯浪费。真正变化的只有「新进来的 `s[i+k]`」和「被挤出去的 `s[i]`」。

3. **优化为**：维护一个计数器 `cnt`（字符 → 窗口内出现次数），配合 `i` 与窗口右端同步推进：
   - 右端进：`cnt[s[i]] += 1`
   - 窗口满 `k` 后：若 `len(cnt) == k` 则 `ans += 1`
   - 左端出：`cnt[s[i-k+1]] -= 1`，**归零则删键**

   每步 O(1)，整体 O(n)。

4. **进一步观察（本题最优雅的一步）**：既然窗口大小固定是 `k`，「窗口内每个字符都恰好出现一次」不必逐个检查，用 `len(cnt) == k` 就够了 —— 计数器的键数就是「不同字符数」。这比自己维护一个 `distinct` 变量更省事，因为 Python 的 `dict` 天然提供 `len()`。

### 关键点

- **`len(cnt) == k` 只在窗口大小恰为 `k` 时成立**。如果窗口还能更长（比如求「最长无重复子串」那题），这个等价关系就断了，必须改用别的判据。
- **出窗口后计数归零必须 `del`**：`len(cnt)` 统计的是「键的个数」，不是「窗口中不同字符数」。不删键，历史字符会一直占着名额，判据直接失效。
- 遍历顺序是「**先加右端 → 判满 → 再移左端**」，使得检查时刻窗口内容正好是 `s[i-k+1..i]`，语义干净。
- 剪枝 `k > len(s)` 提前返回。其实**它不是防越界**（`if i < k-1: continue` 已经保证了 `i-k+1 >= 0`），纯粹是省掉一趟无意义的循环。

## 三、代码实现

### 最终代码

```python
from collections import defaultdict


class Solution:
    def numKLenSubstrNoRepeats(self, s: str, k: int) -> int:
        if k > len(s):
            return 0
        ExistLetter = defaultdict(int)   # 字符 -> 当前窗口内的出现次数
        ans = 0
        for i, j in enumerate(s):
            ExistLetter[j] += 1          # 1) 右端进窗
            if i < k - 1:                # 窗口还没铺满 k 个
                continue
            if len(ExistLetter) == k:    # 2) 窗口大小恰为 k，不同字符数 == k 即无重复
                ans += 1
            ExistLetter[s[i - k + 1]] -= 1        # 3) 左端出窗
            if ExistLetter[s[i - k + 1]] == 0:    #    归零则删键，保证 len() 语义正确
                del ExistLetter[s[i - k + 1]]
        return ans
```

## 四、复杂度分析

| 版本 | 时间复杂度 | 空间复杂度 |
| :--- | :--- | :--- |
| **最终代码** | O(n) | O(min(k, 26)) |
| 朴素解法（逐窗口建 set） | O(n·k) | O(k) |
| 理论下界 | O(n) | O(1) |

> 复杂度中的 `n` 指字符串 `s` 的长度；`k` 为窗口长度。
> 空间上界写成 `O(min(k, 26))` 是因为计数器最多只能装下 26 个不同的小写字母，即使 `k = 10^4` 也是如此。

## 五、优化评估

**结论**：时间复杂度 **O(n) 已是理论下界**，但空间与常数因子**仍有可优化空间**。

### 瓶颈分析

任何算法都必须检查字符串的每个位置（每个字符都可能是某个合法窗口的一部分，跳过它就可能漏解），所以 `Ω(n)` 不可突破。

当前实现的三处开销：

1. **`len(cnt)` 与 `del` 每轮各一次**，字典操作涉及哈希与内存管理，常数明显高于数组下标访问；
2. **空间是 `dict`**，比定长 26 的数组重；
3. **缺 `k > 26` 剪枝**：字符集只有 26 个小写字母，`k > 26` 时答案必然是 `0`。现有代码遇到 `k = 10^4` 仍会把整串扫一遍。

### 可优化空间

换一个**维护量**：不再记「窗口内计数」，而记「**每个字符上次出现的下标**」，并顺带维护「以 `i` 结尾的最长无重复子串的左端点 `left`」。

- 遇到字符 `c` 时，若它的上次出现位置 `last[c]` 仍在当前无重复窗口内（`last[c] >= left`），说明重复了，`left` 直接跳到 `last[c] + 1`；
- 于是 `i - left + 1` 就是「以 `i` 结尾的最长无重复子串长度」。只要它 `>= k`，那么**以 `i` 结尾、长度为 `k` 的那个窗口必然也无重复**，`ans += 1`。

这样每轮只有「一次数组读 + 一次数组写 + 一次比较」，**既没有 `len()` 也没有 `del`**，空间固定为 26 个 int。理论上界没变，实测常数更小，代码也更短。

### 优化代码

```python
class Solution:
    def numKLenSubstrNoRepeats(self, s: str, k: int) -> int:
        n = len(s)
        if k > n or k > 26:      # 小写字母只有 26 种，长于 26 的窗口必有重复
            return 0
        last = [-1] * 26         # 字符 -> 上次出现的下标
        left = 0                 # 以 i 结尾的最长无重复子串的左端点
        ans = 0
        for i, ch in enumerate(s):
            c = ord(ch) - 97
            if last[c] >= left:  # 该字符还在当前无重复窗口内 -> 左边界跳到它后面
                left = last[c] + 1
            last[c] = i
            if i - left + 1 >= k:  # 无重复窗口长度 >= k，则末尾 k 个字符构成的窗口必然合法
                ans += 1
        return ans
```

**优化理由**：

- **正确性**：`s[i-k+1..i]` 是以 `i` 结尾、长度为 `k` 的子串，它是「以 `i` 结尾的最长无重复子串」的后缀（`i-left+1 >= k` 时），无重复性质对子串封闭，故合法；反过来任何合法窗口都会被它的右端点 `i` 计到，**不重不漏**。
- **常数**：全程只有整数比较与数组读写，无需哈希字符串、无需删除键。
- **剪枝**：`k > 26` 时直接 O(1) 返回，避免 `k = 10^4` 时白扫一遍。

### 常数级优化（可选）

- `last` 用 `list` 而非 `dict` 索引，避免字符哈希；`ord(ch) - 97` 比 `ch` 直接查表慢一点点，但省掉哈希后的净收益明显。
- 把 `last`、`ans` 在循环外绑定成局部变量（Python 的局部变量查找比闭包/全局快），在 10^4 规模上收益有限，不必强求。

## 六、易错点与总结

### 易错点

- **`del` 漏写是这道题的头号杀手。** 实测对比（同一份代码只去掉 `del`）：

  | 输入 | 正确输出 | 漏写 `del` 的输出 |
  | :--- | :--- | :--- |
  | `s = "havefunonleetcode", k = 5` | 6 | **1** |
  | `s = "abc", k = 1` | 3 | **1** |

  原因是 `len(cnt)` 变成了「历史上出现过的不同字符数」，它一旦涨过 `k` 就再也降不回来，判据永久失效。

- **把 `len(cnt) == k` 用到了变长窗口上**。这个等价只在窗口大小恰为 `k` 时成立；求「最长无重复子串」（LC 3）时必须换判据。
- **写成「先移左端、再判满」**：那样检查的窗口就错位成 `s[i-k..i-1]`，会整体偏移一位。顺序必须是「右进 → 判 → 左出」。
- **`k > 26` 时的隐性浪费**：不剪枝不会算错，但 `k = 10^4` 会白跑一整轮 O(n)。
- `k = 0` 不在约束内；若强行传入，`s[i-k+1] = s[i+1]` 会在末尾越界 —— 约束保证不用考虑。

### 题型套路沉淀

- **定长滑动窗口模板**（背下来）：

  ```text
  先铺满前 k 个：for i in range(k): 加入 s[i]
  检查第一个窗口
  for i in range(k, n):
      加入 s[i]            # 右进
      移除 s[i - k]        # 左出
      检查当前窗口
  ```

  本题只是把「先铺满」和「边滑边判」合并进同一个循环，并用 `if i < k - 1: continue` 代替。

- **「窗口内无重复」的两套维护方式**：
  - ① **计数表 + 不同字符数**：适合定长窗口，判据是 `len(cnt) == k`；缺点是出窗要 `del`。
  - ② **`last[c]` + 左边界跳转**：适合「最长/计数无重复子串」，无删除操作，常数更小，是更通用的武器。
