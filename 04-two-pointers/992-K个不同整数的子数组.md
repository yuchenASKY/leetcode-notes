# 992. K 个不同整数的子数组

> **难度**：困难
> **标签**：数组 · 哈希表 · 滑动窗口 · 计数
> **原题链接**：https://leetcode.cn/problems/subarrays-with-k-different-integers/

---

## 一、题目描述

给定正整数数组 `nums` 和整数 `k`，统计**不同整数个数恰好为 `k`** 的连续子数组个数。子数组必须连续，允许元素重复出现。

### 示例

```text
输入：nums = [1,2,1,2,3], k = 2
输出：7
解释：恰好由 2 个不同整数组成的子数组共 7 个：
      [1,2], [2,1], [1,2], [2,3], [1,2,1], [2,1,2], [1,2,1,2]

输入：nums = [1,2,1,3,4], k = 3
输出：3
解释：恰好由 3 个不同整数组成的子数组：[1,2,1,3], [2,1,3], [1,3,4]
```

### 约束条件

- `1 <= nums.length <= 2 * 10^4`
- `1 <= nums[i], k <= nums.length`（即值域也有界：`nums[i] <= n`）

---

## 二、解题思路

### 核心思想

**「恰好 k 种」= 「至少 k 种」− 「至少 k+1 种」**，而后面两个集合对左端点都是**前缀**（固定右端时，子数组的种类数随左端右移单调不增），于是各用一个滑窗指针的当前值就能直接读出个数，两个窗口在同一趟扫描里并跑。

### 思路演进

1. **暴力解法**：枚举全部 `O(n²)` 个子数组，对每个用哈希表统计不同整数种类数，等于 `k` 就计数。
   `n = 2 * 10^4` 时子数组个数为 `2 * 10^8`，**根本枚举不完**（不是常数问题，是量级问题）。

2. **瓶颈定位**：问题出在「恰好 k」这个约束对窗口**不单调**。固定右端 `j` 时，让左端 `l` 右移，窗口内种类数只减不增 —— 所以满足「种类数 ≤ k」的 `l` 是一个前缀 `[0, p]`，满足「≤ k−1」的是一个更短的前缀 —— 但满足「== k」的 `l` 是一段**中间的连续区间**，单个指针刻画不了它。两个指针分别去卡这段区间的左右边界，就成了「两窗同趟」。

3. **关键转化**：不去直接刻画区间，而是用**两个各自单调的集合做差**：

   ```
   #(恰好 k) = #(种类数 >= k) - #(种类数 >= k + 1)
   ```

   由单调性，「种类数 ≥ k」的左端点集合是 `[0, left_1 - 1]`、「≥ k+1」的是 `[0, left_2 - 1]`，两个集合还是**前缀**，可以各用一个指针维护。一句话说清为什么原来不行、现在行：**原来要统计的是两边界之间的区间长度（需要知道两个边界）；现在把它换成两个前缀长度之差，前缀长度恰好就等于对应滑窗指针的值 —— 指针值本身就是答案的一部分。**

4. **最优解**：窗口 1 收缩到「种类数 < k」（`while len(cnt1) >= k`），窗口 2 收缩到「种类数 < k+1」（`while len(cnt2) >= k+1`），每轮 `ans += left1 - left2`。一趟扫描、两个左指针都不回退，摊还 O(n)。

### 关键点

- **判据是「按键数」的那一族**：约束作用在「窗口内**不同整数种类数**」上，所以计数表里某个键被减到 0 时**必须 `del` 删键**。若只减到 0 而不删键，`len(cnt)` 只增不减，左指针会被推到 `IndexError`。
  这与「某元素出现次数 > k」那类**按值**判据的题恰好相反（那类题删不删键都无所谓）—— 两族最本质的区别就在这一行。
- **两个收缩阈值只差 1，但位置固定、不可互换**：窗口 1 停在「≤ k−1」，窗口 2 停在「≤ k」。相应地：
  - `left1` = 满足「种类数 **≥ k**」的左端点数
  - `left2` = 满足「种类数 **≥ k+1**」的左端点数
  - 答案 = `left1 - left2`
- **左指针语义是「不满足阈值的那一侧」的端点数，不是合法端点数**。这是本题最容易写出负数的地方，详见「六、易错点」。
- **不需要 `left <= right` 越界守卫**：`k >= 1` 由约束保证，`while len(cnt1) >= k` 成立时窗口必非空 ⇒ `left1 <= j`，读 `nums[left1]` 绝不会越界（不像和为 0 那类题，条件可能恒真）。

## 三、代码实现

### 最终代码

> 代码为用户提交并通过的版本（截图转录）。截图里只有 `class Solution:`，缺少 import，已补 `from collections import defaultdict` 与 `from typing import List`；截图完整，21 行含 `return ans`，未被裁掉。

```python
from collections import defaultdict
from typing import List


class Solution:
    def subarraysWithKDistinct(self, nums: List[int], k: int) -> int:
        cnt1 = defaultdict(int)          # 窗口1：收缩到“窗口内不同整数 < k”
        cnt2 = defaultdict(int)          # 窗口2：收缩到“窗口内不同整数 < k + 1”
        ans = left1 = left2 = 0
        for j in nums:
            cnt1[j] += 1
            cnt2[j] += 1
            while len(cnt1) >= k:                     # 停在 len(cnt1) <= k - 1
                cnt1[nums[left1]] -= 1
                if cnt1[nums[left1]] == 0:
                    del cnt1[nums[left1]]             # 按键数判据：必须删键
                left1 += 1
            ans += left1                              # += #(左端 l 使 distinct(l..j) >= k)
            while len(cnt2) >= k + 1:                 # 停在 len(cnt2) <= k
                cnt2[nums[left2]] -= 1
                if cnt2[nums[left2]] == 0:
                    del cnt2[nums[left2]]
                left2 += 1
            ans -= left2                              # -= #(左端 l 使 distinct(l..j) >= k + 1)
        return ans
```

## 四、复杂度分析

| 版本 | 时间复杂度 | 空间复杂度 |
| :--- | :--- | :--- |
| **最终代码（单趟双窗）** | O(n) 摊还 | O(k) |
| 等价写法：两趟 `atMost(k) - atMost(k-1)` | O(n) | O(k) |
| 朴素解法（枚举所有子数组） | O(n²) | O(k) |
| 理论下界 | Ω(n) | Ω(k) |

> 复杂度中的 n 指 `nums` 的长度（≤ 2 × 10⁴）；k 指题面给定阈值，它同时界定了两个窗口内允许出现的不同整数种类数（≤ k 与 ≤ k−1），故计数表的键数为 O(k)。
> 时间上 O(n) 是摊还：两个左指针各自单调递增、整趟合计推进不超过 2n 次，内层两个 `while` 的摊还代价是 O(1)。

## 五、优化评估

**结论**：时间已达理论下界 O(n)，空间 O(k) 是这类「按种类数计数」问题的必要状态，**不存在算法级优化空间**；剩下的只有常数级收益，实测 1.3 × ~ 1.8 ×。

### 瓶颈分析

单步开销 = 2 次计数更新（哈希）+ 2 次 `len()` + 出窗时的 1 次索引与可能的 1 次 `del`，**全部落在常数项**。`n = 2 × 10⁴` 时整趟耗时仅 8 ~ 13 ms，说明既没有可去掉的数量级，数据规模也远没到需要担心的程度。

为什么不可能更好：

- 时间下界 Ω(n)：任何子数组计数都必须读完全部元素，否则可能漏掉以它为右端的解。
- 空间下界 Ω(k)：判据依赖「窗口内不同整数种类数」，这要求按值维护计数表；窗口内最多 k 种值，所以 Ω(k) 是必需的（数组计数法的 O(n) 只是把它换成了更大的常数空间，并没降低下界）。

### 优化代码

下面给出本轮的胜出实现。**V1 与 V2 都是等价改写，已用同一套暴力基准验证（偏差 0/40）**：

**V1 —— 纯常数优化（推荐，空间不变，仍是 O(k)）**

```python
class Solution:
    def subarraysWithKDistinct(self, nums, k):
        cnt1, cnt2 = {}, {}
        ans = left1 = left2 = 0
        for j in nums:
            cnt1[j] = cnt1.get(j, 0) + 1
            cnt2[j] = cnt2.get(j, 0) + 1
            while len(cnt1) >= k:
                x = nums[left1]                # 出窗元素缓存进局部变量
                cnt1[x] -= 1
                if cnt1[x] == 0:
                    del cnt1[x]
                left1 += 1
            ans += left1
            while len(cnt2) >= k + 1:
                x = nums[left2]
                cnt2[x] -= 1
                if cnt2[x] == 0:
                    del cnt2[x]
                left2 += 1
            ans -= left2
        return ans
```

**优化理由**：`dict.get` 的自增写法比 `defaultdict.__missing__` 走一次工厂函数再自增要短；出窗元素用局部变量接住，省掉重复的下标运算。实测 1.32 × ~ 1.38 ×（见下表）。

**V2 —— 数组计数（最快，代价是空间 O(n)）**

```python
class Solution:
    def subarraysWithKDistinct(self, nums, k):
        n = len(nums)
        c1, c2 = [0] * (n + 1), [0] * (n + 1)      # 题面保证 nums[i] <= n，值域有界
        d1 = d2 = 0                                # 各自窗口内的不同种类数
        ans = left1 = left2 = 0
        for x in nums:
            if c1[x] == 0: d1 += 1
            c1[x] += 1
            if c2[x] == 0: d2 += 1
            c2[x] += 1
            while d1 >= k:
                y = nums[left1]
                c1[y] -= 1
                if c1[y] == 0: d1 -= 1
                left1 += 1
            ans += left1
            while d2 >= k + 1:
                y = nums[left2]
                c2[y] -= 1
                if c2[y] == 0: d2 -= 1
                left2 += 1
            ans -= left2
        return ans
```

**优化理由**：把哈希换成值域数组（`1 <= nums[i] <= n` 是题面给的，不需要额外压缩），种类数改由一个整数计数器 `d` 维护，彻底去掉哈希开销。实测 1.67 × ~ 1.80 ×，是三档里最快的。

**代价必须写清楚**：空间从 O(k) 涨到 O(n)，且**只在值域有界（且上界为 n 量级）时可用**；若 `nums[i]` 无界（真实的工程数据里很常见），这条路直接不成立，只能退回哈希。

### 常数级优化（可选）

实测表（`n = 20000` 即题面上限，9 轮轮转取每版最优值；同一台机、同一轮内比较，已复跑一次结果一致）：

| 版本 | A 值域 50 / k=20 | B 值域 = n / k=100 | C 全等 / k=1 |
| :--- | :--- | :--- | :--- |
| V0 用户原版（`defaultdict`） | 11.65 ms（1.00 ×） | 13.33 ms（1.00 ×） | 8.28 ms（1.00 ×） |
| V1a 仅「出窗元素缓存到局部变量」 | 11.24 ms（1.04 ×） | 12.82 ms（1.04 ×） | 8.01 ms（1.03 ×） |
| V1b 仅「`defaultdict` → `dict.get`」 | 9.24 ms（1.26 ×） | 10.09 ms（1.32 ×） | 6.43 ms（1.29 ×） |
| **V1c 两项合并（推荐）** | **8.82 ms（1.32 ×）** | **9.65 ms（1.38 ×）** | **6.22 ms（1.33 ×）** |
| **V2 数组计数** | **6.98 ms（1.67 ×）** | **7.41 ms（1.80 ×）** | **4.89 ms（1.69 ×）** |
| V3 两趟 `atMost` | 9.44 ms（1.23 ×） | 9.23 ms（1.44 ×） | 6.99 ms（1.18 ×） |

- **提速几乎全部来自 `dict.get` 那一项**（1.26 × ~ 1.32 ×），而「出窗元素缓存到局部变量」单独看只有 1.03 × ~ 1.04 × —— 落在噪声里，不值得为它动代码。两项合起来 1.32 × ~ 1.38 ×，已是「不改渐近、不改空间」的上限附近。
- **被证伪的改法：两趟 `atMost(k) - atMost(k-1)`（V3）**。它少一个窗口的计数表，看似更清爽，但要多扫一趟数组，实测反而比单趟双窗慢 1.18 × ~ 1.44 ×（等价的另一条路线，**不是**更优解）。
- 三档输入按「最坏情况」挑：A 值域小窗口长、B 值域 ≈ n 每步都在引入新种类、C 全等 + `k=1` 制造最多的 `del`。

## 六、易错点与总结

### 易错点

- **忘了 `del` 删键**：判据是按键数（不同整数种类数），只把计数减到 0 而不删键，`len(cnt)` 永不下降，左指针会被推到数组之外。这是「按键数」与「按值」两族的**唯一分界动作**。
- **减法方向写反（最容易出负数的地方）**：本题两个指针数的是**违反阈值的左端点数**。若把收缩条件改写成「窗口 ≤ k」与「≤ k−1」（即 `> k` 与 `> k-1`），指针的语义随之平移一位，答案必须写成 `left2 - left1`；照抄 `left1 - left2` 会得到正确答案的**相反数**。
  实测：口径改成「两窗口长度之差」后，40 组随机用例中 15 组出错且**全部为负**（真值非 0 的恰好 15 组），最小反例 `nums = [1], k = 1`（真值 1、实得 −1）。**答案出现负数，就是减法方向写错的信号。**
- **`while` 不能换成 `if`**：出窗元素在窗口内可能还有剩余，只缩一格并不会让种类数下降。实测偏差 10/40，最小反例 `nums = [2,2,1], k = 1`（真值 4、实得 5）：`left2` 那一步出窗的 `2` 在窗口里还剩 1 个，删掉它后窗口仍有 2 种整数，`len(cnt2) >= k+1` 依然成立，违规没有被消除。
- **两个阈值互换或写成 `> k` / `> k+1`**：`>= k` 与 `>= k+1` 只差一个等号，但对应的窗口边界（≤ k−1 与 ≤ k）是固定的 —— 一并写错会让答案整体偏小或偏大，而官方示例 1（`k = 2`）恰好还能碰巧对上一部分，容易漏检。
- **`k = 1` 的退化情形**：此时窗口 2 的阈值是 2，两个窗口都非空，逻辑自洽；若改用「两趟 `atMost(k) - atMost(k-1)`」的写法，`atMost(0)` 会把窗口立刻清空、返回 0，这是对的，但要确认 `while len(cnt) > lim` 在 `lim = 0` 时确实会把窗口收缩到空。

### 题型套路沉淀

- **滑动窗口三族判据，先认族再写代码**：
  1. 「窗口内部度量 ≤ 上限」→ 收缩到合法为止，答案取每轮窗口长度 / 最大长度；
  2. 「计数型：对每个右端点统计合法左端点数」→ 窗口停在**非法**一侧，`while` 条件与第 1 族互为反面，答案口径是**端点数**（`ans += left`）而不是窗口长度；
  3. **本题所属的「恰好 k」型** → 把「恰好」拆成两个单调前缀之差，`#(≥ k) - #(≥ k+1)`，两个窗口在同一趟里并跑，答案口径是**两个指针值之差**。
- **「恰好 k / 恰好 goal」通用套路**：凡是题目要求「恰好等于某个阈值」，先想能不能改写成「至少/至多」的差 —— 因为「至少/至多」通常对窗口单调，而「恰好」不单调。本题的两种落地方式：单趟双窗（推荐）或两趟 `atMost`（等价但常数略劣）。
- **判据按键数还是按值，决定了要不要 `del`**：题面说「不同整数个数」「不同种类数」→ 按键数 → 必须删键；题面说「某元素出现次数」「重复次数」→ 按值 → 不必删键。写代码前先把这条定下来，能省掉一整类调试。
- **双指针能用的前提是先确认单调性**：固定右端时「种类数随左端右移单调不增」，这是本题能上滑窗的根基；换成「元素的绝对差之和」这类非单调度量时，滑窗失效，必须换结构。

| Q2 `while` + 窗口长度之差 | 15/40（**全部为负**） | `nums = [1], k = 1`：真值 1 / 实得 −1 |
| Q3 `if` + 端点数之差 | 10/40 | `nums = [2,2,1], k = 1`：真值 4 / 实得 5 |
| Q4 `if` + 窗口长度之差 | 15/40（全部为负） | `nums = [1], k = 1`：真值 1 / 实得 −1 |

结论定性：**口径必须取「左端点数之差」**（换成长度之差会得到正确答案的相反数）；**收缩必须用 `while`**（`if` 在出窗元素仍有剩余时无法消除违规）。

### 5. 微基准

| 项 | 内容 |
| :--- | :--- |
| 规模 | n = 20000（题面上限） |
| 档位 | A 值域 50 / k=20；B 值域 = n / k=100；C 全等 / k=1 |
| 计时方式 | `perf_counter`，9 轮轮转（每轮内各版本依次跑），取每版最优值，每轮内 5 次取均 |
| 版本数 | 6（V0 原版、V1a、V1b、V1c、V2、V3） |
| 稳定性 | 完整复跑一次，各档相对倍数一致（差异 < 4%） |

结果见「五、优化评估」的实测表：V1c 1.32 × ~ 1.38 ×、V2 1.67 × ~ 1.80 ×、V3 1.18 × ~ 1.44 ×、V1a 1.03 × ~ 1.04 ×（噪声内）。所有数字均来自同一轮实测，无估算。

### 6. 用例总量
