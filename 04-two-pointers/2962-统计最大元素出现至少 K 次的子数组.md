# 2962. 统计最大元素出现至少 K 次的子数组

> **难度**：中等
> **标签**：数组 · 滑动窗口
> **原题链接**：https://leetcode.cn/problems/count-subarrays-where-max-element-appears-at-least-k-times/

---

## 一、题目描述

给定整数数组 `nums` 和正整数 `k`，统计有多少个子数组满足：**`nums` 的全局最大元素**（记 `M = max(nums)`，整个数组的最大值）在这些子数组中至少出现 `k` 次。子数组指连续的一段。

⚠️ 这里的「最大元素」是**整个 `nums` 的最大值**，是一个与子数组无关的常量；**不是**「子数组自身的最大值」。这个区别是本题唯一的阅读理解陷阱（见第六节易错点 1）。

### 示例

```text
示例 1：
输入：nums = [1,3,2,3,3], k = 2
输出：6
解释：M = 3，包含 3 至少 2 次的子数组为 [1,3,2,3]、[1,3,2,3,3]、[3,2,3]、[3,2,3,3]、[2,3,3]、[3,3]

示例 2：
输入：nums = [1,4,2,1], k = 3
输出：0
解释：M = 4，没有任何子数组包含 4 至少 3 次
```

### 约束条件

- `1 <= nums.length <= 10^5`
- `1 <= nums[i] <= 10^6`
- `1 <= k <= 10^5`

> 长度上限 10^5 意味着子数组总数约 5×10^9，任何枚举子数组的写法都必然超时。

## 二、解题思路

### 核心思想

**「至少含 k 个 M」这个性质对左端点前缀封闭**：固定右端点 `r` 后，若 `[l, r]` 合法，则所有 `l' < l` 都合法。于是合法起点必然是 `0..left-1` 这样一段前缀，**以 `r` 结尾的合法子数组数恰好等于临界左边界 `left`** —— 双指针维护出 `left` 后直接 `ans += left` 即可。

### 思路演进

1. **暴力解（朴素）**：枚举全部 `n(n+1)/2` 个子数组，对每个子数组数一遍 M 的出现次数。时间 **O(n²)**（增量维护）到 O(n³)（每个子数组重算 max + count），空间 O(1)。`n = 10^5` 时约 5×10^9 个子数组，必然 TLE。
2. **瓶颈定位**：相邻右端点的两个窗口只差一个元素，但暴力把「数 M 的个数」对每个子数组**重做了一遍** —— 重复枚举。同时注意一个结构信息被浪费了：`[l, r]` 中 M 的个数**随 `l` 左移而单调不减**，即「合法性」是前缀封闭的。一旦看到前缀封闭，就该想到：不需要枚举全部 `(l, r)`，每个 `r` 只要找到**分界点**。
3. **关键转化**：改写命题 —— 对每个 `r` 求临界左边界 `f(r) = min{ l : [l, r] 中 M 的个数 ≥ k }`（不存在则视为 `r+1`）。由前缀封闭性，以 `r` 结尾的合法子数组**恰好**是 `l ∈ [0, f(r)-1]` 这 `f(r)` 个。**为什么原来不行**：每个 `r` 都从头数 M 的个数，重复了 O(n) 的扫描；**现在为什么行**：`f(r)` 随 `r` 单调不减（右端点右移只会让窗口更大、M 更多，临界点只会往右走），所以用一个左指针就够 —— 每轮右指针加一格使 M 的计数 +0/+1，一旦达到 k 就让左指针右移直到计数掉回 k−1。**左指针整趟只前进 n 次**，摊还 O(1)/轮，总时间 O(n)；而且 `left` 的数值本身就是答案要的东西。
4. **最优解**：滑窗 + 每轮 `ans += left`。

### 正确性论证（不变量 + 归纳步 + 终态）

- **不变量**：每轮 `while` 结束后，`left` 满足 —— 窗口 `[left, right]` 内 M 的个数 `≤ k-1`（非法），且当 `left > 0` 时窗口 `[left-1, right]` 内 M 的个数 `≥ k`（合法）。即 `left` 恰是 `f(right)`。
- **归纳步**：`right-1` 轮结束时 `f(right-1)` 已知。加入 `nums[right]` 后，窗口内 M 的个数最多涨 1（若 `nums[right] == M`），所以「M 的个数 ≥ k」这一谓词的临界点右移量完全由新增元素与左端被弹出的元素决定；`while` 的条件 `cnt[M] >= k` 与循环体内的 `left += 1` 恰好构成「把临界点推到不小于旧值、且落在最小合法位置」的定点迭代，退出时即得 `f(right)`。
- **为什么合法起点数 = `left`**：由窗口「删除元素不会让 M 的个数增加」，`l ≥ left` 时 `[l, right]` 中 M 的个数 ≤ 窗口内的个数 ≤ k−1 ⇒ 非法；`l ≤ left-1` 时 `[l, right]` 是窗口 `[left-1, right]` 的超集 ⇒ M 的个数 ≥ k ⇒ 合法。故合法起点恰为 `0..left-1`，共 `left` 个。
- **终态即答案**：每个 `r` 都贡献了「以 `r` 结尾的全部合法子数组」，且不同结尾的子数组互不相同 ⇒ 累加即为答案，不重不漏。
- **另一条独立视角**：整个循环里 `left` 只在「窗口已凑够 k 个 M」时才被推动，所以任何时刻 `left` 都等于「窗口内部最后 k 个 M 中最旧那个的位置 + 1」—— 这直接给出了第五节的「一次跳转」版实现。

### 关键点

- M 是**全局**最大值，与子数组无关，全程只算一次 `max(nums)`。
- **收缩的目标是「让窗口重新非法」**，而不是「让窗口合法」—— 这是本族与「最长/最短窗口」家族最根本的分歧点：那族的窗口每轮都合法、答案口径是长度；本族窗口每轮结束时**故意保持非法**，答案口径是**左指针位置**。
- 判据是**按值**的（`cnt[M] >= k`），不是**按键数**的（窗口内不同种类数）。所以哈希表里的键**不需要删**：计数归零的键留在表里完全无害。（对比：`窗口内不同字符数 ≤ K` 那类题如果忘了 `del`，键数只增不减，左指针会被推到越界 —— 两族判据别串用。）
- 前缀封闭性是 `ans += left` 的全部依据，也是本族能 O(n) 的根据。

## 三、代码实现

### 最终代码

```python
from collections import Counter
from typing import List


class Solution:
    def countSubarrays(self, nums: List[int], k: int) -> int:
        n = max(nums)                # 全局最大元素 M（注意：这里的 n 不是数组长度）
        ans = left = 0
        cnt = Counter()
        for right, j in enumerate(nums):
            cnt[j] += 1
            while cnt[n] >= k:       # 窗口内 M 的个数仍 ≥ k → 左边界还能右移
                cnt[nums[left]] -= 1
                left += 1
            ans += left              # 以 right 结尾的合法子数组：左端点取 0..left-1
        return ans
```

## 四、复杂度分析

| 版本 | 时间复杂度 | 空间复杂度 |
| :--- | :--- | :--- |
| **最终代码**（Counter + while） | O(n) | O(D) ≤ O(n) |
| 朴素解法（枚举所有子数组） | O(n²) | O(1) |
| 理论下界 | Ω(n) | O(1) |

> 复杂度中的 `n` 指**数组 `nums` 的长度**（注意与代码里被命名为 `n` 的 `max(nums)` 无关）；`D` 指数组中出现过的不同值的个数。
>
> - 时间 O(n)：右指针前进 n 次，左指针整趟也只前进 n 次（摊还 O(1)/轮），`while` 循环体总执行次数 ≤ n。
> - 空间 O(D)：`Counter` 保留窗口内**出现过**的全部值的计数（本题按值判据，不需要删键），`D ≤ n`。
> - 下界 Ω(n)：不知道 M 是谁就无从判据，而确定 M 必须扫完整个数组；额外空间可以压到 O(1)（见第五节）。

## 五、优化评估

**结论**：**时间已到理论下界 O(n)，空间与常数仍有优化余地** —— 空间可从 O(D) 压到 O(1)，实测常数上还能再快 3.5×～4.8×。

### 瓶颈分析

- **时间**：渐近上已经无可优化（左指针摊还 O(1)/轮）。剩下的全是常数：每轮要做 `cnt[j] += 1`（一次哈希读 + 一次哈希写）与 `cnt[n]`（一次哈希读），而这些操作维护的是**整张计数表**，可本题的判据只需要**一个数** —— M 在窗口里的个数。
- **空间**：`Counter` 记录的是窗口内所有元素的计数，但 `while` 条件只用到 `cnt[M]`，其余全是冗余信息。值域大时（下表 B 场景，值域 ≈ n）键数能涨到 n 个，白占 O(n) 空间。

### 可优化空间

把「整张计数表」换成「一个标量」`cm` = 窗口 `[left, right]` 内 M 的个数：

- 右端遇到 M → `cm += 1`；
- `while cm >= k` 时收缩，**只有移出的那个元素正好是 M 才 `cm -= 1`**。

这样空间降到 O(1)，同时把每轮 3 次哈希访问降成常数次整数比较。

### 优化代码

**优化版 A —— 单计数器（O(1) 空间）**

```python
from typing import List


class Solution:
    def countSubarrays(self, nums: List[int], k: int) -> int:
        m = max(nums)
        ans = left = 0
        cm = 0                       # 窗口 [left, right] 内 M 的个数
        for right in range(len(nums)):
            if nums[right] == m:
                cm += 1
            while cm >= k:
                if nums[left] == m:
                    cm -= 1
                left += 1
            ans += left
        return ans
```

**优化版 B —— 下标队列 + 一次跳转（不写 `while`）**

```python
from collections import deque
from typing import List


class Solution:
    def countSubarrays(self, nums: List[int], k: int) -> int:
        m = max(nums)
        ans = left = 0
        pos = deque()                # 窗口内 M 出现的下标（升序）
        for right, x in enumerate(nums):
            if x == m:
                pos.append(right)
                if len(pos) == k:            # 窗口里刚好凑够 k 个 M
                    left = pos.popleft() + 1 # 最小合法起点 = 最旧那个 M 的下标 + 1
            ans += left
        return ans
```

**优化理由**：

- 版 A：判据只依赖 M 的计数，其余信息的维护纯属浪费。用标量替代 `Counter`（`dict` 子类），每轮少掉哈希读写，空间降到 O(1)。
- 版 B：`while` 版是「删一格、试一格」，其实收缩终点可以直接算出来 —— 由正确性论证里的第二条视角，`left` 恒等于「窗口内最后 k 个 M 中最旧那个的位置 + 1」，所以凑够第 k 个 M 的那一刻一步跳到位即可。它与 `while` 逐格收缩**逐轮状态完全等价**（对拍 44 组偏差 0），只是消掉了内层循环的全部迭代判断。

**实测（n = 10⁵，9 轮轮转取最优，单位 ms）**：

| 场景 | while + Counter（最终代码） | 版 A 单计数器 | 版 B 下标队列 |
| :--- | ---: | ---: | ---: |
| A 值域 1..1000, k=20 | 33.68 | 10.33 | 6.29 |
| B 值域 ≈ n, k=1 | 41.16 | 8.48 | 6.30 |
| C 全同值, k=1 | 34.52 | 12.36 | 11.89 |
| D 值域 {0,1}, k=2 | 35.81 | 13.10 | 9.78 |
| E 前 99999 个非 M + 1 个 M, k=1（单轮内层最长） | 43.65 | 9.59 | 4.91 |
| **五场景合计** | **188.82** | **53.85（快 3.5×）** | **39.16（快 4.8×）** |

> B 场景是专门为 `Counter` 设计的「最坏情况」：值域 ≈ n 时它的键数会涨到 10⁵，实测比 A 场景（值域仅 1000）慢了 7.5 ms；而版 A / 版 B 完全不带哈希表，在 B 场景反而是最快的一档。

### 常数级优化（可选）

- 不要用 `Counter` / `dict` 充当「单变量计数器」：实测慢 3.5×（见上表），纯粹是数据结构选错。
- 版 B 用下标队列替代「回看数组」：`while` 版每格都要 `nums[left]` 读一次数组，版 B 直接由 M 的下标算出跳转终点。
- `max(nums)` 这趟扫描无法省略（不知道 M 就无从判据），属于必要开销。

## 六、易错点与总结

### 易错点

1. **「最大元素」= 全局最大值，不是子数组自身的最大值** —— 本题唯一的阅读理解陷阱。更要命的是：**两个官方示例在两种读法下答案恰好相同**（示例 1 中重复出现的只有 3，它既是全局最大值、也是那些子数组的最大值），所以读错题也能过示例。反例：`nums = [5,1,1], k = 2` —— 正解 **0**（没有任何子数组含两个 5），按「子数组自身最大值」读会得 **1**（子数组 `[1,1]`）。
2. **`while` 不能换成 `if`**：加入一个 M 后窗口内 M 的个数最多到 k，而**移出一个元素未必减掉一个 M**（可能移出的是非 M），一次收缩不足以让窗口回到非法。实测最小反例 `nums = [1,3,3], k = 2`：正解 **2**（`[1,3,3]`、`[3,3]`），`if` 版得 **1**；24 组小批量用例里 `if` 版错 10 组。
3. **别把「长度口径」家族的四象限表搬过来**：那张表（含「`while` 换 `if` 仍然正确」那一格）的前提是「答案口径 = 窗口长度」且「窗口长度单调不减」。本题答案是**计数**，窗口收缩后**故意保持非法**，靠左指针位置反推合法起点数 —— 口径不同，结论不可迁移。
4. **判据按值、不按键数 ⇒ 不需要删键**：`cnt[M] >= k` 是值判据，计数归零的键留在表里无害；习惯性 `del` 只是徒增开销。反之若遇到「窗口内不同字符数 ≤ K」这类**键数**判据的题，不删键就是 bug（键数只增不减，左指针会被推到越界）。
5. **变量名 `n` 遮蔽了「数组长度」的惯例**：`n = max(nums)` 之后代码里的 `n` 是**元素值**，`while cnt[n] >= k` 看着像「计数表长度」，其实是「最大元素的计数」；若后续还想用长度做别的计算就会踩坑。建议改名 `m` / `mx`。
6. **答案可能超出 32 位**：全同值且 `k = 1` 时答案为 `n(n+1)/2`，`n = 10^5` 时约 **5.0×10⁹ > 2³¹−1**。Python 天然无溢出；换 C++ / Java 必须开 `long long`。

### 题型套路沉淀

- **「统计满足某性质的子数组个数」通用套路**：固定右端点 `r` → 求临界左边界 `f(r)` → 若性质对左端**前缀封闭**（往左扩只会更满足）→ 以 `r` 结尾的合法子数组数 = `f(r)`（或 `n - f(r)`）→ 累加。三步固定动作：验前缀封闭、用滑窗维护 `f(r)`、`ans += left`。
- **先判断这题属于哪族滑窗**：看收缩后的窗口是「合法」还是「故意非法」。
  - 合法 ⇒ **最长/最短窗口族**：口径是**窗口长度**，每轮取 `max`（或用 `n - left`），`while` 收缩到合法为止。
  - 故意非法 ⇒ **计数族**：口径是**左指针位置**，`ans += left`，`while` 收缩到非法为止。
  本题属后者。族选错，后面所有结论（能不能换 `if`、答案取什么）全会错。
- **「至少 k 个某元素」的判定只看那一个值的计数** —— 一个标量就够，不需要整张表。多维护的信息在渐进复杂度上不显眼，在常数和空间上却是实打实的浪费。
- 同族题型（同为「固定右端点 + 计数合法起点」的计数族滑窗）：`713. 乘积小于 K 的子数组`、`2302. 统计得分小于 K 的子数组数目`、`1358. 包含所有三种字符的子字符串数目`。
