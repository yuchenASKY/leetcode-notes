# 3795. 不同元素和至少为 K 的最短子数组长度

> **难度**：中等
> **标签**：数组 · 哈希表 · 滑动窗口
> **原题链接**：https://leetcode.cn/problems/minimum-subarray-length-with-distinct-sum-at-least-k/

---

## 一、题目描述

给定整数数组 `nums` 和整数 `k`，求**最短**的连续非空子数组长度，使得该子数组中**不同值之和**（每个值只累加一次，重复出现不重复计数）**至少**为 `k`；不存在这样的子数组则返回 `-1`。

注意度量的口径：不是"子数组元素之和"，而是"子数组里**去重后**的元素之和"。例如 `[2, 2, 3]` 的度和是 `2 + 3 = 5`，不是 `7`。

### 示例

```text
输入：nums = [2,2,3,1], k = 4
输出：2
解释：子数组 [2,3] 的不同值 {2,3} 之和 = 5 ≥ 4，长度 2 为最短。

输入：nums = [3,2,3,4], k = 5
输出：2
解释：子数组 [3,2] 的不同值 {3,2} 之和 = 5 ≥ 5。

输入：nums = [5,5,4], k = 5
输出：1
解释：子数组 [5] 的不同值 {5} 之和 = 5 ≥ 5。
```

### 约束条件

- `1 <= nums.length <= 10^5`
- `1 <= nums[i] <= 10^5`
- `1 <= k <= 10^9`

## 二、解题思路

### 核心思想

**把"窗口内不同值之和"做成一个可增可减的滑窗状态**（计数表 `cnt` + 累计量 `temp`），问题就退化成经典的「最短窗口使度量 ≥ k」：固定右端时，窗口越小度量越小，于是左端右移 **单调** 地把度量压下去 —— 双指针成立。

### 思路演进

1. **暴力解法**：枚举所有子数组。对每个左端点 `i`，用 `set` 增量维护不同值集合与度和，向内枚举 `j`；一旦度和 ≥ k 就 `break`（更长的 j 只会更长）。时间 **O(n²)**、空间 O(V)，`n = 10^5` 时 10^10 量级的操作，必然超时。

2. **瓶颈定位**：慢在"每个左端点都要重新向内扫一遍"。虽然 `break` 剪掉了 j 维度上多余的部分，但 `n` 个起点之间的信息**完全不共享** —— 从 `i` 挪到 `i+1` 时，前一轮辛苦攒出来的 `set` 与度和全被丢掉，重来一遍。

3. **关键转化**：有两条由弱到强的路。

   **① 存在性对长度单调 → 二分答案。** 若长度 `L` 存在合法窗口 `[i, j]`，则 `L + 1` 一定也存在：`j + 1 < n` 时把窗口右扩一格（不同值集合只增不减，度和不会变小）；`j = n - 1` 时必有 `i >= 1`，把窗口左扩一格 `[i-1, n-1]` 同理。于是对长度二分、判定用定长滑窗一次 O(n) 扫完，总 **O(n log n)**。比暴力好了一个数量级，但仍不是线性。

   **② 固定右端时"度和随左端单调不增" → 双指针。** 固定右端 `r`，令 `g(l)` = 窗口 `[l, r]` 的不同值之和。`l` 右移 ⟹ 窗口作为集合只会变小 ⟹ 它的不同值集合是原集合的**子集** ⟹ `g(l)` 单调不增。所以合法的左端集合是一个前缀 `[0, l_max]`，**以 `r` 结尾的最短合法窗口就是以 `l_max` 为左端的那个**。右端单向前进、左端只前进不回退，两端总步数各 ≤ n ⇒ 总体 **O(n)**。

   把 `g` 落成增量维护的两个量：

   - 加入一个值 `x`：若 `cnt[x] == 0`，说明 `x` 是窗口里的**新值**，`temp += x`；然后 `cnt[x] += 1`。
   - 移出一个值 `x`：`cnt[x] -= 1`；**减到 0 时**才说明 `x` 彻底离开窗口，此时 `temp -= x`。

4. **最优解**：双指针，O(n) 时间 / O(V) 空间（`V` = 不同值个数）。而任何算法都必须至少读一遍数组（否则未读的那个元素完全可能让答案变成 1），**Ω(n) 是时间下界** —— 已经贴到理论下界，没有数量级空间可挖了。

### 关键点

- **判据**：窗口合法 ⟺ `temp >= k`。收缩条件是 `while temp >= k`（**不是** `>`），因为"至少为 k"包含取等。
- **重复元素不会刷新答案**：若 `nums[r]` 在当前窗口里已经出现过，那么对任意左端 `l`，`[l, r]` 与 `[l, r-1]` 的不同值集合**完全相同**（`nums[r]` 这个值已经在里面了），而前者长度还多 1。所以以 `r` 结尾的最短合法窗口绝不会把"重复元素"放在右端 —— 这一轮可以直接跳过，答案只可能由"新值入场"的那些轮更新。
- **`continue` 其实是个零成本护栏**：每一次进入循环体时都有 `temp < k`（`k >= 1` 时首轮 `temp = 0 < k`；后续每轮或以 `while` 退出、或 `while` 根本没进，退出时同样 `temp < k`）。所以重复元素加入后 `temp` 仍然 `< k`，后面那个 `while temp >= k` **本来就不会执行**，`continue` 省掉的只是"重新求值一次条件"。它是等价改写，不是必要分支（实测也确认无收益，见第五节）。
- **单调性的来源是"集合包含"，不是"元素非负"**：本题 `g(l)` 单调是因为窗口缩小 ⟹ 不同值集合是子集，跟元素正负**无关**（哪怕允许负数，度和依然单调不增）。这一点是与"窗口元素和 ≤ budget"那一族最本质的区别 —— 后者的单调性建立在逐元素可加 + 非负之上，一旦有负权就塌，必须换前缀和 + 单调队列。**这里不要套用那边的"必须非负"前提。**
- **属于"按值"型窗口，不是"按键数"型**：`cnt` 的键是元素**值**，计数归零**不需要删键**，结果一样正确（删键只是内存与常数的取舍，见第五节）。若换成"窗口内不同种类数 ≤ K"那类题，才必须删键，否则键数只增不减、左指针会被推到越界。
- **属于"最短"型，别套"最长"型的写法**：本题是度量 **≥ 目标** 时收缩，答案是"收缩到不能再收"的那个窗口长度，所以左指针必须用 `while` 收到底；"最长"型的平移版（左指针每轮最多挪一格 + 终值口径 `n - left`）在这里**不适用**。

## 三、代码实现

### 最终代码

```python
from collections import defaultdict
from math import inf
from typing import List


class Solution:
    def minLength(self, nums: List[int], k: int) -> int:
        ans = inf
        left = temp = 0                # temp: 当前窗口内「不同值之和」
        cnt = defaultdict(int)         # 值 -> 在当前窗口内的出现次数
        for right, j in enumerate(nums):
            if cnt[j] >= 1:            # j 这一值已在窗口里：不会刷新答案，跳过
                cnt[j] += 1
                continue
            cnt[j] += 1                # 新值入场
            temp += j
            while temp >= k:           # 收缩到恰好非法，最后一个记录的即最短
                ans = min(ans, right - left + 1)
                if cnt[nums[left]] == 1:   # 移出后该值彻底离开窗口
                    temp -= nums[left]
                cnt[nums[left]] -= 1
                left += 1
        return ans if ans <= len(nums) else -1
```

> 截图里只有 `class Solution:`，上面的 `defaultdict` / `inf` / `List` 三个 import **是补上的**，本地运行需要它（LeetCode 判题环境会预置这些 import，所以提交时不必写）。

## 四、复杂度分析

| 版本 | 时间复杂度 | 空间复杂度 |
| :--- | :--- | :--- |
| **最终代码（双指针）** | O(n) | O(V) |
| 二分答案 + 定长滑窗判定 | O(n log n) | O(V) |
| 朴素解法（枚举左端点 + 增量 set） | O(n²) | O(V) |
| 理论下界 | Ω(n) | Ω(min(n, V)) |

> 复杂度中的 `n` 指 `nums` 的长度，`V` 指 `nums` 中**不同值**的个数（`V <= n`）。
> 时间下界的依据：任何算法都必须读完全部元素，否则未读的那个元素完全可能让答案变成 1。
> 空间下界的依据：窗口的"不同值集合"最坏可以占满整个数组，维持它至少需要 `min(n, V)` 个条目。
> 最终代码的额外空间正是计数表 `cnt` 的大小：**原版 = V**（历史上出现过的所有值都留着键），**第五节优化版 = 窗口内不同值个数**（归零即删键）。

## 五、优化评估

**结论**：时间复杂度已是理论下界 **O(n)**，数量级上无优化空间；但**常数层面仍有可量化的收益** —— 把归零的计数键删掉（值域大时 1.32~1.35×），并把 `min()` 换成直接比较（~1.07×）。另外实测确认：用户原版里的 `continue` 分支是**零收益**的等价护栏，不必动它。

### 瓶颈分析

- 主循环 `n` 次 + 左指针总推进 ≤ `n` 次，每步都是 O(1) 的字典读写，**耗时几乎全在字典操作上**（以及收缩路径上每次一次的 `min()` 函数调用，被执行 Θ(n) 次）。
- **原版的隐性代价在空间局部性**：`cnt` 从不删键，键数最终会涨到**整个数组的不同值个数 `V`**（`nums[i] <= 10^5` 时最多 10 万个键），而窗口里通常只有几十~几百个不同值。字典越大，哈希探测越容易跳到不同的 cache line。这一点在"**值域 ≈ n、元素互不相同**"的输入上被放大。
- 反过来说，如果值域本来就很小（高重复输入），键数天然只有几十个，删键**一点用都没有** —— 所以这不是"普适提速"，而是"最坏情况补漏"。

### 常数级优化实测

同一台机器、同一轮次内**轮转测量**（`for rep in range(9): for 每个版本`），取 9 轮最优值；两轮复核结论一致。

**场景一：值域 ≈ n（`1..10^5` 随机排列，`k = 10^7`，答案 171，`n = 10^5`）**

| 版本 | 第一轮 | 第二轮 | 相对原版 |
| :--- | ---: | ---: | ---: |
| 用户原版（带 `continue`） | 46.6 ms | 46.0 ms | 1.00× |
| A：去掉 `continue` | 46.0 ms | 45.8 ms | 1.00~1.02× |
| B：计数归零时 `del` 键 | 35.4 ms | 34.1 ms | **1.32~1.35×** |
| C：`del` 键 + 去掉 `min()` | 32.7 ms | 32.2 ms | **1.43×** |

**场景二：高重复（值域 `1..100` 随机，`k = 4000`，答案 100，`n = 10^5`）**

| 版本 | 第一轮 | 第二轮 | 相对原版 |
| :--- | ---: | ---: | ---: |
| 用户原版（带 `continue`） | 28.2 ms | 28.6 ms | 1.00× |
| A：去掉 `continue` | 28.5 ms | 28.8 ms | 0.99× |
| B：计数归零时 `del` 键 | 28.9 ms | 28.4 ms | 0.98~1.01× |
| C：`del` 键 + 去掉 `min()` | 26.4 ms | 26.4 ms | **1.07~1.08×** |

**读表：**

- **A 没有收益**（0.99~1.02×，落在噪声里）—— 正好印证第二节的静态推导：`continue` 只是省掉一次必然为假的 `while` 条件求值。
- **B 的收益量级完全由"值域 / 窗口不同值数"的比值决定**：比值大（场景一，10^5 : ~171）时 1.3× 以上；比值小（场景二，100 : ~10）时归零。
- **C 相对 B 的额外收益（去掉 `min()`）在两个场景都稳定在 ~7%**：收缩路径被执行 Θ(n) 次，每次省一次函数调用。

### 优化代码

```python
from collections import defaultdict
from math import inf
from typing import List


class Solution:
    def minLength(self, nums: List[int], k: int) -> int:
        ans = inf
        left = temp = 0
        cnt = defaultdict(int)
        for right, j in enumerate(nums):
            if cnt[j] >= 1:
                cnt[j] += 1
                continue
            cnt[j] = 1                 # 新值入场（键此前不存在，直接赋值，省一次读）
            temp += j
            while temp >= k:
                length = right - left + 1
                if length < ans:       # 用直接比较替代 min() 调用
                    ans = length
                x = nums[left]         # 取局部变量，避免下标重复求值
                if cnt[x] == 1:        # 移出后该值彻底离开窗口
                    temp -= x
                    del cnt[x]         # 关键：计数归零就删键，让字典只装窗口内的值
                else:
                    cnt[x] -= 1
                left += 1
        return ans if ans <= len(nums) else -1
```

**优化理由**：

1. **`del cnt[x]`（收益主体）**：原版把"历史上出现过的所有值"都留在字典里，优化版让字典的键数恒等于**窗口内的不同值个数**。复杂度不变（都是 O(V) 级），但字典规模从"整个数组的不同值数"降到"窗口的不同值个数"，在值域远大于窗口不同值数的输入上实测 1.32~1.35×。**注意这只是常数优化，且值域小时收益为零。**
2. **`if length < ans` 替代 `min(ans, length)`**：少一次函数调用，收缩越密集收益越明显（实测 ~1.07×）。
3. **`cnt[j] = 1` 替代 `cnt[j] += 1`**：该分支下 `cnt[j]` 必然不存在（上一行刚判过 `cnt[j] >= 1` 为假），所以直接赋值比"读-加-写"少一次哈希查找。
4. **正确性不受影响**：唯一改变语义的是"键是否存在"（原来靠 `cnt[x] == 0` 表示值不在窗口，现在靠"键不存在"表示）。代码里所有计数读取都发生在"该值必然在窗口内"的位置（`cnt[x] == 1`、`cnt[j] >= 1`），不会踩到 `defaultdict` 隐式建 0 键的行为。

## 六、易错点与总结

### 易错点

- **变量名误导**：`for right, j in enumerate(nums)` 里 `j` 是**元素值**不是下标，真正当下标用的是 `right` / `left`。题面里的 `j` 很容易被当成索引。
- **`while temp >= k` 不能写成 `>`**：题目是"至少为 k"，取等也要收缩。示例 3（`nums = [5,5,4], k = 5`，答案 1）就是靠取等触发收缩。
- **减 `temp` 的时机**：必须先判断 `cnt[x] == 1`（最后一次出现）再 `cnt[x] -= 1`，顺序写反就会漏减。用 `defaultdict` 时"读计数"会隐式建 0 键，所以要删键时先取到局部变量再判断，别在同一表达式里又读又删。
- **返回 `-1` 的分支不能省**：`ans` 初值 `inf`，最后用 `ans <= len(nums)` 判断是否有解。
- **别套"最长窗口"的平移版写法**：本题是"最短"型，左指针必须 `while` 收到底；换成"每轮最多挪一格 + 答案取终值 `n - left`"会大面积出错。
- **别把"按键数"族的习惯当成本题的正确性要求**：本题是"按值"型窗口，计数归零**不删键也是对的** —— 删键只影响内存和常数，不影响结果。反过来在"窗口内不同种类数 ≤ K"那类题里，不删键就直接错。

### 题型套路沉淀

- **最短窗口型（度量 ≥ 目标）的固定骨架**：

  ```text
  右端从 0 扫到 n-1：
      把 nums[right] 并入窗口状态
      while 窗口满足下限约束：        # 度量 >= 目标
          用当前窗口长度刷新答案      # 注意：刷新发生在收缩之前
          把 nums[left] 移出窗口状态；left += 1
  循环结束时窗口「恰好不满足约束」
  ```

  `while` 收到底保证了**最后一个被记录的窗口就是以 right 结尾的最短合法窗口**，因此每轮取 `min` 是对的；把 `while` 换成 `if` 在本型不成立。
- **判断能不能上双指针，只看一条**：固定右端时，窗口度量是否随左端右移**单调**（不增或不减）。满足就能"右端不回退 + 左端不回退"，把 O(n²) 压到 O(n)。
- **但"单调"的来源必须分清**：本题来自**集合包含关系**（窗口缩小 ⟹ 不同值集合是子集），**与元素正负无关**；而"窗口元素和 ≤ budget"一类的单调性来自**元素可加 + 非负**，有负权就塌。两族的判据不能互相套用，否则会把不该有的前提（或不该有的结论）带进来。
- **窗口状态的两族要认清**：**按值**（每个元素的出现次数，归零不必删键）vs **按键数**（窗口内不同种类数，归零必须删键）。看题目约束的是"某个元素的出现次数"还是"不同种类的个数"就能分开。
- **"最短"与"最长"的配套口径完全不同**：最短型是"收缩到非法 + 每轮取 max/min 长度"，最长型才轮到"平移版 + 终值 `n - left`"。
