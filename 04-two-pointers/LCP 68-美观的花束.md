# LCP 68. 美观的花束

> **难度**：中等
> **标签**：数组 · 滑动窗口
> **原题链接**：https://leetcode.cn/problems/1GxJYY/

---

## 一、题目描述

一排鲜花从左到右摆开，`flowers[i]` 是第 i 个位置的**品种编号**。可以选任意一段**连续区间**做成插花（不能丢弃区间内的花）。如果这段区间里**每个品种的出现次数都不超过 `cnt`**，就说这束插花是「美观的」。求一共有多少个可选的区间是美观的。

### 示例

```text
示例 1
输入：flowers = [1,2,3,2], cnt = 1
输出：8
解释：同一品种最多出现 1 次。
      长度 1：[1]、[2]、[3]、[2]            → 4 个
      长度 2：[1,2]、[2,3]、[3,2]            → 3 个
      长度 3：[1,2,3]                        → 1 个
      [2,3,2]、[1,2,3,2] 都含 2 朵品种 2，不合法
      合计 4 + 3 + 1 = 8

示例 2
输入：flowers = [5,3,3,3], cnt = 2
输出：8
解释：全部 10 个区间里，含 3 朵品种 3 的只有 [3,3,3] 与 [5,3,3,3] → 10 - 2 = 8
```

### 约束条件

- `1 <= flowers.length <= 10^5`
- `1 <= flowers[i] <= 10^5`
- `1 <= cnt <= 10^5`
- **结果无需取模**，用例保证输出在 int32 范围内

## 二、解题思路

### 核心思想

固定右端点 `r` 时，**合法的左端点一定是 `[L(r), r]` 这样一段连续后缀**，所以"以 r 结尾的合法区间"恰好 `r - L(r) + 1` 个；而 `L(r)` 随 `r` 单调不减 —— 于是用一个滑动窗口维护 `L(r)` 即可。

### 思路演进

1. **暴力解法**：枚举全部 O(n²) 个区间，每个区间统计各品种出现次数（每区间重建计数 O(长度)）→ O(n³)；若改成"固定左端、右端递增时增量计数"→ O(n²)。n = 10⁵ 时是 10¹⁰ 量级，必然超时。
2. **瓶颈定位**：`[l, r]` 与 `[l, r+1]` 的计数几乎一样，暴力却对每个 `l` 从头数一遍 —— 重复劳动；更糟的是**完全没有剪枝**：已经知道 `[l, r]` 不合法了，还要继续枚举 `[l, r+1]`、`[l, r+2]`…
3. **关键转化**：注意到两条单调性。
   - **继承性**：区间变大时各品种计数只增不减，所以 `[l, r]` 合法 ⇒ 它的**任何子区间**都合法；
   - **后缀性**：固定 `r`，若 `[l, r]` 合法，则 `[l+1, r]、[l+2, r]…` 全都合法（左端右移只会删元素）。
   
   合起来：固定 `r` 时的合法左端点是连续的一段 `[L(r), r]`，个数直接算出来。而 `L(r)` **单调不减**（r 变大只会让窗口更满，最小合法左端不可能回退）—— 前提具备，可以上双指针。
4. **最优解**：右指针每轮把 `flowers[r]` 入窗；**只有当新入窗的品种计数超过 `cnt`** 时，才从左侧不断弹出元素直到它回到 `cnt` 以内。此时 `[left, r]` 就是"以 r 结尾的极大合法窗口"，答案累加 `r - left + 1`。左右指针各走一趟，均摊 O(n)。

### 关键点

- **判据**：窗口合法 ⟺ `∀ 品种 v：窗口内 v 的出现次数 ≤ cnt`。
- **收缩判据只需要看新入窗的那个品种**。窗口在入窗前已经合法，入窗后唯一的计数变化是 `cnt0[x] += 1`，**只有 x 可能违规**。这是 `while cnt0[j] > cnt` 成立的全部依据 —— 不写清这个不变量，读者会以为它漏检了别的品种。
- **"违规量恒为 1" ≠ "只需挪一格"**：超出的**量**是 1（计数超了 1 朵），但要把这一份超出消掉，可能要连着弹很多格 —— 实测单轮最多弹过 **2786 格**。所以这里必须是 `while`，不能是 `if`。
- **判据按「值」，不是按「键数」**：本题违规条件是"某个品种的计数 > cnt"，计数降到 0 也**不需要** `del` 键。这与"窗口内不同种类数 > K"那一族（如 `3. 无重复字符的最长子串`）恰好相反 —— 那族必须删键，否则键数只增不减、左指针会被推越界。**两族别串用**。
- 回答的是**区间个数**，不是最长窗口长度 —— 这个差异决定了后面"收缩方式 × 答案口径"该怎么选。

## 三、代码实现

### 最终代码

```python
from collections import defaultdict
from typing import List


class Solution:
    def beautifulBouquet(self, flowers: List[int], cnt: int) -> int:
        cnt0 = defaultdict(int)        # 品种 -> 当前窗口内的出现次数
        ans = left = 0
        for right, j in enumerate(flowers):
            cnt0[j] += 1               # 右端入窗
            while cnt0[j] > cnt:       # 只有新入窗的品种 j 可能违规
                cnt0[flowers[left]] -= 1
                left += 1
            ans += right - left + 1    # 以 right 结尾的合法区间数
        return ans
```

> 截图里只有 `class Solution:` 本体，`defaultdict` 与 `List` 两个 import 是本次补上的（让笔记里的代码可直接运行）。截图共 11 行、末尾 `return ans` 完整，没有被裁掉的行。

### 正确性论证

**不变量**：每轮 `while` 结束后，窗口 `[left, right]` 内每个品种的计数都 ≤ `cnt`，且 `left` 是满足该条件的**最小**下标（窗口极大）。

- **归纳（合法性）**：空窗口合法。设第 `right` 轮入窗前窗口合法；入窗后只有 `cnt0[flowers[right]]` 增加，其余计数不变，故**违规只可能来自新元素 `j`**。`while` 逐格弹出左端元素直到 `cnt0[j] ≤ cnt`，此时全部计数都回到约束内。
- **极大性**：入窗前 `cnt0[j] ≤ cnt`，入窗后 `cnt0[j] ≤ cnt + 1`，所以循环的停止点必然出现在"弹出的那一格恰好是最早的那个 `j`"之后 —— 再弹一格，窗口就不再是以 `right` 结尾的极大合法窗口。故结束时 `left` 正是 `L(right)`。
- **计数口径**：由左端后缀性，以 `right` 结尾的合法区间数 = `right - left + 1`，逐轮累加即答案。总计数 = 全部合法区间数，不重不漏。

## 四、复杂度分析

| 版本 | 时间复杂度 | 空间复杂度 |
| :--- | :--- | :--- |
| **最终代码** | O(n) | O(σ) |
| 朴素解法 | O(n³)（每区间重建计数）/ O(n²)（增量计数） | O(σ) |
| 理论下界 | Ω(n) | Ω(σ) |

> n 指 `flowers` 的长度（≤ 10^5）；σ 指数组里出现的**不同品种数**（≤ min(n, 10^5)）。
> 时间下界：任何正确算法都必须读完整个数组，故 Ω(n) 不可突破。
> 空间下界：要判断"每个品种都 ≤ cnt"，最坏情况下必须同时记住 σ 个品种的计数，故 Ω(σ) 也不可省。

左指针 `left` 全程只右移、最多走 n 格，所以 `while` 的总弹出次数 ≤ n，**内层是摊还 O(1)** 而不是 O(n)。插桩实测（n = 10⁵）：总弹出步数 96 581 ~ 99 000，摊还 **0.966 ~ 0.990 步/轮**。

## 五、优化评估

**结论**：时间复杂度已是理论下界 O(n)，**但常数项还有 1.2×~2.1× 的空间**；另外 **cnt = 1 时可以把逐格 `while` 整段换成"一次跳转"**。

### 瓶颈分析

- 时间上：每个元素至少要被读一次，Ω(n) 打不掉。
- 常数上时间花在两处：① 每轮一次哈希表读写（`dict` 的哈希与扩容）；② `while` 内的逐格弹出（摊还 ~1 步/轮，但**单轮峰值可达 2786 格**）。
- 空间上 `dict` 最坏要存 σ 个键；而题面给了 `flowers[i] ≤ 10^5` —— **值域有界，就没必要用哈希表**。

### 可优化空间

**① `dict` 计数 → 定长 `list` 计数（推荐，通用）**
值域 ≤ 10^5 时开一个 `max(flowers) + 1` 的数组即可，省掉全部哈希开销。实测 5 个场景**全胜**，提速 **1.21×~2.14×**。

**② `while` 逐格弹出 → 一次跳转（仅 cnt = 1）**
cnt = 1 时"窗口内最早的那个 j"就等于"j 上一次出现的位置"，于是可以直接 `left = last[j] + 1` 一步到位，连 `while` 和数组回写都省掉。实测 **1.99×~2.11×**，比只换数组还快一档。

**③ ~~通用化的一次跳转（每个品种挂一个 deque）~~**
~~用 deque 记录每个品种最近 cnt 个位置，超出 cnt 时 `left = 最早位置 + 1`。~~ **实测被证伪**：在"值域 ≈ n"（10 万个互不相同的品种）场景下只有 **0.20×**（比原版慢 5 倍）—— 每轮都要新建一个 `deque` 对象，10 万次对象创建直接主导了耗时；其余场景也只有 0.55×~1.15×。
⇒ **这个方向只在 cnt = 1（可用单个 `last` 数组、零对象创建）时成立，不要推广到一般 cnt。**

### 优化代码

通用版（定长数组 + 逐格收缩，实测 1.2×~2.1×）：

```python
from typing import List


class Solution:
    def beautifulBouquet(self, flowers: List[int], cnt: int) -> int:
        d = [0] * (max(flowers) + 1)   # 品种编号 <= 10^5，数组比 dict 快
        ans = left = 0
        for right in range(len(flowers)):
            x = flowers[right]
            d[x] += 1
            while d[x] > cnt:
                d[flowers[left]] -= 1
                left += 1
            ans += right - left + 1
        return ans
```

cnt = 1 专用版（一次跳转，实测 ≈2.0×）：

```python
from typing import List


class Solution:
    def beautifulBouquet(self, flowers: List[int], cnt: int) -> int:
        """仅当 cnt == 1 成立：此时"窗口内最早的 j"就是"上一次出现的 j" """
        last = [-1] * (max(flowers) + 1)
        ans = left = 0
        for right, x in enumerate(flowers):
            p = last[x]
            if p >= left:              # 上一次的 x 还在窗口里 → 直接跳到它后面
                left = p + 1
            last[x] = right
            ans += right - left + 1
        return ans
```

**优化理由**：① 把哈希查找换成数组下标访问，省掉每轮的哈希与扩容；② 当 `cnt = 1` 时"弹出到最早的那个 j 之后"这一步有闭式解，不必逐格模拟。两者都不改变 O(n)。

### 常数级优化（可选）

- 判据按值，计数归零时**不用** `del` 键 —— 比"按键数"家族少一次字典删除。
- 退化特判：`cnt >= n` 时全数组必然合法（任何品种最多出现 n 次），答案直接是 `n * (n + 1) // 2`，可以 O(1) 返回。只对极端用例有意义，属可选早退，本笔记未做实测。

## 六、易错点与总结

### 易错点

1. **把 `while` 换成 `if`（本题最典型的错误）**
   - 错在哪：`if` 每轮只弹一格，若弹出的**不是** `j`，窗口**仍然非法**；而 `ans += right - left + 1` 这个口径要求窗口每轮都"合法且极大"，于是把非法区间也数了进去。
   - 最小反例：`flowers = [1,2,2], cnt = 1` → 真值 4（`[1]、[2]、[2]、[1,2]`），`if` 版得 5（多算了非法的 `[2,2]`）。
   - 连**题目自带的两个示例都会挂**：示例 1 得 9（应 8）、示例 2 得 9（应 8）。
   - 为什么不能像"最长窗口"家族那样一句"长度单调所以没事"糊过去：**本题的答案是区间个数，不是窗口长度**。平移式写法（每轮只挪一格、允许窗口短暂非法）在"长度口径"下靠长度单调救命，搬到"计数口径"上会直接塌。
2. **误以为 `while cnt0[j] > cnt` 漏检了别的品种** —— 它没漏，依据是"入窗前窗口已合法 + 只有 j 的计数变化"。这个前提一旦被破坏（例如一次批量往窗口里加多个元素），就必须改回全量检查。
3. **把"按值"与"按键数"两族的判据串用** —— 本题按值（某品种计数 > cnt），计数归零不必删键；写成"窗口内不同品种数 > K"这种按键数的判据就必须删键。混用会导致左指针越界或窗口永远不合法。
4. **照抄带 `% (10**9+7)` 的题解** —— 本题题面写得很清楚"结果无需取模"。注意 int32 上限 2 147 483 647 **大于** 10⁹+7，所以"答案保证在 int32 内"**并不代表取模不会生效**：n = 65 000 且品种全不同时答案 2 112 532 500 仍在 int32 内，取模后变成 112 532 486，直接错。
5. **命名坑**：`for right, j in enumerate(flowers)` 里的 `j` 是**品种编号**不是下标（和左指针 `left` 并排看尤其像）；`cnt`（阈值）与 `cnt0`（计数表）只差一个字符。建议改用 `x` 与 `counter`。
6. **负下标**：本题没有 `right - k` 这类下标表达式，不存在 Python 静默取到末尾元素的隐患（写定长窗口变体时才需警惕）。

### 题型套路沉淀

- **"统计满足条件的子数组个数"骨架**（越短越合法型）：

  ```python
  left = ans = 0
  for right in range(n):
      把 flowers[right] 的统计加进窗口
      while 窗口不合法: 从左侧弹出
      ans += right - left + 1      # 以 right 结尾的合法区间数
  ```

  `ans += right - left + 1` 有两条前提：① 合法性对"从左端删元素"封闭（子区间继承父区间的合法性）；② 每轮结束时窗口是"以 right 结尾的**极大**合法窗口"。两条都成立才能每轮累加。
- **收缩用 `while` 还是 `if`，由答案口径决定**：答案是"最长窗口长度"且窗口度量单调时，`if` 平移版可以等价；答案是"区间个数 / 元素和"时，`if` 版会让非法窗口参与计数，**必须用 `while` 收干净**（或精确跳到应到位置）。
- **判据族识别三连问**：违规是"按值"还是"按键数"？违规量恒为 1 是否等于只需挪一格？答案是长度还是计数？三问答完，收缩方式与计数表维护方式就定了。
- 同类题：`713. 乘积小于 K 的子数组`、`3258. 统计满足 K 约束的子字符串数量 I`、`2302. 统计得分小于 K 的子数组数目`。

### 7. 取模的静态核对

n = 65 000、品种全不同时答案为 2 112 532 500，小于 2^31 − 1 = 2 147 483 647（仍在 int32 内）；而 `2 112 532 500 % (10**9 + 7) = 112 532 486` ≠ 真值 —— 带 `mod` 的写法在这题是实打实的错解。
