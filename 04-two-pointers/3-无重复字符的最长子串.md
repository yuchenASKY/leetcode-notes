# 3. 无重复字符的最长子串

> **难度**：中等
> **标签**：哈希表 · 字符串 · 滑动窗口
> **原题链接**：https://leetcode.cn/problems/longest-substring-without-repeating-characters/

---

## 一、题目描述

给定字符串 `s`，求**不含重复字符的最长连续子串**的长度。要求是**子串**（连续），不是子序列 —— `"pwwkew"` 的 `"pwke"` 虽然每个字符都不同，但它是子序列，不算数。

### 示例

```text
示例 1
输入：s = "abcabcbb"
输出：3
解释：最长无重复子串是 "abc"，长度为 3。（"bca" 和 "cab" 也是正确答案）

示例 2
输入：s = "bbbbb"
输出：1
解释：最长无重复子串是 "b"，长度为 1。

示例 3
输入：s = "pwwkew"
输出：3
解释：最长无重复子串是 "wke"，长度为 3。
     请注意答案是子串长度，"pwke" 是子序列，不是子串。
```

### 约束条件

- `0 <= s.length <= 10^5`
- `s` 由**英文字母、数字、符号和空格**组成

> **一个隐藏但极重要的推论**：字符集是"可打印 ASCII"，大小只有 **95**（26 小写 + 26 大写 + 10 数字 + 32 符号 + 1 空格）。
> 因为窗口内不许有重复字符，所以 **窗口长度天然 ≤ 95**。这一点在后面复杂度分析里是决定性的 —— 它让"每轮切片"这类写法从 O(n²) 被救回 O(n)。

---

## 二、解题思路

### 核心思想

**变长滑动窗口**：维持窗口 `[left, right]` 内的字符**始终互不重复**这一不变量。右指针只进不退；遇到重复时，左指针**直接跳到那个重复字符上次出现的下一位**，而不是一格一格挪。

两个指针都单调右移，所以整体 O(n)。

### 思路演进

1. **暴力解法 O(n³)**：枚举所有子串 `s[i..j]`，用 `set` 判重，取最长的。`n = 10^5` 时是天文数字。

2. **暴力解法 O(n²)**：固定左端点 `i`，右端点 `j` 从 `i` 一路向右扩，扩到重复为止。每个 `i` 独立扫一遍，仍然 10^10 级。

3. **观察到（关键的一步）**：把所有 `i` 的扫描合起来看，其实**左端点根本不需要回退**。记 `L(r)` 为"以 `r` 结尾的最长无重复子串的左端点"，则 `L(r)` 关于 `r` **单调不减**（把左端点右移只会让"无重复"这个条件更容易满足）。这个性质是滑动窗口能成立的根基 —— 否则左指针来回跑，复杂度就退化了。

4. **进一步观察到（本题最省事的一步）**：维护窗口里的"字符计数表"或"set"都是**过度设计**。因为不变量保证窗口内本来就没有重复，那么新字符 `s[r]` 一旦造成重复，**重复对象只可能是它自己的上一次出现**。于是只需要记住"每个字符上次出现的下标"就够了：

   ```
   left = max(left, last[s[r]] + 1)
   ans  = max(ans, r - left + 1)
   ```

   整个算法坍缩成两行更新 + 一次查表。`last` 用大小为 95（或 128）的数组即可，连哈希都不用。

### 关键点

- **`left = max(left, last[ch] + 1)` 里的 `max` 不能省。** `last[ch]` 可能落在 `left` **左边**（那个位置早已滑出窗口，不再构成重复），此时若直接把 `left` 拖到 `last[ch] + 1`，左边界会**往回退**，答案偏大。这是 last 数组版最经典的错误，`"abba"` 这类输入必错。
- **「窗口内无重复」有两条实现路线**（与同目录 `1100` 那道题呼应）：
  - ① **计数表 + 窗口大小**：判据是"不同字符数 == 窗口长度"。出窗口时要 `del` 归零的键，多一步，容易漏。
  - ② **`last[c]` + 左边界跳转**：无删除操作、无计数回退，是**变长**窗口下的通用武器。本题正属于第 ② 类。
- **答案要在每一轮都更新**：滑动窗口的答案永远是"某个以 `r` 结尾的窗口长度"，漏更新会丢解。
- 左指针**只跳不动格**：一次跳到 `last[ch] + 1` 就足以消除重复，不需要 `while` 循环（这也是本题比通用滑窗模板更简洁的原因）。

## 三、代码实现

### 最终代码

用户提交的版本（逐字保留）：

```python
class Solution:
    def lengthOfLongestSubstring(self, s: str) -> int:
        s.replace(' ', '')
        if s == '':
            return 0
        ans = mid = right = 1
        left = 0
        for i in s[1:]:
            IndexFind = s[left : right].find(i)
            if IndexFind != -1:
                mid -= IndexFind
                left += IndexFind + 1
                right += 1
                continue
            right += 1
            mid += 1
            ans = max(ans, mid)
        return ans
```

**它好在哪**：它没有引入 `last` 数组，而是**用窗口自身当判据** —— `s[left:right].find(i)` 在窗口里找新字符，找不到就扩窗，找到就把左边界跳到"第一次出现"的下一位。因为窗口无重复，「第一次出现」就是「唯一一次出现」，所以 `left += IndexFind + 1` 一步到位，正确性没问题（实测见文末）。

**它的代价**：每轮 `s[left:right]` 都会**新建一个字符串对象**，这是唯一的实质开销；另外维护了一个完全冗余的变量 `mid`（见第五节）。

## 四、复杂度分析

| 版本 | 时间复杂度 | 空间复杂度 |
| :--- | :--- | :--- |
| **最终代码（用户版）** | O(n·\|Σ\|)，\|Σ\| ≤ 95 ⇒ 实际 O(n) | O(1)（额外切片 ≤ 95 字节） |
| 优化版 A（`rfind` 免切片） | O(n·\|Σ\|) 但常数更小 | O(1) |
| 优化版 B/C（`last` 数组） | **O(n)** | O(\|Σ\|) = O(1) |
| 朴素解法（固定左端点向右扩） | O(n²) | O(\|Σ\|) |
| 朴素解法（枚举子串 + set） | O(n³) | O(n) |
| 理论下界 | **Ω(n)** | Ω(1) |

> 复杂度中的 `n` 指字符串 `s` 的长度；`|Σ|` 指**字符集大小**，本题 `|Σ| ≤ 95`。
>
> **为什么用户版不是 O(n²)**：窗口内不许有重复 ⇒ 窗口长度 ≤ 字符集大小 = 95 ⇒ 每次切片最多复制 95 个字符 ⇒ 总时间 O(95n) = O(n)。如果字符集无界（比如允许任意 Unicode 字符），它才是真正的 O(n²)。

## 五、优化评估

**结论**：时间复杂度**已是理论下界 O(n)**，不需要动算法；但代码里有 **1 处死代码 + 1 处冗余状态 + 1 个可消除的分配**，都实测过。

### 瓶颈分析

**(1) `s.replace(' ', '')` 是死代码，而且会误导。**

Python 的 `str` 不可变，`s.replace(...)` 返回新串、**返回值被直接丢弃**，`s` 一个字都没变。更麻烦的是它有"我要把空格删掉"的语义暗示 —— 而题目里的字符集**明确包含空格**：

| 输入 | 正确答案 | 若真删掉空格 |
| :--- | ---: | ---: |
| `"a a"` | **2** | 1（错） |

所以这行不仅是无效代码，方向还是反的。删掉。

**(2) `mid` 是完全冗余的派生量：恒等于 `right - left`。**

给用户代码插桩、跑 2000 组随机输入，逐轮断言 `mid == right - left`：**0 次违反**。`mid` 从头到尾就是窗口长度的一个副本，`mid -= IndexFind` / `mid += 1` 只是在手工同步一个本来就能随时算出来的值。多维护一个状态，就多一个可能不一致的地方 —— 删掉。

**(3) `s[left:right]` 每轮新建字符串，是唯一的真实开销。**

实测每步累计复制的字符数（`n = 10^5`）：

| 输入场景 | 窗口最大值 | 切片累计复制字符数 | 平均每步 |
| :--- | ---: | ---: | ---: |
| 单字符重复 `"aaaa…"` | 1 | 99,999 | 1.0 |
| 2 种字符 | 2 | 150,060 | 1.5 |
| 26 种小写随机 | 22 | 605,163 | 6.1 |
| 95 种 ASCII 随机 | 42 | 1,186,557 | 11.9 |
| 95 个 ASCII 循环 | **95** | **9,495,440** | **95.0** |

规律很清楚：**窗口越接近字符集上界，切片开销越大**。最坏情况下每步白复制 95 个字符、总共近 1000 万字符。

### 可优化空间

两条路，按"改动幅度"排序：

- **A（最小改动）**：把 `s[left:right].find(i)` 换成 `s.rfind(i, left, right)` —— 直接在**原串**上搜指定区间，**零分配**，窗口骨架和 `find` 的语义完全保留。
- **C（标准写法）**：换成 `last[c]` 数组 + 左边界跳转，18 行 → 8 行，没有切片、没有冗余变量、没有 `mid`，语义就是第二节里推导出的两行更新。

### 优化代码

**版本 A —— 最小改动（保留用户思路，只去掉切片与冗余变量）**

```python
class Solution:
    def lengthOfLongestSubstring(self, s: str) -> int:
        if s == '':
            return 0
        ans = right = 1
        left = 0
        for ch in s[1:]:
            p = s.rfind(ch, left, right)   # 在 [left, right) 内找上次出现，原串上搜，不切片
            if p != -1:
                left = p + 1               # 跳到重复字符的下一位
                right += 1
                continue
            right += 1
            if right - left > ans:         # 窗口长度现算，不需要 mid
                ans = right - left
        return ans
```

**版本 C —— 标准写法（`last` 数组 + 左边界跳转）**

```python
class Solution:
    def lengthOfLongestSubstring(self, s: str) -> int:
        last = [-1] * 128        # 每个字符上次出现的下标（题面保证是 ASCII）
        left = ans = 0
        for right, ch in enumerate(s):
            c = ord(ch)
            p = last[c]
            if p >= left:        # 只有当"上次出现"还在窗口内，才构成重复
                left = p + 1
            last[c] = right
            if right - left + 1 > ans:
                ans = right - left + 1
        return ans
```

> 版本 C 里把 `left = max(left, last[c] + 1)` 写成了 `if p >= left` 分支：两者等价，但后者把"什么时候才需要动左边界"这件事说清楚了 —— 也正好避免了漏写 `max` 把左边界拖回去的经典错误。

**优化理由**：

- **A**：切片的收益是零（只是把"搜窗口"换成"搜原串的区间"），成本是每轮一次字符串分配。`rfind` 直接消灭这笔开销，其余逻辑一个字没改。
- **C**：每轮只有"一次数组读 + 一次比较 + 一次数组写"，没有分配、没有哈希、没有删除，空间固定 128 个 `int`。**代码最短且最容易讲清楚**。

**实测（本机 CPython 3.13，各取 7 次最优值，单位 ms）：**

`n = 100000`：

| 场景 | 用户版 | A `rfind` | B `dict` | C `list` | D `set` | A 提速 | C 提速 |
| :--- | ---: | ---: | ---: | ---: | ---: | ---: | ---: |
| 单字符重复 | 11.29 | **9.13** | 10.98 | 10.33 | 13.65 | 1.24× | 1.09× |
| 2 种字符 | 12.98 | **9.81** | 11.73 | 10.78 | 14.39 | 1.32× | 1.20× |
| 26 种小写 | 14.59 | **9.24** | 11.35 | 9.79 | 17.41 | 1.58× | 1.49× |
| 95 种 ASCII 随机 | 15.09 | **9.19** | 10.67 | 9.77 | 16.95 | 1.64× | 1.54× |
| 95 种 ASCII 循环（窗口恒 95） | 12.70 | 12.34 | 11.48 | **10.13** | 14.18 | 1.03× | 1.25× |

`n = 50000`：

| 场景 | 用户版 | A `rfind` | B `dict` | C `list` | D `set` |
| :--- | ---: | ---: | ---: | ---: | ---: |
| 单字符重复 | 5.76 | **4.50** | 5.41 | 5.02 | 6.85 |
| 2 种字符 | 6.46 | **4.89** | 5.83 | 5.40 | 7.11 |
| 26 种小写 | 7.24 | 4.56 | 5.65 | **4.88** | 8.79 |

**怎么读这两张表**：

- 用户版两档都**能过**（`n = 10^5` 只要十几毫秒），它不是"会 TLE 的写法"，只是每轮白分配一次字符串。
- **`D set` 版（`while ch in seen` 收缩）是五个里最慢的**：它每轮至少一次 `set` 哈希 + `in` 判断，遇到重复还要进循环做 `remove`。经典模板 ≠ 快。
- **没有全场景最优的一版**：`A` 在"窗口不满"的四个场景最快（C 层 `rfind` 扫描 + 零分配），但在"窗口恒 95"时被 `C` 反超 —— 因为那时 `rfind` 每步仍要线性扫 95 个字符，而 `C` 是 O(1) 查表。
- 综合建议：**追求最小改动选 A，追求最稳上界与可读性选 C**。

### 常数级优化（可选）

- `last` 用 `[-1] * 128` 而非 `dict`：省掉字符串哈希，实测 `C` 比 `B` 稳定快 5~10%。
- 答案更新写成 `if right - left + 1 > ans` 而不是 `ans = max(ans, ...)`：省一次函数调用（这是个真实收益，**不是玄学**，本轮基准里两版都是这么写的）。
- 若把 `left`、`ans`、`last` 提前绑定为局部变量，收益在 10^5 规模上仍有限，不必强求。

## 六、易错点与总结

### 易错点

- **`left = max(left, last[ch] + 1)` 漏掉 `max`**：`last[ch]` 可能位于 `left` 左侧（字符已滑出窗口），直接赋值会让左边界**倒退**，答案偏大。`"abba"` 这类输入必错。
- **`s.replace(...)` 是空操作**：`str` 不可变。本题的字符集**包含空格**（`"a a"` 答案是 2），任何"顺便把空格删掉"的想法都是错的。
- **计数表版必须 `del` 归零的键**：`len(cnt)` 统计的是键数，不删键它只增不减，判据永久失效（`1100` 那道题踩过这个坑）。
- **别把"窗口无重复"的判据套错**：`len(cnt) == 窗口长度` 这个等价式**只在定长窗口**下好用；变长窗口（本题）下 `len(cnt)` 与长度没有那个关系，必须换 `last` 数组或直接用 `find`。
- **维护 `mid` 这种派生变量**：本轮插桩 2000 组、0 次违反，说明用户确实同步得很好 —— 但收益为零、风险非零（改代码时容易顾此失彼）。
- **空串**：`s = ""` 要返回 `0`（用户版有特判，别删）。

### 题型套路沉淀

- **变长滑动窗口模板**：

  ```text
  left = 0; ans = 0
  for right, ch in enumerate(s):
      加入 ch / 更新状态
      while 约束被破坏:  移出 s[left]; left += 1
      ans = max(ans, right - left + 1)
  ```

- **「无重复」是这条模板里最特殊的一类约束**：通用模板退出成 `while`，但"无重复"有个性质 —— 新字符造成的重复**必然是它自己上次出现**，与窗口里其他字符无关。于是 `while` 退化成一次 `if`，状态也从"整张计数表"退化成"每个字符的上次下标"。**判断能不能做这种退化，是这类题的解题分水岭。**

- **两代武器对照**：

  | 维护量 | 适用 | 出窗操作 | 代表题 |
  | :--- | :--- | :--- | :--- |
  | 窗口计数表 + 窗口大小 | **定长**窗口无重复 | 必须 `del` 归零键 | `1100` |
  | `last[c]` + 左边界跳转 | **变长**最长无重复 | 无（自动被 `last[c] >= left` 过滤） | **本题** |

- **同型题**：
  - `3090. 每个字符最多出现两次的最长子字符串`（**本仓库同目录已有**）—— 本题把"每字符 ≤ 1 次"放宽成"≤ 2 次"的**直接推广**：状态从 `last[c]` 变成 `last1[c]/last2[c]`，判据从 `last[c] >= left` 变成 `last2[c] >= left`，其余一字不改；
  - `1100. 长度为 K 的无重复字符子串`（**本仓库同目录已有**）—— 定长版，正好是本题的对照组；
  - `159. 至多包含两个不同字符的最长子串`、`340. 至多包含 K 个不同字符的最长子串` —— 把"不许重复"放宽成"至多 K 种"；
  - `424. 替换后的最长重复字符`、`1004. 最大连续 1 的个数 III` —— 同一条"左指针不回退"骨架；
  - `438. 找到字符串中所有字母异位词`、`567. 字符串的排列` —— 定长滑窗 + 计数表。

- **一条可背的推广路线（"每字符最多 k 次"）**：

  | k | 状态 | 判据 |
  | :---: | :--- | :--- |
  | 1 | `last[c]` | `last[c] >= left` |
  | 2 | `last1[c]` / `last2[c]` | `last2[c] >= left` |
  | 任意 k | 每字符一个长度 k 的 `deque`（存最近 k 次下标） | `dq[0] >= left` |

  三者的共同点：**新来的字符造成的那点"超出"，只需左边界跳一次就能消掉** —— 因为每轮只追加一个字符，它自己的计数最多涨 1。这个前提一旦破坏（比如一次加一批），就必须退回 `while` 收缩。

### 验证记录

- 3 个官方示例 + 空串：用户版**全部通过**（`3` / `1` / `3` / `0`）。
- **基准自检**：先用 O(n³) 暴力解（枚举所有子串 + `set` 判重）验 O(n²) 暴力解本身，600 组、`n ≤ 10`，**偏差 0 组** —— 确保"用基准验解"这件事本身可靠，而不是拿一个没验证的基准去验。
- **随机对拍**：以 O(n²) 暴力解为基准，4000 组随机输入（`n ≤ 40`，字符集分别取 1 / 2 / 3 / 4 / 6 / 26，含小写字母、数字、符号三种池），**五个版本（用户版 / A / B / C / D）偏差均为 0 组**。
- **边界用例**：`""`、单字符、全是空格、`"a a"`（空格必须算作字符）、全相同、全不同、95 个互不相同的 ASCII 字符、95 字符重复两遍（窗口恰好顶到字符集上界）—— 五版结果一致。
- **不变量插桩**：2000 组随机输入下逐轮断言 `mid == right - left`，**0 次违反**，证实 `mid` 是冗余状态。
- **窗口上界实测**：`n = 10^5` 各场景下窗口最大值为 1 / 2 / 22 / 42 / 95，与"窗口 ≤ 字符集 95"的推论一致；切片累计复制字符数最多 949 万个（95 个字符循环那一档）。
