# 3325. 字符至少出现 K 次的子字符串 I

> **难度**：中等
> **标签**：滑动窗口 · 哈希表 · 字符串 · 计数
> **原题链接**：https://leetcode.cn/problems/count-substrings-with-k-frequency-characters-i/

## 一、题目描述

给定字符串 `s` 和整数 `k`，统计 `s` 的所有子串中，**至少有一个字符出现次数 ≥ k** 的子串数量。子串指连续的、非空的字符序列。

### 示例

```text
输入：s = "abacb", k = 2
输出：4
解释：符合条件的子串为 "aba"、"abac"、"abacb"、"bacb"
     （前三个里有 'a' 出现 2 次，最后一个里有 'b' 出现 2 次）

输入：s = "abcde", k = 1
输出：15
解释：k = 1 时任何非空子串都满足条件，共 5*6/2 = 15 个
```

### 约束条件

- `1 <= s.length <= 3000`
- `1 <= k <= s.length`
- `s` 仅由小写英文字母组成

---

## 二、解题思路

### 核心思想

把「存在某个字符出现 ≥ k 次」这个**存在性**条件，改写成关于**右端点的阈值**问题：固定右端点 `r` 后，"窗口 `[l, r]` 非法"对左端点 `l` 是**单调递减**的（`l` 变大 ⇒ 窗口变短 ⇒ 各字符计数只减不增 ⇒ 谓词只能从真变假）。所以每个 `r` 都存在唯一的阈值 `L(r)`，使得满足条件的起点恰为 `0, 1, …, L(r) - 1`，贡献 `L(r)` 个；答案即 `Σ L(r)`。而 `L(r)` 用一个增量维护的滑动窗口在线求出。

### 思路演进

1. **暴力解法**：枚举全部 O(n²) 个 `[l, r]`，对每个子串重新统计字符出现次数（26 桶），看是否有字符 ≥ k 次。n = 3000 时共有 4.5×10⁶ 个子串，每个再扫一遍窗口或取 26 个桶的最大值 ⇒ O(n²·|Σ|)。

2. **瓶颈定位**：慢在两处 —— ① 重复枚举：子串数量本身就是 n² 级；② 相邻子串的信息完全重叠（`[l, r+1]` 只是 `[l, r]` 多了一个字符），但每换一个起点就把上一次的计数**整段丢掉重算**。换句话说，我们枚举的是"区间"，而问题只关心"区间里是否存在计数 ≥ k 的字符"，浪费了大量结构。

3. **关键转化**：**不枚举起点，改为枚举右端点**。固定 `r`，把"窗口内存在字符出现 ≥ k 次"看成关于 `l` 的谓词 `P(l)`。由于 `l` 增大只会从窗口里**删**元素，各字符计数单调不增，`P` 只能从真变假 ⇒ 存在阈值 `L(r)` 使 `P(l)` 为真 ⟺ `l < L(r)`。于是"O(n²) 个子串"被压成"n 个阈值"。而 `L(r)` 之间可以**增量**转移：`r` 右移一格只让 `s[r]` 的计数 +1，如果它达到 `k`，就把左指针往右推、边推边把移出窗口的字符计数 −1，直到 `s[r]` 的计数降回 `k-1` —— 此时窗口内已无任何字符计数 ≥ k，左指针就是 `L(r)`。
   ⇒ 一句话：**原来不行是因为把每个子串当独立问题算；现在能行是因为固定右端后谓词对左端单调，阈值可以随右指针滑动地增量维护**。

4. **最优解**：左右指针各自单调右移，总移动 n 步，O(n) 时间、O(26) 空间。

### 关键点

- **判据只盯 `s[r]` 一个字符**（`while cnt[j] >= k`），而不是"窗口内是否存在任何字符 ≥ k 次"。这看着像漏检，实际靠的是**循环不变量**：每轮 `while` 退出时"窗口内每个字符的计数都 ≤ k-1"。归纳证明 —— 上一轮结束时不变量成立；本轮加入 `s[r]` 只会让 `s[r]` 的计数变成 `k`（其它字符仍是 ≤ k-1）；收缩只减小计数、不会制造新的违规。⇒ 唯一的违规源就是刚进来的 `s[r]`，只查它一个就够。
- **必须用 `while`，不能退化成 `if`**：`s[r]` 的计数可能一次超出很多格，左指针要**连挪多格**才能把它压回 `k-1`。`if`（每轮最多挪一格）会让"合法窗口"的左边界滞后，贡献少算 —— 最小反例 `s = "abb", k = 2` 见「易错点」。
- **贡献口径是 `ans += left`，不是"窗口长度"**：`left` 同时是"最小合法左端点"和"满足条件的起点个数"，论证分两半 —— ① 窗口 `[left, r]` 自身合法（所有计数 ≤ k-1）⇒ 起点 `left … r` 都不满足条件；② 窗口 `[left-1, r]` 里 `s[r]` 出现恰 `k` 次（这是左指针最后一次右移的触发原因）⇒ 起点 `0 … left-1` 对应的窗口都是它的超集，全满足条件。两边相加恰为 `left` 个。
- **k = 1 无需特判**：`while` 一进入就成立（`cnt[j] = 1 ≥ 1`），左指针被推到 `r+1`，每轮贡献 `r+1`，累加即 `n(n+1)/2` —— 与示例 2 完全吻合。
- **不存在越界 / 负索引风险**：`while` 条件 `cnt[c] >= k ≥ 1` 蕴含 `s[r]` 仍在窗口内，故进入循环体时必有 `left ≤ r`，`s[left]` 取的是窗口内的元素；推到 `left = r+1` 后循环条件必然为假（该字符计数已归零），不会带着越界的 `left` 再取一次下标。

## 三、代码实现

### 最终代码

```python
from collections import Counter


class Solution:
    def numberOfSubstrings(self, s: str, k: int) -> int:
        cnt = Counter()
        ans = left = 0
        for right, j in enumerate(s):
            cnt[j] += 1
            while cnt[j] >= k:
                cnt[s[left]] -= 1
                left += 1
            ans += left
        return ans
```

> `from collections import Counter` 在截图里没有（LeetCode 编辑器自带），已补全；`right` 本题未被使用，保留只为可读性。

## 四、复杂度分析

| 版本 | 时间复杂度 | 空间复杂度 |
| :--- | :--- | :--- |
| **最终代码** | O(n) | O(26) |
| 朴素解法（最坏情况） | O(n²·\|Σ\|) | O(\|Σ\|) |
| 理论下界 | O(n) | O(1) 额外（仅只读输入） |

> 复杂度中的 n 指字符串长度 `len(s)`；|Σ| 指字符集大小，本题固定为 26（小写字母）。

- **时间**：右指针走 n 步；左指针单调不减、全程最多走 n 步，故内层 `while` 的总代价是 O(n)，单轮**均摊 O(1)**（不是每轮 O(n) 的嵌套）。
- **空间**：`Counter` 最多只有 26 个键，与 n 无关。
- **与实测量级对齐**（n = 3000 取题面上限）：朴素解的耗时**完全取决于输入形态** —— `k` 小时遇到重复即可早退（k=2、随机 26 字母，实测 8.2 ms），`k` 大时必须扫完全部 4.5×10⁶ 个子串（k=3000，实测 1513.2 ms）。滑窗版在两种形态下都是 0.4 ~ 0.5 ms 量级。⇒ **朴素解能不能过取决于用例，而 O(n) 与用例无关**，这才是换算法的理由。

## 五、优化评估

**结论**：时间复杂度已是理论下界 O(n)、空间已是常数级 O(26)，**渐近复杂度没有优化空间**；剩下的只有常数项，实测仍有约 **2 倍**的提升。

### 瓶颈分析

- **时间上界论证**：任何正确解都必须读到某个字符第 k 次出现的位置才能计数（否则该子串是否合法无从得知），故下界为 Ω(n)；当前实现每轮只做 O(1) 摊还次操作，不重复计算任何子串信息，**已触到下界**。
- **空间上界论证**：判据本身要求同时记住 26 个字符的计数（少了任何一桶，`while` 的退出条件就无法判定），O(26) 不可再压；左指针与答案只需两个整型变量。
- **剩下的瓶颈是常数项**：`Counter` 的每次读写都走 `dict` 哈希路径（首次访问还触发 `__missing__`），而字符集只有 26 个、天然适合下标寻址；另外 `enumerate(s)` 生成的 `right` 在本题里根本没被使用。

### 可优化空间

渐近复杂度已到顶（见上）。可做的是**常数级改写**：用长度 26 的 `list` 替代 `Counter`，并去掉多余的 `enumerate`。

### 优化代码

```python
class Solution:
    def numberOfSubstrings(self, s: str, k: int) -> int:
        cnt = [0] * 26                 # 小写字母直接当下标，替代 Counter
        ans = left = 0
        for j in s:                    # 去掉 enumerate：right 本题用不到
            c = ord(j) - 97
            cnt[c] += 1
            while cnt[c] >= k:
                cnt[ord(s[left]) - 97] -= 1
                left += 1
            ans += left
        return ans
```

**优化理由**：判据只用 `cnt[c]` 的读与写，`list` 字面量下标寻址比 `dict` 哈希快；去掉 `enumerate` 省掉每轮的元组解包。逻辑与最终代码**逐语句等价**（同一套窗口、同一套收缩条件），只换了存储与遍历形式。

实测对照（同一轮、9 次轮转取最优；A = 截图原版，B = 上述数组版）：

| 输入形态 | n | A（Counter） | B（数组） | 提速 |
| :--- | :--- | :--- | :--- | :--- |
| 随机 26 字母, k=2 | 3000 | 1.03 ms | 0.50 ms | 2.05x |
| 随机 26 字母, k=2 | 100000 | 33.57 ms | 17.07 ms | 1.97x |
| 全同字符, k=n/2 | 3000 | 0.76 ms | 0.39 ms | 1.97x |
| 全同字符, k=n/2 | 100000 | 25.97 ms | 13.17 ms | 1.97x |

> n = 3000 是题面上限；n = 100000 一档属于**把结论泛化到任意 n 的研究**，不是本题会出现的规模。本题数据范围内两种写法都是毫秒级，**不存在"不优化就超时"的说法**，差异纯属常数项。

### 常数级优化（可选）

- 更激进的写法：先把字符串转成 `bytes`（`b = s.encode()`），取字符变成 `b[left] - 97`，省掉每次 `ord()` 调用。收益随规模增长，但牺牲可读性，本题不值得。
- **等价口径提示**：对每个右端点都有 `left + (r - left + 1) = r + 1`，所以「`Σ L(r)`」与「`n(n+1)/2 − Σ(合法窗口长度)`」（即"总子串数减去所有字符都 ≤ k-1 次的子串数"）**恒等**。两种口径共用同一个窗口，选哪个只是写法偏好；但换口径时别把 `left` 的含义记混 —— 它衡量的是**非法窗口的起点个数**，不是窗口长度。

## 六、易错点与总结

### 易错点

- **把 `while` 写成 `if`（本族最经典的错）**：收缩可能要连挪多格，`if` 让左指针每轮最多前进 1 格，"合法窗口"的左边界随之滞后，贡献被少算。
  **最小反例**：`s = "abb", k = 2` —— 真值 2（`"bb"`、`"abb"`），`if` 版得 1（r = 2 时 `left` 只从 0 挪到 1，只算了一个起点）。同批 20 组随机小串（字母表 2、n ≤ 12）中 `if` 版错 4 组。
- **把 `ans += left` 写成 `ans += right - left + 1`**：那是"窗口合法"的口径（用来从总数里**减**），方向正好反了 —— 窗口合法时左边才是要减掉的起点，窗口非法时要加的是左边界本身。
- **误以为判据需要扫全窗口**：写成"检查窗口内所有字符计数 < k"不会错，但会把 O(1) 的检查变成 O(26)，也丢掉了"每轮只可能有一个违规源"这条性质。真正危险的是反过来：既要省这一层检查、又顺手把 `while` 改成 `if`（不变量两边都不成立）。
- **忘记 `from collections import Counter`**：LeetCode 环境自带，本地复现会直接 `NameError`。
- **给 k = 1 加特判**：不必要 —— 左指针会被推到 `r+1`，累计结果自然等于 `n(n+1)/2`。

### 题型套路沉淀

- **「至少一个满足 X」型计数，两条路**：① 直接对每个右端点求"非法窗口的起点个数"并累加（本题写法）；② 总子串数 − "一个都不满足"的子串数（即所有字符都 < k 次）。两者在本题**恒等**，选一个即可。
- **滑窗的成立前提是"谓词对左端单调"**：固定右端、左端右移时约束只能从违规变合规（本题）或反之，才谈得上双指针。找不到单调性就别硬套滑窗，该换前缀和 + 单调队列一类结构。
- **每轮只追加一个元素 ⇒ 违规源只有一个**：所以可以只检查刚进来的元素（本题 `cnt[j] >= k`）。**但它的前提是"上一轮结束时窗口已全局合法"这个不变量**，写代码前先把不变量写下来，是这类题最省事的自查手段。
- **贡献口径与收缩方式必须配套**：收缩到合法（`while`）+ 每轮按"非法前缀长度"累加，是本题自洽的一对；换成"只挪一格"的写法，口径也得跟着变，否则两头不对。
