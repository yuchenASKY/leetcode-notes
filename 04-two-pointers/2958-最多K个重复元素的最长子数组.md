# 2958. 最多 K 个重复元素的最长子数组

> **难度**：中等
> **标签**：数组 · 哈希表 · 滑动窗口
> **原题链接**：https://leetcode.cn/problems/length-of-longest-subarray-with-at-most-k-frequency/

---

## 一、题目描述

给定整数数组 `nums` 与整数 `k`，称一个数组是**好数组**当且仅当其中**每个值的出现次数都不超过 `k`**。求 `nums` 中最长**好子数组**（连续非空）的长度。

一句话：**"每个值出现 ≤ k 次"的最长窗口**。

### 示例

```text
示例 1
输入：nums = [1,2,3,1,2,3,1,2], k = 2
输出：6
解释：最长好子数组是 [1,2,3,1,2,3]，1/2/3 的频率都没超过 2。
     [2,3,1,2,3,1] 与 [3,1,2,3,1,2] 同样合法。

示例 2
输入：nums = [1,2,1,2,1,2,1,2], k = 1
输出：2
解释：[1,2] 与 [2,1] 都合法。

示例 3
输入：nums = [5,5,5,5,5,5,5], k = 4
输出：4
解释：最长好子数组是 [5,5,5,5]。
```

### 约束条件

- `1 <= nums.length <= 10^5`
- `1 <= nums[i] <= 10^9`（**值域无界**，这条决定了状态只能用哈希表）
- `1 <= k <= nums.length`（**k 是变量**，这条决定了不能像 `3090` 那样写死两个变量）

> **两条必须立刻记下的推论**：
> 1. **值域 `10⁹` 无界** ⇒ `1695` 那种"用定长数组当 `last`"的优化**搬不过来**，"每个值上次出现的位置"必须放哈希表。
> 2. **`k` 是输入而不是常数** ⇒ `3` 的单个 `last`、`3090` 的 `last1/last2` 都不够用，任意 `k` 需要"最近 `k+1` 次出现位置"这类**可变长状态**（`deque`），或者干脆退回计数表。

## 二、解题思路

### 核心思想

**变长滑动窗口 + 按值计数**：维持不变量「窗口 `[left, right]` 内每个值的出现次数 ≤ `k`」，右端每轮只进一格；一旦新加入的值违规，就把 `left` 右移到违规消失。每轮用窗口长度更新答案。

它与同目录的 `3`（每字符 ≤ 1 次）、`3090`（每字符 ≤ 2 次）、`1695`（每值 ≤ 1 次）是**同一条骨架**，只换了三处：

| | `3` | `3090` | **本题 2958** | `1695` |
| :--- | :--- | :--- | :--- | :--- |
| 输入 | 字符串 | 字符串 | 整数数组 | 正整数数组 |
| 约束量 | 每字符 ≤ 1 | 每字符 ≤ 2（写死） | **每值 ≤ k（变量）** | 每值 ≤ 1 |
| 值域 | 26 | 26 | **10⁹（无界）** | 10⁴ |
| 答案口径 | 长度 | 长度 | **长度** | 求和 |

### 思路演进

1. **朴素解法**：枚举所有子数组 `(l, r)`，逐个数频次判合法性 → **O(n³)**；固定左端向右扩、扩不动就换下一个左端 → **O(n²)**。`n = 10⁵` 时 O(n²) 是 10¹⁰ 量级，必然超时。

2. **瓶颈定位**：固定左端重新扫一遍是**重复枚举**。而合法性对左端右移是**前缀封闭**的 —— `[l, r]` 合法 ⇒ `[l+1, r]` 也合法（从窗口里拿掉元素只会让计数下降）。这说明"以 `r` 结尾的最长合法窗口的左端 `L(r)`"**关于 `r` 单调不减**，两个指针都只向右走，总移动量 O(n)。

3. **关键转化（把解法压成一句判据）**：

   > **窗口 `[left, right]` 合法 ⟺ 窗口内每个值的计数 ≤ k** —— 一条**按值**的判据。

   它带来两个后果：
   - 因为**上一轮结束时窗口已经合法**，新加入的 `nums[right]` 是**唯一**可能的违规源 ⇒ 收缩条件写成 `cnt[nums[right]] > k` 就够，不必扫描整张计数表；
   - 它是**唯一**的违规源，所以**违规量恒为 1**（从 `k` 涨到 `k+1`）。

   ⚠️ 但"违规量恒为 1"**不等于"左指针挪一格就够"**：要挪的是"直到窗口内最早那个 `x` 被移出去"的**格数**，实测单步最多 **1001 格**、平均最多 **981 格**（见第五节插桩表）。这是后面"`while` 能不能换 `if`"的分水岭。

4. **最优解**：两种等价写法 ——
   - **收缩版（用户版）**：计数表 `cnt` + `while cnt[nums[right]] > k` 逐格挪 `left`；
   - **跳转版**：每个值维护一个 `deque` 存**最近 `k` 次出现的位置**，`left` 一次跳到"最早那个 + 1"。

   两者**逐轮状态完全一致**（`left` 序列 / 窗口长度序列 / 答案三者全等，实测 2000 组 60,615 轮差异 0）。区别只在常数。

### 关键点

- **判据是"按值"还是"按键数"，决定了要不要 `del`**：本题是 `cnt[x] > k`（**按值**），计数减到 0 留着键**完全无害**，所以用户版不写 `del` 是对的；对照 `904. 水果成篮` 的判据是 `len(cnt) > 2`（**按键数**），那里**必须** `del` 掉归零的键，否则键数只增不减、`left` 会被推越界。
- **答案口径是"窗口长度"** ⇒ 与 `1695`（答案是**求和**）分道：求和口径下"长度单调"这根救命稻草不存在，`while` 一步都不能让。
- **`while` 不能换成"只挪一格"**：实测错 **20.8%**（穷举 250,959 组），最小反例 `[1,2,2,1]`、`k=1`（真值 2、实得 3）。原因见「易错点」。
- **跳转版的 `deque` 必须先清掉过期下标**：不清理时 `len(dq)` 把已滑出窗口的位置也算进去，会把 `left` **拖回去**，实测错 **17.8%**。
- **`k` 是变量 ⇒ 状态是可变长的**。`3` 用 1 个 `last`、`3090` 用 `last1/last2`，本质是"存最近 `k` 次位置"在 `k=1/2` 时退化成定长变量；`k` 任意时必须给每个值配一个**长度 k 的 `deque`**（或用计数表）。
- **没有负下标风险**：`left` 单调不减且恒 `≤ right`，`nums[left]`、`cnt[nums[left]]` 都不会取到 `-1`。

## 三、代码实现

### 最终代码（用户提交版）

截图里的代码**缺两行 import**：`defaultdict` 来自 `collections`，`List` 来自 `typing`。LeetCode 环境内置了它们，本地复制会直接 `NameError`（我实测确认过），以下为补齐后的逐字版本：

```python
from collections import defaultdict
from typing import List


class Solution:
    def maxSubarrayLength(self, nums: List[int], k: int) -> int:
        cnt = defaultdict(int)
        ans = left = 0
        for right, j in enumerate(nums):
            cnt[j] += 1
            while cnt[j] > k:
                cnt[nums[left]] -= 1
                left += 1
            ans = max(ans, right - left + 1)
        return ans
```

**它好在哪**：

- `while cnt[j] > k` 里的 `j` 就是 `nums[right]`，所以这条判据**只盯新元素**，一次字典读就判断完，不必扫描计数表 —— 这是"上一轮窗口已合法"这个不变量的直接红利。
- 判据按值，**不需要 `del`**，循环体只有 4 次查表/算术。
- 骨架与 `3 / 3090 / 1695` 完全同源，`k` 作为参数直接进判据，**天然支持任意 `k`**，不用为不同的 `k` 写不同状态。

**它的代价**：`defaultdict` 的哈希开销；窗口长且 `k` 大时 `while` 单步要挪几百上千格（每格一次哈希读 + 一次哈希写）；每轮一次 `max()` 调用。

## 四、复杂度分析

| 版本 | 时间复杂度 | 空间复杂度 |
| :--- | :--- | :--- |
| **最终代码（用户版）** | O(n) 摊还 | O(D) |
| 优化版 G（k=1 跳转 + k≥2 计数表） | O(n) 摊还 | O(D) |
| 跳转版（每值一个 `deque` 存最近 k 次位置） | O(n) | O(D) + 每值一个 `deque` 对象 |
| 朴素解法（固定左端向右扩） | O(n²) | O(D) |
| 朴素解法（枚举子数组 + 逐个数频次） | O(n³) | O(n) |
| 理论下界 | **Ω(n)** | Ω(D) |

> 复杂度中的 `n` 指数组 `nums` 的长度；`D` 指扫描到的**不同取值个数**（≤ min(n, 10⁹)）。
>
> **时间下界 Ω(n)**：最坏情况（整个数组互不相同）答案依赖**每一个**元素，任何算法都必须至少读一遍输入。
>
> **摊还依据**：`left` 整趟只向右推进、总位移 ≤ n（实测 `n = 10⁵` 各场景 0 ~ 99,999），所以内层 `while` 的**总**迭代次数是 O(n) 而非 O(n²)。
>
> **空间口径**：本题值域 `10⁹` 无界，`D` 随 `n` 增长，O(1) 额外空间的口径**不成立**（对照：`1695` 的值域是 `10⁴`，可以用定长数组把它压成常数）。

## 五、优化评估

**结论**：时间已是理论下界 O(n)，**算法层面没有可优化空间** —— 用户版与"一次跳转"版**逐轮状态完全一致**（穷举 + 随机，差异 0）。可做的是**常数级**优化：实测 `B`（`if` 替 `max`）拿 **1.00~1.11×**，`G`（`k=1` 走跳转、`k≥2` 走用户版）在 `k=1` 场景拿 **1.37~2.35×** 且在其他场景不回退。

### 瓶颈分析

**(1) 用户版每轮的固定成本**：`defaultdict` 一次读 + 一次写（两次哈希）、一次 `max()` 调用；`while` 内部每挪一格还要一次哈希读 + 一次哈希写 + 一次 `nums[left]` 索引。

**(2) `while` 单步要挪多少格 —— 这是"能不能换 `if`"的证据**（`n = 10⁵` 逐轮插桩）：

| 场景 | 收缩轮次 | 收缩轮占比 | 单步 ≥2 格的轮次 | 单步最多格数 | 平均格数 | 左指针总位移 |
| :--- | ---: | ---: | ---: | ---: | ---: | ---: |
| 全相同 k=1 | 99,999 | 100.0% | 0 | 1 | 1.00 | 99,999 |
| 全相同 k=50000 | 50,000 | 50.0% | 0 | 1 | 1.00 | 50,000 |
| 2 种值交替 k=1 | 99,998 | 100.0% | 0 | 1 | 1.00 | 99,998 |
| 2 种值交替 k=2 | 99,996 | 100.0% | 0 | 1 | 1.00 | 99,996 |
| 10 种值随机 k=3 | 23,000 | 23.0% | 18,422 | 25 | 4.35 | 99,979 |
| 1000 种值随机 k=5 | 524 | 0.5% | 520 | **913** | 188.58 | 98,817 |
| 10^4 值整块循环 k=2 | 80,000 | 80.0% | 0 | 1 | 1.00 | 80,000 |
| 对抗型稀疏重复 k=1 | 100 | 0.1% | 98 | **1001** | 981.00 | 98,100 |
| 全不同 k=1（零收缩） | 0 | 0.0% | 0 | 0 | 0.00 | 0 |
| 全不同 k=5（零收缩） | 0 | 0.0% | 0 | 0 | 0.00 | 0 |
| 稀疏重复 k=1000 | 0 | 0.0% | 0 | 0 | 0.00 | 0 |

⇒ ① 左指针总位移恒 ≤ n，摊还 O(1) 成立；② **单步可以要挪上千格**（`1000 种值随机 k=5` 里 520 次收缩中有 520 次都 ≥2 格），所以"每轮只挪一格"的写法在这里连窗口合法性都保不住。

**(3) `right` 不是死变量**：长度口径需要它，不能照抄 `1695` 那样把 `enumerate` 拆掉。

### 可优化空间

**算法级：没有。** 跳转版与用户版 `left` / 窗口长度 / 答案三个序列逐轮全等（穷举 8194 + 250,959 组、随机 2000 组 60,615 轮，差异 0），所以"换 `deque`"只是**换实现**，不是换算法，上界仍是 O(n)。

**「把 `while` 换成 `if`」必须掐掉**，实测穷举（值域 1..2 / 1..3，`n ≤ 9`，枚举了每个 `(nums, k)` 组合）：

| 收缩方式 | 收缩判据 | 答案口径 | 错误率（1..2 / 1..3） | 最小反例 |
| :--- | :--- | :--- | ---: | :--- |
| `while` 逐格 | `cnt[j] > k`（只看新元素） | 每轮 `max`（**用户版**） | **0% / 0%** | — |
| `while` 逐格 | `cnt[j] > k` | 终值 `n - left` | 22.0% / 19.7% | `[1,2,2]` k=1：真 2、实得 1 |
| 只挪一格 | `cnt[j] > k` | 每轮 `max` | 22.1% / 20.8% | `[1,2,2,1]` k=1：真 2、实得 3 |
| 只挪一格 | `cnt[j] > k` | 终值 `n - left` | 22.1% / 20.8% | `[1,2,2,1]` k=1：真 2、实得 3 |
| 只挪一格 | `max(cnt.values()) > k`（**整体判据**） | 每轮 `max` | 0% / 0% | — |
| 只挪一格 | `max(cnt.values()) > k`（**整体判据**） | 终值 `n - left` | 0% / 0% | — |
| `while` 逐格 | `max(cnt.values()) > k`（整体判据） | 每轮 `max` | 0% / 0% | — |
| `deque` 跳转（**缺过期清理**） | `len(dq) > k` | 每轮 `max` | 17.8% / 13.8% | `[1,2,2,1]` k=1：真 2、实得 3 |
| `deque` 跳转（有清理） | `len(dq) > k` | 每轮 `max` | 0% / 0% | — |

**怎么读这张表**：

- **两格 ❌ 都在"只换一半"上**：`while` 版是"收缩到合法为止"，长度序列**不单调**，所以终值口径会丢历史最大值（`[1,2,2]` 欠报成 1）；只挪一格版每轮都可能留下非法窗口，所以必须每轮取 `max`，但它**连每轮取 `max` 都是错的** —— 20.8% 的错来自判据（见下条）。
- **锅在判据，不在"这个家族不支持平移"**：把判据从"只看新元素"换成**整体判据** `max(cnt.values()) > k` 之后，平移版 250,959 组**全对**。这与 `1695` 的归因实验完全一致 —— `cnt[j] > k` 是**局部判据**，它发现不了上一轮残留的违规。**`[1,2,2,1]` k=1 的逐轮展开**：`r=2` 时 `cnt[2]=2>1`，只挪一格 `left: 0→1`，窗口 `[2,2]` 仍然非法；`r=3` 加入 `1` 时判据只看新元素（`cnt[1]=1 ≤ 1`）→ 残留违规没被发现，长度按 `4-1=3` 记下 → 超报。
- **别为了"少写个 `while`"去用整体判据的平移版**：它每轮要 `max(cnt.values())`，是 O(D) 的额外成本，换来的是**更差的鲁棒性**（判据一旦写歪就崩）。用户版的 `while` 是必需的。
- 注意 **"一次跳转" ≠ "平移"**：跳到 `dq[0] + 1` 是**精确收缩**（与 `while` 逐格收缩逐轮状态全等），只是把量级不定的挪动换成 O(1) 查表；"平移"是**故意不收缩到合法**。名字像，性质完全不同。

### 优化代码

**版本 B —— 最小改动（只把 `max` 换成 `if`，零风险）**

```python
from collections import defaultdict
from typing import List


class Solution:
    def maxSubarrayLength(self, nums: List[int], k: int) -> int:
        cnt = defaultdict(int)
        ans = left = 0
        for right, j in enumerate(nums):
            cnt[j] += 1
            while cnt[j] > k:
                cnt[nums[left]] -= 1
                left += 1
            if right - left + 1 > ans:      # 省掉一次 max() 调用
                ans = right - left + 1
        return ans
```

**版本 G —— 推荐（`k=1` 走跳转，`k≥2` 保持用户版）**

```python
from collections import defaultdict
from typing import List


class Solution:
    def maxSubarrayLength(self, nums: List[int], k: int) -> int:
        ans = left = 0
        if k == 1:
            # k=1 时"最近 1 次出现位置"就是一个整数，不需要计数表，
            # 也没有任何对象创建，是本题唯一能稳定跑赢计数表的写法
            last = {}
            for right, x in enumerate(nums):
                p = last.get(x, -1)
                if p >= left:               # 只有"上次出现"还在窗口内才算重复
                    left = p + 1
                last[x] = right
                if right - left + 1 > ans:
                    ans = right - left + 1
            return ans
        cnt = defaultdict(int)
        for right, j in enumerate(nums):
            cnt[j] += 1
            while cnt[j] > k:
                cnt[nums[left]] -= 1
                left += 1
            if right - left + 1 > ans:
                ans = right - left + 1
        return ans
```

**版本 J —— `k` 任意时的精确跳转（等价参照，不推荐直接上）**

```python
from collections import defaultdict, deque
from typing import List


class Solution:
    def maxSubarrayLength(self, nums: List[int], k: int) -> int:
        pos = defaultdict(deque)                 # 值的所有"候选最早出现位置"
        ans = left = 0
        for right, x in enumerate(nums):
            dq = pos[x]
            dq.append(right)
            while dq and dq[0] < left:           # 必须先弹掉已滑出窗口的过期下标
                dq.popleft()
            if len(dq) > k:                      # 窗口内该值已有 k+1 个 -> 越过最早那个
                left = dq.popleft() + 1
            if right - left + 1 > ans:
                ans = right - left + 1
        return ans
```

> 另一个等价写法（`3090` 笔记里提到的通用化形式）是给每个值配 `deque(maxlen=k)`，**先判后追加**：
> `if len(dq) == k and dq[0] >= left: left = dq[0] + 1`，再 `dq.append(right)`。
> 它靠 `maxlen` 自动丢最旧、并用 `dq[0] >= left` 挡住过期下标，省掉了清理循环 —— 实测 5000 组随机 + 250,959 组穷举**偏差 0**，`left` 序列与用户版逐轮全等。

**优化理由（数据说话）**：

- **B**：`ans = max(ans, ...)` → `if ... > ans`，省一次函数调用。11 个场景里 **9 个 1.05~1.11×**，零收缩场景打平（0.95~1.00×，属噪声级）。
- **G 的 `k=1` 分支为什么能快一倍**：`k=1` 时"每个值最近一次的窗口内位置"就是一个整数，`last` 字典**每轮只有一次 `get` + 一次 setitem**，没有任何对象创建；而计数表版要维护计数、且 `while` 每格一次哈希。`k=1` 又恰好是滑窗题（`3`、`1695`、`1493` 那一族）出现频率最高的口径，所以这个分支很值。
- **J（`deque` 跳转）只在"值重复度高"时划算，在"值域 ≈ n"时会**反向爆炸到 0.26×**：每遇到一个**首次出现**的值就要新建一个 `deque` 对象，`n = 10⁵` 个互不相同的值 = 10 万个对象创建 + 10 万次 `append` + 索引，光这一项就 ~90 ms，把"少做哈希"省下的时间全赔进去还倒欠 4 倍。**值域无界时，跳转版的收益是不确定的，用户版反而最稳。**
- 被实测证伪的改法：**`E`（每值一个 `list` + 独立 `head` 指针字典）** 在所有场景 **0.59~0.97×**，两个字典的查表开销比计数表更贵 —— 记下来，别再试。

**怎么读这张表**：

- **用户版所有场景都能过**（最坏 34.41 ms），它不是"会 TLE 的写法"，优化买到的是 1.0~2.35 倍的常数。
- **`G` 是唯一"只赚不亏"的改法**（0.95~2.35×）：`k=1` 拿跳转的红利，`k≥2` 老实走用户版，所以不会碰上 `deque` 的对象创建陷阱。
- **`F`（`k=1` 跳转、`k≥2` 也走 `deque`）请勿模仿**：在 `k≥2` 且值域 ≈ n 的两行掉到 0.26×，和 `D` 一样惨。
- **"值重复度"才是决定跳转版值不值得的变量**，不是 `k` 也不是 `n`：`10^4 值整块循环 k=2`（只有 10⁴ 个不同值）跳转版 1.11×，`全不同 k=5`（10⁵ 个不同值）掉到 0.26×。

### 常数级优化（可选）

- `ans = max(ans, right - left + 1)` → `if right - left + 1 > ans`：省一次函数调用，实测稳赚（版本 B）。
- `k == 1` 时改用 `last` 字典：状态从"每值一个计数"缩成"每值一个下标"，免掉 `while` 的逐格哈希（版本 G）。
- **不要**把 `cnt` 从 `defaultdict` 改成"先 `if j in cnt` 再赋值" —— `cnt[j] += 1` 依赖默认值，显式判断反而更慢。
- 值域有界时（如 `1695`）优先"定长数组 + 前/后位置表"；本题值域 `10⁹` 无界，这条用不上。

## 六、易错点与总结

### 易错点

- **把 `while` 换成"只挪一格"**：错 **20.8%**（250,959 组穷举），最小反例 `[1,2,2,1]`、`k=1`（真 2、实得 3）。根因是 `cnt[j] > k` 只检查新元素，发现不了上一轮残留的违规 —— 本笔记第五节有完整归因。
- **`while` 版配终值口径 `n - left`**：错 **19.7%~22.0%**，最小反例 `[1,2,2]`、`k=1`（真 2、实得 1）。`while` 版每轮都收缩到合法，长度序列会下降，必须每轮取 `max`。
- **`deque` 跳转忘了弹过期下标**：`len(dq)` 会把已滑出窗口的位置算进去，`left` 被**拖回**左侧，错 **17.8%**。正确写法是先 `while dq and dq[0] < left: dq.popleft()`，或者用 `deque(maxlen=k)` + `dq[0] >= left` 守卫（`3090` 的写法）。
- **看到"计数表"就条件反射加 `del`**：本题判据**按值**，**不需要**；只有 `904 / 159 / 340` 那种按键数（`len(cnt) > K`）的判据才必须 `del`。
- **缺 `from collections import defaultdict` / `from typing import List`**：截图第 1 行就是 `class Solution:`，本地复制会直接 `NameError`（定义时不报错、**调用时**才报错，`exec(src)` 验不出来，必须真的调用一次）。
- **把 `1695` 的"定长数组当 `last`"搬过来**：本题 `nums[i] ≤ 10⁹`，数组开不出来。
- **把 `3090` 的 `last1/last2` 搬过来**：那是 `k=2` 写死的产物；`k` 是输入，必须可变长状态。
- **上 `deque` 跳转前先看值重复度**：值域 ≈ n（新值多）时它比用户版慢 4 倍（实测 0.26×）。
- **用二分/前缀和去"优化"左指针**：左指针是摊还 O(1)，换 O(log n) 是负优化（`1208` 那轮实测过 0.44~0.81×）。
- **负下标**：用户版只用 `nums[left]`，`left` 单调不减且 ≤ `right`，无风险；改跳转版后要记得初值 `-1` 与守卫 `p >= left`（不能只写 `p != -1`）。

### 题型套路沉淀

- **「每值计数 ≤ k」家族的判据表**（`k` 决定状态形状）：

  | k | 状态 | 判据 | 代表题 |
  | :---: | :--- | :--- | :--- |
  | 1 | `cnt[x]` 计数表，或 `last[x]` 一个下标 | `cnt[x] > 1` / `last[x] >= left` | `3`、`1695`、`1493` |
  | 2 | `last1[x]` / `last2[x]` 两个下标 | `last2[x] >= left` | `3090` |
  | 任意 k | 每值一个 `deque(maxlen=k)` | `len(dq) == k and dq[0] >= left` | **本题 2958**（跳转版） |
  | 任意 k | 窗口计数表 + `while` 收缩 | `cnt[x] > k` | **本题 2958**（用户版，推荐） |

- **本族与相邻族的对照（同骨架，只差"判据 / 答案口径"一格）**：

  | 题 | 窗口合法性度量 | 判据种类 | 答案口径 | `while` → 平移 `if` |
  | :--- | :--- | :--- | :--- | :--- |
  | `3` / `3090` / **本题** | 每值计数 ≤ k | 按值 | 长度 | 可以换（**判据须写成整体判据**） |
  | `904` / `159` / `340` | 不同种类数 ≤ K | 按键数（**必须 `del`**） | 长度 | 可以换 |
  | `1004` / `1208` / `1493` | 某度量（0 的个数 / 代价和）≤ 上限 | 按度量值（可加） | 长度 | 可以换（实测 0 错） |
  | `1695` | 每值计数 ≤ 1 | 按值 | **求和** | **不可以换** |
  | `209` 最短型 | 窗口和 ≥ target | 按和（可加） | 长度 | 不可以（"平移"只救最长型） |

- **一条可背的判别顺序**：先看**答案口径是不是"长度"**（不是长度的，平移版直接出局）；再看**收缩判据是不是对"整个窗口"成立的**（只看新元素的判据会漏掉残留违规）；两条都过，才能把 `while` 换成"只挪一格 + 终值口径"。**但本题没有任何换的必要** —— 用户版的 `while` 才是把它变成"一次只查一个键"的那个设计。
- **「一次跳转」是精确收缩，不是平移**：`left = dq[0] + 1` 与 `while` 逐格收缩逐轮状态全等，只是把量级不定的挪动换成 O(1) 查表。它**不是**"每轮只挪一格"那种带前提的优化，别混为一谈。
- **值域是否无界，决定优化路线**：`1695`（值域 10⁴）→ 定长数组 + 前缀和，稳赚；**本题（值域 10⁹）→ 任何"按值建对象"的方案都要先算一算对象创建成本**，值域 ≈ n 时它能把收益吃光。
- **同型题**：`3. 无重复字符的最长子串`（**同目录已有**，k=1 对照组）、`3090`（同目录已有，k=2 写死版）、`1695`（同目录已有，答案口径=求和的镜像题）、`904`（同目录已有，按键数判据的对照组）、`1493`（同目录已有）、`1100`（同目录已有，定长对照）、`1208`（同目录已有）、`1004`、`159` / `340`、`424`、`2024`、`992. K 个不同整数的子数组`。
