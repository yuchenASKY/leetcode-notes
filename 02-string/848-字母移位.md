# 848. 字母移位

> **难度**：中等
> **标签**：数组 · 字符串 · 前缀和
> **原题链接**：https://leetcode.cn/problems/shifting-letters/

---

## 一、题目描述

给一个由小写字母组成的字符串 `s`，以及一个长度相同的整数数组 `shifts`。对每个 `i`，把 `s` 中**前 `i + 1` 个字母**都向后移位 `shifts[i]` 次（字母表循环，`'z'` 之后回到 `'a'`）。所有移位按 `i` 从 0 到 n-1 依次施加，求最终字符串。

换句话说：字母 `s[j]` 会被第 `j, j+1, ..., n-1` 轮移位各碰一次，所以它累计要移 `shifts[j] + shifts[j+1] + ... + shifts[n-1]` 次 —— 这是 `shifts` 在 `j` 处的**后缀和**。

### 示例

```text
输入：s = "abc", shifts = [3,5,9]
输出："rpl"
解释：
  第 i=0 轮移前 1 个字母 3 次："abc" -> "dbc"
  第 i=1 轮移前 2 个字母 5 次："dbc" -> "igc"
  第 i=2 轮移前 3 个字母 9 次："igc" -> "rpl"
校验：'a' 共移 3+5+9=17 次 -> 17%26=17 -> 'r'
      'b' 共移 5+9=14 次   -> 'b'+14='p'
      'c' 共移 9 次        -> 'c'+9='l'
```

### 约束条件

- `1 <= s.length <= 10^5`
- `s` 仅由小写英文字母组成
- `shifts.length == s.length`
- `1 <= shifts[i] <= 10^9`

## 二、解题思路

### 核心思想

**每个字母的位移量是 `shifts` 的一个后缀和，而后缀和可以「先求总和，再边走边减」在 O(1) 空间里滚出来。**

### 思路演进

1. **暴力解法（按题面字面模拟）**：外层枚举 `i`，内层把 `s[0..i]` 每个字母都移位 `shifts[i]` 次。时间 O(n² · 移位量)，即便对 `shifts[i]` 先取模，也是 **O(n²)**：n = 10^5 时约 5×10⁹ 次操作，必然超时。而且中间字符串一直在变，模拟本身没有信息量。
2. **观察到**：题目规定的是「每轮移前 `i+1` 个」，这个区间是**单调扩张**的。所以对固定位置 `j` 而言，凡是 `i >= j` 的轮次都会碰到它，位移量恰好是 `shifts[j..n-1]` 的和 —— 与字母内容无关，**可以一次性算出来，不必真的一轮轮去搬**。于是问题从「模拟」变成「求后缀和」。
3. **优化为**：后缀和的标准写法是从右往左累加 `X[j] = shifts[j] + X[j+1]`，但那要么开一个 O(n) 的数组，要么倒着走。本解法换个角度：**总和就是 `X[0]`**，它一开始就能用 `sum(shifts)` 拿到；而相邻两项的关系是 `X[j+1] = X[j] - shifts[j]`。于是**只需一次从左到右扫描**，用滚动变量 `x` 携带当前的后缀和，用完立刻减掉 `shifts[i]` 交给下一位。不需要额外数组，也不需要反向遍历。

### 关键点

- **对应关系别搞反**：`shifts[i]` 影响的是 `s[0..i]`，所以 `s[j]` 的位移量是 `shifts[j]` 往后的**后缀和**，不是前缀和。前缀和方向想反了会得出完全错的字符串（示例里 `'a'` 要移 17 次，而前缀和是 3 次）。
- **先移位、后递减**：循环体里必须先用当前的 `x` 算字符，再执行 `x -= shifts[i]`。顺序颠倒会让第一位少减一次。
- **随时对 26 取模**：`shifts[i]` 最大 10⁹、n 最大 10⁵，后缀和可达 10¹⁴ 量级。移位只看 `% 26` 的结果，因此 `x` 全程保持在 `[0, 25]`。Python 的 `%` 对负数返回非负值，`x -= shifts[i]` 变成负数也能自动归位，无需手动 `+26` 修正。

---

## 三、代码实现

### 最终代码

```python
class Solution:
    def shiftingLetters(self, s: str, shifts: list[int]) -> str:
        ord_a = ord('a')
        x = sum(shifts) % 26          # 初始为 X[0]：s[0] 的总位移量（已取模）
        ans = []
        for i, c in enumerate(s):
            index = ord(c) - ord_a
            ans.append(chr(ord_a + (index + x) % 26))
            x = (x - shifts[i]) % 26  # 滚到 X[i+1]：去掉 shifts[i] 这一轮的贡献
        return "".join(ans)
```

## 四、复杂度分析

| 版本 | 时间复杂度 | 空间复杂度 |
| :--- | :--- | :--- |
| **最终代码** | O(n) | O(n)（结果数组；不计输出则 O(1)） |
| 朴素解法（逐轮模拟） | O(n²) | O(n)（中间字符串） |
| 理论下界 | O(n) | O(n)（必须产出长度为 n 的答案） |

> 复杂度中的 n 指字符串 `s`（也是 `shifts`）的长度。

## 五、优化评估

**结论**：**已是最优**，时间与空间都到理论下界，无进一步优化余地。

### 瓶颈分析

时间上有两处 O(n) 的必要开销：`sum(shifts)` 要把 `shifts` 完整读一遍（否则算不出 `X[0]`），遍历 `s` 要产出 n 个字符（否则答案不全）。两者相加仍是 O(n)，没有重复计算的部分。

空间上只有一个滚动变量 `x` 和结果列表：`x` 是 O(1)，结果列表是输出的本身，不可省。

### 可优化空间

**时间上不可能低于 O(n)**：任何正确解都必须至少读一遍 `shifts`（每个元素都影响某个字母的位移量，漏读一个就可能改变答案），也必须写满 n 个输出字符，这是输出规模的硬下界，而本解正好是 O(n)。

**空间上不可能低于 O(n)**：答案是长度 n 的字符串，Python 字符串不可变，构造过程必然需要一块长度为 n 的缓冲。本解没有在这之外多开任何与 n 同阶的结构。

## 六、易错点与总结

### 易错点

- **把位移量当成了前缀和**。题面说的是「移前 `i+1` 个」，容易顺着读成「`s[j]` 受 `shifts[0..j]` 影响」，方向正好相反。用示例的 `'a'` 验证：正确是 17 次（3+5+9），前缀和会算出 3 次，得到 `'d'` 而非 `'r'`。
- **循环体内两步顺序写反**。先 `x -= shifts[i]` 再取字符，会让 `s[0]` 少算一次 `shifts[0]`。
- **忘记 `sum(shifts)` 也要取模**。虽然 Python 大整数不会溢出，但让 `x` 一上来就是 10¹⁴ 量级，`(index + x) % 26` 的计算就白扛了一个大数；统一 `% 26` 后 `x` 始终在 `[0, 25]`，口径清爽。
- **`x -= shifts[i]` 后为负时不加 26**。Python 的 `%` 返回非负余数，所以本解安全；如果改写成 C++ / Java，就必须写成 `((x - shifts[i]) % 26 + 26) % 26`，否则后续 `(index + x) % 26` 会得到负下标。

### 题型套路沉淀

- **「区间单调扩张 / 收缩的累积作用」→ 转化成前缀和或后缀和**。凡是题面描述「第 i 轮影响某个随 i 单调变化的前缀（或后缀）」，先别急着模拟，写出每个位置被影响的总次数，通常就是一个和式，能 O(1) 递推。
- **后缀和的两种走法**：正着走需要额外数组或反向遍历；「先取总和、边走边减」可以在一次正向扫描里滚出来，是写 O(1) 空间时优先考虑的形式。
- **循环移位一律先取模**：`(base + offset) % 26` 是字母表移位的固定写法，基准用一次 `ord('a')` 缓存下来，全程用 `0..25` 的下标运算，最后再转回字符。
