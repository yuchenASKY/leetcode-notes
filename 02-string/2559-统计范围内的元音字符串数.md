# 2559. 统计范围内的元音字符串数

> **难度**：中等
> **标签**：数组 · 字符串 · 前缀和
> **原题链接**：https://leetcode.cn/problems/count-vowel-strings-in-ranges/

---

## 一、题目描述

给定字符串数组 `words` 和若干查询 `queries[i] = [li, ri]`。对每个查询，统计下标区间 `[li, ri]`（含两端）内**首尾字母都是元音**的字符串个数。元音为 `a`、`e`、`i`、`o`、`u`。

注意：每个字符串「是否首尾为元音」这件事与查询区间**无关**，区间只决定要数哪一段。

### 示例

```text
输入：words = ["aba","bcb","ece","aa","e"], queries = [[0,2],[1,4],[1,1]]
输出：[2,3,0]
解释：
  元音字符串是 "aba"、"ece"、"aa"、"e"（下标 0、2、3、4），"bcb" 首字母 b 不是元音
  查询 [0,2] → 下标 0,2 中共 2 个
  查询 [1,4] → 下标 1,2,3,4 中共 3 个
  查询 [1,1] → 只有 "bcb"，共 0 个
```

```text
输入：words = ["a","e","i"], queries = [[0,2],[0,1],[2,2]]
输出：[3,2,1]
```

### 约束条件

- `1 <= words.length <= 10^5`
- `1 <= words[i].length <= 40`
- `words[i]` 仅由小写英文字母组成
- `0 <= queries.length <= 3 * 10^4`
- `queries[i].length == 2`
- `0 <= li <= ri < words.length`

## 二、解题思路

### 核心思想

**把「每个词是否合格」压成一个 0/1 序列，再用前缀和把任意区间的求和变成一次减法。** 预处理 O(n)，每个查询 O(1)。

### 思路演进

1. **暴力解法**：对每个查询 `[li, ri]`，把 `li..ri` 逐个取出来，检查首尾字符是否为元音并计数。时间 O(q · n)，q 最多 3×10⁴、n 最多 10⁵，最坏约 3×10⁹ 次字符判断 —— 必然超时。而且这里有个明显的浪费：同一个单词会在不同查询里被反复判断几十次，结论却永远不变。

2. **观察到**：单词的合格性只取决于自身（`word[0]` 与 `word[-1]` 是否在元音集合里），与查询毫无关系。所以任何一次判断的结果都可以**复用**。问题真正剩下的部分只是一个纯粹的结构性问题：**在一个 0/1 序列上反复求区间和**。

3. **优化为**：先扫一遍 `words`，把每个词判成 1 或 0，累积成前缀和数组 `s`，其中 `s[k]` = 前 `k` 个单词里合格单词的个数（`s[0] = 0`，长度 `n + 1`）。于是区间 `[l, r]` 的和 = `s[r + 1] - s[l]`。单词判断总共只做 n 次，查询全部变成两次数组访问加一次减法。

> 这一步的关键是**把「元素级判断」和「区间级统计」拆开**：前者一次性做完、结果固化；后者交给前缀和做 O(1) 的差分化简。两者混在一起（每个查询都重新判断）就是暴力解，拆开就是 O(n + q)。

### 关键点

- 前缀和数组长度取 **`n + 1`** 而不是 `n`：`s[0] = 0` 作为哨兵，`s[k]` 表示「前 k 个」。这样区间 `[l, r]` 的答案统一写成 `s[r + 1] - s[l]`，`l = 0` 时也不需要特判。
- 元音判断用 `set` 查表（`x[0] in vowels and x[-1] in vowels`），比 `str.find` 或手写 `or` 串联都更简洁；26 个字母里判 5 个，集合哈希一次就够。
- **首尾可以同一个字符**：长度为 1 的单词（如 `"a"`、`"e"`）只要它是元音就算合格 —— `x[0]` 与 `x[-1]` 指向同一个位置，`and` 两边都成立，天然正确，不需要额外分支。
- 题目保证 `words[i].length >= 1`，所以 `x[0]` / `x[-1]` 不会越界；如果约束没这条，必须先判空串。

## 三、代码实现

### 最终代码

```python
from typing import List


class Solution:
    def vowelStrings(self, words: List[str], queries: List[List[int]]) -> List[int]:
        letters = 'aeiou'
        letter = set(letters)
        n = len(words)
        s = [0] * (n + 1)                 # s[k] = 前 k 个单词中元音字符串的个数
        for i, x in enumerate(words):
            if x[0] in letter and x[-1] in letter:
                s[i + 1] = s[i] + 1
            else:
                s[i + 1] = s[i]
        ans = []
        for i, j in queries:
            ans.append(s[j + 1] - s[i])   # 区间 [i, j] = 前缀[j+1] - 前缀[i]
        return ans
```

> `from typing import List` 截图里没有（LeetCode 环境自带），本地运行需要补上。

## 四、复杂度分析

| 版本 | 时间复杂度 | 空间复杂度 |
| :--- | :--- | :--- |
| **最终代码** | O(n + q) | O(n) |
| 朴素解法 | O(n · q) | O(1) |
| 理论下界 | O(n + q) | O(n) |

> 复杂度中的 n 指 `words` 的长度（单词个数），q 指 `queries` 的长度（查询个数）。单个单词长度上限 40，是常数，计入字符比较也仍为 O(1)。

## 五、优化评估

**结论**：时间复杂度已达理论下界，无需再优化；空间上是标准的「一次预处理换 O(1) 查询」代价。

### 瓶颈分析

时间分两块，都不可压缩：

- **预处理**：每个单词至少要被看一眼首尾字符才能知道合不合格，n 个单词 ⇒ Ω(n)。
- **回答查询**：q 个答案必须逐个产出，⇒ Ω(q)。

所以 O(n + q) 是下界，当前代码正好贴着它。对比暴力解 O(n · q)，省下的正是「同一单词被重复判断」的那部分。

空间上 O(n) 全部来自前缀和数组 —— 这是把区间和变成两次访问必须付出的存储代价。

### 可优化空间

**没有必要再动**。唯一能把额外空间压到 O(1) 的方向是「复用输入数组」（把 `words` 原地改写成一串累计值），代价是修改了调用方传入的数据，在工程上属于副作用，得不偿失；而查询顺序被打乱后还得额外存一份下标映射，反而多出 O(q) 空间。因此保持现状。

### 常数级优化（可选）

- 元音判断写成 `x[0] in vowel_set and x[-1] in vowel_set`，两边的集合对象提到循环外，避免循环内重复构造。
- `s` 的填充可以用 `if/else` 直接赋值，不必先算布尔再转整数；已按此写法给出。
- 若追求极简（不加 `import`），元音判断也可写成 `x[0] in 'aeiou' and x[-1] in 'aeiou'` —— 5 个字符的线性扫描，在本机量级下与集合哈希的差异可以忽略，胜在少一个变量。

## 六、易错点与总结

### 易错点

- **前缀和长度少写 1**：写成 `s = [0] * n` 后 `s[r + 1]` 直接越界。记住「`n + 1` 个格、第 k 格管前 k 个」。
- **区间映射写反**：区间 `[l, r]` 是 `s[r + 1] - s[l]`，不是 `s[r] - s[l]`（后者会漏掉 `r` 这个位置），也不是 `s[r + 1] - s[l + 1]`（会漏掉 `l`）。
- **单字符单词漏判**：不要写成 `x[0] in letter and x[-1] in letter and len(x) > 1`，那会把 `"a"`、`"e"` 这类正确答案排除掉。
- **首尾判断偷懒用 `x[0]` 和 `x[1:]`**：长度 1 时 `x[1:]` 是空串，空串 `in` 集合为 `False`，逻辑就错了。
- **对每个查询重新判断单词**：这是最自然的直觉写法，也是本题唯一会被卡住的写法。

### 题型套路沉淀

- **前缀和的标准触发条件**：**输入不可变（或至少与查询无关）+ 大量区间求和查询**。只要看到「多次询问区间内满足某条件的元素个数」，先想「能不能把条件判断预处理器化成一个 0/1 数组，再用前缀和回答」。
- **通用模板**：

  ```python
  pre = [0] * (n + 1)
  for i, x in enumerate(arr):
      pre[i + 1] = pre[i] + (1 if cond(x) else 0)
  # 查询 [l, r]
  ans = pre[r + 1] - pre[l]
  ```

  换成「区间和 / 区间最大值不符合可减性」时，前缀和就不适用了（最大值不能相减），要换稀疏表或线段树 —— 这是前缀和的适用边界。
- **两步拆解的价值**：把「元素级判定」与「区间级统计」分离，是这类区间查询题通用的降复杂度手法，比记住某个具体题的代码更有用。
