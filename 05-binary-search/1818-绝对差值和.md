# 1818. 绝对差值和

> **难度**：中等
> **标签**：数组 · 二分查找 · 排序
> **原题链接**：https://leetcode.cn/problems/minimum-absolute-sum-difference/

---

## 一、题目描述

给定两个长度都是 `n` 的正整数数组 `nums1`、`nums2`，定义绝对差值和为所有 `|nums1[i] - nums2[i]|` 之和。

你可以从 `nums1` 里**任选一个元素**去替换 `nums1` 中的**至多一个**元素（替换值也必须取自 `nums1`），使新的绝对差值和最小，返回最小可能值对 `10^9 + 7` 取模的结果。

### 示例

```text
示例 1
输入：nums1 = [1,7,5], nums2 = [2,3,5]
输出：3
解释：把 nums1[1] = 7 换成 1 → [1,1,5]，差值和 = |1-2| + |1-3| + |5-5| = 1 + 2 + 0 = 3
      （原来的差值和是 1 + 4 + 0 = 5，收益 2）

示例 2
输入：nums1 = [2,4,6,8,10], nums2 = [2,4,6,8,10]
输出：0
解释：原差值和已经是 0，不替换

示例 3
输入：nums1 = [1,10,4,4,2,7], nums2 = [9,3,5,1,7,4]
输出：20
```

### 约束条件

- `n == nums1.length == nums2.length`
- `1 <= n <= 10^5`
- `1 <= nums1[i], nums2[i] <= 10^5`

---

## 二、解题思路

### 核心思想

**每个位置被替换时带来的收益是互相独立的，所以只需取「收益最大的那个位置」**；而单点的最优收益是「原差值 − 在 `nums1` 中离 `nums2[i]` 最近的元素的距离」，最近邻查询用「排序 + 二分」在 O(log n) 内完成。

### 思路演进

1. **暴力解法**：直接照定义枚举 —— 外层枚举「改哪个下标 `i`」，内层枚举「改成 `nums1` 里的哪个值 `nums1[j]`」，每次重算差值和。时间 **O(n²)**（只算收益的话）到 **O(n³)**（每次重算总和），n = 10^5 时彻底不可行。

2. **瓶颈定位**：内层循环在做的是「**在 `nums1` 里找离 `nums2[i]` 最近的那个值**」。这是一个纯查询，却被写成了整表扫描；而且**这个查询与外层改动无关** —— 无论改 `nums1` 的哪个位置，`nums2[i]` 的最近邻都是同一个。重复枚举的是同一件事。

3. **关键转化**：
   - 被替换的位置只有一个，改 `nums1[i]` 不改动任何别的位置的差值 ⇒ 总差值 = 原总和 − 收益(`i`)，且收益(`i`) 只依赖 `i` ⇒ **取收益最大的那个位置即可（贪心）**。
   - 收益(`i`) = `|nums1[i] - nums2[i]|` − `min_j |nums1[j] - nums2[i]|`，把 `nums1` 排序后，"最近邻"退化成"二分定位后的相邻两格"。
   - 于是 **O(n) 个查询 × O(log n)** 完成，整体 O(n log n)，瓶颈转移到排序上。

4. **最优解**：`nums = sorted(nums1)`，对每个 `i` 用 `bisect_left(nums, nums2[i] + 1)` 拿到「第一个大于 `nums2[i]` 的位置 `k`」，则 `nums[k]`（若存在）是右侧最近邻、`nums[k-1]`（若存在）是左侧最近邻，二者取近者即是全局最近邻。累加原差值、记录最大收益，最后一次性取模。

### 判据与判据族定位

**本题判据（一条可判定真假的命题）**：对有序数组 `nums` 和键 `b`，若 `k = bisect_left(nums, b + 1)`，则

- `nums[k]` 是 `nums` 中**最小的、严格大于 `b`** 的元素（`k == n` 时不存在）；
- `nums[k-1]` 是 `nums` 中**最大的、不大于 `b`** 的元素（`k == 0` 时不存在）；
- ⇒ `min{ |v - b| : v ∈ nums } = min(b - nums[k-1], nums[k] - b)`（单侧不存在时取另一侧）。

**族定位**：属 `05-binary-search` 目录下的「**有序序列上的单调谓词边界定位**」（**下标二分**）族 —— 二分的是**下标**，谓词由数组自身的单调性给出。与同目录另两族的关系：

| 载体 | 二分对象 | 谓词来源 | 与本题的关系 |
| :--- | :--- | :--- | :--- |
| 原数组自身（本题） | 下标 | 数组已排序 | 本节判据 |
| 前缀和数组 | 下标 | 由元素非负推出有序 | 不适用（本题无前缀和） |
| 值 → 有序下标表 | 下标 | append 顺序 | 不适用 |
| **二分答案** | **答案值** | `check(x)` 可行性 | 不适用（本题不是最小化最大值类） |

> `§3.4 ①~⑫`（滑动窗口判据族）与本题**无关**：本题没有窗口、没有左右指针收缩，`while` 里也没有单调度量。

### 关键点

- **收益独立 ⇒ 贪心取最大**：这是把 O(n²) 降成 O(n log n) 的前提。注意题目说的是"用 `nums1` 中的一个元素替换 `nums1` 中的至多一个元素"，所以"不替换"永远可选，收益为 0。
- **收益恒 ≥ 0**：`min_j |nums1[j] - nums2[i]| ≤ |nums1[i] - nums2[i]|`（`nums1[i]` 自身就是候选），所以最大收益的初值可以取 `0`，不必用 `-1` 或 `-inf`。
- **只对最终结果取模**：因为最大收益 ≤ 原总和，`sumnum - minusmax` 恒非负；反过来，若中途对 `sumnum` 取模，减法就会错。
- **二分定位用「左右夹逼」而非「找相等」**：要找的是最近邻，键本身通常不在数组里，所以取的是插入点两侧的两个元素。

## 三、代码实现

### 最终代码

用户已提交通过的版本（截图来源，`from bisect import bisect_left` 与 `from typing import List` 原文没有，已补）：

```python
from bisect import bisect_left
from typing import List


class Solution:
    def minAbsoluteSumDiff(self, nums1: List[int], nums2: List[int]) -> int:
        nums = nums1                      # 死代码：下一行立刻重新绑定，等价于直接写 sorted(nums1)
        nums = sorted(nums)
        minusmax = 0
        sumnum = 0
        for i in range(len(nums1)):
            minus = abs(nums1[i] - nums2[i])
            sumnum += minus
            numIndex = bisect_left(nums, nums2[i] + 1)     # 第一个 > nums2[i] 的位置
            if numIndex == len(nums):
                val = nums2[i] - nums[numIndex - 1]        # 右侧不存在，只能向左
            elif numIndex == 0:
                val = nums[numIndex] - nums2[i]            # 左侧不存在，只能向右
            else:
                val = min(nums[numIndex] - nums2[i], nums2[i] - nums[numIndex - 1])
            if minus - val > minusmax:
                minusmax = minus - val
        return (sumnum - minusmax) % (10 ** 9 + 7)
```

## 四、复杂度分析

| 版本 | 时间复杂度 | 空间复杂度 |
| :--- | :--- | :--- |
| **最终代码**（排序 + 二分） | O(n log n) | O(n) |
| 值域桶版（本题优化，见下节） | O(n + V) | O(V) |
| 朴素解法（枚举位置 × 替换值） | O(n²) | O(1) |
| 理论下界 | 比较模型 Ω(n log n)；值域有界时可到 O(n + V) | — |

> - `n` 指 `nums1`、`nums2` 的长度（本题 ≤ 10^5）。

> - **下界不是唯一的**：在纯比较模型下，"n 次静态集合的最近邻查询"需要 Ω(n log n)（排序下界）；但题目额外给了值域 `≤ 10^5`，利用它可以把 log 因子彻底消掉，得到 O(n + V) —— 见「五、优化评估」。

## 五、优化评估

**结论**：用户版是这道题的标准解，**没有渐进缺陷**；但在**值域与 n 同量级或更小**时，仍有一条由题面值域上界带来的 O(n + V) 路线可再快 1.5× ~ 2×；而值域远大于 n 时该路线会退化 10× 以上。**是否"已最优"取决于值域，而不是取决于算法。**

### 瓶颈分析

把用户版的循环拆开逐段实测（7 轮同轮轮转取最优，ms）：

| 场景 | sort | 循环 | 合计 | 循环占比 |
| :--- | ---: | ---: | ---: | ---: |
| S1 `n=1e5, V=1e5`（随机值） | 15.918 | 84.609 | 100.527 | 84.2% |
| S2 `n=1e5, V=10` | 5.955 | 35.055 | 41.010 | 85.5% |
| S3 `n=2000, V=1e5` | 0.189 | 0.760 | 0.949 | 80.1% |
| S4 `n=1e5` 全同值 | 0.623 | 30.681 | 31.304 | 98.0% |

⇒ **时间几乎全在循环里的那 n 次 `bisect` 上（80% ~ 98%），排序只占 2% ~ 20%**。所以"优化"只有一个方向：**减少/换掉这 n 次二分**。而 `bisect` 的时间本身几乎全在 C 层，Python 层能动的只有两条路 —— 减少调用次数，或换掉查表方式。

### 可优化空间

**路线 B（值域桶 + 双向 O(1) 查表）**：题面给了 `nums1[i] <= 10^5`，于是可以

1. 用 `present[v]` 标记每个值是否出现；
2. **正扫一遍**得到 `last_le[x]` = 不超过 `x` 的最大出现值（即"左侧最近邻"）；
3. **倒扫一遍**得到 `first_ge[x]` = 不小于 `x` 的最小出现值（即"右侧最近邻"）；
4. 每个查询退化成两次数组下标访问，**O(1)**。

总复杂度 **O(n + V)**，log 因子消失；代价是两张长度 V + 2 的表（空间 O(V)）和一次 O(V) 的建表。

**路线 C（等价改写，常数级）**：`bisect_left(nums, nums2[i] + 1)` 与 `bisect_right(nums, nums2[i])` **逐位等价**（因为两侧都是整数：`nums[k] > b ⟺ nums[k] ≥ b + 1`），但前者每次调用要多做一次整数加法；`b + 1 > 256` 时还会新建一个 `int` 对象。隔离测试（20 万次调用、7 轮取最优）：**104.5 ms → 95.1 ms（0.910×，每次约省 47 ns）**。

### 优化代码

```python
from typing import List


class Solution:
    def minAbsoluteSumDiff(self, nums1: List[int], nums2: List[int]) -> int:
        MOD = 10 ** 9 + 7
        V = max(nums1)
        VB = max(V, max(nums2))        # 查询值可能比 nums1 的最大值还大，表要铺到查询上界
        present = bytearray(VB + 2)
        for v in nums1:
            present[v] = 1

        # last_le[x] = 不超过 x 的最大出现值，0 表示不存在
        last_le = [0] * (VB + 2)
        run = 0
        for v in range(VB + 1):
            if present[v]:
                run = v
            last_le[v] = run

        # first_ge[x] = 不小于 x 的最小出现值，V + 1 是「不存在」哨兵
        first_ge = [V + 1] * (VB + 2)
        run = V + 1
        for v in range(VB, -1, -1):
            if present[v]:
                run = v
            first_ge[v] = run

        total = 0
        best = 0
        for a, b in zip(nums1, nums2):
            d = a - b
            if d < 0:
                d = -d
            total += d
            lo = last_le[b]
            hi = first_ge[b]
            val = 1 << 30
            if lo:                     # 守卫不可省，见下
                val = b - lo
            if hi <= V:
                t = hi - b
                if t < val:
                    val = t
            g = d - val
            if g > best:
                best = g
        return (total - best) % MOD
```

**优化理由**：把每个查询的 O(log n) 二分换成两次 O(1) 数组访问；建表 O(V)。收益大小完全由 `V` 与 `n` 的比值决定（见下表）。

### 实测（4 档场景 × 7 轮同轮轮转取最优）

第一组（`A` = 用户版、`C` = 等价改写版、`E` = 把 `bisect_left` 绑成局部变量、`B` = 值域桶版）：

| 场景 | A_user | C_br | E_local | B_bucket | C/A | E/A | B/A |
| :--- | ---: | ---: | ---: | ---: | ---: | ---: | ---: |
| S1 `n=1e5, V=1e5` | 92.096 | 85.012 | 92.807 | 57.262 | 0.923 跨1.0 | 1.008 同侧 | **0.622** |
| S2 `n=1e5, V=10` | 40.883 | 39.483 | 40.678 | 19.930 | 0.966 跨1.0 | 0.995 跨1.0 | **0.487** |
| S3 `n=2000, V=1e5` | 1.027 | 0.916 | 0.912 | 10.323 | 0.892 同侧 | 0.888 同侧 | **10.054** |
| S4 `n=1e5` 全同值 | 30.286 | 30.457 | 30.796 | 35.331 | 1.006 跨1.0 | 1.017 跨1.0 | **1.167** |

（单位 ms；"跨 1.0" 指该档 7 轮逐轮比值区间跨过 1.0，判为**噪声内持平**）

第二组（同一轮轮转内对比两种建表写法，`B` = Python 层显式循环建表、`B2` = `itertools.accumulate` 在 C 层建表）：

| 场景 | A_user | B_bucket | B2_acc | B/A | B2/A |
| :--- | ---: | ---: | ---: | ---: | ---: |
| S1 `n=1e5, V=1e5` | 92.800 | 60.152 | 61.328 | 0.648 | 0.661 |
| S2 `n=1e5, V=10` | 42.384 | 19.665 | 22.281 | 0.464 | 0.526 |
| S3 `n=2000, V=1e5` | 0.973 | 9.859 | 9.512 | 10.132 | 9.776 |
| S4 `n=1e5` 全同值 | 31.862 | 35.665 | 38.391 | 1.119 | 1.205 |

> ⚠️ 两张表的绝对值不可互比（同一脚本换一次运行，`A_user` 在 S1 档读出 92.1 / 92.8 / 100.5 ms，漂移约 ±9%）；**倍数只在各自那一轮轮转内部有效**。

三条结论：

1. **值域桶路线不是无条件优化，分界线在 `V` 与 `n` 的比值上**：`V ≈ n` 时它快 **1.54× ~ 1.61×**（S1）、`V ≪ n` 时快 **2.05× ~ 2.16×**（S2）；但 `V = 50n` 时慢 **10×**（S3），连"`V ≈ n` 但输入退化"的 S4 也慢 **1.12×**。
   - S3 的机理很直白：建表是**固定开销 ≈ 9 ~ 15 ms（∝ V）**，而 `n = 2000` 时用户版的整个循环只有 0.76 ms，怎么摊都摊不回来。S3 的时间构成里**建表占 92.3%**。
   - S4 的机理是另一条：`nums1` 全是同一个值 ⇒ 排序几乎免费（0.62 ms，Timsort 单 run）、且二分每次比较的都是**同一个整数对象** ⇒ 用户版的循环从 84.6 ms 掉到 30.7 ms，桶版省下的 8.6 ms 抵不过建表的 13.4 ms。
2. **`B2`（用 `itertools.accumulate` 把两次 O(V) 扫描压到 C 层）并没有收益**：S1/S3 与显式循环持平（0.661 vs 0.648、9.776 vs 9.512），S2/S4 反而更差（0.526 vs 0.464、1.205 vs 1.119）。原因是 `accumulate` 每轮仍要回调一个 Python 可调用对象（`max` / `min`），单价与显式循环相当，而它还要多付出 `list()` 物化与镜像数组分配的成本。⇒ **"把循环交给 C 层"在需要逐元素调用 Python 函数时不成立。**
3. **等价改写（C）的方向与小幅收益真实存在，但在大 n 档会被噪声淹没**：隔离测试给出干净的 **0.910×**（每次调用约省 47 ns），`n = 2000` 的 S3 档也复现了这个方向（0.837 ~ 0.892，**7 轮全部 < 1.0**）；`n = 1e5` 的三档则跨 1.0。按 47 ns/次估算，`n = 1e5` 应省约 4.7 ms —— 相对 92 ms 只有 5%，正落在噪声带内。**结论：可以换，但不值得当成收益项写进复盘。**

### 常数级优化（可选）

| 改法 | 实测 | 采信 |
| :--- | :--- | :--- |
| `bisect_left(nums, b + 1)` → `bisect_right(nums, b)` | 隔离 0.910×；S3 档 7 轮全 < 1.0 | ✅ 可换（小幅） |
| 把 `bisect_left` 绑成局部变量 `bl` | S1 档 1.004 ~ 1.152（同侧=略亏）、S2/S4 跨 1.0 | ❌ 无收益 |
| `accumulate` 建表替代显式循环（`B2`） | S2/S4 更差、S1/S3 持平 | ❌ 排除 |
| 用 `if d > best: best = d` 内联替代 `max()` | 本题循环里本来就没用 `max` | — |

**最终推荐**：值域与 n 同量级或更小时用桶版，否则用排序 + 二分版；两者可用一句 `if max(nums1) <= 4 * len(nums1)` 之类做分发（本题 `V = n = 10^5` 实测桶版领先 1.5× 以上，`V = 50n` 时落后 10×，交点落在 `V` 与 `n` 同量级附近）。

## 六、易错点与总结

### 易错点

- **取模时机**：题面只要求"答案可能很大，对 `10^9 + 7` 取余后返回"。若在累加 `sumnum` 的过程中取模，`sumnum - minusmax` 会算出错误结果（可能为负）。本题必须**先算出完整的差值总和、减掉最大收益、再取模**。
- **溢出（跨语言）**：`n = 10^5` 且差值最大 10^5 时，总和最高约 `10^10`，**超出 32 位** ⇒ 迁到 C++ / Java 时求和变量必须是 `long long` / `long`，且取模前的减法同样要在 64 位下做。
- **二分越界就删守卫**：`nums[numIndex]` 与 `nums[numIndex - 1]` 分别需要 `numIndex < n` 和 `numIndex > 0`，缺任一个都会 `IndexError`（不是静默错解，是直接崩）。
- **`bisect_left(nums, b + 1)` 的等价性依赖整数性**：`nums[k] > b ⟺ nums[k] ≥ b + 1` 只在两侧都是整数时成立；若键是浮点就会失效。换成 `bisect_right(nums, b)` 更直观、也略快。
- **`nums = nums1` 之后又 `nums = sorted(nums)`**：前一行是死代码，不影响正确性（`sorted` 返回新列表，`nums1` 不会被原地改动，所以后面继续用 `nums1[i]` 是安全的）。

### 题型套路沉淀

- **「只改一个元素，求最优」型**：先拆成 `答案 = 原指标 − max 收益`，再证明各位置收益互不影响 ⇒ 贪心取最大。（若题目变成"可以改 k 个元素"，收益就**不再独立**，需要重新排序或 DP。）
- **最近邻查询模板**：

  ```python
  k = bisect_left(sorted_arr, x + 1)          # 第一个 > x
  if k == len(sorted_arr):   nearest = sorted_arr[-1]      # 只能向左
  elif k == 0:               nearest = sorted_arr[0]       # 只能向右
  else:                      nearest = min(...)            # 两侧比较
  ```

- **值域有界 ⇒ 双向扫描建表**：需要「不超过 x 的最大值 / 不小于 x 的最小值」时，两次 O(V) 扫描就能把任意次查询压成 O(1)。适用判据：**`V` 与 `n` 同量级或更小**；`V ≫ n` 时固定建表成本摊不薄，反而更慢（本题 S3 档实测慢 10×）。
- **本目录的族区分**：本题是「下标二分」（二分的是**下标**，谓词来自数组自身有序），不要与「二分答案」（二分的是**答案值**，谓词是 `check(x)` 可行性）混用 —— 两者的 `while` 写法与边界处理不同。
