# 3620. 恢复网络路径

> **难度**：困难
> **标签**：图 · 拓扑排序 · 二分查找 · 动态规划
> **原题链接**：https://leetcode.cn/problems/network-recovery-pathways/

---

## 一、题目描述

给一张 `n` 个节点的**有向无环图**，`edges[i] = [u, v, cost]` 表示一条 `u → v`、恢复成本为 `cost` 的单向边；`online[i]` 标记节点是否在线（节点 `0` 与 `n-1` 恒在线）。

一条 `0 → n-1` 的路径**有效**，当且仅当：

1. 路径上所有**中间节点**都在线；
2. 路径上所有边的成本之和 `≤ k`。

有效路径的**分数**定义为该路径上**最小的边成本**。求所有有效路径中分数（即「最大化的最小值」）的最大值；一条有效路径都没有时返回 `-1`。

也就是说：要在这个「成本预算 `k`」和「节点必须在线」的双重约束下，把路径上**最薄的那条边**尽量撑大。

### 示例

```text
输入：edges = [[0,1,5],[1,3,10],[0,2,3],[2,3,4]], online = [true,true,true,true], k = 10
输出：3
解释：0 → 1 → 3 总成本 15 > k，无效；
      0 → 2 → 3 总成本 7 ≤ k，分数 min(3,4) = 3；
      仅此一条有效路径，故答案为 3。

输入：edges = [[0,1,7],[1,4,5],[0,2,6],[2,3,6],[3,4,2],[2,4,6]],
      online = [true,true,true,false,true], k = 12
输出：6
解释：节点 3 离线，经过它的路径全部作废；
      0 → 1 → 4 成本 12，分数 5；
      0 → 2 → 4 成本 12，分数 6；取较大者，答案为 6。
```

### 约束条件

- `n == online.length`
- `2 <= n <= 5 * 10^4`
- `0 <= m == edges.length <= min(10^5, n * (n - 1) / 2)`
- `edges[i] = [u_i, v_i, cost_i]`，`0 <= u_i, v_i < n`，`u_i != v_i`
- `0 <= cost_i <= 10^9`
- `0 <= k <= 5 * 10^13`
- `online[i]` 为 `true` 或 `false`，且 `online[0]`、`online[n-1]` 均为 `true`
- 给定图保证是**有向无环图**（DAG）

## 二、解题思路

### 核心思想

**「最大化路径最小边权」是二分答案的标准信号。** 二分一个下界 `lower`，判定「只允许走权值 `≥ lower` 的边时，`0 → n-1` 的最小总成本是否 `≤ k`」；在 DAG 上这个判定就是一趟拓扑序 DP，`O(n+m)`。

### 思路演进

1. **暴力解法**：DFS 枚举所有 `0 → n-1` 的路径，沿途记录成本和「已走边的最小值」，最后取合法路径里分数最大的。问题在于路径数是**指数级**的（最坏 `2^(n-1)`），`n = 5*10^4` 时完全不可行 —— 而且大量路径在算完之后才发现成本超了 `k`，白算。

2. **观察到关键性质 —— 单调性**：把「答案 ≥ lower」这件事看作一个谓词。
   - 若在 `lower` 下存在合法路径，那么把下界调到更小（`lower' < lower`）时，可用边集合**变大**、约束**更松**，该路径依然合法；
   - 若在 `lower` 下不存在合法路径，那么调大下界只会让可用边更少、约束更紧，更加不可能。
   ⇒ 谓词随 `lower` 单调，可以对答案**二分**。最优化问题被降级成了判定问题。

3. **判定怎么做**：固定 `lower` 后，把边分成「可用（`cost ≥ lower`）」和「不可用」两类。于是问题变成：在只含可用边的子图上，求 `0 → n-1` 的**最小总成本**，判断是否 `≤ k`。
   - 只要最小成本 `≤ k`，就存在一条「边权全部 `≥ lower`、总成本 `≤ k`」的路径，判定成立；
   - 若最小成本 `> k` 或根本走不到，则任何满足下界的路径都会超预算，判定不成立。

4. **别用 Dijkstra**：题目明说图是 **DAG**，最短路径必然按拓扑序递推 —— `f[v] = min(f[u] + w)`，把每条边看一次就够，判定从 `O(m log n)` 降到 `O(n+m)`。总复杂度 `O((n+m) log C)`，其中 `C` 是答案值域。

5. **拓扑序上的两个坑**（这是本题真正的难点）：
   - **坑一：`0` 不是唯一的源点。** DAG 里完全可能有别的点指向 `0`，也可能有若干入度为 `0` 但与 `0` 无关的点。若直接对原图做拓扑 + DP，某些节点的入度会被「从 `0` 不可达的前驱」一直撑着 —— 那些前驱永远不会被访问，入度就永远降不到 `0`，节点永远不入队，`f` 值传不出去，合法路径被漏掉。
     **处理**：建图后先跑一趟「净化」——从所有**非 `0` 的入度 `0` 点**出发做拓扑消除（它们必然不可能是 `0 → n-1` 路径上的点），把它们的出边一条条从后继入度里扣掉。跑完之后，`deg[y] > 0` 的节点恰好就是**从 `0` 可达**的节点。此时 `deg` 的含义已经变成「可达子图内的入度」，后续判定拿它当初始入度即可。
   - **坑二：拓扑进度不能跟着边权过滤走。** 判定时 `f` 的松弛只在 `wt >= lower` 时发生，但**入度递减必须对每条边都做**。如果写成「只有可用边才减入度」，那么一个只要有一条 `< lower` 入边的节点，入度永远减不到 `0`，它就不会入队 —— 明明可以经另一条大边到达，却被判成不可达。

6. **二分方向的收尾**：本题的 `check(lower)` 返回 `True` 表示「在 `lower` 下走不出合法路径」，即 **`答案 < lower`**（注意是反的）。于是「答案」= 「第一个使 `check` 为 `True` 的 `lower`」`- 1`，正好可以用 `bisect_left` 表达。

### 关键点

- **二分上界取 `max_wt` = 从 `0` 出发的可用边的最大权值**：任何路径的第一条边都出自 `0`，分数不可能超过它，所以 `max_wt` 就是答案的自然上界。若 `0` 没有可用出边，`max_wt = -1`，二分区间为空，直接落到 `-1`。
- **`f[n-1]` 保持 `inf` 是特性而非 bug**：当所有指向 `n-1` 的边都 `< lower` 时，`n-1` 依然会因为入度清零而入队，但 `f` 没被松弛过，仍是 `inf`；此时 `inf > k` 恒成立，判定自然是「不可行」。
- **`online` 的过滤放在建图阶段**：端点任一离线的边直接不进邻接表，判定函数里就只剩一张纯净的、只含在线节点的子图，不需要再判 `online`。
- **`k` 可达 `5*10^13`**，超出 32 位整数。Python 的大整数无所谓，改写其他语言时要用 64 位。

## 三、代码实现

### 最终代码

> `bisect_left` / `deque` / `inf` / `List` 的 import 截图里没有（LeetCode 环境已预置），此处已补齐。

```python
from bisect import bisect_left
from collections import deque
from math import inf
from typing import List


class Solution:
    def findMaxPathScore(self, edges: List[List[int]], online: List[bool], k: int) -> int:
        n = len(online)
        g = [[] for _ in range(n)]
        deg = [0] * n
        max_wt = -1
        for x, y, wt in edges:
            if online[x] and online[y]:      # 端点离线的边直接丢弃
                g[x].append((y, wt))
                deg[y] += 1
                if x == 0:                   # 答案上界：离开 0 的最大边权
                    max_wt = max(max_wt, wt)

        # 净化：从非 0 的入度 0 点出发做拓扑消除，跑完后 deg 只剩「从 0 可达子图」内的入度
        q = deque([i for i in range(1, n) if deg[i] == 0])
        while q:
            x = q.popleft()
            for y, _ in g[x]:
                deg[y] -= 1
                if y and deg[y] == 0:        # 节点 0 不参与消除
                    q.append(y)

        def check(lower: int) -> bool:
            # 返回 True 表示「下界取 lower 时走不出合法路径」，即 答案 < lower
            deg_copy = deg.copy()
            f = [inf] * n
            f[0] = 0

            q = deque([0])                   # 拓扑序 DP
            while q:
                x = q.popleft()
                if x == n - 1:
                    return f[x] > k          # inf > k 也成立 → 走不到即为不可行
                for y, wt in g[x]:
                    if wt >= lower:          # 只有可用边才参与松弛
                        f[y] = min(f[y], f[x] + wt)
                    deg_copy[y] -= 1         # 入度递减与边权无关，必须无条件执行
                    if deg_copy[y] == 0:
                        q.append(y)
            return True                      # n-1 不可达

        # 二分「第一个令 check 为 True 的 lower」，减一即答案
        return bisect_left(range(max_wt + 1), True, key=check) - 1
```

## 四、复杂度分析

| 版本 | 时间复杂度 | 空间复杂度 |
| :--- | :--- | :--- |
| **最终代码**（二分答案 + DAG 拓扑 DP） | O((n + m) log C) | O(n + m) |
| 二分答案 + Dijkstra | O(m log n · log C) | O(n + m) |
| 朴素解法（DFS 枚举所有路径） | O(2^n) | O(n + m) |
| 理论下界 | O(n + m) | O(n + m) |

> 复杂度中的 `n` 指节点数，`m` 指边数，`C` 指答案值域上界（本题 `C = max_wt ≤ 10^9`，故 `log C ≤ 30`）。
> 每轮判定只把每条边看常数次，二分约 30 轮；净化那趟拓扑消除本身是 `O(n + m)`。

## 五、优化评估

**结论**：时间上已到本题的最优量级，**没有数量级上的优化空间**。

### 瓶颈分析

- 判定部分是「DAG 上单源最短路」，`O(n + m)` 与「把边读一遍」同阶，不可能再快。
- 二分轮数由答案值域决定：`[0, max_wt]` 上取整二分约 `log2(max_wt + 1) ≈ 30` 轮。换成「把边权排序去重后在**下标**上二分」也是 `log m` 轮，量级相同，还要多付一次排序 —— 不划算。
- 实际常数开销集中在：每轮 `deg.copy()` 与 `[inf] * n` 的两趟 `O(n)` 数组构造，以及 Python 层 `m` 次边的循环。

### 可优化空间

- **上界已是最紧**：`max_wt` 只取「离开 `0` 的可用边」，而不是全局最大边权，这一点已经吃满了。
- **下界可以更紧**：理论下界是 `min(离开 0 的可用边权)`（路径第一条边同样受约束），但只影响一轮左右的轮数，量级不变。
- 想继续压常数只能靠改写实现细节，大 O 不变。

### 常数级优化（可选）

- 用 `if f[x] + wt < f[y]: f[y] = f[x] + wt` 替代 `min(f[y], f[x] + wt)`，省掉一次函数调用。
- `deg.copy()` 与 `[inf] * n` 都是 C 层操作，已比 Python 层循环快，不必再手动改写。
- 把 `check` 里用到的 `g`、`deg`、`n`、`k` 在闭包外先绑定成局部名字，能少几次 `LOAD_DEREF`。

## 六、易错点与总结

### 易错点

- **入度递减被塞进 `if wt >= lower` 里**（最隐蔽的一个）：此时只要节点有一条 `< lower` 的入边，入度就永远减不到 `0`，节点永不入队，`f` 传不出去 → 漏解或答案偏小。记住：**松弛看边权，拓扑看结构**，两件事必须解耦。
- **不做「净化」直接拓扑**：`0` 可能不是唯一的源点，不可达的前驱会把后继的入度撑住，导致可达节点也不入队。这趟消除是**正确性**的一环，不是剪枝优化。
- **二分方向搞反**：本题 `check(lower) == True` 表示「答案 `< lower`」（不可行），所以是 `bisect_left(...) - 1`；若写成 `check` 返回「可行」，就该配 `bisect_right(...) - 1`。写错方向时小样例往往还能过，大样例才崩。
- **忘记过滤 `online`**：必须在建图阶段扔掉端点离线的边，否则判定里会走出「穿过离线节点」的路径。
- **上界取成全局最大边权**：不影响正确性，但会白跑若干轮；取成全局最小边权则直接漏解。
- **`k` 用 32 位整型存**：`k` 上限 `5*10^13`，会溢出。

### 题型套路沉淀

- **「最大化最小值 / 最小化最大值」→ 二分答案**：先确认谓词单调，再把「求最优」转成「给定阈值判可行」。判定的通常形态是「过滤掉不满足阈值的边/元素，看剩下的还能不能完成任务」。
- **DAG 上的判定优先考虑拓扑序 DP**：题目给了 DAG 就一定不要上 Dijkstra / SPFA，`O(n+m)` 和无堆的简单代码都是白送的。
- **拓扑排序前先想「谁是源」**：起点 `0` 未必入度为 `0`，也未必是唯一源点。常见处理是从「非起点的入度 0 点」反向消除不可达部分，把 `deg` 校正成「可达子图内的入度」。
- **`bisect` 支持 `key`**：`bisect_left(range(hi + 1), True, key=predicate) - 1` 是「在整数值域上二分单调谓词」的一行写法，前提是 predicate 的返回值方向与 `-1` 的收尾对齐 —— 写之前先把「True 代表什么」写进注释。
