# 668. 乘法表中第k小的数

> **难度**：困难
> **标签**：二分查找 · 二分答案
> **原题链接**：https://leetcode.cn/problems/kth-smallest-number-in-multiplication-table/

---

## 一、题目描述

给定 `m`、`n`、`k`，考虑一个 `m × n` 的乘法表，其中 `mat[i][j] = i * j`（`i`、`j` 均从 1 开始）。表里共有 `m * n` 个数（含重复），要求返回其中**第 `k` 小**的数。

注意是「第 k 小」而不是「第 k 个不同值」：重复出现的数字按出现次数分别计数。

### 示例

```text
输入：m = 3, n = 3, k = 5
输出：3
解释：3×3 乘法表的元素为
      1 2 3
      2 4 6
      3 6 9
     升序排列为 1,2,2,3,3,4,6,6,9，第 5 个数是 3。
```

```text
输入：m = 2, n = 3, k = 6
输出：6
解释：表为 1 2 3 / 2 4 6，升序为 1,2,2,3,4,6，第 6 个数是 6。
```

### 约束条件

- `1 <= m, n <= 3 * 10^4`
- `1 <= k <= m * n`

---

## 二、解题思路

### 核心思想

**不在「位置」上二分，而是在「值」上二分。** 把「第 k 小」改写成谓词判断：`count(x)` = 表中 `<= x` 的元素个数。`count` 关于 `x` 单调不减，于是答案就是**最小的满足 `count(x) >= k` 的 `x`**。

### 思路演进

1. **暴力解法**：把整张表算出来（`m * n` 个数），排序后取第 `k` 个。`m = n = 3 * 10^4` 时表里有 `9 * 10^8` 个数，光是存下来就已经不可行。或者用「每行单调」做 k 路归并，堆里维护 `min(m, n)` 个游标，只弹出前 `k` 个 —— 可行性上勉强成立，但 `k` 可以到 `m * n`，最坏等价于把整张表过一遍。

2. **观察到**：题目问的是「某个值排第几」，而不是「第 k 个位置的元素是谁」。**给定一个候选值 `x`，数出「不大于 x 的元素有几个」极其便宜** —— 第 `i` 行的元素是 `i, 2i, 3i, …, ni`，是等差数列，`<= x` 的个数直接是 `min(x // i, n)`，一次整除就能算，不需要真的枚举这一行。

   于是 `count(x) = Σ(i = 1..m) min(x // i, n)`，单次计算只要 O(m)。

3. **优化为**：`count(x)` 随 `x` 增大单调不减（`x` 变大，能数进来的元素只增不减）。这是一个标准的**单调谓词**，可以在值域 `[1, m * n]` 上二分：找**第一个**满足 `count(x) >= k` 的 `x`。

4. **正确性论证**（关键，不能省）：设二分结果为 `x*`，由「第一个满足」得

   ```text
   count(x* - 1) < k <= count(x*)
   ```

   这说明**在 `x*` 这个值上计数发生了增长**，即表中确实存在等于 `x*` 的元素（否则 `count(x*) = count(x* - 1)`）。既然 `x*` 真实出现在表里，且它之前的元素不足 `k` 个、算上它刚好够 `k` 个，那么 `x*` 就是第 `k` 小的数。

   这一步同时解决了**重复元素**问题：二分的是「值」而非「位置」，重复出现的数字被 `count` 按出现次数自然累加，不需要去重，也不会因为把某个值数了多遍而错位。

### 关键点

- **二分值域而不是二分下标** —— 这是「二分答案」的判别标志。答案空间是 `[1, m * n]` 这些**可能的值**，而不是某个数组的位置。
- **计数的 cap 不能省**：第 `i` 行只有 `n` 个元素，`x // i` 可能远大于 `n`，必须取 `min(x // i, n)`。
- **两个哨兵要保证口径一致**：`left = 0` 必然不满足（`k >= 1`），`right = m * n + 1` 必然满足（`count = m * n >= k`）。二分始终维持「`left` 不满足、`right` 满足」的不变式，收敛后 `right` 就是答案。
- **单调性是二分成立的全部前提**，本题的单调性来自「`x` 增大 ⇒ 满足 `i * j <= x` 的格子集合只扩不缩」，非常直观。

## 三、代码实现

### 最终代码

```python
class Solution:
    def findKthNumber(self, m: int, n: int, k: int) -> int:
        # 统计表中小于等于 t 的元素个数是否达到 k
        def check(t: int) -> bool:
            cnt = 0
            for i in range(1, m + 1):
                cnt += min(t // i, n)   # 第 i 行只有 n 个元素，必须 cap
                if cnt >= k:
                    return True
            return False

        # left 必然不满足（count(0) = 0 < k），right 必然满足（count(m*n+1) = m*n >= k）
        left = 0
        right = m * n + 1
        while left + 1 < right:
            mid = (left + right) // 2
            if check(mid):
                right = mid     # mid 已满足，答案可能是 mid 或更小
            else:
                left = mid      # mid 不满足，答案严格更大
        return right
```

## 四、复杂度分析

| 版本 | 时间复杂度 | 空间复杂度 |
| :--- | :--- | :--- |
| **最终代码** | O(m · log(mn)) | O(1) |
| 朴素解法（建表 + 排序） | O(mn · log(mn)) | O(mn) |
| 理论下界 | O(log(mn)) | O(1) |

> 复杂度中的 `m`、`n` 指：乘法表的两个维度（行数、列数）。`log(mn)` 是二分次数（值域大小 `m * n`），`m` 是每次 `check` 扫描的行数。

## 五、优化评估

**结论**：主项 `O(m · log(mn))` 已经是很成熟的形态，**但仍有一个免费的对数外因子可以削掉** —— 计数那一层的循环维度可以从 `m` 换成 `min(m, n)`。

### 瓶颈分析

时间几乎全部花在 `check` 里的那个 `for` 循环上，它被调用了 `O(log(mn))` 次。除此之外二分本身只是一些整数运算，可忽略。

空间上只用了 `left / right / mid / cnt` 几个整数，已是 O(1)，没有再压缩的余地。

### 可优化空间

计数结果对 `m`、`n` 是**对称**的：它数的是满足 `i * j <= x` 的格子数，把行列互换，同一个集合只是换了个遍历方向。所以当 `m > n` 时，先把两个参数交换，让**较小的那一维**去当循环上限、较大的那一维当 cap，结果完全一致。

这一步把每次 `check` 从 O(m) 降到 O(min(m, n))，整体从 `O(m · log(mn))` 降到 `O(min(m, n) · log(mn))`。本题 `m`、`n` 上界相同，所以最坏情况不变，但在「一维远大于另一维」的输入上能省下一个明显的因子。

### 优化代码

```python
class Solution:
    def findKthNumber(self, m: int, n: int, k: int) -> int:
        # 计数对 m、n 对称：让循环维度取较小的一维，cap 取较大的一维
        if m > n:
            m, n = n, m

        left, right = 0, m * n + 1
        while left + 1 < right:
            mid = (left + right) // 2
            cnt = 0
            for i in range(1, m + 1):
                cnt += min(mid // i, n)
                if cnt >= k:
                    break
            if cnt >= k:
                right = mid
            else:
                left = mid
        return right
```

**优化理由**：`count(x) = #{(i, j) : 1 <= i <= m, 1 <= j <= n, i * j <= x}` 在转置下不变，因此遍历行还是遍历列得到的和相同；选维度较小的方向枚举，纯赚不亏。

### 常数级优化（可选）

- **循环上限可以再收一收**：当 `i > mid` 时 `mid // i == 0`，这一行对 `cnt` 毫无贡献，可以直接跳出循环，不必空跑到 `m`。在 `mid` 较小时（二分前段）省下的迭代不少。
- **提前终止**：`cnt >= k` 就 `return True`（最终代码已包含），避免把剩下的行数完 —— 按值从小到大扫行时，靠前的行贡献最大，往往很早就越过 `k`。

## 六、易错点与总结

### 易错点

- **漏掉 `min(..., n)`**：第 `i` 行只有 `n` 个元素，直接写 `t // i` 会把根本不存在的 `i * (n + 1)`、`i * (n + 2)` … 也算进去，`cnt` 虚高 ⇒ 二分提前「满足」⇒ 答案偏小。这是本题最常见的错。
- **二分口径写反**：本题求的是「**第一个**满足 `count(x) >= k` 的 `x`」，所以命中时收紧的是 `right = mid`。若写成 `left = mid`（去求「最后一个不满足」再 +1），逻辑上也能做，但很容易和 `mid` 的取整方向配合错，差一位。
- **区间开闭与循环条件不配套**：最终代码用的是「双哨兵 + `left + 1 < right`」写法，好处是 `mid` 严格落在 `(left, right)` 内，`left = mid` 永远不会原地打转。换成 `while left <= right` 就必须重新推导，不能混搭。
- **误以为要去重**：「第 k 小」在重复元素上是按出现次数计的，不要去重；去重后语义完全变了。
- **值域上界取 `m * n` 而非 `m * n + 1`**：右哨兵必须取到「必然满足」，用 `m * n` 时 `check(m*n)` 恰好为真、答案可能就是它，一旦循环口径是 `left + 1 < right` 就会漏掉这个端点。加 1 当哨兵最省心。

### 题型套路沉淀

- **二分答案的四步模板**，本题是一个标准范例：
  1. 写出谓词 `check(x)`，并**证明它关于 x 单调**；
  2. 找出「必然不满足」的左哨兵与「必然满足」的右哨兵；
  3. 二分找**第一个满足**的值；
  4. **论证这个值是一个合法解**（本题靠 `count` 在 `x*` 处的跳变，说明表里真有这个数）—— 第 4 步经常被跳过，但它正是「二分出来的值不一定在答案集合里」这一隐患的唯一防线。
- **判定一道题能不能二分答案，看三件事**：谓词单调、单次 `check` 的代价可接受、答案落在可枚举的值域里。三条都满足就基本可以转成判定问题。
- **触发词**：「第 k 小 / 第 k 大」「最小的最大值」「最大的最小值」「至少需要多少」—— 出现这类问法时，优先想「能不能二分这个量，再用一个高效的判定函数收口」。
- **判定函数要尽量做到「数而不造」**：本题的 `min(x // i, n)` 用一次整除代替了枚举整行，这是把 O(mn) 压到 O(m) 的关键；类似的「等差数列 / 排序数组里数个数用除法」的手法在计数类判定里高频出现。
