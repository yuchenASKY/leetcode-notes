# 2563. 统计公平数对的数目

> **难度**：中等
> **标签**：数组 · 双指针 · 二分查找 · 排序
> **原题链接**：https://leetcode.cn/problems/count-the-number-of-fair-pairs/

---

## 一、题目描述

给定一个下标从 0 开始、长度为 `n` 的整数数组 `nums`，以及两个整数 `lower`、`upper`。若数对 `(i, j)` 满足

- `0 <= i < j < n`，且
- `lower <= nums[i] + nums[j] <= upper`

则称它是一个**公平数对**。返回公平数对的**数目**。

注意要求的是「和落在闭区间内」的**计数**，不要求返回下标，也不要求列出具体数对。

### 示例

```text
示例 1：
输入：nums = [0,1,7,4,4,5], lower = 3, upper = 6
输出：6
解释：共有 6 个公平数对：(0,3)、(0,4)、(0,5)、(1,3)、(1,4)、(1,5)

示例 2：
输入：nums = [1,7,9,2,5], lower = 11, upper = 11
输出：1
解释：只有单个公平数对：(2,3)，即 9 + 2 = 11
```

### 约束条件

- `2 <= nums.length <= 10^5`
- `-10^9 <= nums[i] <= 10^9`
- `-10^9 <= lower <= upper <= 10^9`

---

## 二、解题思路

### 核心思想

**排序之后，「和落在区间内」这件事就从「值域判断」变成了「下标是一段连续区间」。** 对每个 `x = nums[i]`，它的合法搭档是值在 `[lower - x, upper - x]` 内的元素；数组有序 ⇒ 这些元素正好排成连续的一段，用两次二分定位段的左右端点即可。

### 思路演进

1. **朴素解**：双重循环枚举所有数对，判断和是否落在 `[lower, upper]`。时间 O(n²)，空间 O(1)。`n = 10^5` 时约 `5×10^9` 次数对，不可能通过。

2. **瓶颈定位**：固定 `x = nums[i]` 时，内层做的事是「在数组里数有多少个 `y` 落在 `[lower - x, upper - x]`」—— 这是一个纯**计数查询**，却被线性扫描实现，把本该 O(log n) 的步骤做成了 O(n)。

3. **关键转化**：**排序**。数组一旦有序，「值落在某区间」与「下标落在某连续段」等价，计数查询退化成两次**边界定位**：
   - `bisect_right(a, upper - x)` = 值 `<= upper - x` 的元素个数（段右端点的「后一位」）；
   - `bisect_left(a, lower - x)` = 值 `< lower - x` 的元素个数（段左端点的「前一位」）；
   - 两者之差就是值落在 `[lower - x, upper - x]` 的元素个数。
   用一句话说清「为什么原来不行、现在为什么行」：**无序时区间查询只能扫，有序后区间查询变成下标作差。**

4. **最优解**：排序 O(n log n) + 对每个元素两次 O(log n) 的二分，总时间 O(n log n)。排序换来的是「每个元素一次 O(log n) 定位」，把整体的 `O(n²)` 压到 `O(n log n)`。

### 判据与判据族定位

本题的判据可以压成一条可判定真假的命题（`a` 为升序数组，下标从 0 开始）：

```text
#( j < i 且 lower <= a[j] + a[i] <= upper )
    = bisect_right(a, upper - a[i], 0, i) - bisect_left(a, lower - a[i], 0, i)
```

- **上界用 `bisect_right`（闭）、下界用 `bisect_left`（开）**，一闭一开才能把「恰好等于边界」的元素算进来且不算重。这两个函数选错方向必错，见「六、易错点」的实测最小反例。
- **二分区间固定为 `[0, i)`**，即只在「当前元素之前的前缀」里数。这是把 `i < j` 转化为「有序数组的下标先后」之后，保证每个数对**恰好被数一次**的关键；省掉它会让答案直接错（见易错点实测）。

**判据族定位**：本题属「**有序序列上的区间计数**」—— 排序是前提，判据是「两个边界定位之差」。同族里另有「**单边界（后缀）计数**」形态：当条件只有一侧（如「和 `>=` 某个阈值」）时判据退化成 `n - bisect_left(a, 阈值)`，只数一段后缀。本题条件天然是双边的 `[lower - x, upper - x]`，所以是「区间型」而不是「后缀型」，**两族不要串用**（后缀型拿来套双边条件会漏掉上界那一侧）。此外，本题不能走「值域桶 + 前缀和」那条消掉 log 的路线 —— `nums[i]` 值域达 `±10^9`，桶的规模远大于 `n`（这条判据的适用条件见 §五）。

### 关键点

- **排序不损失答案**：题目只问对数、不问下标，而「哪两个数相加落在区间内」在排序前后不变（多重集不变）。这是能排序的前提；若题目要求返回原始下标，就必须先记录下标，排序的用法要改。
- **`j < i` 用二分区间 `[0, i)` 表达**：天然去重，**不需要**「数两遍再除以 2」，也不需要处理自配对。
- **`lower - x` / `upper - x` 可能超出 32 位**（`lower` 下探 `-10^9`、`x` 接近 `10^9`），Python 无整数溢出问题；换 C++ 必须用 `long long`。
- **答案本身可能超出 32 位**：`n = 10^5` 且全为 `0`、`lower <= 0 <= upper` 时答案 = `n(n-1)/2 = 4 999 950 000 > 2^31 - 1`，返回类型必须能装下 64 位。

## 三、代码实现

### 最终代码

```python
from bisect import bisect_left, bisect_right
from typing import List


class Solution:
    def countFairPairs(self, nums: List[int], lower: int, upper: int) -> int:
        nums.sort()
        ans = 0
        for i, x in enumerate(nums):
            r = bisect_right(nums, upper - x, 0, i)   # 值 <= upper - x 的个数（前缀内）
            l = bisect_left(nums, lower - x, 0, i)    # 值 <  lower - x 的个数（前缀内）
            ans += r - l                              # 值落在 [lower-x, upper-x] 的个数
        return ans
```

> 截图里只有 `class Solution:`，`from bisect import ...` 与 `from typing import List` 是**补全**（让笔记里的代码可直接运行），逻辑与截图一致。截图末尾即 `return ans`（编辑器显示共 9 行），**没有截断**，无需按缩进补全。

## 五、优化评估

**结论**：**渐进复杂度已是最优**（比较排序下界 Ω(n log n)，本题无可用的小值域，桶路线出局），但**常数仍有约 1.6× 的空间** —— 把「每个元素两次二分」换成「两趟两指针」，实测端到端 **0.600×（快 1.67×）**。

### 瓶颈分析

在同一次运行内做阶段归因（n = 10^5，9 轮轮转取最优，各目标在同一轮内轮转测量）：

| 计时对象 | 耗时 | 相对 A 端到端 |
| :--- | ---: | ---: |
| A 端到端（排序 + n 次双二分） | 50.139 ms | 1.000× |
| B 端到端（排序 + 两趟两指针） | 30.066 ms | 0.600× |
| 阶段：排序 `sorted(src)` | 12.448 ms | 0.248× |
| 阶段：A 的 n 次双二分循环 | 37.405 ms | 0.746× |
| 阶段：B 的两趟两指针循环 | 17.654 ms | 0.352× |

两条读数的自洽性：`12.448 + 37.405 = 49.853 ≈ 50.139`、`12.448 + 17.654 = 30.102 ≈ 30.066`，阶段之和与端到端吻合在 1% 以内（阶段各自的「最优值」不能严格相加，`min(a)+min(b) >= min(a+b)`，本次吻合说明读数没被噪声污染）。

由此可读出的结论：

1. **A 路线 74.6% 的时间花在那 n 次双二分上**，排序只占 24.8%。
2. A 路线的**可去成本 = A 循环 − B 循环 = 19.751 ms**，占 A 端到端 **39.4%** ⇒ 单改动天花板 `1/(1−0.394) ≈ 1.65×`，实测 `1/0.600 = 1.67×`，**几乎吃满**。
3. 剩下的是排序（B 路线里占 `12.448/30.066 = 41.4%`）—— 不可去：`nums[i]` 值域 `±10^9`，「值域桶 + 前缀和」的固定成本与值域上界绑死，桶的轮数（约 `2×10^9` 级）远超 n，直接出局。

### 可优化空间

把「对每个元素查一次」换成「整趟扫描一次」，用**两指针**数出「和 `<= X` 的无序数对个数」，再用两次调用做差分：

```text
#(lower <= a[i] + a[j] <= upper) = f(upper) - f(lower - 1)
其中 f(X) = #(数对 (i, j), i < j, a[i] + a[j] <= X)
```

`f(X)` 在有序数组上可以 O(n) 双指针求得（`lo=0, hi=n-1`：若 `a[lo] + a[hi] <= X`，则 `lo` 与 `(lo, hi]` 内每个元素都合法，一次加上 `hi - lo` 个后 `lo += 1`；否则 `hi -= 1`）。差分能成立是因为 `a` 的值都是整数 ⇒ `sum < lower` 与 `sum <= lower - 1` 等价（**这条等价只依赖整数性**，与值域是否连续、是否有空隙无关）。

时间 O(n log n)（排序主导）+ O(n) 两趟扫描，空间 O(1)（除排序缓冲外不额外开数组）。

### 优化代码

```python
from typing import List


class Solution:
    def countFairPairs(self, nums: List[int], lower: int, upper: int) -> int:
        a = sorted(nums)
        n = len(a)

        def count_le(X: int) -> int:
            """有序数组 a 中，和 <= X 的无序数对 (i, j), i < j 的个数"""
            lo, hi, cnt = 0, n - 1, 0
            while lo < hi:
                if a[lo] + a[hi] <= X:
                    cnt += hi - lo      # (lo, k) 对 k in (lo, hi] 全部合法
                    lo += 1
                else:
                    hi -= 1             # a[hi] 太大，与谁都配不上，丢弃
            return cnt

        return count_le(upper) - count_le(lower - 1)
```

**优化理由**：A 版对每个元素都要进一次二分（每轮两次 C 层调用，共 2n 次），单次调用虽只有几十纳秒，但被 `n = 10^5` 放大成 37 ms；B 版把 `2n` 次二分调用换成两趟各 O(n) 的**纯指针移动**，循环体只有一次加法和比较，总迭代次数同为 2n 量级但每次更便宜。整体仍受排序主导 —— 所以这是**常数优化**，不是渐进优化。

### 常数级优化（实测结果）

**被测伪的改法**：把 `bisect_right` / `bisect_left` 绑定成局部变量再调用（减少全局名查找）：

```python
br, bl = bisect_right, bisect_left
for i, x in enumerate(nums):
    ans += br(nums, upper - x, 0, i) - bl(nums, lower - x, 0, i)
```

实测 **A2/A = 0.969× / 0.989× / 1.022× / 0.990×（四档跨过 1.0）**，落在噪声内 ⇒ **无有效收益**。这与本仓库在 `05-binary-search` 上已有的记录方向一致：二分的耗时几乎全在 C 层 `_bisect` 里，Python 层只有两条路可动 ——「减少 C 层调用次数」与「换掉查表方式」；单纯做名字绑定属于第三条，本仓库至今全是反向或噪声结论。

## 六、易错点与总结

### 易错点

- **忘记把二分限制在 `[0, i)`，直接在全数组上数** —— 后果最严重的一个。排序后全数组计数会把每个数对数两遍，还会把 `nums[i]` 自己配给自己。实测（40 组随机、n ≤ 20）：**38/40 组出错**；最小反例 `nums = [-2, -2], lower = upper = -4`：真值 **1**、实得 **4**（两对重复 + 一个自配对）。
- **上界/下界的开闭选反**（上界用 `bisect_left`、下界用 `bisect_right`）—— 会漏掉恰好等于边界的元素，并且因差值变小而可能得到**负数**。实测 40 组错 **21** 组；最小反例同样是 `nums = [-2, -2], lower = upper = -4`：真值 **1**、实得 **-1**。⇒ 又一次印证本仓库的经验：**答案出现负数就是口径/判据写错的信号**，正常解的计数不可能为负。
- **`lower - 1` 那一步在非整数场景会失效**：`f(upper) - f(lower - 1)` 依赖「值都是整数」；若数组是浮点，必须改成 `f(upper) - f(lower - eps)` 或直接单次双窗口，否则会漏掉 `sum` 恰为 `lower` 的浮点数对之间不存在的「空隙」。本题是整数题，安全。
- **返回值溢出（C++/Java）**：`n = 10^5`、全 `0`、`lower <= 0 <= upper` 时答案是 `4 999 950 000`，`int` 装不下；Python 无此问题，但迁移语言时要留意。
- **把排序用在「要求返回原下标」的题上**：本题不要求下标所以可以直接排序；如果题目要求输出数对而非计数，排序后必须把下标一起带上，否则原下标丢失。

### 题型套路沉淀

- **排序 + 区间计数**（本题主线）：`bisect_right(上界) - bisect_left(下界)`，上界闭、下界开。凡是「数有多少对数满足和落在某区间」的题，都先想「排序后能不能变成两次边界定位」。
- **双指针差分**：`f(upper) - f(lower - 1)`，其中 `f(X)` = 和 `<= X` 的无序对个数，用一趟双指针 O(n) 求出。双边条件拆成两个单边条件相减，是本族最常用的降复杂手段 —— 前提是被计数的值都是整数。
- **计数型的 64 位意识**：`n ≤ 10^5` 的量级下，答案上限 `n(n-1)/2 ≈ 5×10^9` 已经越过 32 位；写 C++/Java 时返回值一律用 64 位。
- **两条路线的选择**：同样 O(n log n)，`2n` 次 C 层 `bisect` 调用 vs 两趟 Python 层指针移动 —— 本题实测后者更快（0.600×），但这个结论**依赖「两趟扫描只做加法与比较」**；如果两指针前还需要额外排序或按值建对象，常数优势可能反转（见本仓库在同类题上的记录）。

- 分档依据：本题二分的迭代次数只由 n 决定（与数据分布无关），但**双指针的循环次数与数据分布有关**，故额外补了「高重复档」，确认优化方向在该档不退化为反向结论。
