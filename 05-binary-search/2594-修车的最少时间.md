# 2594. 修车的最少时间

> **难度**：中等
> **标签**：二分 · 数组
> **原题链接**：https://leetcode.cn/problems/minimum-time-to-repair-cars/

---

## 一、题目描述

有若干个机械工，第 `i` 位的能力值为 `ranks[i]`。能力值为 `r` 的机械工修好 `n` 辆车需要 `r * n²` 分钟（修得越多越慢，是平方关系）。所有机械工**可以同时开工**，问修完总共 `cars` 辆车**最少**需要多少时间。

### 示例

```text
输入：ranks = [4,2,3,1], cars = 10
输出：16
解释：
- 第一位机械工修 2 辆车，需要 4 * 2 * 2 = 16 分钟。
- 第二位机械工修 2 辆车，需要 2 * 2 * 2 = 8 分钟。
- 第三位机械工修 2 辆车，需要 3 * 2 * 2 = 12 分钟。
- 第四位机械工修 4 辆车，需要 1 * 4 * 4 = 16 分钟。
16 分钟是修理完所有车需要的最少时间。

输入：ranks = [5,1,8], cars = 6
输出：16
```

### 约束条件

- `1 <= ranks.length <= 10^5`
- `1 <= ranks[i] <= 100`
- `1 <= cars <= 10^6`

## 二、解题思路

### 核心思想

**不枚举「谁修几辆车」，而是二分「总时间 T」**：给定 T，每位机械工最多能修 `isqrt(T // r)` 辆，「所有工人总能力是否 ≥ cars」关于 T 单调不降 —— 于是求最小可行 T 就是一个二分答案。

### 思路演进

1. **暴力解法**：直接枚举分配方案 —— 每位机械工分到几辆车（`x_0 + x_1 + ... + x_{n-1} = cars`），取 `max(r_i * x_i²)` 的最小值。方案数是 `C(cars + n - 1, n - 1)` 级别，`n` 到 10^5、`cars` 到 10^6，组合爆炸，完全不可行。**问题的形态本身就不适合枚举答案的「分配」**。

2. **观察到**：题目的问法是「最少需要多少时间」，而这类问法常常可以把**答案本身当作搜索变量**。关键在于：给定一个时间 T，判断「T 分钟够不够修完所有车」是**容易**的 ——
   - 每位机械工在 T 分钟内能修的车上限是满足 `r * n² <= T` 的最大整数 `n`，即 `n = isqrt(T // r)`；
   - 把所有机械工的上限加起来，若 `sum >= cars`，说明 T 够用；否则不够用。
   - 而且这个「够不够」**关于 T 单调**：T 越大，每位工人的上限只增不减，`sum` 单调不降，所以判定结果是 `假 假 … 假 真 真 … 真` 的形态。

3. **优化为**：在 T 的取值区间上二分，找**第一个判定为真**的 T。取值下界取 `0`（一定不可行，因为 `cars >= 1`），上界取 `min(ranks) * cars * cars`（让能力值最小的那位**独自**修完所有车，这是一个一定可行的构造）。每轮判定 O(n)，总耗时 O(n log U)。

### 关键点

- **判定函数不需要真的构造分配方案**。每位机械工能修的车辆数是 `0, 1, ..., k_i` 中任意一个值（区间），若干个区间的和集就是 `0 .. sum(k_i)` 的完整连续区间 —— 因此「总能力 ≥ cars」**当且仅当**存在一种合法分配。这就是判定只需要数数、不需要分车的依据。
- **整数开方必须用 `isqrt`，不能用 `sqrt` 再取整**：`r * n² <= T` 等价于 `n <= sqrt(T / r)` 的下取整，写成 `isqrt(T // r)` 才精确；浮点 `sqrt` 在 T 达到 10^12~10^14 量级时可能在边界上差一辆车，直接翻转判定结果。
- **二分不变量要明确**：始终保证 `left` 不可行、`right` 可行，循环条件 `left + 1 < right`，终止时两指针相邻，答案就是 `right`（第一个可行值）。返回 `left` 会得到「最大的不可行值」，差一个单位。
- **上界必须可行**：`min(ranks) * cars * cars` 是「能力值最小的机械工一个人干完全部活」的时间，一定是可行解；若贪图小上界（如 `min(ranks) * cars`）则右端可能不可行，二分假设被破坏，答案会偏小。
- 数据范围上界 `min(ranks) * cars² <= 100 * 10^12 = 10^14`，Python 无整数溢出问题；二分约 47 轮，配合 O(n) 判定在限制内很宽松。

## 三、代码实现

### 最终代码

```python
from math import isqrt        # 截图里没有、已补
from typing import List       # 截图里没有、已补


class Solution:
    def repairCars(self, ranks: List[int], cars: int) -> int:
        def helper(mid):
            ans = 0
            for i in ranks:
                ans += isqrt(mid // i)   # i * n^2 <= mid  =>  n <= isqrt(mid // i)
            return ans

        left = 0
        right = min(ranks) * cars * cars   # 速度最快的那位独自修完所有车，一定可行
        while left + 1 < right:            # 不变量：left 不可行，right 可行
            mid = (left + right) // 2
            if helper(mid) >= cars:        # mid 分钟够用 -> 收缩右端
                right = mid
            else:
                left = mid                 # 不够用 -> 抬高左端
        return right                       # 第一个可行值
```

## 五、易错点与总结

### 易错点

- **用 `sqrt` 代替 `isqrt`**：`int(sqrt(T / r))` 在 T 很大时会因浮点误差在边界差 1，判定翻车。用整数除法 + `isqrt`。
- **二分上界选得不可行**：右端必须是真解的上界。`min(ranks) * cars * cars` 是安全构造；写成 `min(ranks) * cars` 之类会漏解。
- **单调方向写反**：`helper(mid) >= cars` 表示「够用」，此时要**收缩右端**去找更小的时间；反了会返回极大的值。
- **返回值取错**：左指针停在「不可行」的一侧，答案是右指针。
- **判定条件写成 `== cars`**：总能力超过 cars 也算够用（多出来的车不必修），必须是 `>=`。
- C++ / Java 实现时 `min(ranks) * cars * cars` 会超出 `int`，需用 `long long`（本题 Python 无此问题）。

### 题型套路沉淀

- **「最少需要多少时间 / 多少天 / 最小的最大值」⇒ 二分答案**。识别特征：题目直接问一个最小（或最大）的数值 X，而**给定 X 后能 O(n) 判断「可不可行」**，且这个判断关于 X 单调。
- 二分答案的三件套，按顺序检查：
  1. **判定函数**单调（本题 `helper(T)` 单调不降）；
  2. **值域**：左端点取一个确定不可行的值，右端点取一个确定可行的构造值；
  3. **不变量式模板**：`while left + 1 < right`，左不可行右可行，返回第一个可行值。
- **判定只需数总量、不必构造方案**：当每个单位（机械工 / 天数 / 箱子）的产出可以取 `0..k_i` 的**任意整数**时，总量可达性是连续区间，故「总能力 ≥ 需求」与「存在合法分配」等价。这类"并行资源分配求最短工期"的题基本都能这么处理。
- 同型思路：把「优化分配」的难题反过来做成「给定答案判可行性」的简单题。
