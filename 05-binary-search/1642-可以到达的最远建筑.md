# 1642. 可以到达的最远建筑

> **难度**：中等
> **标签**：数组 · 二分 · 贪心
> **原题链接**：https://leetcode.cn/problems/furthest-building-you-can-reach/

---

## 一、题目描述

给定数组 `heights` 表示一排建筑的高度，从下标 `0` 出发依次向后移动。从建筑 `i` 走到 `i+1` 时：

- 若 `heights[i] >= heights[i+1]`（下坡或平路），**不消耗**任何资源；
- 若 `heights[i] < heights[i+1]`（上坡），必须二选一：消耗**一架梯子**，或消耗 `heights[i+1] - heights[i]` 块**砖块**。

梯子与砖块可以自由分配到任意一个上坡处。求在最优分配下**能够到达的最远建筑下标**（下标从 0 开始）。

### 示例

```text
输入：heights = [4,2,7,6,9,14,12], bricks = 5, ladders = 1
输出：4
解释：
- 0 → 1：4 >= 2，不消耗
- 1 → 2：2 < 7，用 5 块砖
- 2 → 3：7 >= 6，不消耗
- 3 → 4：6 < 9，用掉唯一的梯子
- 4 → 5：9 < 14，砖和梯子都已用尽，无法继续
```

```text
输入：heights = [4,12,2,7,3,18,20,3,19], bricks = 10, ladders = 2
输出：7
```

```text
输入：heights = [14,3,19,3], bricks = 17, ladders = 0
输出：3
```

### 约束条件

- `1 <= heights.length <= 10^5`
- `1 <= heights[i] <= 10^6`
- `0 <= bricks <= 10^9`
- `0 <= ladders <= heights.length`

## 二、解题思路

### 核心思想

**把「能走到哪」转成对终点的可行性判定，而「走到第 m 栋要花多少砖」有闭式答案 —— 判定单调，于是可以二分答案。**

具体地，记第 `i` 步的价格 `p_i = max(0, heights[i] - heights[i-1])`（走一步必须付出砖 `p_i` 或梯子 `1`），则

```
走到 m 所需的最少砖数 need(m) = Σ_{i=1..m} p_i  −  ( p 中最大的 min(ladders, 正价格个数) 项之和 )
```

### 思路演进

1. **暴力解法**：枚举终点 `m = 0, 1, ..., n-1`，对每个 `m` 重新决定「哪些上坡用梯子、哪些用砖」。想都不用想的局部贪心（"能用砖就用砖，梯子省着"）是错的：梯子应该留给**最大的**落差，一旦前面对小落差用了梯子，后面遇到大落差时就会不够。做对的话每个 `m` 要对前缀重新分配资源，整体到 O(n²) 甚至更高。
2. **观察到**：这题有两个关键结构。
   - 每一步的"价格"只由落差决定，与用哪种资源无关；下坡/平路价格是 0，直接忽略即可 —— 于是每一步都能统一写成非负价格 `p_i`。
   - **梯子是一张"万能抵扣券"**：不管落差多大，一架梯子都能顶掉它。既然梯子不挑大小，就应该把它花在**最贵的**几步上。用交换论证可以证明：若某方案对价格 `a < b` 的两步分别用了梯子、砖块，把两者对调后砖消耗从 `b` 降到 `a`，不会变差。所以最优分配必然是「梯子覆盖前 `ladders` 大的价格，砖块覆盖其余」。
3. **优化为**：`need(m)` 因此有了闭式：前缀价格总和，减去其中最大的 `min(ladders, 正价格个数)` 项。而且 `need(m)` 关于 `m` **单调不减**（从 `m` 到 `m+1` 只多了一个非负价格 `p_{m+1}`，而梯子能抵扣的部分最多增加 `p_{m+1}`），于是「能否到达」这个谓词是单调的 —— 这就是二分的入场券：在 `[0, n-1]` 上二分**最后一个**满足 `need(m) <= bricks` 的 `m`。

> 注意"能到达 `m`"与"`need(m) <= bricks`"是等价的：只要砖够，梯子必然够（梯子数已经体现在 `need` 里），所以判定只需一个不等式。

### 关键点

- **统一下坡与平路**：`p_i = max(0, h[i] - h[i-1])`，把"不需要资源"吸收成"价格 0"，后面所有推理都只处理非负价格。
- **梯子的分配是本题的灵魂**：必须"顶掉最大的几个价格"，而不是"随便用"。这一步一旦做对，判定就从「模拟」变成「排序 + 前缀和」。
- **单调性决定了它属于二分答案**：不是"在有序数组里找值"，而是"谓词在答案轴上单调"，是二分答案的典型形态（与"最小化最大值 / 最大化最小值"同源）。
- **判定函数里要同时卡两层资源**：砖的总量（求和）和梯子的个数（前缀取几项）。只看总落差不够 —— 例如总落差很小但上坡次数多于梯子数时，仍可能不够。
- **边界**：答案下界恒为 `0`（最差也能站在第 0 栋），所以二分下界必须取 `0` 这个"确实可行"的点；上界取 `n`（开区间）或 `n-1`（闭区间）要写一致。本题代码用 `left = 0, right = n` + `while left + 1 < right` 的"左闭右开"写法返回 `left`，天然包含 `0`。
- **判定式里 `ladders >= mid` 的短路不能省**：它既表达"上坡数都不超过梯子数 ⇒ 全部用梯子 ⇒ 砖消耗为 0"的捷径，也顺手挡住了 `bricks_cost_sort[-i]` 在 `i > 列表长度` 时的越界异常。

## 三、代码实现

### 最终代码

```python
class Solution:
    def furthestBuilding(self, heights: list[int], bricks: int, ladders: int) -> int:
        n = len(heights)
        if n == 1:
            return 0
        bricks_cost = [0] * n
        for i in range(1, n):
            bc = heights[i] - heights[i - 1]
            if bc > 0:
                bricks_cost[i] = bc

        left = 0
        right = n
        while left + 1 < right:
            mid = (left + right) // 2
            bricks_cost_sort = sorted(bricks_cost[: mid + 1])
            if ladders >= mid or sum(bricks_cost_sort) - sum(bricks_cost_sort[-1 * i] for i in range(1, ladders + 1)) <= bricks:
                left = mid
            else:
                right = mid
        return left
```

> 代码为已提交通过的版本，未做改写。它只用到内置的 `sorted` / `sum`，**不需要任何 import**（也就没有需要补的导入）。`bricks_cost[0]` 恒为 `0`（第 0 栋没有来路），这个占位元素排序后落在最小端，正好被"砖块买最便宜的那些"吸收掉，不影响判定结果。

## 四、复杂度分析

| 版本 | 时间复杂度 | 空间复杂度 |
| :--- | :--- | :--- |
| **最终代码** | O(n log² n) | O(n) |
| 朴素解法（枚举终点 + 每个前缀重新排序） | O(n² log n) | O(n) |
| 理论下界 | O(n log n) | O(n) |

> 复杂度中的 n 指 `heights` 的长度（建筑数量）。

最终代码的时间由两部分构成：外层二分只有 O(log n) 轮，而每一轮的判定要对一个长度不超过 `mid + 1` 的前缀 `sorted`，单轮 O(n log n)，相乘即 O(n log² n)。空间是 `bricks_cost` 数组 O(n)，加上每轮排序产生的切片副本 O(n)，同阶。

## 五、优化评估

**结论**：思路（二分答案）正确且判定式简洁，但**实现上把"每轮的判定"做成了独立的重算**，没有利用「从 m 到 m+1 只多一个价格」的增量结构，因此时间上比本题的经典做法高一个 log。

### 瓶颈分析

时间花在两处：

- **每轮判定都重新排序整个前缀**。二分一共 O(log n) 轮、每轮 `sorted` 长度约 `n/2` 的前缀，上一轮排好的顺序在下一轮完全用不上 —— 这是"二分答案 + 每轮从头重算"的固有代价。
- **判定式里的两次求和**。`sum(bricks_cost_sort) - sum(bricks_cost_sort[-1 * i] for i in range(1, ladders + 1))` 把整段求了两遍和，其中后一项还是 Python 层的生成器循环（长度 `ladders`），开销比库函数大。等价的写法是 `sum(bricks_cost_sort[: len - ladders])` 或一次遍历，大 O 不变但常数更小。

空间上，`bricks_cost` 数组其实可以省掉 —— 判定时按需现算相邻差即可；不过真正省空间的路线（下面这种）需要堆，仍然是 O(n)。

### 可优化空间

"能否到达 `m`" 本身具备**增量结构**：`m → m+1` 只新增一个价格，之前的分配方案基本可以沿用。把这层结构用起来，就可以放弃二分，改成**从左到右一次扫描 + 反悔贪心**：

- 维护一个大根堆，堆里是"当前决定用砖支付的那些落差"；
- 每遇到一个正落差 `d`，先假设用砖（入堆、砖数减 `d`）；
- 若砖数变成负数，就**反悔**：把堆中最大的落差弹出来改用梯子（砖数加回该值、梯子数减 1）；梯子也用完则说明这一步过不去，答案就是 `i`。

这样只扫一遍、每次堆操作 O(log n)，整体 O(n log n)，也是本题的理论下界量级。

### 优化代码

```python
import heapq

class Solution:
    def furthestBuilding(self, heights: list[int], bricks: int, ladders: int) -> int:
        heap = []                       # 大根堆（存负数）：当前用砖支付的落差
        for i in range(len(heights) - 1):
            d = heights[i + 1] - heights[i]
            if d <= 0:
                continue                # 下坡/平路不消耗
            heapq.heappush(heap, -d)
            bricks -= d                 # 先假设用砖
            if bricks < 0:              # 砖不够 → 反悔
                if ladders == 0:
                    return i            # 梯子也没了，只能停在第 i 栋
                bricks -= heapq.heappop(heap)   # 堆存的是负数，等价于 bricks += 最大落差
                ladders -= 1
        return len(heights) - 1
```

**优化理由**：它把"每轮重新决定整段前缀怎么分配"换成了"每步只做一次局部反悔"，用堆顶保证任何时候被换成梯子的都是当前最大的落差，等价于梯子始终覆盖最贵的几步 —— 与二分答案里的贪心判据完全一致，但省掉了重复排序。

### 常数级优化（可选）

- 判定式改成"先算总代价，再减去被梯子抵扣的部分"的**单次遍历**形式（见上），避免对同一段求两遍和。
- `sum(... for i in range(...))` 这类生成器求和，可以换成对切片的 `sum()`（C 层实现）或 `heapq.nlargest`，大 O 不变、常数更小。
- 因为 `bricks_cost` 只有正价格非零，二分时按 `p` 的非零项个数（即上坡次数）而不是 `mid` 来卡梯子数，可以少算无效项。

## 六、易错点与总结

### 易错点

- **只盯着一个资源**：砖的总量和梯子的个数是两个独立约束，必须同时满足。只看"总落差够不够"会漏掉"上坡次数多于梯子数"的情况，反之亦然。
- **梯子的贪心方向搞反**："能不用梯子就不用"是错的。梯子不挑落差大小，把它用在小的落差上等于浪费；正确方向是**梯子始终覆盖最大的几个落差**，砖块去买便宜的那些。
- **单调性方向写反**：`need(m)` 随 `m` 单调**不减**，所以合法区间是"左边一片可行、右边一片不可行"，二分要找**最后一个**可行的 `m`（不是第一个）。
- **二分的下界没取到"确实可行"的点**：下界必须取到答案的合法最小值（这里是 `0`），否则会漏掉"一栋都走不了、答案为 0"的情形。
- **判定式越界**：`bricks_cost_sort[-i]` 只在 `i <= 列表长度` 时合法；去掉 `ladders >= mid` 的短路后，`ladders` 偏大时直接 IndexError。
- **前缀里混进占位元素**：`bricks_cost[0] = 0` 是必要的占位（让下标与建筑对齐），排序后它会落在最小端并被自然吸收，但心里要清楚它不参与真实消耗。
- **`n == 1` 的边界**：只有一个建筑时直接返回 0；虽然循环本身也不会出错（`left = 0, right = 1` 不进入循环，返回 0），但显式写出来更清楚。

### 题型套路沉淀

- **二分答案四步模板**（"最大化可行 / 最小化可行"通用）：
  1. 写判定函数 `ok(x)` —— 不是"查是否存在"，而是"这个 x 到底行不行"；
  2. **证明单调性**（本题：能到 `m` ⇒ 能到所有 `< m` 的点）；
  3. 定边界 —— 下界取一个"确实可行"的点，上界取一个"确实不可行"的点或开区间端点；
  4. 用固定的收敛写法（如 `while left + 1 < right`，返回 `left`）取最后一个 `true`。
- **"每步二选一资源"的闭式判定**：当一步必须选 A 或 B、且 A 是"万能抵扣"时，先用**交换论证**证明 A 该花在最贵的几步上，判定式就能从"模拟"降成"排序 + 前缀和"。
- **识别信号**：凡是"能不能走到第 k 个位置""前 k 个元素最多能承受多少""最短需要多少时间/容量"这类问法，先想能不能二分答案配一个闭式判定；若发现"k → k+1 只增量地多一个元素"，再考虑放弃二分、改成一次扫描 + 堆/前缀结构。
