# 475. 供暖器

> **难度**：中等
> **标签**：二分 · 数组 · 排序
> **原题链接**：https://leetcode.cn/problems/heaters/

---

## 一、题目描述

房屋和供暖器都位于同一条水平线上，给出它们各自的位置坐标。所有供暖器共用同一个固定的加热半径 `r`，位置落在这个半径内的房屋才算取到暖。要求找出能覆盖**所有**房屋的最小半径。

### 示例

```text
输入：houses = [1,2,3], heaters = [2]
输出：1
解释：仅位置 2 有一个供暖器，半径取 1 即可覆盖 1 和 3。

输入：houses = [1,2,3,4], heaters = [1,4]
输出：1
解释：两个供暖器分别覆盖左侧与右侧两户，半径取 1 已足够。

输入：houses = [1,5], heaters = [2]
输出：3
解释：1 距供暖器 1 个单位、5 距供暖器 3 个单位，取最大值 3。
```

### 约束条件

- `1 <= houses.length, heaters.length <= 3 * 10^4`
- `1 <= houses[i], heaters[i] <= 10^9`

---

## 二、解题思路

### 核心思想

**答案本身具有单调性，于是把「求最小半径」改写成对一个判定问题的二分。** 半径 `r` 够用 ⇒ 任何更大的半径也够用，所以可行半径构成一个后缀 `[ans, +∞)`；只要能在 O(n + m) 内判断「半径 r 能否覆盖全部房屋」，就能二分出这个后缀的起点。

### 思路演进

1. **暴力解法**：对每个房屋，扫一遍所有供暖器求出最近距离，答案就是这些距离的最大值。时间是 O(n·m)，n = m = 3×10⁴ 时约 9×10⁸ 次比较，必然超时。

2. **观察到（另一条可行路线）**：上面慢在内层那趟线性扫描。把 `heaters` 排序后，每个房屋的最近供暖器可以直接二分查出来（`bisect`），答案 = 这些最近距离的最大值，时间降到 O((n + m) log m)。这条路已经能过 —— 它的视角是「**逐点求出答案，再取最大**」。

3. **换个视角（本题解法）**：与其直接算答案，不如**先判断一个半径行不行**。半径 `r` 的可行与否满足单调性 —— 半径调大，覆盖范围只增不减，原本能覆盖的房屋不会反而失去供暖。于是可行域形如

   ```text
   r:   0    1    2    3    4    5  ...
   check(r):  F    F    F    T    T    T
   ```

   任务是找第一个 `T`。这就是标准的**二分答案**：先把「求最小」化成「判可行」，再在候选值域上二分。

4. **判定函数怎么写**：暴力判定仍是 O(n·m)，不划算。注意到 `houses` 与 `heaters` 都排好序后，**随着房屋从左往右扫，能覆盖它的那个供暖器下标只会单调右移，永远不用回退**。于是用一个不回退的指针 `j` 维护「最靠左的、有可能够到当前房屋的供暖器」：够不到就把 `j` 往右推，推开到第一个刚好够得着的；若它离得太远、或者右边已经没有供暖器了，就说明这个房屋没人管，判定失败。`j` 全程最多移动 m 次，加上遍历房屋的 n 次，单次判定是 O(n + m)。

   总复杂度：O((n + m) log V)，`V` 为半径上界。

### 关键点

- **单调性是二分答案的前提**。这里的谓词是「若 `r` 可行，则 `r + 1` 也可行」，严格成立，所以可以二分找左边界。任何不具单调性的条件（例如「恰好」某个供暖器覆盖）都不能这样二分。

- **二分用开区间写法**：`left = -1` 侧保证恒假、`right` 侧保证恒真，`while left + 1 < right` 退出时 `right` 就是第一个可行值。
  - 左端点取 `-1`：位置坐标都是正数，半径 `-1` 覆盖不了任何房屋，所以 `check(left)` 必定为假，不会把界的左侧误取成可行值。
  - 右端点取 `max(max(heaters), max(houses))`：半径取到这个值时，任何一个供暖器都能罩住任何一个房屋，所有房屋位于 `[0, 上界]` 之内 ⇒ `check(right)` 必定为真，答案一定落在区间内。

- **覆盖口径是闭区间**，即 `|houses[i] - heaters[j]| <= r` 算作覆盖，写成 `heaters[j] - r <= houses[i] <= heaters[j] + r`。因此「够不着」的右移条件必须用**严格大于**：只有 `houses[i] > heaters[j] + r` 时才需要继续往右找。

- **指针不回退的依据是两数组都有序**：`houses[i]` 单增 ⇒ 「能覆盖 `houses[i]` 的最左侧供暖器下标」单增。若把 `j = 0` 写进房屋循环体内，判定就退化回 O(n·m)，外层再乘 log V 反而更慢。

- **越界保护要在解引用之前**：`while` 停下来时 `j` 可能正好等于 m（右侧供暖器全部够不着当前房屋），此时访问 `heaters[j]` 会下标越界。

## 三、代码实现

### 最终代码

```python
class Solution:
    def findRadius(self, houses: list[int], heaters: list[int]) -> int:
        n = len(houses)
        m = len(heaters)
        houses.sort()
        heaters.sort()

        # 判定：半径为 mid 时，能否覆盖全部房屋
        def helper(mid):
            j = 0                              # 候选供暖器下标，整个判定过程中只向右移动
            for i in range(n):
                # 当前供暖器够不到 houses[i]，往右找；注意是严格大于（闭区间口径）
                while j < m and houses[i] > heaters[j] + mid:
                    j += 1
                # j 未越界，且 houses[i] 落在第 j 个供暖器的闭区间内 ⇒ 这户有暖
                if j < m and heaters[j] - mid <= houses[i] and houses[i] <= heaters[j] + mid:
                    continue
                # 否则：右侧已无供暖器，或最靠左的候选也覆盖不到这户
                return False
            return True

        # 开区间二分：left 侧恒假（半径为 -1 谁都覆盖不到），right 侧恒真
        left = -1
        right = max(max(heaters), max(houses))
        while left + 1 < right:
            mid = (left + right) // 2
            if helper(mid):
                right = mid          # mid 可行，答案不超过 mid
            else:
                left = mid           # mid 不可行，答案大于 mid
        return right                 # 第一个可行值，即最小半径
```

## 四、复杂度分析

| 版本 | 时间复杂度 | 空间复杂度 |
| :--- | :--- | :--- |
| **最终代码**（二分答案 + 不回退指针判定） | O((n + m) log V) | O(1)（不计排序） |
| 排序后逐房屋二分查最近供暖器 | O((n + m) log m) | O(1)（不计排序） |
| 朴素解法（每个房屋扫全部供暖器） | O(n·m) | O(1) |

> 复杂度中的 n 指房屋数量 `len(houses)`，m 指供暖器数量 `len(heaters)`，V 指半径搜索上界 `max(max(houses), max(heaters))`（≤ 10^9，故 log V ≤ 30）。
> 空间列不计排序开销：Python 的 `sort()` 使用 Timsort，会额外占用 O(n + m) 的辅助空间。

## 五、易错点与总结

### 易错点

- **右移条件写成 `>=`**：`while houses[i] >= heaters[j] + mid` 会把「恰好卡在半径端点上」的房屋也判成够不着，答案偏大。
- **漏掉 `j < m` 直接访问 `heaters[j]`**：`while` 因 `j == m` 退出时，下一行的 `heaters[j]` 直接抛 IndexError。
- **`j` 的位置放错**：它必须初始化在房屋循环**之外**。写进循环体内（每户都从 0 重新扫）会让判定退回 O(n·m)。
- **二分开区间与边界值混用**：改动 `left = -1` 或缩小 `right` 时，要同时确认 `check(left)` 恒假、`check(right)` 恒真，否则可能返回一个假的边界值。
- **谓词掺入额外条件**：判定函数必须只回答「半径 r 是否覆盖全部房屋」。「是否恰好由某一个供暖器覆盖」这类条件不单调，不能拿来做二分。

### 题型套路沉淀

- **二分答案的两件套**：① 找出单调谓词（可行域是后缀 / 前缀）；② 写一个尽量便宜的判定函数。总代价 = 判定代价 × log(值域)。看到「最小半径 / 最小容量 / 最小速度 / 最少天数」这类**最小化一个参数且可行性随参数单调**的表述，先想这条路，而不是急着直接构造答案。
- **开区间二分模板**（返回值即答案，不用额外判边界）：

  ```python
  lo = <必定不满足的下界>   # 如 -1
  hi = <必定满足的上界>
  while lo + 1 < hi:
      mid = (lo + hi) // 2
      if check(mid):
          hi = mid
      else:
          lo = mid
  return hi
  ```

- **判定函数里的双指针**：当输入有序，且「第 i 个元素要找的那个位置」随 i 单调移动时，用一个不回退的指针就能把判定从 O(n log m) 压到 O(n + m)。本题的指针维护的是「能覆盖当前房屋的最左供暖器」。
- **闭区间口径与严格比较的对应关系**：判覆盖用 `<=` 的一侧，在指针推进时就要用 `>` —— 两者是同一件事的两种写法，改动其一时必须同步改另一个。
