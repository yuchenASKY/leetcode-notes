# 1385. 两个数组间的距离值

> **难度**：简单
> **标签**：数组 · 二分查找 · 排序
> **原题链接**：https://leetcode.cn/problems/find-the-distance-value-between-two-arrays/

---

## 一、题目描述

给定两个整数数组 `arr1`、`arr2` 和整数 `d`，统计 `arr1` 中有多少个元素 `arr1[i]` 满足：**不存在**任何 `arr2[j]` 使得 `|arr1[i] - arr2[j]| <= d`。这个个数就是「距离值」。

换成人话：`arr1[i]` 要跟 `arr2` 里**所有**元素都隔开超过 `d`，才算一个合格元素。

### 示例

```text
输入：arr1 = [4,5,8], arr2 = [10,9,1,8], d = 2
输出：2
解释：
  arr1[0]=4：与 arr2 各元素差为 6,5,3,4，全部 > 2 -> 合格
  arr1[1]=5：与 arr2 各元素差为 5,4,4,3，全部 > 2 -> 合格
  arr1[2]=8：|8-10|=2 <= 2 且 |8-8|=0 <= 2 -> 不合格
  距离值 = 2
```

```text
输入：arr1 = [1,4,2,3], arr2 = [-4,-3,6,10,20,30], d = 3
输出：2
```

```text
输入：arr1 = [2,1,100,3], arr2 = [-5,-2,10,-3,7], d = 6
输出：1
```

### 约束条件

- `1 <= arr1.length, arr2.length <= 500`
- `-10^3 <= arr1[i], arr2[j] <= 10^3`
- `0 <= d <= 100`

> 注意：`arr1` 和 `arr2` 的长度上限都只有 500，值域更是窄到 2001 个整数。这个「小」是本题的关键伏笔 —— 它决定了「值域桶」这条路可行，也决定了暴力解并不一定慢（见第五节）。

## 二、解题思路

### 核心思想

**「对所有 j 都成立」⟺「最近的元素也成立」。**

把 `arr2` 排序后，任取 `i`，离它最近的元素必定是**插入位置两侧紧邻的那两个**。于是每个 `arr1[i]` 只需要做一次二分定位 + 两次比较，完全不必扫 `arr2`。

### 判据与判据族定位

**本题判据（一条可判定真假的命题）**：

> 设 `arr2` 已升序，`k` = 第一个满足 `arr2[k] > i` 的下标（`k ∈ [0, m]`）。
> `arr1[i]` 合格 ⟺
> - `k == m` 时：`i - arr2[m-1] > d`
> - `k == 0` 时：`arr2[0] - i > d`
> - 其余：`arr2[k] - i > d` **且** `i - arr2[k-1] > d`

三条分支合起来的语义就是一句话：**插入位置两侧夹住 `i` 的那两个元素（若存在）都与 `i` 相差严格大于 `d`。**

**判据族定位**：本题属「**有序序列上的单调谓词边界定位**」族 —— 也就是最狭义的「下标二分」。这里的谓词是 `Q(k) ≡ (arr2[k] > i)`，它关于 `k` 是 `False...False True...True` 的单调形状，二分定位的就是它的跳变点。

> ⚠️ 本族与 `05-binary-search` 下另一大类「**二分答案**」（最小化最大值、第 K 小、可行域二分）是**两族**：那族的二分对象是**答案值**，谓词是可行性判定 `check(x)`；本族的二分对象是**下标**，谓词直接就是数组的单调性本身。两族的 `while` 写法、边界处理、终止条件都不同，**不要串用**。

### 思路演进

1. **暴力解法**：对每个 `arr1[i]`，遍历 `arr2` 的每一个 `arr2[j]`，一旦发现 `|arr1[i] - arr2[j]| <= d` 就淘汰。时间 O(n·m)，n = m = 500 时最坏 2.5×10⁵ 次内层循环。

2. **瓶颈定位**：内层那趟扫描，我们其实只关心一件事 —— **离 `arr1[i]` 最近的那个 `arr2` 元素有多远**。可是「谁离我最近」这个问题在**无序**序列里没有任何捷径：不去逐个比对，就无法排除某个更近的元素。所以瓶颈不在比较本身，而在「**最近邻这个信息在无序数据里取不到**」。

3. **关键转化**：**先对 `arr2` 排序，把「最近」这个全局量变成局部量。**
   有序之后，最近的元素只能出现在 `i` 的插入位置左右两侧 —— 前驱（≤ `i` 的最大元素）和后继（> `i` 的最小元素），再远的元素只会更远。于是：
   - 原来不行：无序时「谁离 `i` 最近」必须靠 O(m) 全扫描来界定；
   - 现在行：排序把最近邻**锁定在插入点两侧两个固定位置**上，一次 O(log m) 的二分就把它拿到手。
   代价是一次 O(m log m) 的排序，之后每个查询降到 O(log m)。

4. **最优解**：`arr2.sort()` + 每个 `arr1[i]` 一次二分定位。总时间 O(m log m + n log m)。距离理论下界（Ω(n+m)，因为两个数组都必须读一遍）只差一个 log 因子，对本题约束已经是碾压级。

### 关键点

- **严格大于**：`|diff| <= d` 就淘汰，所以存活条件是 `diff > d`，**不是** `>= d`。用 `bisect_right`/手写「第一个 > target」正是为了配合这条。
- **插入位置的两侧是一对，不能只看一侧**：`k` 两侧的 `arr2[k]`、`arr2[k-1]` 都要检查。
- **`k == 0` 与 `k == m` 两个边界必须显式处理**：这两处只有一侧邻居存在。特别是 `k == 0`，如果漏掉不处理而直接去访问 `arr2[k-1]`，Python 的负索引会**静默取到最后一个元素**，代码不报错、答案却少算（实测见第七节）。
- **`arr1` 不需要排序**：输出只是一个计数，与 `arr1` 的顺序无关。

## 三、代码实现

### 最终代码

> 截图里没有 `import`，已补上 `from typing import List`；其余与提交版本逐字一致。

```python
from typing import List


class Solution:
    def lower_bound(self, vec: List[int], target: int) -> int:
        """返回第一个 > target 的下标（左右哨兵写法，等价于 C++ 的 upper_bound）"""
        left = -1
        right = len(vec)
        while left + 1 < right:
            mid = (left + right) // 2
            if vec[mid] > target:
                right = mid
            else:
                left = mid
        return right

    def findTheDistanceValue(self, arr1: List[int], arr2: List[int], d: int) -> int:
        arr1.sort()
        arr2.sort()
        ans = 0

        for i in arr1:
            numIndex = self.lower_bound(arr2, i)
            if numIndex == len(arr2):
                if i - arr2[-1] > d:
                    ans += 1
                continue
            if numIndex == 0:
                if arr2[0] - i > d:
                    ans += 1
                continue
            if arr2[numIndex] - i > d and i - arr2[numIndex - 1] > d:
                ans += 1

        return ans
```

**两点说明（判断性质的描述，不是错误）**：

- 方法名叫 `lower_bound`，但「`vec[mid] > target` 就往左收」定位到的是**第一个严格大于** `target` 的位置，语义上对应 C++ 的 `upper_bound`（以及 Python 的 `bisect_right`），不是 `lower_bound`。功能上两种约定都能用（实测见第七节），只是命名容易在二刷时造成误读。
- 循环里 `left = -1`、`right = len(vec)` 是**哨兵式开区间**写法：`-1` 与 `len` 都只是虚拟边界，保证 `vec[left] <= target < vec[right]` 这个不变量在 `left/right` 不越界的前提下始终成立。

## 四、复杂度分析

> 记 n = `len(arr1)`，m = `len(arr2)`，V = `arr2` 的取值宽度（本题 `[-10^3, 10^3]` ⇒ V = 2001）。

| 版本 | 时间复杂度 | 空间复杂度 |
| :--- | :--- | :--- |
| **最终代码** | O(n log n + (n + m) log m) | O(1) 额外 |
| 优化 V1（去掉 `arr1.sort()`） | O((n + m) log m) | O(1) 额外 |
| 优化 V2（`bisect_right`） | O(m log m + n log m) | O(1) 额外 |
| 优化 V3（值域桶 + 前缀和） | O(V + n + m) | O(V) |
| 朴素解法 | O(n·m) | O(1) |
| 理论下界 | Ω(n + m) | O(1) 额外 |

几点补充：

- **Python 的 `list.sort()` 不算「原地 O(1)」**：Timsort 最坏需要 O(n) 辅助空间。这里按「额外分配的数据结构」口径记 O(1)。
- **最终代码里的 O(n log n) 来自 `arr1.sort()`，这一步是纯冗余** —— 输出只是计数，`arr1` 的顺序不参与任何判断。去掉它就是 V1 行。
- **`arr2` 的排序不可省**（只排了 m 个元素换 n 次 O(log m) 查询，稳赚）；而**由于值域只有 2001 个整数，`arr2` 还可以改用计数桶排序**，把 O(m log m) 砍成 O(m + V) —— 这就是 V3 那条路线。
- **下界 Ω(n + m) 在本题是可达到的**：V3 就是 O(V + n + m)，已经把 log 因子彻底消掉。也就是说本题在小数据范围内的真正最优是 O(n + m)，二分解法在渐进意义上**不是**最优，只是够用。

## 五、优化评估

**结论**：算法层面已经足够，**但仍有三处可优化 —— 一处是真的结构性冗余（可直接删），两处是常数层（收益显著）**。

### 瓶颈分析

本题约束极小（n, m ≤ 500），任何版本都在**亚毫秒**量级，所以下面的对比**不是「不优化就会 TLE」**，而是把它们当作**泛化到任意 n 的研究**来看：究竟哪一段在吃时间。

最终代码的时间由三块构成，实测（`n = m = 500`，d = 0 档，用户版合计 0.486 ms）：

| 环节 | 量级 | 说明 |
| :--- | :--- | :--- |
| `arr1.sort()` | 0.010 ms（n=500）／10.316 ms（n=10⁵） | **纯冗余**，删掉不影响结果 |
| `arr2.sort()` | 与 `arr1.sort()` 同量级 | 必要，是一次性投入 |
| n 次「手写二分」 | 占大头 | 每次约 1.53 μs（实测，见下） |

真正的瓶颈是**第三块**：n 次二分，每次都在 Python 解释层跑十几轮 `while`。这部分几乎没有算法可挖（O(log m) 已是最优），**能动的只有常数**。

### 可优化空间

#### ① 删掉 `arr1.sort()`（结构性冗余）

`arr1` 的顺序不影响结果，排序纯属浪费。实测 `arr1.sort()` 本身值 **0.010 ms（n=500）**、**10.316 ms（n=10⁵）**。

> ⚠️ **但别把它的收益想大了**：占用户版总耗时的比例上限是 **n=500 时约 2%、n=10⁵ 时约 5.8%**。四次复跑里 V1 的实测读数在 **0.96× ~ 1.08×** 之间抖动（其中一轮曾读到 1.26×，属机器状态漂移），与「上限 5.8%」吻合。**正确性上确实冗余，性能上可忽略** —— 若只看某一轮的 1.26× 就写进笔记，就把噪声当成了收益。这也正是「做常数对比必须把合并改动拆开归因」的实例。

#### ② 用 `bisect_right` 替掉手写二分（常数层，收益最大）

单次定位开销实测：

| 实现 | 每次耗时 |
| :--- | :--- |
| 手写 `lower_bound`（Python 层 `while`） | 1.532 μs |
| `bisect_right`（C 实现） | 0.168 μs |

**≈ 9.1×**。整体收益被排序与循环壳摊薄后仍达 **3.9× ~ 4.7×**（见下表）。

#### ③ 值域桶 + 前缀和（换渐进路线，大规模时最强）

题面值域只有 `[-1000, 1000]`，可以开一个 2001 长的布尔桶标记 `arr2` 出现过哪些值，再做一遍前缀和；对每个 `a = arr1[i]`，只需 O(1) 查询区间 `[a-d, a+d]` 内是否落有 `arr2` 元素。总复杂度 **O(V + n + m)**，与 `m` 无关。

- n = m = 500：**2.0× ~ 2.1×**（比 V2 慢 —— 建 2001 轮前缀和的固定成本摊不掉）；
- n = m = 10⁵：**8.9× ~ 9.2×**（反超 V2，因为查找部分彻底不再随 m 增长）。

⇒ **两条路线各有适用区间**：规模小、值域无界或动态查询多 → 二分；值域固定且很小、数据量大 → 桶。

### 优化代码

**V2：`bisect_right` 版（推荐，通用、无值域假设）**

```python
from bisect import bisect_right
from typing import List


class Solution:
    def findTheDistanceValue(self, arr1: List[int], arr2: List[int], d: int) -> int:
        arr2.sort()
        m = len(arr2)
        ans = 0
        for i in arr1:
            k = bisect_right(arr2, i)          # 第一个 > i 的下标
            if k == m:                          # i 不小于任何元素 -> 只看最大值
                if i - arr2[-1] > d:
                    ans += 1
            elif k == 0:                        # i 不大于任何元素 -> 只看最小值
                if arr2[0] - i > d:
                    ans += 1
            elif arr2[k] - i > d and i - arr2[k - 1] > d:
                ans += 1
        return ans
```

**V3：值域桶 + 前缀和版（值域小时最快）**

```python
from typing import List


class Solution:
    LO, HI = -1000, 1000                        # 题面值域，V = 2001

    def findTheDistanceValue(self, arr1: List[int], arr2: List[int], d: int) -> int:
        V = self.HI - self.LO + 1
        off = -self.LO
        pre = [0] * (V + 1)                     # pre[t] = 值域前 t 个位置里 arr2 元素的个数
        for b in arr2:
            pre[b + off + 1] = 1
        for i in range(V):
            pre[i + 1] += pre[i]

        ans = 0
        for a in arr1:
            lo = a - d + off
            hi = a + d + off
            if lo < 0:
                lo = 0
            if hi > V - 1:
                hi = V - 1
            if pre[hi + 1] - pre[lo] == 0:      # 区间 [a-d, a+d] 内没有 arr2 元素
                ans += 1
        return ans
```

> 本题 `d <= 100`、`a ∈ [-1000, 1000]`，所以裁剪后 `lo <= hi` 恒成立，上面的越界分支实际不可达，保留是为了让代码在更宽的值域下也正确。

**优化理由**：

- V2 把「每次查 1.53 μs」换成「0.168 μs」，判据一字未改，可读性还更好（少了十几行手写二分）。
- V3 换掉了整条渐进路线：把「排序 + 二分」替换为「计数 + 前缀和」，代价是必须依赖**值域有界**这一题面条件，空间也从 O(1) 升到 O(V)。

### 实测提速表

同一轮测量、同一台机器，9 轮轮转取最优（只比快慢，不判对错）：

| 场景 | 用户原版 | V1 去 `arr1.sort()` | V2 `bisect_right` | V2b `bisect_left` | V3 桶+前缀和 | V4 暴力早退 |
| :--- | ---: | ---: | ---: | ---: | ---: | ---: |
| n=m=500, d=0 | 0.486 ms | 0.463 ms (1.05×) | 0.122 ms (**3.97×**) | 0.120 ms (4.06×) | 0.229 ms (2.12×) | 10.249 ms (0.05×) |
| n=m=500, d=100 | 0.454 ms | 0.424 ms (1.07×) | 0.098 ms (**4.65×**) | 0.100 ms (4.53×) | 0.222 ms (2.04×) | 0.218 ms (2.08×) |
| n=m=10⁵, d=0 | 183.002 ms | 191.313 ms (0.96×) | 46.783 ms (3.91×) | 43.842 ms (4.17×) | 19.809 ms (**9.24×**) | — |
| n=m=10⁵, d=100 | 185.563 ms | 177.809 ms (1.04×) | 43.715 ms (4.24×) | 43.599 ms (4.26×) | 20.850 ms (**8.90×**) | — |

（V4 暴力在 n = 10⁵ 档不参与 —— 期望内层迭代约 10⁹ 次，远超合理耗时。）

### 常数级优化（可选）

- **`arr1.sort()` 可直接删**（V1），但收益上限只有 2% ~ 5.8%，见上文归因。
- **`numIndex == len(arr2)` 里 `len()` 每轮重算**：挪到一个局部变量 `m` 里（示例代码已这样改）。属微小改进，量级在噪声内，不建议为它单独改代码，顺手带上即可。
- **`self.lower_bound(...)` 的方法查找开销**：每次调用都要过一次属性查找。换成 `bisect_right` 顺带消掉了这部分 —— 单次 1.532 μs → 0.168 μs 的差距里，解释层 `while` 循环是主因，方法调用只占小头，两者不必分开优化。

### 一条被证伪的直觉：「范围太小了，暴力更快」

题解区常见这个说法，本题**有条件成立**：

| 场景 | 暴力早退 | 用户版 | 结论 |
| :--- | ---: | ---: | :--- |
| n=m=500, d=100 | 0.218 ms | 0.454 ms | 暴力**快 2.08×** |
| n=m=500, d=0 | 10.249 ms | 0.486 ms | 暴力**慢 21×** |

差别全在**内层早退是否触发**。`arr2` 取值在 `[-1000,1000]`，单个元素命中 `|a-b| <= d` 的概率约 `(2d+1)/2001`：

- `d = 100` ⇒ 命中率约 10% ⇒ 内层期望只跑约 10 次就 `break`，暴力的期望代价从 `n·m` 塌成 **n·(1/p)**；
- `d = 0` ⇒ 命中率约 0.05% ⇒ 几乎从不早退，退化成满扫 `n·m` = 2.5×10⁵ 次。

⇒ 判断「暴力够不够」要看**内层循环的期望迭代次数 ≈ 1/p**，而不是题面给的 `n·m` 上界。这也是本题「简单」的原因：约束把 `n·m` 压到了 Python 也能轻松过的量级，二分在这里是**优雅**而非**必需**。

## 六、易错点与总结

### 易错点

1. **把 `> d` 写成 `>= d`**。题面要求是「不存在 `|diff| <= d`」，所以存活条件必须是**严格大于** `d`。写成 `>=` 会把「恰好差 `d`」的元素错判为合格。
2. **漏掉 `k == 0` 边界 —— Python 负索引不报错，静默少算**。删掉 `if numIndex == 0` 分支后，代码会去算 `i - arr2[k-1]`，而 `k == 0` 时 `arr2[-1]` 是**最后一个元素**（不是「不存在」），`i - arr2[-1]` 为负、与 `d` 比较恒为 `False`，于是这一类元素永远不被计数。
   实测（递增枚举命中第一个反例即停）：**最小反例 `arr1 = [-2], arr2 = [-1], d = 0`，真值 1、实得 0** —— 程序不抛异常，只是答案错了。这是本题最隐蔽的坑。
3. **只检查一侧邻居**。「对所有 `arr2[j]` 都成立」必须同时排除前驱和后继两个方向，只比较 `arr2[k]` 会漏掉左边更近的元素（示例 1 里 `arr1[2] = 8` 正是被左侧的 `arr2` 中元素 `8` 判掉的）。
4. **误以为插入位置的两种约定（`bisect_left` / `bisect_right`）会给出不同结果**。其实都可以：重复元素只会让 `k` 整体平移，而「`k-1` 与 `k` 这一对仍夹住 `i`」这件事不变。实测 `bisect_left` 与 `bisect_right` 两版在 3 组官方示例 + 10 条手工边界 + 40 组随机对拍上**均 0 偏差**。真正的要求是「成对取」，而不是取哪一种。
5. **把 `arr1.sort()` 当必要步骤保留**。它不影响正确性（实测 0 偏差），但也几乎不带来收益 —— 容易在复审时误以为「排序是解法的一部分」。

### 题型套路沉淀

- **「对所有元素成立」先转化成「对最近邻成立」**：把全称量词降成极值问题，是本题最关键的一步。同型思路常见于「存在/不存在」→「最大/最小」的改写。
- **最近邻查询的标准降维**：无序时求「离 `x` 最近的元素」必须 O(m)；**排序后锁死在插入位置两侧两个下标**，一次 O(log m) 边界定位即可。凡是题目里出现「与另一个集合中任意元素的最近距离」，就该想到这条路线。
- **二分的两种插入位置都要会**：`bisect_left`（第一个 `>=`）与 `bisect_right`（第一个 `>`）。本题两者都能用，但在「值相等要算进左边还是右边」有分歧的题里，选错就错。
- **值域小是有用信号**：当 `值域宽度 V ≪ n` 时，「排序 + 二分」可以整体换成「计数 + 前缀和」，把 `log` 因子消掉，得到 O(V + n + m)。本题 V = 2001 而 n、m 可到 10⁵，正是这条路线占优的典型场景。
- **手写二分 vs 标准库**：Python 里手写二分每轮都在解释层跑循环，实测比 C 实现的 `bisect` 慢 **≈ 9.1×**（单次）。**除非题目明确要求手写或要自定义谓词，否则直接调用标准库。**
- **判断暴力是否够用要看期望迭代次数**：有早退的内层循环期望代价是 `1/p`（`p` 为命中概率），而非上界 `m`。本题 `d` 大时暴力比二分还快，`d` 小时慢 21 倍 —— **同一个「O(n·m)」标签下，实测能差两个数量级。**

### 5) 删掉再对拍：`k == 0` 分支在防什么

把 `bisect_right` 版里的 `elif k == 0` 分支删掉，按规模递增枚举小空间，**第 6 组就命中反例**：

```text
arr1 = [-2], arr2 = [-1], d = 0
真值 1（|-2 - (-1)| = 1 > 0，合格）
实得 0（走掉了夹住 i 的两侧判据，arr2[-1] 被负索引静默取成 -1，-2 - (-1) = -1 不 > 0）
```

程序**不抛异常、不越界**，只是答案错了 —— 说明这个分支防的不是崩溃，而是**负索引导致的静默错算**。

### 6) 微基准

规模取题面上限的 `n = m = 500`，另加一档 `n = m = 10⁵` 作为**泛化到任意 n 的研究**（题面之外的规模）。9 轮轮转、每轮跑遍所有场景与变体，取最优值。耗时数据见第五节的实测表。

结论摘要：

- 二分定位由手写改为 `bisect_right`，单次 **1.532 μs → 0.168 μs（≈ 9.1×）**，整体 **3.9× ~ 4.7×**；
- 值域桶在 n = 500 时 2.0× ~ 2.1×、在 n = 10⁵ 时 **8.9× ~ 9.2×**，两条路线的适用区间不同；
- 暴力早退在 `d = 100` 时比用户版**快 2.08×**、在 `d = 0` 时**慢 21×**，差别的来源是内层早退概率 `p`；
- V1（去 `arr1.sort()`）四次复跑读数在 **0.96× ~ 1.08×** 之间抖动（一轮漂移到 1.26×），**拆开归因**后确认收益上限就是 `arr1.sort()` 自身开销 —— `n = 500` 时 0.010 ms（约占 2%）、`n = 10⁵` 时 10.316 ms（约占 5.8%）⇒ 结论是「正确性冗余、性能可忽略」。
