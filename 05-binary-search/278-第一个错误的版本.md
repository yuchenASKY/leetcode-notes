# 278. 第一个错误的版本

> **难度**：简单
> **标签**：二分查找 · 交互
> **原题链接**：https://leetcode.cn/problems/first-bad-version/

---

## 一、题目描述

有 `n` 个版本，编号 `1..n`。从某个版本 `bad` 开始，它以及它之后的所有版本都是坏的（之前的都正常）。你只能通过调用 `isBadVersion(version)` 询问某个版本是否为坏版本，要求找出**第一个**坏版本，并**尽量少调用该接口**。

### 示例

```text
输入：n = 5, bad = 4
输出：4
解释：
调用 isBadVersion(3) -> false
调用 isBadVersion(5) -> true
调用 isBadVersion(4) -> true
所以，4 是第一个错误的版本。
```

### 约束条件

- `1 <= bad <= n <= 2^31 - 1`
- `isBadVersion` 由评测系统提供，调用次数会被统计

---

## 二、解题思路

### 核心思想

`isBadVersion` 在整个编号区间上是一条**单调的布尔序列**：`[1, bad-1]` 全为 `false`，`[bad, n]` 全为 `true`。于是「找第一个坏版本」= **在单调布尔序列上找 `false → true` 的分界点**，用二分把每次询问的信息量榨到 1 bit。

### 思路演进

1. **暴力解法**：从 `1` 到 `n` 顺序询问，第一次返回 `true` 的就是答案。正确但最坏要问 `n` 次；`n` 最大到 `2^31 - 1`，一次询问哪怕只花 1 微秒也跑不完，直接超时。
2. **观察到**：数组本身我们既没有、也拿不到，唯一的信息通道是 `isBadVersion`。但这题的好处是**答案的候选区间有单调结构** —— 一旦某个版本 `v` 是坏的，那么 `v` 之后的**全部**都是坏的；一旦 `v` 是好的，那么 `v` 之前的**全部**都是好的。也就是说每问一次，能一次性排除掉「`v` 之前全部」或「`v` 之后全部」这半边。
3. **优化为**：二分。维护两个**已知答案的锚点** —— `left` 一定是好版本（假），`right` 一定是坏版本（真），每次取中点询问，根据结果把区间收缩一半；当两者相邻时，`right` 就是最小的那个「真」，即答案。

### 关键点

- **用哨兵消灭边界特判（开区间写法）**：`left = 0`（版本号从 1 开始，0 号不存在 ⇒ 一定不是坏版本，天然满足「`left` 为假」）、`right = n + 1`（`n+1` 不存在 ⇒ 视作「一定坏」，天然满足「`right` 为真」）。这样循环体内永远不需要判断「答案是不是 1」「答案是不是 n」。
- **循环条件是 `left + 1 < right`**，即开区间 `(left, right)` 里还有候选；退出时 `left + 1 == right`，`right` 就是最小真值位置。
- **`mid` 必须落在开区间内部**：由于循环保证 `left + 1 < right`，取 `mid = (left + right) // 2` 必然满足 `left < mid < right`，不会死循环、也不会碰到哨兵。
- **收缩方向**：`isBadVersion(mid) == True` ⇒ `mid` 本身可能是答案，把 `right` 收到 `mid`（保留）；否则 `mid` 及之前全部排除，把 `left` 提到 `mid`（`mid` 已知为假，可以做锚点）。
- 返回值是 `right`（最后一个假版本的**下一个**），不是 `left`（`left` 停在最后一个好版本上）。

## 三、代码实现

### 最终代码

```python
# The isBadVersion API is already defined for you.
# def isBadVersion(version: int) -> bool:

class Solution:
    def firstBadVersion(self, n: int) -> int:
        left = 0        # 哨兵：一定不是坏版本
        right = n + 1   # 哨兵：一定"坏"（越界视作坏）
        while left + 1 < right:
            mid = (left + right) // 2
            if isBadVersion(mid) == True:
                right = mid     # mid 可能是答案，保留
            else:
                left = mid      # mid 及之前全部排除
        return right
```

## 五、优化评估

**结论**：已是理论下界，**无法再优化**。

### 瓶颈分析

整个算法的时间全部来自 `isBadVersion` 的调用，其余算术都是 O(1)。每次调用只能回答「是 / 否」这一个二元问题，最多提供 1 bit 信息。

### 可优化空间

要从 `n` 个候选里唯一确定答案，判定树的叶子数至少要 `n`，而深度为 `d` 的二叉树最多 `2^d` 个叶子 ⇒ 至少要 `⌈log₂ n⌉` 次询问。当前写法每次恰好排除近一半，调用次数就是 `⌈log₂(n+1)⌉` 量级，**已顶到信息论下界**，没有进一步压缩的空间。空间上只用了两个整型变量，也已经是 O(1)。

### 常数级优化（可选）

- 其他语言里 `mid = (left + right) // 2` 在 `n` 接近 `2^31 - 1` 时会整数溢出，需写成 `left + (right - left) // 2`；**Python 的大整数没有这个问题**，可以照写。
- 严格来说这题的问法是「第一个坏版本」，用它自带的闭区间模板 `low = 1, high = n` + `while low < high: mid = (low+high)//2; if bad(mid): high = mid else: low = mid + 1` 同样正确且少一个哨兵；两者的询问次数在同一数量级，属于写法偏好，不构成优化。

## 六、易错点与总结

### 易错点

- **`left` 从 1 开始**：如果 `bad == 1`（1 号就是坏版本），`left = 1` 就不再满足「`left` 一定为假」这个前提，模板直接失效。用 `0` 号哨兵可以一劳永逸地避开这个假设。
- **`right` 写成 `n`**：那么 `right` 是否「一定为真」取决于 `bad` 是否等于 `n`，同样破坏前提；`n + 1` 才是恒定安全的假想上界。
- **返回 `left`**：`left` 停在最后一个**好**版本上，差一位。
- **循环条件写成 `left <= right`**：这是闭区间模板的条件，套到开区间写法上会让 `mid` 撞到哨兵（例如 `left = 0, right = 1` 时 `mid = 0`，`isBadVersion(0)` 越界）。
- **`mid` 收缩成 `left = mid + 1`**：开区间模板里两侧都只走到 `mid`，`+1` 会跳过一个可能的答案。

### 题型套路沉淀

- **单调布尔函数求分界点**（左侧全假、右侧全真）：固定用「双哨兵 + 开区间」模板 —— `left` 恒假、`right` 恒真，`while left + 1 < right`，返回 `right`。这个模板对「找第一个满足条件的位置」是通用的，不用为目标值的边界单独写特判。
- **交互题的复杂度按调用次数算**：这类题的优化目标不是 CPU 时间，而是「问了几次」，所以二分是天然解法 —— 每次询问都把候选集砍半，询问次数直接落在信息论下界上。
