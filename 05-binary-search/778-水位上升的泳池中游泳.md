# 778. 水位上升的泳池中游泳

> **难度**：困难

> **原题链接**：https://leetcode.cn/problems/swim-in-rising-water/

## 一、题目描述

`grid` 是 `n × n` 的矩阵，`grid[i][j]` 表示位置 `(i, j)` 的平台高度。下雨使水池水位随时间 `t` 线性上涨，时间为 `t` 时水位就是 `t`。

可以从一个平台游向上下左右相邻的平台，前提是当前水位同时淹没这两个平台（方格内游动不耗时）。从左上角 `(0, 0)` 出发，返回到达右下角 `(n-1, n-1)` 所需的**最少时间**。

### 示例

```text
输入：grid = [[0,2],[1,3]]
输出：3
解释：t = 0 时水位只有 0，四周平台都比水位高，动弹不得；
      直到 t = 3 水位淹过全场，才能一路游到 (1, 1)。
```

```text
输入：grid = [[0,1,2,3,4],[24,23,22,21,5],[12,13,14,15,16],[11,17,18,19,20],[10,9,8,7,6]]
输出：16
解释：存在一条绕行的蛇形路径，其最高格子高度为 16；
      16 以下无论怎么走都会被某个更高的格子挡住。
```

### 约束条件

- `n == grid.length`
- `n == grid[i].length`
- `1 <= n <= 50`
- `0 <= grid[i][j] < n²`
- `grid[i][j]` 中每个值**均无重复**

## 二、解题思路

### 核心思想

**答案是「路径上最大高度的最小值」，而它关于时间单调，所以可以二分。**

从 `(0,0)` 走到 `(n-1,n-1)` 的任意一条路径 `P`，能把整条路径游通的最早时刻就是 `P` 上最高的那个格子；答案是所有路径里这个值的最小值：`min over P ( max over cells in P grid )`。

换成判定问题就很好写：**`feasible(t)` = 只允许踩 `grid ≤ t` 的格子，能否从 `(0,0)` 走到 `(n-1,n-1)`**。随着 `t` 增大只会有更多格子被淹没开放，因此 `feasible` 单调递增，二分 `t` 即可。

### 思路演进

1. **暴力解法**：直接按时间枚举 `t`，从 `grid[0][0]` 一路试到 `n² - 1`，每个 `t` 做一次网格遍历看终点是否可达，第一个成功的 `t` 就是答案。做法正确，但答案值域有 `n²` 个候选，逐个试要跑 `n²` 次判定、每次 `O(n²)`，总复杂度 `O(n⁴)`。

2. **观察到**：水位只会涨不会退，格子被淹没之后就**永远保持开放**。所以 `feasible(t)` 是单调的 —— `t` 可行，则 `t + 1` 必然可行。这种「候选答案上存在单调谓词」的结构，正是二分的前提。

3. **优化为**：把暴力枚举改成在答案值域上二分。下界取 `grid[0][0]`（起点自己都还没被淹没时必然不可达），上界取 `n² - 1`（值互不相同且 `0 ≤ grid[i][j] < n²`，故全场最高高度就是 `n² - 1`，此时所有格子都开放，必然可达）。每轮二分只跑一次 `O(n²)` 的 BFS 判定，轮数 `O(log(n²)) = O(log n)`。

### 关键点

- **二分的是答案 `t` 本身，不是数组下标** —— 这是「二分答案」类问题的标志。
- **单调性是门票**：本题的单调性来自「格子只会开、不会关」这一物理事实，写判定前必须先确认它成立。
- **起点哨兵不能省**：判定开头必须挡掉 `t < grid[0][0]`。否则 BFS 一进来就把 `(0,0)` 塞进 `seen`，即使水位还没淹过起点也会被判成可达。
- 判定里的遍历用 `appendleft + popleft`，实际是**栈**（DFS）；本题每条边代价相同、只问连通性，DFS 与 BFS 完全等价，用哪个都行。
- 二分的**上界必须取一个「一定可行」的值**，否则收敛位置会错。

## 三、代码实现

### 最终代码

```python
from collections import deque          # 截图里没有、已补


class Solution:
    def swimInWater(self, grid: list[list[int]]) -> int:
        m = len(grid)
        n = len(grid[0])

        def bfs(t: int) -> bool:
            if t < grid[0][0]:             # 起点哨兵：水位没淹过起点时直接不可达
                return False
            dot = deque()
            dot.append((0, 0))
            seen = {(0, 0)}
            while dot:
                x, y = dot.popleft()
                for nx, ny in ((x + 1, y), (x - 1, y), (x, y + 1), (x, y - 1)):
                    if 0 <= nx < m and 0 <= ny < n and grid[nx][ny] <= t and (nx, ny) not in seen:
                        seen.add((nx, ny))
                        dot.appendleft((nx, ny))

            if (m - 1, n - 1) in seen:
                return True
            return False

        # 二分答案：以下为截图未覆盖的部分，已补
        lo, hi = grid[0][0], n * n - 1      # hi 处全场开放，保证可行
        while lo < hi:
            mid = (lo + hi) // 2
            if bfs(mid):
                hi = mid
            else:
                lo = mid + 1
        return lo
```

## 四、复杂度分析

| 版本 | 时间复杂度 | 空间复杂度 |
| :--- | :--- | :--- |
| **最终代码** | O(n² log n) | O(n²) |
| 朴素解法（线性枚举 t + BFS） | O(n⁴) | O(n²) |
| 理论下界 | O(n²) | O(n²) |

> 复杂度中的 n 指矩阵的**边长**（`grid` 是 `n × n`，共 `n²` 个格子）。一次判定的 BFS 要遍历至多 `n²` 个格子、每条边 `O(1)`，故为 `O(n²)`；二分轮数为 `O(log(n²)) = O(log n)`，相乘得 `O(n² log n)`。

## 五、优化评估

**结论**：时间已到这类「二分答案 + 可达性判定」的标准复杂度，**没有可降的大 O 空间**（判定的可行性检查本身就是 `O(n²)`，二分的 `log` 因子来自轮数）。

### 瓶颈分析

时间上，`O(n²)` 是任何解法都绕不开的——至少要读一遍矩阵。当前的 `log n` 因子来自二分轮数（`n = 50` 时约 11 轮），每轮都重新分配一次 `seen` 与双端队列，存在重复劳动，但受限于「判定必须整体重跑」，没有把轮数降到 `O(1)` 的通用办法。

空间上是 `seen` 集合 + 双端队列，两者都最多装 `n²` 个格子。

### 可优化空间

本题存在几条**同复杂度量级**的等价路线，并非更快的替代，仅作对照：

- **并查集按高度升序加边**：把所有格子按高度排序，依次「淹没」并把它与已淹没的四邻合并，当起点与终点首次连通时，当前高度即为答案。整体在 `O(n² log n)` 量级（排序主导）。
- **Dijkstra 式最短路**：把「路径上最大高度」当作路径代价，用堆维护「到达每个格子的最小最大高度」，终点出堆即答案，同为 `O(n² log n)`。

三条路线大 O 同级，本题数据规模（`n ≤ 50`）下没有替换的必要，二分答案写法最直白、最不容易写错。

### 常数级优化（可选）

- `seen` 用 `set` 存 `tuple` 坐标，哈希与分配开销都不小；换成 `n × n` 的 `bytearray` 或 `list[list[bool]]` 做访问标记，能把常数压下来，大 O 不变。
- 二分的下界可以再收紧——例如取起点与终点高度的较大值（两者都必须被淹没），能省下若干轮判定。
- `(m - 1, n - 1)` 与 `(0, 0)` 是每轮都要重建的常量元组，提到闭包外先用局部变量存好，可少一些重复构造。

## 六、易错点与总结

### 易错点

- **漏掉起点哨兵**：判定里若不写 `if t < grid[0][0]: return False`，由于 `(0,0)` 一开始就被塞进 `seen`，`t` 小于起点高度时会被误判为「可达」，二分收敛到错误的小值。
- **二分上界取错**：上界必须是「一定可行」的高度。这里取 `n² - 1`（因值域为 `[0, n²)` 且互不相同，最大高度恰为 `n² - 1`）即可保证 `bfs(hi)` 为真。
- **访问标记时序**：入队时就 `seen.add`，而不是出队时再加，否则同一个格子会被反复入队。
- **开闭写反**：移动条件是 `grid[nx][ny] <= t` 而不是 `< t` —— 水位恰好等于平台高度时平台已被淹没，可以站上去。
- **越界判断的顺序**：`0 <= nx < m and 0 <= ny < n and grid[nx][ny] <= t` 必须让边界判断在访问 `grid` 之前，靠 Python `and` 的从左到右短路求值保障。
- **`n = 1` 的退化情形**：只有起点也是终点，判定恒为真，答案应直接是 `grid[0][0]`，二分循环不进入、返回 `lo` 即正确。

### 题型套路沉淀

- **「最小化最大值 / 最大化最小值」→ 二分答案**。把优化问题转成判定问题 `feasible(t)`，只要谓词关于 `t` 单调，就能在值域上二分。固定骨架：

  ```python
  lo, hi = 下界, 上界必然可行
  while lo < hi:
      mid = (lo + hi) // 2
      if feasible(mid):
          hi = mid          # 可行则往小找
      else:
          lo = mid + 1      # 不可行则往大找
  return lo
  ```

- **写二分答案前的三连问**：① 答案是否单调？② 值域多大（决定轮数）？③ 单次 `feasible` 的代价（决定总复杂度 = 轮数 × 判定代价）？
- **判定按题意挑工具**：本题是「只走高度 ≤ t 的格子能否连通」⇒ 网格 BFS/DFS 连通性；换成别的题可能是贪心计数、前缀和 + 二分等。
- **下界/上界的可靠性比「省几轮」重要得多**：下界要取到谓词确实为假的那一点，上界要取到谓词确实为真的那一点，两者错一个，二分就会收敛到错误位置或死循环。
