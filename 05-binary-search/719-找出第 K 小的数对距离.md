# 719. 找出第 K 小的数对距离

> **难度**：困难
> **标签**：数组 · 双指针 · 二分查找 · 排序
> **原题链接**：https://leetcode.cn/problems/find-k-th-smallest-pair-distance/

---

## 一、题目描述

数对 `(a, b)` 由整数 `a` 和 `b` 组成，距离定义为 `|a - b|`。给定整数数组 `nums` 和整数 `k`，在所有满足 `i < j` 的下标对中，求第 `k` 小的数对距离（距离相同的数对**分别计数**，不合并）。

### 示例

```text
输入：nums = [1,3,1], k = 1
输出：0
解释：所有数对及距离为 (1,3)->2、(1,1)->0、(3,1)->2，第 1 小的是 0。

输入：nums = [1,1,1], k = 2
输出：0

输入：nums = [1,6,1], k = 3
输出：5
```

### 约束条件

- `n == nums.length`
- `2 <= n <= 10^4`
- `0 <= nums[i] <= 10^6`
- `1 <= k <= n * (n - 1) / 2`

---

## 二、解题思路

### 核心思想

**「第 k 小的距离」直接求不了，但「距离 ≤ d 的数对有几个」很好求，而且这个计数随 `d` 单调不减 —— 于是对答案（距离值本身）做二分。**

### 思路演进

1. **暴力解法**：枚举所有 `i < j`，算出 `n(n-1)/2` 个距离，排序后取第 `k` 个。n = 10^4 时数对约 5×10^7 个，收集这一个数组本身就要几百 MB，再排一遍更不可能 —— **内存和时间同时爆掉，不可行**。

2. **观察到**：距离一定是整数，且一定落在 `[0, max(nums) - min(nums)]` 里，值域不超过 10^6。所以答案的候选只有 O(V) 种，可以**在值域上二分**，而不是在数对集合上排序。

   二分的依据是下面这条单调性 —— 记 `count(d)` 为「距离 ≤ d 的数对个数」，则：

   > `count(d)` 随 `d` 增大**单调不减**（`d` 变大只会把更多数对纳入统计）。

   因此 `count(d) >= k` 这个判据关于 `d` 是「前假后真」的，第一个使之为真的 `d` 就是答案。这一步把问题从「找一个第 k 小元素」转化成了「**找一个满足单调判据的最小值**」—— 即**二分答案（对值域二分）**。

3. **优化为**：让 `check(d)` 做到 O(n)。先把 `nums` 排序，此时「距离 ≤ d」等价于「下标区间内」——对每个右端点 `j`，满足 `nums[j] - nums[i] <= d` 的左端点恰好是一段连续前缀 `[0, i]`，个数就是 `j - i`。再关键的是：`j` 右移时 `nums[j]` 变大，门槛 `nums[j] - d` 也随之变大，**`i` 只增不减**，所以 `i` 不必对每个 `j` 重新二分，跟着 `j` 同向滑动即可，一次线性扫描就能数完所有数对。

   于是整体：外层 `log V` 轮二分，每轮 O(n) 计数。

### 关键点

- **二分的是距离值，不是下标**。判据 `check` 不是「查找」而是「计数」，这是二分答案区别于普通二分的本质。
- **排序不改变答案**：距离只依赖两个值的大小关系，排序只是把「值相近」变成「下标相近」，数对集合一一对应。
- **计数口径是 `j - i`**：`i` 停在第一个满足 `nums[j] - nums[i] <= d` 的位置后，合法的左端点是 `[i, j-1]` 共 `j - i` 个，`i` 自己也算进去（`nums[j] - nums[i] <= d` 成立）。
- **左边界取 `-1` 而不是 `0`**：答案可能是 `0`（存在相等元素时数对距离就是 0），把 `0` 当成「必然不满足」会漏掉正确答案。`d = -1` 时 `count = 0 < k` 恒成立，是天然的安全下界。
- **判据用 `>= k` 而不是 `== k`**：要的是「最小的使 `count >= k` 成立的 `d`」——因为距离值有重复，`count` 会在某个 `d` 处直接跨过 `k`，等号往往取不到。

## 三、代码实现

### 最终代码

```python
class Solution:
    def smallestDistancePair(self, nums: list[int], k: int) -> int:
        nums.sort()

        def check(mx: int) -> bool:
            cnt = i = 0
            for j, x in enumerate(nums):
                while x - nums[i] > mx:
                    i += 1
                cnt += j - i
            return cnt >= k

        left, right = -1, nums[-1] - nums[0]
        while left + 1 < right:
            mid = (left + right) // 2
            if check(mid):
                right = mid
            else:
                left = mid
        return right
```

> 二分采用**开区间模板**：`left` 恒为「不满足判据」的一侧（初值 `-1`），`right` 恒为「满足判据」的一侧（初值 `max - min`，此时所有数对都被计入，`count = n(n-1)/2 >= k` 必然成立），循环到 `left + 1 == right` 时 `right` 即答案。

## 四、复杂度分析

| 版本 | 时间复杂度 | 空间复杂度 |
| :--- | :--- | :--- |
| **最终代码** | O(n log n + n log V) | O(1)（不含排序） |
| 朴素解法（枚举所有数对 + 排序） | O(n² log n) | O(n²) |
| 理论下界 | O(n log n)（排序下界） | O(1) |

> 复杂度中的 `n` 指数组 `nums` 的长度；`V = max(nums) - min(nums)` 指值域宽度（本题 `V <= 10^6`）。
> 计数部分只用了 `cnt`、`i` 两个标量，额外空间为 O(1)；Python 的 `list.sort()` 是 Timsort，最坏需要 O(n) 的临时空间。
> `log V <= 20`，所以主项实际是排序的 `n log n`。

## 五、优化评估

**结论**：复杂度上**已是最优**，不需要再改。

### 瓶颈分析

时间由两段构成：排序 `O(n log n)` 和二分 `O(n log V)`。后者是 `log V ≈ 20` 轮 × 每轮一次线性双指针扫描；前者是必需的。

### 可优化空间

- **能不能不排序？** 不能。双指针计数依赖「下标序 = 值序」，这是排序换来的；不排序就得对每个 `j` 重新扫一遍，退化为 O(n²)。
- **能不能不二分？** 答案取值有 O(V) 种可能且判据单调，二分是这类问题的标准做法；换成「先收集所有距离再排序/选择」会直接退化到 `O(n² log n)` 与 `O(n²)` 空间，正是被排除的朴素解。
- 空间上已经压到 O(1)（`check` 是流式计数，不存储任何数对），没有继续压缩的余地。

### 常数级优化（可选）

- 二分上界可以从 `nums[-1] - nums[0]` 收紧（例如取 `nums[-1] - nums[0]` 仍是最稳妥的可行上界；若先算出更小的可行值可减少几轮，但收益不到 1 轮以上，意义有限）。
- `check` 里把 `nums` 绑定到局部变量（闭包已捕获，无需额外处理），避免重复的属性查找。

## 六、易错点与总结

### 易错点

- **`left` 初始化成 `0`**：答案可能为 0，`0` 不等于「不可行」，会漏解或多跑一轮错误判定。必须用 `-1`。
- **`while` 条件写成 `>= mx`**：题目要的是「距离**≤** d」，写成严格大于会把等于 `mx` 的那一档错误排除，`cnt` 偏小、答案偏大。
- **`cnt` 累加写成 `i` 或 `i + 1`**：合法左端点是 `[i, j-1]`，个数是 `j - i`。写成 `i` 会漏掉 `i` 本身，写成 `i + 1` 会多算一个（`nums[j]` 自己那一项，对应距离 0，只有 `j` 自己，不能计）。
- **把 `i` 写在 `for` 里重新初始化**：那退化成 O(n²)。`i` 必须在循环外定义、跨 `j` 单调右移。
- **判据写成 `cnt == k`**：距离存在大量重复，`cnt` 很可能从 `< k` 直接跳到 `> k`，等号取不到会死循环或返回错误值。
- 静态核查：`i` 不会越过 `j`，因为 `nums[j] - nums[j] = 0 <= mx`（`mx` 恒非负），所以 `j - i >= 0`，`cnt` 不会出现负数。

### 题型套路沉淀

- **看到「第 k 小 / 第 k 大」+「数对 / 子数组 / 差值」，先想能不能把「第 k 小」转成「≤ d 的个数 ≥ k」**：这是把选择问题转成判定问题的标准动作，一旦计数关于 `d` 单调，就能二分答案。
- **二分答案的三件套**：① 确定答案的取值区间；② 证明判据的单调性；③ 写出 O(n) 或 O(n log n) 的 `check`。三者缺一不可，最常翻车的是把「可行下界」设错（本题的 `-1`）。
- **有序数组 + 计数型 `check` → 双指针**：形如「统计差不超过 d 的数对 / 元素个数」的 `check`，排序后让两个指针同向滑动，天然 O(n)；这是二分答案里最常见的组合。
- **开区间二分模板**（`left` 不可行、`right` 可行、`while left + 1 < right`）比闭区间模板少了「`mid` 是否要 ±1」的判断，边界最不容易写错，建议固化成肌肉记忆。
