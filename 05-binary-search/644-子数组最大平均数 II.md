## 一、题目描述

给定一个包含 `n` 个整数的数组 `nums` 和一个整数 `k`，找出**长度大于等于 `k`** 且**平均数最大**的连续子数组，并输出这个最大平均数。计算误差小于 `10^-5` 的结果都算正确。

注意两点容易读漏的地方：① 子数组长度是「**≥ k**」而不是「恰好等于 k」；② 返回的是**平均值**，不是子数组本身。

### 示例

```text
输入：nums = [1,12,-5,-6,50,3], k = 4
输出：12.75000
解释：
 - 长度 4 的子数组平均值：[0.5, 12.75, 10.5]，最大 12.75
 - 长度 5 的子数组平均值：[10.4, 10.8]，最大 10.8
 - 长度 6 的子数组平均值：[9.16667]，最大 9.16667
 其中最大值 12.75 来自子数组 [12,-5,-6,50]（长度恰好为 4）。
 题目要求无需考虑长度小于 4 的子数组。
```

### 约束条件

- `n == nums.length`
- `1 <= k <= n <= 10^4`
- `-10^4 <= nums[i] <= 10^4`

## 二、解题思路

### 核心思想

**「求最大平均值」本身难做，但它的判定问题很好做，而且判定结果关于候选值单调 —— 于是改为对答案二分。**
对候选平均值 `x`，把每个元素减去 `x`，则「某段子数组的平均值 ≥ x」等价于「`(nums[i] - x)` 在这段上的和 ≥ 0」；这个判定用前缀和在 O(n) 内即可完成。

### 思路演进

1. **暴力解法**：枚举所有起点 `i` 和终点 `j`（满足 `j - i + 1 >= k`），用前缀和 O(1) 算出每段平均值并取最大值。长度为 ≥ k 的区间共 O(n²) 个，时间 O(n²)；`n = 10^4` 时约 5×10⁷ 次操作，属于「勉强能过但很难再优化」的一档。
2. **观察到**：直接最大化平均值很别扭 —— 平均值不是可累加量，没法像「最大子数组和」那样一次扫描求出来。**但把问题反过来问**：「是否存在一段长度 ≥ k 的子数组，其平均值 ≥ x？」这个问题很干净：令 `b[i] = nums[i] - x`，则它等价于「`b` 是否存在长度 ≥ k 的子数组和 ≥ 0」，前缀和一次扫描就能回答。
3. **单调性是关键**：若存在平均值 ≥ x 的子数组，则对任意 `y <= x`，同一段子数组的平均值同样 ≥ y，判定也为真。所以 `check(x)` 的真值集合是一个「前缀区间」——存在阈值 `ans`，`x <= ans` 时判定为真、`x > ans` 时为假。**这就是能二分的依据。**
4. **优化为**：在实数区间 `[min(nums), max(nums)]` 上对 `x` 二分，用 `check(x)` 逼近阈值 `ans`。因为答案是实数，二分不能按整数那样收敛到「某一个值」，而是收敛到「一个足够窄的区间」，用区间宽度 `≤ 1e-5` 作为终止条件，最终返回下界。

### 关键点

- **核心转化**：`子数组平均值 ≥ x` ⟺ `(nums[i] - x) 在该子数组上的和 ≥ 0`。这一步把「无法累加的平均值」变成了「可以累加的和」，是整个解法的支点。
- **`check(x)` 怎么写**：设 `b[i] = nums[i] - x`，前缀和 `prefix[i+1] = prefix[i] + b[i]`（长度 `n+1`，`prefix[0] = 0`）。要判断是否存在 `i - j >= k` 且 `prefix[i] - prefix[j] >= 0`，即对每个 `i >= k`，看 `prefix[i]` 是否 ≥ `min(prefix[0 .. i-k])`。用一个变量滚动维护这个「最小前缀」即可 O(n) 判定。
- **能二分的前提是单调**：`check(x)` 关于 `x` 单调递减（`x` 越大越难满足）。写判定之前必须先确认这一点，否则二分不成立。
- **二分的是实数**：循环条件用 `while left + 1e-5 < right` 控制精度，不能用整数二分的 `left <= right`；更新时把 `mid` 直接赋给某一侧，**不做 ±1**。
- **二分区间取 `[min(nums), max(nums)]`**：任何子数组的平均值都落在元素最小值与最大值之间。由于 `nums` 含负数，下界取 `0` 是错的；取真实最值既正确又能显著收窄区间、减少迭代次数。

## 三、代码实现

### 最终代码

```python
from typing import List


class Solution:
    def findMaxAverage(self, nums: List[int], k: int) -> float:
        n = len(nums)

        def check(mid: float) -> bool:
            # 判定：是否存在长度 >= k 的子数组，其平均值 >= mid
            prefix = [0] * (n + 1)
            for i in range(n):
                prefix[i + 1] = prefix[i] + (nums[i] - mid)

            min_pre = 0                      # 维护 min(prefix[0 .. i-k])，初始为 prefix[0] = 0
            for i in range(k, n + 1):
                min_pre = min(min_pre, prefix[i - k])
                if prefix[i] >= min_pre:     # 存在 j <= i-k 使 prefix[i] - prefix[j] >= 0
                    return True
            return False

        left = min(nums)
        right = max(nums)
        while left + 1e-5 < right:           # 实数二分，收敛到宽度 <= 1e-5
            mid = (left + right) / 2
            if check(mid):
                left = mid                   # mid 可行，答案在右半区
            else:
                right = mid                  # mid 不可行，答案在左半区
        return left
```

> 说明：截图里的代码把 `mid` 标注成了 `int`，但 `mid` 实际是浮点数，这里改成 `float`；`from typing import List` 截图里没有、已补。

## 四、复杂度分析

| 版本 | 时间复杂度 | 空间复杂度 |
| :--- | :--- | :--- |
| **最终代码** | O(n · log(R / ε)) | O(n) |
| 朴素解法（枚举所有区间） | O(n²) | O(1) |
| 理论下界 | Ω(n)（至少要把数组读一遍） | O(n) |

> 复杂度中的 **n** 指数组 `nums` 的长度；**R = max(nums) - min(nums)** 是二分区间初始宽度，**ε = 1e-5** 是要求的精度。
> 二分轮数约为 `log2(R / ε)`：本题 `R ≤ 2×10^4`、`ε = 10^-5`，即 `log2(2×10^9) ≈ 31` 轮，每轮判定 O(n)，合计约 O(n log(R/ε))。
> 朴素解法每一段的平均值都能用前缀和 O(1) 求出，所以是严格的 O(n²)，而不是 O(n³)。

## 五、优化评估

**结论**：时间上已经是该思路下的最优结构，无法再用更低的渐近复杂度完成；**空间有 O(n) → O(k) 的压缩余地，但在本题数据规模下没有必要**。

### 瓶颈分析

时间被两件事卡住：① 二分的轮数由「精度要求」决定，是题目给定的，不能减少；② 每一轮判定都必须扫一遍数组（O(n)），因为任意一个元素都可能改变判定结果。两者相乘即为 O(n log(R/ε))，这与「先线性判定、再对判定结果二分」这一范式的时间下界一致。

空间上唯一的开销是 `check` 里的 `prefix` 数组。而判定其实只用到两个值：`prefix[i]`（当前）和 `prefix[i-k]`（k 步之前）。

### 可优化空间

- **空间**：既然只依赖 `prefix[i]` 与 `prefix[i-k]`，就不必保存整条前缀和 —— 用一个长度恒为 `k` 的滚动缓冲保存最近的 k 个前缀值，最老的那个正好就是 `prefix[i-k]`，空间降到 O(k)。
- **时间**：无。二分轮数由精度决定，判定次数由「纯线性」这一下界兜住，没有可省的部分。
- **题外话**：`n ≤ 10^4`，O(n) 空间只有几万个浮点数，压缩到 O(k) 没有实际收益，原写法更易读 —— 下面的优化版仅作思路记录。

### 优化代码

```python
from collections import deque
from typing import List


class Solution:
    def findMaxAverage(self, nums: List[int], k: int) -> float:
        n = len(nums)

        def check(mid: float) -> bool:
            # 只保留最近 k 个前缀值，队首出队的恰好是 prefix[i-k]
            hist = deque([0.0])              # 初始存放 prefix[0] = 0
            cur = 0.0                        # 当前的 prefix[i]
            min_pre = 0.0
            for i in range(1, n + 1):
                cur += nums[i - 1] - mid
                if i < k:
                    hist.append(cur)
                    continue
                min_pre = min(min_pre, hist.popleft())   # 出队值就是 prefix[i-k]
                if cur >= min_pre:
                    return True
                hist.append(cur)
            return False

        left = min(nums)
        right = max(nums)
        while left + 1e-5 < right:
            mid = (left + right) / 2
            if check(mid):
                left = mid
            else:
                right = mid
        return left
```

**优化理由**：判定式 `prefix[i] - prefix[j] >= 0 (j <= i-k)` 只用到一组「相隔 k 的前缀值」，因此把前缀和数组换成滚动缓冲即可，空间由 O(n) 降为 O(k)，时间复杂度不变。

### 常数级优化（可选）

- **`right` 的下界可以再收紧一点**：下界除了 `min(nums)`，还可以取「所有长度恰为 k 的窗口平均值的最大值」作为初始下界（它一定是可行解），能把二分区间进一步缩小、减少几轮迭代。代价是要先 O(n) 扫一遍所有长度 k 的窗口，得不偿失，本题不建议。
- **内层汇总用 `accumulate`**：`prefix` 可用 `itertools.accumulate` 一次生成，省掉显式循环，但可读性下降，非必要不改。

## 六、易错点与总结

### 易错点

- **把「长度 ≥ k」当成「长度恰好 k」**：只枚举长度为 `k` 的窗口会漏掉更长的更优子数组（示例里长度 5、6 的区间也必须考虑）。
- **`min_pre` 的更新时机**：必须先 `min_pre = min(min_pre, prefix[i-k])` 再与 `prefix[i]` 比较，这样才保证 `j <= i-k`（即窗口长度 ≥ k）。若写成 `prefix[i-k+1]` 或忘了更新，等价于把窗口错误地限制成长度恰好 `k` 或 `k+1`。
- **实数二分的终止条件**：不能用 `while left <= right`（实数会无限收敛、永不相等，直接死循环），要用宽度阈值 `left + 1e-5 < right`；更新时把 `mid` 直接赋给 `left`/`right`，**不能 ±1**。
- **二分区间不能随便取**：`nums` 含负数，下界若写成 `0`，`check` 在负区间上的语义就错了；必须取 `[min(nums), max(nums)]`。
- **前缀和下标差一位**：`prefix` 长度为 `n+1`、`prefix[0] = 0`、`prefix[i]` 对应 `nums[0..i-1]`；`for i in range(k, n + 1)` 与 `prefix[i-k]` 的配对最容易写错。
- **类型标注**：原代码把 `mid` 标成 `int`，实际是浮点，应为 `float`（不影响运行，但会误导阅读）。

### 题型套路沉淀

- **二分答案（求极值 / 最大化最小值 / 最小化最大值）的识别信号**：**「直接求最优值很难，但给定一个候选值 `x`，判断它是否可行很容易」**。一旦出现这个特征，就优先考虑把问题转成「判定 + 二分」。
- **固定三步**：① 写出 `check(x)`（通常是一次线性扫描或前缀和）；② 验证 `check(x)` 关于 `x` **单调**（真值集合是一个前缀区间）；③ 确定二分区间与端点更新方式。实数答案用**精度阈值**收敛并返回下界；整数答案用 `left <= right` 并在更新时 `±1`。
- **「平均值 / 比率」类问题的一个通用转化**：比较平均值时，把每个元素整体减去候选值 `x`，就变成比较「和是否 ≥ 0」—— 把不可累加的平均值转化为可累加的和，是这类题的标志性动作。
- **本题的判定子问题是独立的知识点**：「是否存在长度 ≥ k 的子数组和 ≥ 0」= 前缀和 + 滚动维护最小前缀，可直接复用。
