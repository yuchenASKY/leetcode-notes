# 744. 寻找比目标字母大的最小字母

> **难度**：简单
> **标签**：二分查找 · 数组
> **原题链接**：https://leetcode.cn/problems/find-smallest-letter-greater-than-target/

---

## 一、题目描述

给定一个按**非递减顺序**排好序的字符数组 `letters` 和一个字符 `target`，返回 `letters` 中**严格大于** `target` 的最小字符；若不存在这样的字符，则返回 `letters[0]`。

### 示例

```text
输入：letters = ['c','f','j'], target = 'a'
输出：'c'
解释：字典序上比 'a' 大的最小字符是 'c'。

输入：letters = ['c','f','j'], target = 'c'
输出：'f'
解释：比 'c' 严格大的最小字符是 'f'（'c' 本身不算）。

输入：letters = ['x','x','y','y'], target = 'z'
输出：'x'
解释：没有字符比 'z' 大，返回首元素。
```

### 约束条件

- `2 <= letters.length <= 10^4`
- `letters[i]` 是一个小写字母
- `letters` 按**非递减顺序**排序
- `letters` 最少包含两个不同的字母（排除"全部字符相同"的退化输入；此时二分仍然正确，回绕返回的 `letters[0]` 就是那个唯一字符）
- `target` 是一个小写字母

---

## 二、解题思路

### 核心思想

把「找最小的大于 `target` 的字符」翻译成「**找有序数组中第一个满足 `letters[i] > target` 的下标**」。这个谓词在非递减数组上必然呈「一段 False + 一段 True」，单调性一到手就可以二分；「不存在则回绕取首元素」这条约定放在二分之外单独处理。

### 思路演进

1. **朴素解法**：从左往右线性扫描，遇到第一个大于 `target` 的字符就返回；扫完都没有就返回 `letters[0]`。时间 O(n)、空间 O(1)。题面 n ≤ 10^4，这个写法提交上去也是 0 ms —— 优化它的理由不是"会超时"，而是**有序性把上界压到了对数级**，白给的信息不用可惜。
2. **瓶颈定位**：线性扫描完全没用到「数组已按非递减顺序排序」这个免费前提。它在做一件没必要的事 —— 逐格确认"前面所有的字符都不大于 `target`"；而有序性意味着这件事**可以一次性批量排除**。
3. **关键转化**：定义谓词 `P(i) = (letters[i] > target)`。因为 `letters` 非递减、`target` 固定，所以 i 增大时 `letters[i]` 不减，一旦某个位置为 True，它右边全是 True ⇒ `P` 的取值必然是「`False…False True…True`」。
   于是**答案 = 第一个 `P(i) == True` 的下标 p**（若不存在，按题面规约 p = n）。谓词单调 ⟺ 可二分：每轮取中点比较一次，True 就把右界收到 mid、False 就把左界推到 mid，一次比较排除一半。
   这个量有正式名字：**严格上界**（C++ 的 `upper_bound`、Python 的 `bisect_right`）—— 与 `lower_bound`（第一个 **≥** target 的位置）只差一个等号，本题要的是前者。
4. **最优解**（截图中的最终代码）：用**开区间哨兵**写法 `left = -1, right = n` 维护不变量，循环到 `left + 1 == right` 时 `right` 就是 p；`p == n`（不存在更大字符）的越界情形交给调用方返回 `letters[0]`。
   离理论下界的距离：比较次数约 ⌈log₂(n+1)⌉ = 14（n = 10^4），而决策树下界同为 ⌈log₂(n+1)⌉ ⇒ **比较次数已经到顶**，剩下的只有常数项。

### 正确性论证

不变量（`n = len(letters)`；把"第一个大于 target 的下标，不存在时取 n"记为 p）：

1. 若 `left >= 0`，则 `letters[left] <= target`；
2. 若 `right <= n - 1`，则 `letters[right] > target`；
3. **p ∈ (left, right]** —— 开区间 `(left, right)` 内永远含有答案。

- **初始**：`left = -1`、`right = n`。此时 (1)(2) 对空集成立，`p <= n = right` 使 (3) 成立。
- **归纳**：由 `left + 1 < right` 可得 `left < mid < right`（`mid = (left + right) // 2` 落在开区间内部）。若 `letters[mid] > target`，则 mid 自身满足谓词 ⇒ `p <= mid`，令 `right = mid` 后 (2) 成立且 `p ∈ (left, mid]`；否则 `mid < p`，令 `left = mid` 后 (1) 成立且 `p ∈ (mid, right]`。
- **终止**：`left + 1 == right` 与 `p ∈ (left, right]` 联立 ⇒ `p = left + 1 = right`，故 `return right` 正确；`p == n` 时外层返回 `letters[0]`，正是题面要求。

### 判据族定位

- 本题属**「谓词边界二分」族**：二分对象是**下标**，求一个单调谓词的**首个 True 位置**，答案就落在下标域里。
- **本族判据**：`P(i) = (letters[i] > target)` 在非递减数组上单调（False 前缀 + True 后缀）。谓词单调 ⟺ 可二分，这是本族唯一的前提。
- 与相邻族的差别（别串用）：
  - **存在性二分**（问"某个值在不在里面"）：判据是 `letters[mid] == target` 这类"点命中"，不涉及边界，命中即可返回；
  - **二分答案**：二分的对象是**答案值本身**（不是下标），谓词是"以 x 为答案可不可行"，通常还要配一个 O(n) 的 `check`；
  - **本题**：二分对象是下标，谓词直接由"数组元素 vs target"给出，没有额外的 `check` 成本。
- 回绕**不是本族的一般形态**，而是本题题面附加的一条「越界 → 取首元素」规约，属调用方约定，不改变二分本身。

### 关键点

- **严格 vs 非严格**：谓词必须是 `letters[mid] > target`。写成 `>=` 求的是 `lower_bound`，当 `target` 恰好出现在数组中时会返回 `target` 自身 —— 示例 2（`['c','f','j'], target='c'`）会立刻从 `'f'` 错成 `'c'`。
- **回绕不能塞进谓词里**：答案下标等于 `p`（`p < n`）或 `0`（`p == n`），作为 p 的函数在 `p = n` 处从 n 跳回 0，**不单调** ⇒ 不存在能同时表达两种情形的单一单调谓词。必须"先求严格上界，再单独判越界"。
- **`left = -1` 是只当边界、永不读值的哨兵**：代码只访问 `letters[mid]`，而 `left < mid < right` 保证 `mid ∈ [0, n-1]`，所以负数下标不会触发 Python「负索引静默取末尾元素」的坑。
- **二分模板必须自洽**：开区间（`left + 1 < right`，两侧都赋 `mid`）与闭区间（`left <= right`，赋 `mid ± 1`）是两套模板，混用会死循环。本题用的是开区间哨兵版。

## 三、代码实现

### 最终代码

截图中的通过版本。截图未裁掉任何行（最后一行 `return letters[start]` 完整可见）；也没有需要补的 `import` —— `list[str]` 是内置泛型别名，Python 3.9+ 可直接用。

```python
class Solution:
    def lower_bound(self, letters: list[str], target: str) -> str:
        left = -1
        right = len(letters)
        while left + 1 < right:
            mid = (left + right) // 2
            if letters[mid] > target:
                right = mid
            else:
                left = mid
        return right

    def nextGreatestLetter(self, letters: list[str], target: str) -> str:
        start = self.lower_bound(letters, target)
        if start == len(letters):
            return letters[0]
        return letters[start]
```

> 命名备注：这里被命名为 `lower_bound` 的方法，实际求的是「第一个**严格大于** target 的下标」，即 C++ `upper_bound` / Python `bisect_right`；`lower_bound` 的惯例含义是「第一个 **≥** target 的位置」。详见「五、优化评估」。

## 四、复杂度分析

| 版本 | 时间复杂度 | 空间复杂度 |
| :--- | :--- | :--- |
| **最终代码**（手写开区间二分） | O(log n) | O(1) |
| 朴素解法（线性扫描） | O(n) | O(1) |
| 理论下界（不预处理） | Ω(log n) 次比较 | O(1) |

> 复杂度中的 **n = `letters` 的长度**（`target` 只是单个字符，不构成规模）。
>
> - 比较次数：`while` 每轮把开区间 `(left, right)` 的长度至少折半，约 ⌈log₂(n+1)⌉ 次 —— n = 10^4 时是 14 次。
> - 理论下界：答案是「n+1 个候选位置」之一（含"不存在"），决策树下界同为 ⌈log₂(n+1)⌉，故**比较次数已到顶**。空间 O(1)：只用两个下标变量，不随 n 增长。

## 五、优化评估

**结论**：渐进复杂度已到（不预处理前提下）的下界，**没有可再降的渐进空间**；能动的只有常数项 —— 把手写循环换成 C 实现的 `bisect_right`（实测 6.41×）。

### 瓶颈分析

手写二分每次迭代全在 Python 解释器内完成：一次加法、一次整除、一次下标、一次字符串比较、一次分支，n = 10^4 时约 14 轮 ⇒ 实测约 1.3 µs/查询。渐进上无空间可调，耗时全在解释器开销上。

「已知数组有序」这个前提下，**O(log n) 为什么不可能再被突破**，三条依据：

1. **决策树下界**：「第一个 > target 的位置」有 n+1 种可能取值（含"不存在"），任何基于比较的算法至少要 ⌈log₂(n+1)⌉ 次比较才能区分开；
2. **「字母表只有 26 个」这个天然小值域并不能白送 O(1)**：想用它必须先做 O(n) 预处理（26 位掩码或计数数组），而无预处理的二分只要 O(log n) ⇒ **单次调用下预处理更贵**（实测比线性扫描还慢 4.46×，见「七、验证记录」场景 B）；
3. **二分的"已排序"前提是题面免费给的**：若输入无序，就得先付 O(n log n) 排序（或 O(n) 计数/建掩码），那时 O(log n) 的结论才需要重新讨论。

### 可优化空间

只做常数项优化：`bisect.bisect_right(letters, target)` 的语义与手写版**完全一致** —— 都是"第一个 **>** target 的下标"，返回值域同为 `[0, n]`，越界情形仍由调用方处理。它把整段循环搬进了 C。

### 优化代码

```python
from bisect import bisect_right


class Solution:
    def nextGreatestLetter(self, letters: list[str], target: str) -> str:
        i = bisect_right(letters, target)          # 第一个 > target 的下标，落在 [0, n]
        return letters[0] if i == len(letters) else letters[i]
```

**优化理由**：比较逻辑与手写版逐轮等价，但迭代发生在 C 里，省掉 Python 层的算术/下标/分支与一次 `self.` 方法调用。实测（n = 10^4、10^5 次查询）：134.2 ms → 20.9 ms，**6.41×**。

### 常数级优化（可选）

均已在同一轮基准里对照过（数字见「七、验证记录」）：

| 改法 | 实测 | 结论 |
| :--- | :--- | :--- |
| `bisect_right` 替代手写循环 | **6.41×** | 唯一有量级意义的改动 |
| 取模回绕 `letters[bisect_right(...) % len(letters)]` | 0.95×（慢 1.05×） | 写法更短、无分支，但多付一次取模；且要求读者自己论证"返回值只可能等于 n、不会超过 n"。**可读性与速度双输，不推荐** |
| 内联 helper（省一次方法查找 + 调用） | 1.03× | 收益真实但极小（10^5 次查询共省 3.7 ms ≈ 37 ns/次），损失可读性 |
| 等价手段：`@staticmethod` 或写成模块级函数 | 同 1.03× 一档 | 省掉 `self.` 绑定的同源收益 |

另外两条**静态推导**（不涉及运行）值得留意：

- **改名**：`lower_bound` 求的是严格上界，应叫 `upper_bound` / `first_greater`。这个错名有实质风险 —— 顺着名字很容易把比较改成 `>=` 去"对上语义"，而那正是本题最容易错的地方。
- **`left = -1` 的哨兵约定要写在注释里**：它永远不会被读值（mid 恒在区间内），但改写代码的人若顺手读一次 `letters[left]`，Python 会静默取到 `letters[-1]`。

## 六、易错点与总结

### 易错点

- **`>` 写成 `>=`（本题最致命）**：那是在求 `lower_bound`。示例 2 立刻暴露 —— `letters = ['c','f','j'], target = 'c'` 会返回 `'c'` 而非 `'f'`。
- **忘记回绕，或回绕写法不对**：`p == n` 时必须返回 `letters[0]`；直接写 `letters[p]` 在 `p == n` 时 `IndexError`。另注意 `p` 只可能等于 `n`，不会超过 n（这是"返回值落在 [0, n]"的直接推论）。
- **混用两套二分模板导致死循环**：开区间 `while left + 1 < right` 必须两侧都赋 `mid`；闭区间 `while left <= right` 必须赋 `mid ± 1`。典型错法 `while left < right` 配 `right = mid`，在区间只剩 2 个元素时不收敛。
- **哨兵被读值**：本写法从不访问 `letters[left]`，所以 `left = -1` 安全；一旦调试时顺手打印 `letters[left]`，Python 会**静默**返回最后一个元素（不报错、结果只是错）。
- **误以为能用字符位次直接算答案**：`target` 本身可能不在 `letters` 里，字符之间的"距离"没有意义 —— 必须回到**下标域**做二分。
- **漏看"非递减"是排序而非严格递增**：数组有重复元素是常态（示例 3 就是 `['x','x','y','y']`），二分的谓词不受影响，但别指望"每个字符只出现一次"来简化判断。

### 题型套路沉淀

- **有序数组 + 找边界 ⇒ 二分求「首个满足谓词的位置」**。上手先问三件事：
  1. 谓词在数组上**单调**吗（False 前缀 + True 后缀）？
  2. **严格还是非严格**（`>` vs `>=`，即 `upper_bound` vs `lower_bound`）？
  3. 答案可能落在**哨兵值**上（本题 p ∈ [0, n]，含 n）时，调用方怎么处理越界？
- **开区间哨兵模板**（不会死循环的版本，推荐形成肌肉记忆）：

  ```text
  left, right = lo - 1, hi + 1        # 哨兵，永不作为答案读值
  while left + 1 < right:
      mid = (left + right) // 2
      if P(mid):  right = mid         # 两侧写法一致，不需要 ±1
      else:       left = mid
  return right                        # 首个 True 的位置，可能等于 hi + 1
  ```

  好处：`mid` 恒落在开区间内、区间每轮折半 ⇒ 天然终止；代价是返回值域比原数组多两个端点，**调用方必须处理越界**。
- Python 里「求上界 / 下界」优先直接用 `bisect_right` / `bisect_left`（C 实现），只有谓词需要自定义时才手写模板。

  - 但**预构建**后每查询确实比 `bisect_right` 快 1.36×（0.155 µs vs 0.212 µs）；
  - 两者的分界点由"构建成本 ÷ 每查询省下的时间"给出：0.62 ms ÷ 0.056 µs ≈ **1.1×10^4 ≈ n** ⇒ **只有查询次数 Q 与 n 同量级以上，预处理才摊得回来**。本题 Q = 1，所以这条路线（以及一切"小值域 → O(1)"的路线）在本题不成立 —— 这正是「O(log n) 已是下界」的量化依据，也说明**值域小给的是"预处理后的 O(1) 查询"，不是"免预处理的 O(1) 算法"**。
