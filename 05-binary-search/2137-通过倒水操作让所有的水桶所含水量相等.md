# 2137. 通过倒水操作让所有的水桶所含水量相等

> **难度**：中等
> **标签**：二分 · 数组
> **原题链接**：https://leetcode.cn/problems/pour-water-between-buckets-to-make-water-levels-equal/

---

## 一、题目描述

给定 n 个水桶的水量数组 `buckets`（第 i 个桶有 `buckets[i]` 升水）。可以把任意水量（可以是小数）从任意一个水桶倒进另一个水桶，但**每倒出 k 升水，会有 `loss%` 洒掉**，接收方实际只收到 `k × (1 - loss/100)` 升。

问：把各桶水量调成**完全相同**之后，每个桶里能有**最多**多少水。误差不超过 `10^-5` 即算通过。

### 示例

```text
输入：buckets = [1,2,7], loss = 80
输出：2.00000
解释：从水桶 2 向水桶 0 倒 5 升水。5 * 80% = 4 升会洒掉，水桶 0 只获得 5 - 4 = 1 升。
     此时三个桶都含有 2 升水，所以返回 2。

输入：buckets = [2,4,6], loss = 50
输出：3.50000
解释：先从水桶 1 向水桶 0 倒 0.5 升（水桶 0 收到 0.25），此时 buckets = [2.25, 3.5, 6]；
     再从水桶 2 向水桶 0 倒 2.5 升（水桶 0 收到 1.25），三桶均变为 3.5。

输入：buckets = [3,3,3,3], loss = 40
输出：3.00000
解释：所有水桶的水量本来就相同。
```

### 约束条件

- `1 <= buckets.length <= 10^5`
- `0 <= buckets[i] <= 10^5`
- `0 <= loss <= 99`

## 二、解题思路

### 核心思想

**把「求最大可行水量」变成「判定某个水量是否可行」，再用单调性二分。**

答案是一个实数、无法枚举，但可行性关于目标水量单调：**目标越低越容易做到**。于是可行域一定是一段前缀 `[0, t*]`，二分找右端点即可。每次判定只需一趟 O(n) 遍历：统计「缺水桶的总缺口」与「富余桶倒出去后对方**实际**能收到的总量」，比大小。

### 思路演进

1. **暴力解法**：直接把「目标水量 t」当枚举量。但 t 是实数 —— 若按步长 `ε` 撒网格，需要 `max(buckets)/ε ≈ 10^5 / 10^-5 = 10^10` 个候选点，每个点判定 O(n)，时间 O(n·R/ε)，完全不可行。
   另一条思路是「列方程直接解」，但 `loss` 让倒出去的水和收到的水不守恒，桶与桶之间的调度关系无法用一个线性方程一次解出，闭式解不好推。

2. **观察到**：**可行性对 t 单调** —— 若目标 t 可行，则任何 `t' < t` 也一定可行（每个缺水桶的缺口更小、每个富余桶要送出的水更少，原来够用的水量只会更宽裕）。⇒ 可行/不可行在数轴上是一个干净的分界，**答案 = 最大的可行 t**。

3. **优化为**：用**二分**代替枚举，把 `R/ε ≈ 10^10` 个候选点压到 `log₂(R/ε) ≈ 54` 次。剩下的落点就是判定函数本身：
   - 记 `rate = 1 - loss/100` 为「倒出 1 升、对方实际收到的比例」；
   - 遍历每个桶：若 `i > t`，它要倒出 `i - t`，对总供水量的**净贡献**是 `(i - t) × rate`；若 `i <= t`，它需要补 `t - i`；
   - 令 `ans = 缺口总和 - 净供水总和`。**`ans <= 0` 即表示「能送到的」不少于「缺的」，t 可行**。
   判定是 O(n)，总体 O(n·log(R/ε))。

4. **（还能更精确，见「五、优化评估」）**：`g(t) = rate × Σ_{i>t}(i - t) - Σ_{i<t}(t - i)` 关于 t 连续、单调递减，且只在每个桶的水量处折一次，因此排序 + 前缀和就能逐段解出 `g(t) = 0` 的精确根，得到 O(n log n) 的无误差解。代价是代码变长、要处理分段边界，而浮点二分 54 轮已足够达到题目要求的 1e-5 精度。

### 关键点

- **判据方向别写反**：只把「倒出的水」乘 `rate`，缺口侧保持原值；两侧同时乘 rate 会放大误差并改变不等号方向。
- **判定式写 `ans < 10^-5` 而不是 `ans <= 0`**：二分里的 `mid` 永远落不到最优点上，用与题目同量级的容差收尾，等价于「缺口比供水多出的量可忽略」。注意这会让 `ans ∈ (0, 1e-5)` 也判为可行，也就是目标水位可能被高估不到 `1e-5`，仍然在题目容差之内。
- **浮点二分不能用 `while left < right`**：实数区间永远缩不到一个点，会死循环。要么固定轮数（54 轮足够覆盖 10^5 的值域），要么像本题这样写成 `while left + eps < right`。
- **初始区间要一真一假**：`left = min(buckets) - 1` 一定可行（没有任何桶缺水，`ans < 0`），`right = max(buckets) + 1` 一定不可行（不倒水时也不会凭空产生水，每桶最多只能是原本的最大值）。这样区间一定含解且两端类型明确，收敛后 `left` 就是答案。
- **不必模拟倒水过程**：只要总量上「缺的能被补上」，具体怎么倒无序关心（可以一桶一桶地倒，允许多次、允许小数），所以判定可以退化成纯统计。

## 三、代码实现

### 最终代码

```python
from typing import List          # 截图里没有，已补


class Solution:
    def equalizeWater(self, buckets: List[int], loss: int) -> float:
        rate = 1 - loss * 0.01          # 倒出 1 升，对方实际收到的比例

        def check(t: float) -> bool:    # 目标水量 t 是否可达（原截图标注为 int，已改为 float）
            ans = 0.0
            for i in buckets:
                if i <= t:
                    ans += t - i                  # 缺口：这个桶还需要补多少水
                else:
                    ans -= (i - t) * rate         # 供水：倒出去的水实际能送到别处的量
            if ans < 10 ** -5:
                return True
            return False

        left = min(buckets) - 1         # 一定可行
        right = max(buckets) + 1        # 一定不可行
        while left + 10 ** -5 < right:
            mid = (left + right) / 2
            if check(mid):
                left = mid
            else:
                right = mid
        return left
```

## 四、复杂度分析

| 版本 | 时间复杂度 | 空间复杂度 |
| :--- | :--- | :--- |
| **最终代码** | O(n · log(R/ε)) | O(1) |
| 朴素解法 | O(n · R/ε) | O(1) |
| 理论下界 | O(n) | O(1) |

> 复杂度中的 n 指水桶数量 `buckets.length`；`R` 指 `max(buckets) - min(buckets)`（值域宽度，量级 ≤ 10^5），`ε` 是二分收敛阈值 `10^-5`。`log(R/ε) ≈ 54`，即二分约 54 轮，每轮判定 O(n)，所以总共约 `54n` 次操作。

## 五、优化评估

**结论**：在「浮点二分答案」这条路线上，**已是实用最优**；唯一能进一步压缩复杂度的方式是换一条求根路线。

### 瓶颈分析

- 二分轮数由精度决定：`log₂(R/ε) ≈ 54`，且 `ε` 再收紧一个数量级也只多 3~4 轮，所以「轮数」已经不是瓶颈。
- 真正的开销全在 `check`：它必须扫完整个数组（每个桶的状态都由 `t` 决定，不扫描就无法知道缺/余），因此每轮判定 Ω(n) 不可省。
- 空间上没有可压缩的东西：只用常数个浮点变量，没有额外容器。

### 可优化空间

- **理论下界 O(n)**：任何算法都必须至少读一遍数组（否则漏看的桶的水量可能让答案完全不同），所以时间不可能低于线性。
- **精确解路线**：定义 `g(t) = rate · Σ_{i>t}(i - t) - Σ_{i<t}(t - i)`。它关于 t 连续、严格单调递减（`g'(t) = -rate · (大于 t 的桶数) - (小于 t 的桶数) < 0`），且只在每个桶的水量处改变斜率一次。因此在任意两个相邻桶值之间 `g` 是一条直线，可以 O(1) 解出该段上的根 —— 排序 + 前缀和后逐段扫一遍即可得到**无浮点误差的精确答案**，时间复杂度 O(n log n)（瓶颈在排序）。代价是需要额外 O(n) 空间存排序结果与前缀和，且要仔细处理重复值 / 分段边界。
- 取舍：题目只要求 `10^-5` 精度，二分解法代码短、无需处理边界，因此本题仍推荐二分；只有当精度要求极高（或必须精确输出）时，精确解路线才更划算。

### 优化代码

精确解（排序 + 前缀和逐段求根），结果与二分解一致且无精度损失：

```python
from itertools import accumulate
from typing import List


class Solution:
    def equalizeWater(self, buckets: List[int], loss: int) -> float:
        rate = 1 - loss / 100
        a = sorted(buckets)
        n = len(a)
        pre = list(accumulate(a, initial=0))    # pre[k] = a[0] + ... + a[k-1]
        total = pre[n]

        # 设恰好有 k 个桶的水量 < t，则 g(t) = rate*(total-pre[k]) + pre[k] - t*(rate*(n-k) + k)
        # 令 g(t) = 0 解出该段上的根，落在 [a[k-1], a[k]] 内即为全局最优解
        for k in range(n + 1):
            x = (rate * (total - pre[k]) + pre[k]) / (rate * (n - k) + k)
            lo = a[k - 1] if k > 0 else -1.0
            hi = a[k] if k < n else float("inf")
            if lo - 1e-12 <= x <= hi + 1e-12:
                return x
        return 0.0
```

**优化理由**：把「二分逼近」换成「直接解方程」。因为 `g` 在每段内是直线，根可以用前缀和 O(1) 算出，于是不再需要 54 轮扫描，也彻底摆脱 `ε` 的精度依赖；代价是必须排序，复杂度由 O(n log(R/ε)) 变为 O(n log n)。

### 常数级优化（可选）

- `check` 里把手写 `for` 换成 `sum` / 生成器表达式（如 `ans = sum(t - i if i <= t else -(i - t) * rate for i in buckets)`）只是写法更短，**每轮仍要遍历全部元素**，复杂度和实际开销同量级，不必强改。
- `10 ** -5` 是浮点幂运算，写成 `1e-5` 字面量更直观（也少一次运算），但都只在循环外/每轮一次，影响可忽略。
- 值得保留的两处：`rate` 在循环外算好（避免每轮重复乘 `0.01`）；`left` / `right` 用 `min` / `max` 初始化一次即可。

## 六、易错点与总结

### 易错点

- **判定方向写反**：把 `(i - t) * rate` 写成了 `(i - t) / rate`，或给缺口侧也乘了 `rate`，会让答案整体偏移。
- **浮点二分写死循环**：用 `while left < right` 判收敛，实数区间永不相等，直接超时。
- **容差取太大**：判定阈值若写成 `1e-3` 之类的粗容差，水位会被系统性高估，超出题目容差；取 `1e-5` 与题目要求同量级才安全。
- **初始区间不含解**：`right` 若取 `max(buckets)` 而该点恰好可行（例如所有桶水量相同时），二分会卡在错误的一侧；写成 `max + 1` / `min - 1` 保证两端一假一真。
- **`loss` 的口径**：`loss` 是百分数（`loss = 80` 表示洒掉 80%），要除以 100，别当成 0.8 直接用。

### 题型套路沉淀

- **二分答案（浮点型）的三件套**：① 判定函数 `check(t)` 只回答「可行/不可行」；② 证明可行性对 t 单调；③ 初始区间构造为一假一真，收敛用 `while r - l > eps`（或固定 54 轮）。
- **「猜一个答案 + O(n) 验证」的识别信号**：题目要求的是一个**最大值 / 最小值**且答案是可比较的实数或大范围整数，同时**直接构造答案很难、但验证一个候选答案很容易**（本题验证只需统计缺/余），就应该往二分答案上想。
- **有损耗 / 折损的物料题**：把「送去的水」与「收到水」分开算，判定时只对「送出侧」乘效率系数，**不要两侧同时缩放** —— 这是这类题最容易写错的地方。
- **浮点二分的精度取法**：收敛阈值一般取与题目容差相同或更小一个数量级；轮数固定写法 `for _ in range(60)` 也可，能覆盖 10^5 值域到 1e-13。
