# 2064. 分配给商店的最多商品的最小值

> **难度**：中等
> **标签**：二分查找 · 贪心 · 数组
> **原题链接**：https://leetcode.cn/problems/minimized-maximum-of-products-distributed-to-any-store/

---

## 一、题目描述

有 `n` 间商店和 `m` 种商品，第 `i` 种商品共有 `quantities[i]` 件。要把**所有**商品分到商店里，规则有两条：

- 一间商店**至多只能放一种商品**，但件数不限；
- 允许有商店分到 0 件。

设 `x` 为所有商店中「单店商品件数」的最大值，求 `x` 的最小可能值。

### 示例

```text
输入：n = 6, quantities = [11,6]
输出：3
解释：11 件商品 0 分给 4 间店（2,3,3,3），6 件商品 1 分给 2 间店（3,3）；
      所有商店的最大件数 max(2,3,3,3,3,3) = 3。

输入：n = 7, quantities = [15,10,10]
输出：5
解释：三种商品各分给 3 / 2 / 2 间店，每间店都恰好 5 件，最大值仍为 5。

输入：n = 1, quantities = [100000]
输出：100000
```

### 约束条件

- `m == quantities.length`
- `1 <= m <= n <= 10^5`
- `1 <= quantities[i] <= 10^5`

---

## 二、解题思路

### 核心思想

**答案 `x` 具有单调性：`x` 越大越容易可行 —— 于是不枚举方案，而是二分答案 `x`，用一次 O(m) 的贪心判定 `check(x)` 收/放区间。**

### 思路演进

1. **暴力解法**：直接搜索所有分配方案。方案数是把 `m` 组商品拆成至多 `n` 份的全部拆法，组合爆炸，无法枚举。

   退一步，改成「从小到大枚举 `x = 1, 2, 3, …`，第一个可行的 `x` 就是答案」。判定单次 `x` 至少要遍历一遍 `quantities`，而值域到 10^5，于是整体 O(m · max(quantities)) —— 本题上限下约 10^10 量级，不可行。

2. **观察到**：`check(x)` 的返回值关于 `x` **单调不减**。

   因为「每间店至多放 `x` 件」这条限制一旦放宽到 `x' > x`，原先的分配方案原封不动仍然合法；反过来，`x` 不可行则更小的值必然也不可行。也就是说，可行/不可行在数轴上形成**一个分界点**：`< 答案` 一律不可行，`>= 答案` 一律可行。

   单调性是二分的唯一前提，不需要方案有任何结构。

3. **优化为**：在值域 `[1, max(quantities)]` 上二分这个分界点。每次用贪心算出「至少要多少家店」，与 `n` 比较。

   贪心判定怎么算：商品之间**互不干扰**（一间店只能装一种商品），所以可以逐种独立计算再相加。第 `i` 种商品共 `quantities[i]` 件、每店上限 `x` 件，最少需要 `ceil(quantities[i] / x)` 家店（写成整数式即 `(quantities[i] - 1) // x + 1`）。把 `m` 种商品的需求相加，总和 `<= n` 即说明该 `x` 可行。

### 关键点

- **「一间店只能有一种商品」正是可加性的来源**：它把整题拆成 `m` 个互不影响的子问题，否则每种商品的店数需求无法直接相加（店会互相争抢）。
- **上取整必须用整数写法**：`(q - 1) // x + 1`。用 `q // x` 会漏算、用浮点 `ceil(q / x)` 在 10^5 量级虽不溢出但没必要引入误差。
- **二分区间取左开右闭 `(left, right]`**：维护「`left` 恒不可行、`right` 恒可行」的不变式，结束时答案就是 `right`。
  - `right` 初值取 `max(quantities) + 1`：此时每种商品都只需 1 家店，共 `m` 家，而题设保证 `m <= n`，必然可行。
  - `left` 初值取 `0` 只作**约定俗成的下界哨兵**，它永远不会被判定 —— 因为 `right >= max(quantities) + 1 >= 2`，所以 `mid = (left + right) // 2 >= 1`。正因如此，`check` 里那个 `// x` 不会踩到除零。
- **收敛条件是 `left + 1 < right`**，不是闭区间的 `left < right`。左开右闭写法下把两者混用会死循环。
- **判定里顺手剪枝**：累加过程中一旦 `temp > n` 立即返回 `False`，不必把 `quantities` 算完。

## 三、代码实现

### 最终代码

```python
from typing import List


class Solution:
    def minimizedMaximum(self, n: int, quantities: List[int]) -> int:
        left = 0                          # 哨兵：恒不可行（不参与判定）
        right = max(quantities) + 1       # 恒可行：每种商品各占 1 家店，共 m <= n 家

        def check(t: int) -> bool:
            """每间店至多 t 件时，是否能在 n 家店内放完所有商品"""
            temp = 0
            for i in quantities:
                temp += (i - 1) // t + 1   # ceil(i / t)
                if temp > n:               # 剪枝：已经超了就不用算完
                    return False
            return True

        while left + 1 < right:            # 区间 (left, right] 内二分
            mid = (left + right) // 2
            if check(mid):
                right = mid                # mid 可行，答案 <= mid
            else:
                left = mid                 # mid 不可行，答案 > mid
        return right
```

> 截图里没有 `from typing import List`（LeetCode 判题环境已内置），本地直接运行时已补上。

## 四、复杂度分析

| 版本 | 时间复杂度 | 空间复杂度 |
| :--- | :--- | :--- |
| **最终代码** | O(m · log V) | O(1) |
| 朴素解法（线性枚举 x） | O(m · V) | O(1) |
| 理论下界 | O(m)（至少要读一遍输入） | O(1) |

> 复杂度中的 **m** 指 `quantities` 的长度（商品种类数），**V = max(quantities)**，即答案的值域上界。
> 注意：**本题题面里的 `n` 是商店数量**，不能直接当作复杂度里的 n 用；判定单轮的成本由商品种类数 `m` 决定。

## 五、优化评估

**结论**：**时间与空间都已是本题的标准最优路线**，不存在更优的阶数。

### 瓶颈分析

时间由两块组成：判定轮的次数 `log V`（值域二分），以及每轮必须扫完 `quantities` 的 `m`。

每轮 `m` 的扫描是**信息论上的必要开销**：`m` 种商品各自的件数都会独立影响可行性，少看任何一种，都可能把不可行的 `x` 误判成可行（例如漏看的那一种恰好件数极大）。

### 可优化空间

`log V <= 17`（V <= 10^5），这一项已经小到只剩常数意义；而 `m` 无法再降。因此本题的时间下界就是 Ω(m)，当前 O(m log V) 与它的差距仅是一个不超过 17 的因子，**没有可改善的阶数空间**。

空间上只用了一个累加器和两个指针，O(1) 也已触底。

## 六、易错点与总结

### 易错点

- **漏掉「一间店只能装一种商品」**：会误以为不同商品可以混装在同一家店里凑数，从而把判定算成 `ceil(sum(quantities) / x) <= n`，答案偏小。
- **上取整写成 `q // x`**：漏算后所需店数被低估，判定过于乐观，二分会收敛到偏小的错误答案。
- **`left` 取 0 后错用闭区间二分**：闭区间写法里 `mid` 可能取到 0，`// 0` 直接抛 `ZeroDivisionError`。左开右闭写法才让这个哨兵安全。
- **上界取 `max(quantities)` 而非 `max(quantities) + 1`**：`max` 本身在 `m == n` 这类极端输入下也恰好可行，但作为「恒可行上界」不安全；`+1` 才有严格保证。
- **收敛条件写反**：左开右闭区间必须用 `left + 1 < right`，用 `left < right` 会在相邻两点间反复震荡、死循环。

### 题型套路沉淀

- **二分答案（最小化最大值 / 最大化最小值）通用模板**：

  ```python
  left, right = 不可行的下界, 可行的上界   # 保证 right 一定可行
  while left + 1 < right:                # 区间 (left, right]
      mid = (left + right) // 2
      if check(mid): right = mid
      else:          left = mid
  return right                           # 答案 = 分界点
  ```

  识别信号：问的是「**某个全局最大值/最小值的极值**」而不是「具体方案」，且约束越松越容易满足。

- **写这类题先问三个问题**：① `check(x)` 是否单调？② `check` 内部能不能拆成可累加的独立子问题？③ 区间两端的初值是否一个恒可行、一个恒不可行？
