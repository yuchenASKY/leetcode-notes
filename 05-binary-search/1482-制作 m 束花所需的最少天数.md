# 1482. 制作 m 束花所需的最少天数

> **难度**：中等
> **标签**：二分 · 数组
> **原题链接**：https://leetcode.cn/problems/minimum-number-of-days-to-make-m-bouquets/

---

## 一、题目描述

给定数组 `bloomDay`，`bloomDay[i]` 表示第 `i` 朵花开放所需的天数；再给定 `m`（需要的花束数）与 `k`（每束花所需的**相邻**花朵数）。每天可以选择摘花，一旦摘下就不能再用。求能做出 `m` 束花所需的**最少天数**；无论如何都做不到则返回 `-1`。

要点在于「**相邻**」：`k` 朵花必须来自数组里一段**连续**的位置，中途遇到还没开的花，这一段就断了。

### 示例

```text
示例 1
输入：bloomDay = [1,10,3,10,2], m = 3, k = 1
输出：3
解释：第 1 天开 [x,_,_,_,_]；第 2 天 [x,_,_,_,x] 只能做 2 束；
      第 3 天 [x,_,x,_,x] 可以做 3 束（k = 1 时不必相邻），答案为 3。

示例 2
输入：bloomDay = [1,10,3,10,2], m = 3, k = 2
输出：-1
解释：3 束 × 每束 2 朵 = 需要 6 朵，而花园里总共只有 5 朵，无解。

示例 3
输入：bloomDay = [7,7,7,7,12,7,7], m = 2, k = 3
输出：12
解释：第 7 天可摘第 1 束（前 4 朵连续，取其中 3 朵），但第 2 束遥遥无期；
      第 12 天全部开放，才凑够 2 束，答案为 12。

示例 4
输入：bloomDay = [1000000000,1000000000], m = 1, k = 1
输出：1000000000
解释：必须等到第 1000000000 天才开花。
```

### 约束条件

- `n == bloomDay.length`
- `1 <= n <= 10^5`
- `1 <= bloomDay[i] <= 10^9`
- `1 <= m <= 10^6`
- `1 <= k <= n`

注意 `bloomDay[i]` 的上界是 **10^9** —— 这个量级直接宣判了「逐天枚举」的死刑，是本题选型的决定性线索。

## 二、解题思路

### 核心思想

把「最少天数」当成**答案本身**去二分：定义谓词 `check(d)` = 「第 `d` 天能否做出至少 `m` 束花」，它关于 `d` 单调不减，于是在答案值域上二分出**最小的可行 `d`**。

### 思路演进

1. **暴力解法**：

   从第 1 天起逐天递增 `d`，对每个 `d` 线性扫一遍数组统计能切出多少束，第一个满足 `>= m` 的 `d` 就是答案。

   复杂度 `O(max(bloomDay) × n)`。代入上界：`10^9 × 10^5 = 10^14`，完全不可行。

2. **观察到**：逐天枚举里做了大量**重复劳动** —— 第 `d` 天能摘的花，第 `d + 1` 天一定还能摘（花开了不会谢）。于是

   > `check(d)` 关于 `d` **单调**：`d` 越大，开花的位置越多，能切出的束数只增不减。

   单调谓词 + 求最小可行点 → 典型的**二分答案**。`10^9` 的逐天枚举被压成 `log₂(10^9) ≈ 30` 次判定。

3. **优化为**：二分答案 + `O(n)` 贪心判定。

   - **值域**：下界 `left = 0`（哨兵，见下），上界 `right = max(bloomDay)` —— 取「最大开花天数」时全部花都开了，是**必然可行**的点。
   - **判定 `check(mid)`**：顺序扫描 `bloomDay`，维护「当前连续段里已开花朵数」`temp`；遇到 `<= mid` 的花朵就 `temp += 1`，一旦 `temp` 达到 `k` 就切走一束（`ans += 1`）并把 `temp` 清零；遇到 `> mid` 的花朵则说明连续段被打断，`temp` 归零。
   - **二分口径**：维护半开区间 `(left, right]`，不变量是「`left` 处不可行、`right` 处可行」，循环条件 `left + 1 < right`，退出时 `left + 1 == right`，`right` 即最小可行天数。

   贪心切花为什么对？因为一束花只要 `k` 朵相邻，**能切就立刻切**不会比留着更差：留下的那几朵若不切，也只能给后面同样的一段用，早切一步等价于把可用的连续长度整体前移，束数不会减少。这是标准的区间贪心（每段长度 `L` 贡献 `⌊L / k⌋` 束）。

### 关键点

- **`m * k > n` 必须提前剪枝**：花的总数都不够，谓词 `check(d)` 永远不可能为真。若不剪枝，二分只会把 `right` 收敛到 `max(bloomDay)` 并返回它 —— 输出一个「看似合法」的错误答案，而不是 `-1`。这是本题最容易漏掉、且测试用例（示例 2）专门盯防的一个点。
- **下界 `left = 0` 是承重的「必假哨兵」，不是随便取的常数**：因为 `bloomDay[i] >= 1`，第 0 天必然开不了花，`check(0) = 0 < m` 恒成立，于是「`left` 不可行」这条不变量天然成立。若把下界抬到 `min(bloomDay)` 之类的值，就必须额外保证它确实不可行，否则二分可能收敛到一个错误位置。
- **判定里 `temp >= k` 分支内写 `temp -= k` 与 `temp = 0` 等价**：`temp` 每轮最多 `+1`，进入该分支时它必然**恰好等于** `k`，所以减法结果就是 `0`。写法上等价，但语义上 `temp = 0` 更能表达「切走一束、连续段重新计数」的意图。
- **循环条件用 `left + 1 < right` 而非 `left < right`**：`mid = (left + right) // 2` 向下取整，若写 `while left < right` 并配 `left = mid`，在 `left + 1 == right` 时会算出 `mid == left`，赋值原地不动 → **死循环**。`left + 1 < right` 天然保证区间长度 ≥ 2，规避了这个坑。
- **上界直接取 `max(bloomDay)`**：这是「必然可行」的天然上界（所有花都开了），因此不需要对右端点额外做一次可行性校验，二分结束即可直接返回。
- **`bloomDay` 无需排序**：判定依赖的是**位置顺序**（相邻性），一旦排序就破坏了题目的全部结构。全局有序的只有**答案值域**，不是输入数组。

## 三、代码实现

### 最终代码

```python
class Solution:
    def minDays(self, bloomDay: list[int], m: int, k: int) -> int:
        if m * k > len(bloomDay):
            return -1

        def check(mid):
            temp = 0   # 当前连续段中已开花的朵数
            ans = 0    # 已切出的花束数
            for i in bloomDay:
                if i <= mid:
                    temp += 1
                    if temp >= k:
                        temp -= k   # 等价于 temp = 0（此处 temp 必恰为 k）
                        ans += 1
                else:
                    temp = 0    # 连续段被未开放的花打断
            return ans

        left = 0                 # 哨兵：第 0 天必然不可行
        right = max(bloomDay)    # 必然可行
        while left + 1 < right:  # 不变量：left 不可行，right 可行
            mid = (left + right) // 2
            if check(mid) >= m:
                right = mid
            else:
                left = mid
        return right
```

> 代码为提交通过的版本；`list[int]` 类型标注依赖 Python 3.9+ 的内置泛型，LeetCode 判题环境已满足，无需额外 `import`。

## 四、复杂度分析

| 版本 | 时间复杂度 | 空间复杂度 |
| :--- | :--- | :--- |
| **最终代码** | O(n · log(max(bloomDay))) | O(1) |
| 朴素解法（逐天枚举） | O(n · max(bloomDay)) | O(1) |
| 理论下界 | O(n)（判定本身至少要扫完整个数组一次） | O(1) |

> 复杂度中的 n 指：`bloomDay` 的长度（花园里花朵的数量）。二分轮数为 `log₂(max(bloomDay))`，本题中约为 30 轮。

**为什么不可能做到 O(n)**：`check` 是逐元素判定，读全部 `n` 个元素才敢断定「这一天的束数到底够不够」，单次判定已占满 `O(n)` 的信息下界；而可行性关于天数单调、值域宽达 `10^9`，不做二分就只能线性扫值域。两者相乘即 `O(n · log(max(bloomDay)))`，本题已是该模型下的最优量级。

## 五、优化评估

**结论**：已是最优（量级最优，且常数项已经很干净）。

### 瓶颈分析

- **时间**：开销集中在「约 30 轮 × 每轮一次全数组扫描」，即 `check` 的循环体。循环体本身只有比较、自增、分支，没有嵌套循环，也没有任何额外分配。
- **空间**：只用 `temp` / `ans` / `left` / `right` / `mid` 几个标量，与 `n` 和值域均无关，`O(1)`。

### 可优化空间

- **值域下界**：`left = 0` 只用了一轮就跳到有效范围，不影响渐近，也不值得为省零点几轮去换「哨兵必假」这条不变量 —— 保留 `0` 是更稳的选择。
- **判定方式**：任何「预计算 + 跳步」的判定改写都要额外付出 `O(n)` 的预处理与额外空间，且只在「平均每段都很长」时才可能划算，而输入结构不受控制。既然渐近量级已经触底，就不做这种得不偿失的改写。

### 常数级优化（可选）

- 把 `check` 需要的 `bloomDay` 在调用前绑定为局部变量、`k` 与 `m` 也一并绑定，可减少闭包变量查找（不改复杂度，仅省一点解释器开销）。
- `bloomDay` 只在 `check` 里被顺序遍历，用 `for i in bloomDay` 的直接迭代已经比 `for idx in range(len(...))` 再下标访问更快，现有写法即是此式。

## 六、易错点与总结

### 易错点

- **漏掉 `m * k > n` 的剪枝**：会返回 `max(bloomDay)` 这种「假答案」而不是 `-1`；示例 2 就是专门检查这一点的用例。
- **把 `m * k > n` 写成 `m * k > len(set(bloomDay))` 之类的变体**：花束按**位置**切，不按**不同天数**切，这里只能和数组长度 `n` 比较。
- **二分边界写成 `left = mid` 却不改循环条件**：`while left < right` + `mid` 向下取整 + `left = mid` 会在 `left + 1 == right` 时死循环，务必用 `left + 1 < right`。
- **`right` 初值取小了**：若把上界取成 `min(bloomDay)` 或某个「看起来够大」的值，一旦该值不可行，二分可能收敛到错误位置甚至返回不可行的解。取 `max(bloomDay)` 最省心。
- **判定里忘记 `temp = 0`（遇到未开花时）**：会把被未开放花朵打断的两段错误地并成一段，束数被高估，答案偏小。
- **判定里切走一束后忘记清空 `temp`**：连续段长度 `4`、`k = 3` 时只能切 `1` 束，不清零会被算成 2 束。
- **对 `bloomDay` 排序**：相邻性被破坏，题意直接失真。

### 题型套路沉淀

**「二分答案」的固定四件套**（本题是标准样本）：

1. **确认单调性**：把候选答案记为 `x`，写出谓词 `check(x)`，并验证「`x` 变大 ⇒ `check(x)` 只可能从假变真」（或反向）。这是能否二分的唯一判据。
2. **圈定值域**：下界取一个**确定不可行**的哨兵（本题 `0`，靠 `bloomDay[i] >= 1` 保证），上界取一个**确定可行**的点（本题 `max(bloomDay)`，因为全部开花）。两端各自有明确理由，是二分不出错的前提。
3. **写判定**：`check` 通常是**一次线性贪心扫描**。判定内部的贪心必须能自证「局部取法不劣于其他取法」——本题是「每段长度 `L` 贡献 `⌊L / k⌋`」。
4. **选边界口径**：本题用**左开右闭** `(left, right]` + `while left + 1 < right`，不变量为「`left` 假、`right` 真」，退出即得答案。这套口径的好处是**不需要后处理**（不用再判断返回 `left` 还是 `right`）。

> 一句话记忆：**「最小可行值 / 最小化最大值」+ 单调谓词 ⇒ 左开右闭二分，返回 `right`。** 判定函数里凡是「连续满足条件的元素凑成一组」的模型，都套「连续段长度整除 `k`」这一贪心。
