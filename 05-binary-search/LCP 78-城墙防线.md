# LCP 78. 城墙防线

> **难度**：中等
> **标签**：二分答案 · 贪心
> **原题链接**：https://leetcode.cn/problems/Nsibyl/

---

## 一、题目描述

给出 n 段互不重叠、按位置升序排列的城墙，第 i 段占区间 `rampart[i] = [x, y]`。现在所有城墙**同时向左、向右或向两侧膨胀相同的总长度 t**，要求膨胀后任意两段城墙仍不重叠。求 t 的最大值。最左、最右两段城墙的外侧没有边界，可以无限向外膨胀。

### 示例

```text
输入：rampart = [[0,3],[4,5],[7,9]]
输出：3
解释：rampart[0] 向左侧膨胀 3；rampart[2] 向右侧膨胀 3；
      rampart[1] 向左侧膨胀 1、向右膨胀 2。不存在膨胀更多的方案。

输入：rampart = [[1,2],[5,8],[11,15],[18,25]]
输出：4
```

### 约束条件

- `3 <= rampart.length <= 10^4`
- `rampart[i].length == 2`
- `0 <= rampart[i][0] < rampart[i][1] <= rampart[i+1][0] <= 10^8`

## 二、解题思路

### 核心思想

**把「求最大值」转成「判断给定 t 是否可行」的单调谓词，再二分答案**；而 `check(t)` 用一次自左向右的贪心在 O(n) 内解决。

### 思路演进

1. **暴力解法**：直接枚举方案。每段城墙的左膨胀量可以取 `0..t` 的任意整数，n 段城墙的组合数是 (t+1)^n，完全不可行。退一步，也可以让 t 从 0 往上递增、逐个模拟，但 t 的上界可达 10^8 量级，同样超时。

2. **观察到①（单调性）**：**若 t 可行，则所有 t' < t 也可行**。把原来每段城墙「左 a 个、右 b 个」（a + b = t）的膨胀量换成一组新的 `(a', b')`，只要 `a' + b' = t'` 且 `a' <= a`、`b' <= b`，重叠约束只会更松 —— 例如取 `a' = min(a, t')`、`b' = t' - a'` 即可。可行性关于 t 是单调的（`false...false true...true`），于是可以对 t **二分答案**，把枚举降到 O(log V)。

3. **观察到②（判定只需贪心）**：固定 t 后，唯一的信息是「每段城墙往右侵占了下一个空隙多少」。设第 i 个空隙（在第 i-1 段与第 i 段之间）长度为 `gap_i = rampart[i][0] - rampart[i-1][1]`，记 `l_i / r_i` 为第 i 段城墙向左 / 向右的膨胀量，则约束是

   ```text
   l_i + r_i = t          （每段必须凑够 t）
   r_{i-1} + l_i <= gap_i （同一个空隙被左右两段共享）
   ```

   空隙是被相邻两段城墙**共享**的：第 i 段城墙「向左」占掉的那部分，第 i-1 段城墙再也用不到。因此让第 i 段城墙**尽可能吃掉左侧空隙**（`l_i = min(t, gap_i - r_{i-1})`），它的 `r_i` 就取到了最小值，留给右边的余地最大。这是标准的局部最优推全局最优，故一次 O(n) 扫描即可判定。

4. **优化为**：左到右扫一遍，维护 `tmpr` = 上一段城墙向右侵占的量；每段算出它必须向右侵占多少 `tmpr`，并顺手检查这个量有没有超过下一个空隙。末尾那段城墙右侧无限，天然可行。外层对 t 二分。

### 关键点

- **t 必须「凑够」而不是「至多」**：每段城墙的左右膨胀量之和恰好等于 t，这决定了贪心是「先用左空隙，不够的必须向右补」。
- **只有 n-1 个内部空隙**：第 0 段城墙左侧、第 n-1 段城墙右侧都没有约束，所以第 0 段一律把 t 全部放到左边（`r_0 = 0`），第 n-1 段永远判定通过。
- **上界取 `gap_1 + gap_2 + 1` 就够**：第 1 段城墙（下标 1）可用的资源只有它左右两个空隙，`l_1 + r_1 = t <= gap_1 + gap_2`，因此 `gap_1 + gap_2 + 1` 是一个「一定不可行」的开区间右端点，二分无需取到 10^8。
- **判定里用减法传递约束**：`tmpl = j[0] - rampart[i-1][1] - tmpr` 直接把上一段向右的侵占量从当前空隙里扣掉，避免显式维护空隙数组。

## 三、代码实现

### 最终代码

```python
from typing import List  # 截图里没有、已补


class Solution:
    def rampartDefensiveLine(self, rampart: List[List[int]]) -> int:
        m = len(rampart)

        def check(t: int) -> bool:
            tmpl = 0   # 当前城墙向左可用的剩余空隙
            tmpr = 0   # 上一段城墙向右侵占的量
            for i, j in enumerate(rampart):
                if i == 0:
                    continue
                # 扣掉前一段城墙向右侵占的部分，剩下的才是本段可用的左侧空间
                tmpl = j[0] - rampart[i - 1][1] - tmpr
                # 左侧不够，缺口必须由右侧承担
                tmpr = max(t - tmpl, 0)
                # 右侧还有下一段：空隙装得下就继续
                if i + 1 < m and rampart[i + 1][0] - j[1] >= tmpr:
                    continue
                # 右侧无边界，一定可行
                if i + 1 >= m:
                    return True
                # 右侧空隙装不下 → t 不可行
                return False
            return True

        left = -1   # t = 0 恒可行，作为「可行」哑元
        right = rampart[1][0] - rampart[0][1] + rampart[2][0] - rampart[1][1] + 1
        while left + 1 < right:
            mid = (left + right) // 2
            if check(mid):
                left = mid
            else:
                right = mid

        return left
```

## 四、复杂度分析

| 版本 | 时间复杂度 | 空间复杂度 |
| :--- | :--- | :--- |
| **最终代码** | O(n log V) | O(1) |
| 朴素解法（枚举 t 并逐个模拟） | O(n · V) | O(1) |
| 理论下界 | O(n log V) | O(1) |

> 复杂度中的 n 指城墙段数 `len(rampart)`；V 指二分值域的大小，本解法中 V = `gap_1 + gap_2 + 1 <= 2 * 10^8`，故 `log V` 约 28。

## 五、优化评估

**结论**：时间与空间均已是最优，无可优化项。

### 瓶颈分析

- 判定 `check(t)` 必须至少看一遍所有城墙，否则无法确认每段城墙都凑够 t 且不越界 —— 下界 O(n)。
- 值域上界与坐标范围同阶（10^8），不二分就只能线性枚举 t，代价是判定开销的 10^8 倍；二分后把枚举次数压到约 28 次。
- 空间上整个算法只用了 `tmpl` / `tmpr` / `left` / `right` / `mid` 几个整型变量，没有随 n 增长的额外结构。

### 可优化空间

**不存在渐近意义上的优化空间**：`O(n log V)` 已经同时打满「判定必须线性扫」和「求最值必须对单调谓词定位」这两个下界。

### 常数级优化（可选）

- `if i == 0: continue` 让第一次循环空转一圈，可以直接把第 0 段的 `tmpr = 0` 作为初值从 `i = 1` 开始遍历，省掉一次判断。
- 循环内 `rampart[i - 1][1]`、`rampart[i + 1][0]` 的重复下标取值可以用局部变量缓存，减少 `list` 的三级索引访问。
- 二分区间只有约 28 轮，常数级改动对总耗时的量级影响可以忽略；这些写法主要是为了可读性，而非性能。

## 六、易错点与总结

### 易错点

- **把约束写成 `<=` 而不是 `<`**：膨胀后允许「紧贴」但不可重叠，题目约束里 `rampart[i][1] <= rampart[i+1][0]` 也允许空隙为 0，所以判定用的是 `>=` / `<=`，写成严格不等号会漏掉刚好贴合的可行解。
- **忘记给二分值域一个「一定不可行」的右端点**：`right` 必须是开区间端点，`gap_1 + gap_2 + 1` 才是安全的；若直接取 `10^8`，需要额外确认它一定不可行。
- **输出用的是 `left` 而非 `mid`**：区间写法是「`left` 始终保持可行、`right` 始终不可行」，循环退出时答案是 `left`。
- **贪心方向搞反**：必须「先用左侧空隙」而不是「先用右侧」。空隙是相邻两段共享的，把当前城墙的膨胀压到左边，才能把右边的空隙尽可能腾给下一段。
- **访问 `rampart[2]` 越界**：题目保证 `n >= 3`，所以上界表达式可以放心写下标 1、2；如果换成 n 可能为 1 或 2 的场景，需要另作处理。

### 题型套路沉淀

- **「最大化最小值 / 最大化可行值」类问题**：先验证可行性谓词是否单调（通常由「把解调小只会让约束更松」保证），再把「求最大」换成「二分 + 判定」。
- **判定里的贪心判据要能说服自己**：本题的判据是「空隙被相邻两段共享，因此当前段应尽量少侵占右侧」。凡是判定里含贪心的二分答案题，写完后都该复述一遍这句理由，说不清就是判据站不住。
- **二分的上下界优先从问题结构里推**，而不是直接抄坐标最大值 —— 本题只需前两个空隙之和即可得到紧上界。
- **区间写法固定套路**：`left = -1`（可行哑元）、`right = 上界 + 1`，循环条件 `left + 1 < right`，`check(mid)` 为真则 `left = mid`，否则 `right = mid`，最后返回 `left`。
