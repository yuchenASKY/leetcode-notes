# 275. H 指数 II

> **难度**：中等
> **标签**：数组 · 二分查找
> **原题链接**：https://leetcode.cn/problems/h-index-ii/

---

## 一、题目描述

`citations` 是一个**已按非降序排列**的整数数组，`citations[i]` 表示研究者的第 `i` 篇论文被引用的次数。求该研究者的 **h 指数**，即最大的 h，使得 n 篇论文中**至少**有 h 篇论文分别被引用了**至少** h 次。

因为数组已经有序，题目要求实现**对数时间复杂度**的算法。

### 示例

```text
示例 1：
输入：citations = [0,1,3,5,6]
输出：3
解释：共有 5 篇论文，被引次数分别为 0,1,3,5,6。
     其中 3 篇每篇至少被引用 3 次，其余 2 篇每篇被引用不多于 3 次，所以 h = 3。

示例 2：
输入：citations = [1,2,100]
输出：2
```

### 约束条件

- `n == citations.length`
- `1 <= n <= 10^5`
- `0 <= citations[i] <= 1000`
- `citations` 按**升序排列**

---

## 二、解题思路

### 核心思想

**把「求最大的 h」转化为对答案值域做二分。** 判定条件 `citations[n - h] >= h` 关于 h 是单调的（h 越大越难成立），因此真假分界点唯一，可以用 O(1) 判定把它夹出来。

### 思路演进

1. **暴力解法**：h 只可能取 `0..n`，逐个枚举 h，检查「前 h 大的论文是否每篇都 ≥ h 次」。因为数组升序，前 h 大的论文正是 `citations[n-h:]`，其中被引次数最少的是 `citations[n-h]`，于是判定退化为一次比较 `citations[n-h] >= h`。从 `h = n` 往下找到第一个成立的 h 即为答案 —— 时间 O(n)，空间 O(1)。
2. **观察到**：判定函数 `P(h) = (n - h >= 0) and (citations[n - h] >= h)` 是**单调**的。h 增大时索引 `n-h` 向左移，`citations[n-h]` 单调不增；而右侧要比较的 h 单调增 —— 一边变紧一边变松，P 只会由真翻假，绝不会反复。既然真假分界只有一处，就没必要线性地逐个试。
3. **优化为**：直接在答案值域上二分这个分界点。每轮取 `mid` 做一次 O(1) 判定，成立就把 `left` 推到 `mid`，不成立就把 `right` 收到 `mid`，O(log) 轮后 `left` 即为最大的可行 h。

### 关键点

- **这是「二分答案」，不是「二分下标」**：被二分的量是答案本身 h，数组下标只是判定时的辅助。位置 `n - h` 是「第 h 大」那篇论文的 0 基索引，也就是前 h 大中最小的一篇。
- **单调性给了二分合法性**：要判断「至少 h 篇被引 ≥ h 次」，只需看第 h 大的那篇是否 ≥ h —— 排在它后面的 h-1 篇只会更大。反过来，一旦 P 在某个 h 处为假，所有更大的 h 必然也为假。
- **上界必须满足 P(right) 为假**：代码取 `right = max(citations) + 1`。因为「h 篇论文每篇至少 h 次」蕴含 `max(citations) >= h`，所以 h 超过最大被引次数时判定必假。同理 h ≤ n 也恒成立，因此 `n + 1` 同样可以作为右边界。
- **`mid > n` 必须显式挡住**：候选 h 可能超过论文总数 n（例如 `max(citations) = 1000` 而上界起点为 1001），此时 `n - mid < 0`。Python 的负下标**不报越界**，会静默绕到数组尾部取元素 —— 不写这个护栏不会崩，只会把答案算错，是本题最隐蔽的坑。
- **哨兵式开区间模板**：`left = 0` 是候选答案占位，`right` 保证 P 为假；循环不变量维持「`left` 可行 / `right` 不可行」，`left + 1 < right` 时区间长度 ≥ 2 才继续。退出时 `left` 即满足 P 的最大值。
- **全 0 的边界**：`max(citations) == 0` 时 `right == 1`，代码用 `if right == 1: return 0` 直接返回。（即使删掉这一分支，`while left + 1 < right` 也不会进入，最终仍 `return left = 0`，结果相同；保留它只是把 h = 0 这个边界写得更直白。）

## 三、代码实现

### 最终代码

```python
class Solution:
    def hIndex(self, citations: list[int]) -> int:
        n = len(citations)
        left = 0                                            # 候选答案占位
        right = max(citations) + 1                          # 保证 P(right) 为假
        if right == 1:                                      # 全部为 0，h 指数必为 0
            return 0
        while left + 1 < right:                             # 开区间 (left, right)
            mid = (left + right) // 2
            if n - mid >= 0 and citations[n - mid] >= mid:  # 先挡负下标，再判定
                left = mid                                  # 至少 mid 篇被引 >= mid 次
            else:
                right = mid
        return left
```

> 代码与截图一致；本题无需额外 `import`（`list[int]` 为内置泛型），因此没有需要补充的导入。

## 四、复杂度分析

| 版本 | 时间复杂度 | 空间复杂度 |
| :--- | :--- | :--- |
| **最终代码（二分答案）** | O(log(max(citations) + 1)) | O(1) |
| 朴素解法（线性扫描 h） | O(n) | O(1) |
| 理论下界 | O(log n) | O(1) |

> 复杂度中的 n 指论文总数，即 `citations` 的长度（n ≤ 10^5）。
>
> 二分区间长度为 `right = max(citations) + 1`，故轮数为 O(log(max(citations) + 1))。又因为 h ≤ n 恒成立（「至少 h 篇」不可能超过论文总数），把右边界换成 `n + 1` 同样正确，那时轮数写作 O(log n)。两者都是对数级；在本题的约束下 `citations[i] <= 1000`，区间长度不超过 1001。

## 五、优化评估

**结论**：时间复杂度已达理论下界，空间复杂度 O(1) 也无可压缩空间。**已是最优。**

### 瓶颈分析

每轮判定的开销是常数（一次下标访问 + 一次整数比较），总开销完全由二分轮数决定。h 的可能取值为 `0..n` 共 n+1 个，要确定真假分界所在的那一个位置，任何算法都必须把候选范围收敛到单点，比较次数下界是 Ω(log n) —— 当前解法正好达到。

### 可优化空间

没有更低复杂度的算法可走：题目直接要求对数时间，而「二分答案」正是满足该要求的标准形态。剩下的差异只在**区间上界的松紧**（`max(citations) + 1` 与 `n + 1` 都正确，都满足 P(right) 为假），属写法选择，不改变复杂度量级，也谈不上谁「更优」。

## 六、易错点与总结

### 易错点

- **漏掉 `n - mid >= 0` 这道护栏**：本题最大的坑。Python 支持负下标，`mid > n` 时 `citations[n - mid]` 不会抛 IndexError，而是静默取到数组靠尾部的元素，于是判定结果错了却毫无报错，调试时极难定位。
- **判定写成 `citations[mid] >= mid`**：位置搞反了。要用的是「第 h 大」那一篇（索引 `n - h`），不是数组里第 h 篇。
- **误用闭区间/`while left <= right` 模板**：本题的 `left` 是「可能的答案」、`right` 是「保证不成立的边界」，必须用 `left + 1 < right` 的开区间哨兵写法，否则边界反复横跳、容易死循环或漏解。
- **上界取错**：`right` 必须让 P(right) 为假。取 `right = n` 或在某些写法下取 `right = max(citations)`，都会漏掉边界上恰好成立的 h；取 `n + 1` 或 `max(citations) + 1` 才安全。
- **忽略 h 的双重上界**：h 同时被论文总数 n 和最大被引次数 `max(citations)` 限制，只想到其中一个就会把边界设错。

### 题型套路沉淀

- **二分答案的识别信号**：题目问「最大 / 最小的 X，使得……」；「X 是否可行」的判定本身很快（O(1) 或 O(n)）；且判定结果关于 X 单调。三条同时满足，就该往二分答案上想，而不是去找更精巧的贪心。
- **二分答案的标准骨架（求最大值版，哨兵开区间）**：

  ```python
  left, right = 下界哨兵, 上界 + 1      # P(right) 必为假
  while left + 1 < right:
      mid = (left + right) // 2
      if P(mid):
          left = mid                   # mid 可行，答案不会更小
      else:
          right = mid
  return left                          # 求最大值时返回 left
  ```

- **写判定函数前先自查参数范围**：涉及 `n - x` 这类「从尾部倒数」的索引，一律显式加上 `x <= n` 的护栏。Python 的负下标静默生效，这个坑在别的语言里会报错、在这里只会默默算错。
