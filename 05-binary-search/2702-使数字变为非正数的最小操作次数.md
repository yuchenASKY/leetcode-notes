# 2702. 使数字变为非正数的最小操作次数

> **难度**：困难
> **标签**：数组 · 二分查找
> **原题链接**：https://leetcode.cn/problems/minimum-operations-to-make-numbers-non-positive/

---

## 一、题目描述

给定数组 `nums` 和两个整数 `x`、`y`（保证 `y < x`）。每次操作**必须**选一个下标 `i`：

- `nums[i]` 减去 `x`；
- 其余所有位置各减去 `y`。

求让 `nums` 中所有元素都 `<= 0` 所需的**最少操作次数**。

难点在于「每次操作都会波及全局」：选了一个下标，其他元素也不是原地不动，所以不能孤立地看某个元素需要几次。

### 示例

```text
示例 1：
输入：nums = [3,4,1,7,6], x = 4, y = 2
输出：3
解释：三次操作的一种最优顺序为：
  操作 1：选 i = 3，nums = [1,2,-1,3,4]
  操作 2：选 i = 3，nums = [-1,0,-3,-1,2]
  操作 3：选 i = 4，nums = [-3,-2,-5,-3,-2]
  此时全部非正，返回 3。

示例 2：
输入：nums = [1,2,1], x = 2, y = 1
输出：1
解释：只需对 i = 1 操作一次，nums 变成 [0,0,0]，全部非正。
```

### 约束条件

- `1 <= nums.length <= 10^5`
- `1 <= nums[i] <= 10^9`
- `1 <= y < x <= 10^9`

> 注意最后一条：**`y` 严格小于 `x`**，所以差分 `x - y >= 1`，不会出现除以 0 的情况。

## 二、解题思路

### 核心思想

**二分答案 + O(n) 可行性判定。**

把「最少几次」这个优化问题，转成「给定 `k` 次，能不能做到」这个判定问题；由于「`k` 次能做到 ⇒ `k+1` 次也一定能做到」，可行域是一个后缀，于是可以在答案上二分。

判定的关键是**把全局衰减与差异化补偿拆开**：`k` 次操作里，如果下标 `j` 被选中了 `c_j` 次，那么它一共减掉了

```text
c_j * x + (k - c_j) * y  =  k * y  +  c_j * (x - y)
```

也就是说：**每个元素都先无差别地减掉 `k*y`，被选中的那 `c_j` 次每次额外多减 `(x - y)`**。于是只要「额外补偿」的总需求量不超过可用的操作次数 `k`，`k` 就是可行的。

### 思路演进

1. **暴力解法**：从 `k = 1` 开始逐个试，对每个 `k` 做一次 O(n) 的可行性判定，第一个可行的 `k` 就是答案。判定本身没错，但**枚举次数太多** —— 当 `y = 1`、`nums[i] = 10^9` 时答案可以接近 `10^9`，`10^9 * 10^5` 显然跑不动。
2. **观察到单调性**：如果 `k` 次操作能让所有元素非正，那么做 `k+1` 次也一定可以 —— 多出来的那次操作只会让某个元素再减小一点，不会破坏任何已满足的 `<= 0`。即判定函数 `check(k)` 随时间只能从 `False` 翻转到 `True`，是**单调布尔序列**。
3. **优化为**：既然单调，就不必逐个枚举，直接在答案上二分第一个 `True`，复杂度从「答案 × n」变成「log(答案范围) × n」。判定的具体推导见下面「关键点」——它是本题真正需要想清楚的地方。
4. **落地细节**：用 `bisect_left(range(right), True, key=check)` 代替手写二分循环。`range` 支持 O(1) 随机访问，`key` 参数让它按 `check(k)` 的布尔值去定位第一个 `True`；如果整段都是 `False`，它会返回 `len`（也就是 `right`），恰好对应「答案就是上界」的情形。

### 关键点

- **判定的三条推导**：
  1. 设 `k` 次操作中下标 `j` 被选中 `c_j` 次，则 `nums[j]` 的净减少量为 `k*y + c_j*(x-y)`（对每个 `c_j` 都恰好减 `(k - c_j)` 次 `y`，因为每一步「没被选中的元素都要减 `y`」）。
  2. 要求 `k*y + c_j*(x-y) >= nums[j]`，解出 `c_j >= (nums[j] - k*y) / (x - y)`，向上取整；若分子 `<= 0`（说明光靠基线衰减就已经非正）则 `c_j = 0`。
  3. 每次操作**恰好只能选一个下标**，所以「总需求」必须 `<= k` 才可行 —— 判据是 `sum(c_j) <= k`，**不是 `== k`**（多出来的操作次数可以随便用，只要不破坏结果）。
- **贪心取最小需求**：每个元素只取「刚好够」的次数，总和最小；若连这个最小值都超过 `k`，任何方案都做不到。
- **向上取整的整数写法**：`ceil(p / q) = (p - 1) // q + 1`（`p >= 1`，`q >= 1`）。注意当 `p <= 0` 时该式结果 `<= 0`，正好可以当作「不需要额外补偿」来跳过 —— 这也是代码里只判 `divide > 0` 的原因。
- **上界必须取一个「一定可行」的值**：把 `k` 次操作全砸在同一个下标上，则该下标减 `k*x`，其余每个元素各减 `k*y`。取 `k = max(nums) // y + 1`，则 `k*y > max(nums) >= nums[j]` 对所有 `j` 成立，全体必非正 ⇒ `check(right)` 恒为真。（上界取偏大没关系，二分自会收敛到最小值。）
- **二分的搜索区间是 `[0, right)`**：`range(right)` 只到 `right - 1`。当答案恰等于 `right` 时不需要特判 —— 整段为 `False` 时 `bisect_left` 返回 `right`，结果依然正确。

## 三、代码实现

> 截图里只有 `class Solution` 本体，缺少 `List` 与 `bisect_left` 的 import，已补。

### 最终代码

```python
from typing import List
from bisect import bisect_left


class Solution:
    def minOperations(self, nums: List[int], x: int, y: int) -> int:
        # 判定：num 次操作能否让所有元素 <= 0
        def check(num: int) -> bool:
            minus = num * y                  # 基线：每个元素都会被减掉 num * y
            temp = []
            for i in nums:
                temp.append(i - minus)       # 余量：还需要靠「选中」额外补掉多少
            for i in temp:
                divide = (i - 1) // (x - y) + 1   # ceil(i / (x - y))；i <= 0 时为 0 或负
                if divide > 0:
                    i -= divide * (x - y)    # 只改了循环变量，不影响列表，保留原提交写法
                    num -= divide            # 消耗掉这么多次「选中这个下标」
            if num >= 0:
                return True
            return False

        right = max(nums) // y + 1           # 上界：全体都减 k*y > max(nums)，必定可行
        ans = bisect_left(range(right), True, key=check)
        return ans
```

## 四、复杂度分析

| 版本 | 时间复杂度 | 空间复杂度 |
| :--- | :--- | :--- |
| **最终代码** | O(n log M) | O(n) |
| 朴素解法（逐个尝试 k） | O(答案 × n) | O(n) |
| 理论下界 | O(n) | O(1) |

> 复杂度中的 `n` 指数组 `nums` 的长度；`M` 指二分答案的上界 `max(nums) // y + 1`（不超过 `10^9`，所以二分约 30 轮）。
> `log M` 来自二分的轮数，每轮判定都要完整扫一遍数组。

对比：朴素解法的最坏情况里「答案」本身可以逼近 `10^9`，两者之间是量级差距，不是常数差距。

## 五、优化评估

**结论**：时间上 O(n log M) 已是本题的常规最优量级；**空间上的 O(n) 是多余的**，可以顺手去掉。

### 瓶颈分析

时间花在「约 30 轮 × 每轮 O(n) 的判定」上。判定必须至少看一遍数组（否则无法知道哪个元素还差多少），所以 `n` 这一维无法再降；二分轮数由答案范围决定，也不会更少。结论：时间量级已经到位。

额外空间则完全来自 `temp` 这个中间列表 —— 它只是为了先把「余量」算出来再逐个处理，属于可以省掉的中间产物。

### 可优化空间

把两趟循环合成一趟：一边遍历 `nums`、一边从 `num` 里扣减需求，`k` 一旦被扣成负数就可以立刻返回 `False`。这样不需要 `temp`，额外空间降到 O(1)，判定的语义完全不变。

### 优化代码

```python
from typing import List
from bisect import bisect_left


class Solution:
    def minOperations(self, nums: List[int], x: int, y: int) -> int:
        def check(k: int) -> bool:
            base = k * y
            for v in nums:
                need = v - base
                if need > 0:
                    k -= (need - 1) // (x - y) + 1
                    if k < 0:            # 需求超过可用次数，后面只会更不够
                        return False
            return True

        right = max(nums) // y + 1
        return bisect_left(range(right), True, key=check)
```

**优化理由**：原版的两趟循环是为了「先算出全部余量、再统一扣减」，但扣减的对象是同一个计数器 `num`，中间结果没有别的用途。合成一趟后，`k < 0` 时就已确定不可行 —— 因为 `k` 在循环中只减不增，后续不可能再回到非负。

### 常数级优化（可选）

- `(need - 1) // (x - y) + 1` 里的 `x - y` 是循环不变量，可以提前取到一个局部变量里，避免每轮重复做减法。
- 上取整也可以写成 `(need + x - y - 1) // (x - y)`（即 `ceil(p/q) = (p + q - 1) // q`）。两种写法等价，注意后一种在 `need` 为负时不能直接用 —— 需要先判 `need > 0`，而前一种天然把负数归到「不需要补偿」，所以原版省掉了一次判断。

## 六、易错点与总结

### 易错点

- **判据写成 `sum(c_j) == k`**：每次操作「必须」选一个下标，但可行只要「需求不超过可用次数」，`sum(c_j) <= k` 即可。写成 `==` 会把大量合法解误判为不可行。
- **漏掉「其他元素减 y」**：只盯着被选中的元素（净减 `x`），忘了没被选中的元素每轮也在减 `y`。本题之所以能用 `k*y` 当基线，正是因为「除 `i` 以外全部减 `y`」这条规则作用到了每一个元素。差分项必须写成 `x - y`，而不是 `x`。
- **上取整写成向下取整**：`c_j` 需要「够」而不是「差不多」，必须 `ceil`。用 `//` 直接取整会低估需求，把不可行的 `k` 判成可行。
- **没有跳过已经非正的元素**：余量 `<= 0` 的元素不该再累加次数（`c_j = 0`）。忘了这一步会把需求算大，导致答案偏大。
- **上界取错导致 `bisect_left` 返回 `len`**：上界必须自身可行。取 `max(nums) // y + 1` 的依据是「所有元素至少减 `k*y`」；若随手取一个不可行的上界，二分可能一路返回越界值。
- **二分区间开闭**：`range(right)` 是 `[0, right)`，恰好把「答案等于上界」这种情况交给返回 `len` 来兜住 —— 依赖上界可行性这个前提，两者是配套的。

### 题型套路沉淀

- **二分答案四件套**：① 写出判定函数 `check(k)`；② 说明单调性（`check(k) 真 ⇒ check(k+1) 真`，即「代价可以浪费、不能节省」）；③ 给一个「一定可行」的上界，保证二分区间的右端有意义；④ 在单调布尔序列上找第一个 `True`（Python 里 `bisect_left(range(right), True, key=check)` 一行就能拿到结果）。
- **「一次操作影响全局」类问题的通用拆法**：先剥离出所有元素共同承担的**基线衰减**（这里是 `k*y`），再把「只有选中的元素才能享受的额外收益」单列出来逐元素计数（这里是 `c_j*(x - y)`）。拆开之后，全局耦合就消失了，判定退化成一次线性扫描。
- **判定里出现「分配次数」时，判据是不等式而不是等式**：需求总数 `<=` 可用次数即可，别把它写成恰好相等。反过来，若题目要求「必须恰好用完」，才需要额外核查上界与下界的双向可达性。
- 二分答案题的答案范围往往很大（本题可达 `10^9`），**不要试图枚举**，一旦发现「答案 × 单次判定」会爆，就应该立刻转成二分答案。
