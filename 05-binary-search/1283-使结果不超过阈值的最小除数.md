# 1283. 使结果不超过阈值的最小除数

> **难度**：中等
> **标签**：数组 · 二分查找
> **原题链接**：https://leetcode.cn/problems/find-the-smallest-divisor-given-a-threshold/

---

## 一、题目描述

给定正整数数组 `nums` 与正整数阈值 `threshold`。选一个正整数 `d` 作除数，把数组里每个数**向上取整**地除以 `d` 再求和，要求这个和 ≤ `threshold`；求满足条件的 `d` 中的**最小值**。题面保证一定有解（约束里有 `nums.length <= threshold`）。

### 示例

```text
输入：nums = [1,2,5,9], threshold = 6
输出：5
解释：d=4 时和为 1+1+2+3=7 > 6；d=5 时和为 1+1+1+2=5 ≤ 6。

输入：nums = [2,3,5,7,11], threshold = 11
输出：3

输入：nums = [19], threshold = 5
输出：4
```

### 约束条件

- `1 <= nums.length <= 5 * 10^4`
- `1 <= nums[i] <= 10^6`
- `nums.length <= threshold <= 10^6`（这条是"答案一定存在"的来源）

---

## 二、解题思路

### 核心思想

定义谓词 `P(d) = Σ⌈nums[i]/d⌉ <= threshold`。**`P(d)` 关于 `d` 单调**（`d` 越大，每一项的商越小或不变），所以答案就是"`P(d)` 由假变真的那个分界点"——在答案空间 `[1, max(nums)]` 上二分，判定一次花 `O(n)`。

### 思路演进

1. **暴力解法**：`d` 从 1 开始逐一试到 `max(nums)`，对每个 `d` 扫一遍数组求和，取第一个满足条件的 `d`。时间是 `O(n · max(nums))`；本题 `n = 5*10^4`、`max(nums)` 最大 `10^6` ⇒ 最坏约 `5*10^10` 次除法，不可行。

2. **瓶颈定位**：慢在"**把答案空间线性枚举了一遍**"。而判定本身 `O(n)` 已经无法再省（要求出整个和），所以唯一的突破口是**减少判定次数**。

3. **关键转化**：利用 `P(d)` 的**单调性**（`d ↑ ⇒ Σ⌈x/d⌉ ↓`）把"逐个试"换成"二分定位答案"，判定次数从 `O(max(nums))` 降到 `O(log max(nums)) ≈ 20` 次。

   同时把判定式化成**纯整数**形式（避免 `ceil` 调用与浮点）：

   ```
   ⌈x/d⌉ = (x - 1) // d + 1        （要求 x ≥ 1，本题满足）
   ⇒ P(d) ⟺ Σ((x-1)//d) + n <= threshold
          ⟺ Σ((x-1)//d) <= threshold - n   （n 是常量，整体右移一次即可）
   ```

   用户代码正是这么写的：内层只算 `(x - 1) // mid`，右边统一减去 `len(nums)`——比每个元素各自 `+1` 少一次加法，也避免了对 `n` 的重复处理。

4. **最优解**：`left = 0`（哨兵：恒定不可行，因为除数必须 ≥ 1）、`right = max(nums)`（恒定可行：每个数除以 ≥ max 后 `⌈x/d⌉ = 1`，和为 `n <= threshold`），区间内二分。这个 `while left + 1 < right` / `return right` 的写法是"**找最小可行值**"的标准型。

### 关键点

- **判据族定位**：本题二分的是**答案值**（二分答案），不是数组下标。同目录下另有一族是"有序序列上的下标二分"，两族的 `while` 写法、边界处理、单调性来源都不同，**不要串用**。
- **判定式的等价性**：`Σ⌈x/d⌉ <= threshold ⟺ Σ((x-1)//d) <= threshold - n`。左式减右式恰好是 `n`（每一项 `⌈x/d⌉ - (x-1)//d = 1`），**这个 `- n` 不能漏**（漏掉会让判定变严、答案偏大，官方示例 1 就会退化成 2）。
- **循环不变式**：`left` 恒为"已知不可行"，`right` 恒为"已知可行"，每次收缩都保持它，循环终止时 `left + 1 == right`，故 `right` 就是最小可行值。
- **`right = max(nums)` 的可行性依赖题面保证 `n <= threshold`**：这是题面给的，不是推导出来的。约束里没有这条的话（`threshold < n`）就无解。
- **`mid` 不会取到 0**：`left >= 0` 且 `left + 1 < right` ⇒ `right >= 2` ⇒ `mid = (left+right)//2 >= 1`，所以内层除法安全。`left = 0` 只是哨兵，永远不参与判定。

## 三、代码实现

### 最终代码

```python
class Solution:
    def smallestDivisor(self, nums: List[int], threshold: int) -> int:
        left = 0
        right = max(nums)

        while left + 1 < right:
            mid = (left + right) // 2
            if sum((x - 1) // mid for x in nums) <= threshold - len(nums):
                right = mid
            else:
                left = mid
        return right
```

## 四、复杂度分析

> 复杂度中的 n 指 `len(nums)`；V 指答案空间上界 `max(nums)`（本题 ≤ `10^6`）。

| 版本 | 时间复杂度 | 空间复杂度 |
| :--- | :--- | :--- |
| **最终代码** | `O(n log V)`，约 `5*10^4 × 20 = 10^6` 次整数除法 | `O(1)` |
| 朴素解法（枚举每个 d） | `O(n · V)`，最坏约 `5*10^10` 次 | `O(1)` |
| 实用下界 | `Ω(n)`（至少要读一遍数组）；在"只能整体求和来判定可行性"的前提下 `O(n log V)` 已是标准形态 | `O(1)` |

数值感受（`n = 5*10^4`、`V ≈ 10^6`）：朴素解要比二分解多做约 **5 万倍**的除法。判定的 `O(n)` 无法避免（可行探测必须算完整和），能省的只有"探测次数"，所以本题优化的方向只能是**减少 `O(n)` 判定的次数或单次判定的常数**。

## 五、优化评估

**结论**：**渐进已最优**（`O(n log V)`），但常数层面还有两类**实测有效**的改动：一类稳赚（一次 C 层求和 + 严格下界收缩），一类条件收益（`d0` 探针 / 内层提前退出），另有两条被实测证伪。全部数据来自本次实测（`n = 5*10^4`、5 档场景、9 个版本**同一轮轮转**、7 轮取最优；倍数 = 版本耗时 / 用户版耗时）。

### 瓶颈分析

单次运行 = `≈20` 次探测 × `n` 次"整数除法 + 加法"，**耗时几乎 100% 落在这条 Python 层循环上**（没有可预先建立的索引/桶：排序不影响 `Σ⌈x/d⌉` 的结构，值域桶 `V = 10^6` 反而更贵）。实测用户版在四个场景的绝对耗时高度一致（52.2 ~ 53.1 ms），只有"答案就是 1"的档是 10.1 ms（4 次探测就结束）——这正好说明耗时 `∝ 探测次数 × n`。

### 可优化空间：① 稳赚 —— 一次 C 层求和 + 严格下界收缩

- **探针**：`P(1) ⟺ Σx <= threshold`，而这个和可以用 `sum(nums)`（**C 层**）算出来，比"用 Python 生成器对 `d=1` 求和"快约 4 倍。命中时直接返回 1，一次二分都不用跑。
- **下界**：`P(d) ⇒ Σx/d <= Σ⌈x/d⌉ <= threshold ⇒ d >= ⌈Σx/threshold⌉ =: d0`。注意这是**必要条件**，所以 `d < d0` 全部不可行，可以把二分的左端从 0 直接提到 `d0 - 1`，砍掉 `[0, d0)` 这一段探测。

实测（B 版）：**五档全不亏** —— S2（答案 1）**0.024×（快 42 倍，逐轮区间 [0.020, 0.026]）**；S3 / S4 分别 0.964× / **0.940×（全<1）**；S1 / S5 逐轮区间跨 1.0（噪声内持平）。两个子改动的归因是干净的：S2 的 42 倍**全部**来自探针（只加下界的 `B''` 在该档 1.009×，因为该档 `d0 = 1`，下界本来就无从收缩）；S3 / S4 的 3~6% **全部**来自下界（只加探针的 `B'` 在两档分别是 1.006× / 0.986×，跨在噪声带上）。

### 可优化空间：② 条件收益 —— 判定 `d0` 本身（甜区：答案恰好落在下界）

既然 `d0` 是必要条件，那么"`P(d0)` 成立 ⟺ 答案就是 `d0`"：一次 `O(n)` 判定就能直接收工；若判定失败，还能把 `left` 直接取为 `d0`（已实测不可行），比 ① 再省一次探测。实测（F 版）：**S4（全同大值，答案 = `d0` = 100000）0.058×（快 17 倍，逐轮 [0.056, 0.062]）**；代价是未命中时白付一次 `O(n)` 判定 —— S1 1.049×、S5 1.045×（**全>1**，约 +4~5%，正好是 1/20 的探测预算）。

⚠️ F 版有个**必须保留的分支**：`d0 = 1` 时（等价于 `Σx <= threshold`）要走**C 层 `sum(nums)`**，不能把探针一律写成 `sum((x-1)//d0 for x in nums)` —— 后者是 Python 生成器循环，实测 S2 档会从 0.024× 退化到 **0.261×**。

### 可优化空间：③ 条件收益 —— 内层提前退出（甜区：`threshold - n` 极小）

判定式各项非负 ⇒ 累加值一旦超过 `limit = threshold - n` 就可以 `break`。实测（C 版）：**S3（`threshold = n` ⇒ `limit = 0`）0.064×，比 ① 再快 15 倍（逐轮 [0.062, 0.065]）**，插桩显示内层访问量从 `20n` 降到 **4.8%**。但代价是明显且可复现的：剪枝不触发时"每个元素多一次比较"，S1 1.035×、S5 **1.042×（全>1）**。

为什么它和 ① 的收益高度重叠？**剪枝只在"探测点落在答案左侧（不可行侧）"时才有机会触发**——探测点 ≥ 答案时必须算完整和，一次都省不掉。而 ① 的下界收缩已经把 `[0, d0)` 整段砍掉了，剩下的探测点几乎全部落在答案右侧。插桩佐证（访问量，A = `20n` 为基准）：

| 场景（答案 / 下界 d0） | A 探测次数 | C（含下界）访问量比 | C0（**去掉下界**的纯剪枝）访问量比 |
| :--- | ---: | ---: | ---: |
| S1 随机大值 th=3n（199302 / 166054） | 20 | 0.997 | 0.973 |
| S2 小值 th=1e6（1 / 1） | 4 | 0.000（探针直接返回） | 0.000 |
| S3 极紧 th=n（999994 / 497875） | 20 | 0.048 | 0.048 |
| S4 全同大值 th=10n（100000 / 100000） | 20 | 0.950 | 0.940 |
| S5 随机中值 th=100n（5021 / 4996） | 20 | 1.000 | 0.987 |

S1 / S5 里"纯剪枝"也只省 2.7% / 1.3% —— 因为这两档答案紧贴下界（199302 vs 166054、5021 vs 4996），二分的探测点**几乎全部落在可行侧**；S3 之所以大赚，是因为该档答案贴在区间上界（= `max(nums)`），19 次探测**几乎全是不可行探测**，而 `limit = 0` 让它们第一次越界就退出。

### 被证伪的两条（实测净负，已排除）

- **降序预处理**（把大元素排在前面，让累加更快越界）：五档全不赚 —— S1 1.176×、S5 **1.288×（全>1）**；S3 档 0.130× 也明显劣于纯循环剪枝的 0.064×（该档 `limit = 0`，随机顺序下第一个元素就能触发，`sorted` 的 `O(n log n)` 纯属白付）。⇒ 排除。
- **分块求和**（每 1024 / 8192 个元素用一次 C 层 `sum`，想同时拿到"C 层速度"与"剪枝"）：S3 档 0.083× / 0.214×，均劣于纯循环剪枝的 0.064×（一块必须整块扫完才能判一次）；其余档仍 +5% ~ 7%（S5 1.070× 全>1）。⇒ 排除。

### 优化代码

**推荐（稳赚、零回退）**：C 层探针 + 严格下界收缩。

```python
class Solution:
    def smallestDivisor(self, nums: List[int], threshold: int) -> int:
        n = len(nums)
        limit = threshold - n                    # Σ((x-1)//d) <= threshold - n
        total = sum(nums)                        # 一次 C 层求和：既算下界，也判 d=1
        if total <= threshold:                   # P(1) 成立 ⇒ 答案就是 1
            return 1
        left = (total + threshold - 1) // threshold - 1   # 下界 d0 - 1，必为不可行
        right = max(nums)
        while left + 1 < right:
            mid = (left + right) // 2
            if sum((x - 1) // mid for x in nums) <= limit:
                right = mid
            else:
                left = mid
        return right
```

**条件收益（甜区：答案恰好等于下界 `d0`）**：把探针升级为"直接判定 `d0`"。注意 `d0 = 1` 的分支必须保留 C 层 `sum`。

```python
class Solution:
    def smallestDivisor(self, nums: List[int], threshold: int) -> int:
        n = len(nums)
        limit = threshold - n
        total = sum(nums)
        if total <= threshold:                   # d0 == 1 的分支：走 C 层 sum，别用生成器
            return 1
        d0 = (total + threshold - 1) // threshold
        if sum((x - 1) // d0 for x in nums) <= limit:
            return d0                            # 下界本身可行 ⇒ 它就是答案
        left = d0                                # 已实测不可行，可直接当左端
        right = max(nums)
        while left + 1 < right:
            mid = (left + right) // 2
            if sum((x - 1) // mid for x in nums) <= limit:
                right = mid
            else:
                left = mid
        return right
```

**条件收益（甜区：`threshold - n` 极小）**：内层提前退出。

```python
class Solution:
    def smallestDivisor(self, nums: List[int], threshold: int) -> int:
        n = len(nums)
        limit = threshold - n
        total = sum(nums)
        if total <= threshold:
            return 1
        left = (total + threshold - 1) // threshold - 1
        right = max(nums)
        while left + 1 < right:
            mid = (left + right) // 2
            s = 0
            for x in nums:
                s += (x - 1) // mid
                if s > limit:                    # 各项非负 ⇒ 越界即可退出
                    break
            if s <= limit:
                right = mid
            else:
                left = mid
        return right
```

**优化理由**：三类改动的共同点是"**减少 `O(n)` 判定的次数**"（探针/下界 = 少跑几次二分；提前退出 = 少扫几个元素），而不是"让一次判定更快"——后者在本题受限于"可行探测必须算完整和"，天花板很低（用户版 `while` 循环体内的可省成本实测不到 5%）。①② 在各自甜区之外的代价是 +4~5%（白付一次 `O(n)` 探测）与 +3~4%（白付每元素一次比较），因此**推荐只落 ①**；②③ 要按输入结构（答案是否贴近下界 / `threshold` 是否贴近 `n`）决定，不属于无条件替换。

## 六、易错点与总结

### 易错点

- **漏掉 `- len(nums)`**：`Σ((x-1)//d)` 比 `Σ⌈x/d⌉` 正好少 `n`，写成 `<= threshold` 会让判定变严、答案偏大。最小反例就是**官方示例 1**：`nums = [1,2,5,9], threshold = 6` 会返回 `2`（真值 `5`）。
- **`ceil` 的三种写法**：`(x-1)//d + 1`、`(x + d - 1)//d`、`-(-x//d)` 都对（本题 `x ≥ 1`）；不要用 `math.ceil(x/d)`（浮点 + 函数调用），也别用 `round`。
- **区间端点语义写反**：`left` 必须是"已知不可行"、`right` 必须是"已知可行"。本题 `right = max(nums)` 的可行性来自题面保证 `n <= threshold`——去掉这条保证（例如自己造 `threshold < n` 的用例）整个解法就无解了。
- **`left = 0` 只是哨兵**：`while left + 1 < right` 保证了 `mid >= 1`，所以内层除法安全。若改成 `while left <= right`、或写成 `left = mid + 1` 的闭区间变体，`mid` 就可能取到 0 → `ZeroDivisionError`。
- **别凭"二分都要 `mid ± 1`"的肌肉记忆改边界**：本题是"左侧恒不可行"的开区间写法，`left = mid`（不加 1）与 `right = mid`（不减 1）才是对的，加/减 1 会丢掉正确答案。

### 题型套路沉淀

- **"最小化某个值使条件成立" + 条件关于该值单调 ⇒ 二分答案**。标准模板（本题即此形）：

  ```python
  lo = 不可行哨兵; hi = 可行哨兵
  while lo + 1 < hi:
      mid = (lo + hi) // 2
      if feasible(mid):
          hi = mid
      else:
          lo = mid
  return hi
  ```

  与"下标二分"的区别：这里二分的对象是**答案值**、区间端点的可行性是**先验已知**的（哨兵），而不是靠数组本身的有序性。
- **本题两个可复用的优化杠杆**（都属"减少判定次数"，比"加快单次判定"值钱得多）：
  1. **必要条件做下界**：从不等式推出 `d >= ⌈Σx/threshold⌉`，把答案空间左端一次性抬起来。任何"最小化某值"的题都可以先问一句"能不能用一个廉价的必要条件把搜索区间砍掉一截"。
  2. **端点探针**：把"最可能命中的那个端点"用一次**更便宜的 C 层运算**判掉（本题 `Σx <= threshold` 用 `sum()`；推广到 `d0` 之后就是"下界是否已经可行"）。
- **判据族判别**：写本题时不要在谓词里掺"下标""有序性"这类属于下标二分的前提，也不要套用滑动窗口的单调性框架——本题的单调性来自 `⌈x/d⌉` 关于 `d` 的单减性，与窗口收缩无关。
