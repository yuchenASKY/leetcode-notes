# 3281. 范围内整数的最大得分

> **难度**：中等
> **标签**：数组 · 二分查找 · 贪心 · 排序
> **原题链接**：https://leetcode.cn/problems/maximize-score-of-numbers-in-ranges/

---

## 一、题目描述

给定数组 `start` 与整数 `d`，得到 `n = len(start)` 个长度都等于 `d` 的闭区间 `[start[i], start[i] + d]`。要求从**第 i 个区间里取一个整数**（每个区间恰好取一个，共取 n 个），把这些整数的**得分**定义为「任意两个所选整数之差的绝对值中的最小值」。求能取到的最大得分。

### 示例

```text
输入：start = [6,0,3], d = 2
输出：4
解释：三个区间分别是 [6,8]、[0,2]、[3,5]。
      取 8、0、4，得分 = min(|8-0|, |8-4|, |0-4|) = 4。
      注意 4 落在 [3,5] 内、0 落在 [0,2] 内，都合法；再大就放不下了。

输入：start = [2,6,13,13], d = 5
输出：5
解释：区间为 [2,7]、[6,11]、[13,18]、[13,18]。
      取 2、7、13、18，得分 = 5。
```

### 约束条件

- `2 <= start.length <= 10^5`
- `0 <= start[i] <= 10^9`
- `0 <= d <= 10^9`

---

## 二、解题思路

### 核心思想

**把「最大化最小差值」改成判定问题，再对答案二分。** 判定「得分能否达到 t」时，只需要一个问题：能不能让取出的 n 个数两两相差都不小于 t。这个问题可以用「排序后逐个区间取最小可行值」的贪心在 O(n) 内回答。答案对 t 单调（t 可行则更小的 t 必可行），于是二分。

### 思路演进

1. **暴力解法**：每个区间有 `d + 1` 种取值，组合总数 `(d+1)^n`。`d` 最大到 `10^9`，即使 `n = 2` 也不可能枚举；退一步「按 t = 0,1,2,… 逐个试」，每次判定 O(n)，总复杂度 O(n·V)，其中 V 是答案值域上界，最大约 2×10⁹ —— 仍然是 10¹⁵ 级别，必然超时。所以需要找到**答案的单调性**。

2. **关键转化一（去重化简）**：一堆数两两之间的最小绝对差，等于**把它们排好序之后相邻两数之差的最小值**。因此「任意两数之差的绝对值都 ≥ t」等价于「排序后每对相邻数之差都 ≥ t」。判定时只要关心一条有序链，不需要检查所有数对。

3. **关键转化二（区间可重排）**：题面说「第 i 个数必须属于第 i 个区间」，但得分只与取到的这堆数有关、与谁是第几个无关。所以把区间按左端点排序只是给区间重新排了个队，**不改变可行的数集，也不改变答案**。排序后区间下界单调不减，后面才能做从左到右的贪心。

4. **判定用的贪心（关键）**：设上一位置取的数是 `cur`，当前区间的下界是 `s = start[i]`。为了让当前数既满足「比 cur 至少大 t」又落在区间内，必须取
   `max(cur + t, s)`。
   - 不能取更小：`cur + t` 是硬性下限，`s` 是区间下限。
   - 取更大没有意义：在满足约束的前提下，当前取值越小，留给后面区间的空间越大。
   所以「每步取最小可行值」是贪心的最优策略。若算出的值超过 `s + d`，说明这一位无论如何都放不下，t 不可行。

5. **二分答案**：`t` 的下界是 `0`，上界是 `max(start) - min(start) + d`（因为所有取值都落在 `[min(start), max(start) + d]` 这个跨度里，任意两数之差不会超过它）。可行区间用「开区间」写法：`left = -1` 作**可行哨兵**、`right = 上界 + 1` 作**不可行哨兵**，二分结束后 `left` 就是最大可行 t。

### 关键点

- **判定的贪心方向**：每一步取尽可能小的值，是一个"只会放宽后续约束"的动作，所以局部最优即全局最优。
- **必须排序**：不排序时区间下界不单调，贪心会让 `cur` 被某个下界很大的区间顶到很高，后面下界更小的区间反而接不上。
- **边界哨兵取 `-1` 与 `上界 + 1`**：`t = 0` 未必一定可行吗？实际可行（同一区间内可以取相同的数，差为 0 也满足 ≥ 0 的恒等关系），但把 `left = -1` 当作永远可行的哨兵，可以让二分模板不需要单独处理 `check(0)`，写法统一。
- **上界不是 `d + 1`**：跨度来自 `max(start) - min(start)` 与 `d` 的叠加。

## 三、代码实现

### 最终代码

```python
class Solution:
    def maxPossibleScore(self, start: list[int], d: int) -> int:
        start.sort()

        def check(t: int) -> bool:
            cur = start[0]
            for i in start[1:]:
                if i + d < cur + t:
                    return False
                cur = max(cur + t, i)
            return True

        left = -1
        right = max(start) - min(start) + d + 1
        while left + 1 < right:
            mid = (left + right) // 2
            if check(mid):
                left = mid
            else:
                right = mid
        return left
```

## 四、复杂度分析

| 版本 | 时间复杂度 | 空间复杂度 |
| :--- | :--- | :--- |
| **最终代码** | O(n log n + n log V) | O(n)（排序辅助），不计排序为 O(1) |
| 朴素解法 | O(n · V) | O(1) |
| 理论下界 | O(n log n + n log V) | O(1) |

> 复杂度中的 n 指 `start` 的长度；V 是答案的值域上界 `max(start) - min(start) + d`，最大约 2×10⁹，故 `log V ≈ 31`。
>
> 排序 O(n log n) 是一次性开销；之后每层二分做一次 O(n) 的贪心判定，共 `log V` 层。与「把 t 从 0 逐个往上试」的 O(n·V) 相比，差在把「线性枚举答案」换成了「在答案空间上二分」。

## 五、优化评估

**结论**：时间复杂度已贴近下界，**大 O 没有可压缩的空间**。

### 瓶颈分析

判定阶段必须检查全部 n 个区间（任何一个区间放不下都会让 t 不可行），所以单次判定不可能低于 O(n)；而答案在值域上是离散单调的，除二分之外的等价路线仍是 `log V` 层级。两部分相乘即为总代价，当前写法已经把这个结构用满。

### 可优化空间

- **没有更优的渐进路线**：不存在绕开「读一遍所有区间」的判定方式。
- **空间无法再降的部分**：`start.sort()` 的原地排序在 CPython 里需要 O(n) 的临时缓冲，这属于内建实现，不算算法额外空间。

### 常数级优化（可选）

- `for i in start[1:]:` 每次进入 `check` 都会把 `start` 复制一份（O(n) 拷贝，`log V ≈ 31` 次），改成按下标遍历可以省掉这块拷贝：

```python
class Solution:
    def maxPossibleScore(self, start: list[int], d: int) -> int:
        start.sort()
        n = len(start)
        s0 = start[0]

        def check(t: int) -> bool:
            cur = s0
            for k in range(1, n):
                s = start[k]
                if s + d < cur + t:
                    return False
                cur = cur + t if cur + t > s else s
            return True

        left = -1
        right = start[-1] - s0 + d + 1
        while left + 1 < right:
            mid = (left + right) // 2
            if check(mid):
                left = mid
            else:
                right = mid
        return left
```

- `max(a, b)` 在热点里是函数调用，用条件表达式替代可少一次调用；`max(start) / min(start)` 在已排序的数组上直接取 `start[-1] / start[0]` 即可（最终代码里的那次调用也只发生一次，影响可忽略）。

## 六、易错点与总结

### 易错点

- **忘记排序**：直接在原始 `start` 上贪心会让 `cur` 被高下界区间顶高，后面低下界的区间接不上，判定结果偏保守 —— 表现是答案偏小但不报错，很难发现。
- **判定里写成 `cur = cur + t`**：当 `cur + t < start[i]` 时取到的值落在区间外（小于下界），是非法取值。必须是 `max(cur + t, start[i])`。
- **上界取成 `d + 1`**：跨度里还有 `max(start) - min(start)` 一项，漏掉后二分右边界可能小于真实答案。
- **二分哨兵用闭区间写法但 `check(0)` 不单独处理**：`left = 0` 的前提是「0 一定可行」，虽然本题确实成立，但开区间写法（`-1` / `上界 + 1`）不依赖这个前提，更不容易写错。
- **原地 `start.sort()` 修改了入参**：本题无副作用要求，但在需要复用输入的场景里要留意。

### 题型套路沉淀

- **二分答案（最大化最小值 / 最小化最大值）三件套**：① 把最优化转成「给定 t 是否可行」的判定；② 论证单调性（t 可行 ⇒ 更小的 t 可行）；③ 写一个 O(n) 的贪心判定，外层二分收紧答案。
- **开区间二分模板**（哨兵都不满足条件，循环条件 `left + 1 < right`，结束返回 `left`）：不会死循环，也不用纠结 `mid` 的取整方向。
- **「最大化最小间隔」类判定的通用骨架**：先排序，再从左到右「每步取最小的可行值」，任何一步放不下即失败。区间问题里要注意下限是「上一个值 + t」与「本区间下界」的**较大者**，上限是「本区间上界」。
- 遇到「得分/代价是两两之间最小值」的描述，先想到「排序后只需看相邻项」，能把判定从 O(n²) 的直觉压到 O(n)。
