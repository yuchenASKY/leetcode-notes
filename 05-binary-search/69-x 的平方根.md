# 69. x 的平方根

> **难度**：简单
> **标签**：二分查找 · 数学
> **原题链接**：https://leetcode.cn/problems/sqrtx/

---

## 一、题目描述

给一个非负整数 `x`，求它的**算术平方根**的**整数部分**（小数部分直接舍去），即返回最大的满足 `k * k <= x` 的整数 `k`。

禁止使用任何内置指数函数和算符，例如 `pow(x, 0.5)` 或 `x ** 0.5`。

### 示例

```text
输入：x = 4
输出：2

输入：x = 8
输出：2
解释：8 的算术平方根是 2.82842...，由于返回类型是整数，小数部分将被舍去。
```

### 约束条件

- `0 <= x <= 2^31 - 1`
- 不允许使用内置的指数/开方函数

---

## 二、解题思路

### 核心思想

**「最大的满足 `k * k <= x` 的整数 `k`」这个性质在答案两侧是单调的** —— 小于等于答案的一侧全部可行、大于答案的一侧全部不可行。于是把「求平方根」变成在一个有序的、由真假组成的序列上找**最后一条可行位置**，二分即可。

### 思路演进

1. **暴力解法**：从 `k = 0` 开始逐个试，只要 `k * k <= x` 就继续加，直到第一个 `k * k > x` 就返回 `k - 1`。时间 O(√x)，`x` 取到 `2^31 - 1` 时大约要试 46341 次 —— 能过，但把「最多 31 次比较就能定位的事」做成了 4 万多次。

2. **观察到**：判定函数 `f(k) = (k * k <= x)` 在 `[0, +∞)` 上是**单调的**：一旦某个 `k` 不满足，它后面的所有数都不满足。整个值的分布就是「前面一段全 true，后面全 false」。这就是标准的二分段结构，答案就是 true 段的最后一个下标。

3. **优化为**：在 `[0, x + 1]` 上二分。维护**「left 恒可行、right 恒不可行」的开区间语义**，每轮取中点判定，可行就抬 `left`，不可行就压 `right`，区间每次减半；当 `left + 1 == right` 时两端已经夹死，`left` 就是答案。迭代次数是 `log2(x + 1)`。

### 关键点

- **`right = x + 1` 是哨兵，不是随便写的**：`(x + 1)^2 > x` 对一切 `x >= 0` 成立，所以右端点天然「不可行」，不需要额外的边界特判；而且 `x = 0` 时区间退化成 `[0, 1]`，循环一次都不进，直接返回 `0`。
- **循环条件是 `left + 1 < right`，而不是 `left < right`** —— 这是本题最容易翻车的地方。因为 `mid = (left + right) // 2` 是**向下取整**，若写成 `while left < right` 还配 `left = mid`，当区间缩到 `right == left + 1` 时 `mid` 恒等于 `left`，判定为真就把 `left` 设回它自己，**死循环**。让循环在两端相邻时停止，正好把「答案」留在了 `left` 上。
- **返回 `left`，不是 `right`**：`left` 是可行侧（`left² <= x`），`right` 是不可行侧（`right² > x`）。
- 判定写成 `mid * mid - x <= 0` 与 `mid * mid <= x` 完全等价；Python 的整数不会溢出，这里不必担心 `mid²` 越界（`mid` 最大约 2^31，平方仍在任意精度范围内）。

---

## 三、代码实现

### 最终代码

```python
class Solution:
    def mySqrt(self, x: int) -> int:
        left = 0                    # 恒满足 left * left <= x
        right = x + 1                # 恒不满足 right * right <= x
        while left + 1 < right:      # 两端相邻时停止，left 即答案
            mid = (left + right) // 2
            if mid * mid - x <= 0:   # 可行：答案至少是 mid
                left = mid
            else:                    # 不可行：答案必小于 mid
                right = mid
        return left
```

## 四、复杂度分析

| 版本 | 时间复杂度 | 空间复杂度 |
| :--- | :--- | :--- |
| **最终代码** | O(log x) | O(1) |
| 朴素解法（逐个试） | O(√x) | O(1) |
| 理论下界 | O(log x) | O(1) |

> 复杂度中的 n 指：本题没有数组，规模就是 `x` 本身。二分区间长度从 `x + 1` 开始每轮减半，迭代次数约 `log2(x + 1)`；`x = 2^31 - 1` 时最多约 31 轮。

## 五、优化评估

**结论**：在题目限制下**已是最优**。

### 瓶颈分析

每一轮二分只做一次乘法比较和一次区间收缩，没有可省的重复计算；空间上只用了两个下标变量，O(1) 已经到顶。

### 可优化空间

- **为什么不可能更好**：结果是整数、是在一棵「可行 / 不可行」的有序结构上定位分界点，每次比较最多提供 1 bit 信息，而候选集合有 `x + 1` 个元素，信息论下界就是 `log2(x + 1)` —— 二分恰好达到这个下界。
- **换算法但不换量级**：牛顿迭代 `x_{n+1} = (x_n + x // x_n) // 2` 同样是对数级收敛，代码更短，但在 `x` 为小值或完全平方数附近需要额外处理收敛判据，可读性不如二分，本题没有换的必要。
- **O(1) 的路线被题目封死**：浮点开方后取整的 O(1) 做法依赖 `sqrt` / `pow` / `** 0.5`，题目明令禁止；即便允许，也要处理 `2^31 - 1` 这类浮点误差导致的 off-by-one。

### 常数级优化（可选）

- `mid = (left + right) // 2` 改写成 `mid = left + (right - left) // 2` 在 C++/Java 里是防溢出的必要动作，在 Python 里属可读性选择，两者等价。
- 判定放成 `mid * mid <= x` 比 `mid * mid - x <= 0` 少一次减法，语义也更直白。

## 六、易错点与总结

### 易错点

- **`while left + 1 < right` 与 `left = mid` 必须配套**：改成 `while left < right` 就会在 `right == left + 1` 且 `mid` 可行时原地打转（如 `x = 4`，`left = 2, right = 3`，`mid` 恒为 2）。若坚持 `left < right`，就得改用上取整 `mid = (left + right + 1) // 2`。
- **`right` 初值取 `x` 而不是 `x + 1` 会错**：`x = 1` 时区间直接是 `[0, 1]`，循环不进入、返回 `0`，而正确答案是 `1`。
- **返回 `right`**：`right` 是不可行侧，返回值会整体偏大 1。
- **用 `math.isqrt` / `x ** 0.5` / `pow`**：题目明确禁止内置指数函数与算符，写了解答也无效。

### 题型套路沉淀

- **「找最后一个满足条件的元素」型二分**：判定函数单调时，把区间维护成「左端可行 / 右端不可行」，循环到两端相邻，答案落在可行侧。
- **定式模板（闭开区间 + 端点哨兵）**：
  ```python
  lo, hi = <可行下界>, <不可行上界>
  while lo + 1 < hi:
      mid = (lo + hi) // 2
      if check(mid): lo = mid
      else:          hi = mid
  return lo
  ```
  只要 `check` 在左侧全真、右侧全假，这个骨架就不会死循环、不会差一。凡是「最大的 k 使 f(k) 成立」都可以直接套。
- **边界靠哨兵吃掉，别靠特判**：把右端点设成「一定不满足」的值，`x = 0`、`x = 1` 这类退化输入自然被循环条件挡住，不用写 `if x < 2: return x`。
