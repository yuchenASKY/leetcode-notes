# 1898. 可移除字符的最大数目

> **难度**：中等
> **标签**：数组 · 字符串 · 二分查找
> **原题链接**：https://leetcode.cn/problems/maximum-number-of-removable-characters/
> **完成状态**：❗ **未做出** —— 二刷目标：不看笔记，独立推出「判定函数关于 k 单调 ⇒ 可以二分答案」这一步，并自己写出一个**不会退化成字符存在性判断**的子序列判定。

---

## 一、题目描述

给定字符串 `s` 和 `p`（保证 `p` 是 `s` 的子序列），以及一个元素互不相同、取值均为 `s` 下标的数组 `removable`。要求找出**最大**的 `k`（`0 <= k <= removable.length`），使得「先把 `removable` 中前 `k` 个下标对应的字符从 `s` 中删掉」之后，`p` 仍然是剩下的 `s` 的子序列。

也就是说：删除是**前缀式**的（要么删前 k 个，要么一个都不删），要找一个最长的可删除前缀长度。

### 示例

```text
输入：s = "abcacb", p = "ab", removable = [3,1,0]
输出：2
解释：删掉下标 3、1 后 s 变成 "accb"，"ab" 仍是其子序列；
      再删掉下标 0 后 s 变成 "ccb"，"ab" 不再是子序列。
```

```text
输入：s = "abcab", p = "abc", removable = [0,1,2,3,4]
输出：0
解释：删掉 removable 的第一个下标 0 之后 s 变成 "bcab"，"abc" 不再是子序列，故只能取 k = 0。
```

```text
输入：s = "abcbddddd", p = "abcd", removable = [3,2,1,4,5,6]
输出：1
```

### 约束条件

- `1 <= p.length <= s.length <= 10^5`
- `0 <= removable.length < s.length`
- `0 <= removable[i] < s.length`
- `removable` 中的元素**互不相同**
- 保证 `p` 是 `s` 的子序列
- `s` 和 `p` 均由小写英文字母组成

## 二、解题思路

### 核心思想

**判定函数 `check(k)` 关于 `k` 单调（k 越大越难成立），于是「找最大的可行 k」变成可以在答案上二分。** 单次 `check` 只需 O(|s|) 扫描即可完成子序列判定。

### 思路演进

1. **暴力解法**：从 `k = 0` 开始逐个试，每试一个 `k` 就真的删掉 `removable[:k]` 个字符、再判定一次 `p` 是不是子序列。单次判定 O(|s|)，最坏要试 L+1 次（L = `removable.length`），总时间 O(L·|s|)。代入 |s| = L = 10^5 就是 10^10 量级，必然超时。
2. **观察到「单调性」**：把「删掉前 k 个下标」记成集合 `D(k)`，显然 `D(k1) ⊆ D(k2)` 当 `k1 <= k2`（删除是前缀式累积的）。于是剩下的字符串 `s - D(k2)` 是 `s - D(k1)` 的**子序列**。而子序列关系是可传递的：如果 `p` 是更短的 `s - D(k2)` 的子序列，它自然是更长的 `s - D(k1)` 的子序列。反过来不成立 —— **删得越多，`p` 越不可能还是子序列**。
   ⇒ `check(k)` 呈 `真 真 真 … 真 假 假 假` 的形状，答案就是最后一个「真」的位置。
3. **优化为「二分答案」**：既然判定结果单调，就没有必要逐个 k 试。在 `[0, L]` 上二分：`check(mid)` 为真说明答案**不小于** mid，把左界抬到 mid；为假说明答案严格小于 mid，把右界压到 mid。二分只需 O(log L) 轮，每轮 O(|s|)。
4. **判定函数的写法（本题真正的考点）**：判定「`p` 是否为剩余串的子序列」必须体现**相对顺序**，不能只判断「字符是否存在」。最简洁的写法是**用一个生成器把剩余字符按原顺序吐出来，再让 `in` 去逐个消费**：
   ```python
   it = (s[i] for i in range(len(s)) if i not in idx)
   return all(c in it for c in p)
   ```
   `c in it` 会不断从生成器里取字符**直到匹配到 c 为止**，并且游标**只前进、不回头**；下一个字符必须出现在上一个匹配位置之后。于是 `all(c in it for c in p)` 天然就是一遍扫描的子序列判定。这正是「顺序」被保住的机制。

### 关键点

- **二分的前提是先论证单调性**，而不是「感觉可以二分」。本题的单调性来自「删除集合随 k 单调增长 + 子序列关系可传递」。
- **`it` 必须是生成器（或迭代器），不能写成 `list` / `set`**。这是全题最容易写错的点：写成列表后 `c in it` 变成「字符是否出现过」的存在性查询，丢掉了顺序信息，在重复字符场景下会误判（见「易错点」）。
- **二分写法用开区间**：`left = -1`、`right = len(removable) + 1`，循环条件 `left + 1 < right`，最终返回 `left`。这样不用额外写「`check` 是不是为真」的 if 分支，天然覆盖 `k = 0` 与 `k = L` 两个端点。
- **`check` 内部的删除标记每轮都要重建**：生成器在上一轮已被消费干净，无法跨轮复用。

## 三、代码实现

### 最终代码

> 来自本人提交的代码（截图），未补 import —— 本题只用到内置的 `list[int]` 泛型（Python 3.9+），不需要任何导入。

```python
class Solution:
    def maximumRemovals(self, s: str, p: str, removable: list[int]) -> int:

        def check(x: int) -> bool:
            idx = set(removable[:x])                                  # 本轮被删掉的下标
            it = (s[i] for i in range(len(s)) if i not in idx)        # 剩余字符按原顺序吐出
            return all(c in it for c in p)                            # 生成器只前进 => 子序列判定

        left = -1                       # 哨兵：仅为二分下界，从不参与判定
        n = len(removable) + 1
        right = n
        while left + 1 < right:
            mid = (left + right) // 2
            if check(mid):
                left = mid              # mid 可行 => 答案不小于 mid
            else:
                right = mid             # mid 不可行 => 答案严格小于 mid
        return left                     # 循环结束时 left = 最大的可行 k
```

## 四、复杂度分析

| 版本 | 时间复杂度 | 空间复杂度 |
| :--- | :--- | :--- |
| **最终代码** | O((\|s\| + L) · log L) | O(L) |
| 朴素解法（逐个 k 试） | O(L · \|s\|) | O(L) |
| 理论下界 | O(\|s\| + L) | O(L) |

> 复杂度中的 `|s|` 指字符串 `s` 的长度，`L` 指 `removable` 的长度（`L < |s| <= 10^5`）。
>
> - 单次 `check` 要扫一遍 `s`，复杂度 O(|s|)；建删除标记集合是 O(x) ⊆ O(L)。二分轮数为 O(log L)，故总时间 O((|s| + L) log L)。
> - 「理论下界」那一行指的是**读入规模**的下界：任何算法都必须至少把 `s`、`p`、`removable` 读一遍；本题不存在「不扫描 `s` 就能判定子序列」的办法。
> - 空间 O(L) 来自每轮的删除标记集合（以及 `removable[:x]` 切片）。

## 五、优化评估

**结论**：在「二分答案 + 线性判定」这条路线内部，**已经是最优写法**；log 因子可以去掉，但需要很强的增量维护技巧，对本题数据规模不值得。

### 瓶颈分析

时间由两部分相乘构成：**二分轮数 O(log L)** × **单次判定 O(|s|)**。

- 单次判定这一项已经是下界：判定「`p` 是否为剩余串的子序列」必须按顺序扫过 `s`，少扫一个字符就可能漏掉唯一的匹配位置。
- 空间上的常数来自「把被删下标装进 `set`」：每轮都要建集合、做 `L` 次哈希插入与 `|s|` 次哈希查询。

### 可优化空间

- **去掉 log 因子**：理论上可以「时间倒流」—— 先算出删完全部 `removable` 后的串，再按 `removable` 的**逆序**逐个把字符加回来，同时增量维护 `p` 能匹配到的最长前缀长度。但插入一个字符可能让匹配位置整体前移，维护代价高、实现复杂度远大于收益，本题规模（10^5）下不值得。
- **压掉哈希开销**：把 `set` 换成 `bytearray(len(s))` 的标记位（下标即位置），配合标准双指针判定，省掉哈希表；空间开销从 O(L) 的哈希桶变成 O(|s|) 的字节数组，代码反而更直白。

### 优化代码

等价的「标记位 + 双指针」判定版本（大 O 不变，去掉哈希，语义更常规）：

```python
class Solution:
    def maximumRemovals(self, s: str, p: str, removable: list[int]) -> int:
        m, n = len(s), len(p)

        def check(x: int) -> bool:
            dead = bytearray(m)
            for i in removable[:x]:
                dead[i] = 1
            j = 0                                   # 已匹配到 p 的第 j 个字符
            for i in range(m):
                if dead[i] == 0 and j < n and s[i] == p[j]:
                    j += 1
            return j == n

        left, right = -1, len(removable) + 1
        while left + 1 < right:
            mid = (left + right) // 2
            if check(mid):
                left = mid
            else:
                right = mid
        return left
```

**优化理由**：两版的时间 / 空间复杂度完全相同（判定都是 O(|s|)、二分都是 O(log L)），差别只在常数与可读性 —— 生成器版更短、更 Pythonic；双指针版不依赖「迭代器只前进」这一隐式语义，语义外显，不容易被误改成列表。

### 常数级优化（可选）

- 生成器版里 `idx = set(removable[:x])` 的切片会产生一个临时列表，可直接写 `set(removable[:x])`（切片无法避免）或用 `itertools.islice` 惰性取前 `x` 个；后者省一次临时列表分配，但可读性下降。
- `check` 里把 `len(s)`、`s` 提到闭包外层局部变量可少几次属性查找，属于可忽略的微优化。

## 六、易错点与总结

### 易错点

- **把 `it` 写成列表 / 集合**：`all(c in it for c in p)` 只有在 `it` 是**迭代器（生成器）**时才是子序列判定；写成 `list` 或 `set` 就退化成「`p` 的每个字符都在剩余串里出现过」，丢掉了顺序与重数。反例：`s = "aaa"`、`p = "aa"`、`removable = [0,1]`，删完前两个只剩 1 个 `'a'`，正确的 `check(2)` 应为 `False`，而集合版会返回 `True`。
- **二分右界取成 `len(removable)`**：`k` 的合法取值是 `0..L`（含 `L`），右界必须取 `L + 1` 才能把 `k = L` 纳入搜索区间。本题的 `n = len(removable) + 1` 正是为此。
- **`left = -1` 是哨兵，不是候选值**：它只用来把区间写成开区间，**从不参与 `check`**。若真的有人去调用 `check(left)`，`removable[:-1]` 的负索引语义会删掉「除最后一个以外的所有下标」，得到完全相反的口径。（同理，别把 `left` 的初值设成 `0` 后在循环里直接 `return`，会漏掉答案为 `0` 的情况。）
- **每轮 `check` 复用同一个生成器**：生成器一旦被消费到尽头就永远为空，第二次判定会直接得到「剩余串为空」的错误结果。
- **只看 `p` 是否还是 `s` 的子字符串/子串**：本题是**子序列**，字符不必相邻，只要相对顺序保持；不要写成子串匹配（KMP 那一套在这里是杀鸡用牛刀）。

### 题型套路沉淀

- **二分答案的识别信号**：题目问「最大的 k 使某性质成立」，而这个性质恰好**关于 k 单调**（越大越难满足 / 越大越容易满足）。本题就是典型：删除集合随 k 单调增长 ⇒ 判定结果单调下降。
- **二分答案的标准结构**（三段式，务必背下来）：
  1. 写 `check(x) -> bool`，语义是「取 k = x 时性质是否成立」；
  2. 定区间与哨兵：本题 `left = -1`、`right = L + 1`，`while left + 1 < right`，返回 `left`；
  3. 在 ① 之前**先用一句话论证单调性** —— 没有单调性就没有二分，这一步不能跳。
- **子序列判定的正确写法**：单指针扫 `s`（`if s[i] == p[j]: j += 1`），或者像本题这样用「迭代器只前进」的隐式语义配合 `c in it`。两者复杂度相同，**共同点是游标绝不回头**。
- **单调性论证的通式**：把「操作集合」写出来，证明「可行性随集合增大而递减」（或反之），再引用关系的可传递性（子序列关系、包含关系等）即可完成论证。
