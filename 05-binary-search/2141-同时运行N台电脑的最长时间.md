## 一、题目描述

有 `n` 台电脑和若干电池，第 `i` 块电池可以为电脑供电 `batteries[i]` 分钟。开始时每台电脑至多接一块电池；之后可以在**任意整数时刻**把某台电脑的电池换掉，接上任意一块电池（新的或别台电脑用过的都行），切换不耗时。电池不可充电。求能让 `n` 台电脑**同时**运行的最长分钟数。

### 示例

```text
输入：n = 2, batteries = [3,3,3]
输出：4
解释：三块电池共 9 分钟，平均分给 2 台电脑即各 4 分钟。
      可以先各接一块、跑 2 分钟后对调，再用第三块电池补上最后一段时间。
```

```text
输入：n = 2, batteries = [1,1,1,1]
输出：2
解释：四块 1 分钟的电池，每台电脑分到两块，各跑 2 分钟。
```

### 约束条件

- `1 <= n <= batteries.length <= 10^5`
- `1 <= batteries[i] <= 10^9`

## 二、解题思路

### 核心思想

**答案是单调的 —— 能同时跑 `T` 分钟就一定能跑 `T - 1` 分钟，于是对答案二分。** 而「`T` 是否可行」只需要一次求和：每块电池最多贡献 `min(batteries[i], T)` 分钟，总贡献够 `n * T` 就行。

### 思路演进

1. **朴素解法（按过程模拟）**：顺着题面去安排「第几分钟让哪台电脑换哪块电池」。但切换点可以是任意整数时刻、一块电池也可以被切成多段分给不同电脑，可选调度方案是爆炸性的，既写不出确定的贪心顺序，也无法枚举。
2. **换一个角度**：不去安排「怎么跑」，而是问「最多能跑多久」。设答案为 `T`。关键观察是 `T` 有**单调性**：既然能同时跑 `T` 分钟，那么少跑一会儿当然也行（把最后那段砍掉即可，电池都不用重排）。⇒ 于是可以把「求最大值」变成「判断某个 `T` 是否可行」，再二分逼近最大的可行 `T`。
3. **如何判定 `T`**：把注意力从「时间轴」转到「每块电池能贡献多少」。因为切换零耗时、切换次数不限，**一块电池是可切分的** —— 它今天可以供电脑 A、之后供电脑 B，所以只需要关心它的总量，不必关心它接在哪。但一块电池对某台电脑的贡献不会超过 `T` 分钟：一台电脑总共才跑 `T` 分钟，而同一时刻只能接一块电池，给再多也用不上。因此第 `i` 块电池的有效贡献是 `min(batteries[i], T)`，于是

   **`T` 可行 ⟺ `Σ min(batteries[i], T) >= n * T`**

   必要性显然（总消耗 `n * T`，总供给不能少于它）；充分性来自「电池可任意切分、可随时更换」—— 只要总量够，就能把每块电池的可用时长切成若干段，贴到 `n` 台电脑的时间轴上拼满。
4. **二分答案**：判定一次是 `O(n)`，答案范围是 `[0, sum(batteries) // n]`（总供电量决定了平均上限）。为了统一使用半开区间写法，把上界取成 `sum // n + 1` 这个**必定不可行**的哨兵，`while l + 1 < r` 收敛后 `l` 就是最大可行值。

### 关键点

- **识别单调性是入口**：题面在描述「一个过程」，直接模拟很难；一旦意识到「可行性随 `T` 单调」，问题就归约成标准的二分答案。
- **电池可切分 ⇒ 只看总量**：「切换零耗时、次数不限」正是「每块电池的贡献可以随意拆分」的依据，也是判据能简化成一个求和的原因。
- **每块电池的贡献必须被 `T` 截断**：`min(b, T)` 里的 `T` 不能省 —— 一块 `10^9` 的电池在一台只跑 100 分钟的电脑上只能贡献 100 分钟，多出来的部分对「同时运行」毫无帮助。
- **上界要留哨兵**：`while l + 1 < r` 要求 `l` 恒可行、`r` 恒不可行。若直接取 `r = sum // n`，当总和恰好整除 `n` 时会把这个最优解排除在搜索区间之外，所以要 `+ 1`。
- **小数据同样成立**：`n = 1, batteries = [b]` 时 `r = b + 1`，一轮即得 `l = b`，无需特判。

## 三、代码实现

### 最终代码

```python
from typing import List


class Solution:
    def maxRunTime(self, n: int, batteries: List[int]) -> int:
        # 二分答案：l 恒为可行解，r 恒为不可行解（哨兵），收敛后 l 即最大可行值
        l, r = 0, sum(batteries) // n + 1
        while l + 1 < r:
            x = (l + r) // 2
            # 判定：每块电池最多贡献 min(b, x) 分钟，总贡献够 n * x 才可行
            if n * x <= sum(min(b, x) for b in batteries):
                l = x
            else:
                r = x
        return l
```

> 截图中的代码没有 `from typing import List`，此处已补上（LeetCode 判题环境自带，但本地直接运行需要）。

## 四、复杂度分析

| 版本 | 时间复杂度 | 空间复杂度 |
| :--- | :--- | :--- |
| **最终代码** | O(n log(S/n)) | O(1) |
| 朴素解法（线性枚举答案） | O(S) | O(1) |
| 理论下界 | O(n) | O(1) |

> 复杂度中的 `n` 指 `batteries` 的长度（电脑台数满足 `n <= batteries.length`）；`S` 指 `sum(batteries)`，即二分搜索的上界，最大约 `10^5 × 10^9 = 10^14`。

- 二分共 `O(log(S / n))` 轮，每轮判定要扫一遍全部电池 ⇒ 时间 `O(n log(S / n))`。
- 朴素解法从小到大枚举 `T`、每个 `T` 花 `O(n)` 判定，最坏要做约 `S / n` 次判定 ⇒ `O(S)`；`S` 的量级使它完全不可行。
- 任何算法都必须至少读一遍全部电池，故时间下界是 `Ω(n)`；空间上只维护 `l / r / x` 等标量，`O(1)`。

## 五、优化评估

**结论**：**已是最优**。

### 瓶颈分析

判定的每一步都取决于具体的电池值 `batteries[i]`，无法在不看它的情况下得到贡献 `min(b, x)`，所以每轮 `O(n)` 的扫描删不掉；而谓词是单调的 0/1 函数，二分已经是信息论框架下的最优搜索。空间上只有几个标量，没有可压缩的余地。

### 可优化空间

- 判定无法低于 `O(n)`：漏掉任何一块电池都可能把不可行的 `T` 误判成可行。
- 二分轮数无法低于 `log(答案范围)`：除此之外没有利用输入结构的更强手段（例如排序后跑前缀和再跳着判定，复杂度量级不变，且不改变本解的正确性）。
- 现有的生成器写法 `sum(min(b, x) for b in batteries)` 已经避免了构造中间列表，是本路线下自然的写法。

（本节无「优化代码」：没有值得替换的同复杂度写法。）

### 常数级优化（可选）

- 若 `sum(batteries) < n`，可直接返回 `0`，省掉几轮二分；但二分本身也能得到 `0`，属非必需的特判。
- 把 `min(b, x)` 展开成 `x if b > x else b` 能省一次函数调用，是纯粹的常数优化，不改复杂度。

## 六、易错点与总结

### 易错点

- **上界取错导致漏掉边界答案**：把 `r` 写成 `sum(batteries) // n`（少个 `+ 1`），在「总和恰好被 `n` 整除」的用例上会把最优解排除在区间外，结果比正确答案小 1。半开区间二分要求右端点是**已确认不可行**的值。
- **忘记对每块电池取 `min(b, T)`**：直接拿 `sum(batteries)` 去和 `n * T` 比，会把「单块超大电池」的余量错误地匀给所有电脑。例如 `n = 2, batteries = [100, 1]`：总量 101 看着能撑 50 分钟，但那块 1 分钟的电池只能补 1 分钟，实际答案是 **1**。
- **误以为要模拟切换顺序**：题面对「任意时刻断开/连接」的长篇描述是干扰项，认识到电池可任意切分后，问题与「怎么切、什么时候切」完全无关。
- **判据写成严格大于**：可行条件是 `>=`；取等号时电量恰好耗尽，仍是合法解。

### 题型套路沉淀

- **「求最长/最大 X，且能跑 `T` 就一定能跑 `T-1`」⇒ 二分答案**。识别信号：题目在描述一个过程或要求一个极值，而「合法性」随答案单调。
- **二分答案三件套**：① 写出单调的判定谓词 `check(T)`；② 取「恒为真」的下界与「恒为假」的上界（上界常加 1 当哨兵）；③ 用 `while l + 1 < r` 统一写法，收敛后取最大可行值。
- **过程类题目先找「等价的可切分 / 可交换模型」**：本题的「电池可任意切分、只需关心总量」正是把复杂调度问题降成一次求和的钥匙。
