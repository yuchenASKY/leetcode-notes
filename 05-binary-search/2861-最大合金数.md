# 2861. 最大合金数

> **难度**：中等
> **标签**：数组 · 二分查找
> **原题链接**：https://leetcode.cn/problems/maximum-number-of-alloys/

---

## 一、题目描述

有 `n` 种金属和 `k` 台机器。第 `i` 台机器造 **1 份**合金要消耗 `composition[i][j]` 份第 `j` 种金属；初始库存是 `stock[j]`，缺的部分可以按 `cost[j]` 的单价买入，总预算为 `budget`。**所有合金必须由同一台机器制造**，求预算内最多能造的合金数。

### 示例

```text
示例 1
输入：n = 3, k = 2, budget = 15, composition = [[1,1,1],[1,1,10]], stock = [0,0,0], cost = [1,2,3]
输出：2
解释：用第 1 台机器造 2 份，需买 2 份金属 1、2 份金属 2、2 份金属 3，花费 2*1 + 2*2 + 2*3 = 12 ≤ 15。

示例 2
输入：n = 3, k = 2, budget = 15, composition = [[1,1,1],[1,1,10]], stock = [0,0,100], cost = [1,2,3]
输出：5
解释：用第 2 台机器造 5 份，只需买 5 份金属 1、5 份金属 2（金属 3 库存充足），花费 5*1 + 5*2 = 15 ≤ 15。

示例 3
输入：n = 2, k = 3, budget = 10, composition = [[2,1],[1,2],[1,1]], stock = [1,1], cost = [5,5]
输出：2
解释：用第 3 台机器造 2 份，每种金属各缺 1 份，花费 1*5 + 1*5 = 10 ≤ 10。
```

### 约束条件

- `1 <= n, k <= 100`
- `0 <= budget <= 10^8`
- `composition.length == k`，`composition[i].length == n`
- `1 <= composition[i][j] <= 100`
- `stock.length == cost.length == n`
- `0 <= stock[i] <= 10^8`
- `1 <= cost[i] <= 100`
- 题面中的 `composition` / `stock` / `cost` 为 1-indexed（代码里按 0-indexed 访问即可）

## 二、解题思路

### 核心思想

**答案具有单调性，所以二分答案。** 能造出 `x` 份，就一定能造出任意少于 `x` 份的数量（少造只会少花钱），于是把「最大可行值」这类问题交给二分：判定函数 `check(x)` 返回「是否存在一台机器，造 `x` 份的总花费不超过 `budget`」。

### 思路演进

1. **暴力解法**：从 `x = 0` 开始逐个往上试，对每个 `x` 枚举 `k` 台机器判断可行性，直到第一次不可行。单次判定 O(nk)，而答案最大可达 10^8 量级，总复杂度 O(n·k·A)，必然超时 —— 枚举的每一步都只让答案 +1，信息量太低。
2. **观察到**：`check(x)` 关于 `x` 是**单调**的。`x` 变大时，每台机器每种金属的补购量只会不减，花费也只增不减，所以可行性只会从 `True` 变成 `False`，不会来回跳。这正是二分所需的性质。
3. **优化为**：在 `[0, 上界]` 上对答案做二分，判定次数从 O(A) 降到 O(log A)。
4. **关键转化（判定函数怎么算）**：第 `j` 台机器造 `x` 份的成本为
   `Σ_i max(x * composition[j][i] - stock[i], 0) * cost[i]` —— 库存够的那部分不算钱，缺的部分才按单价买入。再取 `k` 台机器里最小的那个成本与 `budget` 比较（**不能跨机器拼凑**，只能整体选一台）。
5. **上界怎么定**：由 `composition[i][j] >= 1` 可知，造 1 份合金至少消耗每种金属各 1 份。若 `x > max(stock)`，则每种金属都至少缺 `x - max(stock)` 份，哪怕只买最便宜的那种，也要花 `(x - max(stock)) * min(cost)`；超过预算即不可行。故
   `A <= max(stock) + budget // min(cost)`，取 `right = 该值 + 1` 就保证右端点是**不可行**的。

### 关键点

- 二分的是**答案本身**（合金数量），不是数组下标 —— 判断依据是「可行性关于答案单调」。
- 判定里必须有 `max(..., 0)`：库存富余的金属不能倒贴钱，否则会把不可行误判成可行（示例 1、3 的库存都不足以暴露这个 bug，示例 2 的 `stock[2] = 100` 才会暴露）。
- 每台机器算完要**清零**再算下一台；`budget` 是「一台机器」的预算，不是所有机器合计。
- 二分区间写法：`left = -1`（哨兵）、`right = 上界 + 1`（不可行），循环条件 `left + 1 < right`，结束时 `left` 是最后一个可行的值，即答案。

## 三、代码实现

### 最终代码

```python
from typing import List


class Solution:
    def maxNumberOfAlloys(self, n: int, k: int, budget: int, composition: List[List[int]], stock: List[int], cost: List[int]) -> int:
        def check(fenshu: int) -> bool:
            stockneed = [[] for _ in range(k)]
            money = 0
            for j in range(k):
                for i in range(n):
                    stockneed[j].append(max(fenshu * composition[j][i] - stock[i], 0))
            for j in range(k):
                for i in range(n):
                    money += stockneed[j][i] * cost[i]
                if money <= budget:
                    return True
                else:
                    money = 0
            return False

        left = -1
        right = max(stock) + budget // min(cost) + 1
        while left + 1 < right:
            mid = (left + right) // 2
            if check(mid):
                left = mid
            else:
                right = mid
        return left
```

> 说明：`from typing import List` 截图里没有（LeetCode 环境自带），已补齐。截图在 `if check(mid):` 一行被编辑面板底边截断，其后按同样的开区间写法补全为 `left = mid` / `else` / `right = mid` / `return left`。

## 四、复杂度分析

| 版本 | 时间复杂度 | 空间复杂度 |
| :--- | :--- | :--- |
| **最终代码** | O(n·k·log A) | O(n·k) |
| 朴素解法（线性枚举答案） | O(n·k·A) | O(n·k) |
| 理论下界 | O(n·k·log A) | O(n) |

> 复杂度中的 n 指金属种类数（`stock`、`cost` 的长度）；k 指机器台数；A 指最大合金数，其量级上界为 `max(stock) + budget // min(cost)`，故 `log A ≈ log(max(stock) + budget)`。

## 五、优化评估

**结论**：时间复杂度已到理论下界（每次判定必须把 k 台机器的 n 种金属都看一遍），但代码里的 **O(n·k) 空间可以压到 O(n)**。

### 瓶颈分析

时间上，`check` 的 O(nk) 无法再省 —— 想判断某台机器是否可行，就必须知道它每一种金属缺多少。真正多余的是**先把 k×n 的欠料表整张存下来**：对某一台机器而言，算完欠料就能立刻乘单价累加金额，没必要为所有机器先建表。

### 可优化空间

把「建表」和「求和」合并成一趟：外层枚举机器 `j`，内层一边算欠料一边累加金额，金额一旦超过 `budget` 就可以提前跳出内层循环。只需为当前机器保留临时变量，空间降到 O(n)（甚至可以做到 O(1)，因为单项金额可即时消费）。

### 优化代码

```python
class Solution:
    def maxNumberOfAlloys(self, n: int, k: int, budget: int, composition: List[List[int]], stock: List[int], cost: List[int]) -> int:
        def check(fenshu: int) -> bool:
            for j in range(k):
                money = 0
                comp = composition[j]
                for i in range(n):
                    need = fenshu * comp[i] - stock[i]
                    if need > 0:
                        money += need * cost[i]
                        if money > budget:      # 提前剪枝
                            break
                if money <= budget:
                    return True             # 每台机器独立清零，不跨机器拼凑
            return False

        left = -1
        right = max(stock) + budget // min(cost) + 1
        while left + 1 < right:
            mid = (left + right) // 2
            if check(mid):
                left = mid
            else:
                right = mid
        return left
```

**优化理由**：省掉 k×n 的 `stockneed` 二级列表（空间 O(nk) → O(n)）；同时把「是否超预算」的检查提前到内层，金额一旦超标立即放弃这台机器，避免把剩余金属白算一遍。

### 常数级优化（可选）

- `money > budget` 时立即 `break`，这在预算紧、`x` 已经偏大时能省掉大量乘法。
- 把 `composition[j]` 取出来存成局部变量 `comp`，内层少一层下标索引；`cost`、`stock` 同理可以在 `check` 外缓存。

## 六、易错点与总结

### 易错点

- **漏掉 `max(..., 0)`**：写成 `fenshu * composition[j][i] - stock[i]` 直接乘单价，库存富余时会算出**负数金额**，凭空"赚钱"，把不可行判成可行。示例 2 的 `stock = [0,0,100]` 专门用来暴露这一点。
- **跨机器拼凑**：`money` 必须在每台机器开始时清零（本题代码在 `else` 分支里 `money = 0` 就是干这个）；否则第 1 台的欠料会算到第 2 台头上，`check` 恒为 `True`。
- **上界开小了**：`max(stock)` 或 `budget // min(cost)` 单独用都不是合法上界，必须相加（依据是最便宜金属的价格下界）。上界开小 → 二分到不了真实答案。
- **二分边界混写**：`left = -1, right = 上界 + 1` 配 `while left + 1 < right` 是**开区间**写法，返回 `left`；一旦改成 `while left <= right` 的闭区间写法，就必须另外维护 `ans`，两种写法不能混。
- **`stockneed` 用 `[[] for _ in range(k)]`**：写成 `[[]] * k` 会让 k 个位置指向同一个列表，全部机器共用一个数组。

### 题型套路沉淀

- **二分答案（最大化可行值）**：题干形如「在不超过 X 的前提下最大化 Y」，且「Y 越大越难满足」（可行性关于 Y 单调），就二分 Y。固定模板：

  ```python
  left, right = 下界 - 1, 上界 + 1     # left 侧哨兵，right 侧保证不可行
  while left + 1 < right:
      mid = (left + right) // 2
      if check(mid): left = mid        # mid 可行 → 答案不小于 mid
      else:          right = mid       # mid 不可行 → 答案小于 mid
  return left                          # 最后一个可行的值
  ```

- **判定函数 = 把「约束」直译成一次模拟**：本题的约束是「同一台机器 + 预算」，于是判定就是逐台机器算成本取最小值。
- **上界要自己证**：`check(上界 + 1)` 必须为 `False`。能用题面条件推出紧上界最好（本题用 `composition[i][j] >= 1` 推出与 `min(cost)` 的关系）；推不出来就取一个合法且足够大的值，但要确认它不会溢出语义。
- **「库存抵扣」模型的通用坑**：凡是有初始存量、按增量付费的题（库存/已有资源/前缀余量），增量都要先 `max(增量 - 存量, 0)` 再乘单价。
