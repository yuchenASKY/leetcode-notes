# 1170. 比较字符串最小字母出现频次

> **难度**：中等
> **标签**：数组 · 字符串 · 二分查找 · 排序
> **原题链接**：https://leetcode.cn/problems/compare-strings-by-frequency-of-the-smallest-character/

---

## 一、题目描述

定义 `f(s)` = 字符串 `s` 中**（按字典序）最小的那个字母**在 `s` 里出现的次数（`s` 非空）。例如 `s = "dcce"` 时最小字母是 `"c"`、出现 2 次，故 `f(s) = 2`。

给定待查表 `queries` 与词汇表 `words`，对每个 `queries[i]` 统计 `words` 中满足 `f(queries[i]) < f(W)` 的**词的个数**，返回长度与 `queries` 相同的答案数组。

### 示例

```text
示例 1：
输入：queries = ["cbd"], words = ["zaaaz"]
输出：[1]
解释：f("cbd") = 1（最小字母 'b' 出现 1 次），f("zaaaz") = 3（'a' 出现 3 次），1 < 3。

示例 2：
输入：queries = ["bbb","cc"], words = ["a","aa","aaa","aaaa"]
输出：[1,2]
解释：f("bbb") = 3，只有 f("aaaa") = 4 比它大 → 1；
      f("cc") = 2，f("aaa") = 3 与 f("aaaa") = 4 都比它大 → 2。
```

### 约束条件

- `1 <= queries.length <= 2000`
- `1 <= words.length <= 2000`
- `1 <= queries[i].length, words[i].length <= 10`
- `queries[i][j]`、`words[i][j]` 均由小写英文字母组成

## 二、解题思路

### 核心思想

**把「逐个词比较」换成「一次预处理 + 每个查询一次二分」。** `f` 值只由字符串自身决定、与查询顺序无关，而查询问的只是「有多少个 `f(W)` 超过某个阈值」—— 这是一个**阈值计数**问题，排序后可以用一次下标定位回答。

### 判据

本题的判据是一条阈值计数恒等式（设 `a = sorted(f(W) for W in words)`，`n = len(words)`，`v = f(queries[i])`）：

> `words` 中满足 `f(W) > v` 的词数 = `n − #{k : a[k] ≤ v}` = `n − bisect_right(a, v)`

排序之后，谓词 `P(k) = (a[k] > v)` 关于 `k` **单调**（前缀全 False、后缀全 True），所以边界位置可以二分定位。这正是「有序序列上的单调谓词边界定位」族的标准形态。

用户代码里写的是 `bisect_left(a, v + 1)`，与 `bisect_right(a, v)` **完全等价**：因为 `f` 值恒为整数，`a[k] > v ⟺ a[k] ≥ v + 1`。注意这个等价只依赖「两侧都是整数」，与值域是否连续无关（可以有空隙、有重复）；换成 float 就不再成立。

### 思路演进

1. **暴力解法**：对每个查询，把 `words` 的每个词都算一遍 `f` 再与 `f(queries[i])` 比较。若只把 `f(queries[i])` 提出来算一次，代价仍是 O(Σ_q + m·(Σ_w + n)) —— 每个查询都要**重算 n 个词的 f** 并**线性扫一遍 n 个结果**。
2. **瓶颈定位**：两处重复。①`words` 的 `f` 值在 m 次查询里被反复重算，共 m 遍；②每次查询都做了「线性扫描一遍所有 f 值」，而它要的其实只是一个**计数**（比阈值大的有几个），与元素的先后顺序毫无关系 —— 顺序信息被白白丢弃了。
3. **关键转化**：把「计数」翻译成「位置」。对有序数组 `a`，「大于 v 的元素个数」= `n −` 「第一个大于 v 的位置」。原先行不通，是因为数组无序、第 k 个位置对「值的大小关系」没有任何含义；排序后 `a` 单调不减，「`a[k] > v`」对 k 单调 —— **单调性一旦到手，二分就能把一次查询从 O(n) 压到 O(log n)**。
4. **最优解**：先预处理 `words` 的 f 值并排序，再对每个查询做一次二分（即下面用户提交的代码）。
   还能再进一步：题面给出 `len(s) ≤ 10`，于是 `f(s)` 的值域被锁死在 `[1, 10]` —— 只有 10 个取值，排序和二分都可以一起消掉（见「五、优化评估」）。

### 关键点

- `f(s)` 是「**字典序最小的那个字母**的出现次数」，不是「出现次数最少的字母的次数」，也不是「最小字母的位置」。
- 二分的谓词方向别搞反：`bisect_left(a, v)` 数出来的是 **`< v`** 的个数，`bisect_right(a, v)` 数的才是 **`≤ v`** 的个数；正确用的是后者。
- 二分的返回值可能等于 `n`（阈值比所有 f 值都大）⇒ 答案 0，`n − i` 天然处理，**不需要特判**；也不要画蛇添足写成 `n − i − 1`。
- `words` 的 f 值只算一次是本题的核心收益，别在查询循环里重新算。
- **隐藏资源**：`len(s) ≤ 10` 让 `f` 的值域固定为 `{1, …, 10}`，这是「桶 + 后缀和」路线成立的前提。

### 判据与判据族定位

- **本族**：*有序序列上的单调谓词边界定位*（**下标二分**）—— 二分对象是**下标** `k`，谓词由数组自身的单调性给出（本题谓词就是 `a[k] > v`）。同族动作：先把要查的量排序，再把「计数」翻译成「位置」。
- **相邻族**：*二分答案*（最小化最大值 / 第 K 小 / 可行域二分）—— 二分对象是**答案值** `x`，谓词是 `check(x)` 的可行性判定，`while lo < hi` 的写法与边界收缩方式都不同。**两族不得串用判据**：本题完全没有 `check(x)`，也没有「答案值」这个变量。
- 本题与**滑动窗口**无关（判据中不含任何窗口约束），因此滑窗各族的判据（含「窗口内部状态型」「两端点值型」等）对本题目一律不适用。

## 三、代码实现

### 最终代码

用户提交并已 AC 的版本（截图）。截图里只有 `class Solution:`，用到了 `bisect_left` 却没有 import —— 已补上 `from bisect import bisect_left`（截图共 17 行、末行 `return ans` 完整，**无裁切**，未做任何补写）。

```python
from bisect import bisect_left


class Solution:
    def f(self, s):
        minimal = min(s)
        return s.count(minimal)

    def numSmallerByFrequency(self, queries: list[str], words: list[str]) -> list[int]:
        word_fre = []
        ans = []

        for word in words:
            word_fre.append(self.f(word))
        word_fre.sort()

        for query in queries:
            i = bisect_left(word_fre, self.f(query) + 1)
            ans.append(len(words) - i)
        return ans
```

## 四、复杂度分析

**n 的含义**：`n = words.length`（词汇表长度），`m = queries.length`（查询次数），`Σ_w` / `Σ_q` 分别是 `words` / `queries` 里所有字符串的字符总数。注意 `f` 的实现是 `min` + `count`，对每个串要扫两遍，但都在 C 层。

| 版本 | 时间复杂度 | 空间复杂度 |
| :--- | :--- | :--- |
| **最终代码**（排序 + 二分） | O(Σ_w + Σ_q + n log n + m log n) | O(n) |
| 朴素解法（每查询重算 f + 线性扫） | O(Σ_q + m·(Σ_w + n)) | O(1) 额外 |
| 值域桶 + 后缀和（本题可达） | O(Σ_w + Σ_q + n + m) | O(1)（桶长恒为 11） |
| 理论下界 | Ω(Σ_w + Σ_q + m) | O(1) 额外 |

> 下界的依据：所有输入字符都必须至少读一遍（否则可能漏掉某个最小字母）⇒ Ω(Σ_w + Σ_q)；答案本身有 m 个数要输出 ⇒ Ω(m)。
> 「桶 + 后缀和」版本多出的那个 n，是「至少要逐词做一次 `min` 扫描」这笔必做开销，无法省掉 —— 也就是说**它已经在常数因子意义上贴住了下界，log 因子被彻底消掉**。

## 五、优化评估

**结论**：算法的**结构**没有问题，但**不是渐进最优**：`f` 的值域被题面锁死在 `[1, 10]`，用「计数桶 + 后缀和」可以把排序与二分一起消掉，把 O(n log n + m log n) 降到 O(n + m)。实测在题面上限（n = m = 2000）下快 **1.28× ~ 1.37×**；再叠加常数优化（内联 `f`、列表推导）可到 **1.45× ~ 1.85×**。

### 瓶颈分析

按用户代码 A 的四个阶段分别计时（n = m = 2000，7 轮轮转取最优；阶段拆分测量会损失一点循环局部性，故其合计略高于融合版）：

| 阶段 | 长度 10 的串 | 长度 1 的串 |
| :--- | ---: | ---: |
| ① 算 `words` 的 f 值（建表） | 0.560 ms（37%） | 0.292 ms（32%） |
| ② `sort` | 0.055 ms（4%） | 0.005 ms（1%） |
| ③ 算 `queries` 的 f 值 | 0.561 ms（37%） | 0.291 ms（32%） |
| ④ 二分 + 回填答案 | 0.354 ms（23%） | 0.322 ms（35%） |
| **合计** | **1.530 ms** | **0.910 ms** |

⇒ **耗时大头是 ① + ③ 的 f 值计算（64% ~ 74%）**，二分占 23% ~ 35%，而 `sort` 只占 1% ~ 4%（2000 个小整数排序太便宜了）。

### 可优化空间

- **可去掉的只有 `sort` + 二分，占 27% ~ 36%**，因此「只换这一条路线」的收益天花板 = `1/(1−0.27) ≈ 1.37×`（长度 10）/ `1/(1−0.36) ≈ 1.56×`（长度 1）。桶 + 后缀和实测 1.28× / 1.37×，**已吃掉天花板的约九成**，差额来自它仍要付出的 m 次 Python 层循环与 11 轮后缀和。
- **① + ③（64% ~ 74%）在渐进上不可去**：任何解法都至少要读一遍 `Σ_w + Σ_q` 个字符才能求出 `min`。这部分只能靠常数优化压（见下表的 D 版）。
- **本题谈不上「不优化就会 TLE」**：题面上限 n = m = 2000，六个版本全部在 2.5 ms 以内（Python，本机）。因此下面这条优化属于「**泛化到更大 n 时的研究**」，而不是过题必需 —— 事实上排序 + 二分的写法在本题约束下已经绰绰有余。

### 优化代码

值域桶 + 后缀和（不排序、不二分）：

```python
class Solution:
    def numSmallerByFrequency(self, queries: list[str], words: list[str]) -> list[int]:
        cnt = [0] * 11                       # len(s) <= 10 ⇒ f(s) ∈ [1, 10]
        for w in words:
            cnt[w.count(min(w))] += 1
        ge = [0] * 12                        # ge[v] = f 值 >= v 的词数
        for v in range(10, 0, -1):
            ge[v] = ge[v + 1] + cnt[v]
        return [ge[q.count(min(q)) + 1] for q in queries]
```

**优化理由**：`len(s) ≤ 10` ⇒ `f(s)` 只有 10 个可能取值，于是「排序 + 二分」这套为**无界值域**准备的工具全部是多余的。开一个长度 11 的计数桶统计 f 值分布（O(n)，桶长与 n 无关），再做一次**后缀和**得到 `ge[v] =「f 值 ≥ v 的词数」`，此后每个查询只需 `ge[f(q) + 1]` 一次查表 —— 单次查询从 O(log n) 降到 O(1)，建表从 O(n log n) 降到 O(n)。**log 因子彻底消掉，且空间仍是 O(1)**（桶长固定 11）。

⚠️ **这条路线依赖「值域有界」**：`cnt[f] += 1` 直接拿 f 值当下标，一旦 `len(s) > 10` 就会 `IndexError`（题面已保证不会发生）；值域无界时路线不可用，只能退回排序 + 二分。

### 常数级优化（可选）

同一轮、同一台机器上一次性对比（n = m = 2000，7 轮轮转取最优，A = 用户代码）：

| 版本 | 长度 10 的串 | 长度 1 的串 | 混合长度 |
| :--- | ---: | ---: | ---: |
| **A 用户代码**（排序 + `bisect_left(a, v+1)`） | 1.356 ms（1.00×） | 0.695 ms（1.00×） | 1.086 ms（1.00×） |
| B 同上，改用 `bisect_right(a, v)` | 1.330 ms（1.02×） | 0.670 ms（1.04×） | 1.069 ms（1.02×） |
| C 桶 + 后缀和（保留 `self.f` 调用） | 1.062 ms（1.28×） | 0.509 ms（1.37×） | 0.828 ms（1.31×） |
| **D** C + 内联 f + 列表推导 | **0.935 ms（1.45×）** | **0.375 ms（1.85×）** | **0.699 ms（1.55×）** |
| E 仍是排序 + 二分，只做常数优化（列表推导 + 内联 f） | 1.188 ms（1.14×） | 0.502 ms（1.38×） | 0.928 ms（1.17×） |
| ~~F 单趟 Python 循环求 f（"看起来更聪明"）~~ | ~~2.485 ms（0.55×）~~ | ~~0.639 ms（1.09×）~~ | ~~1.651 ms（0.66×）~~ |

- **B 与 A 完全等价**（40 组随机对拍 0 偏差），计时差异在噪声内（1.02× ~ 1.04×）⇒ 它**不是优化**，只是把口径写得更直白：「比 v 大的个数」天然对应 `bisect_right(a, v)`，不必在脑子里做一次 `+1` 换算。
- **E 说明了一件反直觉的事**：完全不改算法、只把「方法调用 + `append` 循环」换成「内联 `f` + 列表推导」，就能拿到 **1.14× ~ 1.38×**。结合瓶颈占比（f 计算占 64% ~ 74%），可以确认**在本题的规模量级上，逐元素的方法调用开销比算法阶数的差异更能决定实测耗时** —— 这也是 D 能突破「1.37× / 1.56× 天花板」的原因：它同时压掉了 ① ③ 的常数。
- **F 被证伪**：把 `min()` + `count()` 两次 C 层扫描改写成「单趟 Python 循环同时求最小字母与计数」，在长度 10 的串上**慢了近一倍（0.55×）**，混合长度也慢（0.66×），只有在长度 1 的串上略快于 A（1.09×）却仍明显慢于 E（0.79×）。原因是 `len(s) ≤ 10` 时 C 层两趟扫描的常数极小，而 Python 层的逐字符解释器开销远大于省下的那一趟 —— **「少扫一遍」在这里是负优化**。
- C 与 D 都**依赖值域有界**（见上），其余版本无此前提。

## 六、易错点与总结

### 易错点

- **`bisect_left(a, v)` 与 `bisect_right(a, v)` 数的是不同集合**：前者数 `< v`，后者数 `≤ v`。写成 `n - bisect_left(word_fre, v)`（漏掉 `+1`）会把所有 `f(W) == v` 的词误算进答案，而官方两个示例恰好都有 `f` 互不相等的特点，**不一定能暴露**。
- **误解 `f` 的定义**：`f(s)` 是最小**字母**的出现次数；把它当成「出现次数最少的字母的次数」会得到完全不同的值（例如 `"aab"` 中两者分别是 2 和 1）。
- **在查询循环里重算 `words` 的 f 值**：这是把 O(n log n + m log n) 退化成 O(m·Σ_w) 的最常见写法，示例规模小看不出来。
- **给 `n − i` 再减 1**：`bisect_*` 返回的已经是「≤ v 的元素个数」，减多一个会全体偏小。
- **桶版本的下标就是 f 值**：值域一变（`len(s) > 10`）立刻 `IndexError`；把这条路线当通用模板套到值域无界的题上会直接崩。
- 本题有一个「看不出来」的坑：`f` 的值域被 `len(s) ≤ 10` 限制在 `{1..10}` —— 不注意到它，就不会想到「桶 + 后缀和」这条更优路线。

### 题型套路沉淀

- **阈值计数 → 排序 + 二分**：凡问「有多少个元素满足 `x > v` / `x >= v` / `x <= v`」，预处理排序后统一用 `n − bisect_right(a, v)` 之类的恒等式回答，单次查询 O(log n)。这是本族（下标二分）的**固定动作**。
- **「比较」翻译成「位置」**：计数问题本身与顺序无关，但答它以「位置」为载体就需要单调性 —— 先排序造出单调性，再用二分定位。这个转化是本族的核心思想。
- **预处理与查询顺序无关的量**：`f` 只依赖字符串自身 ⇒ 一次性算好。凡是「m 次查询共享同一份静态数据」的题，都应先想「哪些量可以离线预处理」。
- **值域有界是隐藏资源**：题面一旦给出值域上界（或像本题给出字符串长度上界，从而间接锁住 `f` 的值域），就优先考虑「桶 + 前缀/后缀和」把 log 因子消掉。识别信号：**题面直接给出某个 `≤` 小常数 / 小范围**。代价是这条路线的正确性从此依赖该上界。
- **优化要有天花板意识**：先用阶段归因量出「可去成本占比」，再判断某条优化路线值不值得走 —— 本题 `sort` 只占 4%，所以「换更快的排序」是无意义的；真正值得做的是把 bin 表换成 O(1) 查表，以及压掉逐元素的方法调用。
