# 374. 猜数字大小

> **难度**：简单
> **标签**：二分查找 · 交互题
> **原题链接**：https://leetcode.cn/problems/guess-number-higher-or-lower/

---

## 一、题目描述

我心里从 `1 .. n` 中选了一个数 `pick`，你每次可以报一个数 `num`，我通过预先定义好的接口 `guess(num)` 回告结果：`-1` 表示你报的数**比我选的大**，`1` 表示**比我选的小**，`0` 表示猜中。在整个过程中 `pick` 保持不变，要求用尽量少的次数猜出这个数并返回它。

### 示例

```text
输入：n = 10, pick = 6
输出：6

输入：n = 1, pick = 1
输出：1

输入：n = 2, pick = 1
输出：1
```

### 约束条件

- `1 <= n <= 2^31 - 1`
- `1 <= pick <= n`
- `guess(num)` 的返回值语义：`-1` → `num > pick`；`1` → `num < pick`；`0` → `num == pick`

---

## 二、解题思路

### 核心思想

**`guess` 就是一个三点比较器**，它一次就能告出「目标在 mid 的左边 / 就是 mid / 在 mid 的右边」，而这正好是二分收缩所需要的信息 —— 候选集合还是 `1 .. n` 这个有序区间，于是直接二分。

### 思路演进

1. **暴力解法**：从 `1` 开始逐个 `guess(i)`，直到返回 `0`。调用次数最坏 O(n)，而 `n` 上限是 `2^31 - 1`，最坏要猜二十多亿次，必然超时（交互题里还会因为调用次数超限被判错）。
2. **观察到**：`pick` 在整个游戏里**保持不变**，所以任意一次 `guess` 的结果对后续永远有效，不存在"信息过期"。并且每次调用返回的是 `-1 / 0 / 1` 三种结果中的一个：`0` 直接结束，另外两种恰好告诉我们该往哪个方向走。
3. **优化为**：维护一个候选区间，每轮取中点 `mid` 去问，`1` 就把左边界抬到 `mid`（`mid` 已排除），`-1` 就把右边界压到 `mid`（`mid` 已排除），`0` 就直接返回。区间每轮至少少一半，`log₂ n` 次必中。

### 关键点

- **符号方向别搞反**：`-1` 的含义是"**你报的数比我选的大**"，也就是**猜大了**，答案是往**左**走，所以更新的是 `right`；`1` 才是猜小了、往右走。这是本题最容易写反的地方（和 `<` / `>` 的比较直觉不一致）。
- **开区间写法 `(left, right)`**：`left = 0`、`right = n + 1` 是两个哨兵，都不属于答案域 `1 .. n`。循环条件 `left + 1 < right` 保证区间内至少还有一个候选，此时 `mid = (left + right) // 2` 必然落在 `[1, n]` 内，不会问出 `0` 或 `n + 1` 这种非法猜测。
- **`left = mid` / `right = mid` 必须配开区间模板**：因为 `mid` 可能等于 `left`（当 `right - left == 1` 时），如果同时用闭区间的 `while left <= right`，会原地打转变成死循环。模板和边界更新方式必须成套使用。
- `n` 的上界是 `2^31 - 1`，Python 整数无溢出问题；但换成 C++/Java 时 `(left + right) // 2` 在 `left + right` 逼近 `2^32` 时会溢出，得写 `left + (right - left) // 2`。

## 三、代码实现

### 最终代码

```python
# The guess API is already defined for you.
# @param num, your guess
# @return -1 if num is higher than the picked number
#          1 if num is lower than the picked number
#          otherwise return 0
# def guess(num: int) -> int:          # ← 由评测系统提供，本地运行时需自行模拟


class Solution:
    def guessNumber(self, n: int) -> int:
        left = 0
        right = n + 1            # 开区间 (left, right) 的两个哨兵
        while left + 1 < right:
            mid = (left + right) // 2
            temp = guess(mid)
            if temp == 0:
                return mid
            if temp == -1:
                right = mid      # 猜大了：答案在左侧，排除 mid
            else:
                left = mid       # 猜小了：答案在右侧，排除 mid
```

## 四、复杂度分析

| 版本 | 时间复杂度 | 空间复杂度 |
| :--- | :--- | :--- |
| **最终代码** | O(log n) | O(1) |
| 朴素解法（从 1 线性扫描） | O(n) | O(1) |
| 理论下界 | O(log n) | O(1) |

> 复杂度中的 n 指候选值的上界，即题目给出的 `n`，候选集合大小为 `1 .. n`。

## 五、优化评估

**结论**：已是最优，时间和空间都到理论下界。

### 瓶颈分析

时间全部花在 `guess` 的调用次数上（每次调用相当于一次"询问"）。每问一次 `mid`，`0` 分支直接结束；`1` / `-1` 分支留下的候选数是 `mid - 1` 与 `n - mid`，两者之和恒为 `n - 1`，所以无论 `mid` 取哪儿，**未命中时剩余候选至少有一边是 `≈ n/2` 这个量级**，只能做到折半。折半即 `log₂ n`，正是二分给出的结果。

### 可优化空间

不存在更少询问的写法：`n` 个候选、每次询问只有「偏大 / 命中 / 偏小」三种结果，而命中是终止分支，真正起收缩作用的是左右两支，且两支之和固定为 `n - 1` —— 最坏情况下每轮最多把候选砍一半，因此 `⌈log₂ n⌉` 次是信息量意义上的下界，二分已经达到。空间上只用两个整型指针，没有可压缩的余地。

### 常数级优化（可选）

- 循环内 `(left + right) // 2` 的结果只用于 `guess` 与边界赋值，没有可省的重复计算；`temp == 0` 放在最前面是因为命中即返回，能省掉后续判断。
- 若改成闭区间写法 `lo, hi = 1, n` + `while lo < hi`，可少两个哨兵变量，但需要额外处理 `mid` 落在哪一侧的赋值（`hi = mid` / `lo = mid + 1`），可读性上各有取舍，本题两种写法询问次数同阶。

## 六、易错点与总结

### 易错点

- **`-1` / `1` 的方向写反**。记住一句：`-1` 是"我报的数**高了**" → 答案在**低**处 → 收右边界。写成 `left = mid` 会在错误的方向上越走越远，最后返回一个错误答案而不报错。
- **两套二分模板混用**。本题代码是「开区间 `(left, right)` + `while left + 1 < right` + `left = mid / right = mid`」这一套；若改成 `left = 1, right = n` 的闭区间，就必须配 `while left <= right` 和 `right = mid - 1 / left = mid + 1`。混着写（例如闭区间里用 `left = mid`）在 `right - left == 1` 时会死循环。
- **哨兵越界**。`left = 0, right = n + 1` 只为保证 `mid ∈ [1, n]`；如果把初值写成 `left = 0, right = n`，当 `n = 1` 时区间里取不到任何合法值。
- **`mid` 溢出（非 Python）**。`n` 可达 `2^31 - 1`，C++/Java 中 `left + right` 可能溢出成负数，用 `left + (right - left) // 2`。
- 本地调试时忘了 `guess` 是评测系统注入的接口，直接跑会 `NameError`，需要自己按 `pick` 写一个模拟函数。

### 题型套路沉淀

- **交互题 + 二分**：题目不给数组，但给了一个 `O(1)` 的询问接口，且询问结果能定方向 —— 这就是"隐式有序数组上的二分"，把 `guess(mid)` 当成 `a[mid]` 的比较来写即可。
- **开区间二分模板（推荐背下来）**：
  ```python
  left, right = 下界哨兵, 上界哨兵   # 二者都不属于答案域
  while left + 1 < right:
      mid = (left + right) // 2
      if 命中(mid):  return mid
      if mid 偏大:   right = mid
      else:          left = mid
  ```
  它的好处是**不用记忆 `±1`**：`mid` 一旦被判掉就整块排除，`left`/`right` 永远是"已排除"的边界，收缩逻辑不容易写错。
- **问次数 = 复杂度**：这类题把"调用接口的次数"当时间复杂度看，暴力 O(n) 次询问在 `n = 2^31` 时是灾难，必须想到折半。
