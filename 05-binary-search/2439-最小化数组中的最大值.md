# 2439. 最小化数组中的最大值

> **难度**：中等
> **标签**：数组 · 二分查找 · 贪心 · 前缀和
> **原题链接**：https://leetcode.cn/problems/minimize-maximum-of-array/

---

## 一、题目描述

给定一个长度为 `n` 的非负整数数组 `nums`。每次操作选一个下标 `i`（`1 <= i < n`）且 `nums[i] > 0`，把 `nums[i]` 减 1、`nums[i - 1]` 加 1。操作可以做任意次，问最终数组中**最大值**能达到的**最小**值是多少。

直观理解：数值只能从右往左「搬运」（后面的数匀给前面的数），且 `nums[0]` 只进不出，是唯一一个无法被削减的位置。

### 示例

```text
输入：nums = [3,7,1,6]
输出：5
解释：
1. 选 i = 1，nums 变为 [4,6,1,6]
2. 选 i = 3，nums 变为 [4,6,2,5]
3. 选 i = 1，nums 变为 [5,5,2,5]
最大值为 5，且无法得到更小的最大值。

输入：nums = [10,1]
输出：10
解释：nums[0] = 10 无法被削减，只需把 1 匀给前面也无济于事，最大值仍是 10。
```

### 约束条件

- `n == nums.length`
- `2 <= n <= 10^5`
- `0 <= nums[i] <= 10^9`

---

## 二、解题思路

### 核心思想

**答案由「每个前缀的平均值上取整」的最大值决定**；先用二分答案把「最小化最大值」转成可行性判定，判定本身是 O(n) 的前缀扫描。

### 思路演进

1. **暴力解法**：题目没给操作次数上限，无法枚举操作序列；退一步「枚举答案 `t`，从 `min(nums)` 到 `max(nums)` 逐个判定」，每个 `t` 都要扫一遍数组，时间 O(n·V)，V 是值域宽度（可达 10^9），不可接受。

2. **观察到**：操作只把数值从右侧挪到左侧相邻位置，**任意前缀 `nums[0..i]` 的元素和永远不变**（左侧加 1、右侧减 1 发生在同一个前缀内部时相互抵消；跨前缀搬运则等价于「后一个前缀减 1、前一个前缀加 1」，而前缀和被要求的是「至少」）。记前缀和 `S_i = nums[0] + ... + nums[i]`，则前缀 `0..i` 中必然存在一个元素不小于 `⌈S_i / (i + 1)⌉`（`i + 1` 个数分 `S_i` 的总量）。于是

   ```
   答案 >= max_{0 <= i < n} ⌈S_i / (i + 1)⌉   =: lower
   ```

   例如 `[3,7,1,6]` 的前缀为 `3, 10, 11, 17`，对应 `⌈3/1⌉ = 3`、`⌈10/2⌉ = 5`、`⌈11/3⌉ = 4`、`⌈17/4⌉ = 5`，下界为 5 —— 与答案吻合。而 `[10,1]` 的 `⌈10/1⌉ = 10` 直接把答案锁死在 10（首元素削不动）。

3. **关键转化**：判定「答案是否 `<= t`」不再需要模拟操作，只需检查每个前缀是否装得下：

   ```
   check(t) 为真  <=>  对每个 i，都有 ⌈S_i / (i + 1)⌉ <= t
   ```

   理由：前缀和守恒决定了「前缀 `0..i` 的总量不可能变小」，所以只要每个前缀都能把总量摊到不超过 `t`，就一定能通过不断把右侧超出 `t` 的部分往左推来达成（`nums[0]` 装不下的情况恰好被 `i = 0` 的判定拦下）。这一步把不可模拟的过程变成了纯前缀比较，O(n)。

4. **最优（二分答案）**：`check` 关于 `t` 单调 —— `t` 可行则 `t + 1` 必然可行（放宽约束只会更容易满足）。于是在值域上二分最小的可行 `t`：
   - 下界哨兵取 `min(nums) - 1`：一定不可行，因为 `nums[0] >= min(nums) > min(nums) - 1`，`check` 直接返回假；
   - 上界哨兵取 `max(nums) + 1`：一定可行，因为每个元素 `<= max(nums) < max(nums) + 1`；
   - 用「左开右闭」的写法（`left` 恒不可行、`right` 恒可行），`while left + 1 < right` 收敛后 `right` 就是答案。

### 关键点

- **守恒量是前缀和，不是总和**。是「每个前缀」都要满足约束，只看总和会把答案算小。
- **必须上取整**：`⌈S / (i + 1)⌉` 写成 `(S - 1) // (i + 1) + 1`。Python 中 `S = 0` 时结果恰为 `0`，天然正确；用 `//` 会向下取整导致答案偏小（如 `[3,4]`：`⌈7/2⌉ = 4`，而 `7 // 2 = 3`）。
- **下界哨兵不可省**：`left` 必须是「谓词确实为假」的点，否则可能提前收敛到不可行的值。用 `min(nums) - 1` 而不是 `min(nums)`，配 `left + 1 < right` 的模板无需额外特判。
- 前缀和规模最大约 `10^5 * 10^9 = 10^14`，Python 整数无溢出问题（若写 C++ 需要 `long long`）。

## 三、代码实现

### 最终代码

```python
from typing import List  # 截图里没有、已补


class Solution:
    def minimizeArrayValue(self, nums: List[int]) -> int:
        def check(t: int) -> bool:
            if nums[0] > t:          # 首元素只进不出，是硬下界
                return False
            temp = 0                 # 前缀和
            for i in range(len(nums)):
                temp += nums[i]
                # (temp - 1) // (i + 1) + 1 == ceil(temp / (i + 1))
                if (temp - 1) // (i + 1) + 1 <= t:
                    continue
                return False         # 该前缀不可能摊到 <= t，t 不可行
            return True

        # 不变量：left 恒不可行，right 恒可行
        left = min(nums) - 1
        right = max(nums) + 1
        while left + 1 < right:
            mid = (left + right) // 2
            if check(mid):
                right = mid
            else:
                left = mid
        return right
```

## 四、复杂度分析

| 版本 | 时间复杂度 | 空间复杂度 |
| :--- | :--- | :--- |
| **最终代码** | O(n log V) | O(1) |
| 朴素解法 | O(n · V) | O(1) |
| 理论下界 | O(n) | O(1) |

> 复杂度中的 n 指数组 `nums` 的长度；V 指数组的**值域宽度** `max(nums) - min(nums) + 2`（本题可达 10^9，故 `log V ≈ 30`）。空间上 `check` 只维护一个滚动前缀和，不复制数组，因此额外空间为 O(1)。

## 五、优化评估

**结论**：时间复杂度仍有优化空间 —— 本题的判定下界 `lower` **本身就是可达的**，可以跳过二分直接 O(n) 求出。

### 瓶颈分析

二分版本每轮都重扫一遍数组，共约 `log V ≈ 30` 轮，`n = 10^5` 时约 3×10^6 次迭代，完全能过，但这一维是可以省掉的：被反复计算的量始终是同一批前缀平均值。

### 可优化空间

第 2 步推出的下界 `lower = max_i ⌈S_i / (i + 1)⌉` 同时是**可行**的：对任意前缀都有 `⌈S_i / (i + 1)⌉ <= lower`，正是判定 `check(lower)` 为真的条件。下界可达 ⇒ 下界即答案，于是无需二分，一次遍历取最大值即可。

### 优化代码

```python
from typing import List


class Solution:
    def minimizeArrayValue(self, nums: List[int]) -> int:
        prefix = 0
        ans = 0
        for i, x in enumerate(nums):
            prefix += x
            cur = (prefix - 1) // (i + 1) + 1   # ceil(prefix / (i + 1))
            if cur > ans:
                ans = cur
        return ans
```

**优化理由**：把「二分 + 判定」压成「一次前缀扫描」。二分版本的价值在于**不需要证明下界可达**，是更通用的「最小化最大值」套路；本题由于守恒量是前缀和、下界构造性可达，闭式写法更直接。

### 常数级优化（可选）

- 上取整也可写成 `-(-prefix // (i + 1))`（利用 Python 整除向下取整、取负翻转方向），与 `(prefix - 1) // (i + 1) + 1` 等价，可读性更直白。
- 判定里若要避免除法，可把条件改写成**差值累加**：令 `diff += nums[i] - t`，一旦 `diff > 0` 即说明该前缀装不下，返回假。两版的大 O 相同，取写法更清楚的那个即可。

## 六、易错点与总结

### 易错点

- **漏掉上取整**：用 `prefix // (i + 1)` 会低估答案。反例 `nums = [3,4]`：真答案是 4（`[4,3]`），但 `7 // 2 = 3` 会给出错误结果。
- **判定只看最大值而不看前缀**：`[10,1]` 这类数据下，只盯着「现在最大的是谁」会以为还能继续削，实际 `nums[0] = 10` 只进不出，答案被锁死在首元素上。
- **哨兵取错**：把 `left` 初始化成 `min(nums)`（它可能就是答案、是可行点）会破坏「`left` 不可行」的不变量。用 `min(nums) - 1` / `max(nums) + 1` 这对哨兵配 `left + 1 < right` 最稳。
- **整除语义差异**：`(S - 1) // (i + 1) + 1` 在 `S = 0` 时得到 `0`（Python `//` 向下取整）；同样的表达式搬到 C++ 会因为整数除法向零取整而得到 `1`，跨语言移植时要留意。
- 二分收敛后返回的是 `right`（可行一侧），不是 `mid`；区间为空时 `mid` 已无意义。

### 题型套路沉淀

- **「最小化最大值 / 最大化最小值」→ 二分答案 + O(n) 判定**，这是此类问题的第一反应；判定写不出来时，先找「什么量在操作中守恒」。
- **守恒量决定判定形式**：本题的守恒量是**前缀和**，于是判定退化成前缀比较。找守恒量比试着模拟操作高效得多。
- **二分模板固定动作**：`left` = 一定不可行的点、`right` = 一定可行的点、`while left + 1 < right`、`check(mid) ? right = mid : left = mid`、返回 `right`。哨兵按题意取「下界 - 1」与「上界 + 1」，天然规避边界特判。
- **闭式优先**：若能从判定条件直接读出单调的闭式答案（如本题取所有前缀平均的最大值），就不必真去二分 —— 但先写二分、再化简，是更保险的推导顺序。
