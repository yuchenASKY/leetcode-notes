# 3639. 变为活跃状态的最小时间

> **难度**：中等
> **标签**：数组 · 二分查找
> **原题链接**：https://leetcode.cn/problems/minimum-time-to-activate-string/

---

## 一、题目描述

给定长度为 `n` 的字符串 `s`，以及 `0 ~ n-1` 的一个排列 `order`。从 `t = 0` 开始，每个时间点 `t` 把 `s[order[t]]` 替换成 `'*'`。若某子串中**至少含一个** `'*'` 则称它「有效」；当有效子串总数 **≥ k** 时称字符串「活跃」。求字符串**首次**活跃的时间 `t`，若全部替换后仍无法活跃则返回 `-1`。

注意：`s` 的字符内容本身不影响答案 —— `'*'` 出现的位置完全由 `order` 决定，因此只有长度 `n` 有意义。

### 示例

```text
示例 1：
输入：s = "abc", order = [1,0,2], k = 2
输出：0
解释：t = 0 时 s 变为 "a*c"，有效子串为 "*"、"a*"、"*c"、"a*c" 共 4 个 ≥ 2，已经活跃。

示例 2：
输入：s = "cat", order = [0,2,1], k = 6
输出：2
解释：
  t = 0 → "*at"，有效子串 3 个（"*"、"*a"、"*at"），3 < 6；
  t = 1 → "*a*"，有效子串 5 个，5 < 6；
  t = 2 → "***"，6 个子串全部含 '*'，6 ≥ 6，活跃。

示例 3：
输入：s = "xy", order = [0,1], k = 4
输出：-1
解释：全部替换也只有 2*3/2 = 3 个有效子串，永远达不到 4。
```

### 约束条件

- `1 <= n == s.length <= 10^5`
- `order.length == n`
- `0 <= order[i] <= n - 1`，且 `order` 是 `0 ~ n-1` 的一个排列
- `s` 仅由小写英文字母组成
- `1 <= k <= 10^9`

## 二、解题思路

### 核心思想

**「有效子串数 ≥ k」对时间 `t` 单调成立 ⇒ 二分答案**；而单次判定可以在 O(n) 内完成 —— 枚举右端点，用「最近一个 `'*'` 的位置」直接算出贡献，不去枚举任何子串。

### 思路演进

1. **暴力解法**：老老实实模拟。对每个时刻 `t`，枚举全部 O(n²) 个子串并逐个检查是否含 `'*'`，外层再套一层时间循环 ⇒ **O(n³)**。`n = 10^5` 时连一个时刻都算不完。

2. **第一处转化（怎么在 O(n) 内数出有效子串数）**：子串 = (左端点, 右端点)，**枚举右端点**比枚举子串划算得多。固定右端点 `i`，设 `last` 为「≤ `i` 的最后一个 `'*'` 下标」。那么**以 `i` 结尾的有效子串恰好有 `last + 1` 个**：左端点取 `0..last` 时区间包含位置 `last` 上的 `'*'`；取 `last+1..i` 时整段落在 `'*'` 右边，必然无效。于是

   ```text
   有效子串总数 = Σ_i (last_i + 1)        （last_i 为 ≤ i 的最后一个 '*' 下标，没有则为 -1，贡献 0）
   ```

   一次线性扫描即可，不需要任何子串枚举。

3. **第二处转化（单调性从哪来）**：`t` 增大只会往字符串里**加** `'*'`、从不删（`order` 是排列，每个位置恰好被染一次）。'*' 集合单调增大 ⇒ 每个右端点的 `last_i` 只可能变大或不变 ⇒ **有效子串总数关于 `t` 单调不减**。于是「最小 `t` 使得有效子串数 ≥ k」就是一个标准的**二分答案**。

4. **落成代码**：外层二分时间 `t`（O(log n) 轮），内层 `count(t)` 用上面的扫描做判定（O(n)）⇒ **O(n log n)**。

### 关键点

- **用「轮次值」代替布尔标记，省掉每轮 O(n) 的重置**。判定函数把第 `t` 轮染上的位置统一写成值 `t + 1`，扫描时只认 `x == mid`（`mid` 进函数后已 `+1`）。因为 `order` 是排列、第 `t` 轮恰好覆盖 `order[0..t]` 这 `t+1` 个位置，所以 **`x == t+1` 精确等价于「下标属于 `order[0..t]`」**；而其它位置即使残留着前几轮写进去的旧值，那些值也不等于本轮值，天然被忽略。
  - 示例 1 里能直接看到这个过程：先调用 `count(1)`，`star[0]` 被写成 `2`；随后调用 `count(0)`（本轮值 `1`），`star[0]` 的残留值 `2 ≠ 1`，于是**只有 `star[order[0]] = star[1]` 被计入**，结果正好是"只有 1 个 `'*'`"的状态 —— 如果改用布尔标记，就必须每轮清空一次数组。
- **标记值最小为 1，数组初值为 0**：两者永不相等，未染色的位置不会误命中。这也意味着**不能把某一轮的标记值取成 0**。
- **哨兵 `left = -1`、`right = n`**：`P(-1)` 必假（`k ≥ 1`，而 0 个 `'*'` 时有效子串数为 0），于是 `t = 0` 不用特判，`while left + 1 < right` 统一收敛到「最小满足点」。
- **上界预判 `if k > n*(n+1)//2: return -1`**：全串都是 `'*'` 时有效子串数取到理论最大值 `n(n+1)/2`。超过它直接 `-1`；同时它也**保证了 `P(n-1)` 为真**，即二分一定有解、返回值一定 `< n`（不会把哨兵 `n` 当答案返回）。
- **`ans >= k` 立刻返回**：命中即可收工，不必把剩余下标扫完（`k` 可达 `10^9`）。
- 代码中 `s` 没被使用 —— 合法，因为答案与字符内容无关；`n = len(order)`，由约束 `order.length == n` 与 `len(s)` 等长。

## 三、代码实现

### 最终代码

```python
from typing import List          # 截图里没有、已补


class Solution:
    def minTime(self, s: str, order: List[int], k: int) -> int:
        n = len(order)
        if k > n * (n + 1) // 2:          # 全部替换也凑不够 → 永远不活跃
            return -1

        star = [0] * n                    # star[i] = 把 i 染成 '*' 的那一轮的轮次值（0 = 尚未染色）

        def count(mid):
            mid += 1                      # 轮次值：第 t 轮统一写 t+1，用来和旧轮次的残留值区分
            ans = 0
            for i in range(mid):          # 本轮覆盖 order[0..t]
                star[order[i]] = mid
            last = -1                     # <= i 的最后一个 '*' 下标
            for i, x in enumerate(star):
                if x == mid:              # 只认本轮值，等价于「i 属于 order[0..t]」
                    last = i
                ans += last + 1           # 以 i 结尾的有效子串数
                if ans >= k:
                    return True
            return False

        left = -1
        right = n
        while left + 1 < right:           # 二分最小的 t，使 count(t) 为真
            mid = (left + right) // 2
            if count(mid):
                right = mid
            else:
                left = mid
        return right
```

## 四、复杂度分析

| 版本 | 时间复杂度 | 空间复杂度 |
| :--- | :--- | :--- |
| **最终代码** | O(n log n) | O(n) |
| 朴素解法 | O(n³) | O(1) |
| 理论下界 | O(n) | O(n) |

> 复杂度中的 n 指字符串 `s` 的长度（= 数组 `order` 的长度）。`count` 每轮为两次线性扫描 O(n)，二分共 O(log n) 轮；空间为标记数组 `star`，判定函数原地复用，不随轮次增长。

## 五、易错点与总结

### 易错点

- **漏掉 `-1` 的上界预判**：不先判 `k > n*(n+1)//2`，就可能把哨兵 `n` 当成合法答案返回（或在其它写法里死循环）。这一行同时也是「二分必有解」的依据。
- **二分的收缩方向写反**：本题要**最小**满足的 `t`，所以 `count(mid)` 为真时收缩右边界 `right = mid`、为假时 `left = mid`。写反会得到一个「最大的不满足点」，示例 1 会输出 1 而不是 0。
- **看漏 `count` 里的 `mid += 1`**：进函数后 `mid` 的含义已从「时间 t」变成「轮次值 t+1」，后面 `range(mid)` 与 `x == mid` 用的都是这个新值。漏写或写成 `-=` 时，`t = 0` 会退化成「一个 `'*'` 都没有」，示例 1 直接算错。
- **误以为必须每轮清空 `star`**：正相反，残留值正是靠「不等于本轮值」被自动排除的。前提是**本轮标记值唯一且非 0** —— 这是整个写法成立的隐含条件。
- **`last` 的语义**：「≤ `i` 的最后一个 `'*'` 下标」，而不是「当前这一轮新染的位置」。扫描过程中它被更靠右的 `'*'` 自然刷新，恰好覆盖了此前所有轮次的染色，无需单独区分轮次。

### 题型套路沉淀

- **「最小时间 / 最小容量 / 第 k 个」+ 单调性 ⇒ 二分答案**：先确认「答案越大，判定越容易满足」，再把判定写成 O(n) 的 `check`；答案区间用 `left = -1, right = n` 的半开哨兵形式，避免对边界特判。
- **统计「含某类元素的子串数」**：不要枚举子串，**枚举右端点 + 维护最后一个标记位置 `last`**，贡献 `last + 1`。这是此类计数的标准 O(n) 套路，把「包含至少一个 X」换成其它元素同样适用。
- **同一个集合被反复判定时，用「轮次值」代替布尔标记**：省掉每次 O(n) 的重置，是「二分答案 + 标记数组」里常见的实现手法；代价是标记值必须逐轮唯一、且避开数组初值。
- **先判可行性上界，再二分**：当「答案不存在」对应返回 `-1` 时，先算出判定函数能达到的最大值并提前拦截，既省掉一整轮二分，也让二分区间一定落在合法解内。
