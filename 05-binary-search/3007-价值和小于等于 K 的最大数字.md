# 3007. 价值和小于等于 K 的最大数字

> **难度**：中等
> **标签**：二分查找 · 数位 DP · 位运算
> **原题链接**：https://leetcode.cn/problems/maximum-number-that-sum-of-the-prices-is-less-than-or-equal-to-k/

---

## 一、题目描述

给定整数 `k` 和 `x`。一个数 `num` 的**价值**定义为：它的二进制表示中，**从最低有效位起、位置序号为 `x, 2x, 3x, …` 的那些位上为 `1` 的个数**（位置序号从 1 开始）。

`num` 的**累加价值**是从 `1` 到 `num` 所有数字的价值之和。若一个数的累加价值 `≤ k`，则称它是**廉价的**。求**最大的廉价数字**。

### 示例

```text
输入：k = 9, x = 1
输出：6
解释：x = 1 时"价值"就是 popcount（二进制中 1 的个数）。
      1..6 的 popcount 依次为 1,1,2,1,2,2，累加 = 9 ≤ 9；
      再加 7（popcount = 3）会变成 12 > 9，所以答案是 6。

输入：k = 7, x = 2
输出：9
解释：只统计第 2、4、6… 位。1..9 的价值累加为 6 ≤ 7；
      而 10 的第 2、4 位都是 1，价值为 2，累加变成 8 > 7，所以答案是 9。
```

### 约束条件

- `1 <= k <= 10^15`
- `1 <= x <= 8`
- 答案可以远超 32 位整数：`k = 10^15`、`x = 8` 时答案量级约 `10^17`

## 二、解题思路

### 核心思想

**累加价值随 `num` 单调不减 ⇒ 二分答案**；判定谓词「`1..num` 的累加价值」用**数位 DP** 计数得到。

### 思路演进

1. **暴力解法**：从 `num = 1` 开始逐个求值、逐个累加，累加价值一旦超过 `k` 就返回 `num - 1`。
   - 单个数求价值 O(L)（L 为二进制位数），最坏要一直枚举到答案本身。
   - 答案上界约 `10^17`，逐个枚举在时限内完全不可能。
2. **观察到**：`acc(num) = Σ_{i=1..num} price(i)` 的每一项都是非负的，所以 `acc` 随 `num` **单调不减**。而题目要的正是「满足 `acc(num) ≤ k` 的最大 `num`」——这是一个标准的**二分答案**结构：只要能在可接受的代价内算出任意一个 `acc(mid)`，就能用 O(log 值域) 次判定把答案夹出来。
3. **优化为**：**二分答案 + 数位 DP 计数**。
   - 把 `acc(num)` 换个角度写成「统计 `0..num` 中所有数字在**合法位**上出现的 `1` 的总个数」。这就从"逐个数字求价值"变成了"**按位独立计数再求和**"，而"统计 `≤ num` 的所有数中满足某按位条件的位总数"正是数位 DP 的拿手场景。
   - 二分的目标量取 `k + 1`：找**第一个**使 `acc(num) ≥ k + 1` 的 `num`，则答案 = `num - 1`（它刚好是"最后一个 `acc ≤ k` 的数字"）。Python 的 `bisect_left(range(上界), k + 1, key=count)` 恰好表达这个语义。

### 关键点

- **位置序号是 1-based，最低有效位是第 1 位**。数位 DP 中 `i` 表示"还剩 `i` 位未确定"，当前正在决策的就是第 `i` 位（1-based），所以判据写成 `i % x == 0`；写成 `(i - 1) % x == 0` 就整体错位一位。
- **数位 DP 状态**：`(i, cnt1, is_limit)` —— 剩余位数、已计入的合法位 `1` 的个数、前面若干位是否与上界完全相同。
  - `up = num >> (i - 1) & 1 if is_limit else 1`：贴着上界时当前位最多取到上界该位的值，否则可取 `0..1`。
  - 转移里 `is_limit and d == up`：只有"前一位贴界"且"当前位也取满"时，下一位才继续受限。
- **DP 的返回值**：叶子（`i == 0`）返回 `cnt1`，逐层向上累加。于是 `dfs(num.bit_length(), 0, True)` 返回的就是 `0..num` 全体数字在合法位上出现的 `1` 的总数，即 `acc(num)`。（数字 `0` 也被枚举到，但 `price(0) = 0`，不影响结果。）
- **二分上界 `(k + 1) << x` 是安全的上界**：第 `x` 位（1-based）在长度 `2^x` 的一个周期里有 `2^(x-1)` 个 `1`，取 `N = (k + 1)·2^x` 时它有恰好 `k + 1` 个完整周期，光第 `x` 位就贡献 `(k+1)·2^(x-1) ≥ k + 1` ⇒ `acc(N) ≥ k + 1`，说明这个上界确实越过了分界点。
- **运算符优先级**：`+` 高于 `<<`，所以 `k + 1 << x` 等价于 `(k + 1) << x`（这是本意），但要靠一眼看清。
- 记忆化（`@cache`）只对 `is_limit = False` 的状态生效才有意义：贴界的那条路径每个位数至多两个状态，不记忆也无所谓；这一点由 `is_limit` 作为状态的一部分自动保证。

## 三、代码实现

### 最终代码

```python
from bisect import bisect_left
from functools import cache


class Solution:
    def findMaximumNumber(self, k: int, x: int) -> int:
        def count(num: int) -> int:
            """累加价值：0..num 中所有数在「第 x、2x、3x… 位（1-based）」上 1 的总个数"""

            @cache
            def dfs(i: int, cnt1: int, is_limit: bool) -> int:
                # i：还剩 i 位没确定；当前决策的是第 i 位（1-based）
                if i == 0:
                    return cnt1
                res = 0
                up = num >> (i - 1) & 1 if is_limit else 1
                for d in range(up + 1):
                    # 第 i 位是合法位且填了 1，才把 cnt1 加一
                    res += dfs(i - 1, cnt1 + (d == 1 and i % x == 0),
                               is_limit and d == up)
                return res

            return dfs(num.bit_length(), 0, True)

        # 找第一个 acc(num) >= k + 1 的 num，答案即它减 1
        return bisect_left(range(k + 1 << x), k + 1, key=count) - 1
```

> 截图原代码缺 `from bisect import bisect_left` 与 `from functools import cache`（截图里没有，已补）；`bisect_left` 的 `key=` 参数需要 Python 3.10+。

## 四、复杂度分析

| 版本 | 时间复杂度 | 空间复杂度 |
| :--- | :--- | :--- |
| **最终代码** | O(L³) | O(L²) |
| 朴素解法 | O(U · L) | O(1) |
| 理论下界 | O(L) | — |

> 复杂度中的 n 相关量：
> - `U = (k + 1) << x` 为二分上界，`L = bit_length(U) = O(log k + x)` 为其二进制位数（本题 `L ≤ 58`）。
> - 朴素解法的 `U` 即答案量级（约 `10^17`），`L` 为单个数求价值的位数。

**逐项说明**

- **最终代码**：二分共 `O(log U) = O(L)` 轮；每轮 `count(mid)` 的数位 DP 状态为 `(i, cnt1)` 的组合，共 `O(L²)` 个，每个状态至多两条转移，故单轮 `O(L²)`；相乘得 `O(L³)`。空间是记忆化表，`O(L²)`。
- **朴素解法**：从 1 枚举到答案，每次 O(L)，共 `O(U · L)` —— `U ≈ 10^17`，量级上完全不可行。
- **理论下界**：答案本身有 `L` 位二进制，任何解法至少要把它输出出来，即 `O(L)`。当前解法与之相差一个 `L²` 因子（`二分轮数 L` × `单轮 DP 状态数 L`），见下一节的优化方向。

## 五、优化评估

**结论**：二分 + 计数的**框架已是最优选择**（`acc` 的单调性是二分的必要前提，无法回避）；可优化的是**单轮计数的实现方式**——用「按位闭式统计」替代数位 DP，把总复杂度从 `O(L³)` 降到 `O(L²/x)` 量级。

### 瓶颈分析

时间开销集中在两处相乘：外层二分 `O(L)` 轮，内层每轮 DP `O(L²)` 个状态。空间则是整个记忆化表 `O(L²)`，对本题来说数值很小（`L ≤ 58`），并不是瓶颈。

### 可优化空间

`acc(num)` 的定义允许**按位独立求和**：第 `p` 位（1-based，`p` 为 `x` 的倍数，对应 0-based 下标 `j = p - 1`）在 `[0, num]` 中共出现多少次 `1`，有闭式解 —— 记 `w = 2^j`、该位的周期为 `2w = 2^p`，则

```text
count_p = ⌊(num + 1) / 2w⌋ · w + max(0, (num + 1) mod 2w - w)
```

把所有合法位（最多 `⌈L/x⌉` 个）的贡献相加即是 `acc(num)`。这条路线**不需要 DP，也不需要记忆化表**，单轮计数从 `O(L²)` 降到 `O(L/x)`，总复杂度降为 `O(L²/x)`；`x` 越大省得越多。

### 优化代码

```python
from bisect import bisect_left


class Solution:
    def findMaximumNumber(self, k: int, x: int) -> int:
        def count(num: int) -> int:
            """按位闭式统计：0..num 所有数在第 x、2x、3x…（1-based）位上 1 的总个数"""
            if num <= 0:
                return 0
            total = 0
            p = x                      # 1-based 位置序号，从 x 开始
            while (1 << (p - 1)) <= num:
                w = 1 << (p - 1)       # 该位的权重
                period = w << 1        # 该位的周期 2^p
                full, rest = divmod(num + 1, period)
                total += full * w + max(0, rest - w)
                p += x
            return total

        return bisect_left(range(k + 1 << x), k + 1, key=count) - 1
```

**优化理由**：合法位的取值模式是周期性的（连续 `w` 个 1、再连续 `w` 个 0），因此一整段的贡献可以直接乘出来，只有最后一个不完整周期需要单独补算 —— 这是把 `O(L)` 位的"逐位枚举"换成 `O(1)` 的算术，单轮省掉一个 `L` 因子。

### 常数级优化（可选）

- 二分上界 `(k + 1) << x` 已经比 `10^18` 这类固定上界紧，二分轮数因此更少；能提前算出更紧的上界就更好。
- 数位 DP 版本里 `cnt1` 的取值上界是 `⌈i / x⌉`（只有 1/x 的位是合法位），若改成数组式记忆化，表的规模还能再小一档。

## 六、易错点与总结

### 易错点

- **位序口径写反**：题目是 1-based 位序，且 DP 里 `i` 表示"还剩 i 位"，当前决策位就是第 `i` 位，所以是 `i % x == 0`。写成 `(i - 1) % x == 0` 会整体错开一位，`x = 1` 时甚至察觉不到（因为 `x = 1` 下两种写法等价），换到 `x ≥ 2` 才暴露。
- **上界表达式依赖优先级**：`k + 1 << x` 的正确含义来自 `+` 优先于 `<<`。若误写成 `k + (1 << x)`，上界严重不足，`bisect_left` 会直接返回上界，答案偏小而且不报任何错。
- **二分目标要减 1**：找的是"第一个 `acc ≥ k+1` 的位置"，答案是它前一个；若手写成 `bisect_right(..., k)` 之类的形式，在 `acc(num) == k` 的等号边界上（示例 1 的 `acc(6) = 9 = k`）会偏大 1。
- **`acc` 中包含 `num = 0` 无影响**：DP 枚举 `0..num`，`price(0) = 0`，所以 `acc(num)` 与"1..num 之和"一致。若哪天把 `cnt1` 的初值或边界改成 1 起步，才会引入 off-by-one。
- **答案超出 32 位**：`k = 10^15、x = 8` 时答案量级约 `2.5×10^17`，Python 无溢出问题，换成 C++/Java 必须 `long long`。
- **`@cache` 定义在闭包里**：`dfs` 每次调用 `count` 都会重新创建，缓存互不污染；但如果把它提到 `count` 外面复用，就必须记得清缓存（`cache_clear`），否则会串联不同 `num` 的结果。

### 题型套路沉淀

- **「求最大的 X 使谓词 P(X) 成立」+ P 单调 ⇒ 二分答案**。判定函数只负责回答"P(mid) 真不真"，不要把它写成"求最值"。找边界统一用「第一个使 P 为真的位置，再按题意 ±1」来表达，比手写 `while lo <= hi` 三路分支更不容易错；Python 可直接 `bisect_left(range(上界), 目标值, key=谓词)` 一把梭，`bisect_left` 的语义天然就是"第一个 ≥ 目标的位置"。
- **二分答案的两个前置条件**：① 谓词单调；② **上界本身必须越过分界点**（即 `P(上界)` 必须为真，或如本题 `acc(上界) ≥ k+1`）。上界取小了会静默返回错误答案，值得专门验一次。
- **计数型谓词优先想数位 DP**：状态 `(剩余位数 i, 累计量 cnt, 是否贴上界 is_limit)`；上界位用 `num >> (i-1) & 1` 取；转移用 `is_limit and d == up`；叶子返回累计量、逐层求和 —— 这一套模板专治"统计 `≤ num` 的所有数中满足某按位条件的位置总数"。本题的 `cnt1` 计数对象是"合法位上的 1"，把 `i % x == 0` 作为计数条件嵌进去即可。
- **同一计数往往还有"按位独立统计"路线**：若按位条件彼此独立，可对每一位用闭式（完整周期数 × 半周期长 + 残余部分）直接算贡献，省掉 DP 的一个 `L` 因子。两条路线结果应当一致，可以互为对照。
- **值域大不等于不能二分**：答案可达 `10^17`，但二分只需 ~58 轮；"值域 10^17"只影响轮数的常数，真正决定成败的是判定函数的代价。
