# 2258. 逃离火灾

## 一、题目描述

给定一个 `m x n` 的网格 `grid`，格子取值为 `0`（草地，可通行）、`1`（着火）、`2`（墙，人与火都不可通过）。你初始位于左上角 `(0, 0)`，目标是走到右下角的安全屋 `(m - 1, n - 1)`。

规则按分钟推进，且**顺序固定**：每一分钟你可以先移动到上下左右相邻的草地格子，**你移动之后**火才会向所有非墙的相邻格子扩散一轮。

求在起点**最多可以停留多少分钟**，使得停留结束后你仍能安全到达安全屋：

- 若无论如何都到不了（例如火封死了所有出路）→ 返回 `-1`；
- 若不管停留多久都总能到达（例如火被墙完全围住）→ 返回 `10^9`；
- 边界：**到达安全屋后火紧接着烧到安全屋，也算安全到达**。

### 示例

```text
输入：grid = [[0,2,0,0,0,0,0],
              [0,0,0,2,2,1,0],
              [0,2,0,0,1,2,0],
              [0,0,2,2,2,0,2],
              [0,0,0,0,0,0,0]]
输出：3
解释：停留 3 分钟后仍能安全到达安全屋；停留超过 3 分钟则不能。

输入：grid = [[0,0,0,0],[0,1,2,0],[0,2,0,0]]
输出：-1
解释：火会蔓延到你可以移动的所有格子，无法安全到达。

输入：grid = [[0,0,0],[2,2,0],[1,2,0]]
输出：1000000000
解释：火被墙围住，无论如何你都能安全到达。
```

### 约束条件

- `m == grid.length`，`n == grid[i].length`
- `2 <= m, n <= 300`
- `4 <= m * n <= 2 * 10^4`
- `grid[i][j]` 为 `0`、`1` 或 `2`
- `grid[0][0] == grid[m - 1][n - 1] == 0`（起点与安全屋一定不是火、也不是墙）

## 二、解题思路

### 核心思想

**可行性对「停留时间」单调递减** —— 等得越久火势只会更大、可选路线只会更少。于是答案可以二分，判定函数 `check(t)` 用一次「火先烧 t 轮、之后人走一步火烧一轮」的同步模拟来完成。

### 思路演进

1. **暴力解法**：把停留时间 `t = 0, 1, 2, …` 逐个试一遍，对每个 `t` 完整模拟「等待 t 分钟 + 人行走 + 火扩散」的过程，取最大的可行 `t`。
   问题在于 **`t` 根本没有可枚举的上界**：示例 3 的答案就是 `10^9`，而真实的「无限可行」情形意味着枚举永远不会终止。所以枚举法在结构上就不成立。

2. **观察到两件事**：
   - **单调性**：`t` 增大时，火只会在相同或更多的格子上蔓延，人面对的局面只会更差 —— 因此 `check(t)` 的真值一定是 `True…True False…False` 的形状，具备二分的前提。
   - **"无限可行"有天然判据**：火的扩散轮次是有尽头的。整个网格只有 `m·n` 个格子，火最多在 `m·n` 轮内烧遍所有能到达的格子（此后 `f` 为空、分布不再变化）。因此若 `t = m·n` 时仍可行，说明火早已停滞、再等多久结果都一样 → 答案就是 `10^9`。这个观察同时给出了二分的上界。

3. **优化为**：二分最大的可行 `t`，判定函数负责把「等待」嵌进离散模拟里 —— 先让火空转 `t` 轮（对应我原地不动的 `t` 分钟），随后逐层推进人的 BFS，**人每走完一层、火再扩散一轮**，与题目的时间顺序一一对应。

### 关键点

- **时间轴的严格对齐**：把人第 `k` 步到达某格的时刻记作 `t + k`。普通格子要求「火到达时刻 **严格大于** `t + k`」，而安全屋允许「等于 `t + k`」（题面明确说火随后到也算安全）。这一处非对称是整题最容易写错的地方。
- **火与人的先后顺序**：题面是「我先移动，火后扩散」，所以模拟的循环顺序必须是「处理当前层顶点 → 把下一层加入队列 → 火扩散一轮」，不能颠倒。
- **火用一个 `on_fire` 集合去重**：每个格子只入队一次，保证火的扩散是 O(总格子数) 的。
- **二分的两个哨兵**：下界取 `left = -1`（`-1` 代表「等 0 分钟都不可行」，从而可直接用 `left` 输出 `-1`），上界取 `right = m * n + 1`（落在 `m * n` 上代表「无限可行」）。

## 三、代码实现

### 最终代码

```python
from typing import List   # 截图里没有，已补


class Solution:
    def maximumMinutes(self, grid: List[List[int]]) -> int:
        m, n = len(grid), len(grid[0])

        def check(t: int) -> bool:
            # 所有火源，以及「已经着火」的格子集合
            f = [(i, j) for i, row in enumerate(grid) for j, x in enumerate(row) if x == 1]
            on_fire = set(f)

            def spread_fire():
                """火向四周的草地扩散一轮"""
                nonlocal f
                tmp = f
                f = []
                for i, j in tmp:
                    for x, y in ((i - 1, j), (i + 1, j), (i, j - 1), (i, j + 1)):
                        if 0 <= x < m and 0 <= y < n and grid[x][y] == 0 and (x, y) not in on_fire:
                            on_fire.add((x, y))
                            f.append((x, y))

            # 1) 先让火烧 t 轮，等价于我在起点原地等 t 分钟
            while t and f:
                spread_fire()
                t -= 1
            if (0, 0) in on_fire:          # 还没出发就被烧到
                return False

            # 2) 逐层 BFS：每轮我先走一步，随后火扩散一轮
            q = [(0, 0)]
            vis = set(q)
            while q:
                tmp = q
                q = []
                for i, j in tmp:
                    if (i, j) in on_fire:  # 站上这一格时已经被烧到
                        continue
                    for x, y in ((i - 1, j), (i + 1, j), (i, j - 1), (i, j + 1)):
                        if (0 <= x < m and 0 <= y < n and grid[x][y] == 0
                                and (x, y) not in on_fire and (x, y) not in vis):
                            if x == m - 1 and y == n - 1:
                                return True          # 到达安全屋，火随后到也算安全
                            vis.add((x, y))
                            q.append((x, y))
                spread_fire()
            return False

        # 3) 二分最大可等待时间
        left = -1
        right = m * n + 1
        while left + 1 < right:
            mid = (left + right) // 2
            if check(mid):
                left = mid
            else:
                right = mid
        return left if left < m * n else 10 ** 9
```

## 四、复杂度分析

| 版本 | 时间复杂度 | 空间复杂度 |
| :--- | :--- | :--- |
| **最终代码**（二分 + 同步模拟） | O(N log N) | O(N) |
| 朴素解法（逐个枚举停留时间，每个都完整模拟） | O(N²) 量级，且上界无法确定 | O(N) |
| 理论下界 | O(N) | O(N) |

> 复杂度中的 N 指网格的格子总数 `m × n`（本题 N ≤ 2 × 10⁴）。

- **单次 `check(t)` 是 O(N)**：等待阶段火的总扩散量不超过 N 个格子，人的 BFS 每个格子至多入队一次，行走阶段火的总扩散量同样是 O(N)。
- **二分共 O(log N) 次判定**（判定区间的上下界相差 `m * n + 2`），乘起来即 O(N log N)。
- **空间**：火的状态集合 `on_fire`、人的访问集合 `vis` 与两个队列，最坏都是 O(N)。

## 五、优化评估

**结论**：时间上距理论下界只差一个 `log` 因子，**在当前这种「二分 + 整体模拟」的写法内已无实质优化空间**。

### 瓶颈分析

每次 `check(t)` 都从**初始火源重新扩散**、从**起点重新 BFS**。但二分过程中「火到达每个格子的最早时间」其实与 `t` 完全无关 —— 这部分信息被重复计算了 O(log N) 次，`log` 因子的来源就在这里。

### 可优化空间

若想彻底去掉 `log`，思路是把二分换成一次性预处理：先用多源 BFS 求出**火到达每个格子的时间表**（与 `t` 无关，只算一次），再从安全屋反向推导「人在每个格子最晚可以出发的时刻」，最后直接读起点处的结果，整体 O(N)。

不采用这条路线的原因是**边界不对称会显著抬高出错概率**：普通格子要求人严格早于火、安全屋允许同时到达，反向推导时需要把这两种不等号分开处理，另外还要单独处理「起点被墙/火封死」与「无限可行」两种退化情形。在 N ≤ 2 × 10⁴ 的数据范围下，二分版本多出的 `log` 因子（约 15 倍以内的判定次数）完全在可接受范围内，**换来的是判定逻辑与题面一一对应、几乎不可能写错**。

## 六、易错点与总结

### 易错点

- **忘记「火先烧 t 轮」**：若不先推进等待阶段的火，或漏掉等待结束后对 `(0, 0) in on_fire` 的检查，就会低估火势、给出偏大的答案。
- **时间轴顺序颠倒**：必须是「人走 → 火扩散」；写成「火扩散 → 人走」在每一步都会让火烧得更早一轮，答案偏小。
- **安全屋不能当普通格子处理**：若把安全屋的判定挪到「出队时再检查是否着火」，此时火已经多烧了一轮，会把题面允许的「同时到达」错判成失败。正确做法是在扩展邻居、命中安全屋的那一刻立刻返回 `True`。
- **`10^9` 的判据写错**：它表示「无论等多久都能到」，不是「答案很大」，必须用 `t = m * n` 时是否仍可行来区分，即分界写成 `left < m * n`。
- **二分下界误取 0**：`check(0)` 可能为 `False`（等 0 分钟都到不了），所以 `left` 必须从 `-1` 起，才能用同一个变量同时表达「不可行」与「答案 0」。

### 题型套路沉淀

- **「可行性随时间单调」是二分答案的触发条件**：凡是「求最大/最小的某个等待量、消耗量，且该量越大越难满足」的题，先验证单调性再上二分，不要急着构造贪心。
- **判定函数的写法取决于「等待」如何嵌入过程**：本题的等待是「让另一个扩散源先空转」，所以判定 = 一次带时间轴的同步模拟（队列分层推进 + 每层结束后推进另一个源）。
- **双源赛跑的通用注意点**：两者的推进顺序、每层的时刻语义、以及终点格子是否有「允许同时到达」的特权，必须在动手前逐条写清楚。
- **二分答案的两个哨兵**：下界取一个**保证不成立**的点（本题 `-1`），上界取一个**代表无穷或保证成立**的点（本题 `m * n + 1`，落点 `m * n` 时输出 `10^9`）。哨兵不是可选的常数优化，改错会直接导致答案偏差。
