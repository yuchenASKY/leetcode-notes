# 3924. 有限重边的最小阈值路径

> **难度**：困难
> **标签**：二分答案 · 0-1 BFS · 最短路 · 图
> **原题链接**：https://leetcode.cn/problems/minimum-threshold-path-with-limited-heavy-edges/

---

## 一、题目描述

给定一个有 `n` 个节点的带权无向图（`edges[i] = [ui, vi, wi]`）以及 `source`、`target`、`k`。

对一个整数阈值 `threshold`：边权 `<= threshold` 的边叫**轻边**，`> threshold` 的边叫**重边**。若某条
`source → target` 的路径上重边数量**不超过 `k`**，该路径称为**有效**。

求使"至少存在一条有效路径"的**最小整数阈值**；若无论如何都无解（不可达），返回 `-1`。

### 示例

```text
示例 1：
输入：n = 6, edges = [[0,1,5],[1,2,3],[3,4,4],[4,5,1],[1,4,2]], source = 0, target = 3, k = 1
输出：4
解释：threshold = 4 时轻边为 [1,2,3]、[3,4,4]、[4,5,1]、[1,4,2]，重边只有 [0,1,5]；
      路径 0 → 1 → 4 → 3 只用到 1 条重边，满足 k = 1。再小任何值都无法在 1 条重边内到达 3。

示例 2：
输入：n = 6, edges = [[0,1,3],[1,2,4],[3,4,5],[4,5,6]], source = 0, target = 4, k = 1
输出：-1
解释：0 所在连通块与 4 所在连通块没有边相连，无法到达，故无解。

示例 3：
输入：n = 4, edges = [[0,1,2],[1,2,2],[2,3,2],[3,0,2]], source = 0, target = 0, k = 0
输出：0
解释：起点与终点相同，不需要经过任何边走，最小阈值为 0。
```

### 约束条件

- `1 <= n <= 10^3`
- `0 <= edges.length <= 10^3`
- `edges[i] = [ui, vi, wi]`，`0 <= ui, vi <= n - 1`
- `1 <= wi <= 10^9`
- `0 <= source, target <= n - 1`
- `0 <= k <= edges.length`

## 二、解题思路

### 核心思想

**可行性关于 `threshold` 单调 → 二分答案；判定函数 = 边权只有 0/1 的最短路，用 0-1 BFS 线性解决。**

### 思路演进

1. **暴力解法（枚举候选阈值）**：`threshold` 的作用只是把边分成"轻/重"两类，因此它只有 O(m) 个有效
   取值（阈值取在某个边权上即可；比所有边权都大时与取 `max(w)` 等价）。于是枚举每个候选阈值，对每个
   候选做一次"最多 `k` 条重边能否到达"的搜索，取最小可行值。候选 O(m) 个 × 每次 O(n+m)，时间
   `O(m(n+m))` —— 在 n, m ≤ 10^3 时约 2×10^6 次操作，其实能过，但这份写法把**单调性**整个丢掉了：
   它明明知道"阈值越大越容易可行"，却还在逐个试。
2. **观察到单调性**：阈值变大，只会让某些重边变成轻边，绝不会让轻边变回重边。所以若某个 `t` 可行，
   任何 `t' > t` 也一定可行 —— **可行性关于 threshold 单调不减**。单调 → 可以二分：把候选数从 O(m)
   的对数级比较压缩到 `O(log maxW)` 轮判定。
3. **优化的关键转化**：剩下的问题是怎么写判定函数。直接"在图上搜索并约束重边数"不好写，但把边权
   按当前阈值映射成 `0`（轻边）/ `1`（重边）后，判定就变成了**求最少重边数**，即边权只有 0 和 1 的
   最短路 —— 用 **0-1 BFS**（双端队列）一趟线性扫完：轻边 `appendleft`（距离不变，同层），重边
   `append`（距离 +1，下一层）。队列中存的距离最大只差 1，天然按距离非降弹出，等价于 Dijkstra 的
   桶队列。
4. **边界收尾**：若在最大阈值（所有边都是轻边）下都不可达，说明 `target` 与 `source` 根本不连通 →
   返回 `-1`。阈值下界取 `0` 而不是 `min(w)`（见「关键点」）。

### 关键点

- **单调性是二分的入场券**：先确认"阈值增大不会让可行性变差"，再动手写二分。
- **下界取 `0`**：边权 `>= 1` 保证 `threshold = 0` 时所有边都是重边，此时只要存在一条**总边数不超过
  `k`** 的路径就是可行的 —— 所以答案完全可能是 `0`（示例 3 就是），不能想当然地从 `min(w)` 起二分。
- **0-1 BFS 的两个动作**：`wt == 0` 入队首、`wt == 1` 入队尾。这个"插队"才是让复杂度保持线性的原因，
  全用 `append` 就退化成了带权最短路而不能保证一次线性。
- **入队时就卡住预算**：只有 `new_dis <= k` 的重边松弛才会入队，所以队列里每个条目的重边数都 `<= k`，
  弹出 `target` 时可立即返回 `True`，不需要再比较距离。
- **`if d > dis[x]: continue` 必须保留**：同一个点可能被以更差的距离重复入队，跳过过期条目才能保证
  每个点只被真正处理一次。
- **无解只有一种情形**：`source` 与 `target` 不连通。因为阈值取到 `max(w)` 时所有边都是轻边，只要有
  路径就一定满足 `<= k`。

## 三、代码实现

### 最终代码

```python
from collections import deque
from math import inf          # 截图里没有，已补
from typing import List       # 截图里没有，已补


class Solution:
    def minimumThreshold(self, n: int, edges: List[List[int]], source: int,
                         target: int, k: int) -> int:
        max_wt = 0
        cnt = [[] for _ in range(n)]          # cnt[x] = [(邻居, 边权), ...]
        for i, j, wt in edges:
            cnt[i].append((j, wt))
            cnt[j].append((i, wt))
            max_wt = max(max_wt, wt)

        def check(threshold: int) -> bool:
            """threshold 下 source -> target 的最少重边数是否 <= k（0-1 BFS）"""
            dis = [inf] * n                   # dis[x]：到 x 最少经过几条重边
            dis[source] = 0
            q = deque([(source, 0)])

            while q:
                x, d = q.popleft()
                if x == target:               # 入队时已保证重边数 <= k，故可直接返回
                    return True
                if d > dis[x]:                # 过期条目
                    continue
                for y, w in cnt[x]:
                    wt = 1 if w > threshold else 0
                    new_dis = d + wt
                    if new_dis < dis[y]:
                        dis[y] = new_dis
                        if wt == 0:
                            q.appendleft((y, new_dis))   # 轻边：同层，插队首
                        elif new_dis <= k:
                            q.append((y, new_dis))       # 重边：下一层，插队尾
            return False

        if not check(max_wt):                 # 所有边都是轻边仍不可达 => 不连通
            return -1

        lo, hi = 0, max_wt                    # 二分最小可行阈值
        while lo < hi:
            mid = (lo + hi) // 2
            if check(mid):
                hi = mid
            else:
                lo = mid + 1
        return lo
```

> 说明：截图里只有 `check` 判定函数本身，这里补齐了 `import`、外层二分驱动与 `-1` 判定（截图里没有）。

## 四、复杂度分析

| 版本 | 时间复杂度 | 空间复杂度 |
| :--- | :--- | :--- |
| **最终代码** | O((n + m) · log maxW) | O(n + m) |
| 朴素解法（枚举候选阈值） | O(m · (n + m)) | O(n + m) |
| 理论下界 | O(n + m) | O(n + m) |

> 复杂度中的 n 指：图的节点数（`edges` 里的编号范围）；m 指边数 `edges.length`；maxW 是最大边权
> （`<= 10^9`，故 `log maxW <= 30`）。
>
> 二分的轮数来自阈值取值域 `[0, maxW]`；每轮判定是一次 0-1 BFS，代价 `O(n + m)`（每个点在距离被确定
> 后只被真正处理一次，过期条目直接跳过），乘以 `O(log maxW)` 即为总计。
>
> 下界那一行的 `O(n + m)` 只是"读入数据一次"的下界：本题必须做多轮判定才能定位最小阈值，一轮做不到，
> 所以实际可达到的最优就是 `O((n + m) · log)` 量级。

## 五、优化评估

**结论**：整体已是本题量级下的最优解，没有可降阶的余地。

### 瓶颈分析

时间由两个因子相乘构成：**每次判定至少要扫一遍可达区域**（`O(n + m)`，这是判定本身的下限）；**而阈值
的候选值是 O(m) 个边权**，要在候选集合里定位"最小的可行值"，用单调性做二分已经是最省的定位方式
（比较次数做到对数级，不可能亚对数）。两者相乘就是 `O((n + m) log maxW)`。

### 可优化空间

二分的**取值域**还有常数级余地：现在是在整数域 `[0, maxW]` 上二分，轮数 `log maxW <= 30`；若改成
先对边权排序去重、在**去重后的候选值数组**上二分，轮数降到 `log m`，代价是多一次 `O(m log m)` 的
排序。两者量级相同，本题规模下都不构成瓶颈，保留整数域二分的写法更短、边界更少。

### 常数级优化（可选）

- `dis = [inf] * n` 与 `deque` 的重建是每轮判定的固定开销，无法避免（判定函数要求"干净状态"）。
- 循环内把 `cnt[x]` 先取到局部变量再迭代，可省掉每次邻边访问的重复下标查找。
- `new_dis > k` 的状态对答案无用：当前代码里重边已用 `elif new_dis <= k` 挡在入队之前，这一层剪枝
  本身就带来常数收益（不必再去搜索永远不会被用到的状态）。

## 六、易错点与总结

### 易错点

- **`deque([(source, 0)])` 少写一层方括号**：写成 `deque((source, 0))` 会把元组拆成两个元素，队列变成
  `[source, 0]`，随后 `x, d = q.popleft()` 直接抛 `TypeError`。
- **二分下界写成 `min(w)`**：会漏掉答案为 `0` 的情形（示例 3，以及"存在一条总边数不超过 k 的路径且
  所有边权都 >= 1"的情形）。
- **忘记 `-1` 判定**：直接返回二分结果会把"不可达"错报成某个边权值。必须先判"最大阈值下是否可行"。
- **把 0-1 BFS 写成普通 BFS（全部 `append`）**：轻边会被推到队列尾部，弹出一个点时的距离不再是非降的，
  正确性（以及线性复杂度）都会丢。
- **丢掉 `if d > dis[x]: continue`**：过期条目会被当成有效状态继续扩展，正确性靠运气。
- **轻边/重边的口径写反**：题目是"`<= threshold` 为轻"，判 `w > threshold` 为 1 才是重边；写成
  `w >= threshold` 会在答案恰好等于某条边权时出错。

### 题型套路沉淀

- **"最小化某个阈值 / 最小值最大化，且可行性随阈值单调"** → 二分答案。固定动作三步：
  ① 找到判定函数 `check(t)`；② 确认单调性（通常是"约束变松，可行性不会变差"）；③ 定好可取的
  `[lo, hi]` 与下界哨兵（下界必须取到"判定确实为假"的相邻点，否则会漏掉边界答案）。
- **判定函数常能转化成一个更简单的问题**：本题把"最多 k 条重边的路径存在性"转成"0/1 边权最短路是否
  <= k"。遇到"限制某种边/操作的数量"的图论判定，先想能不能把代价归一成 0/1。
- **0-1 BFS 模板**（边权只有 0 和 1 的最短路）：`dist` 初始化 `inf`；出队时跳过 `d > dist[x]` 的过期
  条目；松弛成功且边权为 0 就 `appendleft`、为 1 就 `append`。
