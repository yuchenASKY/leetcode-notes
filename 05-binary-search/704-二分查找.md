# 704. 二分查找

> **难度**：简单
> **标签**：数组 · 二分查找
> **原题链接**：https://leetcode.cn/problems/binary-search/

---

## 一、题目描述

给定一个 `n` 个元素、**升序有序**的整型数组 `nums` 和一个目标值 `target`，返回 `target` 在 `nums` 中的下标；不存在则返回 `-1`。题目额外要求：必须写出 **O(log n)** 时间复杂度的算法 —— 这一句直接排除了线性扫描。

### 示例

```text
示例 1
输入：nums = [-1,0,3,5,9,12], target = 9
输出：4
解释：9 出现在 nums 中并且下标为 4

示例 2
输入：nums = [-1,0,3,5,9,12], target = 2
输出：-1
解释：2 不存在 nums 中因此返回 -1
```

### 约束条件

- `nums` 按**升序**排列，且**所有元素不重复**
- `n` 在 `[1, 10000]` 之间（即 `1 <= nums.length <= 10^4`）
- `nums[i]` 在 `[-9999, 9999]` 之间

---

## 二、解题思路

### 核心思想

**把「找 target」改写成「找第一个 >= target 的下标」**，再用有序性把这个查找每一轮砍掉一半：有序保证命题 `nums[i] >= target` 对下标 `i` 是**前假后真**的，于是存在唯一分界点；取区间中点问一次，就能判定答案落在哪半边。

### 思路演进

1. **朴素解（暴力）**：从左到右逐个比较，命中即返回。
   ```python
   for i, x in enumerate(nums):
       if x == target:
           return i
   return -1
   ```
   时间 O(n)、空间 O(1)。最坏情况要读完整个数组（`target` 不存在，或恰在末尾）。

2. **瓶颈定位**：问题不在「比较」这个动作，而在**每读一个元素只排除了 1 个候选**。`nums` 升序这个极强的前提在朴素解里被完全浪费了 —— 有序意味着元素之间的**相对位置携带着大小信息**，可暴力解把每个元素都当成了孤立的值来试。

3. **关键转化**：把「找值等于 target 的位置」换成一个**单调的二值问题**。

   定义命题 `P(i) = (nums[i] >= target)`。因为 `nums` 升序，所以 `P` 沿下标是**前假后真**的：`false, false, …, false, true, true, …, true`（`nums` 全部小于 target 时全假；`nums[0] >= target` 时全真）。

   于是要找的答案就是**唯一的分界点** `p = min{ i : P(i) 为真 }` = lower_bound。而"前假后真"这个形状有一个杀手锏性质：

   > 取区间内任意一点 `mid`，读 `nums[mid]` 问一句 `P(mid)`：
   > - 答**真** ⇒ `mid` 以及它**右侧全部**为真 ⇒ 分界点 `p <= mid` ⇒ 左半边（含 mid）是唯一可能区间；
   > - 答**假** ⇒ `mid` 以及它**左侧全部**为假 ⇒ `p > mid` ⇒ 右半边是唯一可能区间。

   **为什么原来不行、现在为什么行**：原来每次读取只能否定"这一个元素等于 target"；现在每次读取否定的是"一整段区间"，候选数直接减半。这正是 O(n) → O(log n) 的分水岭。（这一步的代价是题意被偷换了：从"找等于 target"变成"找第一个 >= target"，所以最后必须补一次值相等校验，见易错点 2。）

4. **最优解（本仓库的最终代码）**：用**红蓝染色**的思路固定不变量 ——
   - `left = -1`：一个**永远为「假」的哨兵**（下标 -1 上"nums[-1] < target"恒成立）；
   - `right = n`：一个**永远为「真」的哨兵**（越界位置的"元素"可视为 +∞ >= target）；
   - 循环中始终保持「`left` 是假、`right` 是真」，区间 `(left, right)` 内的元素才是尚未判定的候选；
   - 每轮把 `mid` 染成假（`left = mid`）或染真（`right = mid`），区间严格缩小；当两色相邻（`left + 1 == right`）时，分界点无处可藏，只能是 `right`。

   n 个元素产生 n+1 个候选位置（0…n），每轮候选数减半 ⇒ 轮数 `⌈log2(n+1)⌉`。

### 判据（可判定真假的命题）

> **`nums` 升序 ⟺ 命题 `P(i) = (nums[i] >= target)` 关于 `i` 前假后真 ⟹ 分界点 `p = min{i : P(i)}` 唯一存在，且 `nums[p] == target ⟺ target ∈ nums`。**

后半句是"最后要补值校验"的直接依据：`p` 只保证 `nums[p] >= target`，不保证相等。

### 判据族定位

本题属「**有序序列上找第一个满足某条件的位置**」族（lower_bound / 红蓝染色），判据的载体是**下标空间**（对 `i` 单调）。

它与相邻的「**二分答案**」族相邻而不同：二分答案是拿一个**值域**（答案的取值范围）做二分，单调性来自一个**额外构造的判定函数** `check(x)`（`x` 越大越容易满足），判据的载体是**值空间**。两族共用「单调 ⇒ 可二分」这根骨架，但**判据的载体不同**：本题的判定就是数组本身的一次读取，没有任何额外 check 函数；错把两族的判据互换（去值域上二分，或给下标二分硬塞 check）都会写不出正确代码。

### 关键点

- **先定区间定义，再写边界**：本题选**开区间** `(left, right)`，`left` / `right` 是"已判定为假/真"的边界，区间内才是候选。`while left + 1 < right`（区间非空）与 `right = mid`（mid 自己可能是分界点，不能丢）都是这个定义的**推论**，不是独立选择。
- `return right` 返回的是 lower_bound，**必须**再做一次 `nums[start] != target` 的值校验。
- `(left + right) // 2` 向下取整，保证 `mid` 严格落在区间内部、区间每轮严格变小，**不会死循环**。

## 三、代码实现

### 最终代码

```python
class Solution:
    def lower_bound(self, nums: list[int], target: int) -> int:
        """返回第一个满足 nums[i] >= target 的下标；全小于 target 时返回 len(nums)"""
        left = -1                # 恒为「假」：nums[left] < target
        right = len(nums)        # 恒为「真」：越界视为 +inf
        while left + 1 < right:  # 区间 (left, right) 非空
            mid = (left + right) // 2
            if nums[mid] < target:
                left = mid       # mid 染「假」，答案必在右侧
            else:
                right = mid      # mid 染「真」，mid 自己可能是答案，必须留下
        return right             # 两色相邻，分界点只能是 right

    def search(self, nums: list[int], target: int) -> int:
        start = self.lower_bound(nums, target)
        if start == len(nums) or nums[start] != target:
            return -1
        else:
            return start
```

> 截图为完整的 18 行（编辑器状态栏"行 18"），末尾 `return start` 未被裁掉。
> 截图里用的 `list[int]` 是 Python 3.9+ 的内置泛型，**不需要** `from typing import List`；本题无任何需要补充的 import（未用到 `bisect` / `collections` 等）。

## 四、复杂度分析

> 复杂度中的 `n` 指数组 `nums` 的长度（也即候选元素个数，`1 <= n <= 10^4`）。

| 版本 | 时间复杂度 | 空间复杂度 |
| :--- | :--- | :--- |
| **最终代码** | O(log n) | O(1) |
| 朴素解法（线性扫描） | O(n) | O(1) |
| 理论下界 | Ω(log n) | O(1) |

**轮数到底是多少**：候选"位置"共 `n + 1` 个（0 到 n，其中 n 表示"不存在"），`(left, right)` 的长度从 `n + 1` 每轮至少减半，因此轮数上界为 `⌈log2(n + 1)⌉`。本次插桩实测了 11 个 `n`（见「七、验证记录」§4），**每一档的最坏轮数都恰好等于这个值**：`n = 10^4` 时为 14 轮（`⌈log2 10001⌉ = 14`），`n = 1000` 时 10 轮。

每轮只读 `nums[mid]` 一次，比较一次 ⇒ **数组访问次数 = 迭代轮数**，所以这个解法在"比较次数"这个口径下**贴着下界走，没有可省的余地**。

**`Ω(log n)` 的依据**（比较模型）：一次 `nums[mid]` 与 `target` 的比较只输出 1 bit 信息，而 `n + 1` 个候选位置必须能互相区分（含"不存在"这一支），决策树至少需要 `⌈log2(n + 1)⌉` 个叶子的高度 ⇒ 任何基于比较的算法都下不来。

## 五、优化评估

**结论**：时间复杂度**已达理论下界（`Ω(log n)`），不存在渐进优化空间**。常数层面只有一处**真实**收益（改成 C 实现的标准库），且本题题面要求"编写算法"，建议保留手写版本。看似聪明的另外三种改法已逐一实测，其中两种被证伪。

### 瓶颈分析

单次查询的耗时构成 = 轮数 × （一次下标访问 + 一次比较 + 一次中点计算 + 一次分支）+ 固定的函数调用开销。轮数这一项**已经用满下界**（实测每档都等于 `⌈log2(n+1)⌉`），所以能动的只剩常数，而且天花板很低：`n = 10^4` 时总共只有 14 轮。

另外代码里有一处**结构性**的固定开销：`search` 调用 `self.lower_bound`，是**每查询一次额外的方法调用**（属性查找 + 绑定方法对象创建 + 调用）。这才是下面 V1 收益的全部来源。

### 可优化空间

| 代号 | 改法 | 性质 | 题面上限 n=10⁴ 实测 | 结论 |
| :--- | :--- | :--- | :--- | :--- |
| V0 | 截图原版 | 基准 | 1.00× | — |
| V1 | 把 `lower_bound` **内联**进 `search` | 常数 | **1.04× ~ 1.07×** | 收益真实但很小，**不建议**（见下） |
| V2 | 改用 `bisect_left`（C 实现） | 常数 | **4.75× ~ 5.05×** | 唯一大幅收益，但违背题面"编写算法"，仅作参考 |
| V3 | `(left+right)//2` → `>>1` | 常数 | 1.01× ~ 1.04× | **证伪**，与 V1 完全重合，见下 |
| V4 | `nums.index(target)`（C 线性） | 算法不同 | 0.02×（慢 47 倍） | 违规（非 O(log n)），仅作常数口径注记 |

- **V1 内联**：收益来自省掉的那次方法调用，`n = 10^4` 时约 4~7%（稳定，4 次复跑一致）；`n = 10^6` 的额外档上测得 1.17× ~ 1.45×，但该档**抖动明显**（同一份脚本 5 次复跑跨度达 28 个百分点，属内存带宽受限），只能定性说"同向、幅度不确定"。**代价是丢掉 `lower_bound` 这个可复用件** —— 它是这套模板里最通用的部分（"第一个 >= x 的位置""插入位置"都能直接复用），为 5% 的可读性倒退不值得，故**不作为推荐改法**。
- **V2 `bisect_left`**：Python 标准库用 C 实现同样的逻辑，`n = 10^4` 时 **4.75× ~ 5.05×**、`n = 10^6` 时 3.73× ~ 4.29×。收益真实且显著，但本题题面明确要求"编写一个具有 O(log n) 时间复杂度的算法"，直接调库等于跳过手写二分；作为**常数参考**列出，交付/面试场景请用手写版。
- **V3 `>>1` 移位**：**证伪**。四档实测里 V3 与 V1（只差一个算子）的耗时差 ≤ 0.02 ms/1000 次查询，且档位间结论互相矛盾（`n = 10^4` 上 `//2` 略快、`n = 10^6` 上 `>>1` 略快）。再做一次**算子级隔离**（5,000,000 次紧循环、无 lambda、无属性查找）：`//2` 371.43 ms vs `>>1` 382.72 ms —— `>>1` **反而略慢**。⇒ Python 里"移位一定比整除快"是**不存在**的经验，别为它牺牲可读性。
- **V4 `nums.index`（C 语言实现的线性扫描）**：这条单独说，它给出一个反直觉的交叉点。

  **"底层是 C" 不等于"更快"**：二分是 Python 层循环（轮数少、每轮昂贵），`list.index` 是 C 层循环（轮数多、每轮极廉价）。谁赢取决于 n。

  | n | V0 二分（Python） | V4 `list.index`（C 线性） | 谁快 |
  | :--- | :--- | :--- | :--- |
  | 16 | 0.45 ms | 0.30 ms | **线性快 1.5×** |
  | 100 | 0.63 ms | 0.70 ms | 基本持平（线性略慢） |
  | 10⁴ | 1.31 ms | 62.83 ms | 二分快 **48×** |
  | 10⁶ | 2.98 ms | 6653.16 ms | 二分快 **2233×** |

  交叉点落在 n 介于 16 与 100 之间：n 很小时 C 层线性的常数优势能盖过 Python 层的对数轮数；一旦到题面上限 `10^4` 就彻底反转。**但这条只作常数口径的注记** —— 题面要求 O(log n)，线性方案无论常数多小都不合规；而且本节所有实测数字都是"泛化到任意 n 的研究"，本题 `n <= 10^4` 时任何写法都是 0 ms，**不是"不优化就会 TLE"**。

### 优化代码

**（仅供参考，不建议替换最终代码）** 若只追求单次查询的常数最小，标准库版：

```python
from bisect import bisect_left


class Solution:
    def search(self, nums: list[int], target: int) -> int:
        i = bisect_left(nums, target)          # C 实现，语义与手写 lower_bound 完全一致
        return -1 if i == len(nums) or nums[i] != target else i
```

**优化理由**：`bisect_left` 就是本题 `lower_bound` 语义的 C 实现，省掉整个 Python 层解释开销（题面上限规模实测约 4.8×）。**不建议在本题使用**：题面要求自己编写 O(log n) 算法；且它只省常数、不改渐进复杂度。

### 常数级优化（可选）

- **`//2` 换 `>>1`**：实测无收益（见上），不要改。
- **内联 `lower_bound`**：省一次方法调用、约 5%（`n = 10^4`），但牺牲可复用性，**保持现状更好**。
- **把 `left` / `right` / `nums` 缓存进局部变量**：本函数里它们已是局部变量，无可缓存项。
- **不要碰轮数相关的结构**：轮数贴下界，任何"少一轮"的尝试都只可能写错。实测确认（§4）当前实现每一档都恰在下界上，**没有一轮是多余的**。

## 六、易错点与总结

### 易错点

1. **区间定义与边界写法混搭 —— 二分 bug 的头号来源。** 常见两种约定：
   - **闭区间** `[left, right]`（`left = 0, right = n - 1`）：循环 `while left <= right`，命中后收缩用 `mid ± 1`；
   - **开区间** `(left, right)`（本题：`left = -1, right = n`）：循环 `while left + 1 < right`，收缩用 `right = mid` / `left = mid`。

   把开区间的初值配上 `mid - 1`，或闭区间配 `right = mid`，就会死循环或漏解。**决定写法的是"不变量"，不是手感**：本题不变量是"`left` 恒假、`right` 恒真"，`mid` 一旦被判定为真，它**自己就可能是分界点**，所以只能是 `right = mid` 而绝不能 `mid - 1`。
2. **只判越界、不判值相等。** `lower_bound` 保证 `nums[start] >= target`，**不保证等于**。少写 `nums[start] != target` 这一项，`nums = [-1,0,3,5,9,12], target = 2` 会返回 **2**（`nums[2] = 3`），而不是 -1 —— 官方示例 2 就能抓出来（实测见「七、验证记录」§3b）。只判 `start == len(nums)` 是**一半**的校验。
3. **`left = -1` 不是笔误，但要小心它只当月"值"、不当"下标"。** 它作为"恒假哨兵"参与算中点；由于循环条件保证 `right >= 1`，有 `mid = (left + right) // 2 >= 0` 且 `mid < right <= n`，所以 `mid` **永远落在 `[0, n-1]`**，`nums[mid]` 不会越界。反过来，若某天写成 `nums[left]`，Python 的**负索引会静默取到最后一个元素**、代码不报错而结果错 —— 用开区间写法时把这条记牢。
4. **`(left + right) // 2` 的溢出问题在 Python 里不存在，换语言要改。** C++ / Java 里 `left + right` 可能溢出 int；Python 的 int 是任意精度，**不需要**写 `left + (right - left) // 2`。这是"换语言提交时必须同步改"的少数点之一。
5. **依赖"元素不重复"这条题面保证。** 有重复元素时这个 `lower_bound` **依然正确**（返回第一个位置），但"二分返回的那个下标"不再唯一，`search` 的语义要重新定义 —— 这类题要改用"左右边界双二分"（找第一个和最后一个位置）。
6. **别把"看起来更快"当结论。** 本次实测证伪了 `>>1` 移位（无差异）与"C 层线性必然更快"（n ≥ 100 后彻底反转）；连基准脚本本身都被抓到两个设计缺陷（变体量级相差三个数量级不能同组轮转、被 lambda 包一层的版本会平白多算一层开销），详见「七、验证记录」。**猜快慢的成本远高于测一次。**

### 题型套路沉淀

- **二分查找 = 在一根单调的 0/1 序列上找分界点。** 写代码前先回答三个问题，答案齐了代码就是机械翻译：
  1. **我要找的位置满足什么条件？**（本题：第一个 `nums[i] >= target`）
  2. **这个条件对下标单调吗（前假后真）？**（靠有序性成立）
  3. **区间定义为开还是闭？**（定下不变量，边界写法随之确定）
- **不变量法（红蓝染色）**：固定"`left` 恒假、`right` 恒真"，每轮染一格，最后两色相邻即答案。这套写法把 `mid ± 1` 的 off-by-one 从"要记住的规则"变成了"定义推出来的必然"，强烈建议作为默认模板。
- **统一成 lower_bound 再判等**：把"找 target"拆成「找第一个 >= target」+「值是否相等」。前者是可复用的通用件（插入位置、第一个/最后一个位置都能复用），后者只是一行判断。**先写通用件，再写那一行判断**。
- **同型练手**（难度递增）：35 搜索插入位置（就是裸 lower_bound）→ 34 在排序数组中查找元素的第一个和最后一个位置（左右边界双二分）→ 69 x 的平方根 / 367 有效的完全平方数（对值域二分，即"二分答案"族的入门）→ 875 爱吃香蕉的珂珂 / 1011 在 D 天内送达包裹的能力（真正的二分答案，需要自己构造 `check`）。
- **题面口径决定结论**：本题 `n <= 10^4`，任何正确写法都是 0 ms。本节所有常数结论都是**泛化到任意 n 的研究**，不能理解为"不优化会超时"。

## 七、验证记录

**验证范围**：按约定，**截图来源的代码是用户已提交 AC 的版本，不再重复验证正确性**（本节不为其跑对拍、不逐行复核逻辑）。下面参与对拍的全部是**本次为笔记新写的代码**：V1 内联版、V2 `bisect` 版、V3 移位版、V4 `list.index` 参考版，以及一个**刻意去掉值校验的错版**（用于定位易错点 2）。脚本 `bench_704.py` 放在 workspace，未进入仓库。

**用例总量**：官方示例 2 + 随机对拍 80 组 + 手工边界 12 条 + 错版定位 1 条 + 轮数探针 44 组 + 微基准 4 档输入 ≈ 143 个，未触及 500 上限；随机对拍按小批量尺度取 `n <= 20`。

| 项 | 做法 | 结果 |
| :--- | :--- | :--- |
| §1 官方示例 | 2 条一起跑并 `assert` | 2/2 通过 |
| §2 随机对拍 | 40 组随机（`n <= 20`，升序无重复）× 每组 2 个 target = 80 组；基准为**独立的线性扫描**（不共用待测逻辑） | V1 / V2 / V3 偏差均为 **0** |
| §3 手工边界 | 12 条：`n = 1` 命中/未命中/双向越界、值域端点 `±9999`、首尾元素命中、数组外目标、偶数步长数组取奇数 target | 不一致 **0** |
| §3b 错版定位 | 删掉 `nums[start] != target`、只判越界 | `nums = [-1,0,3,5,9,12], target = 2` 返回 **2**（应为 -1），被官方示例 2 当场抓出；对拍中把它排除在"新变体偏差表"外 |
| §4 轮数 vs 下界 | 11 个 `n`（1,2,3,4,7,8,15,16,100,1000,10000）× 4 个探针（首元素/中点/末元素/末元素+1）= 44 组，插桩计轮数 | **逐档等于** `⌈log2(n+1)⌉`（n=10⁴ 实测 14 轮 = 理论值 14）；无一档超下界 |
| §5 微基准 | n ∈ {16, 100, 10^4, 10^6}，每档 1000 次查询（500 命中 + 500 未命中），**9 轮轮转取最优**，复跑 5 次 | 见下表 |
| §6 算子级隔离 | 5,000,000 次紧循环，无 lambda / 无属性查找，9 轮取最优 | `(i + i*3) // 2` **371.43 ms** vs `(i + i*3) >> 1` **382.72 ms** ⇒ 无收益 |

**基准脚本本身被抓到的两个缺陷**（先踩到、修掉后才得到上表，记下来以免复现）：

1. **量级相差三个数量级的变体不能同组轮转。** 最初把 V4 和其它变体放进同一个 `for rep in range(9)` 循环里。V4 单轮就要 5 秒级（`n = 10^6`），跑完会把 CPU 缓存整个冲掉，**紧跟在它后面的版本白捡热度** —— 修之前 V1 在 `n = 10^6` 上显示 1.29×、V3 显示 1.37×，把 V4 拆出去单独测后同一处变成 1.45× / 1.42×。⇒ 耗时量级悬殊的变体必须分组测量。
2. **用 lambda 包一层会把开销记到别人头上。** V0 最初写成 `lambda a, b: s.search(a, b)`，而 V1/V2/V3 是直接函数引用 —— 这层 lambda 的开销被算进了"内联版省下来的收益"里，虚高约 5~10 个百分点。改成直接传绑定方法 `s.search` 后才对齐（各变体都是直接函数引用）。

另外记一条**未定量分离**的项：`n = 10^6` 档的测量抖动明显（同一份脚本 5 次复跑，V1 的比值跨度 1.17× ~ 1.45×，属内存带宽受限），因此本表把**题面上限 `n = 10^4`** 作为主口径，`n = 10^6` 只作规模趋势参考、不作结论依据。
