# 2616. 最小化数对的最大差值

> **难度**：中等
> **标签**：数组 · 二分 · 贪心 · 排序
> **原题链接**：https://leetcode.cn/problems/minimize-the-maximum-difference-of-pairs/

---

## 一、题目描述

给定整数数组 `nums` 和整数 `p`，从 `nums` 中选出 `p` 组「下标对」，**每个下标最多出现在一组里**；一组下标 `(i, j)` 的代价是 `|nums[i] - nums[j]|`。要求让这 `p` 个代价的**最大值尽可能小**，返回这个最小值（`p = 0` 时按空集最大值 `0` 处理）。

### 示例

```text
输入：nums = [10,1,2,7,1,3], p = 2
输出：1
解释：下标对 (1,4) 与 (2,5)，差值分别 0 和 1，最大差值为 max(0,1) = 1。
```

```text
输入：nums = [4,2,1,2], p = 1
输出：0
解释：下标对 (1,3)，差值为 |2 - 2| = 0，最大差值的最小值为 0。
```

### 约束条件

- `1 <= nums.length <= 10^5`
- `0 <= nums[i] <= 10^9`
- `0 <= p <= nums.length / 2`

---

## 二、解题思路

### 核心思想

**「最小化最大值」→ 二分答案。** 把原问题反转成判定题「差值上限为 `x` 时能否选出 `p` 对」，这个判定既**单调**（上限越大越容易满足）又能**贪心线性求解**（排序后只配相邻元素），于是对 `x` 二分即可。

### 思路演进

1. **暴力解法**：枚举所有选出 `p` 组下标对的方案，逐组算最大差值再取最小。候选方案数在 `n = 10^5` 时是阶乘级，完全不可行；退一步只在「所有可能的元素差值」里挑 `p` 个候选去验证，仍然是 O(n²) 量级的候选集，也过不了。
2. **观察到**：把问题**反过来问** —— 「给定差值上限 `x`，最多能配出多少对？」这个判定有两条好性质：
   - **单调**：若上限 `x` 可行，则任何 `x' >= x` 也必然可行（放宽约束不会让已有的合法配对失效）。所以「最小的可行 `x`」可以用二分定位。
   - **可贪心**：把 `nums` 排序后，要让「差 ≤ `x`」的配对数最多，只需从左往右扫：遇到 `nums[i+1] - nums[i] <= x` 就立刻配成一对并跳过这两个元素（下标不能重复用）；否则 `nums[i]` 与右侧任何元素的差只会更大，直接弃用它。
3. **关键转化**：为什么「排序后只配相邻元素」不会丢掉最优解？把一组合法配对的下标（升序）看成若干条区间。若某条区间内部还夹着别的下标，就把这对换成「区间内相邻的两个下标」，差值不会变大；反复做这种「缩短区间」的交换，任意一组 `p` 对都能在不增大最大差值的前提下，变成一组**相邻且互不重叠**的配对。于是问题等价于：在有序数组上数一数最多能切出多少个「相邻差 ≤ `x`」的不重叠二元组。
4. **优化为**：在值域 `[0, nums[-1] - nums[0]]` 上二分最小的可行 `x`。每次判定 O(n)，二分 O(log V)，整体 O(n log n + n log V)。

### 关键点

- **排序是前提**：相邻元素的差最小，且只有有序之后「当前元素配不上就整个跳过」的贪心才成立。
- **贪心的两条分支**：差 ≤ `x` → 配对并前进两格；差 > `x` → 只前进一格。
- **二分区间取闭区间 `[0, nums[-1] - nums[0]]`**：答案必然是某两个元素的差，一定落在其中。上界要能取到 —— 当答案恰好等于 `nums[-1] - nums[0]` 时，区间内所有值都不可行，`bisect_left` 返回区间长度（= 上界），正好就是答案。
- 用 `bisect_left(range(...), True, key=check)` 直接找「第一个 `True`」，省掉手写二分；`key` 参数需要 Python 3.10+。

## 三、代码实现

### 最终代码

```python
from typing import List          # 截图里没有，已补
from bisect import bisect_left   # 截图里没有，已补


class Solution:
    def minimizeMax(self, nums: List[int], p: int) -> int:
        nums.sort()

        def check(mx: int) -> bool:
            cnt = i = 0
            while i < len(nums) - 1:
                if nums[i + 1] - nums[i] <= mx:
                    cnt += 1
                    i += 2          # 这两个下标已用掉
                else:
                    i += 1          # nums[i] 与右侧任何元素都超限，弃用它
            return cnt >= p

        # 答案 ∈ [0, nums[-1] - nums[0]]；
        # 区间内全是 False 时 bisect_left 返回区间长度，即上界本身
        return bisect_left(range(nums[-1] - nums[0]), True, key=check)
```

## 四、复杂度分析

| 版本 | 时间复杂度 | 空间复杂度 |
| :--- | :--- | :--- |
| **最终代码** | O(n log n + n log V) | O(n) |
| 朴素解法 | 指数级 | O(n) |
| 理论下界 | O(n log n) | O(n) |

> 复杂度中的 n 指数组 `nums` 的长度；V = `nums[-1] - nums[0]`，即答案的值域宽度（≤ 10^9），二分轮数 O(log V) ≈ 30。
>
> 排序 O(n log n) 是主导项，判定函数每轮只线性扫一遍数组，共跑 O(log V) 轮。朴素解要枚举 `p` 组配对的方案（或 O(n²) 量级的候选差值），与本题的「二分 + 贪心」不在一个数量级。

## 五、优化评估

**结论**：已是本题的标准最优解，无进一步的量级优化空间。

### 瓶颈分析

时间花在两处：① 排序 O(n log n)；② O(log V) 轮线性判定。判定函数只扫一遍数组、无多余开销，已经触底。空间上只有排序产生的开销。

### 可优化空间

- 整体降到 O(n) 级别不现实：答案依赖「哪些元素互为相邻」这一有序关系，比较模型下先排序就至少要 O(n log n)。
- 若 `nums[i]` 的值域很小，可用计数排序把排序降到 O(n + U)；但本题 `nums[i]` 可达 `10^9`，不适用。
- 二分轮数已经只有 O(log V) ≈ 30 次，压缩空间有限。

### 常数级优化（可选）

- 在 `check` 里先把 `len(nums)` 存成局部变量（`n = len(nums)`），避免循环中反复取长度。
- 手写显式上下界的 `while l < r` 二分可省掉 `key` 的包装调用，但可读性下降，收益很小，不推荐盲改。

## 六、易错点与总结

### 易错点

- **配对成功后必须跳过两个下标**（`i += 2`）：题目要求每个下标最多用一次，只跳一格会把同一个元素重复计入。
- **差 > `mx` 时只能跳一格**：数组已排序，`nums[i]` 与右侧任何元素的差都 ≥ `nums[i+1] - nums[i]`，它已经无法参与任何合法配对，只能弃用。
- **二分上界要能取到 `nums[-1] - nums[0]`**：答案可能就是它。用 `bisect_left(range(...))` 时，「区间内全是 False」会自动返回区间长度（即上界），无需额外处理；若改写成手写闭区间二分，别把上界设成 `nums[-1] - nums[0] - 1`。
- **`p = 0` 时答案恒为 0**：此时 `check` 恒真，二分返回 0，逻辑自洽，不需要特判。
- **所有元素相同**时 `range(0)` 为空，`bisect_left` 返回 0，恰好是正确答案，不会越界。

### 题型套路沉淀

- **「最小化最大值 / 最大化最小值」→ 二分答案**：凡是这类问法，优先把问题反转成「上限/下界为 x 时是否可行」的判定，再用单调性二分。
- **排序 + 相邻配对的贪心**：在「选出不重叠二元组、使最大差最小」的模型里，排序后只考虑相邻元素；判定用「能配就配并跳两格、否则跳一格」取得最多配对数。
- **`bisect_left(range(hi), True, key=pred)`**：判定是单调布尔、候选值是连续整数区间时的固定写法，直接拿到「第一个满足条件的位置」，省掉手写二分。
