# 4008. 击败所有怪物的最小初始强度

> **难度**：中等
> **标签**：二分查找 · 数组 · 前缀和 · 差分数组
> **原题链接**：https://leetcode.cn/problems/minimum-initial-strength-to-defeat-all-monsters/

---

## 一、题目描述

有 `n` 只怪物，`monsters[i]` 是第 `i` 只的强度。另有 `m` 条**临时加成**，`boosts[j] = [l, r, v]` 表示「与下标落在 `[l, r]` 内的怪物战斗时，加成 `+v`」；范围可重叠，所有覆盖当前下标的加成**相加**得 `bonus[i]`。

你从一个**非负**初始强度 `S` 出发，从左到右依次打怪：

- 打第 `i` 只时，只有 `当前强度 + bonus[i] >= monsters[i]` 才能击败它；
- 击败后**当前强度减少 `monsters[i]`**（`bonus` 不参与扣血、也不改变当前强度）；若减成负数则置 `0`。

求能打完所有怪物的**最小**初始强度。

要点：`bonus[i]` 与 `S` 无关，它只由 `boosts` 决定；它出现在**判定式**里，不出现在**状态转移**里 —— 这两条一分开，题目就只剩两个独立子问题。

### 示例

```text
输入：monsters = [5,10,15], boosts = [[1,1,10]]
输出：30
解释：bonus = [0,10,0]。S=30：打 0 号 30>=5 → 25；打 1 号 25+10>=10 → 15；打 2 号 15>=15 → 0。S=29 时打 2 号会差 1，故答案 30。

输入：monsters = [5,10,15], boosts = [[1,2,10],[1,2,5]]
输出：5
解释：bonus = [0,15,15]。S=5：打 0 号 5>=5 → 0；打 1 号 0+15>=10；打 2 号 0+15>=15。全程强度都没再涨回来，5 就够。
```

### 约束条件

- `1 <= monsters.length <= 5 * 10^4`
- `1 <= monsters[i] <= 10^9`
- `0 <= boosts.length <= 5 * 10^4`
- `boosts[i] = [l, r, v]`，`0 <= l <= r < monsters.length`，`1 <= v <= 10^9`

## 二、解题思路

### 核心思想

把问题拆成两层，各自用一个经典工具：

1. **算 `bonus`：区间加、单点查 → 差分数组**，`d[l] += v; d[r+1] -= v`，再一趟前缀和即得所有 `bonus[i]`，`O(n + m)`；
2. **定 `S`：谓词 `P(S) = 「从 S 出发能打完」` 关于 `S` 单调 → 二分答案**，把候选从 `S = 0..sum` 压到 `log(sum) ≈ 46` 次。

而本题还多一层：`P(S)` 的每一条约束都能**反解成 `S` 的一个下界**，所以连二分都不需要 —— 一趟扫描直接算答案（见「五、优化评估」）。

### 判据与判据族定位

**判据**：`P(S)` ⟺ 按题面规则从 `S` 模拟一遍，全程不违反 `cur + bonus[i] >= monsters[i]`。

**族定位 —— 本题是「二分答案」族**（可行域二分 / 最小化可行值），与本目录下另一大族「**有序序列上的下标二分**」是两族，边界写法**不可互抄**：

| | 二分对象 | 单调性来源 | 两端点语义 | 收缩写法 |
| :--- | :--- | :--- | :--- | :--- |
| **二分答案**（本题） | **答案值** `S` | 谓词 `P(·)` 本身单调 | **先验哨兵**：`left` 恒不可行、`right` 恒可行 | `left = mid` / `right = mid`（**不带 ±1**） |
| 下标二分 | **下标** | 数据（或构造出的结构）有序 | 真实下标区间 | `left = mid + 1` / `right = mid - 1` 一类 |

本题的单调性是**证出来的**，不是题面给的：先证不变量（见下），再由 `cur_i(S)` 关于 `S` 非减推出「起点更大 ⇒ 每一步的当前强度都不更小 ⇒ 判定只更容易成立」。

**本题贯穿全程的不变量**（也是官方 Hint 2）：

```text
记 pre_i = monsters[0] + ... + monsters[i-1]，则打第 i 只怪之前的当前强度恒为
    cur_i = max(0, S - pre_i)
归纳：cur_{i+1} = max(cur_i - monsters[i], 0) = max(0, S - pre_i - monsters[i]) = max(0, S - pre_{i+1})
（因为 monsters[i] >= 1 > 0，多出来的 -monsters[i] 那一项永远不会成为最大值）
```

有了它，判定条件就变成一行**只关于 `S` 的不等式**：`max(0, S - pre_i) + bonus[i] >= monsters[i]`。

### 思路演进

1. **暴力解法**：从 `S = 0` 开始逐个试，每个 `S` 模拟一遍 `O(n)`（还要重算 `bonus`，再乘 `O(m)`），上界是 `sum(monsters)`。时间 `O(S·n·m)`，而 `S` 可达 `5×10^13` —— 完全不可行。
2. **瓶颈定位**：贵的不是「模拟」，而是**重复**：① 每个候选 `S` 都把与 `S` 无关的 `bonus` 重算一遍；② 明明「`S` 更大只会更容易」，却对 `S` 逐个线性枚举。两条浪费是**正交**的，得分开治。
3. **关键转化一（治 ①）：`bonus` 是「区间加、单点查」的教科书场景** → 差分数组。这里有个必须注意的细节：`d` 要开 `n + 1` 长，因为 `r + 1` 可能是 `n`（合法下标之外），用来消掉「一直持续到末尾」的区间。
4. **关键转化二（治 ②）：单调性 ⇒ 二分答案**。因为 `P(S)` 关于 `S` 单调，把线性枚举换成 `while left + 1 < right` 的哨兵式二分，两端点取 `left = -1`（初始强度非负 ⇒ 必不可行）、`right = sum(monsters)`（见「关键点」的证明）。于是复杂度 `O(n + m + n·log S)`，`log S ≈ 46`。
5. **关键转化三（本题的终局）：`P(S)` 其实是可解析求解的，二分这一步可以整个省掉。** 把每条约束反解：
   - 若 `bonus[i] >= monsters[i]`：`max(0, S - pre_i) >= 0 >= monsters[i] - bonus[i]`，**无条件成立**，对 `S` 无约束；
   - 若 `bonus[i] < monsters[i]`：需要 `max(0, S - pre_i) >= monsters[i] - bonus[i] > 0`，即当前强度**必须为正**，等价于 `S - pre_i >= monsters[i] - bonus[i]`，也就是 `S >= pre_i + monsters[i] - bonus[i]`。

   每条约束都只是 `S` 的一个下界，取最大即可；再加上「初始强度非负」：

   ```text
   answer = max(0,  max  ( pre_i + monsters[i] - bonus[i] ) )
                  i: bonus[i] < monsters[i]
   ```

   **充分性**（该值确实可行）：对每只怪 —— 若 `bonus[i] >= monsters[i]` 直接过；否则 `S >= pre_i + monsters[i] - bonus[i] > pre_i`，此时 `cur_i = S - pre_i >= monsters[i] - bonus[i]`，加加成后恰好够。
   **最小性**：每条约束都是必要条件，取最大后减 1 必然违反某一条。
   一趟 `O(n)` 扫描即可，`log` 因子彻底消失。

### 关键点

- **`right = sum(monsters)` 一定可行**（可证，不是拍脑袋的上界）：取 `S = sum` 时 `cur_i = S - pre_i = sum - pre_i >= monsters[i]`（后面还剩若干只，非负），永不触发置零，判定式恒成立。
- **`left = -1` 一定不可行**：题面要求初始强度非负，`-1` 落在可行域外。二分答案的两个端点必须是**语义明确**的哨兵，不能只取「大概的范围」。
- **两个哨兵的收缩都不带 ±1**：`while left + 1 < right` 配 `left = mid / right = mid`，循环结束时 `right` 就是答案。这与下标二分（`left = mid + 1`）是**两套写法**，混用会得到「答案差 1」或死循环。
- **解析式里 `bonus[i] < monsters[i]` 这个条件是承重的**：去掉它对所有 `i` 取 `max` 会**系统性高估**（见「易错点」的反例）。机理是「加成已经够大时，这只怪对初始强度**没有任何要求** —— 哪怕当前强度是 0 也能过」。
- `bonus` 参与**判定**、不参与**扣血**。把 `bonus` 加进 `cur` 是本题最常见的理解错误。

## 三、代码实现

### 最终代码

以下为已提交通过的版本（截图第 1–24 行，末行 `return right` 后即为空白，无裁切）：

```python
class Solution:
    def minInitialStrength(self, monsters: list[int], boosts: list[list[int]]) -> int:
        def helper(mid, bonus):
            for i, j in zip(monsters, bonus):
                if i > mid + j:
                    return False
                mid = max(mid - i, 0)
            return True

        left = -1
        right = sum(monsters)
        bonus = [0] * (len(monsters) + 1)
        for m, n, k in boosts:
            bonus[m] += k
            bonus[n + 1] -= k
        for i in range(1, len(bonus)):
            bonus[i] += bonus[i - 1]
        while left + 1 < right:
            mid = (left + right) // 2
            if helper(mid, bonus):
                right = mid
            else:
                left = mid
        return right
```

> 代码直接取自截图，未做改动；`list[int]` 是内建泛型，**无需补 `import`**。
> `helper` 里的 `i` / `j` 分别是「怪物强度」与「该下标的加成」（`zip` 的两个序列），`bonus` 长度 `n + 1` 但 `zip` 在短的 `monsters` 上停止，所以多出的哨兵格不会被读到。

## 四、复杂度分析

| 版本 | 时间复杂度 | 空间复杂度 |
| :--- | :--- | :--- |
| **最终代码**（差分 + 二分答案） | `O(n + m + n·log S)` | `O(n)` |
| 优化版（差分 + `O(n)` 解析式） | `O(n + m)` | `O(n)` |
| 朴素解法（枚举 `S`，每次重算加成） | `O(S·n·m)` | `O(1)` |
| 理论下界 | `O(n + m)` | `O(n)` |

> `n = monsters.length`，`m = boosts.length`，`S = sum(monsters) <= 5×10^4 × 10^9 = 5×10^13`，故二分的轮数 `log2(S+1) ≈ 46`（实测：`big` 档 44 轮、`small` 档 18 轮、`covered` 档 44 轮、`tiny` 档 39 轮）。
>
> 时间下界 `O(n + m)`：至少要读完 `n + m` 个数；解析式版达到该下界。空间上差分数组是 `O(n)`，`boosts` 本身占 `O(m)`。

## 五、优化评估

**结论**：**仍有优化空间，而且不是常数级 —— 二分这一步可以整个换成 `O(n)` 解析式**，实测快 **12.7× ~ 53.5×**。另外，若坚持保留二分骨架，骨架内有两条稳定的常数优化（合计约 1.10× ~ 1.15×）。

> 口径说明：`n <= 5×10^4`，截图版最坏档实测也只有 170 ~ 226 ms，**不存在「不优化就过不了」的问题**。下面的优化意义在于**去掉一个 `log` 因子**（`n·log S` → `n`），以及把「谓词可解析求解」这条更普遍的观察记录下来。

### 瓶颈分析

阶段归因（`big` 档，`n = 5×10^4`，各量同轮 7 轮取最优）：

| 阶段 | 耗时 (ms) | 占端到端 |
| :--- | ---: | ---: |
| 差分建表（差分开 `n+1` + Python 前缀和循环） | 13.76 | 6.1% |
| **二分循环（44 轮判定）** | 211.90 | **93.9%** |
| 端到端（截图版） | 225.66 | 100% |
| 优化版：仅差分 | 8.58 | — |
| 优化版：单趟解析判定 | 13.62 | — |
| 端到端（优化版） | 15.65 | — |

四档的「二分段占比」分别为 **93.9% / 95.7% / 98.3% / 94.3%** —— 建表那点开销根本不算瓶颈，**时间几乎全在「`log S` 轮 × 一趟顺序扫描」上**。

这里还有一个让二分雪上加霜的结构性事实：判定是**顺序依赖**的（`cur` 只能一步步推），没法向量化；而且**判定成功的那些轮次必须扫满 `n` 个元素** ——「全程无失败」只能在循环结束时才能确认，只有判定失败才可能提前退出。二分的探测点里有多少是「成功型」，取决于答案离上界有多远：

- 答案靠近**下界**（本题 `big` / `covered` 两档答案恰为 0）：绝大多数探测点可行 ⇒ 几乎每轮都扫满 `n`；
- 答案靠近**上界**（`small` 档答案 `275879` ≈ `sum`）：大量探测点不可行 ⇒ 早退变多，单轮更便宜（实测单轮成本 `big` 4.8 ms vs `small` 3.4 ms）。

所以「轮数 × `O(n)`」是二分版真实的工作量量级，而 `log S ≈ 46` 这个因子在本机代价约为 **200 ms 量级**。

### 可优化空间

`P(S)` 的每条约束都能反解成 `S` 的下界（推导见「思路演进」第 5 步），于是**根本不需要搜索**：

- 二分版：`O(n + m)` 建表 + `46 × O(n)` 判定；
- 解析式版：`O(n + m)` 建表 + **`1 × O(n)`** 扫描。

可去成本 = 二分段（93.9%）⇒ 单改动天花板约 `1/(1 − 0.939) ≈ 16×`。实测按四档取 `12.67× / 14.01× / 53.50× / 16.61×`，与天花板同量级。

`covered` 档（53.5×）特别高的原因是**另一个维度**：那一档只有 4 条 `boost`（`m = 4`），于是 `O(n + m)` 的建表段几乎免费（实测仅差分 0.034 ms），优化版只剩「一趟 `O(n)` 判定 ≈ 3.9 ms」；而二分版照样要付 `44 轮 × n`。**「比值」同时受 `n log S` 与 `m` 两个维度影响，看单档会误判优化的普适性。**

优化后剩下的下限是两个 `O(n)` 的 Python 层循环（`big` 档实测）：差分建表 **8.58 ms** + 单趟解析判定 **≈ 5.0 ms**（由「含建表的单趟」13.62 ms 减去建表 8.58 ms 得），合计 13.6 ms 即优化版主循环的耗时（端到端 15.65 ms，余下约 2 ms 是 `sum(monsters)` 等零碎开销）。二者都已是「每元素一次操作」，没有进一步空间。

### 优化代码

**主优化：差分数组 + `O(n)` 解析式。**

```python
class Solution:
    def minInitialStrength(self, monsters: list[int], boosts: list[list[int]]) -> int:
        n = len(monsters)
        d = [0] * (n + 1)                 # 多开一格：承接 r + 1 == n 的区间收尾
        for l, r, v in boosts:
            d[l] += v
            d[r + 1] -= v

        ans = 0                           # 初始强度必须非负
        pre = 0                           # pre_i = monsters[0..i-1] 之和
        bonus = 0                         # 当前下标的临时加成（滚动前缀和）
        for i in range(n):
            bonus += d[i]
            m = monsters[i]
            if m > bonus:                 # 承重条件：bonus >= monsters 时这只怪无约束
                need = pre + m - bonus
                if need > ans:
                    ans = need
            pre += m
        return ans
```

**优化理由**：

- 把「判定」从一个 `O(n)` 的**谓词**变成一个可以**逐项反解**的不等式（`max(0, S - pre_i) >= monsters[i] - bonus[i]`），于是 `S` 的最小可行值就是所有反解下界的 `max`，只需一趟扫描；
- 原本要跑 `46` 遍的判定循环，现在只跑 `1` 遍 —— 这就是全部收益来源（不是常数优化）；
- 顺带省掉了「二分骨架 + `helper` 闭包调用 + `sum(monsters)`」这些零碎开销。

### 常数级优化（可选）

若为了保持「二分答案」骨架的一致性而不换算法，骨架内实测有**两条**稳定收益项（A12 = 内联 `max` + `accumulate` 建表）：

```python
from itertools import accumulate

class Solution:
    def minInitialStrength(self, monsters: list[int], boosts: list[list[int]]) -> int:
        n = len(monsters)
        d = [0] * (n + 1)
        for l, r, v in boosts:
            d[l] += v
            d[r + 1] -= v
        bonus = list(accumulate(d))       # 前缀和交给 C 层

        def helper(mid, bonus):
            for i, j in zip(monsters, bonus):
                if i > mid + j:
                    return False
                mid -= i                  # 取代 max(mid - i, 0)
                if mid < 0:
                    mid = 0
            return True

        left, right = -1, sum(monsters)
        while left + 1 < right:
            mid = (left + right) // 2
            if helper(mid, bonus):
                right = mid
            else:
                left = mid
        return right
```

| ~~`C`：`A123` + 收紧下界哨兵~~ | 0.797 | 0.911 | 0.820 | 0.853 | **比 `A123` 每档都略慢 ⇒ 不采纳**，见下 |

**被证伪：收紧二分下界。** 想用 `L1 = max_i(monsters[i] - bonus[i])`（每个下标都要求 `S >= monsters[i] - bonus[i]`）把 `left` 从 `-1` 提到 `L1 - 1`。它在**语义上是合法**的（`L1 <= 真答案`，故 `L1 - 1` 确实不可行），但**没有收益**：轮数实测 `44 → 44`、`18 → 18`、`44 → 44`、`39 → 38` —— 因为**轮数只取决于 `log(区间长度)`**，而 `L1` 只削掉区间的一小截（`covered` 档 `L1 = 0`、`big` 档 `L1 = 0`，削减量为 0）。代价却是多一趟 `O(n)` 扫描，于是每一档都比 `A123` 慢一点。**教训：`log` 尺度上的「收紧区间」要用对数去估收益，不能看区间被削掉多少比例。**

**被证伪：切尾 `bonus[:n]`。** 理由如上表；四档区间全跨 1.0，且理论上只会多一次 `O(n)` 拷贝。

## 六、易错点与总结

### 易错点

- **【本题最值钱的一条】解析式漏掉 `bonus[i] < monsters[i]` 条件 ⇒ 系统性高估。** 直接把 `max_i(pre_i + monsters[i] - bonus[i])` 当作答案（去掉条件）时，40 组随机用例错 **7** 组；最小反例（`n = 2`，`n = 1` 时该条件恒不产生影响、两种写法同值，故这是最小规模）：

  ```text
  monsters = [5, 6], boosts = [[0, 1, 6]]
  bonus = [6, 6]：两只怪的加成都不小于自身强度 ⇒ 初始强度 0 就能打完，真值 0
  去掉条件后：i=1 时 pre=5，5 + 6 - 6 = 5 ⇒ 错报 5
  ```

  机理：`bonus[i] >= monsters[i]` 意味着**这只怪无关紧要** —— 哪怕当前强度是 0 也能过，所以 `pre_i` 再大都不该被计入。**凡「先算必要条件再取 max」的题，都要单独检查「该条件是否只在某个子集上成立」。**

- **差分数组必须开 `n + 1`**：`d[r + 1] -= v` 在 `r == n - 1` 时落在下标 `n` 上；只开 `n` 会 `IndexError`。
- **`bonus` 只进判定、不进扣血。** 写成 `cur = max(cur + bonus[i] - monsters[i], 0)` 是错的（题面「注意」专门强调了这一点）。
- **二分答案的两个哨兵都要有语义保证**：`left` 必须**确定不可行**（`-1 < 0`）、`right` 必须**确定可行**（`sum(monsters)`，证明见「关键点」）。把 `right` 随手取成 `10^18` 之类虽然也能过，但「为什么可行」就变成了一句空话 —— 若 `monsters[i]` 上界变大，手写的常数上界会先烂掉。
- **别把两族二分的写法混用**：本题 `while left + 1 < right` 配 `left = mid / right = mid`；换成 `left = mid + 1` 一类会破坏「`left` 恒不可行」的不变量（结果差 1），换成 `while left < right` 配 `left = mid` 则**死循环**。
- **跨语言**：`answer` 最大 `5×10^13`（`pre_i + monsters[i]` 量级），`C++` / `Java` 里必须用 64 位整数，`int` 会溢出。

### 题型套路沉淀

- **「区间加 + 单点查」= 差分开 `n+1` + 前缀和**，与本题的两个子问题无关，是识别题面的第一信号（`boosts[j] = [l, r, v]`）。
- **二分答案的通用三步**：① 写清`P(S)`；② 证 `P` 单调（本题靠不变量 `cur_i = max(0, S - pre_i)` 关于 `S` 非减）；③ 取两个语义明确的哨兵。
- **⭐ 更强的通用一步：`P` 单调之后，先问一句「每条约束能不能反解成答案的下界？」** 本题的 `P` 恰好是「一组关于 `S` 的独立必要条件之合取」，于是二分答案退化成一趟 `max`。这个「**二分答案 → 解析式**」的降级通道在其他题里也常见（判据是逐项可加、项与项不耦合），代价是要多花五分钟做一遍反解 —— 收益常常就是去掉一个 `log`。
- 与本题「两段独立」结构同型的题：先做一次**与答案无关**的预处理（差分 / 前缀和 / 排序），再在预处理结果上做一次**与预处理无关**的搜索或扫描。
- **性能结论要分档测**：本题的比值高度依赖「答案离上界有多远」（`covered` 档答案 0、二分判定几乎不早退，比值 53.5×；`small` 档 14.0×）。只报一档会把结论写歪。
