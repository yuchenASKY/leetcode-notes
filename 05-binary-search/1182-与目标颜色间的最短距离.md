# 1182. 与目标颜色间的最短距离

> **难度**：中等
> **标签**：数组 · 二分查找 · 哈希表
> **原题链接**：https://leetcode.cn/problems/shortest-distance-to-target-color/

---

## 一、题目描述

数组 `colors` 中只有 1、2、3 三种颜色。给定若干查询 `[i, c]`，求下标 `i` 到**任意一个颜色为 `c` 的位置**的最短距离（下标之差 `|j - i|`）；若数组中根本没有颜色 `c`，该查询返回 `-1`。

### 示例

```text
示例 1：
输入：colors = [1,1,2,1,3,2,2,3,3], queries = [[1,3],[2,2],[6,1]]
输出：[3,0,3]
解释：
  下标 1 最近的 3 在下标 4（距离 3）
  下标 2 最近的 2 就是它自己（距离 0）
  下标 6 最近的 1 在下标 3（距离 3）

示例 2：
输入：colors = [1,2], queries = [[0,3]]
输出：[-1]
解释：数组里没有颜色 3。
```

### 约束条件

- `1 <= colors.length <= 5 * 10^4`
- `1 <= colors[i] <= 3`
- `1 <= queries.length <= 5 * 10^4`
- `queries[i].length == 2`
- `0 <= queries[i][0] < colors.length`
- `1 <= queries[i][1] <= 3`

## 二、解题思路

### 核心思想

**每种颜色只维护一条「位置递增序列」，查询就退化成"在有序序列里找 `i` 的插入位置，再看左右两个相邻元素谁更近"。**

「最短距离」不需要全局搜索 —— 在有序序列里，离 `i` 最近的位置**必然**是 `i` 的左邻或右邻：往左走越走越远，往右走也一样。

### 思路演进

1. **朴素解法**：对每个查询 `(i, c)` 从头扫一遍 `colors`，收集所有等于 `c` 的下标 `j`，取 `min |j - i|`。时间 **O(n·q)**；`n = q = 5×10⁴` 时内层约 2.5×10⁹ 次操作，必然超时。
2. **瓶颈定位**：内层循环做的是"在颜色 `c` 的位置集合里找离 `i` 最近的那个"。这个集合**只由颜色 `c` 决定、与 `i` 无关**，却被每个查询重新构建了一遍 —— q 次完全重复的枚举。典型的"重复枚举"型瓶颈。
3. **关键转化**：同一个集合被反复查，就把它**预处理好一次**：把每种颜色的下标按遍历顺序 `append` 成一条序列。因为遍历本身就是从左到右，`append` 的顺序 = 下标递增顺序 ⇒ **这条序列天然升序，连 `sort` 都不用做**。一旦有了有序性，「全局最近」立刻坍缩成「局部比较」：取 `k = bisect_right(a, i)`，则 `a[k-1] ≤ i < a[k]`，最近的位置只可能是 `a[k-1]` 或 `a[k]`，其余元素都比它们更远。**原来不行是因为集合无序、只能线性扫；现在行是因为 `append` 白送了有序性。**
4. **最优解**：建表 O(n) + 每次查询一次 `bisect_right`（O(log k)）+ 一次两元素比较。再进一步还能把 log 因子也消掉，见「五、优化评估」方向 2。

### 判据与判据族定位

**判据（一条可判定真假的命题）**：

> 设 `a` = 颜色 `c` 的位置序列（升序），`k = bisect_right(a, i)`。则
> ① `a` 为空（该颜色从未出现）⇒ 答案 `-1`；
> ② 否则答案 = `min(i - a[k-1], a[k] - i)`，其中 `k == 0` 时左侧无元素、`k == len(a)` 时右侧无元素，缺的一侧视为无穷远（只剩另一侧）。

**族定位**：本仓库 `05-binary-search` 下至少有三种判据形态，同族（都靠"有序 ⇒ 可二分"）但**判据不同，不得互相套用**：

| 判据形态 | 二分的是什么 | 答案形态 |
| :--- | :--- | :--- |
| 谓词边界定位 | 满足单调谓词的首/末位置 | 一个下标 / 一个计数 |
| 区间计数 | 值区间两端的定位 | 两个下标之差 |
| **最近邻（本题）** | **插入位置，再看左右相邻两项** | **两个候选距离取 min** |

本题里 `bisect` 的职责**不是**找边界，而是把"全局最近"降成"相邻二选一"——这是它与前两族最本质的区别。载体是「**值 → 有序下标表**」的多路索引（每个颜色一条序列）。

**与滑动窗口无关**：本题没有窗口、没有双指针、没有"收缩"动作，`§3.4 ①~⑫` 的滑窗判据族一律不适用。

### 关键点

- **有序性来自构造方式，不是题面给的**：数组 `colors` 本身毫无顺序可言，是"按遍历顺序 `append`"这一点给了组内递增性 —— 这也是本题能二分的**唯一前提**。
- **一次 `bisect` 同时给出两个候选**：不要写成"找第一个 ≥ i"和"找最后一个 ≤ i"两次二分。`bisect_right` 返回的 `k` 已经同时给出了左邻 `a[k-1]` 与右邻 `a[k]`。
- **`-1` 只可能来自"该颜色从未出现"**，与 `i` 无关：题面保证 `queries[i][1] ∈ [1,3]`，而颜色也只可能是 1/2/3，不存在"颜色值越界"；所以 `-1` 的判据就是"该颜色的位置表为空"。
- 用户代码里的 `if i[1] not in cnt` 正是上面这条判据的落地 —— **它是必要守卫，不是冗余特判**（见「六、易错点」）。

## 三、代码实现

### 最终代码

```python
from collections import defaultdict
from bisect import bisect_right
from typing import List


class Solution:
    def shortestDistanceColor(self, colors: List[int], queries: List[List[int]]) -> List[int]:
        cnt = defaultdict(list)
        for i, j in enumerate(colors):
            cnt[j].append(i)                       # 组内天然升序，无需排序

        ans = []
        for i in queries:
            if i[1] not in cnt:                    # 该颜色从未出现 ⇒ -1
                ans.append(-1)
                continue
            index = bisect_right(cnt[i[1]], i[0])  # 保证 a[index-1] <= i[0] < a[index]
            if index == len(cnt[i[1]]):            # 右侧无元素，只有左邻
                ans.append(i[0] - cnt[i[1]][-1])
            elif index == 0:                       # 左侧无元素，只有右邻
                ans.append(cnt[i[1]][0] - i[0])
            else:                                  # 左右各一个候选，谁近要谁
                ans.append(min(i[0] - cnt[i[1]][index - 1], cnt[i[1]][index] - i[0]))
        return ans
```

> **补全说明**：截图里的代码只有 `class Solution:`，`from collections import defaultdict`、`from bisect import bisect_right`、`from typing import List` 三行是按可运行性补上的（截图里没有）。代码本体与用户截图逐字一致。

## 四、复杂度分析

| 版本 | 时间复杂度 | 空间复杂度 |
| :--- | :--- | :--- |
| **最终代码** | O(n + q·log n) | O(n) |
| 预处理版（五·优化代码 2） | **O(n + q)** | O(n) |
| 朴素解法 | O(n·q) | O(1) |
| 理论下界 | **Ω(n + q)** | O(n) |

> 复杂度中的 **n** 指数组 `colors` 的长度，**q** 指 `queries` 的长度，**k_c** 指颜色 c 的出现次数（`Σ k_c = n`）。
> 更精确地写，最终代码是 `O(n + Σ_查询 log k_c) ≤ O(n + q·log n)` —— 二分的规模是 `k_c ≤ n`，不是 n 本身。
> **下界**：任何算法都必须读完 `n + q` 个输入整数、并写出 q 个答案 ⇒ 时间不可能低于 `Ω(n + q)`。预处理版正好触到这个下界，最终代码则多付一个 log 因子。

## 五、优化评估

**结论**：常数上有**稳定收益**（值域数组，实测快 1.23 ~ 1.56×）；渐进上**log 因子确实可以消掉**（预处理版 O(n + q)，正是本题官方提示的方向），但**并非无条件更优** —— 预处理成本与 q 无关，实测只在 `q` 明显大于 `n` 时才划算。

### 瓶颈分析（阶段归因）

用户版耗时集中在两处：

- **建表**：n 次 dict 查找 + `append`；
- **查询**：每次 1 次 `in` 判定 + 2~4 次 `cnt[c]` 字典查找 + 1 次 `bisect_right`。

**隔离测量**（固定有序表、20 万次调用、5 轮取最优）：单次 `bisect_right` 在表长 3333 时 **139.0 ns**、表长 16667 时 **156.8 ns** —— 对数级增长，二分本身非常便宜。

**拆开归因**：取 S1（n = q = 5×10⁴）与 S2（n = 5×10⁴、q = 100），两者 n 相同 ⇒ S2 里 `A − B` 的差值几乎全是**建表差**：

| 归因项 | 数值 | 占 A−B 总差的比例 |
| :--- | :--- | :--- |
| 建表差（S2：3.046 − 2.364 = 0.682 ms，n = 5×10⁴） | 0.682 ms | 10.5% |
| 查询段差（S1：6.475 − 0.682 = 5.793 ms，q = 5×10⁴） | 5.793 ms ⇒ **116 ns/查询** | 89.5% |

116 ns/查询正好是 **2~4 次 dict 查找**的代价 ⇒ **用户版每轮查询的主要额外开销不是二分本身，而是包在二分外面的重复字典查找**：`if i[1] not in cnt` 查一次，之后 `cnt[i[1]]` 还要再查 2~3 次。

### 可优化空间

**方向 1（常数，推荐采纳）：值域数组替代 `defaultdict(list)`。**

题面白给值域 —— `1 ≤ colors[i] ≤ 3`、`1 ≤ queries[i][1] ≤ 3` ⇒ 直接开 4 条定长 list。收益来自三处：建表不再算哈希；查询侧 `pos[c]` 变成下标访问，`not in` + 索引被压成一次取；"颜色不存在"自然退化成"空列表"，判据仍是 `if not a`。

实测（7 档场景 × 7 轮同轮轮转、取最优）：逐轮比值 **49/49 轮全部 < 1.0，无一轮跨过 1.0** ⇒ 七档一致领先，**1.23 ~ 1.56×**（详细的逐档区间见「七、验证记录」）。

**方向 2（渐进，条件采纳）：把答案整体预计算成表，消掉 log 因子。**

关键观察：**答案只是 `(下标 i, 颜色 c)` 的属性，与其它查询无关**（查询之间毫无耦合）⇒ 可以对每个被查到的颜色做一次「正扫记 `last`、倒扫记 `next`」得到 `dist[i]`，即把"每查询一次二分"换成"每颜色两趟 O(n) 扫描 + 每次查询 O(1)"，总时间降到 **O(n + q)**。这正是本题官方提示的方向（Hint：offline pre-processing / 计算每个下标向左、向右的答案）。

代价是 **每个被查颜色两趟、最多 6n 次 Python 层迭代，且与 q 无关** ⇒ 是否划算要去比 `q × 单次查询开销` 与 `6n × 单次迭代开销`。

实测的**交叉点**（`q/n` 为查询数与数组长度之比）：

| 场景 | n | q | q/n | 预处理版 / 用户版 （逐轮区间） | 判定 |
| :--- | ---: | ---: | ---: | :--- | :--- |
| S7 大 n 少查询 | 5×10⁴ | 5×10³ | 0.1 | 3.182 [2.914 ~ 3.272] | 稳定**更慢** 3.2× |
| S1 全量随机 | 5×10⁴ | 5×10⁴ | 1 | 0.988 [0.936 ~ 1.144] | 跨 1.0，**持平** |
| S3 单色主导 | 5×10⁴ | 5×10⁴ | 1 | 1.009 [0.966 ~ 1.149] | 跨 1.0，**持平** |
| S4 三色交替 | 5×10⁴ | 5×10⁴ | 1 | 0.935 [0.928 ~ 1.247] | 跨 1.0，**持平** |
| S6 中 n 多查询 | 5×10³ | 5×10⁴ | 10 | 0.543 [0.534 ~ 0.643] | 稳定**更快** 1.9× |
| S5 小 n 多查询 | 10³ | 5×10⁴ | 50 | 0.582 [0.562 ~ 0.707] | 稳定**更快** 1.8× |

⇒ **预处理的收益不随 q/n 无限增长，而是饱和在约 1.9×**（S5 与 S6 几乎相同）：因为 q → ∞ 时比值 → `单次查询开销之比 ≈ 0.5`，`6n` 那份固定成本被摊薄到可以忽略。**判据：`q ≳ 10 n` 才值得上预处理，`q/n ≈ 1` 时纯属白折腾，`q/n ≲ 0.1` 是明确的负优化。**

综合起来：**题面上限档（n = q = 5×10⁴）恰好是持平区** ⇒ 本题**推荐保留二分 + 只做值域数组的常数优化**；若数据形态是"数组短、查询多"（q ≫ n），再换预处理版。注意用户代码的二分版在两种形态下都不会超时，方向 2 的收益是"渐进更优 + 特定形态更快"，**不是"不优化就过不了"**。

### 优化代码

**① 推荐采纳：值域数组版（B）**

```python
class Solution:
    def shortestDistanceColor(self, colors: List[int], queries: List[List[int]]) -> List[int]:
        pos = ([], [], [], [])                     # 值域 = 1..3，直接开 4 条 list
        for i, x in enumerate(colors):
            pos[x].append(i)                       # 组内天然升序

        ans = []
        for idx, c in queries:
            a = pos[c]                             # 下标访问，O(1) 且不算哈希
            if not a:                              # 该颜色从未出现
                ans.append(-1)
                continue
            k = bisect_right(a, idx)
            if k == len(a):
                ans.append(idx - a[-1])
            elif k == 0:
                ans.append(a[0] - idx)
            else:
                ans.append(min(idx - a[k - 1], a[k] - idx))
        return ans
```

**优化理由**：题面白给值域 `1..3` ⇒ 用定长数组替掉哈希表，同时把查询侧"`in` 判定 + 索引"两次字典查找压成一次下标访问。"颜色不存在"退化成空列表，判据不变。实测 7 档 × 7 轮 **49/49 轮全部领先**，1.23 ~ 1.56×。

**② 条件采纳：预处理版（P，O(n + q)）**

```python
class Solution:
    def shortestDistanceColor(self, colors: List[int], queries: List[List[int]]) -> List[int]:
        n = len(colors)
        by_color = {}
        for qi, (idx, c) in enumerate(queries):     # 答案只依赖 (idx, c) ⇒ 按颜色分组离线处理
            if c in by_color:
                by_color[c].append((idx, qi))
            else:
                by_color[c] = [(idx, qi)]

        ans = [-1] * len(queries)
        big = 2 * n + 1                             # 哨兵：保证 "不可达" 的距离 > n
        for c, qs in by_color.items():
            dist = [0] * n
            last = -big                             # 正扫：左侧（含自己）最近的颜色 c
            for i in range(n):
                if colors[i] == c:
                    last = i
                dist[i] = i - last
            nxt = big                               # 倒扫：右侧（含自己）最近的颜色 c
            for i in range(n - 1, -1, -1):
                if colors[i] == c:
                    nxt = i
                d = nxt - i
                if d < dist[i]:
                    dist[i] = d                     # 左右取较近者
            for idx, qi in qs:
                d = dist[idx]
                ans[qi] = d if d <= n else -1       # 钳位不可达（颜色 c 从未出现）
        return ans
```

**优化理由**：把"每查询一次二分"换成"每颜色两趟扫描"，总时间 O(n + q)，log 因子消失，触到 `Ω(n + q)` 下界。**但只在 q ≫ n 时划算**（见上表）；`q/n ≈ 1` 时与二分版持平，`q/n ≲ 0.1` 时慢 3.2×，所以**不做无条件替换**。

> ⚠️ 那个 `d <= n` 的钳位**不能省**。删掉它之后：`colors = [1]`、`queries = [[0,2]]` ⇒ 真值 `-1`、实得哨兵值（静默错解，**不抛任何异常**）；随机对拍 40 组里错 9 组。

### 常数级优化（实测被证伪 / 无效）

- ~~把 `bisect_right` 绑定成局部变量 + 用内联 `if` 替代 `min()`~~：**无效**。C 版相对同结构的值域数组版，S1 的逐轮比值为 `0.942 ~ 1.017`（**跨 1.0**），7 档整体无稳定方向 ⇒ 记为"噪声内持平"。
- ~~手写二分~~：**明显更慢**。在查询密集档，手写二分相对**同结构**的值域数组版稳定慢 **2.1 ~ 3.6×**（二分耗时几乎全在 C 层 `_bisect` 里）。
  ⚠️ **一个容易归错因的陷阱**：S2（q = 100）里手写二分版反而比用户版快 0.81× —— 但**那不是手写二分的功劳**，而是它同样用了值域数组（手写二分版/值域数组版 ≈ 1.0）。想量化"手写二分贵多少"必须拿它去比同结构的版本，不能比用户版。

## 六、易错点与总结

### 易错点

- **把 `-1` 的判据理解成"下标越界"**：`-1` 与 `i` 无关（题面保证 `0 ≤ i < n`），它只表示"该颜色从未出现"。用户代码里 `if i[1] not in cnt` 正是这条守卫。
  **删掉它会怎样（静态推导）**：`cnt` 是 `defaultdict` ⇒ `cnt[c]` 会**静默插入一个空列表**；`bisect_right([], i)` 返回 `0`，而 `len([]) == 0` ⇒ 第一个分支 `index == len(...)` 直接成立 ⇒ 执行 `cnt[c][-1]`，对空列表取下标，**抛 `IndexError`**。
- **左右邻写反**：`bisect_right` 之后满足 `a[k-1] ≤ i < a[k]`，所以左邻是 `k-1`、右邻是 `k`。
  附带一条：改用 `bisect_left` 时 `k` 可能指向 `i` 自己（当 `colors[i] == c`），此时 `min` 会取到 0，**答案依然正确** —— 两个函数在本题都能用；但把 `k-1`/`k` 与二分函数搞混（例如用 `bisect_right` 却取 `k+1`）就必错。
- **`a[-1]` / `a[0]` 的安全性来自分支本身**：`index == len(a)` 蕴含 `len(a) > 0`、`index == 0` 蕴含 `len(a) > 0`，所以两个分支里的 `a[-1]`、`a[0]` 都安全；真正防住空表的是前面的 `if not a`，**不是这两个边界分支**。
- **依赖题面保证 `queries[i][1] ∈ [1,3]`**：值域数组版直接写 `pos[c]`，若哪天放开这条约束（颜色变成任意整数），必须先补越界判断；而"空表 ⇒ `-1`"这条判据与值域无关，可以原样沿用。

### 题型套路沉淀

- **「多路索引 + 邻域查询」**：把"按值分组"的下标集合构造成**有序序列**（`append` 即有序，省掉 `sort`），此后"最近 / 相邻 / 排名 / 计数"全部变成「一次 `bisect` + 常数次访问」。同型载体：值 → 下标表、值 → 时间戳表。
- **什么时候该用预处理替掉二分**：当答案只是"被查位置自身的属性"（与其它查询无关）时，可以整体预计算，把 log 因子消掉。**但必须同时看 q/n** —— 预处理成本与 q 无关，q 太小就是纯亏。本题判据：`q ≳ 10n` 才上，`q/n ≈ 1` 持平，`q/n ≲ 0.1` 是负优化。
- **"值域小到是常数"⇒ 用数组替哈希**：题面白给 `≤ 3`、`≤ 26`、`≤ 120` 这类值时，`dict` / `defaultdict` 都该换成定长数组。识别信号是"题面直接给出值域上界"。
- **二分类题只有两个稳定的常数优化方向**：① 减少对 `bisect` 的**调用次数**（预筛、提前返回、一次定位拿到两个候选）；② 换掉**查表方式**（数组替字典、去重复查找）。其余"看起来更聪明"的改写（手写二分、局部绑定、内联 `min`）在本仓库反复实测为**无效或反向**。

### 1. 基准自检（两条互不相干的暴力互查）

- `brute_scan`：定义级 —— 每个查询扫全部下标，取 `min |j - i|`；
- `brute_group`：先按颜色收集下标列表，再取 `min abs(j - idx)`。
- 12 组 tiny 用例（n ≤ 8）互查，**偏差 0 组** ⇒ 基准可信。

### 2. 正确性

| 用例来源 | 组数 | 偏差 |
| :--- | ---: | :--- |
