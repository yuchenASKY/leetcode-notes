# 2604. 吃掉所有谷子的最短时间

> **难度**：困难
> **标签**：数组 · 二分查找 · 双指针 · 排序
> **原题链接**：https://leetcode.cn/problems/minimum-time-to-eat-all-grains/
> **完成状态**：❗ **未做出** —— 本解法不是自己推出来的，卡在"把求最短时间翻成判定问题"这一步，没有想到「给定 T 能否吃完」可以用一遍线性贪心判定。
> **二刷目标**：不看笔记独立写出 `check(t)`，尤其是两个动作 —— ① 超时后把谷子退回去（`j -= 1`）换下一只鸡；② 换鸡时把 `l`、`r` 清零。再自己说出上界为什么取"第 1 只母鸡全包"。

---

## 一、题目描述

一条数轴上有 `n` 只母鸡和 `m` 颗谷子（位置可重复）。母鸡每秒向左或向右移动 1 个单位，各只母鸡同时且独立地移动；母鸡与谷子同位置即视为吃掉，吃的过程不耗时，且一只母鸡可以吃掉任意多颗谷子。若母鸡行动得当，返回吃掉所有谷子的**最短时间**。

### 示例

```text
输入：hens = [3,6,7], grains = [2,4,7,9]
输出：2
解释：
- 第 1 只母鸡在 1 秒内吃掉位置 2 的谷子；
- 第 2 只母鸡在 2 秒内吃掉位置 4 的谷子；
- 第 3 只母鸡在 2 秒内吃掉位置 7 和 9 的谷子。
所以需要的最长时间为 2 秒。可以证明 2 秒之前吃不完。

输入：hens = [4,6,109,111,213,215], grains = [5,110,214]
输出：1
解释：位置 5、110、214 的谷子分别由第 1、4、6 只母鸡各花 1 秒吃掉，其余母鸡不动。
```

### 约束条件

- `1 <= hens.length, grains.length <= 2 * 10^4`
- `0 <= hens[i], grains[j] <= 10^9`

## 二、解题思路

### 核心思想

**二分答案 + 贪心判定。** "最短时间"没法直接构造，但"给定时间 `T`，能否吃完所有谷子"只要一遍线性扫描就能判断，且这个判定关于 `T` 单调 —— 于是把最优化问题翻成判定问题，再对答案二分。

### 思路演进

1. **暴力解法**：直接模拟 —— 枚举每只母鸡先往左还是先往右、各吃哪几颗谷子，在所有方案里取"最大耗时"的最小值。方案数是「谷子的划分方案数 × 每只母鸡的方向选择」，随 `m` 指数增长，而 `m` 可达 `2 * 10^4`，完全不可行。

2. **观察到**：题目要的是"最长耗时的最小值"。这类"最小化最大值"的难点在于**找不到一个能直接构造答案的局部规则**；但反过来问"`T` 秒内能不能吃完"，判断却是局部的 —— 只要给每只母鸡分配一段连续的谷子、检查它的行程是否超过 `T` 即可。而且 `T` 越大判定越容易（可行域是 `[ans, +∞)` 的单调区间），满足二分答案的前提。

3. **关键转化（判定函数怎么写）**：
   - **排序 + 连续段**：`hens`、`grains` 都升序排序。交换论证可知，一定存在一种最优方案，使（按位置顺序）第 `i` 只母鸡负责的谷子恰好是排序后**连续的一段**，且段之间的先后与母鸡的先后一致 —— 让位置更靠左的母鸡去处理更靠左的谷子不会更差。于是判定退化成"从左到右逐只母鸡扫，每只尽量多吃"。
   - **一段谷子的覆盖代价**：设当前母鸡位置为 `h`，它这一轮要覆盖的谷子里最左的距它 `l`、最右的距它 `r`（左侧没有就是 `l = 0`，右侧没有就是 `r = 0`）。走到两端只有两种顺序：
     - 先左后右：`2 * l + r`；
     - 先右后左：`l + 2 * r`。
     取较小者，即 **`cost(l, r) = 2 * min(l, r) + max(l, r)`** —— 先拐短的那一侧，再拐长的那一侧。
   - **贪心推进**：`i` 指向当前母鸡，`j` 指向最左边还没被吃的谷子。每轮先把 `grains[j]` 纳入当前母鸡的行程（在它左侧就更新 `l`，在右侧就更新 `r`），再算 `curT = 2 * min(l, r) + max(l, r)`：
     - `curT <= t`：这颗谷子当前母鸡吃得下，`j` 前进；
     - `curT > t`：超出当前母鸡的能力，**把 `j` 退回去**交给下一只鸡，并把 `l`、`r` 清零、`i` 前进。
   - 扫完之后若 `j == m`，说明所有谷子都被吃掉，`t` 可行。

4. **二分的两个细节**：
   - **上界**：让第 1 只母鸡独吞所有谷子，代价是 `2 * min(left, right) + max(left, right)`，其中 `left = max(hens[0] - grains[0], 0)`、`right = max(grains[-1] - hens[0], 0)`。这一定能做到，所以答案不会超过它。
   - **用 `bisect_left(range(upper), True, key=check)` 代替手写二分**：`bisect_left` 找的是第一个使 `check` 为真的下标；**如果整个区间内没有真值，它返回区间长度本身**（即 `upper`）。而我们的上界恰好就是答案的最大可能取值 —— 所以 `range(upper)` 正好覆盖到答案，不需要写 `upper + 1`，也不需要额外的哨兵判断。

### 关键点

- **判定函数的单调性**：`l`、`r` 只增不减地累积当前母鸡需求的最远左/右距离，`curT` 随之单调不减。这保证了"吃不下就换下一只鸡"这个贪心不会漏掉夹在中间的谷子。
- **`j -= 1` 不能省**：`j` 在分支里已经自增过，超时后必须把它退回，否则这颗谷子会被静默跳过，判定会把"不可行"误报成"可行"。这是本解法最容易写错的一行。
- **换鸡时必须 `l = r = 0`**：否则上一只鸡的行程会污染下一只鸡的 `curT`，导致判定过早失败。
- **排序不可省**：连续段性质和 `j` 的单调推进都依赖有序性。
- `cost = 2 * min(l, r) + max(l, r)` 与常见的 `min(l, r) + l + r` 是同一个式子（按 `l <= r`、`l > r` 分别展开即可验证），前者更直观。

## 三、代码实现

### 最终代码

```python
from typing import List          # 截图里没有、已补
from bisect import bisect_left   # 截图里没有、已补


class Solution:
    def minimumTime(self, hens: List[int], grains: List[int]) -> int:
        hens.sort()
        grains.sort()
        n, m = len(hens), len(grains)

        def check(t: int) -> bool:
            i = j = l = r = 0          # i: 当前母鸡; j: 最左未吃的谷子; l/r: 本轮最远左/右距离
            while i < n and j < m:
                if grains[j] <= hens[i]:
                    l = max(l, hens[i] - grains[j])   # 谷子在鸡的左侧
                    j += 1
                else:
                    r = max(r, grains[j] - hens[i])   # 谷子在鸡的右侧
                    j += 1
                curT = 2 * min(l, r) + max(l, r)      # 覆盖两端所需的最短时间
                if curT > t:
                    l = r = 0                         # 换鸡：本轮行程清零
                    i += 1
                    j -= 1                            # 吃不下，把谷子退回去
            return j == m

        left = max(hens[0] - grains[0], 0)
        right = max(grains[m - 1] - hens[0], 0)
        # 上界 = 第 1 只母鸡独吞所有谷子的耗时；
        # bisect_left 在区间内全为 False 时返回区间长度，恰好正是答案取到上界的情形
        ans = bisect_left(range(2 * min(left, right) + max(left, right)), True, key=check)
        return ans
```

> `bisect_left(..., key=...)` 需要 Python 3.10+，LeetCode 的 Python3 环境满足。

## 四、复杂度分析

| 版本 | 时间复杂度 | 空间复杂度 |
| :--- | :--- | :--- |
| **最终代码** | O(n log n + m log m + (n + m) · log U) | O(1) 额外 |
| 朴素解法（枚举划分 + 方向） | 指数级 | 指数级 |
| 理论下界 | Ω(n + m) | O(1) |

> 复杂度中的 `n`、`m` 分别指母鸡数量 `len(hens)` 与谷子数量 `len(grains)`；`U` 指所有母鸡与谷子位置的最大值（本题 `U <= 10^9`，故 `log U` 约为 30）。
>
> - **排序**：两个数组各一次升序排序，O(n log n + m log m)。
> - **判定**：`check(t)` 的循环每轮要么 `j += 1`、要么 `i += 1`，两者各自最多前进 `m`、`n` 次，所以单次判定严格 O(n + m)。
> - **二分**：答案值域是 `[0, U]` 量级，判定轮数 O(log U)。
>
> 相比指数级的朴素枚举，这里把"枚举分配方案"换成了"枚举答案 + 线性判定"，是本题唯一可行的路线。

## 五、优化评估

**结论**：已是最优，数量级上没有继续下压的空间。

### 瓶颈分析

时间由三块构成：排序、O(log U) 轮判定、每轮判定 O(n + m)。判定这一块无法再降 —— 每颗谷子至少要"看"一次才能确认被吃掉，单轮判定的下界就是 Ω(m)。排序也省不掉：连续段贪心的正确性完全依赖有序性。二分的约 30 轮来自答案值域本身（`U` 达 `10^9`），除非换掉"二分答案"这个框架，否则消不掉。

### 可优化空间

没有数量级上的改进方向。可能的常数级打磨（大 O 不变）：

- 把 `check` 内反复访问的 `hens`、`grains` 绑定为闭包外的局部名 —— 闭包变量走 cell 查找，比外层局部变量稍慢。
- `2 * min(l, r) + max(l, r)` 里的两次内置函数调用可以合并成"一次比较 + 两分支计算"，省掉一次函数调用开销。
- 二分可以手写 `while lo < hi` 取代 `bisect_left` 的 `key` 回调，但可读性会下降。

### 常数级优化（可选）

以上都属于"大 O 不变、常数略小"的范畴。本题的数据规模下，当前写法已经足够快，**不建议为了常数去牺牲可读性**。

## 六、易错点与总结

### 易错点

- **忘记 `j -= 1`**：`j` 在分支里已经自增过，判定超时后必须退回，否则这颗谷子会被跳过，`check` 会误报 `True`。
- **换鸡时忘记重置 `l`、`r`**：下一只鸡的 `curT` 会带着上一只鸡的行程，判定过早失败。
- **覆盖代价只写一半**：只写 `2 * l + r`（或只写 `l + 2 * r`）会漏掉"先拐长的那一侧"这一更优走法，把可行判成不可行。
- **二分上界取小**：上界必须是最坏情况下也一定可行的值。取"第 1 只母鸡全包"是稳妥而且紧的选择。
- **上界与 `range` 的配合**：用 `range(upper)` 时必须清楚"区间内无真值 ⇒ 返回 `upper`"这一点，否则会怀疑漏解。
- **循环退出后统一判定**：`while i < n and j < m` 有两种退出方式，退出后统一用 `j == m` 判断，而不是在循环里提前 `return True`，两种情形才能都处理正确。

### 题型套路沉淀

- **"最小化最大值 / 最短时间"→ 二分答案**：只要"给定 `X` 是否可行"既单调又能线性判定，就把最优化翻成判定问题。判定函数通常就是"一段顺序扫描 + 贪心"。
- **数轴上的覆盖类贪心**：要覆盖 `[h - l, h + r]`（`l, r >= 0`），从 `h` 出发的最小行程 = `2 * min(l, r) + max(l, r)` —— 先拐短的一侧，再拐长的一侧。这个式子是"从某点出发覆盖一段区间"模型里的通用结论。
- **`bisect_left(range(N), True, key=check)` 求最左真值**：当答案上界恰好可取到 `N` 时，用 `range(N)` 即可 —— 区间内没有真值时它返回 `N`，正好等价于答案取到上界。
- **排序 + 顺序分配的交换论证**：证明"最优解可取为连续段、且段与对象顺序一致"是这类匹配问题的标准开场。
