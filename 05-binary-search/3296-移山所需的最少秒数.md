# 3296. 移山所需的最少秒数

> **难度**：中等
> **标签**：二分查找 · 二分答案 · 数组 · 数学
> **原题链接**：https://leetcode.cn/problems/minimum-number-of-seconds-to-make-mountain-height-zero/

---

## 一、题目描述

有 `mountainHeight` 单位高的山，和一批工人 `workerTimes`（工人 `i` 的"单价"）。所有工人**同时**开工，工人 `i` 要把高度降低 `x` 单位，需要 `workerTimes[i] * (1 + 2 + … + x) = workerTimes[i] * x(x+1)/2` 秒（第 `x` 单位最贵，单价是 `workerTimes[i] * x`）。总耗时定义为**任何一个工人花的最大时间**。

问：把整座山降到 0，最少要多少秒？

### 示例

```text
输入：mountainHeight = 4, workerTimes = [2,1,1]
输出：3
解释：工人 0 降 1 单位（2 秒）、工人 1 降 2 单位（1+2=3 秒）、工人 2 降 1 单位（1 秒），
      max(2,3,1) = 3

输入：mountainHeight = 10, workerTimes = [3,2,2,4]
输出：12

输入：mountainHeight = 5, workerTimes = [1]
输出：15      # 1+2+3+4+5
```

### 约束条件

- `1 <= mountainHeight <= 10^5`
- `1 <= workerTimes.length <= 10^4`
- `1 <= workerTimes[i] <= 10^6`

## 二、解题思路

### 核心思想

**二分答案**：把"最少秒数"换成一个**可判定**的问题 —— 「给定 T 秒，所有工人最多能一起砍掉多少高度？」。单工人的贡献有闭式解，判定 O(n)；而 T 越大能砍的总高度越大（单调），于是对 T 二分。

判定谓词（本题的**判据**）：

$$
\text{feasible}(T) \iff \sum_{i} x_i(T) \ge H,
\qquad x_i(T)=\left\lfloor\frac{\left\lfloor\sqrt{8\lfloor T/W_i\rfloor+1}\right\rfloor-1}{2}\right\rfloor
$$

答案 = 最小的可行 T。

### 思路演进

1. **朴素解**：从小到大枚举 T，每个工人照题面从"降 1 单位"开始逐级累加直到超时，统计总降幅是否 ≥ H。
   复杂度 `O(T* · n · √(T*/W))`。问题在于 **T\* 的量级**：`n = 1`、`W = 10^6` 时答案就是 `10^6 · 10^5·10^5/2 ≈ 5×10^15`，一秒一秒试要试到宇宙末日。这条路不是"慢一点"，而是**量级上不可行**。

2. **瓶颈定位**：慢在"**逐秒枚举**"上。但题面里其实藏着一个更好的结构 —— 判定「T 秒够不够」很便宜（O(n)），而"T 越大越可行"是**单调**的。于是要枚举的不是 T 本身，而是**T 的取值区间**。

3. **关键转化**（两件事，缺一不可）：

   **(a) 单工人能力从"逐级累加"换成"闭式解"** —— 从"降到第几单位开始超时"改成"解一个一元二次不等式"。
   工人 `i` 在 T 秒内最多降 `x` 单位，当且仅当 `W_i · x(x+1)/2 ≤ T`。两边同乘 2、移项配方：

   $$
   W_i\,\frac{x(x+1)}{2}\le T
   \iff x(x+1)\le \frac{T}{W_i}
   \iff (2x+1)^2\le \frac{8T}{W_i}+1
   \iff x \le \frac{\sqrt{8T/W_i+1}-1}{2}
   $$

   在整数上取整就是上面判据里的 `x_i(T)`。**这一步把"逐级累加（O(√T)）"压成 O(1)**，是整个解法的地基。

   **(b) 可行集合是"上集"** ⇒ 可以二分。`x_i(T)` 关于 T 单调不减 ⇒ `cap(T) = Σ x_i(T)` 单调不减 ⇒ `{T : cap(T) ≥ H}` 是 `[T*, +∞)`。因此可以用**只有两个端点的哨兵式二分**：

   - 左哨兵 `left`：一个**已知不可行**的值。取 `0`（`H ≥ 1` 时 0 秒砍不掉任何高度）。
   - 右哨兵 `right`：一个**已知可行**的值。取 `(H+1)·H·min(W)/2` —— 把整座山交给**最快**的那个工人单独砍，一定砍得完。
   - 循环 `while left + 1 < right`：区间内只剩 ≥2 个候选时取中点，可行就把可行边界压到 `mid`，否则抬高不可行边界。收敛时 `right` 就是"最小可行值"，即答案。

   > 为什么原来不行、现在为什么行：原来"以 T 为枚举对象"要把 5×10^15 个 T 逐个试；现在**以 T 的区间为枚举对象**，每次砍一半，只需要 `log₂(区间长度) ≈ 52` 轮。

4. **最优解**：即下面「代码实现」中的版本。它已经把渐进的 `log` 因子消掉了 —— **没有更快的渐进解法**（每次判定必须"看过"每一个工人，`cap(T)` 无法用 O(1) 表达）。剩下的是常数空间（见「优化评估」，可以再快 1~65 倍）。

### 关键点

- **两个整数化细节都是精确的、不是近似**：
  - `mid // i`：因为 `x(x+1)` 是**整数**，`x(x+1) ≤ T/W_i ⟺ x(x+1) ≤ ⌊T/W_i⌋`，所以先整除再代入不会漏解。
  - `(isqrt(N) - 1) // 2`：正确的式子是 `⌊(√N − 1)/2⌋`；设 `r = isqrt(N)`，则 `2x+1 ≤ √N ⟺ 2x+1 ≤ r`（`2x+1` 是奇数），最大的那个 `x` 恰好是 `(r-1)//2`。`r` 奇偶两种情况下都对，**不需要 ±1 修正**。
- **两个哨兵都是"承重"的**：`left` 必须真的不可行（写成可行会返回偏大的值）、`right` 必须真的可行（写成不可行会在区间里找不到答案）。`right` 的可行性由"最快工人独自搬完"这条构造性事实保证。
- **早退 `if left_h <= 0: return True`**：判定只关心"总量够不够"，一旦累计到 H 就可以立刻返回，不必扫完所有工人。这一行的收益**取决于 mid 有多大**（见「优化评估」）。
- 平局/边界都不涉及：答案就是最小的整数 T，没有第二关键字。

### 判据与判据族定位

**所属族**：`05-binary-search` 下的「**二分答案**」族（与本目录另一族「下标二分」并列）—— 二分对象是**答案值 T 本身**，不是任何数组的下标。

| 定位项 | 本题 |
| :--- | :--- |
| 二分对象 | 答案值 `T`（秒数） |
| 谓词 | `feasible(T) = (Σᵢ xᵢ(T) ≥ H)`，`xᵢ(T) = ⌊(⌊√(8⌊T/Wᵢ⌋+1)⌋−1)/2⌋` |
| **有序性 / 单调性从哪来** | **来源⑤「谓词的数学性质」**：`xᵢ(T)` 关于 T 单调不减（闭式里 `T` 只出现在 `√(8⌊T/Wᵢ⌋+1)` 的分子上）⇒ `cap(T)` 单调不减 ⇒ 可行集合是 `[T*, +∞)`。**题面没有给任何有序数组**，也不靠"构造方式"或"非负前提" |
| 区间端点 | **先验哨兵**：`left = 0`（`H ≥ 1` ⇒ 0 秒必然不可行）、`right = (H+1)·H·min(W)/2`（最快工人独自搬完 ⇒ 必然可行） |
| 收缩写法 | `while left + 1 < right` + `left = mid` / `right = mid`（**不带 ±1**） |
| 答案口径 | 收敛后的 `right`（最小可行值） |

**与相邻族的差别（不可互抄）**：

- 与「**下标二分**」（谓词边界定位 / 区间计数 / 最近邻三种形态）的差别：那一族的单调性来自"被查结构自身有序"、"构造方式（`append` 顺序）"或"题面前提"，端点用**数组边界**、答案取"某个**位置**"；本题二分的是**值**，端点用**先验哨兵**（`left` 的值本身从不参与判定），答案取"最小的可行值"。
- 与同族"谓词边界落在序列上"的形态也不一样：本题不是"找第一个满足的位置"、不是"值区间计数"、也不是"最近邻"，判据是**总量是否达到下界**（`≥ H` 型可行性）。
- **§3.4 的滑动窗口判据族（①~⑫）对本题一律不适用** —— 那是"一端固定、另一端单调推进 + 窗口内部状态"的模型，本题连窗口都没有。

**两种完整骨架都对，但不能各取一半**（本题 64 组对拍实测）：`while left+1<right` + `left=mid`（哨兵式）与 `while left<right` + `left=mid+1`（闭区间式）**各自 0/64 偏差**；混成"哨兵式循环 + `left = mid + 1`"偏 **11/64**（最小反例即官方示例 1：真值 3、实得 4），混成"闭区间式循环 + `left = mid`"**64/64 全部死循环**。

## 三、代码实现

### 最终代码

```python
from math import isqrt
from typing import List


class Solution:
    def minNumberOfSeconds(self, mountainHeight: int, workerTimes: List[int]) -> int:
        def helper(mid):
            left_h = mountainHeight
            for i in workerTimes:
                left_h -= (isqrt(mid // i * 8 + 1) - 1) // 2
                if left_h <= 0:
                    return True
            return False

        left = 0
        right = (mountainHeight + 1) * mountainHeight * min(workerTimes) // 2
        while left + 1 < right:
            mid = (left + right) // 2
            if helper(mid):
                right = mid
            else:
                left = mid
        return right
```

> **截图补全说明**：原截图只有 `class Solution:` 及其内部，`from math import isqrt` 与 `from typing import List` 是本次补上的（否则代码在本地跑不起来；`List` 在 LeetCode 的 Python3 模板里由题目自带）。截图**未被裁切** —— 用 Pillow 裁出编辑器行号列放大直读，共 20 行、末行 `return right`、其下为空白区，行号列信息与实际行数一致。

## 四、复杂度分析

> 下表中 **n = `workerTimes.length`（工人数）**，`H = mountainHeight`，`Wmax = max(workerTimes)`，`R = right − left`（二分区间长度）。

| 版本 | 时间复杂度 | 空间复杂度 |
| :--- | :--- | :--- |
| **最终代码（用户版）** | `O(⌈log₂ R₀⌉ · n)`，`R₀ = (H+1)H·min(W)/2`，最坏 ≈ 52 轮 | `O(1)` 额外空间 |
| 推荐优化版（§五 G） | `O(n + ⌈log₂(U−L)⌉ · m)`，`m` = 不同取值个数（≤ n），实测 4 ~ 36 轮 | `O(n)`（Counter / 排序副本） |
| 朴素解法（枚举 T，逐级累加） | `O(T* · n · √(T*/W))`，`T*` 可达 `5×10^15` | `O(1)` |
| 理论下界 | `Ω(n)` —— 至少要读入全部 `workerTimes`；每次判定都必须"看过"每个工人（`cap(T)` 无 O(1) 表达） | `Ω(1)` |

- `n` 很小时（如 `n = 1`，52 轮 × 1 个元素 = 53 次访问）二分轮数虽多，代价仍是瞬间；**轮数多 ≠ 慢**，见 §五 的插桩表。
- 本题 `H ≤ 10^5`、`Wmax ≤ 10^6` ⇒ 最坏一轮判定 O(10^4)，最坏总访问 ≈ 52 × 10^4 = 5.2×10^5 次 `isqrt` 级运算 ⇒ Python 下也就是几十毫秒，**原版直接 AC 绰绰有余**。这说明"优化"在本题是**泛化到任意 n 的研究**，不是"不优化会 TLE"。

## 五、优化评估

**结论**：渐进上已最优（`log` 因子消不掉），但有 **1 ~ 65 倍**的常数空间，且收益完全由**输入结构**决定。

### 瓶颈分析

二分答案这类题的成本可以精确写成两段：

$$
\text{总耗时} \approx \text{轮数} \times \text{单轮判定的代价}
$$

本题恰好**两条腿都能压**，而且两条腿的开关互不相同：

| 杠杆 | 怎么压 | 生效条件 | 实测最大收益 |
| :--- | :--- | :--- | :--- |
| 轮数 | 用**解析双界**替换"0 ~ 单工人界" | 答案远小于单工人界 | 52 → 5 轮 |
| 单轮代价 | **按值聚合**：`Σ f(T,W_i)` ⇒ `Σ c_w · f(T,w)` | 工人取值有重复 | 289710 → 24 次访问 |
| 单轮代价 | **`w > mid` 跳段**（升序 + break） | 迭代中出现 `mid < W_i`（即 `left < Wmax`） | 200000 → 20 次访问 |

**基准都是量出来的、不是估的**（下表与插桩表取自同一次 9 轮轮转运行）。

### 三条优化的推导与实测

#### ① 解析双界（BND）：用连续松弛把区间夹到"常数倍"宽

记 `S = Σ_i 1/√W_i`，则对任意 T：

- **上界**（单工人能力 ≤ 连续解）：`x(x+1)/2 ≤ T/W ⟹ x² < x(x+1) ≤ 2T/W ⟹ x_i(T) < √(2T/W_i)`
  ⟹ `cap(T) < √(2T)·S`。于是 **`T < H²/(2S²)` 时 `cap(T) < H`，必然不可行** ⇒ 这是答案的**下界**。
- **下界**（由 x 的极大性反推）：`(x+1)(x+2)/2 > T/W ⟹ T/W < (x+2)²/2 ⟹ x_i(T) > √(2T/W_i) − 2`
  ⟹ `cap(T) > √(2T)·S − 2n`。于是 **`T ≥ (H+2n)²/(2S²)` 时 `cap(T) > H`，必然可行** ⇒ 这是答案的**上界**。

两个界都取"与用户版右哨兵取交"：

```python
left  = max(0,      int(H*H / (2*S*S)) - 3)
right = min((H+1)*H*min(W)//2,  int((H+2*n)**2 / (2*S*S)) + 3)
```

- `-3 / +3` 是**给浮点误差留的余量**。实测 272 组输入 × 两侧 = 544 次断言，margin 取 0 / 1 / 2 / 3 全部零违反 ⇒ 推导本身够稳，余量只是防身。
- `min` 那一步不能省：`H` 小而 `n` 大时（如 `H = 1`、`n = 10^4`）解析上界 `(1+2n)²/(2S²)` 会**大于**"单工人界"，此时用用户版的原界更紧。

**轮数与区间的实测对比**（`n = 10^4`）：

| 场景 | 用户版 right | 解析双界 [left, right] | 轮数（上界口径） |
| :--- | ---: | :--- | ---: |
| uniform_slow（全 `10^6`） | 5.0×10^15 | [5.0×10^7, 7.2×10^7] | 52.2 → 24.4 |
| uniform_fast（全 `1`） | 5.0×10^9 | [47, 75] | 32.2 → 4.8 |
| mixed（一半 1、一半 10^6） | 5.0×10^9 | [196, 290] | 32.2 → 6.6 |
| all_distinct | 5.0×10^9 | [1.15×10^7, 1.66×10^7] | 32.2 → 22.3 |
| single（`n = 1`） | 5.0×10^15 | [5.0×10^15, 5.00005×10^15] | 52.2 → 35.5 |
| tiny_H（`H = 1`） | 10^6 | [0, 10^6] | 19.9 → 19.9（双界无处可收） |

⚠️ **单独用双界并不总是赚，甚至可以反向**：`smallH_narrow`（`H = 1000`、`W ∈ [1,10]`）档实测 **1.67×（1.60 ms → 2.68 ms，逐轮比值 [1.07~2.16] 全部 > 1）**。机理很清楚：用户版从"很大的 mid"起步，几秒内累计就超过 H、**早退立刻生效**（该档总访问仅 14660 次）；双界把 mid 直接压到答案附近（`mid ≤ 10`），此时 `mid // w` 大量为 0、累计永远够不到 H ⇒ **每一轮都扫满 n**。⇒ **收紧区间砍掉的是"便宜轮"，留下来的是"贵轮"**，这与"轮数减半 ⇒ 耗时减半"的直觉相反。

#### ② 按值聚合（AGG）：把 `n` 换成"不同取值个数"

判定式 `Σ_i x_i(T)` 只依赖 `(T//W_i, 该取值的工人数)`，所以把工人按 `W` 归并成 `(w, c)`，判定变成 `Σ c · x(T,w)`。复杂度从 `O(n)` 降到 `O(distinct)`。**收益完全由重复度决定**（同一次运行内 EAGG / EBRK，7 轮取最优）：

| distinct / n | EBRK (ms) | EAGG (ms) | 比值 | 逐轮区间 |
| ---: | ---: | ---: | ---: | :--- |
| 1 (0.00n) | 6.22 | 1.45 | **0.23×** | 全 < 1 |
| 10 (0.00n) | 10.18 | 1.50 | **0.15×** | 全 < 1 |
| 100 (0.01n) | 13.56 | 1.59 | **0.12×** | 全 < 1 |
| 1000 (0.10n) | 18.35 | 3.75 | **0.21×** | 全 < 1 |
| 2460 (0.25n) | 17.77 | 6.41 | 0.36× | 全 < 1 |
| 4280 (0.43n) | 18.52 | 11.03 | 0.60× | 全 < 1 |
| 5744 (0.57n) | 21.35 | 16.43 | 0.77× | 全 < 1 |
| 6302 (0.63n) | 20.70 | 17.36 | 0.84× | 跨 1 |
| 7148 (0.71n) | 21.05 | 20.08 | 0.95× | 全 < 1（贴线） |
| 7852 (0.79n) | 22.42 | 23.92 | 1.07× | 全 > 1 |
| 8541 (0.85n) | 23.47 | 26.56 | 1.13× | 跨 1 |
| 9211 (0.92n) | 25.35 | 30.75 | 1.21× | 全 > 1 |

⇒ **交叉点约在 `distinct ≈ 0.7n`**（`n = 10^4`、取值均匀分布时）。`distinct ≈ n` 时聚合版慢 **21%**（多一趟 `Counter`、以及每轮多一次 `c *` 乘法/元组解包）。这与"每值建一个容器"那类按值分配型优化不同 —— 这里只建一张表，**不会在"值域 ≈ n"档出现数量级反转**，但确实会稳定地小幅反向。

#### ③ `w > mid` 跳段（BRK）：只在 `mid < Wmax` 时才有意义

`x_i(T) = 0 ⟺ T < W_i`。把 `workerTimes` 升序排好，一旦 `w > mid` 就可以 `break`（后面的只会更大、贡献全是 0）。它的**生效前提**是迭代中真的会出现 `mid < w`：

- 用户版区间从 0 起步、右端极大 ⇒ 早期 mid 很大 ⇒ 不触发；但一旦 `H` 小（答案落在低位）就有大量 mid 小于大部分 `W`，此时收益极大：`tiny_H` 档 **0.05×**、`smallH_wide` 档 **0.16×**。
- 反过来，`mid ≥ Wmax` 恒成立的档（`pool2500`、`all_distinct`）它是**纯开销**：多一个排序 + 每轮一次比较，实测 1.02× ~ 1.16×。
- ⇒ 用开关 `brk = (left < max(W))` 控制：**它写错只影响速度，不影响正确性**（跳过的是贡献为 0 的工人，对求和无影响）。

### 优化代码（推荐版 G）

两个开关正交，四个组合各有用武之地：

```python
from math import isqrt, sqrt
from collections import Counter
from typing import List


class Solution:
    def minNumberOfSeconds(self, mountainHeight: int, workerTimes: List[int]) -> int:
        H = mountainHeight
        W = workerTimes
        n = len(W)
        _isqrt = isqrt

        # --- 解析双界：S = Σ 1/√W_i ---
        S = 0.0
        for w in W:
            S += 1.0 / sqrt(w)
        left = max(0, int(H * H / (2.0 * S * S)) - 3)
        right = min((H + 1) * H * min(W) // 2,
                    int((H + 2 * n) ** 2 / (2.0 * S * S)) + 3)

        brk = left < max(W)                    # 开关一：区间内是否可能出现 w > mid

        if len(set(W)) * 5 <= n * 3:           # 开关二：重复度是否足够高（≤ 0.6n）
            items = sorted(Counter(W).items()) if brk else list(Counter(W).items())

            if brk:
                def cap(mid):
                    s = 0
                    for w, c in items:
                        if w > mid:
                            break
                        s += c * ((_isqrt(mid // w * 8 + 1) - 1) // 2)
                        if s >= H:
                            return True
                    return False
            else:
                def cap(mid):
                    s = 0
                    for w, c in items:
                        s += c * ((_isqrt(mid // w * 8 + 1) - 1) // 2)
                        if s >= H:
                            return True
                    return False
        else:
            ws = sorted(W) if brk else W

            if brk:
                def cap(mid):
                    s = 0
                    for w in ws:
                        if w > mid:
                            break
                        s += (_isqrt(mid // w * 8 + 1) - 1) // 2
                        if s >= H:
                            return True
                    return False
            else:
                def cap(mid):
                    s = 0
                    for w in ws:
                        s += (_isqrt(mid // w * 8 + 1) - 1) // 2
                        if s >= H:
                            return True
                    return False

        while left + 1 < right:
            mid = (left + right) // 2
            if cap(mid):
                right = mid
            else:
                left = mid
        return right
```

**优化理由**：三个杠杆各自独立（轮数 / 不同值个数 / 每轮跳段），且都由输入结构决定是否生效；用两个 O(n) 的探测（`max(W)`、`set(W)`）决定走哪条路，探测成本远低于走错路的代价。

### 被证伪 / 被排除的改法

- 把 `isqrt` 绑定成局部变量（AL）：11 档里 10 档逐轮比值**跨 1.0**，唯一"全<1"的是 `single` 档（0.02 ms 量级，纯噪声）⇒ **判为噪声内持平，不采纳**。（Python 3.11+ 的 `LOAD_GLOBAL` 已做过缓存，这类绑定带来的收益远小于那个一秒钟的 `if` 判断。）
- 单独使用解析双界（E）：在 `smallH_narrow` 档**反向 1.67×**（逐轮区间 [1.07~2.16] 全 > 1），机理见上文 ① ⇒ 双界必须与"每轮更便宜的判定"配套使用。
- 单独使用按值聚合（EAGG）：在 `all_distinct` 档 **1.23×**（多一趟 Counter + 每轮乘法） ⇒ 必须用重复度探测挡住。
- 单独使用跳段（EBRK）：在 `mid ≥ Wmax` 恒成立的档是纯开销 ⇒ 必须用 `left < max(W)` 挡住。

> 顺带记一条**紧凑写法**的实测（与展开版同轮轮转、9 轮取最优）：把四路展开改写成"每轮多判一个 `brk` 标志"的紧凑版，代码短约 20 行；11 档里 9 档与展开版的差异 ≤ 5%，`pool7000`、`all_distinct` 两档分别慢约 8%（绝对量 19.06 vs 17.67 ms、27.98 vs 25.79 ms）。两版任选，本次推荐展开版（每轮少一次标志判断）。

### 三条替代路线在本题的适配性（逐条排除，附依据）

| 路线 | 在本题是否成立 | 依据 |
| :--- | :--- | :--- |
| **值域桶 + 前缀 / 后缀和**（消掉 log 因子） | ❌ **前提不成立** | 它省的是"每次查询的 log 因子"，收益 ∝ 查询次数；本题的"查询"只有 `log₂(区间)` 次（几十次），而判定**本身就是 O(n) 求和**，压根没有可换的 `O(1)` 查询。且 `Wᵢ ≤ 10^6` ⇒ 实测建一张 `V = 10^6` 的表，"分配 + 扫一遍"就要 **59.1 ms**（分配 1.71 ms、扫 56.5 ms、计数 10^4 次 0.94 ms），已超过全互异档整题耗时（~26 ms） |
| **双指针差分替代 `bisect`** | ❌ 无从替换 | 本题判定里**没有 `bisect`**（判据是逐元素代入闭式再求和），不存在"用两趟 O(n) 扫描换 2n 次 C 层调用"的对象 |
| **预处理替代二分**（答案与查询无关时一次填好） | ❌ 无查询量可摊 | 前提是"答案只是被查结构的**下标属性**、且会被问很多次"；本题答案是 `(H, W)` 的函数、只被问一次 |
| **手写循环 vs `bisect`**（§3.7 ⑦ ①） | 手写循环在此**必需** | 二分区间是先验哨兵构成的 `[0, R]`、谓词不落在任何数组上 ⇒ `bisect` 无法表达。判定里唯一可 C 层化的候选是 `Σxᵢ`，但每项都要过 `isqrt` + 整除，`map` / `sum` 没有快速路径 ⇒ 本题的常数优化只能从**减少项数**（聚合 / 跳段）入手 |

## 六、易错点与总结

### 易错点

1. **`mid // i` 的位置**：写成 `mid // (i * 8)` 或 `mid * 8 // i` 都不对（前者丢精度、后者在 `mid*8` 上没区别但容易被 `//` 的结合顺序绕晕）。正确形式是 `mid // i * 8 + 1`，即"先整除、再乘 8、再 +1"。左结合让它恰好等于 `8·⌊T/W⌋ + 1`。
2. **`(isqrt(N) - 1) // 2` 不要画蛇添足**：这里**不需要**任何 ±1 修正（`2x+1` 是奇数这一事实已经兜住了 `r` 的奇偶）。
3. **两种完整骨架都对，但不能各取一半**（本题 64 组对拍）：`while left+1<right` + `left=mid`（哨兵式）与 `while left<right` + `left=mid+1`（闭区间式）各自 **0 偏差**；混成"哨兵式循环 + `left = mid + 1`"偏 **11/64**（最小反例就是官方示例 1：`H=4, W=[2,1,1]` 真值 3、**实得 4**），混成"闭区间式循环 + `left = mid`"**64/64 全部死循环**（步数上限保护下确认）。⇒ 选一种写到底，别各抄一半。
4. **左哨兵必须真的"不可行"**：把 `left` 换成"看起来合理"的紧值 `max(W) - 1`，64 组里偏 **15** 组，最小反例 `H=4, W=[2,8,13]` 真值 12、**实得 13**，**全程不抛异常**（`left` 本身已经可行 ⇒ "答案在 `(left, right]`"的不变量塌掉）。本题取 `left = 0`（`H ≥ 1` 保证不可行）、推荐版取解析下界（已逐组断言不可行）。
5. **右哨兵必须真的"可行"**：把 `right` 减 1（`(H+1)H·min(W)/2 - 1`）即不再是可行值，64 组里偏 **23** 组，最小反例 `H=5, W=[1]` 真值 15、**实得 14** —— 这类档恰好是"答案 == 右界"（`n = 1` 时右界就是答案）。⇒ 右界的可行性不是形式主义。
6. **判定写严格 `>` 属低危型**：`Σxᵢ ≥ H` 写成 `Σxᵢ > H` 时 64 组偏 **29** 组，但**官方示例 2 就能拦住**（真值 12、实得 18）⇒ 官方示例是最便宜的一道网，这类错误不必额外堆用例。
7. **删掉早退不改变正确性**：去掉 `if s >= H: return True` 后 64 组**零偏差** ⇒ 它买的是速度（大 mid 时几秒内就能返回）而不是正确性 —— 写笔记/改代码时要把它记成**常数优化**，别当成"承重逻辑"。
8. **不要在 `H` 很小时低估"区间紧"的代价**：`smallH_narrow` 那个 1.67× 的反例说明，**收紧区间会同时去掉早退的机会**；判定越便宜，收区间的相对收益越小。
9. **`break` 型优化必须挂在"贡献为 0"这个判据上**：`x_i(T) = 0 ⟺ mid < W_i`，所以要先排序。若误写成 `w >= mid` 或漏排序，会**少算正贡献**（不是崩溃，是静默错解）。

### 题型套路沉淀

- **二分答案的成本模型 = 轮数 × 单轮判定的代价**，两条腿要分开优化，而且要分开归因：本题 `uniform_slow` 档**只压轮数**（双界 E）是 0.85×（轮数 52 → 24，少一半多，耗时只少 15%）；**只压单轮代价**（聚合 EAGG）是 0.04×（快 23 倍）。
- **"收紧二分区间"要用对数估收益**：轮数 = `log₂(区间长度)`，从 `5×10^15` 收到 `2×10^7` 只省 `log₂` 的常数倍；但在 `n` 大、答案小时它能把"扫满 n 的轮数"从几十轮压到几轮。
- **改判定式之前先问"它依赖哪些重复信息"**：`Σ_i f(T, W_i)` 只要按值聚合就能把 `n` 换成 `distinct`；这条手法对一切"逐元素代入同一个函数再求和"的判定都成立。**但收益 ∝ 重复度**，必须探测后走（本题交叉点 ≈ `0.7n`）。
- **"跳过贡献为 0 的元素"是二分答案里的通用剪枝**：先找到"什么时候贡献为 0"（本题是 `mid < W_i`），再花一次排序把它变成一段可跳过的后缀。收益取决于**那段后缀占多长**（本题取决于 `left` 与 `Wmax` 的相对大小）。
- **判定的"早退"不是白给的**：本题 `if s >= H: return True` 的收益 ∝ 累计到 H 的速度，而速度 ∝ 当前 mid。所以**轮数与单轮代价是耦合的** —— 任何"只改区间"的优化都必须重新测。
