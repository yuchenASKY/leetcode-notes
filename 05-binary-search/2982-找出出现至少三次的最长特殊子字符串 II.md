# 2982. 找出出现至少三次的最长特殊子字符串 II

> **难度**：中等
> **标签**：字符串 · 二分查找 · 滑动窗口 · 哈希表
> **原题链接**：https://leetcode.cn/problems/find-longest-special-substring-that-occurs-thrice-ii/

## 一、题目描述

给定一个小写字母字符串 `s`。称**仅由单一字符组成**的字符串为「特殊字符串」（如 `"ddd"`、`"zz"`、`"f"` 是，`"abc"` 不是）。

要求返回在 `s` 中作为子串**出现至少三次**的最长特殊字符串的长度；若不存在这样的特殊子串，返回 `-1`。这里「出现」按**不同位置**计次，内容相同的两次子串算两次。

### 示例

```text
输入：s = "aaaa"
输出：2
解释：长度为 2 的特殊子串 "aa" 在 s 中出现三次（下标 [0,1]、[1,2]、[2,3]）；
      长度 3 的 "aaa" 只出现两次，故答案是 2。

输入：s = "abcdef"
输出：-1
解释：每个字符都只出现一次，凑不出出现三次的特殊子串。

输入：s = "abcaba"
输出：1
解释："a" 出现三次，长度 2 的特殊子串（"aa"、"bb"、"cc"）都不存在，故答案是 1。
```

### 约束条件

- `1 <= s.length <= 5 * 10^4`
- `s` 仅由小写英文字母组成

---

## 二、解题思路

### 核心思想

**答案关于长度具有单调性，于是可以二分答案。** 谓词 `check(k)` = 「存在某个字符 `c`，使长度为 `k` 的特殊子串 `c^k` 在 `s` 中出现 ≥ 3 次」。若 `k` 可行，则 `k-1` 必然也可行（同一个字符的同一个块里，短一个字符的子串出现次数只会更多），因此可行区间是前缀 `[1, k_max]`，二分即可。

### 思路演进

1. **暴力解法**：枚举所有起点 `i` 与长度 `len`，取出 `s[i:i+len]` 判断是否单一字符，用哈希表把「内容 → 出现次数」累加起来，最后在次数 ≥ 3 的键里取最长。子串总数 O(n²)，n = 5×10^4 时是 2.5×10^9 量级，必然超时。

2. **观察到**：特殊子串完全由「**连续相同字符块**」（游程）决定。把 `s` 切成长度不一的块 `(c, L)`；对某个块，长度恰为 `k` 的 `c^k` 在该块内出现 `L - k + 1` 次（`L < k` 时为 0）。于是同一个 `c^k` 在整串中的总出现次数，就是所有 `c` 的块贡献之和。

3. **优化为**：既然「长度 `k` 是否可行」可以一次线性扫描判掉，就不必枚举子串。扫描 `s` 时维护「**以当前下标结尾的连续相同字符长度** `ans`」：只要 `ans >= k`，当前位置就是一个 `c^k` 的结束位置，给 `cnt[c]` 加一。某字符计数达到 3 即可提前返回 `True`。这一步恰好等价于 `Σ max(0, L - k + 1)`，把「块内多个起点」自然地算进去了。

4. **最终**：`k` 的单调解锁二分。区间取 `[0, n-1]`，用「保持 `left` 为可行点、`right` 为不可行点」的收缩写法二分最大的可行 `k`。

### 关键点

- **单调性方向**：`check(k)` 真 ⇒ `check(k-1)` 真。原因是同一块内的子串数量随长度递减（`L-k+2 > L-k+1`），长度越短越容易凑够 3 次。这是二分合法的前提。
- **下界哨兵 `left = 0`**：`check(0)` 并**不保证**为真（如 `s = "abcdef"` 时没有任何字符出现 3 次）。因此 `left` 停在 0 就等于「无解」，返回时用 `-1 if left == 0 else left` 把这一情形区分出来。
- **计数口径是「≥ k」而不是「== k」**：不能只统计「块长恰好为 k」的块，那样会漏掉长块内部的多个起点 —— `ans >= num` 才是正确的判断。
- **首字符要单独处理**：`i == 0` 时 `s[i-1]` 会变成 `s[-1]`（Python 负索引），若不加 `continue` 会把首字符误判成「与前一字符不同」。

## 三、代码实现

### 最终代码

```python
from collections import defaultdict  # 截图里没有，已补


class Solution:
    def maximumLength(self, s: str) -> int:
        n = len(s)

        def check(num: int) -> bool:
            cnt = defaultdict(int)
            ans = 0                      # 以当前下标结尾的连续相同字符长度
            for i, j in enumerate(s):
                ans += 1
                if i == 0:               # 首字符没有前驱，单独处理
                    if ans >= num:
                        cnt[j] += 1
                    continue
                if j != s[i - 1]:        # 游程断开，重新计数
                    ans = 1
                if ans >= num:           # 当前位置是一个 j^num 的结束位置
                    cnt[j] += 1
                    if cnt[j] == 3:      # 够三次即可提前收工
                        return True
            return False

        left = 0                         # 下界哨兵：停在 0 表示无解
        right = n - 1                    # 上界：长度 n-1 必然凑不满 3 次
        while left + 1 < right:
            mid = (left + right) // 2
            if check(mid):
                left = mid
            else:
                right = mid
        return -1 if left == 0 else left
```

## 五、优化评估

**结论**：当前 O(n log n) 时间、O(1) 空间，在 n = 5×10^4 的规模下余量充足，不需要再压。

### 瓶颈分析

时间全部花在 `check` 上：每轮要完整扫一遍字符串（O(n)），二分共 O(log n) 轮，两者相乘即 O(n log n)。空间上没有任何随 n 增长的容器 —— 计数表键数上限是字母表大小 26，扫描只用一个游程长度变量。

### 可优化空间

本题的时间下界是 Ω(n)：答案依赖整个字符串，任何算法都至少要读一遍输入。当前复杂度与下界之间只差一个 O(log n) 的因子，而这个因子完全来自「二分多少轮就要重扫多少遍」这一二分答案的固有结构。若把二分框架保留，这一项无法消除；是否改用别的结构来规避重扫，属于另一条解法路线的取舍，本笔记不展开。

## 六、易错点与总结

### 易错点

- **返回值写成 `left`**：`check(0)` 不一定为真，无解时 `left` 会停在 0，直接返回 `left` 会错误地输出 `0` 而不是 `-1`。
- **只统计「块长恰好为 k」**：长块内部含有 `L - k + 1` 个长度为 `k` 的子串，必须用 `ans >= num` 累加，否则 `"aaaa"` 这类用例会算少。
- **忘记处理 `i == 0`**：靠 `s[i - 1]` 判游程是否断开时，首字符会取到 `s[-1]`，导致第一个字符的游程被误置为 1。
- **边界无解**：`n < 3` 时循环不进入，`left` 保持 0 —— 这正好是正确答案 `-1`，但前提是返回值里保留了 `left == 0` 的判断。
- 单调性用反：可行区间是长度的**前缀**（短的容易），因此二分要找的是「最后一个可行的 k」，收缩时可行就抬 `left`、不可行才压 `right`。

### 题型套路沉淀

- **「最长 / 最短 + 某性质单调」→ 二分答案**：先把原问题改写成布尔谓词 `check(k)`，再确认真值区间是前缀（或后缀），最后套「保持一端为真、一端为假」的收缩模板。
- **二分答案的固定骨架**：① 定义 `check` 并确定它是 O(n) 级的单次扫描；② 起止区间取「一个必然可行 + 一个必然不可行」；③ 用 `left + 1 < right` 收敛，退出时 `left` 即答案；④ 下界哨兵不保证可行时，用哨兵值区分「答案为 0」与「无解」。
- **特殊子串 / 游程类问题**：把字符串按「连续相同字符块」压缩，很多性质只在块内变化，块长 `L` 对长度 `k` 的贡献是 `max(0, L - k + 1)`。与之对照，本题的 I 版本数据范围小，直接枚举子串即可通过。
