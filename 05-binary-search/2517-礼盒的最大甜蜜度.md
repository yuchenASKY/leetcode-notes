# 2517. 礼盒的最大甜蜜度

> **难度**：中等
> **标签**：数组 · 排序 · 二分查找 · 贪心
> **原题链接**：https://leetcode.cn/problems/maximum-tastiness-of-candy-basket/

---

## 一、题目描述

给定一个正整数数组 `price`（`price[i]` 是第 `i` 类糖果的价格）和一个正整数 `k`，从这些糖果里挑出 `k` 类**不同**的糖果装成礼盒。礼盒的**甜蜜度**定义为礼盒内任意两种糖果价格绝对差的**最小值**。

要求返回所有选法中能得到的**最大甜蜜度**。

换句话说：在 `price` 中选 `k` 个下标，使得「两两价格差的最小值」尽量大。

### 示例

```text
示例 1：
输入：price = [13,5,1,8,21,2], k = 3
输出：8
解释：选 [5,13,21]，甜蜜度 = min(8, 8, 16) = 8。

示例 2：
输入：price = [1,3,1], k = 2
输出：2
解释：选 [1,3]，甜蜜度 = |1-3| = 2。

示例 3：
输入：price = [7,7,7,7], k = 2
输出：0
解释：任取两类，价格差都是 0。
```

### 约束条件

- `2 <= k <= price.length <= 10^5`
- `1 <= price[i] <= 10^9`

---

## 二、解题思路

### 核心思想

**先把「求最大值」变成「判定某个值行不行」，再对这个值二分。**

甜蜜度只取决于所选价格组成的集合，把 `price` 排序不改变任何答案，但排序之后「两两之差」就变成了「沿序列的距离」。于是对候选甜度 `t`，判定问题变成：**能否在有序数组里挑出 `k` 个元素，使相邻两个被选元素的差都 ≥ `t`**。

这个判定对 `t` 是单调的：`t` 可行 ⇒ 任何更小的 `t` 也可行；`t` 不可行 ⇒ 任何更大的 `t` 也不可行。有单调性就可以二分，把「求最大可行值」压缩到约 30 轮判定。

### 思路演进

1. **暴力解法**：直接从 `price` 里枚举所有大小 `k` 的子集，对每个子集算两两差的最小值，取最大。组合数是 `C(n,k)`，最坏情况下是指数级，`n = 10^5` 时完全不可行。

2. **观察到两件事**：

   - **只需要管相邻**。排序后，若任意两个**相邻被选元素**的差都 ≥ `t`，那么任意两个被选元素的差也一定 ≥ `t`（非相邻的差是两个及以上相邻差之和，只会更大）。所以约束从 `O(k²)` 个不等式收窄成 `k-1` 个。
   - **判定可以用贪心做到 O(n)**。固定 `t` 后，从最小的元素开始选，之后每次跳到「第一个 ≥ 当前选中值 + `t`」的元素。**这个贪心是最优的**：假设存在某个可行解，它的第一个元素 ≥ `price[0]`，而贪心选的 `price[0]` 比它更小，留给后面的空间只会更大；于是逐元素归纳交换，贪心能选出的个数不少于任何其他方案。所以「贪心能选出 ≥ `k` 个」与「存在可行方案」等价。

3. **再观察到**：既然判定是「一直往后跳到 ≥ 当前 + `t`」，那「两个被选元素之间的跳跃」本质上就是**跨过若干个相邻差**。预先算出相邻差数组 `temp[i] = price[i+1] - price[i]`，一次跳跃的代价就是这段相邻差的**和**。
   判定于是退化为：**从左到右扫一遍 `temp`，累加，累加值一旦 ≥ `t` 就切断（记为一个间隔），最后看能不能切出 `k-1` 个间隔。** 这就是代码里的 `cnt += i; if cnt >= t: cou += 1; cnt = 0`。

4. **最终解法**：排序 + 相邻差数组 + 二分答案。二分区间取 `[0, (price[-1]-price[0]) // (k-1)]`，其上界 +1 作为**必然不可行**的哨兵：`k` 个元素的跨度最多是 `max-min`，平均每个间隔不超过 `(max-min)/(k-1)`，所以再大一定做不到。用 `left` 恒可行、`right` 恒不可行、`while left + 1 < right` 的写法，天然避开了所有边界特判。

### 关键点

- **排序不改变答案**：甜蜜度只依赖所选价格值的集合，与原始下标无关。
- **只约束相邻**：`min` 只需在排序后的相邻被选元素之间取，是本题能把 `O(k²)` 校验降成 `O(k)` 校验的关键。
- **累加的是相邻差之和**：`cnt += i`（`i` 是差值），而不是「跨过了几个元素」。差值的和 ≥ `t` 才等价于「两个被选价格之差 ≥ `t`」。
- **`right` 必须是不可行值**：写成 `(max-min)//(k-1) + 1`。如果写成 `max-min`，`k = 2` 时它本身可能就是可行值，会被漏掉。
- **`t = 0` 一定可行**：任何 `k` 个元素的两两差都 ≥ 0，所以 `left = 0` 这个初值不需要额外判定即可成立。

## 三、代码实现

### 最终代码

```python
class Solution:
    def maximumTastiness(self, price: list[int], k: int) -> int:
        price.sort()
        n = len(price)
        temp = []
        for i in range(1, n):
            temp.append(price[i] - price[i - 1])

        def check(t: int) -> bool:
            cnt = 0                      # 当前这一段累计的相邻差之和
            cou = 0                      # 已经切出的间隔数
            for i in temp:               # i 是一个相邻差
                cnt += i
                if cnt >= t:             # 这一段已经够 t，切断，作为一个间隔
                    cou += 1
                    cnt = 0
                if cou >= k - 1:         # k 个元素之间只需要 k-1 个间隔
                    return True
            return False

        left = 0                                 # 恒可行（差至少为 0）
        right = (price[-1] - price[0]) // (k - 1) + 1   # 恒不可行
        while left + 1 < right:
            mid = (left + right) // 2
            if check(mid):
                left = mid
            else:
                right = mid
        return left
```

## 四、复杂度分析

| 版本 | 时间复杂度 | 空间复杂度 |
| :--- | :--- | :--- |
| **最终代码** | O(n log n + n log V) | O(n) |
| 朴素解法（枚举子集） | O(C(n,k) · k) | O(k) |
| 理论下界 | O(n log n) | O(1) |

> 复杂度中的 `n` 指 `price` 的长度，`V = max(price) - min(price)` 是价格值域的宽度（本题 ≤ 10^9，故 `log V ≤ 30`）。

- **排序** O(n log n)；**建相邻差数组** O(n)。
- **二分**共 `O(log V)` 轮，每轮 `check` 线性扫描差值数组，O(n)。两者相乘即 `O(n log V)`。
- **空间**：`temp` 需要 `n-1` 个差值，O(n)。这个数组不是必需的，直接在 `price` 上双指针跳跃也能做，空间可降到 O(1)，但会牺牲可读性。
- 与朴素解法的差距是指数级到 `O(n log V)`：关键不在二分，而在「约束只作用于相邻元素」和「判定可以贪心线性完成」。

## 五、易错点与总结

### 易错点

- **把 `cnt += i` 写成 `cnt += 1`**：那样累加的是「跨过的元素个数」，`cnt >= t` 的条件被解释成「跨过 `t` 个元素」而不是「跨过的价格差之和 ≥ `t`」，判定口径整体错位（答案会系统性偏小）。这是本题最容易写错的一行。
- **误以为要校验所有两两差**：排序后只需校验相邻被选元素，重复校验不会更正确，只会让判定从 O(n) 退化成 O(k²)。
- **右端点取成可行值**：`right` 必须是不可行的哨兵值，否则二分收敛不到真实的可行上界。
- **忘记 `k-1` 而不是 `k`**：`k` 个元素之间只有 `k-1` 个间隔，`cou` 的门槛写错会导致 `k=2` 之类的小规模直接判错。
- **对未排序数组求相邻差**：相邻差必须建立在排序后的数组上，否则「沿序列的距离」没有意义。

### 题型套路沉淀

- **「最大化最小值 / 最小化最大值」→ 二分答案 + 判定**。看到这类目标，先问「如果能 O(n) 判定一个值行不行，是不是就能二分」。
- **判定要够便宜**：二分答案的轮数是 `log(值域)`，判定必须做到 O(n) 级别；判定里出现排序、枚举子集就说明还没想透。
- **二分答案的固定写法**（避免所有边界特判）：

  ```python
  left  = <一定可行的下界>
  right = <一定不可行的上界>
  while left + 1 < right:
      mid = (left + right) // 2
      if check(mid):
          left = mid       # 可行 → 往大推
      else:
          right = mid      # 不可行 → 往小收
  return left
  ```

- **排序 + 相邻差**是「把全局约束化成局部约束」的常用手段：一旦约束只依赖相邻元素，问题就从组合选择变成线性扫描。
- **贪心的正确性靠交换论证**，而不是靠感觉：本题「每次选最小的可行元素」之所以最优，是因为更小的选择只会让后续空间更大。
