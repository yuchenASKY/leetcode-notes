# 378. 有序矩阵中第 K 小的元素

> **难度**：中等
> **标签**：数组 · 二分查找 · 矩阵 · 堆（优先队列） · 排序
> **原题链接**：https://leetcode.cn/problems/kth-smallest-element-in-a-sorted-matrix/

---

## 一、题目描述

给定一个 `n × n` 的矩阵 `matrix`，**每一行、每一列都按非递减顺序排列**。要求返回矩阵中**按大小排序后的第 `k` 个元素**。

注意是「排序后的第 k 个」，重复元素各占一个位置 —— 不是「第 k 个不同的值」。另外题目额外要求**内存复杂度必须优于 O(n²)**，即不允许把 n² 个元素全部摊平存下来。

### 示例

```text
输入：matrix = [[1,5,9],[10,11,13],[12,13,15]], k = 8
输出：13
解释：矩阵中的元素为 [1,5,9,10,11,12,13,13,15]，第 8 小元素是 13

输入：matrix = [[-5]], k = 1
输出：-5
```

### 约束条件

- `n == matrix.length == matrix[i].length`
- `1 <= n <= 300`
- `-10^9 <= matrix[i][j] <= 10^9`
- 保证所有行、所有列都按**非递减**顺序排列
- `1 <= k <= n²`

---

## 二、解题思路

### 核心思想

**不去排序元素，而是对「答案的值域」二分。** 定义 `f(t)` = 矩阵中 `≤ t` 的元素个数，它随 `t` 单调不减；第 k 小的元素恰好是使 `f(t) >= k` 成立的**最小** `t`。于是在 `[min, max]` 上二分 `t`，每轮用行列单调性 O(n²)（最坏）数一遍即可，只需 O(1) 额外空间。

### 思路演进

1. **暴力解法**：把 n² 个元素摊平排序，取下标 `k-1`。时间 O(n² log n)、空间 O(n²) —— 空间直接违反题目要求，n = 300 时是 9 万个 int。
2. **堆的做法**：维护一个大小为 k 的大顶堆，把元素逐个灌进去，超容量就弹堆顶。空间降到 O(k)，时间 O(n² log k)，是可行的思路，但它仍然要把 n² 个元素**全部过一遍并逐个入堆**，也没有利用「行列同时有序」这一更强的结构。
3. **观察到关键性质**：`f(t) = #{x : x <= t}` 关于 `t` 单调不减，因此「`f(t) >= k`」在值域上是一个**先假后真**的单调查询，答案就是那个转折点。判定的成本只跟「怎么数 ≤ t 的个数」有关，跟排序无关 —— 矩阵的行列单调性正好让计数可以提前 `break`。
4. **最终解法**：在 `[min-1, max+1]` 上二分（两端分别是「必然不可行」和「必然可行」的哨兵）。每轮判定逐行扫，行内遇到第一个 `> t` 就停，遇到某行首元素就 `> t` 则整轮结束（列升序保证下面各行首元素只会更大）。用 `left + 1 < right` 的循环不变式，退出时 `right` 就是答案。

### 关键点

- **二分对象是「值」不是「下标」**：矩阵元素排成一维时没法 O(1) 按下标取值，但「值」可以整体比较、可以取中点。
- **判据必须是 `f(t) >= k`，不能写 `== k`**：有重复元素时 `f(t)` 会一次跳好几个，等号很可能永远取不到（例 1 中 `f(13) = 8`，而 `f` 从不等于 `8` 之外的中间值也没问题，但换成 `k = 7`、`f(12) = 6`、`f(13) = 8`，`== 7` 就永不成立）。
- **答案一定是矩阵里出现过的元素**：`f(t)` 只在「元素值」处发生跳变，最小的可行 `t` 必是某个 `matrix[i][j]`，所以值域二分能落在正确答案上。
- **哨兵区间的正确性**：`left = min - 1` 时 `f = 0 < k`（不可行）；`right = max + 1` 时 `f = n² >= k`（可行，因为 `k <= n²`）。两端一假一真，二分必收敛到一个转折点。
- **`break` 依赖「行升序 + 列升序」两条同时成立**：行内升序保证「第一个 `> t` 之后的都 `> t`」；列升序保证「某行首 `> t` ⇒ 之后所有行首都 `> t`」。少了后者，外层 `break` 就是错的。

## 三、代码实现

### 最终代码

```python
class Solution:
    def kthSmallest(self, matrix: list[list[int]], k: int) -> int:
        n = len(matrix)

        def check(t: int) -> bool:          # 矩阵中 <= t 的元素个数是否已达到 k
            cnt = 0
            for i in range(n):
                if matrix[i][0] > t:        # 列升序：本行及以下所有行的首元素都 > t
                    break
                for j in range(n):
                    if matrix[i][j] > t:    # 行升序：本行后面的都 > t
                        break
                    cnt += 1
            return cnt >= k

        left = matrix[0][0] - 1             # 不可行哨兵：f(left) = 0
        right = matrix[-1][-1] + 1          # 可行哨兵：f(right) = n^2 >= k
        while left + 1 < right:             # 不变式：left 不可行，right 可行
            mid = (left + right) // 2
            if check(mid):
                right = mid
            else:
                left = mid
        return right                        # 第一个可行的值
```

> 代码与提交记录一致；`list[list[int]]` 是 Python 3.9+ 的内置泛型写法，不需要额外 `import`（截图里没有、也无需补）。

## 四、复杂度分析

| 版本 | 时间复杂度 | 空间复杂度 |
| :--- | :--- | :--- |
| **最终代码（值域二分 + 逐行 break）** | O(n² log V) | O(1) |
| 朴素解法：摊平后排序 | O(n² log n) | O(n²) |
| 朴素解法：大小为 k 的大顶堆 | O(n² log k) | O(k) |
| 优化版：值域二分 + 阶梯计数 | O(n log V) | O(1) |
| 理论下界 | O(n) | O(1) |

> 复杂度中的 **n 指矩阵的边长**，矩阵共有 n² 个元素；**V = max − min + 1 是值域宽度**，本题 `|matrix[i][j]| <= 10^9`，故 `V` 约 2×10^9、`log₂V ≈ 31`（常量级，与 n 无关）。

补充两点：

- **判定的代价是结构相关的**：`t` 不小于所有元素时每行都扫满 n 个，是 O(n²)；`t` 很小时第一个 `break` 就结束，接近 O(1)。上表取的是最坏情况。
- **空间是 O(1)**：除计数器与左右边界外不申请任何随 n 增长的容器，满足题目「内存优于 O(n²)」的硬性要求。

## 五、优化评估

**结论**：空间已经是 O(1)，时间上还有一层结构性空间 —— 瓶颈不在二分轮数（只有 ~31 轮），而在**每轮判定是 O(n²)**。

### 瓶颈分析

`check(t)` 对每一行都从第 0 列重新线性数到「第一个 `> t`」。最坏情况下（`t` 不小于全部元素）要扫 n² 个格子；把这个 O(n²) 判定乘上 31 轮二分，主导项就是 n²。

### 可优化空间

行列同时有序还给了一个更强的性质：**从右上角或左下角出发，每走一步都能整行或整列地排除**。以左下角 `(n-1, 0)` 为起点：

- 若 `matrix[i][j] <= t`：由于第 j 列升序，第 0..i 行这一列的元素全部 `<= t`，可以直接 `cnt += i + 1`，然后**整列处理完毕**，右移 `j += 1`；
- 若 `matrix[i][j] > t`：由于第 i 行升序，这一行从第 j 列往右全部 `> t`，直接上移 `i -= 1`。

每步排除一整行或一整列，最多走 2n 步，判定降到 O(n)，总时间 O(n log V)。

### 优化代码

```python
class Solution:
    def kthSmallest(self, matrix: list[list[int]], k: int) -> int:
        n = len(matrix)

        def count_le(t: int) -> int:        # 数矩阵中 <= t 的元素个数
            cnt = 0
            i, j = n - 1, 0                 # 从左下角出发
            while i >= 0 and j < n:
                if matrix[i][j] <= t:
                    cnt += i + 1            # 第 j 列的第 0..i 行全都 <= t
                    j += 1                  # 这一列处理完，右移
                else:
                    i -= 1                  # 第 i 行从 j 往右全都 > t，上移
            return cnt

        lo, hi = matrix[0][0], matrix[-1][-1]
        while lo < hi:                      # 答案必然落在 [min, max] 内
            mid = (lo + hi) // 2
            if count_le(mid) >= k:
                hi = mid
            else:
                lo = mid + 1
        return lo
```

**优化理由**：把「逐行线性数」换成「沿阶梯走」，判定从 O(n²) 降到 O(n)，总时间从 O(n² log V) 降到 O(n log V)。注意这里用的是闭区间二分 `lo <= hi` 的变体（`lo` 从 `min` 起、区间两端都取真实值），与上面 `left/right` 哨兵写法不同，两套写法不能混用。

### 常数级优化（可选）

- 内层循环把 `matrix[i]` 取一次存进局部变量 `row`，避免每次都做 `matrix[i]` 的下标寻址。
- `check` 里一旦 `cnt >= k` 就可以提前返回 `True`，不必数完整个矩阵；不过要保证「提前返回」不破坏 `break` 的语义（只需在 `cnt += 1` 后判断）。

## 六、易错点与总结

### 易错点

- **两种二分写法混用**：`left/right` 哨兵 + `while left + 1 < right` + 返回 `right`，和 `lo/hi` 闭区间 + `while lo < hi` + 返回 `lo` 是两套东西。混着写（例如哨兵区间却用 `lo <= hi`、或闭区间却 `return right`）必然错一位。
- **判据写成 `== k`**：有重复值时 `f(t)` 会跳变，等号可能永远取不到，导致死循环或返回错误值。
- **把题目理解成「第 k 个不同的元素」**：重复元素各占一个位置，例 1 里 13 出现两次，`k = 8` 的答案仍是 13。
- **外层 `break` 少一个前提**：只利用行升序时，外层「首元素 > t 就停」不成立 —— 必须靠列升序。
- **`int` 溢出**（C++/Java 才有的坑）：`left`、`right` 取到 `±(10^9 + 1)`，`left + right` 在 32 位下会溢出，Python 无此问题。

### 题型套路沉淀

- **「第 k 小 / 第 k 大」的两条路线**：① 堆（数据太大不能全排序时，只维护 k 个）；② 值域二分（能 O(1) 数出「≤ x 的个数」时）。本题两者都可行，但行列有序的结构明确指向后者。
- **二分答案三件套**：① 找一个随参数单调的判定函数；② 区间两端放「必然不可行 / 必然可行」的哨兵；③ 循环不变式写清楚（谁是假、谁是真），返回值就不会错。
- **二维有序结构上的计数**：看到「行、列都升序」就想到从**左下角或右上角**出发的阶梯走法，单次 O(n)、O(1) 空间 —— 这既是二分判定的最佳载体，也是「有序矩阵中搜索」这类题（如 240. 搜索二维矩阵 II）的共同骨架。
