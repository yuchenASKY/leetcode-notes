# 2560. 打家劫舍 IV

> **难度**：中等
> **标签**：数组 · 二分查找 · 动态规划
> **原题链接**：https://leetcode.cn/problems/house-robber-iv/

---

## 一、题目描述

沿街有一排房屋，第 `i` 间房里有 `nums[i]` 美元。相邻房屋的防盗系统连通，因此小偷**不能偷相邻的两间房**。

小偷的「**窃取能力**」定义为：他偷的所有房子里，**单间金额的最大值**。现在要求他至少偷 `k` 间房（题目保证总能偷到至少 `k` 间），求**最小的窃取能力**。

翻译一遍：在数组里选出一组**互不相邻**的房屋，数量不少于 `k`，让这组房屋里**最大值最小**，返回这个最小值。

### 示例

```text
输入：nums = [2,3,5,9], k = 2
输出：5
解释：偷至少 2 间，共 3 种方式：
      - 下标 0、2 → 能力 max(2,5) = 5
      - 下标 0、3 → 能力 max(2,9) = 9
      - 下标 1、3 → 能力 max(3,9) = 9
      取最小，返回 5
```

```text
输入：nums = [2,7,9,3,1], k = 2
输出：2
解释：取下标 0、4，能力 max(2,1) = 2，是最小的
```

### 约束条件

- `1 <= nums.length <= 10^5`
- `1 <= nums[i] <= 10^9`
- `1 <= k <= (nums.length + 1) / 2`

## 二、解题思路

### 核心思想

**二分答案。** 不直接构造最优方案，而是问一个判定问题：*「如果规定能力上限为 `c`，最多能偷几间房？」* 这个「最多间数」随 `c` 增大单调不减，于是可以在**能力值域**上二分，找出第一个使「最多间数 ≥ `k`」的 `c`。

### 思路演进

1. **暴力解法**：枚举所有互不相邻的房屋组合，挑出数量 ≥ `k` 的，取各自最大值的最小值。方案数是指数级的，`n = 10^5` 完全不可行。
   - 稍微好一点的想法：枚举「能力上限」`c`，对每个 `c` 判断能否凑够 `k` 间。但 `c` 的候选有 `max(nums)` 个，`max(nums)` 可达 `10^9`，逐个判定仍是 `O(n · V)` 级别，必然超时。
2. **观察到**两件事：
   - **(a) 固定 `c` 后问题退化成一个简单的计数问题**：能偷的房屋集合固定为「金额 ≤ `c` 的那些房屋」，而「在一条链上最多能选多少个互不相邻的元素」可以用**打家劫舍式的线性 DP** 直接算出，`O(n)`。
   - **(b) 这个「最多间数」关于 `c` 单调不减**：`c` 变大，可用房屋集合只增不减，最优选取数不可能变少。⇒ 谓词 `solve(c) >= k` 关于 `c` 单调（假 → 真），**这正是二分的信号**。
3. **优化为**：外层对 `c` 二分（`0 ~ max(nums)`），内层用线性 DP 做判定。
   - 下界 `0`：`k >= 1`，而 `solve(0) = 0 < k`，谓词必假，无需额外哨兵。
   - 上界 `max(nums)`：此时所有房屋都可用，`solve` 取到全局最大间数，由题目保证 ≥ `k`，谓词必真，二分必有解。
   - 全程 `O(n log V)` 时间、`O(1)` 空间。

### 关键点

- **二分的是答案的取值范围，不是数组下标。** 判据是「可行性谓词关于取值单调」，与数组是否有序无关 —— 这是「二分答案」和普通二分查找的分水岭。
- **判定的 DP 状态设计**：`f0` = 处理到当前房屋、且**当前房屋不偷**时的最大间数；`f1` = **当前房屋偷**时的最大间数。
  - 若 `nums[i] > c`（这间金额超上限，不能偷）：状态只能落在「不偷」，故 `f0 = f1`；
  - 否则：`f0, f1 = f1, max(f1, f0 + 1)` —— 不偷就继承上一个「偷或不偷都行」的最优 `f1`；偷则上一个必须不偷，即 `f0 + 1`。
  - 不变式 `f1 >= f0` 恒成立（因为 `f1 = max(f1, f0 + 1) >= f1_old >= f0_old`），所以整体最大值就是 `f1`，直接返回即可。
- **`range` 的小技巧**：`range(max(nums))` 的第 `i` 个元素恰好等于 `i`，因此 `bisect_left` 返回的**插入位置**在数值上就等于**答案值**。
- **上界边界**：答案有可能是 `max(nums)`，而它**不在** `range(max(nums))` 里 —— 但此时所有元素都 `< k`，`bisect_left` 返回 `len == max(nums)`，落点恰好正确，所以不必把上界写成 `max(nums) + 1`。

## 三、代码实现

### 最终代码

```python
from bisect import bisect_left
from typing import List


class Solution:
    def minCapability(self, nums: List[int], k: int) -> int:
        # 判定：能力上限为 mx 时，最多能偷多少间互不相邻的房屋
        def solve(mx: int) -> int:
            f0 = f1 = 0          # f0: 当前房屋不偷；f1: 当前房屋偷
            for x in nums:
                if x > mx:       # 金额超过能力上限，这间不能偷，只能继承「不偷」
                    f0 = f1
                else:
                    f0, f1 = f1, max(f1, f0 + 1)
            return f1

        # 在取值区间上二分：range 的第 i 个元素就是 i，插入位置 == 答案值
        return bisect_left(range(max(nums)), k, key=solve)
```

> 截图顶部被裁掉了一行，`bisect_left` 与 `List` 的 `import` 在截图里看不到，已补齐以保证可直接运行。

## 四、复杂度分析

记 `n = len(nums)`，`V = max(nums)`。

| 版本 | 时间复杂度 | 空间复杂度 |
| :--- | :--- | :--- |
| **最终代码** | O(n log V) | O(1) |
| 朴素解法 | O(n · V) | O(1) |
| 理论下界 | O(n) | O(1) |

> 复杂度中的 n 指数组 `nums` 的长度，V 指 `nums` 中元素的最大值（即能力取值区间的长度）。

**最终代码**：二分共 `log₂V` 轮（`V <= 10^9` 时约 30 轮），每轮判定线性扫一遍数组，故 `O(n log V)`；判定只用 `f0`/`f1` 两个变量滚动，无额外存储，空间 `O(1)`。

**朴素解法**：枚举能力上限的每一个取值（`V` 个），每个取值做一次线性判定，`O(n · V)`；`V` 可达 `10^9`，量级上完全不可行。

**理论下界**：任何算法都必须至少读一遍输入才可能得到答案，故时间下界 `Ω(n)`；`n = 10^5` 且 `V <= 10^9` 时 `log V <= 30`，`O(n log V)` 与下界只差一个不超过 30 的常数因子。

## 五、优化评估

**结论**：在「二分答案 + 线性判定」这个框架下，时间已无可降阶的空间，空间已是 `O(1)` 最优。

### 瓶颈分析

- 时间上的两部分：① 判定 `solve` 必须完整扫一遍 `nums` —— 少看一间就可能漏掉更优的选取方案，单次判定不可能低于 `O(n)`；② 二分的轮数由答案值域决定，`log₂(10^9) ≈ 30`，属于算法结构本身的成本。两者相乘就是 `O(n log V)`，降不动。
- 空间上只用两个滚动变量，已经是最省的形态。

### 可优化空间

- 二分上界取到 `max(nums)` 而不是某个更大值，已经是最紧的合法上界（再小可能不可行）。
- 判定内部无需保存任何中间方案，只保留计数即可 —— 因为题目只要「最多能偷几间」这个数量，不需要具体的选取方案。
- 需要留意的结构性依赖：本题成立的前提是「**至少** `k` 间」使谓词单调。如果把条件换成「**恰好** `k` 间」，`solve(c) >= k` 就不再等价于可行（可能选不出恰好 `k` 间，也可能选多了），单调性随之丢失，本解法不再适用。

### 常数级优化（可选）

- `bisect_left(..., key=solve)` 把二分循环放在 C 层执行，Python 侧只承担约 30 次 `solve` 调用，比手写 `while lo < hi` 少一整个循环的解释器开销。用 `bisect` 而不手写，收益就在这里。
- 判定里 `f0, f1` 用元组解包一次性并行赋值，避免引入临时变量。

## 六、易错点与总结

### 易错点

- **把二分对象搞错**：这题二分的是**能力值**，不是数组下标。写成「排序后二分下标」就完全跑偏了。
- **上界边界漏掉**：答案是 `max(nums)` 时它不在 `range(max(nums))` 内，容易被误认为需要写成 `range(max(nums) + 1)`。实际上 `bisect_left` 返回 `len == max(nums)`，刚好等于答案 —— 但要理解这一点，否则换成手写二分时容易把上界写错。
- **忽略下界哨兵的必要性**：这里因为 `k >= 1` 且 `solve(0) = 0`，下界取 `0` 时谓词必假，天然安全。若遇到判定函数在区间左端点为真的题目，就必须把下界调到「确保谓词为假」的位置（如 `min(nums) - 1` 或 `max(nums) - 1` 这类），否则二分会把边界情况判错。
- **判定里的转移写反**：`x > mx` 表示**这间不能偷**，只能继承「不偷」状态；若写成 `f1 = f0` 或漏掉这个分支，计数就会偏大。
- **返回值取错**：整体最大值是 `max(f0, f1)`；本实现靠不变式 `f1 >= f0` 直接返回 `f1`，改状态定义时要同步改返回，否则可能少算一间。

### 题型套路沉淀

- **二分答案三步走**：
  1. 找出一个关于答案**单调**的可行性谓词 `ok(c)`（通常是「上限为 c 时能否达成目标」）；
  2. 写出 `ok` 的高效判定（常是贪心或线性 DP，本题是后者）；
  3. 在**答案值域**上二分第一个 `ok(c)` 为真的位置，注意下界要落在「谓词确实为假」的点上。
- **判断单调性的通用手法**：看「可选集合」是否随参数增大而单调扩张 —— 集合单调 ⇒ 集合上的最优值单调。
- **触发信号**：题面出现「最小化最大值」「最大化最小值」「最小的能力 / 最少的时间 / 最大的容量」这类表述时，优先考虑二分答案；判定环节再去匹配对应的线性算法（计数 DP、贪心、前缀和等）。
- **打家劫舍式线性 DP 的两种用途**：求最大金额、求最多间数。本题只用到了「计数」这一面 —— 状态含义从「最大收益」换成「最多可选个数」，转移结构完全一样。
