# 3048. 标记所有下标的最早秒数 I

> **难度**：中等
> **标签**：数组 · 二分查找 · 贪心
> **原题链接**：https://leetcode.cn/problems/earliest-second-to-mark-indices-i/

---

## 一、题目描述

`nums` 与 `changeIndices` 的长度分别为 `n`、`m`，两者的下标都从 1 开始。第 `s` 秒（`1 ≤ s ≤ m`）只能从下面三件事里挑一件做：

1. 选一个下标 `i`，把 `nums[i]` 减 1；
2. 若 `nums[changeIndices[s]] == 0`，**标记**下标 `changeIndices[s]`（一秒只能标记这一个下标）；
3. 什么都不做。

求在最优操作下，把 `nums` 的全部 `n` 个下标都标记完的**最早秒数**；做不到则返回 `-1`。

关键约束在于：**第 `s` 秒能标记谁是被 `changeIndices[s]` 定死的**，而标记的前提是此刻该下标已被减到 0 —— 于是「什么时候标记」和「什么时候做减法」在争抢同一批秒数。

### 示例

```text
输入：nums = [2,2,0], changeIndices = [2,2,2,2,3,2,2,1]
输出：8
解释：第 1~4 秒把 nums[1]、nums[2] 各减 2 次到 0；第 5 秒标记下标 3（nums[3] 本来就是 0）；
      第 6 秒标记下标 2；第 7 秒空过；第 8 秒标记下标 1。所有下标标记完毕，最早就是第 8 秒。

输入：nums = [1,3], changeIndices = [1,1,1,2,1,1,1]
输出：6

输入：nums = [0,1], changeIndices = [2,2,2]
输出：-1   （下标 1 从未在 changeIndices 中出现，永远无法标记）
```

### 约束条件

- `1 <= n == nums.length <= 2000`
- `0 <= nums[i] <= 10^9`
- `1 <= m == changeIndices.length <= 2000`
- `1 <= changeIndices[i] <= n`

## 二、解题思路

### 核心思想

**答案关于秒数单调 → 二分答案；判定用贪心：每个下标都安排在它「最后一次出现」的那一秒标记。**

### 思路演进

1. **暴力解法**：直接搜索操作序列（每秒三选一）或枚举每个下标的标记秒再逐个验证合法性 —— 状态空间是指数级的，写不出来。
   退一步，把「最早秒数」从 1 线性枚举到 `m`，对每个候选秒数跑一次可行性判定，复杂度 O(m²)。在本题的 `m ≤ 2000` 下能过，但完全没用上问题的结构。
2. **观察到「单调性」**：秒数上限越大，可选的操作就越多。如果第 `x` 秒能标完全部下标，那么第 `x+1` 秒的那套操作原样照做（多出来的一秒「什么也不做」）也能标完。所以可行性关于答案是**前一段全 False、后一段全 True**。于是把「线性枚举答案」换成**二分**，直接省掉一个 m 因子，复杂度来到 O(m log m)。
3. **判定该怎么做 —— 贪心**：判定「`mx` 秒内能否标完全部下标」，等价于「`changeIndices[:mx]` 里挑出合法的操作安排」。要点是：
   - 标记只能发生在第 `s` 秒标记 `changeIndices[s]`，而且那一刻该下标必须已经是 0 —— 也就是说，**某个下标的所有减法都必须排在它的标记秒之前**。
   - 所以一个下标在本次时限内出现多次时，**把它安排在最后一次出现的那一秒标记最有利**：越靠后标记，前面留给他做减法的时间就越多。把「在较早的出现处标记」和「在较晚的出现处标记」做交换，只会让可用时间变多，不会让别的下标变差 —— 贪心落点得证。
   - 于是先预处理 `last_t[i]`：下标 `i + 1` 在 `changeIndices[:mx]` 中最后一次出现的秒（0 起）。若某个下标压根没出现过，直接判不可行。
   - 再逐秒扫一遍：当前秒若是某个下标的**最后出现**，这一秒就被它「占用」去标记，要求此前攒下的空闲秒数够把它减到 0；否则这一秒不是任何下标的最后出现，可以留作减法（或闲置），把它记进「可用秒数」账本。
4. **进一步压缩搜索区间**：标完 `n` 个下标至少需要 `n` 秒（一秒只能标一个），把 `nums` 全部减到 0 至少需要 `sum(nums)` 秒（`nums[i] = 0` 的下标不需要减），而这两类操作互斥 ⇒ 答案至少是 `n + sum(nums)`。二分的左端点直接从 1 提到这个下界。

### 关键点

- **单调性是二分的前提**：一定先确认 `check` 是「False…False True…True」的形状，否则二分出来的位置没有意义。
- **贪心的落点必须精确**：标记要压在「最后一次出现」上。同一个下标出现多次时，标记秒选错会误判可行性。
- **`cnt` 的口径**：它表示「到目前为止还剩多少秒可以拿去做减法」。只有**非最后出现**的秒才能 `+1`；最后出现的那一秒被标记占用，不能同时算作减法秒。
- **下界 `n + sum(nums)` 是承重结构，不是锦上添花**：它把搜索区间从 `[1, m]` 收到 `[n + sum(nums), m]`；当 `sum(nums)` 很大（本题 `nums[i]` 可达 10^9）时区间直接为空，天然得到 `-1`。
- **`n > m` 先快筛**：一秒最多标一个下标，`m < n` 时必定无解。

## 三、代码实现

### 最终代码

```python
from typing import List
from bisect import bisect_left          # 截图中没写出来，已补（key= 参数需 Python 3.10+）


class Solution:
    def earliestSecondToMarkIndices(self, nums: List[int], changeIndices: List[int]) -> int:
        n, m = len(nums), len(changeIndices)
        if n > m:                       # 一秒最多标一个下标，秒数不够
            return -1

        def check(mx: int) -> bool:
            # 1) 预处理：每个下标在 changeIndices[:mx] 中最后出现的秒（0 起）
            last_t = [-1] * n
            for t, idx in enumerate(changeIndices[:mx]):
                last_t[idx - 1] = t
            if -1 in last_t:            # 有下标从未出现 → 不可能被标记
                return False

            # 2) 逐秒贪心：把每个下标的标记安排在它的最后出现处
            cnt = 0                     # 之前攒下、还可用作减法的秒数
            for i, idx in enumerate(changeIndices[:mx]):
                idx -= 1
                if i == last_t[idx]:            # 这一秒必须用来标记 idx
                    if nums[idx] > cnt:         # 前面腾不出足够时间把它减到 0
                        return False
                    cnt -= nums[idx]            # 扣掉被 idx 占用的减法秒数
                else:
                    cnt += 1                    # 这一秒可以留作减法
            return True

        left = n + sum(nums)            # 下界：n 次标记 + sum(nums) 次减法
        ans = left + bisect_left(range(left, m + 1), True, key=check)
        return -1 if ans > m else ans
```

## 四、复杂度分析

| 版本 | 时间复杂度 | 空间复杂度 |
| :--- | :--- | :--- |
| **最终代码** | O(m log m) | O(n + m) |
| 朴素解法（线性枚举答案 + 同款判定） | O(m²) | O(n) |
| 理论下界 | O(m) | O(n) |

> 复杂度中的 n 指 `nums` 的长度（要标记的下标个数），m 指 `changeIndices` 的长度（可用秒数上限）。
> `check(mx)` 需要扫两遍 `changeIndices[:mx]`，即 O(mx) 时间、O(n) 辅助空间；二分在 `[n + sum(nums), m]` 上做 ⌈log m⌉ 次判定 ⇒ 总计 O(m log m)。
> 两次切片 `changeIndices[:mx]` 各自复制了一份长度 `mx` 的列表，这就是方案里那份 O(m) 额外空间的来源（可去掉，见下节）。

## 五、优化评估

**结论**：算法结构已是最优 —— 「二分答案 + O(m) 贪心判定」是这类「求最小的可行时间」问题的标准形态；剩下的只有常数级改动。

### 瓶颈分析

- 时间上，判定里必须把 `changeIndices[:mx]` 走两遍：第一遍统计每个下标的最后出现位置（少看任何一秒都可能把最后出现位置算错），第二遍逐秒决定这一秒是「标记」还是「留作减法」，两遍都不可省。O(m) 的判定没法再降。
- 二分次数由区间长度决定。把左端点从 1 提到 `n + sum(nums)` 只是常数级收益，真正的好处是 `sum(nums)` 很大时区间为空、直接判负，以及让「必为 False」的区间不进入二分（下界必须是判定确实为假的位置，否则会把答案算错）。
- 空间上唯一的浪费是两处切片。把切片换成按下标访问即可抹掉。

### 可优化空间

下界已经用「n 次标记 + sum(nums) 次减法」收紧了，没有更紧的必要条件可用；判定也没有 O(m) 以下的写法 —— 因此本题到此为止。

### 常数级优化（可选）

```python
        def check(mx: int) -> bool:
            last_t = [-1] * n
            for t in range(mx):                     # 不做切片
                last_t[changeIndices[t] - 1] = t
            if -1 in last_t:
                return False
            cnt = 0
            for i in range(mx):
                idx = changeIndices[i] - 1
                if i == last_t[idx]:
                    if nums[idx] > cnt:
                        return False
                    cnt -= nums[idx]
                else:
                    cnt += 1
            return True
```

**优化理由**：判定逻辑与前面完全一致（大 O 不变），只是把两次 `changeIndices[:mx]` 切片换成按下标访问，省掉每次判定两份长度为 `mx` 的临时列表。

## 六、易错点与总结

### 易错点

- **标记的落点写错**：必须压在「最后出现」的秒上。若图省事改成「任意出现处标记」，会把本可以留作减法的时间提前消耗掉，从而漏判可行解。
- **`cnt` 只在非最后出现的秒 `+1`**：最后出现的那一秒被标记占用，不能同时算作减法秒，否则会高估可用时间。
- **忘了检查「下标从未出现」**：`last_t` 初始化为 `-1`，必须显式 `if -1 in last_t: return False`，否则会拿着 `-1` 与 `i` 比较，静默给出错误结论。
- **下界写错会漏解**：二分的左端点必须是「判定确实为假」的位置，本题取 `n + sum(nums)` 是严格的必要条件 —— 标完 n 个下标要 n 秒、把数减到 0 要 sum(nums) 秒，二者互斥。
- **`bisect_left(...)` 返回的是相对 `range` 起点的偏移**，必须加回 `left`；区间全 False（或区间为空）时它返回区间长度，因此末尾的 `return -1 if ans > m else ans` 是必需的兜底。
- **补 import**：截图里没有 `bisect_left` 与 `List` 的来源，需要 `from bisect import bisect_left`、`from typing import List`；`bisect_left` 的 `key=` 参数要求 Python 3.10 及以上。

### 题型套路沉淀

- **「最早 / 最小 / 最大可行的 x」+ 有 O(n) 判定 → 二分答案**：只要能把问题改写成「给定 x，能否做到」且可行性关于 x 单调，就先二分，再把精力全部投到判定上。
- **判定里的「时间账本」贪心**：每个任务有最晚可行时刻（这里是「最后出现」），把最紧的 deadline 优先满足，用一个变量累积「还剩多少可支配的空闲时间」并逐次扣账。凡是「若干任务共享一条时间轴、每个任务有截止点」的判定，都可以套这个骨架。
- **搜索区间两端都要利用结构**：右端是天然上界 `m`，左端不要无脑写 1，而要用必要条件收出来 —— 既能少几次判定，又能在无解时直接判负。
