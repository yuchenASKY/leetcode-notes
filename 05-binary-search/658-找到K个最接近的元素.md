# 658. 找到 K 个最接近的元素

> **难度**：中等
> **标签**：数组 · 二分查找 · 双指针
> **原题链接**：https://leetcode.cn/problems/find-k-closest-elements/

---

## 一、题目描述

给定一个**升序排列**的数组 `arr`，以及整数 `k` 和 `x`，从数组里挑出最接近 `x` 的 `k` 个数，结果仍按升序返回。

「更接近」的判定：`|a - x| < |b - x|`；若距离**相等**，则**数值更小**的那个更接近。

### 示例

```text
输入：arr = [1,2,3,4,5], k = 4, x = 3
输出：[1,2,3,4]
解释：1 与 5 距 3 都是 2，平局取更小的 1，于是丢掉 5。

输入：arr = [1,1,2,3,4,5], k = 4, x = -1
输出：[1,1,2,3]
解释：x 在数组左侧之外，直接取最小的 4 个。
```

### 约束条件

- `1 <= k <= arr.length`
- `1 <= arr.length <= 10^4`
- `arr` 按**升序**排列
- `-10^4 <= arr[i], x <= 10^4`
- 进阶：你可以设计并实现时间复杂度**优于 O(n)** 的算法吗？

## 二、解题思路

### 核心思想

**升序数组上的「接近程度」沿下标弱单峰**（先弱减后弱增），由此得到两个结论：最优解必是**长度 k 的连续区间**；任意区间里「最远」的元素只可能在**两端**。于是问题从「选 k 个数」变成「在 `n - k + 1` 个候选左端点里定位一个」，并且"该不该右移左端点"能写成**关于左端点的单调谓词** ⇒ 二分即可 O(log(n-k)) 定出左端点。

### 思路演进

1. **朴素解**：完全无视「数组已升序」这个条件，把全部元素按偏好键 `(|v - x|, v)` 排序，取前 `k` 个再排序返回。时间 O(n log n)、空间 O(n)。（另一条等价暴力是枚举全部 `n - k + 1` 个连续窗口逐一比较，O(nk) 或 O(n²)。）
2. **瓶颈定位**：排序把「数组有序」这条**免费信息**扔掉了 —— 本题真正要选的只是一段**连续区间**，候选只有 `n - k + 1` 个，花 O(n log n) 去建立全序是纯粹的浪费；而窗口之间高度重叠，逐个比较又在重复劳动。
3. **关键转化**（三小步，每步都只用到了一个观察）：
   - **(a) 最优解是连续区间**。`|arr[i] - x|` 沿下标先弱减后弱增（弱单峰，因为 `arr` 弱升序），偏好键 `(|v - x|, v)` 同样弱单峰；**弱单峰序列里"最小的 k 个"必然落在连续的下标上**（子水平集 `{i : key(i) <= t}` 是区间，取前 k 小即某个区间）。
   - **(b) 两端收缩为什么对**。弱单峰 ⇒ 一个区间上的**最大**偏好键只可能在两个端点上取到 ⇒ 每轮丢掉"更远的那一端"，就是丢掉当前的全局最大键 ⇒ 这个贪心的删除顺序恰好等于「按偏好键降序删除」⇒ 剩下的 k 个正是 k 个最小键。**这就是最终代码的写法，O(n - k)**。
   - **(c) 再进一步：把"位置"交给二分**。「窗口 l」与「窗口 l+1」只差一个元素：前者保留 `arr[l]`、后者保留 `arr[l+k]`。因此
     > 窗口 l 不劣于窗口 l+1 ⟺ `(arr[l] + arr[l+k]) >= 2 * x`

     而 `h(l) = arr[l] + arr[l+k]` 的两项都随 l 非减 ⇒ **`h(l)` 单调不减** ⇒ 谓词「`h(l) < 2x`」是关于 l 的单调谓词（真…真假…假）⇒ 二分求出 `l* = min{l : arr[l] + arr[l+k] >= 2x}`，答案就是 `arr[l* : l* + k]`。
4. **最优解**：二分定位 + 一次 C 层切片：

   ```python
   lo, hi = 0, n - k
   while lo < hi:
       mid = (lo + hi) // 2
       if arr[mid] + arr[mid + k] < x + x: lo = mid + 1
       else: hi = mid
   return arr[lo : lo + k]
   ```

   离理论下界只有常数距离：候选左端点共 `n - k + 1` 个，在单调谓词定位模型下至少要 `log₂(n - k + 1)` 次比较；输出 k 个数本身不可能省。

### 判据与判据族定位

**收缩版判据**：设 `a = arr[left]`、`b = arr[right]`，则 `dist(a) <= dist(b)` ⟹ **右端点 b 必不在最优解中**（丢它）。

**二分版判据**：`arr[l] + arr[l+k] >= 2x` ⟺ 左端点 l 不劣于 l+1。这个等价式值得单独推一遍（记 `a = arr[l] <= b = arr[l+k]`）：

- 若 `b <= x`（两者都在 x 左侧）：`dist(a) >= dist(b)`，等号只在 `a == b` 时成立（此时两个窗口的元素多重集**完全相同**，输出无差别）⟺ 与 `a + b >= 2x` 一致（`a + b <= 2x`，等号 ⟺ `a = b = x` 的退化情形）。
- 若 `a >= x`（两者都在 x 右侧）：`dist(a) <= dist(b)` 恒成立 ⇒ l 恒不劣 ⟺ `a + b >= 2x` 恒成立。
- 若 `a <= x <= b`（x 夹在中间）：`dist(a) <= dist(b) ⟺ x - a <= b - x ⟺ a + b >= 2x`。

三种情形合起来就是「l 不劣于 l+1 ⟺ `arr[l] + arr[l+k] >= 2x`」，而且**只要一次整数加法，连 abs 都不用算**。

**判据族定位**：本题属「**升序数组上的 K 元最优连续区间**」族 —— 候选解是 `n - k + 1` 个**长度固定**的连续区间，判据只由**两个端点的值**决定（与 §3.4 ① 表第二类「合法性只看两端点的值」同源）。

但**它不是 §3.4 的滑窗模板**，两处根本差异：

- 滑窗是「一端固定、另一端单调推进」；本题的收缩是**两端同时往里收**（左端只增、右端只减），既不共用滑窗的 `while/if` 收缩模板，也没有"答案 = 窗口长度"这种口径 —— **窗口长度恒为 k，答案是窗口的"位置"**，所以 §3.4 ⑥ 的四象限口径表在本题不适用（连"长度口径"都谈不上）。
- 二分版更是换了一条路线：把"位置"交给单调谓词定位，与 §3.4 整个滑窗族无交集。

### 关键点

- **弱单峰是本题一切结论的根基**：`|arr[i] - x|` 先弱减后弱增 ⇒ ① 最优解连续；② 区间最大键在端点。缺了任何一条，两端收缩就不再成立（对比：若数组无序，就得退回排序）。
- **平局规则不是细节，是判据本身的一部分**：`arr[l] + arr[l+k] >= 2x` 里的 `>=`、最终代码里 `a <= b` 里的 `<=`，都由"距离相同取更小值"直接决定。把 `>=` 写成 `>`，官方示例 1 立刻错（实测实得 `[2,3,4,5]`）。
- **二分式的下标范围天然安全**：`l ∈ [0, n-k]`，循环里 `mid <= n-k-1` ⇒ `mid + k <= n - 1`，右端点恒在界内，**不需要哨兵**（这也是这份写法比"在两侧造哨兵"更省事的地方）。
- 终止条件 `while right - left + 1 != k` 的正确性依赖不变量「每轮恰好删除一个元素」；写成 `>` 更稳（语义等价且不怕未来改动），写成 `>=` 则可能死循环。

## 三、代码实现

### 最终代码

```python
from typing import List


class Solution:
    def findClosestElements(self, arr: List[int], k: int, x: int) -> List[int]:
        n = len(arr)
        left, right = 0, n - 1
        a, b = abs(arr[left] - x), abs(arr[right] - x)
        while right - left + 1 != k:
            if a <= b:                 # 右端更远（或平局，平局取更小值，所以丢右端）
                right -= 1
                b = abs(arr[right] - x)
            else:
                left += 1
                a = abs(arr[left] - x)
        return arr[left : right + 1]
```

> 代码与截图逐行一致，截图未被裁切（状态栏报总行数 13，`return` 行完整）。

## 四、复杂度分析

| 版本 | 时间复杂度 | 空间复杂度 |
| :--- | :--- | :--- |
| **最终代码（两端收缩）** | O(n - k)（最坏 O(n)） | O(1)（不含 O(k) 的结果切片） |
| 排序取前 k（朴素） | O(n log n) | O(n) |
| 二分定位（本次优化） | O(log(n - k) + k) | O(1)（切片输出本身 O(k)） |
| 理论下界 | Ω(log(n - k) + k) | Ω(k) |

> 复杂度中的 n 指数组 `arr` 的长度，k 是要求的元素个数。
> 下界口径：候选左端点共 `n - k + 1` 个，在"只比较 `arr[l] + arr[l+k]` 与 `2x`"的单调谓词定位模型下至少需要 `log₂(n - k + 1)` 次比较；再叠加不可省的 `Ω(k)` 输出。用户的 O(n - k) 版本在 k 小时退化为 O(n)，因此**不是渐进最优**。

## 五、优化评估

**结论**：仍有优化空间。最终代码是 O(n - k) 的两端收缩，**k 小时退化成 O(n)**，达不到题面进阶要求的「优于 O(n)」；本次给出 O(log(n - k) + k) 的二分版并实测。

### 瓶颈分析

最终代码的耗时**严格 ∝ n - k**（每轮只做常数工作、恰好删掉一个元素），实测三档完全吻合这条规律：

- n = 10^4、k = 1 → **1122.85 μs**
- n = 10^4、k = 5000 → **566.15 μs**（约一半）
- n = 10^4、k = 10^4 → **15.48 μs**（不进循环，只剩一次 n 元素切片）

瓶颈百分之百落在「逐轮 Python 层循环」上。**但要把口径说清楚**：`n <= 10^4` 时最坏也就 1.1 ms，**远远不会 TLE** —— 这里优化的意义是满足进阶要求与渐进性（n 再涨一个数量级时，A 线性膨胀而 B 几乎不变），**不是**"不优化就过不了"。

### 可优化空间

把「逐个丢端点」换成「一次定位左端点」：候选左端点 `l ∈ [0, n-k]`，`h(l) = arr[l] + arr[l+k]` 单调不减 ⇒ 二分求第一个满足 `h(l) >= 2x` 的 l。定位成本 O(log(n - k))，再交给 C 层切片。

### 优化代码

```python
from typing import List


class Solution:
    def findClosestElements(self, arr: List[int], k: int, x: int) -> List[int]:
        n = len(arr)
        lo, hi = 0, n - k                      # 候选左端点区间 [0, n-k]
        while lo < hi:                         # 找第一个 arr[l] + arr[l+k] >= 2x
            mid = (lo + hi) // 2
            if arr[mid] + arr[mid + k] < x + x:
                lo = mid + 1                   # l 太靠左，窗口整体右移更好
            else:
                hi = mid                       # 平局留左（>= 里的等号就是平局规则）
        return arr[lo : lo + k]
```

**优化理由**：`h(l)` 两个加数都非减 ⇒ 谓词「`h(l) < 2x`」单调（真…真假…假），二分合法；`mid + k <= n - 1` 保证不越界。渐进上从 O(n - k) 降到 O(log(n - k) + k)，**k 越小收益越大**：实测 k = 1 时 649×（n = 10^4）/ 149×（n = 2000），k = n/2 时 40~67×，**k = n 时仍不亏**（0.93×，逐轮比值区间不跨 1.0）。

### 对照路线与实测

另有一条等价路线 **C = `bisect_left` 定位插入点 + 向两侧扩张 k 次**（本次新写，一并实测）：

```python
from bisect import bisect_left
from typing import List


class Solution:
    def findClosestElements(self, arr: List[int], k: int, x: int) -> List[int]:
        n = len(arr)
        p = bisect_left(arr, x)
        lo = hi = p
        while hi - lo < k:
            if lo == 0:                        # 守卫：防 arr[lo-1] 变成 arr[-1]
                hi += 1
            elif hi == n:
                lo -= 1
            elif x - arr[lo - 1] <= arr[hi] - x:   # 平局取左侧（更小值）
                lo -= 1
            else:
                hi += 1
        return arr[lo:hi]
```

**实测（7 轮轮转取最优，单位 μs）**：

| 场景 | A 用户版 | B 二分 | B₂ 二分（abs 写法） | C bisect + 扩张 |
| :--- | ---: | ---: | ---: | ---: |
| n = 2000, k = 1 | 210.38 | 1.41 | 1.48 | 0.41 |
| n = 2000, k = 1000 | 116.35 | 2.87 | 2.78 | 120.51 |
| n = 2000, k = 2000 | 3.27 | 3.04 | 2.99 | 237.03 |
| n = 10000, k = 1 | 1122.85 | 1.73 | 1.69 | 0.40 |
| n = 10000, k = 5000 | 566.15 | 8.67 | 8.70 | 579.73 |
| n = 10000, k = 10000 | 15.48 | 14.37 | 14.47 | 1154.75 |

**以 A 为 1.00 的倍数（< 1 表示更快）**：

| 场景 | B 二分 | B₂ 二分（abs） | C bisect + 扩张 |
| :--- | ---: | ---: | ---: |
| n = 2000, k = 1 | 0.007 | 0.007 | 0.002 |
| n = 2000, k = 1000 | 0.025 | 0.024 | 1.036（逐轮 0.931~1.191，噪声内持平） |
| n = 2000, k = 2000 | 0.929 | 0.915 | 72.552 |
| n = 10000, k = 1 | 0.002 | 0.002 | 0.000 |
| n = 10000, k = 5000 | 0.015 | 0.015 | 1.024（逐轮 0.994~1.108，噪声内持平） |
| n = 10000, k = 10000 | 0.928 | 0.934 | 74.575 |

**读表结论**：

- **B 六档全不亏**（最差 0.934×，且六档的逐轮比值区间都**不跨 1.0** ⇒ 是稳定收益而非常数噪声）；耗时随 n 的增长几乎可以忽略（1.41 μs → 14.37 μs 的那部分几乎全是切片本身），与理论一致。
- **C 的收益结构与 B 完全不同**：它把"定位"交给 C 层的 `bisect`，所以 `k = 1` 时甚至比 B 还快（0.40 μs vs 1.73 μs，4.3×）；但代价是必须在 Python 层**扩张 k 次** ⇒ k = n/2 时与 A 持平（逐轮跨 1.0），k = n 时反而慢 70 倍以上。⇒ 两者**不是替代关系**：B 是"全场景稳赚"，C 只在「定位贵、扩张便宜」（k 很小）时更优。选 B。
- **B 与 B₂ 逐位等价**（56 组用例输出完全相同），实测常数也无差别（两列逐轮区间互相重叠）⇒ 选哪个只关乎可读性；推荐 `arr[l] + arr[l+k] >= 2x` 形式，因为它把单调性写在脸上。

### 常数级优化

本次**不做**常数级优化，依据是实测数字本身：二分那一段的绝对耗时只有 ≈ 1.4 ~ 1.7 μs（可由 `k = 1` 档的 B 读数近似，那一档切片只含 1 个元素），而端到端在 `k = n` 档已经是 14.37 μs（由 n 元素切片主导）⇒ 可压缩的天花板在 2 μs 量级，收益低于测量噪声。`x + x` 提到循环外、`lo/hi` 局部绑定这类改法**本次未测**，故不写结论。

## 六、易错点与总结

### 易错点

- **平局方向写反**（本题最高频的错）：判据 `arr[l] + arr[l+k] >= 2x` 改成 `>`，等价于把"距离相同取更小值"翻成"取更大值" ⇒ **官方示例 1 直接错**（真值 `[1,2,3,4]`、实得 `[2,3,4,5]`）。最终代码里对应的是 `a <= b`，写成 `a < b` 会犯同一个错（静态推导，未跑）。
- **C 式扩张必须留 `lo == 0` / `hi == n` 守卫**：删掉左侧守卫后 `arr[lo-1]` 退化为 `arr[-1]`（Python **静默取到最后一个元素**），不抛异常、答案只是错 —— 40 组随机用例错 **11 组**，最小反例 `arr = [3,7], k = 1, x = 2`：真值 `[3]`、实得 `[]`。与"计数/答案出现负数 = 判据写错"同属「结果荒谬但一不报错」的信号。
- **二分下标边界**：`arr[mid] + arr[mid+k]` 中 `mid` 最大 `n-k-1` ⇒ `mid+k <= n-1` 天然安全；一旦改写成 `arr[mid+k+1]` 就会越界。
- **终止条件**：`while right - left + 1 != k` 依赖"每轮恰好删一个"这个不变量，写 `>` 更稳；写成 `>=` 可能死循环。
- **返回顺序**：本题窗口恒连续 ⇒ 切片天然升序；若改用"按距离取 k 个再重新排序"的写法，别忘了最后再排一次（示例 2 的 `[1,1,2,3]` 就是靠这个才成立的）。
- `k = n` 时循环一次都不进（`right - left + 1 == n == k`），直接返回整段 —— 这条退化路径不要漏。

### 题型套路沉淀

- **「升序数组 + 找 k 个最接近」= 固定长度最优连续区间**。标准两步：先证连续（弱单峰 ⇒ 子水平集是区间），再定位左端点。定位有两招 —— 两端收缩 O(n - k)（写起来最短、平局规则最直观）、二分谓词 O(log(n - k))（进阶要求的答案）。
- **只要候选解是"长度固定的连续区间"，就能把"窗口 l 与 l+1 谁更好"写成关于 l 的单调谓词** ⇒ 二分。转化的入口是"两个窗口只差一个端点元素"，本题里正好退化成一次整数加法 `arr[l] + arr[l+k] >= 2x`（连 abs 都不需要）。
- **平局规则要翻译成判据里的不等号方向**：先用一个小例子（示例 1 的 1 vs 5）确认"平局取哪一侧"，再决定写 `>=` 还是 `>`。这一步做对了，本题一半的坑就没了。
- **「定位 + 扩张」与「二分 + 切片」是两种不同的成本结构**：前者定位便宜（C 层 `bisect`）但要 Python 层扩张 k 次，后者定位稍贵但输出走 C 层切片。k 小选前者、k 大选后者；本题因 `k <= n` 且要覆盖全场景，选二分 + 切片。
