# 1891. 割绳子

> **难度**：中等
> **标签**：二分
> **原题链接**：https://leetcode.cn/problems/cutting-ribbons/

---

## 一、题目描述

给定长度数组 `ribbons`（`ribbons[i]` 是第 i 条绳子的长度）和一个整数 `k`。每条绳子可以切成任意多个**正整数长度**的小段，也可以选择不切；切完剩下的碎料允许丢弃。

要求找出**最大的 `x`**，使得能切出**至少 `k` 段**长度都恰好等于 `x` 的绳子；如果无论如何都凑不够 `k` 段，返回 `0`。

关键点：每根绳子最多贡献 `⌊len / x⌋` 段，余料不计入。

### 示例

```text
输入：ribbons = [9,7,5], k = 3
输出：5
解释：9 -> 5 + 4，7 -> 5 + 2，5 保持不动，一共得到 3 段长度为 5 的绳子。

输入：ribbons = [7,5,9], k = 4
输出：4
解释：7 -> 4 + 3，5 -> 4 + 1，9 -> 4 + 4 + 1，一共得到 4 段长度为 4 的绳子。

输入：ribbons = [5,7,9], k = 22
输出：0
解释：总长度 5 + 7 + 9 = 21 < 22，即使全部切成 1 也凑不出 22 段，返回 0。
```

### 约束条件

- `1 <= ribbons.length <= 10^5`
- `1 <= ribbons[i] <= 10^5`
- `1 <= k <= 10^9`

---

## 二、解题思路

### 核心思想

**答案具有单调性**：段长 `x` 越小越容易凑够 `k` 段，越大越难。所以不去枚举 `x`，而是在值域上**二分答案**——判定某个 `x` 是否可行，只需把每条绳子的贡献 `ribbons[i] // x` 累加，看是否达到 `k`。

### 思路演进

1. **暴力解法**：从 `x = 1` 逐个试到 `max(ribbons)`，每个 `x` 扫一遍数组统计能切出多少段，取最大的可行值。时间 O(n · C)（C = `max(ribbons)`）。本题 C 与 n 都能到 10^5，量级 10^10，必然超时。
2. **观察到**：判定函数 `count(x) = Σ ⌊ribbons[i] / x⌋` 关于 `x` **单调不增** —— `x` 变大时每条绳子的贡献只会变少或不变，绝不会变多。于是可行域必然是 `[1, ans]` 这样一段**前缀**：小于等于 `ans` 的 `x` 全部可行，大于 `ans` 的全部不可行。
3. **优化为**：在一段「前真后假」的序列上二分边界，目标从「枚举所有 x」变成「找**最后一个可行的 x**」。用 `left` 表示当前已知可行的位置、`right` 表示当前已知不可行的位置，每次取 `mid` 判定：可行就把 `left` 抬到 `mid`，不可行就把 `right` 压到 `mid`；循环结束时 `left` 即答案。

`left` 的初值需要一点技巧：`x = 0` 没有意义（会除零），所以只能用 `0` 当**占位哨兵**——它本身不参与判定（`mid` 的最小值是 1），但能让"无解"自然落地；`right` 则取 `max(ribbons) + 1` 当"一定不可行"的哨兵，因为不可能切出比最长绳子还长的段。这样区间天然覆盖了无解情形：无解时所有 `x ≥ 1` 都判定失败，`left` 原地不动停在 `0`，直接返回 0。

### 关键点

- **单调性是二分的入场券**：先确认 `count(x)` 随 `x` 单调不增，才敢二分边界。
- **哨兵设计**：`left = 0`（值域下方的占位，不参与判定）、`right = max(ribbons) + 1`（一定不可行）。由于判定只对 `mid ∈ [1, max(ribbons)]` 执行，不会出现除以 0。
- **`sum(ribbons) < k` 提前返回 0 是冗余但无害的**：因为 `left` 从 0 起步，即使删掉这一行，二分也会收敛到 0 返回正确答案；保留它只是让"总长都不够"的无解场景**跳过整轮二分**，更快也更直白。
- `check` 里的 `if i < t: continue` 等价于跳过 `i // t == 0` 的绳子；`ans >= k` 时立即 `return True`，让判定在多数情况下提前结束。

## 三、代码实现

### 最终代码

```python
from typing import List


class Solution:
    def maxLength(self, ribbons: List[int], k: int) -> int:
        if sum(ribbons) < k:
            return 0

        def check(t: int) -> bool:
            ans = 0
            for i in ribbons:
                if i < t:
                    continue
                ans += i // t
                if ans >= k:
                    return True
            return False

        left = 0
        right = max(ribbons) + 1
        while left + 1 < right:
            mid = (left + right) // 2
            if check(mid):
                left = mid
            else:
                right = mid
        return left
```

## 四、复杂度分析

| 版本 | 时间复杂度 | 空间复杂度 |
| :--- | :--- | :--- |
| **最终代码** | O(n log C) | O(1) |
| 朴素解法（枚举 x） | O(n · C) | O(1) |
| 理论下界 | O(n) | O(1) |

> 复杂度中的 n 指绳子条数（`ribbons` 的长度），C = `max(ribbons)`（本题 C ≤ 10^5），对数以 2 为底。
> 空间复杂度不计输入数组本身，额外只用 `ans` / `left` / `mid` 等常数个变量。

## 五、优化评估

**结论**：已经是最优解法，没有进一步的大 O 级优化空间。

### 瓶颈分析

- 时间：一次判定要扫完整条数组，O(n)；二分把值域从 C 压到 log C ≈ 17 次。合计 O(n log C)，在 n、C 均 ≤ 10^5 时约 1.7 × 10^6 次基本操作，远在时限之内。
- 空间：全程只用常数个整型变量，O(1)。

### 可优化空间

- **时间下界是 Ω(n)**：答案必须看过每一条绳子才可能确定，任何算法都逃不掉一次全量读入；本解法只多了一个 log C ≈ 17 的因子。
- **值域本身很窄**：C ≤ 10^5，log C 已经是小常数，二分次数基本可以当成"固定若干轮"。
- 结论：**无需再优化**。

### 常数级优化（可选）

- 大 O 不变的两处提前退出（都是原代码里已有的）：
  - `if sum(ribbons) < k: return 0`：只在总长不够时为真，命中时 O(n) 直接返回，省掉后面整轮二分。
  - `check` 中累计到 `ans >= k` 就 `return True`：不必扫完剩余绳子。
- 两者都只在有利的输入形态上生效，最坏情况下的复杂度与轮数都不变。

## 六、易错点与总结

### 易错点

- **`left` 初值写成 1**：`left = 0` 是"无解时也能自然收敛"的哨兵。改成 1 之后，遇到 `sum(ribbons) < k` 这类无解输入会错误返回 1 而不是 0。
- **`right` 取成 `max(ribbons)`**：必须取 `max(ribbons) + 1`。因为 `x = max(ribbons)` 是**可能可行**的（正好用最长的那条绳子切出一段），不能把它当作已知不可行的边界。
- **判定口径写反**：`check` 判定的是"能凑够 k 段"这个**可行**条件——可行推 `left`，不可行推 `right`，别写反。
- **段长必须是正整数**：`x` 从 1 起，判定不可能取 0；只要保证 `right ≥ 2`（`max(ribbons) ≥ 1` 且加 1）、`mid ≥ 1`，就不会除零。
- **`k` 上界是 10^9**：Python 的整数无溢出之忧，但换成 C++ / Java 时累加值必须用 `long` / `long long`，否则 `Σ ribbons[i] // x` 会撑爆 `int`。

### 题型套路沉淀

- **二分答案（Binary Search on the Answer）**：当题目要求"最大化 / 最小化某个值"、且该值的**可行性判定单调**时，就把问题转成"在值域上二分边界 + 写一个 O(n) 的判定函数"。
- 固定四步：
  1. 写出判定函数 `check(x)`（本题：`Σ ⌊ribbons[i] / x⌋ >= k`）；
  2. 确认单调性（`x` 增大，判定结果由真变假）；
  3. 用两个哨兵夹住边界，`while left + 1 < right` 循环，返回 `left`；
  4. 处理无解边界（本题：`left` 从 0 起步，无解自然返回 0）。
- **哨兵的意义**：`left` 放在值域下界之下作占位（本题取 0，避免除零），`right` 取"一定不可行"的值（`max + 1`）；两侧都留一个确定的位置，循环终止条件 `left + 1 < right` 才能真正锁住边界。
- 判定函数里"一旦满足条件就提前 return"是这类题的常规写法。
