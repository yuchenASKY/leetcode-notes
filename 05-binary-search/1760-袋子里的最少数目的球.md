# 1760. 袋子里最少数目的球

> **难度**：中等
> **标签**：数组 · 二分查找
> **原题链接**：https://leetcode.cn/problems/minimum-limit-of-balls-in-a-bag/

---

## 一、题目描述

给定数组 `nums`（`nums[i]` 是第 `i` 个袋子里的球数）和操作上限 `maxOperations`。每次操作可以选一个袋子，把它里面的球**全部**分进两个新袋子，且两个新袋子都必须装**正整数**个球（即不能分出空袋子）。最多操作 `maxOperations` 次后，记**所有袋子中球数的最大值**为开销，求能得到的**最小开销**。

### 示例

```text
输入：nums = [9], maxOperations = 2
输出：3
解释：[9] -> [6,3] -> [3,3,3]，最大袋子有 3 个球

输入：nums = [2,4,8,2], maxOperations = 4
输出：2

输入：nums = [7,17], maxOperations = 2
输出：7
```

### 约束条件

- `1 <= nums.length <= 10^5`
- `1 <= maxOperations, nums[i] <= 10^9`

---

## 二、解题思路

### 核心思想

**「最小化最大值」＝ 二分答案。** 把问题反过来问：给定一个开销上限 `t`，能不能在 `maxOperations` 次内把所有袋子拆成每袋不超过 `t`？这个判定关于 `t` 单调，于是二分 `t` 即可。

### 思路演进

1. **暴力解法**：开销的可能取值只有 1 ~ `max(nums)`，从 1 开始逐个试，第一个能行的就是答案。每次判定要扫一遍数组统计操作数，总时间 O(n · max(nums))。`nums[i]` 可达 10^9，值域直接爆炸。
2. **观察到**：
   - **判定函数是单调的** —— 上限 `t` 放宽（变大），每个袋子需要的切分次数只会变少或不变，绝不会变多。若 `t` 可行，则任何 `t' > t` 也一定可行；若 `t` 不可行，则任何 `t' < t` 也一定不可行。⇒ 可行域是值域上的一个**后缀**，边界点就是答案，天然适合二分。
   - **判定本身可以 O(1) 算清**：一个装了 `i` 个球的袋子，要切成每份不超过 `t`，最少需要切成 `ceil(i / t)` 份，也就是切 `ceil(i / t) - 1` 次。等价于 `(i - 1) // t`（`i <= t` 时为 0，正好不用动）。所有袋子求和，与 `maxOperations` 比大小即可。
3. **优化为**：二分答案。在区间 `[lo, hi]` 上找**最小的可行 `t`**，用「左开右闭」的写法（`lo` 恒为不可行点、`hi` 恒为可行点，循环不变量成立时 `right` 即答案）。

### 关键点

- **单调性是二分答案的入场券**：先验证「可行性随 `t` 单调」，再去写二分，这题的单调性来自「份数随上限变大而单调不增」。
- **切分次数的闭式表达**：`(i - 1) // t`。自己推一遍比记公式可靠 —— `ceil(i/t) - 1 = (i + t - 1)//t - 1 = (i - 1)//t`。
- **只对 `i > t` 的袋子计数**：`i <= t` 的袋子不用切，`(i - 1) // t` 本来就等于 0，但显式跳过更直观（也避免对无需处理的袋子做除法）。
- **提前剪枝**：统计到 `cnt > maxOperations` 立刻返回 `False`，不必扫完整个数组。
- **区间下界是承重的**：循环结束后返回 `right`，前提是 `right` 一定落在可行点上。因此初始必须让 `left` 落在**确实不可行**的位置。这里取 `left = max(total // (n + maxOperations) - 1, 0)`：由「切 `i` 个球至少需要 `i/t - 1` 次」累加可知，可行解必满足 `total/t - n <= maxOperations`，即 `t >= total / (n + maxOperations)`；再减 1 保证 `left` 落在该下界之下，谓词必为假。**若贪掉这个 `-1`，当 `left` 恰好可行时二分就会返回错误答案。**
- **上界取 `max(nums) + 1`**：`t = max(nums)` 时一个袋子都不用切，必然可行；写成 `+1` 是为了让区间右端保持「开」的语义，`while left + 1 < right` 收敛后 `right` 才严格是第一个可行点。
- **不要在判定里真的去模拟分袋子**：不需要知道怎么分，只需要知道「分几次」。这是把构造问题降成计数问题的关键一跳。

## 三、代码实现

### 最终代码

```python
from typing import List   # 截图里没有、已补


class Solution:
    def minimumSize(self, nums: List[int], maxOperations: int) -> int:
        total = sum(nums)
        n = len(nums)

        # 左开右闭二分：[left, right]，left 恒不可行、right 恒可行
        left = max(total // (n + maxOperations) - 1, 0)
        right = max(nums) + 1

        def check(t: int) -> bool:
            """开销上限为 t 时，所需操作数是否 <= maxOperations"""
            cnt = 0
            for i in nums:
                if i > t:
                    cnt += (i - 1) // t      # ceil(i / t) - 1
                    if cnt > maxOperations:
                        return False
            return True

        while left + 1 < right:
            mid = (left + right) // 2
            if check(mid):
                right = mid
            else:
                left = mid
        return right
```

## 四、复杂度分析

| 版本 | 时间复杂度 | 空间复杂度 |
| :--- | :--- | :--- |
| **最终代码** | O(n log M) | O(1) |
| 朴素解法（枚举每个可能的开销） | O(n · M) | O(1) |
| 理论下界 | O(n log M) | O(1) |

> 复杂度中的 n 指数组 `nums` 的长度，M 指 `max(nums)`（也就是答案的值域上界）。
> 二分轮数为 O(log M)，每轮判定扫一遍数组为 O(n)，故总计 O(n log M)。额外空间只有常数个计数器。

## 五、优化评估

**结论**：已是该思路下的**最优解**，无进一步可优化项。

### 瓶颈分析

时间由「二分轮数 × 每轮判定开销」两部分决定：

- 轮数：答案在 `[0, M]` 值域内，每轮砍一半，`log2(10^9) ≈ 30` 轮，无法再少；
- 每轮：判定必须把每个袋子都过一遍才能知道总次数，O(n) 不可省。

空间上没有任何中间数据结构，纯常数级。

### 可优化空间

没有实质空间，原因是：

- 时间上，`n` 与值域 `M` 与本解规模同阶地决定了信息量 —— 既不能不看完全部袋子（漏掉一个大袋子就会把不可行误判为可行），也不能跳过值域上的二分；
- 空间上，判定函数是「一次求和」，天然流式，不存在可压缩的存储。

因此本解达到了该问题的理论上界，**不需要也不应该再引入额外结构**。

## 六、易错点与总结

### 易错点

- **判定口径写错**：把切分次数写成 `i // t` 或 `(i + t - 1) // t`。正确的是 `ceil(i / t) - 1 = (i - 1) // t`；用 `i // t` 会在 `t` 整除 `i` 时多算一次，导致答案偏大。
- **区间下界漏掉 `- 1`**：`left` 必须落在真正的不可行点上，否则 `right` 的语义被破坏，二分收敛到错误的位置。
- **二分写法混用**：这里用的是左开右闭（`left` 不可行、`right` 可行），所以循环条件是 `left + 1 < right`、返回 `right`。若改成闭区间写法，`mid`、边界更新、返回值三处都要同步改，不能只改一处。
- **剪枝位置放错**：`cnt > maxOperations` 的提前返回要放在**累加之后、继续遍历之前**；漏掉它虽然不影响正确性，但会白扫完整个数组。
- **把判定写成「真的去模拟分袋子」**：多此一举，还会引入不必要的复杂度。判定只需计数。

### 题型套路沉淀

- **「最小化最大值 / 最大化最小值 / 第 K 小」→ 立刻想二分答案**。识别信号：答案本身是一个数值，而且「给个上限能不能做到」容易判定。
- **二分答案的三件套**（缺一不可）：
  1. **上下界**：下界要取到"真正的不可行点"，上界要取到"必然可行的点"；
  2. **判定函数 `check(t)`**：把"构造/模拟"降级成"计数/比较"；
  3. **单调性论证**：先证明可行域是值域上的前缀或后缀，再动手写二分。
- **判定式问题的通用跳法**：不要构造方案，只算"最少几步"。本题是 `ceil(i/t) - 1`，与 `875. 爱吃香蕉的珂珂`、`1283. 使结果不超过阈值的最小除数`、`410. 分割数组的最大值` 属同一骨架（按自身题意独立推导判定式，不要照抄别题）。
- 二分的边界习惯：**左开右闭 + 返回 `right`**，能天然避免"答案恰好等于下界时返回错误"这一类 off-by-one。
