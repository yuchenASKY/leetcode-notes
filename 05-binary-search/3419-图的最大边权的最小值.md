# 3419. 图的最大边权的最小值

> **难度**：中等
> **标签**：二分答案 · 图 · 深度优先搜索
> **原题链接**：https://leetcode.cn/problems/minimize-the-maximum-edge-weight-of-graph/

---

## 一、题目描述

给一个有向带权图（`n` 个节点、边形如 `[A, B, W]`），可以删掉任意多条边，要求剩下的图满足：

1. 除 0 号节点外，**所有节点都能走到 0**；
2. 每个节点的**出度不超过 `threshold`**；
3. 让剩余边的**最大边权尽量小**。

求这个「最大边权的可能最小值」；无解返回 `-1`。

### 示例

```text
输入：n = 5, edges = [[1,0,1],[2,0,2],[3,0,1],[4,3,1],[2,1,1]], threshold = 2
输出：1
解释：删掉边 2 -> 0（权值 2），剩下的边最大权值是 1，且所有点仍能到 0。

输入：n = 5, edges = [[0,1,1],[0,2,2],[0,3,1],[0,4,1],[1,2,1],[1,4,1]], threshold = 1
输出：-1
解释：所有边都是 0 出发的，节点 2 没有任何路径能回到 0。

输入：n = 5, edges = [[1,2,1],[1,3,3],[1,4,5],[2,3,2],[3,4,2],[4,0,1]], threshold = 1
输出：2
解释：删掉 1 -> 3 和 1 -> 4，剩下的边最大权值为 2。
```

### 约束条件

- `2 <= n <= 10^5`
- `1 <= threshold <= n - 1`
- `1 <= edges.length <= min(10^5, n * (n - 1) / 2)`
- `0 <= A_i, B_i < n`，`A_i != B_i`
- `1 <= W_i <= 10^6`
- 一对节点之间可能有多条边，但权值互不相同

## 二、解题思路

### 核心思想

**答案本身就是一个边权值 → 二分答案；判定「只留下边权 ≤ X 的边时能否全部到达 0」→ 建反图后从 0 出发做一次 DFS 计数。**

### 思路演进

1. **暴力解法**：答案一定取某条边的权值。把出现过的边权从小到大排序，逐个当作「最大边权上限」去验证，第一个通过的即答案。每验证一次要重建子图 + 一次遍历，总代价 O(m(n + m))；若直接在值域 `[1, max_w]` 上顺序枚举，最坏是 O(W(n + m))，更慢。

2. **观察到**：判定函数关于「上限 X」是**单调**的 —— X 变大只会让可用的边变多，不会让原本能到达的点变少。记 `check(X) = 「只保留边权 ≤ X 的边时，所有点都能到达 0」`，则 `check` 形如 `False...False True...True`。

3. **优化为**：单调谓词上的答案直接二分。在值域 `[1, max_w]` 上二分最小的可行 X，每轮判定 O(n + m)，总复杂度 O((n + m) log W)，W ≤ 10^6 时只有约 20 轮。

4. **判定的实现（正难则反）**：「所有点到 0」是**多起点汇入**，而「0 到所有点」是**单起点遍历**。把每条边 `x -> y` 反向存成 `y -> x`，于是条件变成「从 0 出发能走到全部 n 个点」，一遍 DFS 累加访问计数，等于 n 即通过。

5. **`threshold` 是干扰项**：反图视角下，「每个节点至多 `threshold` 条出边」变成「每个节点至多 `threshold` 条**入**边」。而 0 到每个点的可达性只需要每个点保留**一条**入边（DFS 树的父边）就够了 —— 反图里每个点 1 条入边 ⇒ 原图里每个点 1 条出边，而题面保证 `threshold >= 1`，永远不越界；如果可达性本来就能满足，多留几条边也只会更宽松。**所以 threshold 完全不影响答案，无需在判定中处理。**

### 关键点

- **二分的是值域不是下标**：候选答案就是边权本身，直接在 `range(max_w + 1)` 上二分，不必先去重边权再对数组二分。
- **单调性来自「加边不劣」**：这是所有「最小化最大值」类二分答案题的通用的二分依据。
- **反图 + 单源遍历**：把「汇入 0」改成「从 0 出发」，判定的写法才干净（不用考虑环，访问过的点不再访问）。
- **`vis` 复用技巧**：把「本轮的 `upper`」当作访问标记的取值，就不必每轮 `[False] * n` 重新分配；因为每轮的 `upper` 互不相同，天然等价于一次清空。
- **无解的两种情形**：① 边数不足 `n - 1`（每个非 0 点至少要留 1 条出边）；② 即使放开到最大边权也到不齐所有点。

## 三、代码实现

### 最终代码

```python
from typing import List
from bisect import bisect_left


class Solution:
    def minMaxWeight(self, n: int, edges: List[List[int]], threshold: int) -> int:
        if len(edges) < n - 1:          # 每个非 0 点至少要留一条出边
            return -1

        g = [[] for _ in range(n)]      # 建反图：x -> y 存成 y -> (x, w)
        for x, y, w in edges:
            g[y].append((x, w))

        vis = [0] * n                   # 用 upper 当标记值，避免每轮重建 vis

        def check(upper: int) -> bool:
            def dfs(x: int) -> int:
                vis[x] = upper
                cnt = 1
                for y, w in g[x]:
                    if w <= upper and vis[y] != upper:
                        cnt += dfs(y)
                return cnt
            return dfs(0) == n          # 从 0 出发能否覆盖全部节点

        max_w = max(e[2] for e in edges)
        ans = bisect_left(range(max_w + 1), True, 1, key=check)
        return -1 if ans > max_w else ans
```

> 代码取自提交通过的版本；截图里没有 `from typing import List` 与 `from bisect import bisect_left`，此处已补齐。

## 四、复杂度分析

| 版本 | 时间复杂度 | 空间复杂度 |
| :--- | :--- | :--- |
| **最终代码** | O((n + m) log W) | O(n + m) |
| 朴素解法（枚举每个候选边权） | O(m(n + m)) | O(n + m) |
| 理论下界 | O(n + m) | O(n + m) |

> 复杂度中的 n 指节点数，m 指 `edges` 的长度，W 指最大边权（本题 W ≤ 10^6，故 log W ≤ 20）。
>
> 二分轮数是 log W 而非 log m，因为直接在值域上二分；候选集合从 W 收窄到「实际出现过的 m 个边权」也仍是同阶。

## 五、优化评估

**结论**：时间复杂度已接近理论下界，**没有再优化一个数量级的空间**。

### 瓶颈分析

- 判定一次必须至少摸到每个节点和每条可用边（否则无法确认可达性），单轮 O(n + m) 是必要的。
- 总复杂度 = 判定代价 × 二分轮数。二分轮数 log W ≤ 20 已经很小，且无法再降：判定是黑箱单调谓词，信息论上至少需要 log(值域大小) 次调用。
- 空间上，反图必须显式存下来（要么反图邻接表，要么原图 + 反向遍历），O(n + m) 无法压缩；DFS 的递归深度最坏为 O(n)。

### 可优化空间

- **时间**：任何解法都至少要看一遍 `edges` 才能确定最大边权（Ω(m)），所以下界是 O(n + m)；当前多出的 log W 因子来自「判定问题的答案只能靠多次调用逼近」，属于二分类问题的固有代价。
- **空间**：如果题目允许原地改动 `edges` 的顺序，可以把反图压成 CSR 式的两个数组，常数更小，但大 O 不变。

## 六、易错点与总结

### 易错点

- **`bisect_left` 的 `key` 语义**：这里把它当作「在布尔序列上找第一个 `True`」用。`key=check` 时比较的是 `check(mid) < True`，即 `check(mid) == False` 的位置全部排在左边，返回的就是最小的可行值。
- **`lo` 与「无解」的表达**：从 `lo = 1` 开始（边权 ≥ 1，更小的值不可能可行），`hi` 取 `max_w + 1`（开区间）。若返回 `max_w + 1`，说明值域内没有一个可行值 → 返回 `-1`。
- **不要试图把 `threshold` 塞进判定**：它不是约束，只是一个干扰条件；把它写进 DFS（比如限制每点最多访问 `threshold` 次）反而会写错。
- **递归深度**：n 最大 10^5，递归 DFS 深度最坏 O(n)，Python 默认递归上限是 1000，本地跑需要提高 `sys.setrecursionlimit`；提交到 LeetCode 时该代码已通过。
- **别漏掉「边太少」这个早退**：`len(edges) < n - 1` 可以直接返回 -1，能省掉一整轮二分的无效判定。

### 题型套路沉淀

- **「最小化最大值 / 最大化最小值」= 二分答案 + 可行性判定**：看到这类措辞，先把问题改写成「给定阈值 X，是否存在合法方案」，再检查这个谓词关于 X 是否单调 —— 单调即可二分。
- **二分对象优先选值域**：当答案物理意义就是一个数值（边权、距离、容量）时，直接对值域二分，比先提取候选集合再二分更省事，复杂度同阶。
- **判定问题往图论标准件上靠**：可达性 → BFS/DFS 计数；「多源汇入一点」→ 反图转成「单源扩散」；判定里出现环不用怕，用一个 `vis` 就够了。
- **警惕题干里的干扰约束**：本题的 `threshold` 看似是硬约束，实际上永远不生效。读题时先问一句「这个条件真的会限制答案吗」，能避免把判定函数写复杂。
- **`vis` 的一轮一换可以省**：用「当前阈值」当访问标记值，多轮复用同一个数组，是有环图多次判定时的常用写法。
