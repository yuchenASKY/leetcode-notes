# 1201. 丑数 III

> **难度**：中等
> **标签**：数学 · 二分查找 · 容斥原理
> **原题链接**：https://leetcode.cn/problems/ugly-number-iii/

---

## 一、题目描述

「丑数」定义为**能被 `a` 或 `b` 或 `c` 整除**的正整数（注意：不是因子只含 `a`、`b`、`c` 的那种丑数，这里只看「能否整除」）。

给定 `n, a, b, c`，求按从小到大排列时第 `n` 个丑数。

### 示例

```text
输入：n = 3, a = 2, b = 3, c = 5
输出：4
解释：丑数序列为 2, 3, 4, 5, 6, 8, 9, 10... 其中第 3 个是 4。

输入：n = 4, a = 2, b = 3, c = 4
输出：6
解释：丑数序列为 2, 3, 4, 6, 8, 9, 10, 12... 其中第 4 个是 6。

输入：n = 5, a = 2, b = 11, c = 13
输出：10
解释：丑数序列为 2, 4, 6, 8, 10, 11, 12, 13... 其中第 5 个是 10。
```

### 约束条件

- `1 <= n, a, b, c <= 10^9`
- `1 <= a * b * c <= 10^18`
- 本题结果在 `[1, 2 * 10^9]` 的范围内

---

## 二、解题思路

### 核心思想

**不生成丑数，改成「数」丑数。** 定义 `cnt(t)` = 区间 `[1, t]` 内丑数的个数，它可以用容斥原理 `O(1)` 算出来；而 `cnt(t)` 随 `t` 单调不降，于是「第 `n` 个丑数」= **使 `cnt(t) >= n` 成立的最小 `t`**，直接二分答案。

### 思路演进

1. **逐个数（最朴素）**：从 1 开始往上扫，每个数判断能否被 `a` / `b` / `c` 整除，数到第 `n` 个就停。单次判断是 `O(1)`，但要走完答案本身 —— 答案可达 `2 * 10^9`，`n` 也可达 `10^9`，量级上完全不可行。

2. **把它当普通「丑数」那样生成**：三指针归并（每次取三个候选里的最小值）或小顶堆，能按顺序生成丑数序列，代价 `O(n)`（堆是 `O(n log 3)`）。但这里的 `n` 是 `10^9` —— 要真生成十亿项，依然过不去；而且 `a`、`b` 的公倍数会被重复生成，还需要额外的去重成本。

3. **关键转化：从「求第 n 个」倒过来问「有多少个」**：与其一个一个地产出，不如给定一个上界 `t`，一次算出 `≤ t` 的丑数有多少个。由于「被 `a` 或 `b` 或 `c` 整除」是一个**并集**，用容斥即可：

   ```
   cnt(t) = ⌊t/a⌋ + ⌊t/b⌋ + ⌊t/c⌋
          − ⌊t/lcm(a,b)⌋ − ⌊t/lcm(b,c)⌋ − ⌊t/lcm(a,c)⌋
          + ⌊t/lcm(a,b,c)⌋
   ```

   三个单集相加，两两交集（即被 `lcm` 整除的数）被算了两次所以要减掉，三数交集又被减多了所以加回来 —— 标准的三集合容斥，共 7 次整除。

4. **计数单调 ⇒ 二分**：`t` 变大时 `cnt(t)` 只会变大（后面的丑数只增不减），把 `cnt(t) >= n` 看成一条「从某处开始恒真的前缀”，二分找这条前缀的左端点即可。判定一次是 `O(1)`，二分只需 `O(log 答案)` 轮。

### 关键点

- **判定必须是 `cnt(t) >= n`，不能是 `== n`**：`cnt` 是阶梯函数，在答案处可能从 `n-1` 直接跳到 `n+2`（中间那几个数不是丑数），所以「恰好等于 `n`」的 `t` 甚至可能不存在。只有第一个满足 `>= n` 的位置才是答案。
- **交集用 `lcm` 而不是乘积**：被 `a` 和 `b` 同时整除的数是 `lcm(a,b)` 的倍数，直接用 `a*b` 会漏算（`a`、`b` 不互质时尤其明显，如 `a=2, b=4`）。
- **`lcm` 在二分外算一次即可**：四个 `lcm` 值（三个两两 + 一个三数）与 `t` 无关，循环里反复算纯属浪费。
- **二分区间怎么定**：`right = min(a,b,c) * n` 一定可行 —— 光靠最小那个数的倍数就已经有 `n` 个；`left` 只需要是一个「一定不满足」的左端点，取 `min(a,b,c) + n - 2` 把区间压窄一点（第 `n` 个丑数必然在它之后），换成 `left = 0` 结论不变，只是多几轮二分。
- **循环写法用 `left + 1 < right`**：区间始终保持「`left` 不满足、`right` 满足」，退出时 `right` 就是答案，既不用纠结 `while left <= right` 的 `mid` 取整方向，也不会死循环。

## 三、代码实现

### 最终代码

```python
import math          # 截图里没有，已补

class Solution:
    def nthUglyNumber(self, n: int, a: int, b: int, c: int) -> int:
        d = math.lcm(a, b)
        e = math.lcm(b, c)
        f = math.lcm(a, c)
        g = math.lcm(a, math.lcm(b, c))

        def check(t: int) -> bool:
            # [1, t] 内能被 a 或 b 或 c 整除的数的个数（三集合容斥）
            cnt = t // a + t // b + t // c - t // d - t // e - t // f + t // g
            return cnt >= n

        left = min(a, min(b, c)) + n - 2   # 一定不满足的端点
        right = min(a, min(b, c)) * n      # 一定满足的端点
        while left + 1 < right:
            mid = (left + right) // 2
            if check(mid):
                right = mid
            else:
                left = mid
        return right
```

## 四、复杂度分析

| 版本 | 时间复杂度 | 空间复杂度 |
| :--- | :--- | :--- |
| **最终代码** | O(log(min(a,b,c) · n)) | O(1) |
| 朴素解法（逐个判断） | O(min(a,b,c) · n) | O(1) |
| 三指针 / 堆生成 | O(n log 3) | O(n) |
| 理论下界 | O(log 答案) | O(1) |

> 复杂度中的 `n` 指题目要求的「第几个丑数」，`min(a,b,c)` 是三个除数里的最小值 —— 它决定了丑数的最小间距，也决定答案上界 `min(a,b,c) · n`；二分区间长度就是这个上界，所以轮数是它的对数。

## 五、优化评估

**结论**：时间已到理论下界，**没有进一步优化的空间**。

### 瓶颈分析

二分的每一轮只做 7 次整数整除和 1 次比较，判定本身是 `O(1)`；真正的成本是轮数 —— 区间上界 `min(a,b,c) · n` 最大约 `10^18`，`log2` 下来也就 60 轮左右，合计几百次运算，可以忽略。

### 可优化空间

**为什么不可能更好**：任何算法的输出都是 `[1, 2·10^9]` 里的某一个值，在只允许「问 `cnt(t)` 是多少」这种计数查询、且计数单调的前提下，二分已经把查询次数压到信息论下界 `log` 级。想再快，只能减少单次判定的常数（整除次数），而不是减少轮数。

### 常数级优化（可选）

- `lcm` 全部提到循环外（上面的代码已经这么做了），避免每轮重复求 `gcd`。
- 若某个除数能被另一个整除（如 `c % a == 0`），则 `c` 这一项完全被 `a` 覆盖，可以先用逻辑剔除掉，少几次整除 —— 但三种情况要分别处理，代码会明显变长，本题规模下不值得。
- 三个 `lcm` 里 `g = lcm(a, lcm(b, c))` 已复用 `lcm` 的结果，不必重算。

## 六、易错点与总结

### 易错点

- **判定写成 `cnt == n`**：`cnt` 会跳过某些值，`== n` 可能永远不成立，直接死循环或返回错误位置。必须是 `>= n`。
- **交集用乘积**：`⌊t/(a*b)⌋` 只有当 `a`、`b` 互质时才等于 `⌊t/lcm(a,b)⌋`；`a=2, b=4` 这类输入会算少。
- **容斥符号写反/漏项**：三项加、三项减、三项交集加，共 7 项，漏掉 `+g` 会把「同时被三个数整除」的数算成负贡献。
- **忘记 `import math`**：`math.lcm` 是 Python 3.9+ 才有的函数，本地跑的时候容易直接 `NameError`。
- **二分边界错配**：`left` 必须是「一定不满足」的位置。若把 `left` 设成答案本身（或某个满足的位置），`left + 1 < right` 的区间不再夹住答案，会返回错值。
- **结果可能超过上界**：`right` 用 `min(a,b,c) * n` 兜底是安全的，但如果手写一个偏小的 `right`（比如直接取 `n`），当 `min(a,b,c) > 1` 时会漏解。

### 题型套路沉淀

- **「第 k 个满足条件 P 的数」→ 二分答案 + 计数判定**：只要能 `O(1)`/`O(log)` 地算出「`≤ t` 里有多少个满足 P」，并且这个计数关于 `t` 单调，就可以二分最小的 `t` 使 `cnt(t) >= k`。这类题的关键从来不是二分，**而是那个计数函数**。
- **计数里的「或」→ 容斥**：`A ∪ B ∪ C` 的规模用「单集和 − 两两交集 + 三数交集」求，交集规模 = `⌊t / lcm⌋`。数论类题目里 `lcm` 几乎总是和容斥一起出现。
- **二分答案的固定模板**：
  ```text
  1. 写 check(t)：单调、O(1)
  2. 定区间：[一定不满足, 一定满足]
  3. while left + 1 < right: mid 处收缩
  4. 返回 right
  ```
  用「`left` 不满足 / `right` 满足」的不变式写，比记 `>=`、`<=`、`±1` 的开闭细节可靠得多。
