# 2819. 购买巧克力后的最小相对损失

> **难度**：困难
> **标签**：数组 · 二分查找 · 前缀和 · 排序
> **原题链接**：https://leetcode.cn/problems/minimum-relative-loss-after-buying-chocolates/

---

## 一、题目描述

有 `n` 块巧克力，价格放在 `prices` 里。每次询问给出 `[k, m]`：Bob 从 `n` 块中**恰好挑 `m` 块**，选中的每块按下面规则分摊 ——

- 价格 `p <= k`：Bob 全额付款（付 `p`，Alice 付 0）；
- 价格 `p > k`：Bob 付 `k`，Alice 付余下的 `p - k`。

记 Bob 共付 `b`、Alice 共付 `a`，要使 `b - a` **最小**。返回每次询问的最小相对损失。

于是每块被选中的巧克力对 `b - a` 的贡献是

```text
g(p) = 2*min(p, k) - p = k - |p - k|
```

问题变成：**在 n 个 `g` 值中取 m 个最小者求和**（未选中的块与两人都无关）。

### 示例

```text
示例 1
输入：prices = [1,9,22,10,19], queries = [[18,4],[5,2]]
输出：[34,-21]
解释：k=18,m=4 时选 [1,9,10,22]，Bob 付 1+9+10+18=38、Alice 付 0+0+0+4=4 ⇒ 38-4=34；
      k=5,m=2  时选 [19,22]，Bob 付 5+5=10、Alice 付 14+17=31 ⇒ 10-31=-21。

示例 2
输入：prices = [1,5,4,3,7,11,9], queries = [[5,4],[5,7],[7,3],[4,5]]
输出：[4,16,7,1]

示例 3
输入：prices = [5,6,7], queries = [[10,1],[5,3],[3,3]]
输出：[5,12,0]
```

### 约束条件

- `1 <= prices.length == n <= 10^5`
- `1 <= prices[i] <= 10^9`
- `1 <= queries.length <= 10^5`
- `queries[i].length == 2`
- `1 <= k_i <= 10^9`，`1 <= m_i <= n`

## 二、解题思路

### 核心思想

`g(p) = k - |p - k|` 是一条**以 `k` 为峰**的折线（`p <= k` 段斜率为 +1、`p > k` 段斜率为 −1）。把 `prices` 升序排好后，"取 `m` 个最小 `g`" 必然表现为：**取最小的若干块 + 最大的若干块**。于是每询问只剩「左边取几块」这一个自由度 `a`，其代价可以 O(1) 算出来，而最优的 `a` 由一条**非降序列**与阈值 `2k` 的交界决定 —— 二分定位即可。

### 思路演进

1. **朴素解**：对每次询问，把 `n` 个 `g(p)` 全算出来排序、取前 `m` 个求和。每次 `O(n log n)`，`q = 10^5`、`n = 10^5` 时是 `q·n log n ≈ 1.7×10^11` 量级，不可能过。
2. **瓶颈定位**：慢在内层重复"重新排序 `n` 个数"。但注意 `g` 的形状与 `k` 无关（永远是"峰在 `k` 的单峰折线"），而折线上最小的值集中在**两端**：最便宜的几块（贡献恰为价格本身）和最贵的几块（贡献为 `2k − p`，越贵越小）。也就是说，真正需要决定的不是"选哪 `m` 个"，而是"**从左边取几个**"。
3. **关键转化**：
   - 先把 `prices` 升序排好并求前缀和 `psum`。记 `need = n - m`（**未选中**的块数）。若左边取 `a` 块、右边取 `m - a` 块，则被舍弃的是中间连续的一段 `prices[a .. a+need-1]`，代价为
     ```text
     cost(a) = psum[a] + 2k(m - a) - (psum[n] - psum[a + need])
     ```
   - 做差分：
     ```text
     cost(a+1) - cost(a) = prices[a] + prices[a+need] - 2k = h(a) - 2k
     ```
     其中 `h(a) = prices[a] + prices[a+need]`。**`h` 是两个非降序列之和 ⇒ 非降**，于是 `cost` 是**单峰**的（先降后升），最优分界点就是
     ```text
     a* = 最小的满足 h(a) >= 2k 的 a（若不存在则 a* = m）
     ```
   - 一句话说清：原来不行是因为要"重新排序"；现在行，是因为**代价关于分界点的差分只依赖两个端点值，而它随分界点单调不减** —— 单峰 ⇒ 边界可用二分求，不必建出 `h` 这个数组。
4. **最优解**：每询问一次 `O(log m)` 的 lower_bound，配合前缀和 `O(1)` 求值，总复杂度 `O(n log n + q log m)`。

### 判据与判据族定位

**判据（可判定真假的命题）**：`cost(a)` 的最小值点 = 使 `prices[a] + prices[a+need] >= 2k` 成立的最小下标 `a`（不足则取 `m`）。等价说法：分界点每右移一格，代价变化 `prices[a] + prices[a+need] - 2k`，符号只翻转一次。

**族定位**：本题属「**有序序列上的单调谓词边界定位**」——被定位的是一维决策变量 `a` 的边界。但它有两个自己的特点，与其他载体（原数组 / 前缀和 / 值→下标表）不同：

- 被二分的数组 `h` 是**虚拟的**：`h(a) = prices[a] + prices[a+need]` 把两个下标拼在一起，且第二个下标带一个随询问变化的偏移 `need`，**无法预先物化成一张表**（这正是它不能用 `bisect` 一把梭、必须手写循环的原因）；
- 有序性不是题面给的，而是**排序 + 两个非降序列相加**推出来的（排序成本必须计入，实测占端到端 3.9%）。

本题与「滑动窗口」族无关：窗口族的合法性来自窗口内部状态或两端点的值，而这里的判据是"分界点代价的单峰性"，与滑动窗口的两根单调性是两回事，**不要串用滑窗模板**。

### 关键点

- **`need = n - m` 必须出现在比较式里**。它代表"被整段舍弃的中间块"，漏掉它就把问题错解成"每个位置各自比较"。这是本题唯一的结构性要害（见「七、验证记录」的 W1 反例）。
- **平局不改变答案**。`h(a) == 2k` 时 `cost(a) == cost(a+1)`，所以二分里写 `>` 还是 `>=`，得到的都是最优解，只是取到"最优段"的左端或右端（实测两版输出逐位相同）。写 `>` 时 `idx` 会停在"第一个使代价不再下降"的位置，语义更直白。
- **`m == n` 是 `need = 0` 的退化情形**。截图代码专门用 `bisect_right` 走了一条 C 层分支；这条分支与通用路径**等价**（`p == k` 时 `p` 与 `2k − p` 都等于 `k`），删掉也对，它买的只是常数。
- **答案可以为负**（示例 1 第二问 `-21`）。不要按"损失非负"的想法加钳制。
- **数值范围**：`2k·m` 上界约 `2×10^14`，Python 无所谓；移植到 C++/Java 必须用 64 位整数。

## 三、代码实现

### 最终代码

> 截图里只有 `class Solution:` 起的部分，`bisect_right` 与 `List` 的 `import` 截图外没有，已补全（不改动任何一行逻辑）；代码结尾是完整的 `return res`，**没有被裁掉的行**。

```python
from bisect import bisect_right          # 截图外补全
from typing import List                  # 截图外补全


class Solution:
    def minimumRelativeLosses(self, prices: List[int], queries: List[List[int]]) -> List[int]:
        n = len(prices)
        prices.sort()
        psum = [0] * (n + 1)
        for i, x in enumerate(prices):
            psum[i + 1] = psum[i] + x

        res = []
        for i, (k, m) in enumerate(queries):
            if m == n:
                x = bisect_right(prices, k)
                res.append(psum[x] + 2 * k * (n - x) - (psum[n] - psum[x]))
                continue

            need, idx = n - m, m
            lo, hi = 0, m - 1
            while lo <= hi:
                mid = (lo + hi) >> 1
                if k - prices[mid] > prices[mid + need] - k:
                    lo = mid + 1
                else:
                    hi, idx = mid - 1, mid
            left = psum[idx]
            right = 2 * k * (n - idx - need) - (psum[n] - psum[idx + need])
            res.append(left + right)
        return res
```

## 四、复杂度分析

> `n = len(prices)`（巧克力块数），`q = len(queries)`（询问个数），`m` 是当前询问要选的块数（`m <= n`）。

| 版本 | 时间复杂度 | 空间复杂度 |
| :--- | :--- | :--- |
| **最终代码** | O(n log n + q log m) | O(n) |
| 朴素解法（每询问重排 g 值） | O(n log n + q·n log n) | O(n) |
| 理论下界 | Ω(n log n + q log m) | Ω(n) |

- 时间：排序 `O(n log n)` 无法避免（除非用值域结构，而值域是 `10^9`）；每次询问要定位一个"非降序列与阈值"的分界点，比较模型下界是 `Ω(log m)`，当前实现恰好是 `O(log m)` 且常数很小 ⇒ **渐进最优**。
- 空间：`psum` 的 `O(n)` 是主要开销；每询问的额外空间是 `O(1)`。

## 五、优化评估

**结论**：**渐进复杂度已最优，但常数仍有可观空间** —— 端到端 86.7% 的时间花在那个手写二分循环上（实测），加两个 O(1) 的端点探针就能把「分界点在两端」的那部分询问直接短路，9 档场景里 **8 档稳定净收益、1 档持平**，最快的一档（探针全命中）逐轮比值 **0.184~0.224（快 4.5~5.4×）**。下面给出可直接替换的优化版 `D`。

### 瓶颈分析

在 `n = q = 10^5` 上做**阶段归因**（`time.perf_counter` 取 7 轮最优）：

| :--- | :--- | :--- | :--- | :--- | :--- | :--- |
| k 随机 | 319.98 ms | 12.40 ms（3.9%） | 7.55 ms（2.4%） | 300.03 ms（93.8%） | 22.47 ms（7.0%） | **277.56 ms（86.7%）** |
| m 全同 | 286.70 ms | 12.40 ms（4.3%） | 7.45 ms（2.6%） | 266.85 ms（93.1%） | 16.08 ms（5.6%） | **250.77 ms（87.5%）** |

⇒ 单改动天花板 = `1 / (1 − 0.867) ≈ 7.54×`（`m` 全同档 `≈ 7.98×`）。**除了二分，没有第二条值得动的路径**：排序 + 前缀和一共只占 6.3%。

### 可优化空间

二分的对象是虚拟数组 `h(a) = prices[a] + prices[a+need]`，**没法预先物化**（`need` 随询问变），所以 `bisect` 用不上，只能从"少跑循环"入手。三条互不相同的路线，实测如下（倍数 = 候选 / A，7 轮**同轮轮转**取最优，方括号内是逐轮比值区间；**区间跨过 1.0 的一律记"噪声内持平"**）：

小档 `n = q = 2000`：

| :--- | :--- | :--- | :--- | :--- | :--- | :--- |

三条路线的读法：

1. **端点双探针（B / D）—— 全场景稳定收益，建议采纳。** `B` 的 9 档 **63 组逐轮比值全部小于 1.0，没有一组跨过 1.0**；`D` 除「`m` 只有 5 个取值」那一档（`0.854~1.015`，该档 `m == n` 的询问占 20.4%，`D` 去掉了 `A` 的 `m == n` 特判，这部分询问从 C 层 `bisect_right` 退化成 Python 循环）之外，其余 8 档 56 组也全部小于 1.0。原因是它只用两个比较就能处理掉 `h(0) >= 2k`（取 `idx = 0`）与 `h(m-1) < 2k`（取 `idx = m`）这两类询问，而这两类在实测里恰好覆盖了 50%~100% 的询问；收益与命中率成正比（命中 100% 档 4~5×，命中 50% 档约 1.4×）。这也解释了为什么它离 7.54× 的天花板还远：剩下那约 50% 的询问仍在跑 Python 循环。至于探针带来的额外成本（未命中时多 2 次比较），在"探针只命中一半"的档（`k` 随机 `0.673~0.743`、`m` 全同 `0.652~0.710`）仍是净收益 ⇒ 这份成本被收益完全覆盖。

   | m 的取值个数 | 组均查询数 | E/A | F/A |
   | :--- | :--- | :--- | :--- |
   | 5 | 400 | **0.516~0.547** | 0.649~0.696 |
   | 20 | 100 | **0.720~0.744** | 0.876~0.902 |
   | 100 | 20 | 2.015~2.206 | 2.528~2.718 |
   | 400 | 5 | 7.433~7.639 | 8.284~8.496 |
   | 2000 | 1 | 22.667~23.321 | 18.221~18.741 |

   交叉点落在"组均查询数 20 ~ 100"之间（组内 `m` 均值约 1000，即大约 **"组均查询数 ≳ m 的 2%~5%" 才翻正**）。题面**不保证** `m` 会重复，`m` 均匀随机时 `Σm ≈ 5×10^9` 个元素要物化（`n = q = 10^5` 规模下）—— 所以它只是一个"若查询的 `m` 高度重复可以开"的备选，**不作默认**。（F 是 E 的改良版：不物化、改成组内按 `k` 排序 + 双指针，省掉 `O(m)` 构建，但要多付一次组内排序，实测只在 `m` 全异这种极端档才反超 E。）
3. **二分循环的常数改写（C）—— 判为噪声内持平，不建议单独采用。** 把 `k - p[mid] > p[mid+need] - k`（两次减法）改成 `p[mid] + p[mid+need] < k2`（一次加法 + 预乘 `k2 = k + k`）：9 档里 6 档的逐轮区间跨过 1.0，最好也不过 0.85，**读不出稳定方向**。⇒ 这条改动本身不亏，但也没有可验证的收益，不该写进结论。

### 优化代码

在用户版本的基础上做三件事：① 加两个 O(1) 端点探针；② 二分判据改成和式比较（顺手，无独立收益）；③ 去掉 `m == n` 特判（探针已天然覆盖 `need = 0`，去掉后少一次每轮比较）。**演进正确性已对拍验证，见「七、验证记录」。**

```python
from typing import List


class Solution:
    def minimumRelativeLosses(self, prices: List[int], queries: List[List[int]]) -> List[int]:
        p = prices
        n = len(p)
        p.sort()
        psum = [0] * (n + 1)
        for i, x in enumerate(p):
            psum[i + 1] = psum[i] + x
        ps = psum
        p0 = p[0]
        pmax = p[n - 1]

        res = []
        for k, m in queries:
            need = n - m
            k2 = k + k
            # 端点探针：h(a) = p[a] + p[a+need] 非降 ⇒ 这两个比较就能定案
            if p0 + p[need] >= k2:              # h(0) >= 2k  ⇒ 全从右边取
                idx = 0
            elif p[m - 1] + pmax < k2:          # h(m-1) < 2k ⇒ 全从左边取
                idx = m
            else:
                idx = m
                lo, hi = 0, m - 1
                while lo <= hi:
                    mid = (lo + hi) >> 1
                    if p[mid] + p[mid + need] < k2:
                        lo = mid + 1
                    else:
                        hi, idx = mid - 1, mid
            res.append(ps[idx] + 2 * k * (m - idx) - (ps[n] - ps[idx + need]))
        return res
```

**优化理由**：`h` 非降 ⇒ "存在 `a` 使 `h(a) >= 2k`" 这件事只要看两个端点就够了 —— 左端点成立则 `idx = 0`，右端点不成立则 `idx = m`，只有夹在中间才真的需要 `O(log m)` 搜索。未命中时两个探针只多花 2 次比较，而实测在所有"探针只命中一半"的档位上（`k` 随机 `0.673~0.743`、`m` 全同 `0.652~0.710`）依然是净收益 ⇒ 这份额外成本被判据的收益完全覆盖。**去特判这一项单独看落在噪声带**、不能单独宣称收益：`A2/A` 在 `m == n` 极少的档是 `0.93~0.97`（略快，省掉每轮一次比较），在 `m == n` 占 20% 的档是 `1.06~1.22`（明显更慢），它是靠与探针配合才在 `D` 里成立。

### 常数级优化（可选）

- `need`、`k2` 在询问内只算一次，别放进循环；`ps`/`p`/`p0`/`pmax` 提到局部变量（截图的写法已经在做这件事）。
- **不要**把比较式改写成 `p[mid] + p[mid + need] < k2` 之外的形态并宣称收益：这一条改写本身（版本 `C`）9 档里 6 档逐轮区间跨过 1.0，属噪声内持平。至于 `while lo <= hi` 换成 `while lo < hi` 的 lower_bound 形态，本题 `hi = m - 1` 已带"上界哨兵"语义、两种写法迭代次数同阶，**本次没有单独实测后者的常数，故不作任何提速宣称**。
- 若查询集合里 `m` 高度重复（例如同一个 `m` 被查上千次），可以换 `E` 路线：按 `m` 分组、物化 `h = [p[i] + p[i+need] for i in range(m)]` 后用 `bisect_left`；实测在"`m` 全同"档 2.2~3.1×，但 `m` 全异档反向 22~32×，**仅在输入结构已知时才用**。

## 六、易错点与总结

### 易错点

- **漏掉 `need` 偏移**：比较式必须用 `prices[mid + need]`（`need = n - m`）。写成 `prices[mid + 1]` 会同时踩两个坑 —— 官方示例 2 直接错（实得 `[7,16,8,1]`、期望 `[4,16,7,1]`），且 `m == n` 时越界抛 `IndexError`；40 组随机里错 26 组。**最小的"静默错解"反例**：`prices = [1,3], queries = [[2,2]]` → 真值 `2`、实得 `4`（全程不报错）。
- **二分上界写成 `hi = m`**：当最优分界恰为 `a = m` 时会读到 `prices[n]` 抛 `IndexError`。最小触发例 `prices=[1,2,3], queries=[[3,2]]`（`h(1) = 5 < 6` ⇒ `idx = 2`）。注意 `prices=[1,2,3], [[2,2]]` 并不触发（走了左半边），所以这类越界**不是每次都炸**，靠碰运气试不出来的。
- **忘记 `need = 0` 的退化**：`m == n` 时 `psum[idx + need] = psum[idx]`、右侧块数为 `m - idx`，通用式天然成立；截图里的 `bisect_right` 分支只是常数优化，删掉不影响正确性。
- **答案出现负数就以为自己写错了**：本题 `-21` 是合法答案，别加 `max(0, ...)`。
- **`prices.sort()` 是原地排序**：会改掉传入的数组顺序，本地复用同一份 `prices` 时要注意。
- **数值溢出**：`2k·m` 上界约 `2×10^14`，C++/Java 必须 64 位。

### 题型套路沉淀

- **贡献函数定形状 → 最优集在两端**：`g(p) = 2min(p,k) - p = k - |p - k|` 是"峰在 `k`"的折线，于是"选 `m` 个最小"必然退化成"前缀 `a` 个 + 后缀 `m - a` 个"，只剩一个自由度。看到"每元素有独立贡献 + 贡献函数单峰"就往这里想。
- **代价差分 = 端点值之差 ⇒ 单峰 ⇒ 边界二分**：`cost(a+1) - cost(a) = p[a] + p[a+need] - 2k`，两个非降序列之和仍非降，符号只翻转一次。这是"把最优化问题变成 lower_bound"的标准套路，**关键是先做差分再谈单调性**。
- **虚拟数组也能二分**：`h` 由 `prices` 的两处下标拼成、且偏移量随询问变，不能预物化 —— 这种时候手写循环是应该的（`bisect` 用不上，不是"手写二分"的坏味）。
- **前缀和 + 差分定位**：凡"从有序数组两端取元素、中间整段丢弃"的题，`psum` 让每次求值 O(1)，把 `O(n)` 的枚举压成 `O(log n)` 的定位。

### 1. 暴力基准与官方示例
