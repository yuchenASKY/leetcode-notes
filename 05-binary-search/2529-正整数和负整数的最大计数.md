# 2529. 正整数和负整数的最大计数

> **难度**：简单
> **标签**：数组 · 二分查找 · 计数
> **原题链接**：https://leetcode.cn/problems/maximum-count-of-positive-integer-and-negative-integer/

---

## 一、题目描述

给定一个**非递减**的整数数组 `nums`，返回其中**正整数个数**与**负整数个数**的较大值。`0` 既不算正数也不算负数。

### 示例

```text
输入：nums = [-2,-1,-1,1,2,3]
输出：3
解释：3 个正数、3 个负数，取最大值得 3。

输入：nums = [-3,-2,-1,0,0,1,2]
输出：3
解释：2 个正数、3 个负数，取最大值得 3。

输入：nums = [5,20,66,1314]
输出：4
解释：4 个正数、0 个负数，取最大值得 4。
```

### 约束条件

- `1 <= nums.length <= 2000`
- `-2000 <= nums[i] <= 2000`
- `nums` 按**非递减顺序**排列
- **进阶**：能否设计时间复杂度 `O(log n)` 的算法？

---

## 二、解题思路

### 核心思想

数组非递减 ⇒ **负数必是一段前缀、正数必是一段后缀、`0` 夹在中间**（可以为空）。于是「数个数」等价于「定位两条边界线的下标」，二分即可在 `O(log n)` 内找到切点。

### 思路演进

1. **暴力解法**：一趟遍历，分别累计 `neg` 与 `pos`，返回两者较大值。时间 `O(n)`、空间 `O(1)`。n ≤ 2000 时这一点开销完全可接受，能直接过。
2. **观察到 / 瓶颈定位**：暴力解的成本是「把每个元素都读一遍」，但输出只要两个整数 —— 单个元素的**值**其实并不重要。因为数组有序，正负各自的**位置范围**是预先确定的：只要知道「首个非负数的下标」与「首个正数的下标」，两个计数就被唯一确定，无需逐个确认。
3. **关键转化**：把「计数」换成「**定界**」。对阈值 `t` 定义谓词
   `P_t(i) = (nums[i] >= t)`。
   由于 `nums` 非递减，`P_t` 沿下标一定是「先假后真」的**单调谓词**，于是「首个为真的下标」（即 `lower_bound(t)`）就是切点：

   - `neg = lower_bound(0)` —— 下标小于它的一定 `< 0`；
   - `pos = n - lower_bound(1)` —— 下标不小于它的一定 `>= 1`，即正数。

   一句话概括「原来为什么不行、现在为什么行」：原来必须逐个读元素，是因为把**元素的值**当成了判定依据；换成「保序的区间」后，一次探测就能把候选下标区间砍半，元素值不必再单独得知。

   ⚠️ 注意**正数必须用 `t = 1`**：`t = 0` 的切点把 `0` 归到「非负」一侧，只能用来数负数，不能用来数正数。

4. **最优解**：做两次 `lower_bound`（`t = 0` 与 `t = 1`），各 `O(log n)`，总计 `O(log n)` 时间、`O(1)` 空间 —— 正好命中题面进阶要求。

### 判据与判据族定位

**判据**：记 `lower_bound(t)` = 首个满足 `nums[i] >= t` 的下标（不存在时返回 `n`），则

```text
pos = n - lower_bound(1)        neg = lower_bound(0)        答案 = max(pos, neg)
```

**判据族**：本题属于「**有序序列上的单调谓词边界定位**」（下标二分）族 —— 搜索空间是**下标**，谓词的单调性由数组有序性直接给出。与「**二分答案**」族的区别：后者把**答案本身**当搜索变量、另配一个可行性判定函数（如「最小化最大值」）；本题不需要，因为边界下标就是答案的原料。

本族最不易写错的统一写法是**半开区间 + 相邻终止**：`left = -1`、`right = n`，循环条件 `left + 1 < right`，返回 `right`。返回值天然落在 `[0, n]`，同时涵盖「全部元素都 ≥ t」（返回 0）与「全部元素都 < t」（返回 n）两个极端，不需要任何特判。

### 关键点

- **`0` 必须单独处理**：数正数用 `t = 1`，数负数用 `t = 0`，两个阈值不能混用。
- **哨兵 `left = -1`**：若把左端从 `0` 起，就必须为「没有任何元素 ≥ t」额外写特判；`-1 / n` 哨兵让两种情况自然收敛。
- **重复元素不影响**：谓词只看 `>= t`，重复值仍然单调，取到的是**首个**满足位置。
- **边界等价性**：`n - start` 与 `end` 在全负 / 全正 / 全零时分别退化为 `0 / n / 0`，无需分支。

## 三、代码实现

### 最终代码

```python
from typing import List


class Solution:
    def lower_bound(self, nums: List[int], target: int) -> int:
        """返回首个满足 nums[i] >= target 的下标；不存在时返回 len(nums)。"""
        left = -1
        right = len(nums)
        # 不变量：nums[left] < target（left == -1 时视为成立）
        #         nums[right] >= target（right == len(nums) 时视为成立）
        while left + 1 < right:
            mid = (left + right) // 2
            if nums[mid] < target:
                left = mid
            else:
                right = mid
        return right

    def maximumCount(self, nums: List[int]) -> int:
        start = self.lower_bound(nums, 1)      # 首个正数下标 ⇒ 正数个数 = n - start
        end = self.lower_bound(nums, 0)        # 首个非负数下标 ⇒ 负数个数 = end
        return max(len(nums) - start, end)
```

> 代码为用户截图中的提交版本（LeetCode 已 AC）。截图里只有 `class Solution:` 一行开头，`from typing import List` 属**补齐 import**（否则笔记里的代码无法直接运行）。
> 截图最后一行是第 16 行 `return max(len(nums) - start, end)`，是完整的收尾语句，**未发现被裁掉的行**。

### 不变量与正确性

- 循环不变式：`nums[left] < target`（`left == -1` 视为成立）、`nums[right] >= target`（`right == len(nums)` 视为成立）。
- 归纳步：`left < mid < right`（由 `left + 1 < right` 推出），故每次比较后区间 `(left, right)` 严格缩短；`nums[mid] < target` 时把 `mid` 归入左侧安全区，否则归入右侧安全区。
- 终态：`right == left + 1`，即 `right` 是**首个**满足 `nums[i] >= target` 的下标。
- 由非递减性，下标 `< end` 的元素全都 `< 0`、下标 `>= start` 的元素全都 `>= 1`，两个计数关系成立；`max` 即答案。

## 四、复杂度分析

下表 n 指 `nums` 的长度（不是值域大小）。

| 版本 | 时间复杂度 | 空间复杂度 |
| :--- | :--- | :--- |
| **最终代码** | O(log n) | O(1) |
| 朴素解法（一趟计数） | O(n) | O(1) |
| 理论下界 | Ω(log n) | O(1) |

**下界论证（对手法，轮廓级）**：取只含 `-1 / 1` 的输入族 `A_t = [-1]*t + [1]*(n-t)`（`t = 0..n`，均为合法输入）。对 `A_t` 查询下标 `i`，答案由 `i < t` 唯一决定，即任何一次探测只能回答「`t > i` 还是 `t <= i`」。对手每轮把「与回答仍相容的 `t` 集合」维持在较大的一半：`k` 次探测后仍相容的 `t` 至多……至少 `(n+1) / 2^k` 个；而这个集合必须落在同一个「答案类」内 —— 该族的答案 `max(t, n-t)` 每个取值只对应 1~2 个 `t`，故必有 `2 >= (n+1) / 2^k`，即 `k >= log2((n+1)/2) = Ω(log n)`。

⇒ 结论：`O(log n)` 与比较模型下的下界同阶，**唯一可动的只有常数项**。

## 五、优化评估

**结论**：**渐进已最优**（`O(log n)` 命中题面进阶要求、与下界同阶；空间 `O(1)` 已到极限）。但**常数项还有接近一个数量级的空间** —— 手写 `lower_bound` 是纯 Python 的 `while` 循环，每调用一次要做约 `⌈log2(n+1)⌉` 次迭代；而 `bisect.bisect_left` 做的是完全相同的事、由 C 实现。

### 瓶颈分析

n = 2000 时整函数耗时 2.055 μs，而单次手写查找 1.121 μs ⇒ 两次查找（2.24 μs）几乎解释了全部耗时（差额来自 `partial` 包装层的开销，见下表的测量设计说明）。也就是说 **100% 的成本落在两次二分循环里**，`max()`、下标算术、函数调用都可忽略；数据分布对耗时没有影响（迭代次数只由 n 决定，与切点位置无关）。

### 可优化空间

- ✅ **换用 `bisect_left`**：语义完全相同（「首个 ≥ target 的下标」），把循环交给 C 实现，实测快 **8.2×（n = 2000）/ 9.6×（n = 10^6）**，且不损失可读性。
- ❌ **值域计数法**（`nums[i] ∈ [-2000, 2000]`，开 4001 长的计数数组一趟扫完）：能过题，但时间 `O(n + V)`、空间 `O(V)`，既不满足进阶的 `O(log n)`，大 n 下也远不如二分。
- ❌ **改用哈希 / `count()` / `index()`**：`nums.index(1)` 只找「等于 1」的第一个位置，对重复与缺失都不成立（`0` 不存在时还会抛 `ValueError`），且仍是 `O(n)`，白白丢掉有序性。
- ⚠️ **把第二次二分的左界收到 `end`**（即 `bisect_left(nums, 1, end)`）理论上不亏：区间长度由 `n` 变成 `n - end`，切点之后的元素不必再看。但这只是把常数再压一点，**渐进不变**（数组无负数也无 0 时 `end = 0`，区间长度仍是 `n`），且需要把 `lo` 参数一路传进手写版本。**本次未实测，仅为复杂度层面的推断。**

### 优化代码

```python
from bisect import bisect_left
from typing import List


class Solution:
    def maximumCount(self, nums: List[int]) -> int:
        # bisect_left(nums, t) 的语义正是「首个 >= t 的下标」，与手写 lower_bound 完全等价
        return max(len(nums) - bisect_left(nums, 1), bisect_left(nums, 0))
```

**优化理由**：把两次 `O(log n)` 的循环交给 C 实现。渐进复杂度不变（仍 `O(log n)` / `O(1)`），但常数大幅下降。

### 常数级优化（实测）

微基准：n = 2000 与 n = 10^6 两档，**7 轮轮转取最优**，每次测量在批量内重复调用后取单次均值。

| 计时对象 | n = 2000 | 相对 A | n = 10^6 | 相对 A |
| :--- | ---: | ---: | ---: | ---: |
| **A 用户版 `maximumCount`** | 2.055 μs | 1.00× | 3.552 μs | 1.00× |
| **B `bisect_left` 版** | **0.250 μs** | **0.12×（快 8.22×）** | **0.371 μs** | **0.10×（快 9.57×）** |
| A' 单次手写 `lower_bound` | 1.121 μs | 0.55× | 1.794 μs | 0.50× |
| B' 单次 `bisect_left` | 0.207 μs | 0.10× | 0.257 μs | 0.07× |
| C 线性扫描版（对照） | 74.855 μs | 36.43× | 116645 μs（≈116.6 ms） | 32836× |

**测量设计说明（三条，避免误读）**：

1. A'/B' 是**归因用**的单次查找，两者都包了一层 `functools.partial`（**包装层数相同**，故彼此可比），其绝对值比裸调用略高；A/B/C 则是完整算法调用，三者包装层数一致（A 的 `Solution` 实例已提到批量之外，避免把「每轮 new 一个对象」算进 A 的耗时 —— 首次测量时确实踩到了这一点，A 的读数因此偏高约 0.03 μs）。
2. A' × 2 = 2.24 μs 与 A 的 2.055 μs 同量级 ⇒ **A 的耗时确实全在两次手写循环上**，没有别的成本可挖。用 A'/B' 的比值看单次查找差距是 5.42× / 6.98×，比 A/B 的 8.22× / 9.57× 小，差额正是 A' 上那层 `partial`。
3. C 是 `O(n)` 的对照：n = 2000 时比 A 慢 36×，n = 10^6 时慢 3 万倍 ⇒ 二分带来的**是渐进优势**。但按本题约束（n ≤ 2000），C 的 74.9 μs 同样能过，**不能**把结论写成「不优化会 TLE」—— 二分的价值在于满足进阶要求与泛化。

## 六、易错点与总结

### 易错点

- **把正数当成「非负数」**：正数必须用 `lower_bound(1)`。若沿用 `lower_bound(0)`，`0` 会被算进正数。反例 `nums = [0,0,5]`：正解 `max(1, 0) = 1`，错解会得 `n - 0 = 3`。
- **`<` 写成 `<=`**：阈值语义从「首个 ≥ t」变成「首个 > t」，此时 `end` 变成首个*正数*下标，`0` 会被一并算作负数。反例 `nums = [-3,0,2]`：正解 `max(1, 1) = 1`，错解得 2。
- **依赖 `index()` / `count()` / `in`**：只处理「等于」，对重复与缺失都不成立，且放弃有序性（仍是 `O(n)`）。
- **负索引陷阱**：`left = -1` 本身安全（只参与算术，不索引）。但若照抄不变量去读 `nums[left]`，`nums[-1]` 会**静默取到最后一个元素** —— 不报错、结果错。本写法只读 `nums[mid]`，不踩这个坑。
- **混用两种二分写法**：`left = -1 / right = n` + `while left + 1 < right` 与 `left = 0 / right = n - 1` + `while left <= right` 是两套不同模板，返回值的含义也不同（前者返回插入点 `[0, n]`，后者返回是否存在）。混用会出现死循环或差一。
- **以为「一次二分就能同时定两个界」**：两个切点的阈值不同（0 与 1），只能分两次找；只有在已知 `0` 的个数时才谈得上合并。

### 题型套路沉淀

- **有序数组上「数某一段有多少个」= 边界定位**：`[l, r)` 中 `>= t` 的个数 = `n - lower_bound(t)`，任意区间 `[t1, t2)` 的个数 = `lower_bound(t2) - lower_bound(t1)`。把计数转成两次查找之差，是本族最常见的入口。
- **`lower_bound` 半开区间模板**（最不易写错）：`left = -1, right = n`；`while left + 1 < right: mid = (left + right) // 2; ...`；返回 `right`。返回值域 `[0, n]`，天然覆盖两端极端，不需要特判。
- **「下标二分」vs「二分答案」**：判断依据是**单调性从哪来** —— 由输入有序性直接给出（本族，搜下标）还是由可行性函数的谓词给出（二分答案，搜答案值）。
- **值域小 ≠ 一定要开桶**：本题值域只有 4001，开桶能过，但题面明确要求 `O(log n)`；**约束量级决定结论口径** —— n ≤ 2000 时任何写法都是微秒级，二分的意义在渐进与泛化，而不是「不优化就超时」。
