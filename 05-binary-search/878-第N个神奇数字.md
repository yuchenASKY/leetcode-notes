# 878. 第 N 个神奇数字

> **难度**：困难
> **标签**：二分查找 · 数学
> **原题链接**：https://leetcode.cn/problems/nth-magical-number/

---

## 一、题目描述

一个正整数如果能被 `a` 或 `b` 整除，就称它是「神奇数字」。给定 `n`、`a`、`b`，返回**按升序排列的第 n 个神奇数字**。答案可能很大，需对 `10^9 + 7` 取模后返回。

### 示例

```text
输入：n = 1, a = 2, b = 3
输出：2
解释：神奇数字序列为 2, 3, 4, 6, 8, 9, 10, 12, ...

输入：n = 4, a = 2, b = 3
输出：6
解释：第 4 个神奇数字是 6。
```

### 约束条件

- `1 <= n <= 10^9`
- `2 <= a, b <= 4 * 10^4`

---

## 二、解题思路

### 核心思想

**答案本身没法直接算，但「不超过 x 的神奇数字有几个」能 O(1) 算出来，而且这个计数随 x 单调不减 —— 于是对答案做二分（二分答案）。**

```text
cnt(x) = x // a + x // b - x // lcm(a, b)
```

因为「`cnt(x) >= n`」等价于「`x >=` 第 n 个神奇数字」，所以**最小的满足 `cnt(x) >= n` 的 `x` 就是答案**。

### 思路演进

1. **暴力解法（逐个枚举）**：从 1 开始逐个判断 `x % a == 0 or x % b == 0`，数到第 n 个就返回。时间复杂度与**答案的数值同阶**，而答案最大可达 `min(a,b) * n ≈ 4 * 10^18`，完全不可行。
2. **稍好的暴力（归并两列倍数）**：分别维护 `a` 的倍数指针和 `b` 的倍数指针，每次取较小的那个前进一步；两个指针撞到同一个数（即 `lcm` 的倍数）时只算一次。这样只走 n 步，但 `n ≤ 10^9`，仍然超时。
3. **观察到**：这题问的不是「第 n 个是多少」，而是「**哪个数是第 n 个**」—— 而「不超过 x 的数字里有几个神奇数字」这一步是纯粹的数数，有闭式解，由容斥直接给出（a 的倍数 + b 的倍数 − 同时是两者倍数的数，即 lcm 的倍数）。数数只要 O(1)。
4. **优化为**：把这个 O(1) 的计数函数当作二分里的 `check`。`cnt(x)` 随 x 单调不减 ⇒ 满足 `cnt(x) >= n` 的 x 构成一个后缀区间 ⇒ 二分它的左端点。左端点恰好落在某个神奇数字上，所以二分出来的就是第 n 个神奇数字。

### 关键点

- **容斥里减的是 `lcm(a, b)`，不是 `a * b`。** 例如 `a = 4, b = 6` 时，能被两者同时整除的数是 12 的倍数而非 24 的倍数。
- **取模只能放在最后一步。** 二分过程中 `cnt` 的比较必须用真实值；若把 `mid % MOD` 拿去比较，单调性直接崩掉。
- **二分区间的两端必须先定性质**：一侧「一定不满足」（`left = min(a,b) - 1`，此时 `cnt = 0 < n`，因为 `n >= 1`），另一侧「一定满足」且作为开区间端点（`right = max(a,b) * n + 1`）。这样 `while left + 1 < right` 收敛后 `right` 就是最小满足点，不需要额外处理边界。
- **上界怎么来的**：`max(a,b)` 的倍数 `max, 2·max, ..., n·max` 本身就贡献了 n 个互不相同的神奇数字，所以第 n 个必然不超过 `max(a,b) * n`。
- **`lcm` 先除后乘**：`a // gcd(a,b) * b` 比 `a * b // gcd(a,b)` 更稳（其他语言里 `a * b` 可能超出 32 位）。Python 的大整数无所谓，但保持习惯。

## 三、代码实现

### 最终代码

```python
import math          # 截图里没有，已补


class Solution:
    def nthMagicalNumber(self, n: int, a: int, b: int) -> int:
        c = a * b // math.gcd(a, b)          # lcm(a, b)

        def check(mx: int) -> bool:
            cnt = 0
            cnt += mx // a                   # a 的倍数个数
            cnt += mx // b                   # b 的倍数个数
            cnt -= mx // c                   # 重复计数的 lcm 倍数，扣除
            return cnt >= n

        left = min(a, b) - 1                 # 必不满足：cnt = 0 < n
        right = (max(a, b) * n) + 1          # 必满足（开区间端点）
        while left + 1 < right:
            mid = (left + right) // 2
            if check(mid):
                right = mid                  # mid 可行，答案在左半（含 mid）
            else:
                left = mid                   # mid 不可行，答案在右半
        return right % (10 ** 9 + 7)
```

## 四、复杂度分析

| 版本 | 时间复杂度 | 空间复杂度 |
| :--- | :--- | :--- |
| **最终代码** | O(log(max(a,b)·n)) | O(1) |
| 归并两列倍数 | O(n) | O(1) |
| 逐个枚举 | O(min(a,b)·n) | O(1) |
| 理论下界 | O(log(min(a,b)·n)) | O(1) |

> 复杂度中的 n 是题目给定的序号 `n`（要返回第几个神奇数字），不是任何数组长度；a、b 为两个除数。二分次数由答案的值域 `max(a,b)·n ≤ 4*10^18` 决定，约 62 次迭代，每次迭代 3 次整数除法。

## 五、优化评估

**结论**：时间已是理论下界（答案的每一种取值都是潜在候选，只能靠对数级搜索定位），空间 O(1) 无可再压。

### 瓶颈分析

时间全部花在约 62 次二分迭代上，每次判定只做三次整除和两次加法，没有任何对输入的遍历、也没有任何可预处理的结构。`O(log(answer))` 是「在一个有序的、由计数函数隐式定义的集合里定位」的信息论下界。

### 可优化空间

大 O 不变，但**二分的值域上界本身可以收紧一个量级**：第 n 个神奇数字一定不超过 `min(a,b) * n`（光 `min(a,b)` 的倍数就有 n 个），而原代码用的是 `max(a,b) * n`。当 `a = 2, b = 4*10^4` 时，两者分别是 `2n` 与 `4*10^4·n`，迭代次数从约 62 次降到约 31 次 —— 只是常数，但改动几乎零成本。

### 优化代码

```python
import math


class Solution:
    def nthMagicalNumber(self, n: int, a: int, b: int) -> int:
        lcm = a // math.gcd(a, b) * b        # 先除后乘，避免中间乘积溢出
        left = min(a, b) - 1                 # 必不满足
        right = min(a, b) * n                # 上界收紧到 min(a,b)*n，必满足
        while left + 1 < right:
            mid = (left + right) // 2
            if mid // a + mid // b - mid // lcm >= n:   # 判定内联，省一次函数调用
                right = mid
            else:
                left = mid
        return right % (10 ** 9 + 7)
```

**优化理由**：二分搜索的比较次数只依赖值域的**对数**，把上界从 `max·n` 换成 `min·n` 直接把对数减半；判定逻辑只有一行，内联后省掉闭包的调用开销，同时避免在循环里反复读取自由变量。

### 常数级优化（可选）

- 把 `a`、`b`、`lcm` 赋给短名的局部变量，减少内层作用域查找 —— 收益在 Python 里有限，不必强求。
- `check` 里 `cnt = 0` 后再累加是多余的写法，直接 `return mx // a + mx // b - mx // c >= n` 等价且更短。

## 六、易错点与总结

### 易错点

- **把容斥项写成 `a * b`**：只在 `gcd(a,b) == 1` 时碰巧正确，`a = 4, b = 6` 这类用例会直接算错。
- **在二分过程中取模**：`cnt` 的比较必须用真实数值，取模只能作用于最终返回值。这是本题唯一一处「不到最后不能动数」的地方。
- **返回 `left` 而不是 `right`**：`left` 是「最后一个不满足的位置」，`right` 才是最小满足点。半开区间写法下答案是 `right`。
- **左端点没给成「必不满足」**：若把 `left` 设成 0 也安全（`cnt(0) = 0 < n`），但设成 1 且 `n = 1` 时可能把真正答案排除在搜索区间之外。
- **上界用 `max(a,b)*n` 之外的值**：比如写成 `n * a * b` 会白白多几十次迭代，虽然不影响正确性。
- **溢出意识**：其他语言里 `max(a,b) * n` 可达 `4 * 10^18`，必须用 64 位整型；`left + right` 相加还有翻倍到 `8 * 10^18` 的风险（仍在 int64 内，但已逼近上限），写 C++ 时用 `left + (right - left) / 2` 更稳妥。

### 题型套路沉淀

- **二分答案的三段式**：① 写出**单调**的判定函数 `check(x)`（通常是「计数」或「可行性」）；② 确定答案值域，并让 `left` 停在必不满足侧、`right` 停在必满足侧；③ `while left + 1 < right` 收敛后取 `right`。这套骨架对所有「求第 k 小 / 最小化最大值 / 最大化最小值」通用。
- **「第 k 小」的通用转化**：凡是问「第 k 个满足条件的数」，先想「统计 ≤ x 的有几个」能不能 O(1) 算，能算就一定能二分。容斥（并集的计数）是这类统计最常用的工具。
- **取模题的通则**：**搜索/比较用原始值，输出才取模**。看到「答案可能很大，对 10^9+7 取模」就要条件反射地检查自己有没有在中途提前取模。
- **二分里 `min` / `max` 的取舍**：值域上界永远优先用「能证明成立的最小那一个」，对数减半是白赚的。
