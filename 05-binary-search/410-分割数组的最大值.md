# 410. 分割数组的最大值

> **难度**：困难
> **标签**：二分 · 二分答案 · 贪心 · 数组
> **原题链接**：https://leetcode.cn/problems/split-array-largest-sum/

---

## 一、题目描述

给定一个非负整数数组 `nums` 和一个整数 `k`，把 `nums` 分成 `k` 个**非空且连续**的子数组，使每个子数组各自的和的最大值最小，返回这个最小的「最大子数组和」。

### 示例

```text
输入：nums = [7,2,5,10,8], k = 2
输出：18
解释：共有四种分法，其中 [7,2,5] 与 [10,8] 的最大子数组和最小，为 18。
```

```text
输入：nums = [1,2,3,4,5], k = 2
输出：9
```

### 约束条件

- `1 <= nums.length <= 1000`
- `0 <= nums[i] <= 10^6`
- `1 <= k <= min(50, nums.length)`

---

## 二、解题思路

### 核心思想

**「最小化最大值」是二分答案的固定信号。** 直接枚举分法不可能，但「给定上限 `t`，能否切出来」这个判定问题可以贪心 O(n) 做；而它关于 `t` 单调（`t` 越大越容易可行），于是对答案二分即可。

### 思路演进

1. **暴力解法**：枚举所有 `k-1` 个切点位置，共 $\binom{n-1}{k-1}$ 种方案，逐个求最大子数组和取最小。n = 1000、k = 50 时组合数爆炸，完全不可行。

2. **想到 DP**：设 `dp[i][j]` 为「前 `i` 个元素切成 `j` 段」的最小最大和，转移需要枚举最后一段的起点，时间 O(k·n²) = 50 × 10⁶，能过但时间复杂度不理想，而且状态定义偏重、写起来也长。

3. **观察到**：题目问的是「最大子数组和」这个**单个数值**的**最小值**，而不是具体的分法。这类问题天然带**单调性** —— 若上限 `t` 可行（存在切法使每段和都 ≤ `t`），那么任何 `t' ≥ t` 也都可行（同一分法照用）；反之 `t' < t` 可能可行也可能不行。可行域是形如 `[ans, +∞)` 的**后缀**。

4. **优化为**：把原问题转成判定问题 —— `check(t)`：能否切出**不超过** `k` 段，使每段和都 ≤ `t`。判定只需要一次**贪心**扫描：从左往右累加，一旦加上下一个元素会超过 `t`，就在它之前切开，让它作为新一段的开头。这种「能装就装、装不下才切」的贪心保证在给定上限下**段数最少**（每段都尽量塞满），所以段数最少值 ≤ k 就说明可行。对 `t` 二分查找最小的可行值即可。

### 关键点

- **「不超过 k 段」与「恰好 k 段」等价**：把一个段再切开只会让两边的和更小，不会破坏「每段和 ≤ t」这个条件；因此段数不足 k 时可以继续切到 k 段。所以判定写成「段数 ≤ k」即可，不用纠结非空与恰好。
- **贪心为什么最优**：上限固定时，让每段尽可能长（前缀和尽量接近但不超过 `t`）得到的段数一定最少。任何其他切法在某一段上只会更短或相同，段数不会更少。（`nums[i] ≥ 0`，所以前缀和单调不减，这个「能塞就塞」的策略无后效性。）
- **下界哨兵必须取到「判定为假」的点**：`left = min(nums) - 1`。取 `min(nums)` 是不安全的 —— 当 `k ≥ n` 时 `check(min(nums))` 为真（每个元素自成一段），二分区间会失去「左端为假」的不变量，可能返回错误答案。取 `min(nums) - 1` 则必定为假：第一个元素就满足 `t < i`。
- **上界取 `sum(nums) + 1`**：整数组作为一段一定满足，判定必为真。
- **单元素超限的判断不能省**：`t < i` 时该元素无论怎么切都放不进任何段，直接返回假。少了这一句，`temp = i` 会把「装不下」误当成「开了新段」，把不可行判成可行。
- 二分返回 `left + 1`：循环结束时 `left + 1 == right`，`right` 是首个可行值，`left` 是最后一个不可行值，答案就是 `left + 1`（即 `right`）。

## 三、代码实现

### 最终代码

```python
from typing import List   # 截图里没有，已补


class Solution:
    def splitArray(self, nums: List[int], k: int) -> int:
        def check(t: int) -> bool:
            """能否切出不超过 k 段，使每段的和都不超过 t"""
            temp = 0            # 当前段的累加和
            cnt = 0             # 已使用的切点数（段数 = cnt + 1）
            for i in nums:
                temp += i
                if temp > t:    # 加上 i 会超限，就在 i 之前切开
                    temp = i
                    cnt += 1
                    if cnt == k or t < i:
                        # cnt == k：已经切成 k + 1 段，超出 k
                        # t < i   ：单个元素就超限，怎么切都放不下
                        return False
            return True

        left = min(nums) - 1    # 保证 check(left) 为假
        right = sum(nums) + 1   # 保证 check(right) 为真
        while left + 1 < right:
            mid = (left + right) // 2
            if check(mid):
                right = mid
            else:
                left = mid
        return left + 1
```

## 四、复杂度分析

| 版本 | 时间复杂度 | 空间复杂度 |
| :--- | :--- | :--- |
| **最终代码** | O(n · log S) | O(1) |
| DP 解法 | O(k · n²) | O(n) |
| 理论下界 | O(n · log S) | O(1) |

> 复杂度中的 n 指数组 `nums` 的长度，S 指 `sum(nums)`（即二分的值域宽度，本题 S ≤ 10⁹，log S ≤ 30）。

## 五、优化评估

**结论**：**已是最优的量级**。二分答案把「搜索方案」换成了「搜索答案的值域」，是这类题的通用最优路线。

### 瓶颈分析

时间由两部分相乘：外层二分 O(log S) 轮，每轮判定贪心扫一遍 O(n)。每轮的 `check` 都必须读到数组末尾才能确认段数不超过 `k`，所以 O(n) 的判定无法再省；而答案值域的 log 级轮数也已经是「整数域上二分」的下界。

DP 的 O(k · n²) 与这里不构成竞争：本题 n ≤ 1000、k ≤ 50，5 × 10⁷ 的规模虽然勉强能过，但把问题维度从「方案」降到「数值」后可省下约 k·n / log S 倍 —— 正是二分答案的价值所在。

### 可优化空间

- 值域下界可以用 `max(nums)` 而不是 `min(nums) - 1`：答案一定 ≥ `max(nums)`（最大元素自己独占一段），这样能少搜几轮，但**不能改成 `max(nums) - 1` 之类的「假下界」**，因为下界必须保证判定为假，否则区间不变量被破坏。这里保留 `min(nums) - 1` 的写法是为了与「左端必假」的模板严格对齐，逻辑最不容易出错。
- 空间上已经压到 O(1)（只用常数个变量），无进一步压缩余地。

### 常数级优化（可选）

- 把 `min(nums)` / `sum(nums)` 的两次独立扫描并入一次遍历：`left`、`right` 可以在同一个循环里顺带求出，省一趟 O(n)。数据规模小时意义不大，但属于零成本写法。
- 判定里的 `t < i` 可以提到 `temp > t` 之前合并成 `if temp > t or i > t:` 的等价形式，减少一次进入分支的机会；收益取决于输入分布，不建议为了它牺牲可读性。

## 六、易错点与总结

### 易错点

- **下界用了 `min(nums)`**：当 `k ≥ n` 时 `check(min(nums))` 为真，二分区间的「左端为假」不变量失效，可能返回比答案小的值。
- **`cnt` 的含义写错**：`cnt` 记的是**切点数**，`cnt == k` 时已经形成 `k + 1` 段，必须返回假；写成 `cnt > k` 会多走一轮，写成 `cnt == k - 1` 则提前判假。
- **漏掉 `t < i`**：某个元素自身大于上限时，贪心会把它单独作为一段（`temp = i`），此后 `temp <= t` 不再成立判断，导致把不可行判成可行。
- **二分返回 `left` 而不是 `left + 1`**：循环结束时 `left` 是最后一个**不可行**值，答案在它右边。
- **整数溢出**：Python 无此问题；若改写 C++/Java，`mid = (left + right) / 2` 在 `int` 下会溢出，应写成 `left + (right - left) / 2`。

### 题型套路沉淀

- **「最小化最大值 / 最大化最小值」→ 二分答案**：看到这种「极值的最优值」表述，先想能不能写一个单调的判定函数 `check(x)`，再对 `x` 的值域二分。同族信号词：第 K 小、在 `X` 天内完成、容量下限、最小速度。
- **判定用贪心、答案用二分**是这类题的标准分工：外层二分定答案，内层贪心做可行性验证。两者耦合点就是「`check` 必须关于答案单调」。
- **二分区间模板选一支就固定下来**：本题用「开区间 `(left, right)` + `left + 1 == right` 收敛 + 左假右真」的写法。**下界一定是判定为假的值，上界一定是判定为真的值** —— 这一条是二分答案里最容易出错、也最容易被当成「无所谓」的地方。
- **模板复用**（本题可以直接套用的骨架）：

```python
lo = <保证 check(lo) == False 的值>
hi = <保证 check(hi) == True 的值>
while lo + 1 < hi:
    mid = (lo + hi) // 2
    if check(mid):
        hi = mid
    else:
        lo = mid
return lo + 1        # 即 hi，最小的可行值
```
