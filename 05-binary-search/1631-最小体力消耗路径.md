# 1631. 最小体力消耗路径

> **难度**：中等
> **标签**：二分
> **原题链接**：https://leetcode.cn/problems/path-with-minimum-effort/

---

## 一、题目描述

给定一个 `rows x columns` 的高度矩阵 `heights`，从左上角 `(0, 0)` 出发走到右下角 `(rows-1, columns-1)`，每一步可以往**上、下、左、右**四个方向之一移动一格。

一条路径的**体力值**定义为：路径上**相邻格子高度差绝对值的最大值**（不是求和）。求所有路径中体力值的最小值。

### 示例

```text
输入：heights = [[1,2,2],[3,8,2],[5,3,5]]
输出：2
解释：路径 [1,3,5,3,5] 上相邻格子差值绝对值最大为 2。
      另一条路径 [1,2,2,2,5] 最大值是 3，更差，所以答案是 2。
```

```text
输入：heights = [[1,2,3],[3,8,4],[5,3,5]]
输出：1
解释：路径 [1,2,3,4,5] 上相邻格子差值绝对值最大为 1。
```

```text
输入：heights = [[1,2,1,1,1],
                 [1,2,1,2,1],
                 [1,2,1,2,1],
                 [1,2,1,2,1],
                 [1,1,1,2,1]]
输出：0
解释：存在一条全程等高的路径，不需要消耗任何体力。
```

### 约束条件

- `rows == heights.length`，`columns == heights[i].length`
- `1 <= rows, columns <= 100`
- `1 <= heights[i][j] <= 10^6`

## 二、解题思路

### 核心思想

**答案是单调谓词的临界点，于是不枚举路径，改为二分答案 + 连通性判定。** 把问题反过来问：给定阈值 `x`，只允许走高度差 ≤ `x` 的相邻边，能不能从左上角走到右下角？

### 思路演进

1. **暴力解法**：枚举 `(0,0) → (rows-1, columns-1)` 的全部路径，对每条路径求「相邻高度差绝对值的最大值」，再取全局最小。路径条数随网格规模指数级增长，`100 x 100` 时根本跑不完。

   > **这里有个必须避开的直觉陷阱**：看到「网格 + 从左上到右下」就想写 DP，按「从左、从上转移」来做。但本题允许**四个方向**移动，路径可以走成「S 形」绕远（例如先向左、再向下、再向右），一个格子的最优值不再只由它的左、上邻居决定 —— **最优子结构不成立**，状态转移方程写不出来。这题不是 DP 题。

2. **观察到**：换个视角，定义谓词

   `f(x)` = 「把矩阵中所有高度差 > `x` 的相邻边"删掉"后，`(0,0)` 与 `(rows-1, columns-1)` 仍连通」

   `x` 变大 ⇒ 被删的边变少（可用边集合单调不减）⇒ 原来能连通的一定还能连通。所以 `f(x)` 关于 `x` **单调**：存在一个分界点，左边全是 `false`、右边全是 `true`。而题目要的答案，恰恰就是**使 `f` 首次为 `true` 的最小 `x`**。

3. **优化为**：既然谓词单调，就在候选区间上**二分** `x`；每次判定只做一次 **BFS**（只沿高度差 ≤ `x` 的边扩展），检查右下角是否被访问过。整个暴力枚举路径的过程，被压缩成值域上的 `O(log V)` 次连通性判定。

### 关键点

- **二分的对象是"答案"本身**（路径上最大的那个高度差），不是数组下标。这是「二分答案」题型与普通二分查找的分水岭：判定函数做的是**逻辑判定**（连通 / 不连通），不是数值比较。
- **判定的语义是"存在"**：只要 BFS 能触达终点，就说明存在一条全部相邻差 ≤ `x` 的路径，命题为真；所以只需在模拟结束后检查 `(m-1, n-1) in seen`。
- **区间用开区间 + 两端哨兵，写起来最不容易错**：
  - `left = -1`：**必假**的哨兵 —— 答案下界是 `0`（等高路径），所以 `-1` 一定不可行。
  - `right = max(heights) - min(heights) + 1`：**必真**的哨兵 —— 取到矩阵全局极差时，任何相邻格的高度差都不会超过它，网格必然连通；`+1` 再留一格余量。
  - 循环条件写成 `while left + 1 < right`，退出时天然满足「`left` 必假、`right` 必真」，直接 `return right`，不需要任何额外的答案变量或边界特判。
- **别把它和最短路混淆**：这里的路径代价是**取 max**（瓶颈边）而不是求和，所以不能直接套 Dijkstra 的 `dist` 累加 —— 累加出来的东西和题意无关。

## 三、代码实现

### 最终代码

> `deque` 与 `List` 的 import 截图里没有，已补。

```python
from collections import deque
from typing import List


class Solution:
    def minimumEffortPath(self, heights: List[List[int]]) -> int:
        n = len(heights[0])          # 列数
        m = len(heights)             # 行数

        # 开区间二分：left 恒为「不可行」，right 恒为「可行」
        left = -1                                                        # 哨兵：答案最小为 0
        right = max(max(row) for row in heights) - min(min(row) for row in heights) + 1   # 哨兵：全局极差下必然连通

        while left + 1 < right:
            mid = (left + right) // 2

            # 判定：只允许走高度差 <= mid 的相邻边，能否从 (0,0) 走到 (m-1, n-1)
            q = deque()
            q.append((0, 0))
            seen = {(0, 0)}                      # 每轮判定都要重建
            while q:
                x, y = q.popleft()
                for nx, ny in [(x - 1, y), (x + 1, y), (x, y - 1), (x, y + 1)]:
                    if (0 <= nx < m and 0 <= ny < n
                            and (nx, ny) not in seen
                            and abs(heights[x][y] - heights[nx][ny]) <= mid):
                        q.append((nx, ny))
                        seen.add((nx, ny))

            if (m - 1, n - 1) in seen:           # 连通 ⇒ mid 可行，尝试更小的答案
                right = mid
            else:                                # 不连通 ⇒ mid 不可行，抬高下界
                left = mid

        return right
```

## 四、复杂度分析

记 `n` = 网格的**格子总数** = `rows × columns`；`V` = 二分值域的宽度，即代码中 `right` 的取值上界（本题为矩阵全局极差 + 1，不超过 `10^6 + 1`）。

| 版本 | 时间复杂度 | 空间复杂度 |
| :--- | :--- | :--- |
| **最终代码**（二分 + BFS 判定） | O(n log V) | O(n) |
| 逐个候选值从小到大试（线性扫 x） | O(n · V) | O(n) |
| 枚举所有路径取最优 | 指数级 | O(n)（递归栈） |
| 理论下界 | O(n) | O(n) |

> 复杂度中的 n 指网格的格子总数 `rows × columns`（本题最大 `10^4`）。
>
> - 二分共 `log₂V` 轮；每轮 BFS 最多访问全部 `n` 个格子、检查 `4n` 条边，是 `O(n)`。
> - 空间上 `seen` 与队列各自最多装 `n` 个格子。
> - 「理论下界 O(n)」的依据：任何算法至少要把全部格子读一遍，否则可能漏掉某条关键路径，因此时间不可能低于 O(n)。

## 五、优化评估

**结论**：在「二分答案」这条路线下已是稳定形态，两个复杂度因子都没有可再压缩的余地。

### 瓶颈分析

总时间 = **二分轮数 × 单次判定**。二分轮数由值域宽度决定（`log₂V`）；单次判定必须把起点所在的连通块至少遍历一遍，否则无法断定「真的到不了终点」，因此是 `O(n)`。两者各自处在不同的维度上，都不可省。

### 可优化空间

- 候选值从 `V` 个压缩到 `log₂V` 次判定，已经把「单调性」提供的信息吃干了 —— 再想减少轮数，就只能放弃二分。
- 判定环节不存在「只看局部就能给出结论」的捷径：连通性是一个**全局性质**，右下角不可达时必须穷尽整个可达区域才能确认。
- 因此 `O(n log V)` 是本路线的时间下界形态。（本题 `rows, columns ≤ 100`，`n ≤ 10^4`、`log₂V ≤ 20`，总操作量远在限制之内。）

## 六、易错点与总结

### 易错点

- **把体力值当成"高度差之和"** —— 这是本题最容易翻车的地方。一旦理解成求和，就会滑向最短路 / DP，整份代码的答案都是错的。题目要的是「路径上最大单步落差」。
- **试图用 DP 从左、上转移**：四方向可绕行 ⇒ 最优子结构不成立，转移方程写不出来。看到「网格 + 左上到右下」先别急着 DP，先确认移动方向是否受限。
- **二分边界写反或漏掉哨兵**：`left` 必须落在「必假」的位置（本题取 `-1`），`right` 必须落在「必真」的位置。若图省事写 `left = 0`，返回时机就会跑偏。
- **判定结束后检查错对象**：要判断的是终点是否被访问（`(m - 1, n - 1) in seen`），而不是「队列是否空了」。
- **`seen` 忘记每轮重建**：判定是在不同阈值下的**不同子图**上进行的，上一轮访问过的格子会污染下一轮，导致结果单调性被破坏。
- **起点即终点的退化情形**：`1 x 1` 矩阵时答案为 `0`，哨兵 `right` 的构造要能覆盖这种情况（本题 `right = 0 - 0 + 1 = 1`，`mid = 0` 时起点已在 `seen` 中，正确返回 `0`）。

### 题型套路沉淀

- **「最小化最大边权 / 最大化最小边权」类问题**：只要答案是一个**单调谓词的临界点**，就可以二分答案，把「在指数级路径空间里搜索」换成「在值域上做 `log` 次可行性判定」。本题的判定是网格连通性（BFS / DFS），凡是这类骨架都可以套用。
- **二分答案三件套**，缺一不可：
  1. 说清楚**单调的判定命题**是什么（这里是「阈值 `x` 下起点终点是否连通」）；
  2. 定死**候选区间与两端哨兵**（一假一真，`while left + 1 < right` 的开区间写法最省心）；
  3. 判定内部的**状态必须独立重建**（`seen`、队列），不能跨轮复用。
- **瓶颈路径问题还有另外两族等价解法**：按边权升序 + 并查集（Kruskal 式，首次连通时的边权即答案）、或把松弛规则改成 `dist[v] = max(dist[u], w)` 的 Dijkstra 式做法。判断该用哪族，就看题目给的形态更适合「排序边」还是「节点上跑搜索」—— 二分这一族的优势是框架最通用、把难度全推给了一个简单的判定函数。
