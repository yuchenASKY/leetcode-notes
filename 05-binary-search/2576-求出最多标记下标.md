# 2576. 求出最多标记下标

> **难度**：中等
> **标签**：二分
> **原题链接**：https://leetcode.cn/problems/find-the-maximum-number-of-marked-indices/

---

## 一、题目描述

给定一个下标从 0 开始的整数数组 `nums`。初始时所有下标都未标记，你可以执行任意次如下操作：选出两个**互不相同、且都尚未被标记**的下标 `i` 和 `j`，若满足 `2 * nums[i] <= nums[j]`，就把 `i`、`j` 一起标记。求最多能标记多少个下标。

理解题意时要注意三点：

- `i` 与 `j` 是**有角色区分**的：`i` 是被「翻倍后不超过对方」的那一方（下称**小端**），`j` 是承接的一方（下称**大端**）；反过来不一定成立。
- 一个下标一旦被标记就不能再用，所以是「配对」问题而不是「计数」问题。
- 每次操作固定消耗 2 个下标 ⇒ **答案一定是偶数**。

### 示例

```text
输入：nums = [3,5,2,4]
输出：2
解释：选 i = 2（值 2）、j = 1（值 5），此时 2 * nums[2] = 4 <= nums[1] = 5，标记下标 2 和 1。
      剩下的下标无法再凑出一次合法操作，故答案为 2。

输入：nums = [9,2,5,4]
输出：4

输入：nums = [7,6,8]
输出：0
```

### 约束条件

- `1 <= nums.length <= 10^5`
- `1 <= nums[i] <= 10^9`

## 二、解题思路

### 核心思想

**答案只取决于元素的值、与原始下标位置无关，所以先排序。** 排序之后可以证明：如果总共能标记 `2k` 个下标，那最优形态一定是「最小的 `k` 个元素」与「最大的 `k` 个元素」按顺序一一配对。于是「能否标记 `2k` 个」退化成一个 O(k) 的逐对比对；而这个判定对 `k` 单调，外层套二分答案即可。

### 思路演进

1. **暴力解法**：直接枚举配对方案 —— 挑哪些元素、谁当小端谁当大端、如何组成一个完整匹配，方案数随 n 指数级膨胀；退一步，哪怕只是「从小到大枚举 k，对每个 k 尝试构造出 `2k` 个标记」，最坏也要 O(n²)。

2. **观察到**：标记动作只用到 `nums` 的**值**，完全不在意下标原来的位置 ⇒ 可以随意重排，先 `sort` 一定不吃亏。
   进一步，每一对被标记的元素中小端 `a`、大端 `b` 满足 `2a <= b`。因为 `nums[i] >= 1`，`2a <= b` 不可能取到 `a = b`，所以**小端一定严格小于大端**。把被标记的 `2k` 个元素升序排列，前 `k` 个天然就是小端的候选集合、后 `k` 个是大端的候选集合。

3. **关键转化（把"找匹配"变成"按序比对"）**：在被标记的 `2k` 个元素里，「小端取尽可能小的、大端取尽可能大的」只会让 `2a <= b` 更容易成立；同侧再按值升序配对，用交换论证（`a_i < a_j` 却配成了 "`a_i` 配更大的大端" 时，交换回来不会变差）即可确认最优形态唯一。于是判定只剩一种需要检查的形状：

   > 令 `k = cnt / 2`，检查是否对所有 `i ∈ [0, k)` 都满足 `2 * nums[i] <= nums[n - k + i]`。

   也就是排序后数组的**前缀 `k` 个**与**后缀 `k` 个**按序号一一配对。判定代价从「组合级地找一个匹配」降到 O(k)。

4. **优化为**：判定 `check(cnt)` 关于 `cnt` 单调 —— 能标记 `2k` 个，就一定能标记 `2(k-1)` 个（少用一对即可）。所以答案是「最大的可行 `cnt`」，可以在 `[0, n]` 上二分，每轮 O(n)、共 O(log n) 轮。

### 关键点

- **答案必为偶数，二分结果必须修正**。`check` 内部用 `cnt // 2` 取对数，因此它在奇偶上是「退化」的：`check(2k + 1) ≡ check(2k)`。于是二分可能收敛到一个**奇数** `left`（只因为 `check(2k+1)` 为真），此时真实答案应是 `left - 1`。这就是结尾 `left if left % 2 == 0 else left - 1` 的来由，漏掉它会在这种情形下多算 1。

  小例子：`nums = [1, 3, 3]`。`check(3)` 取 `k = 1`，比较 `nums[0] = 1` 与 `nums[3 - 1 + 0] = nums[2] = 3`，`2 <= 3` 成立 ⇒ `check(3)` 为真、`check(4)` 因 `n = 3` 无法构造而为假，二分停在 `left = 3`。但 3 个下标根本标不满（每次必须标 2 个），真实答案是 2 —— 靠 `left - 1` 才修正过来。

- **配对方向不能反**：必须是「前缀第 `i` 小的」配「后缀第 `i` 小的」，即 `nums[n - k + i]`；写成 `nums[n - 1 - i]`（最小配最大）是另一种形态，**并不等价**。`[1, 2, 3, 4]` 取 `k = 2` 时按序可行（`2*1 <= 3`、`2*2 <= 4`），反序不可行（`2*2 <= 3` 不成立），方向写反会把不可行的 `k` 判成可行。

- **排序是判定的前提**：`check` 里的「前缀 / 后缀」只有在数组升序时才有意义，忘记排序则整个判定失效。

- **二分的边界设置**：用半开区间 `left = -1`、`right = n + 1`，`check(0)` 恒真（`k = 0` 时空循环）、循环内 `mid` 最大只会取到 `n`，因此 `check` 不会越界 —— 当 `cnt = n` 时最后一个被访问的下标正好是 `nums[n - 1]`。

## 三、代码实现

### 最终代码

```python
from typing import List


class Solution:
    def maxNumOfMarkedIndices(self, nums: List[int]) -> int:
        nums.sort()
        n = len(nums)

        def check(cnt: int) -> bool:
            # 判定能否标记 cnt 个下标：取 k = cnt // 2 对
            # 最优形态 = 最小的 k 个配最大的 k 个，且按序配对
            for i in range(cnt // 2):
                if 2 * nums[i] > nums[n - cnt // 2 + i]:
                    return False
            return True

        left = -1
        right = n + 1
        while left + 1 < right:
            mid = (left + right) // 2
            if check(mid):
                left = mid
            else:
                right = mid
        return left if left % 2 == 0 else left - 1
```

> 截图里只有 `class Solution` 部分，`from typing import List` 是补上的（LeetCode 环境默认已导入该名称，本地运行需要自己加）。

## 四、复杂度分析

| 版本 | 时间复杂度 | 空间复杂度 |
| :--- | :--- | :--- |
| **最终代码** | O(n log n) | O(n)（排序的辅助空间） |
| 朴素解法（枚举 k 逐个尝试构造） | O(n²) | O(1) |
| 理论下界 | O(n log n) | O(1)（不计排序） |

> 复杂度中的 n 指数组 `nums` 的长度。时间由两块构成：排序 O(n log n)，加上二分 O(log n) 轮 × 每轮 `check` O(n) 的判定，两块相加仍是 O(n log n)。空间上除排序外只用了常数个变量；Python 的 `list.sort`（Timsort）最坏需要 O(n) 临时空间，把它计入则为 O(n)。

## 五、优化评估

**结论**：时间复杂度已达到比较模型下的**理论下界**，没有进一步压缩的空间。

### 瓶颈分析

本题的判定条件 `2 * nums[i] <= nums[j]` 完全依赖元素之间的大小关系，任何解法都必须以某种方式获得「序」信息；而基于比较的排序下界是 O(n log n)，所以 O(n log n) 就是这题的终点。

二分部分并不是瓶颈：它只贡献 O(log n) 轮 × O(n) 的判定，与排序同阶，常数上还明显小于排序本身。排序才是真正吃时间的那一块。

### 可优化空间

无。判定的形态（前缀配后缀、按序比对）由交换论证确定，是这个问题的唯一检查形状；剩下能动的只有常数因子。

### 常数级优化（可选）

可以把「二分 `log n` 轮判定」整体省掉，换成一次线性双指针扫描 —— 大 O 不变（仍由排序主导），但省去了 `log n` 次函数调用与重复的索引运算：

```python
from typing import List


class Solution:
    def maxNumOfMarkedIndices(self, nums: List[int]) -> int:
        nums.sort()
        n = len(nums)
        half = n // 2
        i, j = 0, half          # i 扫前半（当小端），j 扫后半（当大端）
        pairs = 0
        while i < half and j < n:
            if 2 * nums[i] <= nums[j]:
                pairs += 1      # 配上了，双方一起前进
                i += 1
            j += 1              # 这个大端配不上，换下一个更大的
        return pairs * 2
```

**优化理由**：把「二分去找最大的可行 k」换成「贪心地一次把能给的小端都配上」。`i`、`j` 都只单调前进，所以扫描本身是 O(n)；它之所以正确，前提仍然是「前一半当小端、后一半当大端、按序配对」这个已经证明过的形态。总复杂度依旧是 O(n log n)，由排序决定。

## 六、易错点与总结

### 易错点

- **二分结果必须修正为偶数**：`check` 用 `cnt // 2` 取对数，导致 `check(2k+1) ≡ check(2k)`，二分可能停在奇数上；直接返回 `left` 会多算 1（如 `[1,3,3]` 会错答 3）。
- **配对方向写反**：要用后缀起点 `n - k + i`（前缀第 i 小配后缀第 i 小），不是 `n - 1 - i`（最小配最大）。两者不等价，写反会放过本不可行的 `k`。
- **后缀起点算错**：`k = cnt // 2`，后缀 `k` 个的起点是 `n - k`，把 `k` 在多处重复展开成 `cnt // 2` 时容易把 `n - cnt // 2` 写错一位。
- **忘记排序**：`check` 的前提是数组升序，「前 k 小 / 后 k 大」的结论只在有序数组上成立。
- **误以为 `i`、`j` 可以随意互换**：约束是单向的 `2 * nums[i] <= nums[j]`，小端与被翻倍的一方必须是同一个人。

### 题型套路沉淀

- **二分答案（最大化可行值）的固定骨架**：
  1. 写出 `check(x)`：以 O(n) 的代价判定「答案是否至少为 x」；
  2. 验证单调性 —— 这里「能标 `2k` 个」⇒「能标 `2(k-1)` 个」；
  3. 用半开区间 `left = 下界哨兵, right = 上界哨兵` 二分，收敛到最后一个 `check` 为真的点；
  4. **回到答案的定义域上修正结果**（本题答案恒为偶数，收敛值落在奇数时要减 1）。第 1 步的 `check` 越"局部"，整题越简单。
- **「存在性判定 → 形态唯一化」是这类题最值钱的一步**：先论证最优解一定长成某个特定形状（前缀配后缀、按序配对），判定复杂度就从「找一个匹配」降到「按序比对」。凡是「配对 / 匹配 + 不等式条件」的题，都先试着把最优形态钉死，再谈怎么找最大的可行规模。
- **排序不改变答案的识别信号**：题目的约束只依赖元素的**值的相对大小**、不依赖原始位置时，优先考虑排序 —— 它通常能把隐含的结构（大小、序、前后缀）直接暴露出来。
