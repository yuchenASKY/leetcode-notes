# 2080. 区间内查询数字的频率

> **难度**：中等
> **标签**：设计 · 线段树 · 数组 · 哈希表 · 二分查找
> **原题链接**：https://leetcode.cn/problems/range-frequency-queries/

---

## 一、题目描述

实现一个数据结构类 `RangeFreqQuery`：构造时给定一个 0 起始的整数数组 `arr`，之后可以反复调用 `query(left, right, value)`，返回闭区间 `arr[left...right]` 中 `value` 出现的次数（即"频率"）。

一句话概括：**一次构造、多次「区间内某值的计数」查询**。

### 示例

```text
输入：
["RangeFreqQuery", "query", "query"]
[[[12, 33, 4, 56, 22, 2, 34, 33, 22, 12, 34, 56]], [1, 2, 4], [0, 11, 33]]
输出：
[null, 1, 2]

解释：
query(1, 2, 4)  -> 1   子数组 [33, 4] 中，4 出现 1 次
query(0, 11, 33) -> 2  整个数组中，33 出现在下标 1 和 7，共 2 次
```

### 约束条件

- `1 <= arr.length <= 10^5`
- `1 <= arr[i], value <= 10^4`
- `0 <= left <= right < arr.length`
- 调用 `query` 不超过 `10^5` 次

---

## 二、解题思路

### 核心思想

**把"在区间里找值"翻转成"按值看下标"。** 预先为每个值收集它在数组中出现的全部下标（天然递增），一次 `query` 就退化成"在这张有序下标表里数有多少个下标落在 `[left, right]` 内" = 两次二分。

### 思路演进

1. **暴力解法**：每次 `query` 直接从 `left` 扫到 `right` 计数。单次 O(right − left + 1)，最坏 O(n)；`n = 10^5`、`q = 10^5` 时上界 **10^10** 次比较，必然超时。

2. **瓶颈定位**：`query` 之间彼此独立，看不出可复用的中间结果，所以瓶颈不在"某一步算重了"，而在**值这一维被反复原地重扫**。一个自然的补救是"空间换时间"——前缀和 `pre[i][v] = 前 i 个元素里 v 的个数`，查询变 O(1)。但空间是 **O(n·V) = 10^5 × 10^4 = 10^9**，直接爆内存；只对出现频率高的值建前缀和，又要引入阈值分治，工程复杂度不划算。

3. **关键转化**：**不要按位置组织信息，按值组织信息。** 记录 `pos[v] = [v 出现的所有下标]`。
   - 由于是按下标从小到大 `append`，`pos[v]` **本身就是升序的** —— 有序性由构造方式白送，不需要额外排序。
   - 于是 `v 在 [left, right] 里的出现次数` ⟺ `pos[v] 中满足 left ≤ 下标 ≤ right 的元素个数`，两端各一次二分即可，**与区间长度完全无关**。
   - 一句话说清差别：原来不行，是因为每次都要重新走一遍区间；现在行，是因为"区间约束"被转成了对一个**与区间长度无关的有序表**的两次边界定位。

4. **最优解**：左端用 `bisect_left(a, left)`（第一个 `≥ left` 的位置 ⟺ 区间内第一个下标），右端用 `bisect_right(a, right)`（第一个 `> right` 的位置 ⟺ 区间外第一个下标），两者之差就是区间内下标个数。

### 关键点

- **`bisect_left` / `bisect_right` 里的"左/右"指的是插入位置，不是区间端点**，闭区间必须"左端用 `left`、右端用 `right`"：

  | 调用 | 返回的位置语义 |
  | :--- | :--- |
  | `bisect_left(a, left)` | 第一个 `≥ left` 的元素位置 ⟺ 区间内首下标 |
  | `bisect_right(a, right)` | 第一个 `> right` 的元素位置 ⟺ 区间外首下标 |

  两者之差 = 落在 `[left, right]` 内的下标个数。

- **等价写法（靠"整数性"兜底）**：下面三个式子**逐位等价**（本次 46 组用例 + 官方示例上输出完全一致）
  - `bisect_right(a, right) - bisect_left(a, left)`
  - `bisect_right(a, right) - bisect_right(a, left - 1)`
  - `bisect_left(a, right + 1) - bisect_left(a, left)`

  等价的前提只有一条：**下标是整数**，所以 `a[k] ≤ right ⟺ a[k] < right + 1`，`a[k] ≥ left ⟺ a[k] > left - 1`。
  但**等价 ≠ 等价代价** —— 实测把两端统一成 `bisect_left(a, right + 1)` 的写法在各个场景下都**不更快**（见 §五）。

- **下标表的有序性是"构造出来的"，不是题面给的**：本题靠 `append` 顺序 = 遍历顺序，属于送分；一旦换成前缀和之类需要自身单调的结构，单调性就要由"元素非负"这类性质推出来。这类**前提必须自己论证并写进笔记**，否则换数据会静默失效。

### 判据与判据族定位

- **本题判据**：`答案 = bisect_right(pos[value], right) - bisect_left(pos[value], left)`，即"有序表上两个边界位置之差"。
- **判据族**：属「**有序序列上的单调谓词边界定位**」（下标二分）族 —— 二分对象是**预构造的有序下标表**，谓词直接来自数组自身的单调性（"下标 > right"）。
  同目录下还共存另一族「**二分答案**」（最小化最大值 / 第 K 小 / 可行域二分）：那里二分的是**答案值**、谓词是 `check(x)` 的可行性，`while` 写法与边界处理都不同，**两族不得串用**。
- 本题**不是滑动窗口题** ⇒ 滑窗那套判据框架（窗口合法性来源、左指针收缩方式、答案口径四象限）在这里**一律不适用**，不要往上面套。
- 与本族最常见的"在原数组上二分"子形态相比，本题多一层：**有序序列是自己造出来的**，所以要多写一次前提论证。

## 三、代码实现

### 最终代码

```python
from bisect import bisect_left, bisect_right
from collections import defaultdict


class RangeFreqQuery:

    def __init__(self, arr: list[int]):
        pos = defaultdict(list)
        for i, x in enumerate(arr):
            pos[x].append(i)          # 按下标递增 append => pos[x] 天然升序
        self.pos = pos

    def query(self, left: int, right: int, value: int) -> int:
        a = self.pos[value]
        return bisect_right(a, right) - bisect_left(a, left)
```

> 截图里只有 `class RangeFreqQuery:` 本体，`from bisect import bisect_left, bisect_right` 与 `from collections import defaultdict` 是**补齐**的（截图里没有，已补），补上后可直接运行。

## 四、复杂度分析

| 版本 | 时间复杂度 | 空间复杂度 |
| :--- | :--- | :--- |
| **最终代码** | 构造 O(n)；单次查询 O(log m_value)；总计 O(n + q log n) | O(n) |
| 朴素解法（每次扫区间） | 构造 O(1)；单次查询 O(right − left + 1)，最坏 O(n)；总计 O(n·q) | O(1) |
| 值域前缀和 | 构造 O(n·V)；单次查询 O(1) | O(n·V) |
| 理论下界 | 构造 Ω(n)；单次查询 Ω(log m_value) | Ω(n) |

> 复杂度中的 n 指 `arr` 的长度，q 指 `query` 的调用次数，V 指值域宽度（本题 10^4），m_value 指 `value` 在 `arr` 中的出现次数（有 m_value ≤ n）。

规模感：`n = q = 10^5` 时，朴素解约 **10^10** 次比较，本解约 **1.7 × 10^6** 次 —— **差 4 个数量级**，这就是"能不能 AC"的分界线。

下界依据：
- **构造**至少要读完整个数组（漏掉任何一次出现，对应值的下标表就不完整）⇒ Ω(n)。
- **单次查询**的结果落在 `[0, m_value]` 共 `m_value + 1` 种可能，且必须读到 `left`/`right` 才能定位边界；任何只靠"有序下标表"作答的算法在比较模型下需要 Ω(log m_value) 次决策。两次 `bisect` 正好达到该量级。
- **空间**：每个下标都要能被将来某次查询取到（题目允许 `left = 0, right = n - 1`），故 Ω(n)。

## 五、优化评估

**结论**：**渐进复杂度已经是理论下界**，在线与离线都没有更快的路线；但常数项有两个可动的点 —— ① 构造阶段用「值域数组」替代哈希表；② 对"查询值不存在"的输入加**空表提前返回**。两者合起来（下文的 D 版）在四档场景上**全部不低于原版**，构造阶段还快 1.31× ~ 1.36×。

### 瓶颈分析

时间分布（n = 10^5、q = 3 × 10^4）：

- **构造阶段**：10.5 ~ 14 ms —— 这是最大的一块，且几乎全在 10^5 次 Python 层循环里。
- **查询阶段**：单次 0.18 μs（值不存在档）~ 0.76 μs（全同值、候选表最长档）。代价随 `log m_value` 变化，量级很稳；每次查询的固定开销 = 1 次查表 + 2 次 C 层 `bisect` 调用 + 1 次减法。

⇒ 可动的只有两处：**换掉查表方式**、**减少 `bisect` 调用次数**。二分本体在 C 层，Python 层碰不到。

### 可优化空间

逐条排除其他路线：

- **值域前缀和**：空间 O(n·V) = 10^9，爆内存。**出局。**
- **线段树 / 树状数组**（题面标签里就有"线段树"）：每个节点需要挂一张"值 → 计数"的表，空间 O(n log n)；单次查询 O(log n) 但常数远大于两次 C 层 `bisect`（每次下降要查哈希表 + 递归/循环开销）。*本条为定性判断，本次未实测。*
- **莫队 / 离线排序**：O((n + q)·√n) ≈ 3 × 10^7 次操作，而本解只有 ≈ 1.7 × 10^6 次比较 —— **慢一个数量级以上**，还得离线。

⇒ **在线路线上，"值 → 有序下标表 + 两次二分"就是终点**，剩下的只能是常数项。

### 优化代码

```python
from bisect import bisect_left, bisect_right


class RangeFreqQuery:
    """值域数组 + 空表提前返回（依赖题面保证 1 <= arr[i], value <= 10^4）"""

    def __init__(self, arr: list[int]):
        pos = [[] for _ in range(10001)]   # 下标即值；arr[i] >= 1，故 0 号槽空置
        for i, x in enumerate(arr):
            pos[x].append(i)               # 列表下标定位，省掉 10^5 次哈希查找
        self.pos = pos

    def query(self, left: int, right: int, value: int) -> int:
        a = self.pos[value]
        if not a:                          # 该值从未出现：直接返回 0，省掉两次二分
            return 0
        return bisect_right(a, right) - bisect_left(a, left)
```

**优化理由**：

1. **构造阶段**：把"值 → 下标表"的映射从哈希表换成**值域数组**（列表下标即值），10^5 次哈希查找换成 10^5 次列表索引，构造耗时 **13.9 ms → 10.5 ms（1.33×）**。
2. **查询阶段**：`if not a: return 0` 让"值从未出现"的查询免掉 2 次 C 层函数调用（0.18 μs → 0.14 μs，**1.34×**）；在命中档只多一次真值测试，实测**没有一档变慢**。

**⚠️ 前提与替代方案**：数组长度写死成 `10001`，直接绑在题面的 `value ≤ 10^4` 上 —— 换到值域不受保证的场景，`self.pos[value]` 会当场 `IndexError`。此时应退回「普通 `dict` + `get` + 提前返回」：

```python
    def __init__(self, arr):
        pos = {}
        for i, x in enumerate(arr):
            if x in pos:
                pos[x].append(i)
            else:
                pos[x] = [i]
        self.pos = pos

    def query(self, left, right, value):
        a = self.pos.get(value)
        if a is None:
            return 0
        return bisect_right(a, right) - bisect_left(a, left)
```

实测这一版在"查询常未命中"档比原版快 **1.43× ~ 1.67×**，代价是命中档慢 **0.92× ~ 0.98×**。⇒ **值域有保证选数组、无保证选 dict**，两条路的取舍点是"值的分布"而不是"哪种写法更高级"。

### 常数级优化

四档场景（n = 10^5、q = 3 × 10^4）、8 个变体**轮转**测量、各取 9 轮最优。倍数 = 原版耗时 ÷ 该版耗时，**> 1 表示更快**：

| 变体 | S1 高重复+全命中 | S2 值域只 100+常未命中 | S3 全同值（表最长） | S4 值域 10^4+基本命中 |
| :--- | :--- | :--- | :--- | :--- |
| A 原版（截图代码） | 0.48 μs / 1.00× | 0.18 μs / 1.00× | 0.76 μs / 1.00× | 0.60 μs / 1.00× |
| B dict.get + 提前返回 | 0.49 / 0.98× | 0.11 / **1.67×** | 0.82 / 0.93× | 0.61 / 0.98× |
| C 值域数组 | 0.47 / 1.03× | 0.18 / 1.03× | 0.74 / 1.03× | 0.52 / 1.17× |
| **D 值域数组 + 提前返回** | **0.46 / 1.05×** | **0.14 / 1.34×** | **0.69 / 1.10×** | **0.52 / 1.15×** |
| G D + 值域越界守卫 | 0.52 / 0.94× | 0.15 / 1.25× | 0.75 / 1.01× | 0.56 / 1.07× |
| H D + bisect 存类属性 | 0.54 / 0.89× | 0.13 / 1.39× | 0.79 / 0.96× | 0.59 / 1.03× |

**构造 n = 10^5 耗时**：A 13.9 ms / B 16.0 ms / C 10.6 ms / **D 10.5 ms（1.33×）**。

**被证伪的改法**（用删除线保留，避免重犯）：

- ~~用 `bisect_left(a, right + 1)` 取代 `bisect_right(a, right)`~~：结果**逐位等价**（46 组用例 + 官方示例 0 偏差），但实测 **0.87× ~ 0.99×，没有任何一档更快**。每轮多一次整数加法，且 `right + 1 > 256` 时会新建一个 `int` 对象。⇒ **"等价"只保证结果相同，不保证代价相同**。
- ~~给 D 版加值域越界守卫~~（G 版 `if value > 10000: return 0`）：代码更健壮，但四档全部退化（命中档 **0.94× ~ 1.07×**，miss 档 1.34× → 1.25×）。题面已给值域保证时，这道守卫是**纯成本**；要健壮性就整体改用 B 版的 dict 路线。
- ~~把 `bisect_left` / `bisect_right` 缓存成类属性~~（H 版 `H.br` / `H.bl`）：命中档 **0.89× ~ 1.03×**，不如直接引用模块全局名。Python 的模块全局名查找与类属性查找单价相当，`H.br` 还要多走一层 —— **"把函数缓存到类上"在这里不是优化**。

## 六、易错点与总结

### 易错点

- **`bisect_left` / `bisect_right` 用反或写成同一个**：`bisect_left(a, right)` 会漏掉"恰好落在 `right` 上"的那个下标；`bisect_right(a, left)` 会把 `left` 之前的越界下标算进去。闭区间 `[left, right]` 必须是"左端 `left` 用 `bisect_left`、右端 `right` 用 `bisect_right`"。
- **`defaultdict` 的"读"会变成"写"**：`self.pos[value]` 在 `value` 从未出现时会**静默插入一个空表**（实测：查询前 2 个键，读完 `pos[9999]` 后变 3 个键）。本题 q ≤ 10^5、值域 ≤ 10^4，最多多插 10^4 个空表，**不影响正确性**；但这是"读操作改状态"，多线程共享实例或长期持有并反复探测不同 key 时要留意。改用 `dict.get(value)` 不会插入（实测键数不变），代价是命中档慢 0.92× ~ 0.98×。
- **两个守卫的失败形态完全不同，别混为一谈**：删掉 D 版的 `if not a: return 0`，同一批 40 组随机用例**偏差仍为 0**（它退化成 C 版）—— 这行**只买常数、不买正确性**；而删掉 B 版的 `if a is None: return 0` 会**首组用例就抛** `TypeError: object of type 'NoneType' has no len()`。
- **值域数组的上界是硬编码前提**：写死 `10001` 就绑定了题面的 `value ≤ 10^4`，换题换数据必须改，否则静默越界失败。

### 题型套路沉淀

- **"区间计数" → "按值存下标 + 两次二分"**：凡是「多次询问某区间里某元素的**出现次数 / 是否存在**」，标准动作都是"值 → 有序下标表"，查询转成两次边界定位。存在性是它的退化版（`存在性 ⟺ bisect_right > bisect_left`）。
- **二分语义口诀**：`bisect_left(a, x)` = "第一个 `≥ x` 的位置"；`bisect_right(a, x)` = "第一个 `> x` 的位置"。闭区间计数 = `右(right) − 左(left)`。
- **"构造出来的有序性"必须自己论证**：本题的有序性来自 `append` 顺序（送分）；换成前缀和一类结构时，单调性要由"元素非负"这类题面性质推出来，前提不写清就会在换数据时静默失效。
- **二分的常数优化空间极小**：本题两个"看起来更聪明"的改法（`right + 1` 版、类属性缓存版）**实测全部更慢**。二分的时间几乎全在 C 层 `_bisect` 里，Python 层能动的只有两件事 —— **减少调用次数**（提前返回）与**换掉查表方式**（值域数组 / dict）。

2. **随机对拍（小批量）**：手工用例 **6 组 / 17 条查询**（单元素、全同值、值不存在、值域上界 10^4、`left = right`、覆盖整个区间）+ 随机 **40 组 / 240 条查询**（`n ≤ 20`、值域 1 ~ 6、每例 6 次查询）⇒ 合计 **46 组 / 257 条查询**，对 **7 个本次新写的变体**（B / C / D / E / F / G / H）全部跑一遍，**偏差均为 0**。用例总量（含微基准 4 档场景输入与 1 档构造输入）约 **52 组**，远低于 500 上限。
3. **微基准**：见 §五 两张表。n = 10^5、q = 3 × 10^4，四档场景（S1 高重复全命中 / S2 值域只 100 且查询常未命中 / S3 全同值 / S4 值域 10^4 基本命中），8 个变体**同轮轮转**、各取 9 轮最优；构造另测 n = 10^5 × 9 轮。
   8 个变体在**两次独立运行中方向一致**（倍数口径）：如 D 版 S2 为 1.34× / 1.32×、构造为 1.33× / 1.36×；F 版四次读数中三档更慢。但 **A 的绝对耗时两次差约 13%**（构造 13.9 vs 17.7 ms、S1 单次 0.48 vs 0.54 μs）⇒ **笔记只引用倍数，不引用绝对值**。
4. **删守卫定位**（对象是本次新写的代码）：删 D 版空表守卫 → 40 组随机对拍偏差 **0**（纯常数行，退化为 C 版）；删 B 版 `None` 守卫 → 首组用例即 `TypeError`。两种失败形态已写入「易错点」。
5. **实现细节核实**：`defaultdict` 未命中读取会插入键（键数 2 → 3）；同一次探测改用 `dict.get` 后键数保持 3。`bisect_left(a, right + 1)` 与 `bisect_right(a, right)` 的等价性由 46 组对拍 + 官方示例确认（0 偏差），但**不保证代价相同**（见 §五）。
