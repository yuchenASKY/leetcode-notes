# 2226. 每个小孩最多能分到多少糖果

> **难度**：中等
> **标签**：数组 · 二分查找
> **原题链接**：https://leetcode.cn/problems/maximum-candies-allocated-to-k-children/

---

## 一、题目描述

有若干堆糖果，第 `i` 堆大小为 `candies[i]`。每堆可以切成任意多个**子堆**，但**不能**把两堆合并。要把糖分给 `k` 个小孩，要求每个小孩拿到的数量**完全相同**，且每个小孩**至多拿一堆**（多余的糖可以不分）。

求每个小孩最多能拿到多少颗糖。

### 示例

```text
示例 1
输入：candies = [5,8,6], k = 3
输出：5
解释：把 8 切成 5+3，把 6 切成 5+1，得到 [5,5,3,5,1]，挑出 3 堆 5 分给 3 个小孩。
     无法做到每人 6 颗。

示例 2
输入：candies = [2,5], k = 11
输出：0
解释：总糖数 7 < 11，连每人 1 颗都凑不齐，答案是 0。
```

### 约束条件

- `1 <= candies.length <= 10^5`
- `1 <= candies[i] <= 10^7`
- `1 <= k <= 10^12`

---

## 二、解题思路

### 核心思想

**把「求最大 x」翻译成「判定 x 是否可行」。** 对固定的每人份数 `x`，第 `i` 堆能切出 ⌊candies[i] / x⌋ 份，所以

```text
P(x) 为真  ⇔  Σ⌊candies[i] / x⌋ >= k
```

`P(x)` 关于 `x` 单调：`x` 越大，每堆切出的份数越少，`P` 必然呈「真…真、假…假」的形态。
于是不必枚举 `x`，直接在答案值域上**二分找 `P` 的最后一个真值**。

### 思路演进

1. **暴力解法（枚举答案）**：`x` 从 1 递增上去，逐个用 `P(x)` 试，取最大的可行 `x`。
   单次判定要扫一遍数组，而 `x` 最大到 `max(candies) = 10^7`，总代价 O(n·C) ≈ 10^12，必然超时。
   更要紧的是：题意里那句"可以证明无法让每个小孩得到超过 5 颗"本身就没有闭式公式 —— **答案只能靠试**，
   说明这题的分岔点不在"怎么算"，而在"怎么少试几次"。

2. **观察单调性**：固定一堆 `c`，它能贡献的份数 ⌊c / x⌋ 随 `x` 增大而**不增**（不会反弹），
   求和后 `f(x) = Σ⌊c_i / x⌋` 同样单调不增。所以谓词 `P(x) = (f(x) >= k)` 的真值必然是
   一段「可行前缀 + 不可行后缀」，**存在明确的边界**——这正是二分的适用条件。

3. **优化为二分答案**：在值域 `[0, max(candies)]` 上二分这个边界。判定一次 O(n)，
   二分 ⌈log₂(C+1)⌉ 轮 ⇒ **O(n log C)** ≈ 10^5 × 24，稳过。

4. **判定条件为什么是充要的**（这题最容易含糊的一步）：
   - *充分*：每堆切出 ⌊c/x⌋ 份大小为 `x` 的子堆，余数 `c % x` 当废料丢掉。总份数 ≥ k 时，
     任取 `k` 份分给 `k` 个小孩即可，多出来的份不分 —— "至多一堆"的限制天然满足。
   - *必要*：任意合法分配中，每个小孩拿的那堆都是从某原始堆切出来的、大小恰为 `x` 的块，
     同一原始堆 `c` 最多提供 ⌊c/x⌋ 个这样的块，所以 `k <= Σ⌊c_i / x⌋`。
   - 两者合起来 ⇒ **`P(x)` 就是"每人 x 颗"能否办到的充要条件**，可以直接拿来做二分判据。

### 关键点

- **判据**：`Σ⌊candies[i] / x⌋ >= k`，边累加边比较，可以在中途提前返回。
- **哨兵区间**：`left = 0`、`right = max(candies) + 1`，**两个端点都代表"不可行"**。
  0 显然不可行；`max+1` 意味着连最大的那堆都切不出 2 份，也不可能凑够 `k` 份（`k >= 1`）。
- **循环形式**：`while left + 1 < right` 配 `mid = (left + right) // 2`，
  可行时 `left = mid`（保留候选），不可行时 `right = mid`（丢弃候选）。
  终止时 `left`、`right` 相邻，`left` 一定是最后一个可行值 —— 这就是"幽灵二分/半开区间"写法。
- **答案允许为 0**：`left` 的初值 0 同时兼任"答案兜底值"，`Σc < k` 时二分自然收敛到 0（示例 2），无需特判。

## 三、代码实现

### 最终代码

```python
import copy                      # 截图里没有、已补
from typing import List          # 截图里没有、已补


class Solution:
    def maximumCandies(self, candies: List[int], k: int) -> int:
        def check(num: int) -> bool:
            candy = copy.deepcopy(candies)
            ans = k
            for i in candy:
                temp = i // num
                ans -= temp
                if ans <= 0:
                    return True
            return False

        right = max(candies) + 1
        left = 0
        while left + 1 < right:
            mid = (left + right) // 2
            if check(mid):
                left = mid
            else:
                right = mid
        return left
```

## 四、复杂度分析

| 版本 | 时间复杂度 | 空间复杂度 |
| :--- | :--- | :--- |
| **最终代码** | O(n log C) | O(n) |
| 朴素解法（枚举 x） | O(n · C) | O(1) |
| 理论下界 | O(n log C) | O(1) |

> 复杂度中的 n 指数组 `candies` 的长度（糖果堆数），C = `max(candies)`（答案值域的上界）。
> 判定 `check` 每轮最多扫 n 堆，二分做约 log₂C 轮；最终代码每次判定都 `deepcopy` 了一份数组，故额外空间为 O(n)。

## 五、优化评估

**结论**：**大 O 已经到该结构的下界，但常数与空间有可压缩处。**

### 瓶颈分析

- **时间**：总代价 = 判定次数 × 单次判定代价。单次判定必须扫过数组（前面的元素不够时无法提前下结论），
  n 这一因子去不掉；值域上有 C 个候选答案，二分用 log C 次判定定位边界，已是比较型搜索的次数下界。
  ⇒ **O(n log C) 是这条路线能达到的复杂度**，不可能靠改判定改写降低。
- **空间**：`check` 里的 `copy.deepcopy(candies)` 复制了一份数组，但整个判定过程只做只读的 `i // num`，
  **没有任何一处修改 `candy`** ⇒ 这份拷贝不承载语义，只是把峰值空间抬到 O(n)。

### 可优化空间

判定是纯只读操作，去掉拷贝即可把空间降到 O(1)，逻辑与最终代码完全等价 —— 这是本题唯一实质的优化点。

### 优化代码

```python
from typing import List


class Solution:
    def maximumCandies(self, candies: List[int], k: int) -> int:
        def check(num: int) -> bool:
            need = k
            for c in candies:            # 只读原数组，不再复制
                need -= c // num
                if need <= 0:
                    return True
            return False

        left, right = 0, max(candies) + 1    # 两端哨兵均为“不可行”
        while left + 1 < right:
            mid = (left + right) // 2
            if check(mid):
                left = mid
            else:
                right = mid
        return left
```

**优化理由**：判定函数没有副作用，传入的就是只读输入，拷贝是纯开销；去掉后额外空间 O(1)，逻辑不变。

### 常数级优化（可选）

- **收紧上界**：`k` 个人各拿 `x` 颗共需 `k·x` 颗糖，而分配的糖彼此不重叠 ⇒ 必有 `k·x <= Σcandies`，
  所以右哨兵可以取 `min(max(candies), sum(candies) // k) + 1`。这只减少二分的轮数（不改变大 O），
  且在 `Σcandies < k` 时右界直接落到 1，一步返回 0。
- **`ans <= 0` 而非 `ans == 0`**：单次 `i // num` 可能一次性把剩余需求减成负数，
  用 `<=` 才不会漏掉这类"超额完成"的情况（见下方易错点）。

## 六、易错点与总结

### 易错点

- **除零**：`check(0)` 会触发 `ZeroDivisionError`。本写法靠"`mid` 永远取不到 0"兜住 ——
  只要 `right >= 2`（本题 `max(candies) >= 1`，故 `right >= 2`），`mid = (left + right) // 2 >= 1`。
  ⇒ `left = 0` 只能当**不可行哨兵**，绝不能当成真实候选答案去判定。
- **哨兵必须"确实不可行"**：左 0、右 `max(candies) + 1` 都不可行，"幽灵二分"才成立。
  若把左哨兵改成 1（或右哨兵取 `max(candies)`），在答案恰为 0 或恰为 `max(candies)` 的用例上会出错。
- **mid 取整方向与赋值口径要配套**：可行时 `left = mid`（**保留** mid），不可行时 `right = mid`（**丢弃** mid），
  配 `(left + right) // 2` 的下取整。若把 `left = mid` 写成 `left = mid + 1` 会跳过答案；
  若换成 `(left + right + 1) // 2` 而上取整，当前区间会死循环。
- **`ans <= 0` 而不是 `ans == 0`**：例如 `candies = [10000000], k = 1`、`mid = 1` 时，
  一次 `i // num` 就把 `ans` 从 1 减到 −9999999，写成 `== 0` 会漏判成"不可行"。
- **k 极大时无需特判**：`Σc < k` 时 x = 1 不可行，二分自然收敛到 0，别去写 `if sum(candies) < k: return 0` 这类冗余分支。

### 题型套路沉淀

- **"最大/最小的可行值" → 二分答案**：把"求最值"整体换成"判定 `P(x)` 是否成立"，
  再用 `P` 关于 `x` 的单调性定位边界。看到"答案落在一个数轴上 + check 一次 O(n)"就该条件反射。
- **二分答案四件套**：① 写出 `P(x)`；② 验证单调性（真值是否呈真…真假…假）；
  ③ 定两端哨兵（**两端都要确实"不可行"或确实"可行"**）；④ 半开区间 `left + 1 < right` +
  下取整 `mid`，可行保留左、不可行收缩右，最后返回 `left`。
- **量级估算**：n × log C 能过、n × C 不能过（本题 10^5 × 10^7 直接爆），
  所以只要 `P` 的判定是线性的，答案值域再大也不慌。
- **判定里带"剩余需求递减"可以提前退出**：不必扫完全部堆就知道结果，能省掉大量无谓迭代。
