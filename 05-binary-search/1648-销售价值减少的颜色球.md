# 1648. 销售价值减少的颜色球

> **难度**：中等
> **标签**：贪心 · 二分查找 · 数组
> **原题链接**：https://leetcode.cn/problems/sell-diminishing-valued-colored-balls/

---

## 一、题目描述

有若干种颜色的球，`inventory[i]` 表示第 `i` 种颜色初始的球数。顾客要买走总计 `orders` 个球，**颜色可以任选**。

单个球的价值 = **该颜色当前剩余的球数**：每卖掉一个同色球，该颜色剩余数减 1，于是下一个同色球的价格也少 1（价格随购买同色球递减）。

求卖满 `orders` 个球所能获得的**最大**总价值，结果对 `10^9 + 7` 取余。题目保证 `orders <= sum(inventory)`，即一定能卖够。

### 示例

```text
输入：inventory = [2,5], orders = 4
输出：14
解释：卖 1 个第一种颜色的球（价值为 2 ），卖 3 个第二种颜色的球（价值为 5 + 4 + 3 ）。
     最大总和为 2 + 5 + 4 + 3 = 14 。
```

```text
输入：inventory = [3,5], orders = 6
输出：19
解释：卖 2 个第一种颜色的球（价值为 3 + 2 ），卖 4 个第二种颜色的球（价值为 5 + 4 + 3 + 2 ）。
     最大总和为 3 + 2 + 5 + 4 + 3 + 2 = 19 。
```

```text
输入：inventory = [1000000000], orders = 1000000000
输出：21
解释：只有一种颜色，把 10^9 个球全卖掉，总价值为 500000000500000000 ，
     它对 10^9 + 7 取余为 21 。
```

### 约束条件

- `1 <= inventory.length <= 10^5`
- `1 <= inventory[i] <= 10^9`
- `1 <= orders <= min(sum(inventory[i]), 10^9)`
- 答案对 `10^9 + 7` 取余

## 二、解题思路

### 核心思想

**贪心：每次都卖当前剩余最多的那种球**（这一步的局部最优就是全局最优）；但不要真的一个一个卖 —— 把各颜色的球数看成一张**柱状图**，最大值一定出现在"最高的那一层"，于是问题变成**二分出最后一批球的价格 `T`**，再用**等差数列求和**把每一整段台阶一次算完。

### 思路演进

1. **暴力模拟（思路对但会超时）**：用一个最大堆存各颜色剩余球数，循环 `orders` 次：取出堆顶（当前最大球数）、累加到答案、减 1、放回堆。每次取当前最大值恰好就是最优策略，所以**贪心本身是正确的** —— 但 `orders` 可以到 `10^9`，哪怕一次操作只要 O(log n)，总量级也完全扛不住（示例 4 就是 `orders = 10^9`）。另外还要注意：真正的答案是"最大总价值之和"，而每一档价格本身递减，所以必须按「价格从高到低」的顺序吃满 `orders` 个球。

2. **观察到**：贪心的过程其实就是**从柱状图顶部往下削**：
   - 最高的那根柱子先被削到和第二高一样高；
   - 然后最高的两根一起往下削，直到和第三高齐平；
   - ……

   每一次"削"削掉的是一整层**等高的台阶**，价格从高到低连续递减，中间那几百上千个球的价值完全可以用等差数列公式一次性算出来，没必要逐个模拟。

3. **关键转化 —— 用阈值 `T` 描述"削到哪儿了"**：设

   ```text
   f(T) = Σ max(0, inventory[i] - T)
   ```

   它的含义是"**价值严格大于 `T` 的球一共有多少个**"（第 `i` 种颜色里价值为 `T+1, T+2, …, ai` 的球各有 1 个，共 `ai - T` 个）。它关于 `T` **单调不增**：阈值抬得越高，能卖的高价球越少。单调性到手，就可以**二分**。

4. **优化为**：二分出**最小的**满足 `f(T) <= orders` 的 `T`，它就是"最后一批被卖出的球的价格"。
   - 先把所有价值 `> T` 的球卖光：第 `i` 种颜色贡献 `T+1 … ai` 这一段等差序列，价值为 `range_sum(T+1, ai)`。全部卖完正好是 `f(T)` 个球。
   - 还差 `rest = orders - f(T)` 个球，它们的价格都等于 `T`，随便从哪些 `ai >= T` 的颜色里出。
   - 把两部分加起来取模即可。

   为什么一定要取"**最小**的满足条件者"？因为 `f` 单调不增，满足 `f(T) <= orders` 的 `T` 构成一个后缀区间；取最小者恰好保证 `f(T-1) > orders`，也就是

   ```text
   rest = orders - f(T) < f(T-1) - f(T) = 满足 ai >= T 的颜色数
   ```

   —— 零头 `rest` 一定落在同一个价格档位 `T` 上，并且**数量足够、不会越界**。若取反了（去取最大的那个 `T`），`rest` 会变得巨大甚至为负，答案全错。

### 关键点

- **贪心为什么不用反悔**：价格只取决于"该颜色还剩多少"，且随卖随降。同一档里多卖一个高价球、少卖一个低价球，总价值只会更大 —— 所以"每次取当前最大球数"是安全的局部最优，能吃满 `orders` 而不需要后悔。
- **二分的是「价格」不是「下标」**：区间是 `T ∈ [0, max(inventory)]`，判定函数是 `f(T)`；这是典型的**二分答案**，而不是在有序数组里找某个元素。
- **取最小的 `T`**，而不是最大的：这是让 `rest` 落在单一价格档的关键（见上）。
- **两段等差数列不能混**：价值 `> T` 的那段是 `T+1 … ai`；只有拿到零头的颜色才把价格 `T` 也算进去（`T … ai`）。写成"所有 `ai >= T` 的颜色都算上 `T`"会多算 `(颜色数 - rest)` 个 `T`。
- `ai == mid` 时 `ai - mid = 0`，不影响求和，所以判定里写 `ai >= mid`（等价于 `ai > mid`）都行；用 `>=` 可以让 `T` 的取值下探到 0（当 `orders == sum(inventory)` 时 `T = 0`，此时 `rest = 0`）。
- **中间不要提前取模**：Python 整数不会溢出，最后统一 `% mod` 最省事也最不易错。（若用 C++/Java 则需在累加过程中取模，且 `(x + y) * (y - x + 1)` 可能超 `int`，要用 64 位。）

## 三、代码实现

### 最终代码

```python
from typing import List


class Solution:
    def maxProfit(self, inventory: List[int], orders: int) -> int:
        mod = 10**9 + 7

        # 二分查找 T 值：最小的满足 f(T) = sum(ai - T for ai >= T) <= orders 的 T
        l, r, T = 0, max(inventory), -1
        while l <= r:
            mid = (l + r) // 2
            total = sum(ai - mid for ai in inventory if ai >= mid)
            if total <= orders:
                T = mid
                r = mid - 1
            else:
                l = mid + 1

        range_sum = lambda x, y: (x + y) * (y - x + 1) // 2

        rest = orders - sum(ai - T for ai in inventory if ai >= T)

        ans = 0
        for ai in inventory:
            if ai >= T:
                if rest > 0:
                    ans += range_sum(T, ai)
                    rest -= 1
                else:
                    ans += range_sum(T + 1, ai)

        return ans % mod
```

> 说明：截图里的代码没有 `from typing import List`，这里已补上（LeetCode 环境会自动注入，本地运行需要它）。

## 四、复杂度分析

| 版本 | 时间复杂度 | 空间复杂度 |
| :--- | :--- | :--- |
| **最终代码** | O(n log M) | O(1) |
| 朴素解法（最大堆逐个模拟） | O(orders · log n) | O(n) |
| 理论下界 | O(n) | O(1) |

> - `n` = `inventory` 的长度（颜色种数，≤ 10^5）；
> - `M` = `max(inventory)`（单色最大球数，≤ 10^9）；
> - `orders` = 订单数（≤ 10^9）。

说明：

- 二分区间是 `[0, M]`，共 `O(log M)` 轮，每轮 O(n) 求和；之后线性扫一遍累加答案，再 O(n)。所以总时间 `O(n log M)`。`log₂(10^9) ≈ 30`，最多约 30 次数组扫描。
- 空间上除输入外只用了常数个变量，`O(1)`。
- 与朴素解对比：堆模拟的时间 `O(orders log n)` 里带的是 `orders` 本身（可达 10^9），而最终代码把它换成了 `M` 的对数 —— 这正是能过示例 4（`orders = 10^9`）的原因。
- 理论下界 `O(n)`：至少要完整读一遍 `inventory` 才知道有哪些颜色、最大值是多少，任何算法都不可能低于 `Ω(n)`。
- 注意：这里的 `M` 是数值大小（≤ 10^9），不是长度，所以 `O(n log M)` 与 `O(n log n)` 同阶但常数不同（`log M ≈ 30`，`log n ≈ 17`）；两者都在可接受范围内。

## 五、优化评估

**结论**：时间复杂度已经足够（`O(n log M)`，约 30 次扫描），无需再换算法；空间 `O(1)`，没有可压缩的空间。仅在常数层面还有余地。

### 瓶颈分析

时间全部花在二分每一轮的 `O(n)` 全量求和上，共约 `log₂M ≈ 30` 轮，即最坏约 `30 × 10^5 = 3 × 10^6` 次加法。这已是本题在 Python 下非常轻松的规模，不需要进一步改算法。

空间方面：最终代码不建堆、不排序、不开额外数组，只用了 `l / r / T / rest / ans` 几个变量，`O(1)`，已经没有可省的东西。

### 可优化空间

两个**不影响大 O、只影响常数**的方向（逻辑需要额外小心，故未改动最终代码）：

1. **判定函数提前退出**：`total` 一旦超过 `orders` 就立刻跳出内层求和并返回"不满足"，不必把整个数组加完。当 `T` 偏小（`f(T)` 远大于 `orders`）时，这能省掉大量加法。
2. **收窄二分下界**：`l` 不必从 `0` 开始。由于最终要卖 `orders` 个球，而所有价值 `> T` 的球有 `f(T) <= orders` 个，可推出 `T >= max(inventory) - orders`（`orders` 很小时这个下界非常紧）。把 `l` 初始化成这个值能直接砍掉一大截二分轮数。

> 保留 `l = 0, r = max(inventory)` 的原版写法是因为它最直白、边界最好推；上面两条属于"确认正确后再动"的常数优化。

### 常数级优化（可选）

- `max(inventory)` 只在开头算一次，别放进循环里反复求。
- 判定里的生成器 `sum(ai - mid for ai in inventory if ai >= mid)` 已经比"先筛出子列表再求和"省一次内存分配，保持现状即可。
- 若真有性能压力，可把二分改成一次 `sort` 后按"台阶"从高到低扫描（前缀和思路）—— 但那是另一条等价路线，本题规模下没有换的必要。

## 六、易错点与总结

### 易错点

- **二分取错一侧**：要找的是**最小**的满足 `f(T) <= orders` 的 `T`。若取最大者，`rest` 会变成一个很大（甚至负数）的值，尾数段完全算错。
- **尾数那一段重复计入 `T`**：只有拿到 `rest` 的那 `rest` 个颜色可以把 `T` 算进去（`range_sum(T, ai)`），其余颜色只能取到 `T+1`（`range_sum(T + 1, ai)`）。若写成"所有 `ai >= T` 都算 `T`"，会多算 `(满足 ai >= T 的颜色数 - rest)` 个 `T`。
- **单调性方向记反**：`f(T)` 是**单调不增**的（阈值越高，高于阈值的球越少）。二分边界条件必须与它一致。
- **真的逐个卖球**：`orders` 到 `10^9`，任何循环 `orders` 次的写法都会超时（示例 4 就是专门卡这一点）。
- **忘记取模 / 提前取模**：题目要求返回 `% (10^9 + 7)`；Python 下最后统一取模即可，但别在等差数列里用整除前就取模（`(x+y)*(y-x+1)//2` 要先算完整）。
- **空区间边界**：`T` 初值给 `-1` 只是兜底哨兵；因为 `orders >= 1` 且 `f(max(inventory)) = 0 <= orders`，二分一定能在 `[0, M]` 内找到合法 `T`（只有当 `orders == sum(inventory)` 时 `T` 才会等于 `0`，此时 `rest = 0`，逻辑依然成立）。

### 题型套路沉淀

- **「二分答案 + 公式批量结算」**：当最优策略是"从大到小连续地取"，而取值上界又很宽（本题 `inventory[i]` 到 10^9）时，把"逐个取"换成
  1. 写出关于阈值 `T` 的**单调判定函数** `f(T)`（"取值 `≥ T` 的那部分总量是多少"）；
  2. **二分**出临界 `T`（注意取最小 / 最大哪一侧）；
  3. 用零头 `rest = orders - f(T)` 在**同一档位** `T` 上补足剩余数量；
  4. 每一段连续取值用**等差数列求和**一次算完。

  这是这类"削山"型贪心题的标准骨架。
- **判定函数的提前退出**是这类题的常见常数优化：累计量一旦越过阈值就返回，能省掉大部分无效扫描。
- 另一个自检习惯：**先想清楚"零头为什么不会越界"**（本题靠 `f(T-1) > orders` 保证 `rest < 满足 ai >= T 的颜色数`）—— 二分答案类题目出问题，多半就出在零头或边界档位没交代清楚。
