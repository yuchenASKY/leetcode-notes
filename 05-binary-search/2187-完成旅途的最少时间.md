# 2187. 完成旅途的最少时间

> **难度**：中等
> **标签**：数组 · 二分查找
> **原题链接**：https://leetcode.cn/problems/minimum-time-to-complete-trips/

---

## 一、题目描述

有 `n` 辆公交车，第 `i` 辆跑完一趟要 `time[i]` 个单位时间，且它可以一趟接一趟地跑（跑到 `t` 时刻时完成的趟数是 `floor(t / time[i])`）。所有车同时开始、互不影响。给定总趟数 `totalTrips`，求**完成至少 `totalTrips` 趟所需的最少时间**。

### 示例

```text
输入：time = [1,2,3], totalTrips = 5
输出：3
解释：
- t = 1：每辆车完成 [1,0,0]，累计 1 趟
- t = 2：每辆车完成 [2,1,0]，累计 3 趟
- t = 3：每辆车完成 [3,1,1]，累计 5 趟  —— 首次达到 5，答案 3
```

```text
输入：time = [2], totalTrips = 1
输出：2
```

```text
输入：time = [5,10,10], totalTrips = 9
输出：25
```

### 约束条件

- `1 <= time.length <= 10^5`
- `1 <= time[i], totalTrips <= 10^7`
- 答案上界可达 `10^14`（如 `time = [10^7]`、`totalTrips = 10^7`）

---

## 二、解题思路

### 核心思想

**答案本身就是一个有序搜索空间。** 记 `f(t) = Σ floor(t / time[i])` 为 `t` 时刻完成的总趟数 —— 它关于 `t` **单调不减**，于是「最小的 `t` 使 `f(t) >= totalTrips`」就是一个单点翻转的谓词，**二分答案**即可：判定一次 O(n)，共 O(log U) 次。

### 判据与判据族定位

**判据**：`P(t) := f(t) >= totalTrips`，`P` 关于 `t` 单调（`false … false, true … true`）；答案 = **第一个为 `true` 的位置**。

**族定位**：本题属 `05-binary-search` 下的**「二分答案」族**，与另一族「**下标二分**（有序序列上的谓词边界定位）」必须区分，两族的骨架**不可互抄**：

| | 二分答案（本题） | 下标二分 |
| :--- | :--- | :--- |
| 二分的对象 | **答案值** `t` | **数组下标** |
| 区间端点 | 先验哨兵：`left` 恒不可行、`right` 恒可行（须**自己构造并证明**） | 数据本身有序，端点就是有效下标 |
| 单调性来源 | 谓词 `P` 关于答案值单调 | 数据有序 / 构造方式 / 非负前提推出的前缀和单调 |
| 每轮代价 | `O(n)` 判定 `P(mid)` | `O(log n)` 或 `O(1)` 查表 |
| 收缩写法 | `right = mid` / `left = mid`（**不带 ±1**） | `right = mid - 1` / `left = mid + 1`（带 ±1） |

本题的单调性来自 `floor(t / x)` 关于 `t` 单调不减（`x >= 1` 保证定义域无奇点），`n` 指公交车数量 `time.length`。

### 思路演进

1. **朴素解**：从 `t = 0` 起逐秒枚举，每步重算 `f(t)`，遇到第一个 `f(t) >= totalTrips` 就返回。正确但代价 `O(n · t*)` —— 本题 `t*` 最坏 `min(time) · totalTrips = 10^14`，连"枚举失败"都要跑 10^14 次外层循环，**完全不可行**（强数据下 1 秒只能跑 10^7 量级）。

2. **瓶颈定位**：问题是「我们在**线性**地扫描一个答案空间，而这个空间的每一格只是重复地在做同一件事」。`f(t)` 与 `f(t+1)` 之间没有便宜的增量结构（每辆车的完成时刻是等差数列，无法增量维护）。真正没用上的是：**`f` 关于 `t` 单调** —— 谓词一旦为真就永远为真，那么「第一次为真」这件事天然适合二分，不需要逐格走。

3. **关键转化**：把问题改写成「在 `[0, U]` 上求单点翻转谓词的分界点」，其中 `U` 必须**是一个已被证明可行的点**（二分要有右边界，且断言 `P(U) = true`）。整数域直接二分 ⇒ 判定次数降到 `log2(U) ≈ 30 ~ 47`，每次 `O(n)`。
   **一句话说明为什么原来不行、现在行**：原来每次只能排除 1 个候选值，现在每次通过 `P(mid)` 一次判定**一次性排除一半**区间 —— 前提是 `P` 单调。

4. **最优解**：用户代码 —— `left = 0`（恒不可行：`f(0) = 0 < totalTrips`，因为 `totalTrips >= 1`）、`right = max(time) * (totalTrips // n + 1)`（恒可行，见下方证明），循环体里 `right = mid` / `left = mid` 都不带 ±1，退出时 `right` 就是最小可行值。

### 正确性论证

**不变量**：每轮开始时 `f(left) < totalTrips <= f(right)`。

- **初始**：`f(0) = 0 < totalTrips`（`totalTrips >= 1`）；`right = max(time) · (q + 1)`（记 `q = totalTrips // n`）满足 `f(right) = Σ floor(right / time[i]) >= n · floor(max · (q+1) / max) = n(q+1) >= totalTrips`（用的是 `time[i] <= max(time)`，故 `right / time[i] >= q+1`，取整后仍 `>= q+1`）。
- **归纳**：`mid` 可行则把可行端收到 `mid`（仍是可行点），不可行则把不可行端提到 `mid`（仍是不可行点），不变量保持。
- **终态**：循环条件 `left + 1 < right` 结束时 `right = left + 1`，故 `right` 是最小的可行值，即答案。

**上界写法的成本含义**：`max(time) · totalTrips` 也可行但更松（每个车单独就能跑完时最坏多几次迭代）；`min(time) · totalTrips`（最快的车独自跑完 `totalTrips` 趟）也可行，但在"全 1 数组"这类输入上比本解松 5 个数量级（`10^7` vs `101`）。**上界越紧 ⇒ 轮数越少**，这是本题唯一能"减少总工作量"的非常数手段（见 §五）。

### 关键点

- **`left` / `right` 是哨兵，不是闭区间的两个端点**：所以 `mid` 处**不写 ±1**；这也是本题与「下标二分」最容易混用的地方。
- 上界必须**证明过**才行，不能"看起来够大"。
- `f(t)` 是"每辆车完成趟数之和"，不需要模拟过程，直接整除求和。
- 计数题注意返回值宽度：`n = 1` 且 `totalTrips = 10^7`、`time[0] = 10^7` 时答案是 `10^14`，`int32` 必爆。

## 三、代码实现

### 最终代码

```python
class Solution:
    def minimumTime(self, time: list[int], totalTrips: int) -> int:
        left = 0
        right = max(time) * (totalTrips // len(time) + 1)
        while left + 1 < right:
            mid = (left + right) // 2
            if sum(mid // x for x in time) >= totalTrips:
                right = mid
            else:
                left = mid
        return right
```

> 代码取自提交记录（截图），**无需补 import**：注解用的是内建 `list[int]`（Python 3.9+），不依赖 `typing`。截图共 11 行、末行为 `return right`，无裁切。

## 四、复杂度分析

| 版本 | 时间复杂度 | 空间复杂度 |
| :--- | :--- | :--- |
| **最终代码** | `O(n log U)`，`U = max(time)·(totalTrips//n + 1) <= ~10^14`，`log2 U <= 47` | `O(1)` 额外 |
| 线性枚举（朴素） | `O(n · t*)`，`t*` 最坏 `10^14` | `O(1)` |
| 理论下界 | `Ω(n)`（必须读入整个 `time`；`f` 无闭式，任何判定都要看完数组） | `Ω(1)` |

> `n` = `time.length`（公交车数）；`U` = 二分区间上界。实测二分层数（插桩）：`n = 10^5` 各场景 `7 ~ 30` 轮，`n = 10^3` 时 37 轮；对应除法总次数 `7×10^5 ~ 3×10^6`。

**是否"不优化就过不了"**：不是。最坏工作量约 `3×10^6` 次整除 + 求和，用户版实测 30 ~ 130 ms 就出答案，余量充足。下面的优化是**常数级**的，只为把耗时压下来，不改变 `O(n log U)` 这一结论。
（C++/Java 迁移注意：`mid` 上界 `~10^14` 与 `f(mid) <= max(time)·totalTrips/min(time) <= 10^14` 都超 `int32`，须用 64 位；`long long` 有约 4 个数量级余量。）

## 五、优化评估

**结论**：渐进复杂度 `O(n log U)` 已是本题的实用下界，**但常数还有 1.3× ~ 24× 的空间**；其中两项改动（本文的 `B`、`H`）在 6 档场景里**逐轮全部优于用户版**，可放心替换。

### 瓶颈分析（阶段归因）

`n = 10^5`、随机 `time`（S2 档，30 轮）：端到端 **129.3 ms**；其中单次 `sum(mid // x for x in time)` 为 **4.262 ms**，`30 轮 × 4.262 ms = 127.8 ms` ⇒ **求和段占 98.9%**。

⇒ 二分外壳（比较、移位、赋值）几乎不花钱，**全部成本在「轮数 × n 次整除」上**。可动的只有三条：

1. 让**每次求和更快**（同样的整数运算，少花 Python 层开销）；
2. 让**每轮的 n 变小**（按值聚合，把 `n` 换成"不同值的个数"）；
3. 让**轮数变少**（更紧的上界 / 提前退出）。

**结论**：

- **稳赚（推荐）**：`B`（`sum(map(mid.__floordiv__, time))` + `>> 1`）**六档 42 轮全部 < 1.0**，提速 **1.19× ~ 1.55×**。机理：`sum(genexpr)` 的每一项都要过一次生成器帧，而 `map` + 绑定方法把逐项调用压到 C 层。隔离测量同向：单次求和 `4.262 ms → 3.395 ms`（`0.797×`）。
- **稳赚且更优（推荐）**：`H` = 「值分布先探测，再决定走聚合还是走 map」**六档逐轮全部 < 1.0**，最差 0.779（仍 1.28×）、最好 0.041（**24×**）。它的两半分别是：
  - `G`（按值聚合，`H` 的重复档路径）：distinct `1 / 2 / 1` 的 S1/S3/S5 **0.146 / 0.034 / 0.036（6.9× ~ 29×）**；`H` 用 `len(set(time)) * 8 <= n` 作开关，逐轮区间也全部 < 1.0。
  - `B`（`H` 的互异档路径）：S2/S4/S6 上 `H` 比 `B` 多付一次 `set` 探测（约 +5%：0.779 vs 0.739、0.870 vs 0.826），但**仍远优于 A**。⇒ `H` 是"没有亏的档"的那个版本；若只想要单行改动，用 `B`。
- **条件收益**：`C` / `E` / `F`（升序 + 提前退出）只在"**最快的少数车就能凑够 `totalTrips`**"时大赚 —— S3 双峰档 `div` 从 `3×10^6` 降到 `6×10^5 ~ 7.3×10^5`，实测 4.1× ~ 4.9×；S4/S6 小赚 8% ~ 8%；而 S1/S5 反向 1.02× ~ 1.04×（排序 + 每项一次比较的固定成本换不到任何早退）。⇒ **不能无条件采用**，必须按 `time` 的分布决定。
- **被证伪**：`D`（单独把上界收紧成 `min(两个可行上界)`）是**负优化** —— S1/S5 分别慢 3.8% / 3.9%，因为多出来的两次 `max`/`min` 全数组扫描（各约 0.5 ms）换不到轮数减少；只在 S3 因省掉 7 轮（30 → 23）才赚 0.793。**正确做法是让 `E` 那样"排序后免费拿 `a[0]` / `a[-1]`"，而不是单独再扫两遍。**
- **被证伪**：`G` 无开关时，`distinct ≈ n` 的 S2/S4 反向 **1.223 / 1.276**（逐轮区间完全在 1.0 以上）。成本归因（§七 第 4 条）说明：此时 `Counter` 建表 17.8 ~ 18.0 ms 却只占 G 总耗时 11.5% ~ 13.6%，**亏的原因是循环根本没缩短**（`div` 仍约等于 `n × 轮数`，因为 distinct 就是 n），还要平白多付一次建表。

### 出局的路线：值域桶 + 前缀和

`time[i] <= 10^7` 看起来像"值域有界 ⇒ 计数桶 + 前缀和"的信号，但本题**不适用**：判定 `f(t) = Σ_v cnt[v] · floor(t / v)` 需要对整个值域求和，即使改用除法分块（`floor(mid/v)` 只有 `O(√mid)` 种取值）也要 **约 `2√mid ≈ 6.3×10^4` 次块循环**，与 `n = 10^5` 同量级；而建表的固定成本实测：`V = max(time) ≈ 10^7` 时 `分配 + 计数 = 29.7 ms`、`前缀和 = 402.4 ms`，**合计 432.2 ms，已经是用户版端到端（125 ms）的 3.5 倍**。⇒ 直接放弃。

### 优化代码

**推荐版（`H`：自适应，六档逐轮全胜）**：

```python
class Solution:
    def minimumTime(self, time: list[int], totalTrips: int) -> int:
        n = len(time)
        T = totalTrips
        if len(set(time)) * 8 <= n:                  # 值高度重复 -> 按值聚合
            items = list(Counter(time).items())
            left = 0
            right = max(time) * (T // n + 1)
            while left + 1 < right:
                mid = (left + right) >> 1
                s = 0
                for x, c in items:
                    s += (mid // x) * c
                if s >= T:
                    right = mid
                else:
                    left = mid
            return right
        left = 0                                     # 否则走 C 层 map
        right = max(time) * (T // n + 1)
        while left + 1 < right:
            mid = (left + right) >> 1
            if sum(map(mid.__floordiv__, time)) >= T:
                right = mid
            else:
                left = mid
        return right
```

> 需 `from collections import Counter`。

**最小改动版（`B`：只换求和写法，六档也是全胜）**：

**条件版（`E`：仅在"少数快车就能凑够"的输入上采用）**：

```python
class Solution:
    def minimumTime(self, time: list[int], totalTrips: int) -> int:
        a = sorted(time)
        n = len(a)
        T = totalTrips
        hi1 = a[-1] * (T // n + 1)      # 排序后取 min/max 是 O(1)，比单独扫两遍便宜
        hi2 = a[0] * T
        left, right = 0, hi1 if hi1 < hi2 else hi2
        while left + 1 < right:
            mid = (left + right) >> 1
            s = 0
            for x in a:                 # 升序 ⇒ 部分和增长最快，越早触发 break
                s += mid // x
                if s >= T:
                    break
            if s >= T:
                right = mid
            else:
                left = mid
        return right
```

**优化理由**：三条都指向同一个式子「轮数 × 每次求和的代价」。`B` 压缩"每次求和"的解释器开销；`H` 把"每次求和"的规模从 `n` 降到"不同值个数"（重复度高时收益极大）；`E` 同时压缩"轮数"（更紧上界）与"每次求和"（早退）。三者的收益结构不同，**必须按输入分布选**：只有 `B` / `H` 是分档全胜的。

| 闭区间式收缩 `left = mid + 1` 配哨兵式 `while left + 1 < right` | `time=[1], T=2` | 2 → **3** | 17 | 高（破坏 `left` 不可行的不变量，答案被顶过一格） |
| 判定写成严格大于 `> totalTrips` | `time=[1], T=1` | 1 → **2** | 22 | 低（**官方示例即挂**：3 例分别得 4 / 4 / 30） |
| `while left < right` 配 `left = mid` | `time=[1,2,3], T=5` | — | — | 高（**死循环**，官方示例即卡死） |

- **上界必须自己证一遍**：`f(right) >= totalTrips`。本解的证法是"每辆车至少 `q+1` 趟"。换任何别的上界都要重证，否则二分会在"右端不可行"的前提下返回一个看似合理的小值。
- **两种循环骨架不许各取一半**：哨兵式（`left+1<right` + `left=mid` + `right=mid`，返回 `right`）与闭区间式（`left<right` + `left=mid+1` + `right=mid`，返回 `left`）各自成对，混用要么死循环要么丢解。
- **`mid` 处不要写 ±1**：`left`/`right` 是"恒不可行 / 恒可行"的哨兵，不是待搜索的闭端点。
- **答案宽度**：`time=[10^7]`、`totalTrips=10^7` 时答案是 `10^14`，C++/Java 里 `int` 必爆。
- 本题不需要模拟"每辆车在每一秒跑了几趟"——`floor(mid / x)` 直接给出一辆车在 `mid` 时刻的完成趟数。

### 题型套路沉淀

- **识别信号**：「求最小的 `t`，使得某个关于 `t` 单调的性质成立」，且性质求值 `O(n)` 或 `O(n log n)` ⇒ 二分答案。典型同型：`1283 使结果不超过阈值的最小除数`、`875 爱吃香蕉的珂珂`、`1011 在 D 天内送达包裹的能力`。
- **固定骨架四步**：① 构造一个**可证明可行**的上界 `U`（可行时才能当 `right` 哨兵）；② `left` 取一个显然不可行的点（常为 0）；③ `while left + 1 < right:` 里按 `P(mid)` 收区间，**不带 ±1**；④ 返回 `right`。
- **本题最值钱的横切结论**：二分答案的耗时 ≈ `轮数 × 一次判定的代价`，而**两者都能压**——本文实测"压缩单次判定"（`H`，最多 24×）优于"压缩轮数"（`E`，只在特定分布上 4.9×）；且**单次判定段实测占端到端 98.9%**，成本全在这里，别去优化二分外壳。
- **"按值聚合"是一个通用手法**：凡是判定式形如 `Σ g(mid, a[i])` 且 `a` 的重复度高，都可以先 `Counter` 把 `n` 换成"不同值个数"；**但必须先探测重复度**，否则在"值全不同"的输入上净亏 20% 以上（实测 1.223 ~ 1.276×）。
- **更紧的上界值不值，要看它省下的轮数能否盖过它的获取成本**：`D` 单独再扫两遍数组是负优化（+3.8%），而 `E` 里"排序顺带拿到 `min`/`max`"就是免费的。
